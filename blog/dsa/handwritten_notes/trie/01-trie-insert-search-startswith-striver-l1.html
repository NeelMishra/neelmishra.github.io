    Implement Trie (Prefix Tree): insert, search & startsWith

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 01_Striver_lec_1.pdf

    A Trie (pronounced "try", from retrieval; also called a prefix tree) stores strings character by character along root-to-node paths so that words sharing a common prefix share the exact same prefix nodes in memory. This note expands Striver Trie Lecture 1 (equivalent to LeetCode 208: Implement Trie (Prefix Tree)), covering the 26-slot self-referential node layout, the pointer-box trace of "apple", and the exact terminal invariant separating search(word) from startsWith(prefix).

    1. Problem & Functionality Specification

    Design a data structure for lowercase English strings ('a'–'z') supporting three operations:

    • insert(word) — Inserts the string word into the Trie.
    • search(word) — Returns true if and only if the exact string word has been previously inserted into the Trie, and false otherwise.
    • startsWith(prefix) — Returns true if there is any previously inserted string in the Trie that begins with prefix, and false otherwise.

    2. Progression: Brute Force $\to$ Hash Set $\to$ Prefix Tree

    Comparing string dictionary representations across $N$ inserted words of length $L$.
    Approach insert(word) search(word) startsWith(prefix) Trade-off
    Unsorted Vector $O(L)$ $O(N \cdot L)$ $O(N \cdot L)$ Scans every stored string on every lookup.
    unordered_set<string> $O(L)$ avg $O(L)$ avg $O(N \cdot L)$ (or $O(L^2)$ insert if hashing all prefixes) Whole-string hashing destroys prefix structure and suffers $O(N \cdot L)$ worst-case hash collisions.
    26-Way Trie (Optimal) $O(L)$ deterministic $O(L)$ deterministic $O(|prefix|)$ deterministic Shared prefixes allocated once; runtime depends only on query length, independent of $N$!

    3. Anatomy of a Trie Node & Vocabulary Mapping

    In the handwritten note, a Trie node is sketched conceptually as:

    // Conceptual sketch from 01_Striver_lec_1.pdf:
// trie {
//     trie a[26]; // Array of size of vocabulary (0->'a', 1->'b', ..., 25->'z')
//     bool flag;  // Marks whether a word ends at THIS reference node
// }

    Why C++ Uses Node* links[26] (Pointers) + Permanent root

    • Self-referential pointers: A struct in C++ cannot contain 26 full copies of itself by value (that would have infinite sizeof!). Instead, each node stores 26 child pointers Node* links[26] = {nullptr} plus bool flag = false.
    • 0-to-25 index arithmetic: Because ASCII codes for 'a' through 'z' are contiguous ($97 \dots 122$), subtracting 'a' maps every letter to its slot in $O(1)$: $$\texttt{'a'} - \texttt{'a'} = 0, \quad \texttt{'b'} - \texttt{'a'} = 1, \quad \dots, \quad \texttt{'z'} - \texttt{'a'} = 25$$
    • Permanent root invariant: Every Trie starts with a single empty root node whose 26 links are nullptr and whose flag is initialized to false (unless the empty string "" itself is explicitly inserted).

    4. Handwritten Dry Run: Inserting "apple" & Shared-Prefix Tree

    Tracing insert("apple") step by step exactly as written on Pages 2–3 of the note:

    1. Start at root, read 'a' (index 0): Does 'a' exist in root? No—all 26 slots are nullptr. Allocate a new reference node (call it node a), store its address at root->links[0], and move the current pointer to node a.
    2. Read first 'p' (index 15): Does node a contain a reference at slot 15? No—allocate node p-1, link node_a->links[15] = node_p1, and advance to node p-1.
    3. Read second 'p' (index 15): Does node p-1 contain a reference at slot 15? No—even though the character is 'p' again, we are now one level deeper! Allocate a brand-new node node p-2 from node p-1's index 15 and advance to node p-2.
    4. Read 'l' (index 11), then 'e' (index 4): Create node l from node p-2, advance to node l; then create node e from node l and advance to node e.
    5. Word exhausted — set terminal flag: Because no characters remain after 'e', we stand inside node e (the reference node pointed to by 'e'!) and set node_e->flag = true.

    Crucial Detail from the Pointer Diagram: Where Does flag = true Live?

    Look closely at the box-and-arrow diagram in Page 1 of the scan: when "bat" ends at 't', the box containing the slot for 't' still has flag = false—its arrow from 't' points to a child reference node whose flag = true! Every node represents the prefix accumulated along the edges leading into it, so a word of length $L$ spans $L + 1$ nodes (root at depth $0$ down to the terminal reference node at depth $L$).

    5. search(word) vs. startsWith(prefix)

    Both lookup functions perform the exact same character-by-character pointer walk from root, differing only in their final line:

    • search(word): Walk through each character ch of word. Two conditions cause search to return false:
      1. Illegal traversal: At some character ch, node->links[ch - 'a'] == nullptr (the path breaks early, e.g., searching "apz").
      2. Terminal flag is false: All characters are parsed, but the final node has flag == false (e.g., searching "app" when only "apple" and "apps" were inserted).
      Only if the entire string is parsed and node->flag == true does search return true.
    • startsWith(prefix): Walk through each character ch of prefix. If node->links[ch - 'a'] == nullptr at any step, return false. Otherwise, as soon as all characters of prefix are parsed without hitting nullptr, immediately return true—because any non-null node in a Trie (without lazy deletions) is guaranteed to lie on the path to at least one inserted word!

    6. Clean C++ Implementation

    Encapsulating the raw pointer indexing inside small helper methods (containsKey, put, get, setEnd, isEnd) follows Striver's production-style Trie pattern so the main Trie methods read like plain English:

    #include <bits/stdc++.h>
using namespace std;

struct Node {
    Node* links[26] = {nullptr};
    bool flag = false;

    bool containsKey(char ch) const {
        return links[ch - 'a'] != nullptr;
    }
    void put(char ch, Node* node) {
        links[ch - 'a'] = node;
    }
    Node* get(char ch) const {
        return links[ch - 'a'];
    }
    void setEnd() {
        flag = true;
    }
    bool isEnd() const {
        return flag;
    }
};

class Trie {
private:
    Node* root;

public:
    Trie() : root(new Node()) {}

    // O(L) time: shared prefix nodes are reused; new nodes allocated only on miss
    void insert(const string& word) {
        Node* node = root;
        for (char ch : word) {
            if (!node->containsKey(ch)) {
                node->put(ch, new Node());
            }
            // Move to the reference trie node for `ch`
            node = node->get(ch);
        }
        node->setEnd();
    }

    // O(L) time: requires valid path AND terminal flag == true
    bool search(const string& word) const {
        Node* node = root;
        for (char ch : word) {
            if (!node->containsKey(ch)) {
                return false; // Illegal traversal
            }
            node = node->get(ch);
        }
        return node->isEnd();
    }

    // O(P) time: requires valid path only (flag does not matter)
    bool startsWith(const string& prefix) const {
        Node* node = root;
        for (char ch : prefix) {
            if (!node->containsKey(ch)) {
                return false;
            }
            node = node->get(ch);
        }
        return true;
    }
};

    7. Complexity Proof & Subtle Edge Cases

    • Time Complexity: Every loop inspects at most $L = |\text{word}|$ characters and performs $O(1)$ array indexing per character $\implies$ $O(L)$ worst-case time per insert, search, and startsWith.
    • Space Complexity: If $N$ words of average length $L$ have zero shared prefixes, at most $1 + N \cdot L$ nodes are created, each holding $26$ pointers ($\Sigma = 26$), giving $O(\Sigma \cdot \sum |w_i|)$ worst-case memory—and substantially less when words share prefixes.
    • Key Edge Cases:
      • Inserting a shorter word after a longer one (e.g., insert("apple") then insert("app")): insert("app") allocates zero new nodes—it walks existing nodes a → p → p and flips node_p2->flag from false to true without disturbing "apple"'s children!
      • Duplicate insertions (insert("apple") twice): Idempotent—walks the existing path and sets flag = true again. (If you need to count how many times "apple" was inserted or erase one copy, see Note 04: Striver Lec 2.)
      • Full-word prefix (startsWith("apple") after insert("apple")): Returns true because every word is a valid prefix of itself.
