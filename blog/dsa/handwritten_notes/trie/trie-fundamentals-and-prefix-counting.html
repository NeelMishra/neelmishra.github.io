    Trie Fundamentals, Prefix Counting, Wildcard Search & Camelcase Matching

    October 2026 · 12 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (01_Striver_lec_1.pdf, 04_Striver_lec_2_countWordsEqualTo.pdf, 02_Ques_Design_Add_and_Search_Words_Data_structure.pdf, 03_Ques_1023.pdf)

    Hash tables check whether an exact string exists in $O(L)$ expected time, but they cannot efficiently answer prefix queries, count how many dictionary entries share a prefix, branch across single-character wildcards, or prune entire families of strings when an uppercase pattern fails early. This first part builds the standard 26-way character Trie from scratch, upgrades its node state to track multiplicities and deletions, and applies Trie traversal to LeetCode 211 (wildcard '.' search) and LeetCode 1023 (Camelcase pattern matching).

    1. Standard Trie: insert, search & startsWith (Striver Lec 1)

    A lowercase-English Trie supports three core dictionary operations in deterministic $O(L)$ worst-case time, where $L = |\text{word}|$:

    • insert(word) — Inserts string word into the Trie, sharing existing prefix nodes and allocating new child nodes only where the path diverges.
    • search(word) — Checks whether word was explicitly inserted as a complete word.
    • startsWith(prefix) — Checks whether any inserted word starts with the given prefix.

    Anatomy of a Standard Trie Node

    Each node contains two data members: an array of 26 child pointers Node* links[26] (mapping 'a' → 0, 'b' → 1, …, 'z' → 25 via ch - 'a') and a boolean terminal marker bool flag = false. Every Trie starts with a permanent root node whose 26 slots are nullptr and whose flag is false.

    Step-by-Step Insertion Trace on "apple"

    Following the exact node-by-node walkthrough in 01_Striver_lec_1.pdf:

    1. Character 'a' (index 0): Does root have a reference at slot 0? No—all 26 slots are empty. Allocate a new node (call it node a), store its address in root->links[0], and advance to node a.
    2. Character 'p' (index 15): Does node a contain a reference at 'p'? No—allocate node p-1, link node_a->links[15] to it, and advance.
    3. Second 'p' (index 15): Does node p-1 contain a reference at 'p'? No—allocate a distinct child node p-2 from node p-1 and advance.
    4. Characters 'l' then 'e': Similarly create node l under node p-2, and node e under node l.
    5. End of word: No characters remain after 'e'. Move into node e and set node_e->flag = true—marking that a complete word terminates on the node referenced by 'e'!
    struct Node {
    Node* links[26] = {nullptr};
    bool flag = false;

    bool containsKey(char ch) const { return links[ch - 'a'] != nullptr; }
    void put(char ch, Node* node) { links[ch - 'a'] = node; }
    Node* get(char ch) const { return links[ch - 'a']; }
    void setEnd() { flag = true; }
    bool isEnd() const { return flag; }
};

class Trie {
    Node* root;
public:
    Trie() : root(new Node()) {}

    void insert(const string& word) {
        Node* node = root;
        for (char ch : word) {
            if (!node->containsKey(ch)) {
                node->put(ch, new Node());
            }
            node = node->get(ch);
        }
        node->setEnd();
    }

    bool search(const string& word) const {
        Node* node = root;
        for (char ch : word) {
            if (!node->containsKey(ch)) return false; // Illegal traversal
            node = node->get(ch);
        }
        return node->isEnd(); // Must end on a node with flag == true
    }

    bool startsWith(const string& prefix) const {
        Node* node = root;
        for (char ch : prefix) {
            if (!node->containsKey(ch)) return false;
            node = node->get(ch);
        }
        return true; // Parsed all prefix characters without hitting NULL
    }
};

    2. Multiplicity & Deletion: countWordsEqualTo, countWordsStartingWith & erase (Striver Lec 2)

    A single bool flag cannot distinguish inserting "samsung" once vs. twice, nor can it safely delete one copy of a word without breaking other words that share its prefix. Lecture 2 replaces bool flag with two integer counters inside every Node:

    • cntPrefix (# words having this node as prefix) — incremented at every character step during insert(word), and decremented at every step during erase(word).
    • cntEndWith (# words ending on this node) — incremented only on the final node after the loop finishes in insert(word), and decremented on the final node in erase(word).

    Handwritten Warning: Never Use cntPrefix in Place of cntEndWith!

    As emphasized at the bottom of 04_Striver_lec_2_countWordsEqualTo.pdf: "It's incorrect to use #_of_words_having_this_node_as_prefix as the counter of #_words_ending_on_this_node, because many words can have this node as prefix, but only a few (or none!) will end on this node." For instance, after inserting "samsung" twice, node 's'–'a'–'m' has cntPrefix == 2 even though "sam" was never inserted (cntEndWith == 0).

    Handwritten Operation Trace (samsung & vivo)

    1. insert("samsung") $\to$ nodes s,a,m,s,u,n,g get cntPrefix = 1; terminal g gets cntEndWith = 1.
    2. insert("samsung") $\to$ nodes s,a,m,s,u,n,g update to cntPrefix = 2; terminal g updates to cntEndWith = 2.
    3. insert("vivo") $\to$ nodes v,i,v,o get cntPrefix = 1; terminal o gets cntEndWith = 1.
    4. erase("vivo") $\to$ walk v,i,v,o decrementing each cntPrefix ($1 \to 0$) and terminal o's cntEndWith ($1 \to 0$).
    5. countWordsEqualTo("samsung") $\to$ reaches g, returns cntEndWith = 2.
    6. countWordsStartingWith("vi") $\to$ reaches i under v, returns cntPrefix = 0!
    struct CountNode {
    CountNode* links[26] = {nullptr};
    int cntEndWith = 0;
    int cntPrefix = 0;

    bool containsKey(char ch) const { return links[ch - 'a'] != nullptr; }
    CountNode* get(char ch) const { return links[ch - 'a']; }
    void put(char ch, CountNode* node) { links[ch - 'a'] = node; }
};

class TrieII {
    CountNode* root;
public:
    TrieII() : root(new CountNode()) {}

    void insert(const string& word) {
        CountNode* node = root;
        for (char ch : word) {
            if (!node->containsKey(ch)) node->put(ch, new CountNode());
            node = node->get(ch);
            node->cntPrefix++;
        }
        node->cntEndWith++;
    }

    int countWordsEqualTo(const string& word) const {
        CountNode* node = root;
        for (char ch : word) {
            if (!node->containsKey(ch)) return 0;
            node = node->get(ch);
        }
        return node->cntEndWith;
    }

    int countWordsStartingWith(const string& prefix) const {
        CountNode* node = root;
        for (char ch : prefix) {
            if (!node->containsKey(ch)) return 0;
            node = node->get(ch);
        }
        return node->cntPrefix;
    }

    void erase(const string& word) {
        if (countWordsEqualTo(word) == 0) return; // Guard if word isn't present
        CountNode* node = root;
        for (char ch : word) {
            node = node->get(ch);
            node->cntPrefix--;
        }
        node->cntEndWith--;
    }
};

    3. LeetCode 211: Design Add and Search Words Data Structure (Wildcard '.')

    In LeetCode 211, addWord(word) inserts lowercase words as usual (e.g. "apple", "ate", "axe", "aterus" in the handwritten tree), while search(word) may contain wildcard dots '.' that match any single letter (so "a.e" matches both "ate" and "axe", and "a...e" matches "apple").

    A single linear pointer no longer works because '.' branches across up to 26 children simultaneously. In the handwritten note, this multi-way branching is modeled with an explicit DFS stack stack = [(root, 0)]:

    • Pop (node, idx). If idx == word.size(), check node->flag—if true, return true immediately!
    • If word[idx] == '.', push (child, idx + 1) for every non-null child in node->links[0..25].
    • Otherwise, if node->links[word[idx] - 'a'] != nullptr, push that single child with idx + 1.

    Subtle Bug to Avoid in Iterative Stack DFS

    When writing the explicit stack loop from the sketch, if one popped branch hits a dead end (missing child or idx == n with node->flag == false—for example, exploring the "aterus" branch at "ate" when searching "a.z"), you must continue to inspect the remaining states still waiting on the stack—only returning false after the entire stack empties! Both the bug-free iterative stack DFS and recursive DFS are shown below:

    class WordDictionary {
    struct Node {
        Node* links[26] = {nullptr};
        bool flag = false;
    };
    Node* root;

    bool dfs(int idx, const string& word, Node* node) const {
        if (idx == (int)word.size()) return node->flag;

        char ch = word[idx];
        if (ch == '.') {
            for (int c = 0; c < 26; c++) {
                if (node->links[c] && dfs(idx + 1, word, node->links[c])) {
                    return true;
                }
            }
            return false;
        }
        Node* next = node->links[ch - 'a'];
        return next != nullptr && dfs(idx + 1, word, next);
    }

public:
    WordDictionary() : root(new Node()) {}

    void addWord(const string& word) {
        Node* node = root;
        for (char ch : word) {
            if (!node->links[ch - 'a']) node->links[ch - 'a'] = new Node();
            node = node->links[ch - 'a'];
        }
        node->flag = true;
    }

    // Iterative explicit-stack version directly mirroring the handwritten note
    bool searchIterative(const string& word) const {
        vector<pair<Node*, int>> st = {{root, 0}};
        int n = word.size();
        while (!st.empty()) {
            auto [cur, idx] = st.back();
            st.pop_back();
            if (idx == n) {
                if (cur->flag) return true;
                continue; // Keep checking other active branches on stack!
            }
            if (word[idx] == '.') {
                for (int c = 0; c < 26; c++) {
                    if (cur->links[c]) st.push_back({cur->links[c], idx + 1});
                }
            } else {
                Node* nxt = cur->links[word[idx] - 'a'];
                if (nxt) st.push_back({nxt, idx + 1});
            }
        }
        return false;
    }

    bool search(const string& word) const { return dfs(0, word, root); }
};

    4. LeetCode 1023: Camelcase Matching via Query-Trie Subtree Pruning

    Given an array of queries and a pattern, queries[i] matches pattern iff we can insert strictly lowercase letters into pattern to form queries[i]. In 03_Ques_1023.pdf, all five queries—0: "FooBar", 1: "FooBarTest", 2: "FootBall", 3: "FrameBuffer", 4: "ForceFeedBack"—are inserted into a single case-sensitive Trie (storing query indices at their terminal nodes) and traversed against pattern = "FB":

    Handwritten Level-by-Level State Trace on pattern = "FB"

    Tracking state (depth, edge_char, remaining_pattern) from the scan:

    • Depth 0: Edge 'F' matches pattern[0] = 'F' $\to$ state (0, 'F', remaining = "B").
    • Depth 1–2: Lowercase edges 'o' and 'r' do not match 'B', and since lowercase insertions are legal, they pass remaining = "B" unchanged down to (2, 'o', "B"), (2, 'r', "B"), (2, 'a', "B").
    • Branch Match: Whenever an edge hits 'B' while waiting for 'B' (e.g. FooBar at depth 3), remaining becomes empty ""! Subsequent lowercase suffixes like "ar" in FooBar [0], "all" in FootBall [2], and "uffer" in FrameBuffer [3] stay valid (true).
    • Uppercase Mismatch Prunes Subtree (marked with X in scan): In ForceFeedBack [4], depth 5 encounters uppercase 'F' while still waiting for 'B'—and in FooBarTest [1], depth 6 encounters uppercase 'T' when remaining == "". Because uppercase characters can never be freely inserted, we immediately prune that entire Trie branch!
    class Solution {
    struct TrieNode {
        unordered_map<char, TrieNode*> child;
        vector<int> queryIds; // Indices of queries ending at this node
    };

    void dfs(TrieNode* node, const string& pat, int pIdx, vector<bool>& ans) {
        if (pIdx == (int)pat.size()) {
            for (int id : node->queryIds) ans[id] = true;
        }
        for (auto& [ch, nxt] : node->child) {
            if (pIdx < (int)pat.size() && ch == pat[pIdx]) {
                // Matches next required character in pattern (upper or lower)
                dfs(nxt, pat, pIdx + 1, ans);
            } else if (islower(static_cast<unsigned char>(ch))) {
                // Extra lowercase character: allowed to skip without advancing pIdx
                dfs(nxt, pat, pIdx, ans);
            }
            // Else: unmatched uppercase character -> prune entire subtree!
        }
    }

public:
    vector<bool> camelMatch(vector<string>& queries, string pattern) {
        TrieNode* root = new TrieNode();
        for (int i = 0; i < (int)queries.size(); i++) {
            TrieNode* cur = root;
            for (char ch : queries[i]) {
                if (!cur->child[ch]) cur->child[ch] = new TrieNode();
                cur = cur->child[ch];
            }
            cur->queryIds.push_back(i);
        }

        vector<bool> ans(queries.size(), false);
        dfs(root, pattern, 0, ans);
        return ans;
    }
};
