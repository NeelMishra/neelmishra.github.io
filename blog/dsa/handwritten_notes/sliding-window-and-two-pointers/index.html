    Sliding Window & Two Pointers: Master Templates & Reading Guide

    October 2026 · 6 min read · Handwritten Notes

    Reading guide for handwritten competitive coding notes (01_Notes.pdf, 02_Striver_Constant_window.pdf, 03_Sliding_window_patterns.pdf)

    Nested brute-force loops over contiguous subarrays recompute overlapping state from scratch in $O(n^2)$ time. Whenever advancing the left boundary $i$ allows the optimal or boundary right pointer $j$ to only move forward ($i \le j$, each pointer advancing at most $n$ times), a two-pointer sliding window maintains the active window $[i \dots j]$ of length $j - i + 1$ in amortized $O(n)$ time.

    The 4 Master Sliding Window Templates at a Glance

    Every problem across these notes reduces to one of four canonical shapes depending on whether the window length is fixed, maximized, counted, or minimized:

    Template Window Goal Shrink Trigger Answer Update Classic Problems
    1. Constant Window Best window of exact size $k$ (or $k+1$ split ends) j - i + 1 == k (slide both i++, j++) ans = max(ans, state) Max Sum of Size $K$, LC 1423 Card Points, LC 1052 Grumpy Owner
    2. Longest Valid Subarray Maximize $j - i + 1$ obeying $\text{cost}(i..j) \le k$ while (invalid(i..j)) remove i++ ans = max(ans, j - i + 1) after shrinking LC 3, LC 424, LC 904, LC 1838, LC 2401, LC 1438
    3. Count Valid Subarrays Count subarrays with $\le k$, $\ge k$, or $== k$ Shrink until valid ($\le k$) or minimal ($\ge k$) ans += j - i + 1 (atMost)
    atMost(k) - atMost(k-1) (exact)    		 LC 713 Product < K, LC 930 Binary Sum, LC 1248 Nice, LC 1358
    4. Minimum Valid Window Minimize $j - i + 1$ satisfying $\text{valid}(i..j)$ while (valid(i..j)) record & shrink i++ ans = min(ans, j - i + 1) inside the while loop! LC 209 Min Subarray Sum, LC 76 Min Window Substring

    Compact C++ Skeletons for All 4 Templates

    // 1. Constant Window (size k)
long long cur = 0, best = LLONG_MIN;
for (int j = 0; j < n; ++j) {
    cur += a[j];
    if (j >= k) cur -= a[j - k];
    if (j >= k - 1) best = std::max(best, cur);
}

// 2. Longest Subarray with Monotonic Cost <= k
int best_len = 0;
for (int i = 0, j = 0; j < n; ++j) {
    add(a[j]);
    while (cost() > k) remove(a[i++]);
    best_len = std::max(best_len, j - i + 1);
}

// 3. Count Subarrays with Exact Cost == k (for non-negative costs)
auto atMost = [&](int limit) -> long long {
    if (limit < 0) return 0;
    long long cnt = 0;
    for (int i = 0, j = 0; j < n; ++j) {
        add(a[j]);
        while (cost() > limit) remove(a[i++]);
        cnt += (j - i + 1); // Every start in [i..j] ending at j is valid!
    }
    return cnt;
};
long long exact_k = atMost(k) - atMost(k - 1);

// 4. Minimum Window Satisfying a Requirement
int min_len = INT_MAX;
for (int i = 0, j = 0; j < n; ++j) {
    add(a[j]);
    while (satisfied()) {
        min_len = std::min(min_len, j - i + 1);
        remove(a[i++]);
    }
}
    When Does Plain Two-Pointer Monotonicity Break? Sliding window sum/product templates rely on monotonicity: expanding $[i..j]$ to $[i..j+1]$ never decreases the sum (all $a[x] \ge 0$) or product (all $a[x] \ge 1$), and shrinking $i \to i+1$ never increases it. When an array contains negative numbers (e.g., LC 560 Subarray Sum Equals K or LC 862 Shortest Subarray with Sum $\ge K$), shrinking $i$ can increase the sum—reach for prefix sums + hash map or a monotonic prefix-sum deque instead!
