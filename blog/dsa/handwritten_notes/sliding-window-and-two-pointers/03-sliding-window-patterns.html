    The 4 Sliding Window Patterns: Universal Formulas for Substring & Subarray Problems

    October 2026 · 10 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 03_Sliding_window_patterns.pdf

    Almost every variable-size substring or subarray problem in interviews and contests looks unique on the surface, yet reduces to one of four exact accumulator formulas once you identify the direction of monotonicity. This note expands the reference sheet in 03_Sliding_window_patterns.pdf with combinatorial proofs, visual geometry, step-by-step dry runs, and clean C++ templates for all four patterns.

    1. The 4 Patterns at a Glance

    Pattern Example Problem (from Note) Key Formula Monotonicity Direction
    1. Longest valid window Longest substring with $\le k$ distinct characters (LC 340 / LC 904) ans = max(ans, window)
    where window = j - i + 1    		 Closed under shrinking ("at most $k$"); maximize length at each $j$
    2. Count windows ending at j Subarrays with $\le k$ odds / product $\lt k$ (LC 713) ans += j - i + 1 Closed under shrinking: if $[i..j]$ is valid, every suffix $[l..j]$ ($i \le l \le j$) is valid
    3. Count windows starting at i Substrings containing all of a, b, c (LC 1358) ans += n - j Closed under extending: once $[i..j]$ is valid, every extension $[i..r]$ ($j \le r \lt n$) is valid
    4. Exactly $k$ Count Number of Nice Subarrays ($k$ odds, LC 1248) atMost(k) - atMost(k - 1) Set difference reduces non-monotonic exact equality to two Pattern-2 passes

    2. Pattern 1: Longest Valid Window — ans = max(ans, j - i + 1)

    Canonical Problem: Given string $s$ and integer $k$, find the length of the longest substring containing at most $k$ distinct characters (LC 340; $k = 2$ is LC 904 Fruit Into Baskets, $k = \text{all unique}$ is LC 3).

    Why it works: For each right index $j$, we advance $i$ only while $\text{distinct}(s[i..j]) \gt k$. The moment the while loop exits, $i$ is the smallest index making $s[i..j]$ valid—so $j - i + 1$ is the exact maximum valid window ending at $j$. Taking the maximum across all $j \in [0, n - 1]$ examines the optimal candidate for every possible right endpoint.

    Dry run on s = "eceba", $k = 2$:

    • j = 0 ('e'): {e:1} $\implies$ [0..0] = "e", length $= 1$, ans = 1.
    • j = 1 ('c'): {e:1, c:1} $\implies$ [0..1] = "ec", length $= 2$, ans = 2.
    • j = 2 ('e'): {e:2, c:1} $\implies$ [0..2] = "ece", length $= 3$, ans = 3.
    • j = 3 ('b'): {e:2, c:1, b:1} ($3 \gt 2$ distinct) $\implies$ shrink i = 0 ('e') $\to$ i = 1 ('c') $\to$ i = 2 leaves {e:1, b:1}, [2..3] = "eb", length $= 2$, ans = 3.
    • j = 4 ('a'): {e:1, b:1, a:1} ($3 \gt 2$) $\implies$ shrink i = 2 ('e') leaves {b:1, a:1}, [3..4] = "ba", length $= 2$, final ans = 3.
    #include <algorithm>
#include <string>

int longestSubstringAtMostKDistinct(const std::string& s, int k) {
    if (k == 0) return 0;
    int freq[256] = {0};
    int distinct = 0, ans = 0;

    for (int i = 0, j = 0; j < static_cast<int>(s.size()); ++j) {
        if (freq[static_cast<unsigned char>(s[j])]++ == 0) {
            ++distinct;
        }
        while (distinct > k) {
            if (--freq[static_cast<unsigned char>(s[i++])] == 0) {
                --distinct;
            }
        }
        ans = std::max(ans, j - i + 1); // Pattern 1: max valid window
    }
    return ans;
}

    3. Pattern 2: Count Windows Ending at j — ans += j - i + 1

    Canonical Problem: Count contiguous subarrays containing at most $k$ odd numbers (or having product $\lt k$ in LC 713 with positive integers).

    Combinatorial Proof of ans += j - i + 1

    An "at most $k$" property is hereditary (closed under taking subsets): if subarray $[i..j]$ has at most $k$ odd elements, then removing elements from the left cannot increase the odd count. Because $i$ was advanced just past the rightmost invalid position, the valid subarrays ending at index $j$ are precisely:

    $$[i..j],\; [i + 1..j],\; [i + 2..j],\; \dots,\; [j..j]$$

    How many left endpoints lie in $\{i, i + 1, \dots, j\}$? Exactly $j - i + 1$! And because two subarrays with different right endpoints $j_1 \ne j_2$ can never be the same subarray, summing $j - i + 1$ across $j = 0 \dots n - 1$ counts every valid subarray once and only once.

    #include <vector>

long long countAtMostKOdds(const std::vector<int>& nums, int k) {
    if (k < 0) return 0;
    long long ans = 0;
    int odds = 0;

    for (int i = 0, j = 0; j < static_cast<int>(nums.size()); ++j) {
        odds += (nums[j] & 1);
        while (odds > k) {
            odds -= (nums[i++] & 1);
        }
        ans += (j - i + 1); // Pattern 2: all valid suffixes ending at j
    }
    return ans;
}

    4. Pattern 3: Count Windows Starting at i — ans += n - j

    Canonical Problem: Given a string $s$ consisting only of 'a', 'b', and 'c', return the number of substrings containing at least one occurrence of all three characters (LC 1358).

    Combinatorial Proof of ans += n - j

    An "at least" requirement is upward-closed (closed under extending): as $j$ scans left-to-right, suppose $j$ is the first index where $[i..j]$ contains all three characters 'a', 'b', and 'c'. Appending extra characters on the right can never erase an already-present character! Therefore, for this fixed left boundary $i$, the valid substrings starting at $i$ are precisely:

    $$[i..j],\; [i..j + 1],\; [i..j + 2],\; \dots,\; [i..n - 1]$$

    There are $(n - 1) - j + 1 = \mathbf{n - j}$ such right endpoints. We add n - j to ans and immediately increment i++ inside the while (valid) loop—retiring start index $i$ forever so it can never be counted again!

    Dry run on s = "abcabc" ($n = 6$):

    • j = 0 ('a'), j = 1 ('b'): missing 'c' $\implies$ loop doesn't fire.
    • j = 2 ('c'): [0..2] = "abc" is valid! Add $n - j = 6 - 2 = \mathbf{4}$ (counts "abc", "abca", "abcab", "abcabc" starting at $i = 0$), shrink $i \to 1$ ("bc", invalid).
    • j = 3 ('a'): [1..3] = "bca" is valid! Add $6 - 3 = \mathbf{3}$ (starting at $i = 1$), shrink $i \to 2$.
    • j = 4 ('b'): [2..4] = "cab" is valid! Add $6 - 4 = \mathbf{2}$ (starting at $i = 2$), shrink $i \to 3$.
    • j = 5 ('c'): [3..5] = "abc" is valid! Add $6 - 5 = \mathbf{1}$ (starting at $i = 3$), shrink $i \to 4$.
    • Total $= 4 + 3 + 2 + 1 = \mathbf{10}$.
    #include <string>

int numberOfSubstrings(const std::string& s) {
    int n = static_cast<int>(s.size());
    int freq[3] = {0, 0, 0};
    long long ans = 0;

    for (int i = 0, j = 0; j < n; ++j) {
        ++freq[s[j] - 'a'];
        while (freq[0] > 0 && freq[1] > 0 && freq[2] > 0) {
            ans += (n - j);     // Pattern 3: all extensions [i..j .. i..n-1]
            --freq[s[i++] - 'a'];
        }
    }
    return static_cast<int>(ans);
}

    5. Pattern 4: Exactly $K$ — atMost(k) - atMost(k - 1)

    Canonical Problem: Given integer array nums and integer $k$, return the number of nice subarrays containing exactly $k$ odd numbers (LC 1248; also LC 930 Binary Subarrays With Sum $== k$ and LC 992 Subarrays with $K$ Different Integers).

    Why a Single Two-Pointer Loop Stalls on cost == k

    Consider nums = [2, 2, 1, 2, 1, 2] with $k = 2$ odds. At $j = 4$, three different left pointers ($i = 0, 1, 2$) all give odds == 2 because even numbers contribute $0$ to the odd count! If you shrink $i$ past the zero-cost evens at $j = 4$, you lose them when $j$ advances to $5$ (which is also even!). Thus cost == k is neither closed under shrinking nor closed under extending.

    Instead of juggling three pointers $(i_{\min}, i_{\max}, j)$, express exact equality as the set difference of two hereditary ("at most") sets:

    $$\#\{\text{subarrays with cost} == k\} = \#\{\text{subarrays with cost} \le k\} - \#\{\text{subarrays with cost} \le k - 1\}.$$

    Dry run on nums = [1, 1, 2, 1, 1], $k = 3$:

    • atMost(3): for $j = 0..4$, valid window sizes $j - i + 1$ are $1 + 2 + 3 + 4 + 4 = \mathbf{14}$.
    • atMost(2): for $j = 0..4$, valid window sizes $j - i + 1$ are $1 + 2 + 3 + 3 + 3 = \mathbf{12}$.
    • exact(3) = atMost(3) - atMost(2) = 14 - 12 = 2 (specifically [1, 1, 2, 1] and [1, 2, 1, 1]).
    #include <vector>

int numberOfSubarrays(const std::vector<int>& nums, int k) {
    auto atMost = [&](int maxOdds) -> long long {
        if (maxOdds < 0) return 0; // Crucial guard when k == 0!
        long long count = 0;
        int odds = 0;
        for (int i = 0, j = 0; j < static_cast<int>(nums.size()); ++j) {
            odds += (nums[j] & 1);
            while (odds > maxOdds) {
                odds -= (nums[i++] & 1);
            }
            count += (j - i + 1);
        }
        return count;
    };

    return static_cast<int>(atMost(k) - atMost(k - 1));
}

    6. Complexity Proof & Subtle Edge Cases

    • Time Complexity — $\mathcal{O}(n)$ amortized: Even though there is a while loop nested inside the for (int j = 0; j < n; ++j) loop, the left pointer $i$ starts at $0$, is only ever incremented, and never exceeds $n$. Therefore i++ executes at most $n$ times across the entire run, giving at most $2n$ pointer steps ($\mathcal{O}(n)$ time; $\mathcal{O}(4n) = \mathcal{O}(n)$ for Pattern 4).
    • Space Complexity — $\mathcal{O}(1)$ (for fixed alphabet arrays or scalar counters) or $\mathcal{O}(\min(n, |\Sigma|))$ with a hash map of distinct elements.
    Three Edge Cases That Catch Candidates
    1. $k = 0$ in atMost(k) - atMost(k - 1): For LC 930 (goal = 0 binary sum), atMost(k - 1) calls atMost(-1)! Without if (limit < 0) return 0; at the top of atMost, while (sum > -1) increments i past j + 1 and reads out-of-bounds memory!
    2. long long for Subarray Counts: An array of length $n = 10^5$ has $\frac{n(n + 1)}{2} \approx 5 \times 10^9$ total subarrays, which overflows signed 32-bit int ($2.14 \times 10^9$). Always accumulate ans in long long.
    3. Negative Numbers Break Window Monotonicity: For subarray sum problems with negative integers (e.g., LC 560 Subarray Sum Equals $K$), expanding $j$ can decrease the sum and shrinking $i$ can increase it, so atMost(k) - atMost(k - 1) does not apply—use prefix sums + hash map instead.
