    Monotonic Stack: Handwritten Notes & Complete Template Guide

    October 2026 · 5 min read · 3-Part Series (6 Handwritten Pages)

    Expanded from MonotonicStack_01_A_comprehensive_guide_and_template_for_monotonic_stack_based_problems.pdf (6 pages)

    Whenever a problem asks for the nearest element to the left or right that is strictly larger or strictly smaller than `arr[i]`, brute-force nested loops take $\mathcal{O}(n^2)$ time. A monotonic stack solves all four boundary queries in a single left-to-right pass in $\mathcal{O}(n)$ time and $\mathcal{O}(n)$ space—using one unified outer-for / inner-while template where only the comparison operator (`<`, `<=`, `>`, `>=`) and assignment position (inside vs. outside the `while` loop) change.

    Master Reference Table (Left-to-Right Pass)

    Assuming we always traverse the array from left to right ($i = 0 \to n - 1$) and treat the rightmost element as the stack top:

    Comparison operator and assignment location for all four strict nearest-boundary queries.
    Problem Stack Variant while Pop Condition Assignment Position
    Next Greater Element (NGE) Monotone Decreasing (equal allowed / Type 4) arr[stack.top()] < arr[i] Inside while loop (on popped index)
    Previous Greater Element (PGE) Monotone Decreasing (strict / Type 3) arr[stack.top()] <= arr[i] Outside while loop (for index i)
    Next Smaller Element (NSE) Monotone Increasing (equal allowed / Type 2) arr[stack.top()] > arr[i] Inside while loop (on popped index)
    Previous Smaller Element (PSE) Monotone Increasing (strict / Type 1) arr[stack.top()] >= arr[i] Outside while loop (for index i)
