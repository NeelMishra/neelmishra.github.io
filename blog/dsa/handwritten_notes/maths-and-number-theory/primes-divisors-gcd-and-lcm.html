    Primes, Divisors, GCD & LCM: Brute Force to Optimal

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (02_TUF_CHECK_FOR_PRIME_NUMBER.pdf, 03_TUF_GCD_OF_TWO_NUMBERS.pdf, 04_TUF_LCM_of_two_numbers.pdf, 05_TUF_divisor_of_a_number.pdf)

    Four foundational primitives show up in nearly every number theory problem: testing whether $n$ is prime, listing all divisors of $n$, computing $\gcd(a, b)$, and computing $\operatorname{lcm}(a, b)$. Walking each primitive through its Brute $\to$ Better $\to$ Optimal progression clarifies both the $\sqrt{n}$ symmetry barrier for multiplicative pairs and the logarithmic compression of Euclid's modulo step.

    1. Check for Prime Number ($O(n) \to O(\sqrt{n})$)

    A positive integer $n \gt 1$ is prime if its only positive divisors are $1$ and $n$ itself (note that $0$ and $1$ are not prime). For example, $n = 5$ returns true (divisors $1, 5$), whereas $n = 8$ returns false (divisors $1, 2, 4, 8$).

    Brute Force — $O(n)$ Scan

    Test every integer $i \in [2, n - 1]$. If n % i == 0 for any $i$, $n$ has a proper divisor and we immediately return false; if the loop finishes without finding a divisor, return true.

    • Time Complexity: $O(n)$ (hits all $n - 2$ iterations whenever $n$ is prime).
    • Space Complexity: $O(1)$.

    Optimal — Factor-Pair Symmetry on $n = 36$ ($O(\sqrt{n})$)

    Why scan past $\sqrt{n}$? Inspect all complementary factor pairs $a \times b = 36$ from the handwritten note:

    bool isPrime(long long n) {
    if (n <= 1) return false;
    if (n <= 3) return true;
    if (n % 2 == 0 || n % 3 == 0) return false;

    // Check up to i * i <= n using integer multiplication (avoids float precision drift)
    for (long long i = 2; i * i <= n; i++) {
        if (n % i == 0) return false;
    }
    return true;
}
// Time Complexity: O(sqrt(n))   |   Space Complexity: O(1)

    2. Enumerating All Divisors of a Number

    The exact same $i \le \sqrt{n}$ symmetry collects all positive divisors of $n$ in a single pass—with one essential boundary check for perfect squares:

    1. Loop $i$ from $1$ while $i \times i \le n$.
    2. If $i$ divides $n$ (r == 0), append $i$ to the divisor list.
    3. Also append its partner quotient $q = n / i$, provided $i \neq q$ so we never push $\sqrt{n}$ twice when $n$ is a perfect square (such as $6$ in $n = 36$).
    4. Sort the collected list at the end if ascending order is required.
    # Python implementation from the handwritten note (using divmod)
class Solution:
    def divisors(self, n: int) -> list[int]:
        res = []
        i = 1
        # Include i * i == n so we catch the square-root divisor
        while i * i <= n:
            q, r = divmod(n, i)
            if r == 0:
                res.append(i)
                # Avoid duplicating the square-root twice (e.g., 6 * 6 == 36)
                if i != q:
                    res.append(q)
            i += 1
        res.sort()
        return res
    // Equivalent C++ implementation
vector<long long> getDivisors(long long n) {
    vector<long long> res;
    for (long long i = 1; i * i <= n; i++) {
        if (n % i == 0) {
            res.push_back(i);
            if (i != n / i) {
                res.push_back(n / i);
            }
        }
    }
    sort(res.begin(), res.end());
    return res;
}
    Exact Divisor Enumeration Complexity Let $K = d(N)$ denote the total number of divisors of $N$ (crudely bounded by $K \le 2\sqrt{N}$, and asymptotically $N^{o(1)}$; for $N \le 10^9$, $\max d(N) = 1344$).
    • Time Complexity: $O(\sqrt{N}) + O(K \log K)$ — $\lfloor\sqrt{N}\rfloor$ loop iterations of $O(1)$ arithmetic plus sorting $K$ divisors. (Tip: pushing small divisors to low and quotients $n/i$ to high, then reversing high, even eliminates the $O(K \log K)$ sort!)
    • Space Complexity: $O(K) \subseteq O(\sqrt{N})$ to store the output array.

    3. GCD of Two Numbers ($O(\min(n_1, n_2)) \to O(\log(\min(n_1, n_2)))$)

    The Greatest Common Divisor (GCD) or Highest Common Factor (HCF) of two integers $n_1, n_2$ is the largest positive integer that divides both without leaving a remainder.

    Brute Force vs. Backward Scan ("Better Approach")

    • Brute Force (Forward $1 \to \min(n_1, n_2)$): Initialize gcd = 1, iterate num from $2$ to $\min(n_1, n_2)$, and overwrite gcd = num whenever n1 % num == 0 && n2 % num == 0. Always performs $\min(n_1, n_2)$ checks.
    • Better Approach (Backward $\min(n_1, n_2) \to 1$ with early break): Start from $\min(n_1, n_2)$ down to $1$; the first common divisor encountered is guaranteed to be the largest, so break immediately! While this runs in $O(1)$ when one number divides the other (e.g. $\gcd(12, 36) = 12$), the worst-case time complexity remains $O(\min(n_1, n_2))$ whenever $n_1$ and $n_2$ are coprime ($\gcd = 1$, e.g. $\gcd(10^9, 10^9 - 1)$).
    # Brute-force Python snippet from the handwritten note
class Solution:
    def GCD(self, n1: int, n2: int) -> int:
        gcd = 1
        for num in range(2, min(n1, n2) + 1):
            if not n1 % num and not n2 % num:
                gcd = num
        return gcd

    Most Optimal — Euclidean Algorithm (Subtraction $\to$ Modulo)

    Euclid's principle states that the GCD of two numbers remains unchanged when the smaller number is subtracted from the larger: $\gcd(a, b) = \gcd(a - b, b)$ for $a \ge b$. Tracing the two handwritten dry runs:

    Handwritten Euclidean Subtraction Traces & Modulo Upgrade

    Trace 1: $\gcd(1, 1) \to \gcd(1 - 1, 1) = \gcd(0, 1) \to \mathbf{1}$.

    Trace 2: $\gcd(7, 2) = \gcd(5, 2) = \gcd(3, 2) = \gcd(1, 2) = \gcd(1, 1) = \gcd(1, 0) = \mathbf{1}$.

    Notice how subtracting $2$ from $7$ three consecutive times ($7 \to 5 \to 3 \to 1$) simply computes the remainder $7 \bmod 2 = 1$! Replacing repeated subtraction with a single modulo jump collapses $\gcd(10^9, 2)$ from $5 \times 10^8$ subtractions down to one division:

    $$\gcd(a, b) = \gcd(b,\, a \bmod b)$$

    Core Fact: Why Does $\gcd(a, 0) = a$ (and $\gcd(0, b) = b$)?

    1. "$\gcd$" means the largest integer that divides both arguments.
    2. Every integer divides $0$: because $0 = a \times 0$, we have $a \mid 0$ for every $a \gt 0$.
    3. Consequently, $0$ imposes zero restriction—the common divisors of $\{a, 0\}$ are element-for-element the divisors of $a$.
    4. The largest divisor of $a \gt 0$ is $a$ itself, so $\gcd(a, 0) = a$!
    // Iterative O(1)-space Euclidean GCD in C++
long long gcd(long long a, long long b) {
    while (b != 0) {
        a %= b;
        swap(a, b);
    }
    return a; // Once b becomes 0, the remaining non-zero value is the GCD
}
// Time Complexity: O(log(min(n1, n2)))   |   Space Complexity: O(1)

    4. LCM of Two Numbers & Overflow Prevention

    The Least Common Multiple (LCM) of two positive integers $a$ and $b$ is the smallest positive integer divisible by both $a$ and $b$. Using the fundamental product identity derived in Part 1:

    Optimal LCM Formula

    $$a \times b = \operatorname{lcm}(a, b) \times \gcd(a, b) \implies \operatorname{lcm}(a, b) = \frac{a}{\gcd(a, b)} \times b$$

    Contest Pitfall: Multiply-Before-Divide Integer Overflow

    In the handwritten math formula $\frac{a \times b}{\gcd(a, b)}$, computing (a * b) / gcd(a, b) in C++ evaluates a * b first. If $a = b = 10^9$, then $a \times b = 10^{18}$ overflows 32-bit int (and if $a, b = 10^{12}$ with $\gcd = 10^9$, $a \times b = 10^{24}$ overflows 64-bit long long even though the true LCM $10^{15}$ fits comfortably!). Since $\gcd(a, b)$ divides $a$ evenly without remainder, always divide before multiplying: (a / gcd(a, b)) * b.

    long long lcm_safe(long long a, long long b) {
    if (a == 0 || b == 0) return 0;
    return (a / std::gcd(a, b)) * b; // Exact integer division first, then multiply
}
// Time Complexity: O(log(min(a, b)))   |   Space Complexity: O(1)
