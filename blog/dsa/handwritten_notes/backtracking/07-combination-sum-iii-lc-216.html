    Combination Sum III (LeetCode 216): Fixed-$k$ Digit Pool & the $O(2^9 + kS)$ Bound

    October 2026 · 6 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 07_Combination_sum_III.pdf

    After proving in Combination Sum II that level $d$ of a single-use combination tree over $m$ items contains $\binom{m}{d}$ nodes, Combination Sum III puts that formula directly to work on a fixed candidate pool {1, 2, ..., 9} capped at depth $k$.

    Problem Statement

    LeetCode 216 · Combination Sum III

    Find all valid combinations of $k$ numbers that sum up to $n$ such that:

    • Only digits 1 through 9 are used.
    • Each digit is used at most once.

    Examples from note:

    • k = 3, n = 7 → [[1, 2, 4]] ($1 + 2 + 4 = 7$).
    • k = 3, n = 9 → [[1, 2, 6], [1, 3, 5], [2, 3, 4]].

    Intuition & Four-Way Pruning on {1..9}

    Because the candidate pool is always 1, 2, ..., 9—already sorted and strictly distinct!—we don't need to sort an input array or check for duplicate siblings. Instead, at call dfs(start, k, rem) where we still need $r = k - |\text{path}|$ digits from start .. 9, we can prune aggressively:

    1. Exact depth cap (path.size() == k): Never recurse past depth $k$; emit path iff rem == 0.
    2. Sorted value cutoff (d > rem): Since digits increase start, start + 1, ..., 9, as soon as d > rem, break.
    3. Remaining pool size cutoff (9 - d + 1 < r): If fewer than $r$ digits remain in {d, ..., 9}, we can never reach size $k$—break!
    4. Minimum / maximum arithmetic sum bounds (optional tightest prune): The smallest sum of $r$ digits starting at $d$ is $\sum_{t=0}^{r-1}(d + t) = r \cdot d + \frac{r(r-1)}{2}$ (if $> \text{rem}$, break), and the largest possible sum of $r$ digits from {1..9} is $\sum_{t=0}^{r-1}(9 - t) = r \cdot 9 - \frac{r(r-1)}{2}$ (if $< \text{rem}$, return early!).

    Dry Run on k = 3, n = 9

    Prefix path start rem Action Across Digits d = start..9
    [1, 2]36Tries 3 (rem=3, depth 3 ≠ 0), 4, 5, hits d = 6 → [1, 2, 6] ✓, then d = 7 > 6 breaks!
    [1, 3]45Tries 4 (rem=1), hits d = 5 → [1, 3, 5] ✓, then d = 6 > 5 breaks!
    [1, 4]54First digit d = 5 > rem = 4 → breaks immediately! ([1, 5..] also breaks via min-sum)
    [2, 3]44Hits d = 4 → [2, 3, 4] ✓, then d = 5 > 4 breaks!
    [3, ...]46Min sum of 2 digits from 4..9 is $4 + 5 = 9 > 6$ → entire [3, ...] subtree prunes!

    Clean C++ & Python Implementations

    #include <vector>
using namespace std;

class Solution {
    void dfs(int start, int k, int rem,
             vector<int>& path, vector<vector<int>>& ans) {
        int need = k - (int)path.size();
        if (need == 0) {
            if (rem == 0) ans.push_back(path);  // O(k) copy at each of the S valid leaves
            return;
        }

        // Max possible sum using the `need` largest digits {10 - need .. 9}
        int maxPossible = need * 9 - need * (need - 1) / 2;
        if (rem > maxPossible) return;

        for (int d = start; d <= 9; ++d) {
            if (9 - d + 1 < need) break;        // not enough digits left in {d..9}
            int minPossible = need * d + need * (need - 1) / 2;
            if (minPossible > rem) break;       // even smallest `need` digits >= d exceed rem!

            path.push_back(d);
            dfs(d + 1, k, rem - d, path, ans);
            path.pop_back();
        }
    }

public:
    vector<vector<int>> combinationSum3(int k, int n) {
        if (k < 1 || k > 9 || n > 45) return {};  // 1 + 2 + ... + 9 = 45
        vector<vector<int>> ans;
        vector<int> path;
        path.reserve(k);
        dfs(1, k, n, path, ans);
        return ans;
    }
};
    class Solution:
    def combinationSum3(self, k: int, n: int) -> list[list[int]]:
        ans: list[list[int]] = []
        path: list[int] = []

        def dfs(start: int, rem: int) -> None:
            need = k - len(path)
            if need == 0:
                if rem == 0:
                    ans.append(path[:])
                return
            for d in range(start, 10):
                if d > rem or 9 - d + 1 < need:
                    break
                path.append(d)
                dfs(d + 1, rem - d)
                path.pop()

        dfs(1, n)
        return ans

    Time & Space Complexity Proof (07_Combination_sum_III.pdf)

    Reproducing the exact derivation from 07_Combination_sum_III.pdf:

    • Maximum recursion depth: $k$ (we pick $1^{\text{st}}, 2^{\text{nd}}, \dots, k^{\text{th}}$ digit → $O(k)$ stack depth).
    • Nodes at each level: Since the available pool {1, ..., 9} has size $9$, depth $d \in \{0, \dots, k\}$ has at most $\binom{9}{d}$ nodes. Summing up to depth $k$: $$\text{Total Nodes} \le \sum_{d=0}^{k} \binom{9}{d} \le \sum_{d=0}^{9} \binom{9}{d} = 2^9 = 512.$$
    • Work per node + valid leaf copies: Each internal node runs for (j = i; j <= 9; j++) ($O(9) = O(1)$ work). Let $S$ be the number of valid combinations emitted; copying each $k$-tuple takes $O(k)$: $$\text{Total Time} = O\!\left(\sum_{d=0}^{k} \binom{9}{d} + k \cdot S\right) \subseteq O(2^9 + k \cdot S) = O(1) \text{ bounded!}$$
    • Space Complexity: $O(k)$ auxiliary recursion stack and path; $O(k \cdot S)$ for the result list.

    Key Edge Cases

    • Impossible sums ($n > 45$ or $n < \frac{k(k+1)}{2}$): The sum of all 9 digits $1 + 2 + \dots + 9 = 45$ (e.g., LeetCode's k = 4, n = 1 has minimum sum $1 + 2 + 3 + 4 = 10 > 1$, returning [] in zero recursive calls with our arithmetic-sum guard).
    • $k = 9, n = 45$: Returns the unique full-pool tuple [[1, 2, 3, 4, 5, 6, 7, 8, 9]].
