    Propagating Truth Values in Backtracking: Short-Circuit OR & Trie Word Break

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 10_Propogating_truth_values.pdf

    Most enumeration backtracking helpers use void dfs(...) because every valid leaf must be visited and pushed into an output array. Decision and single-witness problems—“Can this string be segmented into dictionary words?”, “Does this word exist in the grid?”, or “Fill this Sudoku board with its unique solution”—need a completely different control flow: bubbling a bool truth value up the call stack so the first valid leaf halts the entire search immediately. 10_Propogating_truth_values.pdf highlights LeetCode 139 (Word Break on the Trie problem list) as the canonical blueprint for propagating a valid truth value across indices.

    The Three Return Contracts in Backtracking

    Deciding your recursive signature before writing line 1.
    Contract Signature At Goal Leaf Inside Choice Loop Canonical Problems
    1. Enumerate All void dfs(...) ans.push_back(path); return; Always finish all iterations; always undo Subsets, Permutations, N-Queens
    2. Existence / Witness bool dfs(...) return true; if (dfs(next)) return true; (short-circuit OR!) Word Break (LC 139), Word Search, Sudoku Solver (LC 37)
    3. Count Ways int dfs(...) return 1; ways += dfs(next); (sum over children) Comb Sum IV, Target Sum

    The #1 Bug When Switching From void to bool: Unconditional Early return

    Never write return dfs(next); unconditionally inside a choice loop! Doing so turns a multi-branch tree into a single path that gives up the moment its very first child returns false: 
    // WRONG: checks j = i ONLY, abandoning all remaining siblings j > i!
for (int next : validChoices(state)) {
    return dfs(next);  // BUG: if 1st child fails, siblings are never tried!
}

// RIGHT: logical OR across children — return early ONLY on true!
for (int next : validChoices(state)) {
    apply(state, next);
    if (dfs(next)) return true;  // short-circuit upward on first winner!
    undo(state, next);           // restore state on dead end, keep trying siblings
}
return false;                    // return false ONLY after ALL choices fail

    Core Case Study (10_Propogating_truth_values.pdf): Word Break (LC 139) with a Trie

    LeetCode 139 · Word Break (Trie + Truth Propagation)

    Given a string s of length $n$ and a dictionary of strings wordDict, return true if s can be segmented into a space-separated sequence of one or more dictionary words.

    Insert every word in wordDict into a Trie, and define the boolean predicate:

    $$f(i) = \text{“Can the suffix } s[i \dots n - 1] \text{ be validly segmented?”} = \bigvee_{\substack{i \le j \lt n \\ s[i..j] \in \text{Trie}}} f(j + 1), \qquad f(n) = \text{true}.$$

    Trace how all four pieces cooperate inside canBreak(i):

    1. Base truth at the end of the string (i == n): An empty remaining suffix requires zero words → return true.
    2. Trie prefix pruning: Walk characters s[j] ($j = i, i + 1, \dots$) down Trie edges starting from the Trie root. The instant trie[cur].next[s[j] - 'a'] == -1, break—no longer substring starting at index i can exist in the dictionary!
    3. Upward truth propagation at word boundaries: Whenever trie[cur].isEnd is true, s[i..j] is a valid dictionary word, so we recurse on the remaining suffix starting at j + 1. If canBreak(j + 1) returns true, that true bubbles straight up j + 1 → i → ... → 0!
    4. Caching failed indices (memo[i] = 0): Unlike Word Search—where visited cells depend on the path taken—whether suffix s[i..] can be segmented depends only on index i! Without memo[i], adversarial inputs like s = "aaaa...aaab" with wordDict = ["a", "aa", "aaa"] re-fail at every suffix $2^n$ times; with memo[i], each starting index $i \in [0, n - 1]$ walks the Trie at most once!

    Clean C++ Implementations: Trie Word Break & In-Place Witness (Sudoku)

    #include <algorithm>
#include <cstdint>
#include <string>
#include <vector>
using namespace std;

// 1. Word Break (LC 139): Trie + short-circuit bool propagation + memo[i]
class SolutionWordBreak {
    struct TrieNode {
        int next[26];
        bool isEnd = false;
        TrieNode() { fill(begin(next), end(next), -1); }
    };

public:
    bool wordBreak(string s, vector<string>& wordDict) {
        vector<TrieNode> trie(1);
        for (const string& w : wordDict) {
            int cur = 0;
            for (char c : w) {
                int idx = c - 'a';
                if (trie[cur].next[idx] == -1) {
                    trie[cur].next[idx] = (int)trie.size();
                    trie.emplace_back();
                }
                cur = trie[cur].next[idx];
            }
            trie[cur].isEnd = true;
        }

        int n = (int)s.size();
        vector<int8_t> memo(n, -1);  // -1: unvisited, 0: false, 1: true

        auto canBreak = [&](auto& self, int i) -> bool {
            if (i == n) return true;              // base truth value at end of s
            if (memo[i] != -1) return memo[i];

            int cur = 0;
            for (int j = i; j < n; ++j) {
                cur = trie[cur].next[s[j] - 'a'];
                if (cur == -1) break;             // Trie prefix prune!
                if (trie[cur].isEnd && self(self, j + 1)) {
                    return memo[i] = 1;           // bubble true straight up!
                }
            }
            return memo[i] = 0;                   // cache dead-end index
        };

        return canBreak(canBreak, 0);
    }
};

    Bonus Nuance: Undo vs. Keep on return true (Sudoku Solver, LC 37)

    When a bool dfs(...) problem asks you to fill a board in-place with its solution (like Sudoku Solver, LC 37), notice how if (dfs(idx + 1, board)) return true; intentionally skips the undo block so the winning digit placements remain written in board all the way back to the caller—whereas dead-end digits fall through and undo cleanly:

    // Inside Sudoku Solver's choice loop at empty cell (r, c):
for (int d = 0; d < 9; ++d) {
    int bit = 1 << d;
    if (usedMask & bit) continue;

    board[r][c] = static_cast<char>('1' + d);
    rowMask[r] |= bit; colMask[c] |= bit; boxMask[b] |= bit;

    if (dfs(idx + 1, board)) return true;  // KEEP winning board intact!

    // UNDO only when branch returned false:
    rowMask[r] ^= bit; colMask[c] ^= bit; boxMask[b] ^= bit;
    board[r][c] = '.';
}
return false;

    Time & Space Complexity (Trie Word Break)

    • Trie Build Time & Space: $O\bigl(\sum_{w \in \text{wordDict}} |w|\bigr)$ nodes (with 26-way transitions).
    • Search Time Complexity: Each starting index $i \in \{0, \dots, n - 1\}$ is evaluated at most once thanks to memo[i], and walks at most $L_{\max} = \max_{w} |w|$ Trie edges before either reaching n or hitting cur == -1: $$\text{Total Time} = O\!\left(\sum_{w \in \text{wordDict}} |w| + n \cdot \min(n, L_{\max})\right).$$ Notice this beats substring-hashing DP ($O(n \cdot L_{\max}^2)$) by an entire factor of $L_{\max}$ because walking one character deeper in the Trie is $O(1)$ rather than hashing a length-$L$ substring!
    • Auxiliary Space: $O\bigl(n + \sum |w|\bigr)$ for the recursion stack, memo array, and Trie.
