    Propagating Truth Values & Curated Backtracking Question Bank

    October 2026 · 11 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (10_Propogating_truth_values.pdf, 11_Question_banks.pdf)

    In Parts 1–3, nearly every helper had signature void dfs(...) because we needed to visit every valid leaf and append it to an output vector. A second major family of backtracking problems asks a decision or single-witness question: Does at least one valid segmentation/path exist? or Fill this board with the unique solution and stop immediately! Switching from void accumulation to bool truth-value propagation lets a single winning leaf short-circuit millions of dead branches—provided you handle sibling loops, state cleanup, and failed-index caching properly.

    1. Propagating Truth Values Up a Recursion Tree

    Choosing the right return contract before writing line 1 of recursion.
    Contract Signature At Goal Leaf Inside Choice Loop Representative Problems
    Enumerate All void dfs(...) ans.push_back(path); return; Always finish all iterations; always undo after call Subsets I/II, Permutations, Comb Sum I–III, N-Queens, Palindrome Partitioning
    Existence / Witness bool dfs(...) return true; if (dfs(next)) return true; (short-circuit OR!) Word Break (LC 139), Word Search (LC 79), Sudoku Solver (LC 37), Matchsticks (LC 473)
    Count Ways int dfs(...) return 1; ways += dfs(next); (often memoizable!) Combination Sum IV (LC 377), Target Sum (LC 494), N-Queens II (LC 52)

    The Classic Early-Return Bug Inside a Choice Loop

    Never write return dfs(next); unconditionally inside a for loop! 
    // WRONG: tries ONLY the very first valid branch and ignores all remaining siblings!
for (int next : choices) {
    return dfs(next);  // BUG: if first branch is false, whole function returns false!
}

// RIGHT: bubble up true immediately, but keep trying siblings on false!
for (int next : choices) {
    apply(next);
    if (dfs(next)) return true;  // short-circuit ONLY on success
    undo(next);                  // restore state before trying next sibling
}
return false;                    // all choices exhausted without success

    Case Study (10_Propogating_truth_values.pdf): Word Break (LC 139) Across String Indices

    10_Propogating_truth_values.pdf points specifically to Word Break on the Trie problem list to study how a boolean truth value propagates across string indices. Given string s of length $n$ and dictionary wordDict, can s be segmented into a sequence of one or more dictionary words?

    Insert wordDict into a Trie. Define canBreak(i) = “Can suffix s[i .. n - 1] be validly segmented?”

    1. Base case (i == n): The empty suffix requires zero words → return true!
    2. Walk Trie from index i: Scan j = i, i + 1, ... down Trie edges matching s[j]. If s[j] has no child edge in the Trie, break immediately—no longer prefix starting at i can possibly be in wordDict!
    3. Propagate truth at word endings: Whenever the Trie node at j has isEnd == true, test if (canBreak(j + 1)) return true;. A single true at i == n bubbles straight up j + 1 → i → ... → 0 via logical OR!
    4. Cache failed indices (memo[i] = 0): Unlike Word Search (where visited grid cells depend on the path taken), whether suffix s[i..] can be segmented depends only on index i! On inputs like s = "catsandog" with ["cats", "dog", "sand", "and", "cat"], both "cat" + "sand" and "cats" + "and" land on index i = 7 ("og"). Recording memo[7] = 0 prevents exponential re-exploration on adversarial inputs like "aaaa...aaab".
    class Solution {
    struct TrieNode {
        int next[26];
        bool isEnd = false;
        TrieNode() { fill(begin(next), end(next), -1); }
    };

public:
    bool wordBreak(string s, vector<string>& wordDict) {
        vector<TrieNode> trie(1);
        for (const string& w : wordDict) {
            int cur = 0;
            for (char c : w) {
                int idx = c - 'a';
                if (trie[cur].next[idx] == -1) {
                    trie[cur].next[idx] = (int)trie.size();
                    trie.emplace_back();
                }
                cur = trie[cur].next[idx];
            }
            trie[cur].isEnd = true;
        }

        int n = (int)s.size();
        vector<int8_t> memo(n, -1);  // -1: unvisited, 0: false, 1: true

        auto canBreak = [&](auto& self, int i) -> bool {
            if (i == n) return true;              // base truth value!
            if (memo[i] != -1) return memo[i];

            int cur = 0;
            for (int j = i; j < n; ++j) {
                cur = trie[cur].next[s[j] - 'a'];
                if (cur == -1) break;             // Trie prune: prefix s[i..j] doesn't exist!
                if (trie[cur].isEnd && self(self, j + 1)) {
                    return memo[i] = 1;           // propagate true up the call stack!
                }
            }
            return memo[i] = 0;                   // all word endings from i failed
        };

        return canBreak(canBreak, 0);
    }
};

    In-Place Witness Propagation: Sudoku Solver (LeetCode 37)

    When a problem asks you to mutate a board into its valid solution, notice how return true intentionally skips the undo step so the solved board stays intact all the way back to the caller, whereas failed digits still undo cleanly:

    class Solution {
    int rowMask[9] = {}, colMask[9] = {}, boxMask[9] = {};
    vector<pair<int, int>> empties;

    bool dfs(int idx, vector<vector<char>>& board) {
        if (idx == (int)empties.size()) return true;  // solved!

        auto [r, c] = empties[idx];
        int b = (r / 3) * 3 + (c / 3);
        int used = rowMask[r] | colMask[c] | boxMask[b];

        for (int d = 0; d < 9; ++d) {
            int bit = 1 << d;
            if (used & bit) continue;

            // CHOOSE
            board[r][c] = static_cast<char>('1' + d);
            rowMask[r] |= bit; colMask[c] |= bit; boxMask[b] |= bit;

            // EXPLORE & SHORT-CIRCUIT: do NOT undo if solved!
            if (dfs(idx + 1, board)) return true;

            // UNDO on dead end
            rowMask[r] ^= bit; colMask[c] ^= bit; boxMask[b] ^= bit;
            board[r][c] = '.';
        }
        return false;
    }

public:
    void solveSudoku(vector<vector<char>>& board) {
        for (int r = 0; r < 9; ++r) {
            for (int c = 0; c < 9; ++c) {
                if (board[r][c] == '.') {
                    empties.emplace_back(r, c);
                } else {
                    int bit = 1 << (board[r][c] - '1');
                    rowMask[r] |= bit;
                    colMask[c] |= bit;
                    boxMask[(r / 3) * 3 + (c / 3)] |= bit;
                }
            }
        }
        dfs(0, board);
    }
};

    2. Curated Backtracking Question Bank (11_Question_banks.pdf)

    11_Question_banks.pdf bookmarks the LeetCode Backtracking Practice Study Guide. Rather than memorizing problems in random order, drill them by recursion tree archetype—every problem in the same table shares 90% of its skeleton:

    Archetype A · Subsets, Combinations & Target Sums

    Problem State & Choice Loop Key Duplicate / Pruning Rule
    LC 78 · Subsets dfs(i), loop j = i..n-1 → dfs(j + 1) Push at every node; never look left ($O(n \cdot 2^n)$)
    LC 90 · Subsets II Sort + dfs(i), loop j = i..n-1 if (j > i && a[j] == a[j-1]) continue;
    LC 77 · Combinations Pick $k$ from 1..n, loop j = i..n Size bound: j <= n - (k - path.size()) + 1 ($\binom{n}{k}$ leaves)
    LC 39 · Combination Sum Sort + loop j = i..n-1 → dfs(j, rem - a[j]) Reuse allowed via j; if (a[j] > rem) break;
    LC 40 · Combination Sum II Sort + loop j = i..n-1 → dfs(j + 1, rem - a[j]) Sibling skip j > i && a[j] == a[j-1] + sorted break
    LC 216 · Combination Sum III Digits 1..9, depth cap path.size() == k At most $\sum_{d=0}^k \binom{9}{d} \le 512$ nodes
    LC 491 · Non-decreasing Subsequences Cannot sort input! Loop j = i..n-1 Require a[j] ≥ path.back() + local usedAtDepth set per call

    Archetype B · Permutations, Arrangements & Multisets

    Problem State & Choice Loop Key Duplicate / Pruning Rule
    LC 46 · Permutations vis[n] or in-place swap(a[idx], a[j]) $\sum P(n,i) = \Theta(n!)$ nodes, $O(n \cdot n!)$ leaf copies
    LC 47 · Permutations II Sort + vis[n], loop j = 0..n-1 if (j > 0 && a[j] == a[j-1] && !vis[j-1]) continue;
    LC 526 · Beautiful Arrangement Place 1..n into positions; fill from pos = n down to 1! Check x % pos == 0 || pos % x == 0; large positions branch least
    LC 1079 · Letter Tile Possibilities Frequency array cnt[26] Iterating c = 0..25 with cnt[c] > 0 deduplicates multisets automatically!
    LC 60 · Permutation Sequence $k$-th permutation of 1..n Skip full backtracking—index directly by $(n-1)!$ factorial blocks in $O(n^2)$

    Archetype C · String Cuts, Parentheses & Expression Builders

    Problem State & Choice Loop Key Duplicate / Pruning Rule
    LC 17 · Letter Combinations Position idx maps to 3 or 4 keypad chars Cartesian product: $O(n \cdot 3^a 4^b)$
    LC 22 · Generate Parentheses dfs(open, close) up to $n$ pairs Prune: open < n to add '('; close < open to add ')' ($C_n$ Catalan leaves)
    LC 93 · Restore IP Addresses 4 contiguous cuts of length 1..3 Reject leading zeros ("01") and values $> 255$; prune remaining length $> 3 \cdot \text{remDots}$
    LC 131 · Palindrome Partitioning Cut s[i..j], recurse fresh on j + 1 Precompute $O(n^2)$ isPal[i][j] table so cut checks are $O(1)$
    LC 139 / 140 · Word Break I & II Cut s[i..j] using Trie edges from i LC 139: bool + memo[i]; LC 140: collect sentences / memoize suffix lists
    LC 282 · Expression Add Operators dfs(idx, eval, prevTerm) inserting +, -, * For *, undo prevTerm via eval - prevTerm + prevTerm * cur!

    Archetype D · 2D Grids, CSP Boards & $K$-Bucket Symmetry Pruning

    Problem State & Choice Loop Key Duplicate / Pruning Rule
    LC 79 · Word Search 4-dir simple path on grid, board[r][c] = '#' Unmark on return! Optional: reverse word if last char is rarer than first
    LC 212 · Word Search II Simultaneous grid backtracking + Trie walk Delete matched words & prune empty Trie leaves dynamically!
    LC 51 / 52 · N-Queens I & II 1 queen per row r, try columns 0..n-1 Hash col[c], diag1[r - c + n - 1], diag2[r + c] in $O(1)$
    LC 37 · Sudoku Solver 9-bit masks for row, col, and $3 \times 3$ box MRV heuristic: pick empty cell with fewest valid candidate bits first
    LC 980 · Unique Paths III Hamiltonian walk visiting all non-obstacle squares Track remEmpty; accept goal cell iff remEmpty == 0
    LC 473 / 698 / 2305 · $K$-Buckets
    (Matchsticks, K Equal Subsets, Cookies)    		 Assign item idx to one of $k$ buckets 3-part symmetry prune: (1) sort items descending, (2) skip bucket b if bucket[b] == bucket[b-1], (3) if bucket[b] == 0 fails, break (all empty buckets are indistinguishable!)
    10-Second Interview Diagnostic Checklist
    1. Order irrelevant vs. order relevant? Loop from j = i (Subsets / Combinations) vs. j = 0 with vis[] or swaps (Permutations).
    2. Unlimited reuse vs. single use? Recurse with dfs(j) vs. dfs(j + 1).
    3. Input has duplicates? Sort first (if order may change) and skip j > i && a[j] == a[j - 1] (or use a per-depth unordered_set when input order is fixed, as in LC 491).
    4. Count / existence depends only on (idx, rem) with no path-dependent visited state? Add a memo table—your backtracking tree just became polynomial Dynamic Programming!
