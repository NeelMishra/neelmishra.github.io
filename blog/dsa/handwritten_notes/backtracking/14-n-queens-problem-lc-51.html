    N-Queens Problem (LeetCode 51): Diagonal Conflict Equations & $O(1)$ Hashing

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 14_N_queens_problem.pdf

    $N$-Queens is the quintessential constraint-satisfaction backtracking benchmark. Placing one queen per row reduces $n^2$-cell selection to an $n$-level row-by-row tree—leaving a single geometric question that 14_N_queens_problem.pdf derives from scratch: how do we test whether a new queen at (new_i, new_j) conflicts with any previously placed queen, first algebraically and then in $O(1)$ time?

    Problem Statement

    LeetCode 51 · N-Queens

    Place $n$ chess queens on an $n \times n$ chessboard so that no two queens attack each other (no two queens share the same row, column, or $45^\circ$ diagonal). Return all distinct solutions as $n \times n$ string boards of 'Q' and '.'.

    Example ($n = 4$): Exactly 2 symmetric solutions exist, placing queens at columns [1, 3, 0, 2] and [2, 0, 3, 1] across rows 0..3.

    Deriving the Three Conflict Rules (14_N_queens_problem.pdf)

    Suppose we have already placed queens in earlier rows at coordinates $(i, j)$ and want to test a new queen at $(\text{new\_i}, \text{new\_j})$:

    1. Row conflict (new_i == i): Eliminated structurally! By making recursion depth equal to the row index r = 0, 1, ..., n - 1 and placing exactly one queen in row r before recursing to r + 1, two queens can never occupy the same row.
    2. Column conflict (new_j == j): Occurs whenever any earlier queen chose the same column index.
    3. Diagonal conflict (Equal Coordinate Distance): Follow the stepping pattern written out in 14_N_queens_problem.pdf:
      • Stepping along the main diagonal (\) from $(i, j)$ visits $(i + 1, j + 1), (i + 2, j + 2), \dots, (i + k, j + k)$ downward-right and $(i - 1, j - 1), \dots, (i - k, j - k)$ upward-left—for example, the note traces (1,0), (2,1), (3,2), (4,3), (5,4), (6,5), (7,6)! Along every cell on this line, $\text{new\_i} - i = \text{new\_j} - j = \pm k$, so rearranging gives the invariant $\text{row} - \text{col} = \text{constant}$!
      • Stepping along the anti-diagonal (/) from $(i, j)$ visits $(i + k, j - k)$ and $(i - k, j + k)$: row increases by $k$ while column decreases by the same $k$, giving the invariant $\text{row} + \text{col} = \text{constant}$!
      • Combining both directions into one pairwise distance test (as noted at the bottom of the scan: “what if the distance between $i$'s & $j$'s are the same: $k = \text{new\_i} - i$”): $$|\text{new\_i} - i| = |\text{new\_j} - j|.$$

    Brute → Better → Optimal Progression

    1. Naive Board Scan ($O(n)$ per candidate square): Walk upward-left, straight up, and upward-right from (r, c) scanning for 'Q' (or compare $|r - r_q| == |c - c_q|$ against all $r$ previously placed queens).
    2. $O(1)$ Array Hashing (Cleanest Interview Standard): Maintain col[n], diag1[2n - 1] (indexed by r - c + n - 1), and diag2[2n - 1] (indexed by r + c). Every conflict check, choose, and undo takes three $O(1)$ byte assignments!
    3. Bitmask Propagation ($O(1)$ register ops, zero arrays): Since $n \le 9$ (even $n \le 32$), store cols, d1, and d2 in three integers! Moving from row r to row r + 1 shifts main-diagonal attacks right/left by 1 bit automatically: (d1 | bit) << 1 and (d2 | bit) >> 1.

    Clean C++ Implementations ($O(1)$ Array Hashing & Bitmask)

    #include <cstdint>
#include <string>
#include <vector>
using namespace std;

class Solution {
    void dfs(int r, int n, vector<string>& board,
             vector<uint8_t>& col, vector<uint8_t>& diag1, vector<uint8_t>& diag2,
             vector<vector<string>>& ans) {
        if (r == n) {
            ans.push_back(board);  // O(n^2) snapshot of valid n x n configuration
            return;
        }

        for (int c = 0; c < n; ++c) {
            int d1 = r - c + n - 1;
            int d2 = r + c;
            if (col[c] || diag1[d1] || diag2[d2]) continue;  // O(1) conflict check!

            // 1. CHOOSE
            board[r][c] = 'Q';
            col[c] = diag1[d1] = diag2[d2] = 1;

            // 2. EXPLORE next row
            dfs(r + 1, n, board, col, diag1, diag2, ans);

            // 3. UNDO
            col[c] = diag1[d1] = diag2[d2] = 0;
            board[r][c] = '.';
        }
    }

public:
    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> ans;
        vector<string> board(n, string(n, '.'));
        vector<uint8_t> col(n, 0), diag1(2 * n - 1, 0), diag2(2 * n - 1, 0);
        dfs(0, n, board, col, diag1, diag2, ans);
        return ans;
    }
};
    // Bonus: Ultra-fast bitmask N-Queens II count (LC 52) — pass masks by value, zero undo code!
int totalNQueens(int n) {
    int full = (1 << n) - 1;
    auto dfs = [&](auto& self, int r, int cols, int d1, int d2) -> int {
        if (r == n) return 1;
        int count = 0;
        int avail = full & ~(cols | d1 | d2);  // 1-bits are safe columns!
        while (avail) {
            int bit = avail & -avail;          // isolate lowest safe column in O(1)
            avail -= bit;
            count += self(self, r + 1, cols | bit, (d1 | bit) << 1, (d2 | bit) >> 1);
        }
        return count;
    };
    return dfs(dfs, 0, 0, 0, 0);
}

    Time & Space Complexity

    • Time Complexity: $O(n! + S \cdot n^2)$ where $S$ is the number of valid boards emitted. Why strictly better than $n^n$? Row 0 tries $n$ columns, row 1 has at most $n - 2$ safe columns (column + at least 1 diagonal blocked), row 2 at most $n - 4$, etc.—and each check is $O(1)$! (For $n = 9$, only $S = 352$ solutions exist and fewer than $6{,}000$ nodes are visited vs $9! = 362{,}880$.)
    • Auxiliary Space Complexity: $O(n^2)$ for the mutable $n \times n$ string board ($O(n)$ for col, diag1, diag2, and call stack; $O(n)$ total in N-Queens II where no board strings are needed).

    Key Edge Cases

    • $n = 1$: Returns [["Q"]] (1 solution).
    • $n = 2$ and $n = 3$: Return [] (0 solutions exist—placing a queen anywhere in row 0 leaves at most 1 safe column in row 1, which blocks all columns of row 2!).
    • Negative index bug on r - c: Always add + (n - 1) when indexing diag1[r - c + n - 1]; at (r = 0, c = n - 1), raw r - c == -(n - 1) accesses out-of-bounds memory!
