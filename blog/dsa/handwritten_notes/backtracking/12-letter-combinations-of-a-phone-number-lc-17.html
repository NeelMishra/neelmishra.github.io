    Letter Combinations of a Phone Number (LC 17): Geometric Series & Tight $O(n \cdot 3^a 4^b)$ Proof

    October 2026 · 7 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 12_Letter_combinations_of_a_phone_number.pdf (2 pages)

    Generating phone-keypad strings looks simple to code, yet interviewers routinely probe the exact complexity derivation: why doesn't summing all internal levels $0, 1, \dots, n - 1$ inflate the asymptotic bound beyond the leaf level, and how do 3-letter digits versus 4-letter digits refine $O(n \cdot 4^n)$? Both pages of 12_Letter_combinations_of_a_phone_number.pdf work through that geometric-series proof step by step.

    Problem Statement

    LeetCode 17 · Letter Combinations of a Phone Number

    Given a string digits containing digits from '2'–'9' inclusive, return all possible letter combinations that the number could represent on a telephone keypad:

    • 3-letter digits: 2:"abc", 3:"def", 4:"ghi", 5:"jkl", 6:"mno", 8:"tuv".
    • 4-letter digits: 7:"pqrs", 9:"wxyz".

    Example from note: digits = "34" → 3 choices for '3' (d, e, f) $\times$ 3 choices for '4' (g, h, i) $= 9$ leaves: ["dg","dh","di","eg","eh","ei","fg","fh","fi"].

    Intuition: Multi-Way Cartesian Product Tree

    Unlike Subsets (where every internal node is an answer) or Permutations (where choices come from one shared array), Phone Combinations computes the Cartesian product $M(d_0) \times M(d_1) \times \dots \times M(d_{n-1})$:

    • Recursion depth idx selects which digit position we are currently translating ($0 \le \text{idx} \lt n$).
    • The for loop at depth idx iterates over the 3 or 4 characters mapped to digits[idx], pushes one character onto our mutable buffer cur, recurses to idx + 1, and pops on return.
    • Valid combinations live exclusively at depth-$n$ leaves (idx == n).

    Clean C++ & Python Implementations

    #include <array>
#include <string>
#include <string_view>
#include <vector>
using namespace std;

class Solution {
    static constexpr array<string_view, 10> kPad = {
        "", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"
    };

    void dfs(int idx, const string& digits, string& cur, vector<string>& ans) {
        if (idx == (int)digits.size()) {
            ans.push_back(cur);  // O(n) copy at each leaf
            return;
        }
        for (char ch : kPad[digits[idx] - '0']) {
            cur.push_back(ch);               // O(1) choose
            dfs(idx + 1, digits, cur, ans);  // explore next digit
            cur.pop_back();                  // O(1) undo
        }
    }

public:
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};       // crucial edge case: "" -> [] (NOT [""]!)
        vector<string> ans;
        string cur;
        cur.reserve(digits.size());
        dfs(0, digits, cur, ans);
        return ans;
    }
};
    class Solution:
    PAD = ("", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz")

    def letterCombinations(self, digits: str) -> list[str]:
        if not digits:
            return []
        ans: list[str] = []
        cur: list[str] = []
        n = len(digits)

        def dfs(idx: int) -> None:
            if idx == n:
                ans.append("".join(cur))  # O(n) join at leaf only!
                return
            for ch in self.PAD[ ord(digits[idx]) - ord("0") ]:
                cur.append(ch)
                dfs(idx + 1)
                cur.pop()

        dfs(0)
        return ans

    Exact Geometric-Series Time & Space Proof (Pages 1–2)

    Suppose among the first $k \le n$ digits there are $a$ digits with 3 characters (2,3,4,5,6,8) and $b$ digits with 4 characters (7,9), so $a + b = k$:

    Why Only the Leaf Level Counts Asymptotically

    • Exact nodes at level $k$: $3^a \cdot 4^b$ (so at the leaf level $k = n$ with $a + b = n$, there are exactly $3^a \cdot 4^b$ leaves).
    • Geometric sum across all levels (assuming worst-case branching factor $4$): $$4^0 + 4^1 + 4^2 + \dots + 4^n = \frac{4^{n + 1} - 1}{4 - 1} = \frac{4^{n + 1} - 1}{3} = \frac{4}{3}\cdot 4^n - \frac{1}{3} = \Theta(4^n).$$ Because $\frac{4}{3}$ is a constant independent of $n$, all internal nodes combined ($4^0 + \dots + 4^{n-1} = \frac{4^n - 1}{3}$) number strictly less than half of the bottom leaf layer alone!
    • Internal work vs. leaf work: Every node does $O(1)$ push/pop work, while each leaf performs $O(n)$ extra work to copy the $n$-character string into ans: $$\text{Work Done} = O(\text{all nodes} \times 1 + \text{all leaves} \times n) = O(4^n + n \cdot 4^n) = O(n \cdot 4^n).$$
    • Tighter parameterized bound (Page 1): Replacing the loose $4^n$ upper bound by the exact leaf count $3^a \cdot 4^b$ gives: $$\text{Tight Time Complexity} = \Theta\bigl(n \cdot 3^a \cdot 4^b\bigr) \quad \text{where } a + b = n.$$
    • Space Complexity (Page 2): $O(n)$ auxiliary space for recursion stack + mutable buffer cur, plus $O(n \cdot 3^a \cdot 4^b)$ for storing the $3^a \cdot 4^b$ output strings of length $n$.

    Key Edge Cases

    • Empty input string (digits = ""): Without if (digits.empty()) return {};, calling dfs(0) immediately hits idx == 0 == digits.size() and returns [""] (1 empty string) instead of LeetCode's expected empty list []!
    • Immutable string concatenation inside recursion: Passing cur + ch by value in Python/C++ allocates a new string at every internal node too; while total work stays $\Theta(n \cdot 3^a 4^b)$ because internal levels decay geometrically, mutating a single buffer cur with push_back / pop_back eliminates every intermediate heap allocation.
