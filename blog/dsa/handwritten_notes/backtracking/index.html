    Backtracking: Choice, Constraint, Undo & Recursion Trees

    October 2026 · 8 min read · Handwritten Notes

    1-to-1 reading roadmap for all 14 handwritten competitive coding study notes (01_Subsets.pdf – 14_N_queens_problem.pdf, 21 scan pages)

    Backtracking is controlled exhaustive search over an implicit state-space tree. Instead of materializing exponentially many candidate arrays in memory at once, we maintain a single mutable partial state—a vector path, a visited array, a chessboard, or a running sum—walk down one branch of choices until we hit a valid configuration or violate a constraint, and restore the exact state on return so sibling branches observe a clean slate.

    Across these 14 dedicated study posts, seemingly different problems—power sets, duplicate-free combinations, permutations, grid path search, palindrome cuts, $N$-Queens, and boolean word segmentation—reduce to changing just three knobs on one recursion template: where the choice loop starts, which branches get pruned, and what the recursive call returns.

    The Choose–Constraint–Undo Invariant

    Every backtracking routine maintains a strict loop invariant: immediately after a recursive call dfs(...) returns, every shared container or marker must hold the exact same value it held immediately before that choice was applied.

    Three Phases at Every Decision Node

    1. Base / Goal Check: Have we reached a complete candidate (e.g., rem == 0, row == n, or every prefix node in Subsets)? Record a snapshot ans.push_back(path) or return true.
    2. Prune (Constraint Check): Before recursing, discard choices that break sorted bounds (candidates[j] > rem), duplicate an earlier sibling (j > i && a[j] == a[j - 1]), or attack an existing placement (col[c] || diag1[r - c + n - 1]).
    3. Choose → Explore → Undo: Mutate state, recurse one level deeper, then reverse every mutation in mirror order.
    void backtrack(int start, State& state, const vector<int>& nums,
               vector<Result>& ans) {
    if (isGoal(state)) {
        ans.push_back(snapshot(state));  // O(depth) copy at valid nodes
        if (stopAtGoal()) return;
    }

    for (int j = start; j < (int)nums.size(); ++j) {
        if (shouldSkipSibling(j, start, nums, state)) continue;
        if (exceedsSortedBound(j, nums, state)) break;  // sorted early exit

        applyChoice(state, nums[j]);                    // 1. CHOOSE
        backtrack(nextStart(j), state, nums, ans);      // 2. EXPLORE
        undoChoice(state, nums[j]);                     // 3. UNDO (restore!)
    }
}

    Asymmetric Mutation Is the #1 Backtracking Bug

    If you mutate two pieces of state before recursing—say board[r][c] = '#' and path.push_back(ch)—and an early return skips one of the two undo lines, every subsequent sibling branch inherits corrupted state. Keep mutations minimal, pair every write with its exact inverse right below the recursive call, and pass small scalars (idx, rem) by value so the call stack unwinds them automatically.

    Pick / Not-Pick vs. for-Loop Recursion Trees

    When generating subsets or combinations, there are two equivalent ways to organize the search tree. Understanding how their node counts, leaf positions, and pruning hooks differ makes reading the handwritten traces effortless:

    How the Notes Derive Time & Space Complexity

    Master Backtracking Complexity Formula

    $$\text{Total Time} = \sum_{d=0}^{D} \bigl(\text{Nodes at depth } d \times \text{Internal work per node}\bigr) + \bigl(\text{Valid leaves} \times \text{Snapshot copy cost}\bigr)$$
    • Binomial Subset / Combination Tree (j = i .. n-1, recurse j + 1): Level $k$ contains $\binom{n}{k}$ nodes, summing to $\sum_{k=0}^n \binom{n}{k} = 2^n$ nodes. As proven in Note 06 (Combination Sum II), the inner for loop does not multiply tree size by $n$: each unpruned iteration traverses one edge, and $2^n$ nodes have $2^n - 1$ edges ($O(1)$ amortized per node).
    • Falling-Factorial Permutation Tree (choose unused from $n$): As proven in Note 04 (Permutations), level $i$ has $P(n, i) = \frac{n!}{(n - i)!}$ nodes, summing to $n! \sum_{k=0}^n \frac{1}{k!} \le e \cdot n! = \Theta(n!)$ internal nodes plus $n! \times O(n)$ leaf copies $= O(n \cdot n!)$.
    • Bounded $b$-ary Tree of Depth $D$: As proven in Note 12 (Phone Combinations), $1 + b + b^2 + \dots + b^D = \frac{b^{D+1}-1}{b-1} = \Theta(b^D)$—for any $b \ge 2$, the bottom leaf layer asymptotically dominates all internal levels combined.
