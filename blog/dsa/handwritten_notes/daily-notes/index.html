    Daily Deep-Dive Notes: Prime-Factor Keyboard Moves & Subtree Average Precision

    October 2026 · 4 min read · 2-Part Series (5 Handwritten Pages)

    Expanded from handwritten competitive coding study notes (04_daily: 01_2_Keys_keyboard.pdf & 02_Count_nodes_equal_to_average_of_subtree.pdf)

    This two-part notebook folder captures two focused first-principles investigations from daily LeetCode practice—one where an apparent 2D dynamic-programming problem collapses to pure elementary number theory, and one where a mathematically valid rolling-mean recurrence hits floating-point / integer rounding drift at test case 119 / 138 before being rescued by exact integer tuple propagation.

    Reading Roadmap

    01
    Deep Dive 1: 2 Keys Keyboard (LC 650) — Why Optimal Copy-Paste Equals the Sum of Prime Factors

    Tracing $n = 999$ from $37 + 9 = 46$ down to $37 + 3 + 3 = 43$, proving $a + b \le a \cdot b$ for all $a, b \ge 2$, and comparing $\mathcal{O}(n^2)$ DP against $\mathcal{O}(\sqrt{n})$ prime factorization.

     02
    Deep Dive 2: Count Nodes Equal to Average of Subtree (LC 2265) — Rolling Mean Trap vs. Exact Sum Propagation

    Deriving $A_{n+1} = A_n + \frac{x_{n+1} - A_n}{n + 1}$, dissecting why propagating (mean, count) fails on [1, 3, 0, 3] after 119/138 test cases, and solving cleanly in $\mathcal{O}(n)$ post-order DFS with (sum, count).

    At-a-Glance Comparison

    Core mathematical insight, trap encountered, and optimal complexity for both daily deep-dive notes.
    Problem Initial Temptation Key Insight from Handwritten Notes Optimal Complexity
    LC 650: 2 Keys Keyboard 2D (screen, clipboard) DP in $\mathcal{O}(n^2)$ Multiplying length by $k$ costs $1\text{ Copy} + (k-1)\text{ Pastes} = k$ steps; splitting composite $k = ab$ never hurts ($a + b \le ab$), so answer is $\sum p_i$ (prime factors with multiplicity). $\mathcal{O}(\sqrt{n})$ time, $\mathcal{O}(1)$ space
    LC 2265: Subtree Average Bottom-up rolling mean $(A_n, n)$ Repeated division accumulates truncation/float error up deep trees (failing [1, 3, 0, 3] at case 120); propagate exact integer (sum, count) and divide once per node. $\mathcal{O}(n)$ time, $\mathcal{O}(h)$ stack space
