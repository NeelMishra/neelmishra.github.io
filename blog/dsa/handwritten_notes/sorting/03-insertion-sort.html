    Insertion Sort: Adaptive Sorted Prefix & Natural $O(n)$ Best Case

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 03_Insertion_sort.pdf

    Insertion Sort is the champion among elementary quadratic sorts—so fast and cache-friendly on small or nearly-sorted subarrays that industrial standard libraries (C++ std::sort's Introsort and std::stable_sort / Timsort) switch to Insertion Sort at their recursion leaves! As Page 1 of the handwritten note captures its intuition: "It's like Bubble Sort on the left side until the element is delivered to its correct place—the element goes into its correct position & everyone larger right-shifts by 1."

    1. Core Intuition & Playing-Card Prefix Invariant

    Imagine picking up playing cards one at a time from left to right. A $1$-card hand $\text{arr}[0]$ is trivially sorted. When you pick up card $i$ ($\text{arr}[i]$), your left hand $\text{arr}[0 \dots i - 1]$ is already sorted; you simply walk $\text{arr}[i]$ leftward past every element strictly larger than it, and stop the instant you hit an element $\le \text{arr}[i]$ (or reach index $0$).

    Insertion Sort vs. Selection Sort Prefix Contrast

    • Selection Sort's prefix $\text{arr}[0 \dots i - 1]$: Holds the $i$ globally smallest elements of the entire array—requiring a full $\Theta(n - i)$ scan of the right side on every pass.
    • Insertion Sort's prefix $\text{arr}[0 \dots i - 1]$: Holds the original first $i$ elements of the input rearranged in sorted order—requiring zero lookahead to the right and stopping immediately on the left as soon as $\text{arr}[j - 1] \le \text{arr}[j]$!

    2. Complete Dry Run on [14, 9, 15, 12, 6, 8, 13]

    Following the exact $7$-element trace from Page 1 of 03_Insertion_sort.pdf:

    Element-by-Element Prefix Delivery ($n = 7$)

    • $i = 0$ ($\text{arr}[0] = 14$): A size-$1$ subarray [14] is automatically in its correct order ($j = 0 \implies j \gt 0$ is false, $0$ comparisons).
      State: [14 | 9, 15, 12, 6, 8, 13]
    • $i = 1$ ($\text{arr}[1] = 9$): $j = 1$: $\text{arr}[0] = 14 \gt 9 \implies$ swap $(14, 9)$, decrement $j \to 0$ (stop because $j \gt 0$ fails).
      State: [9, 14 | 15, 12, 6, 8, 13]
    • $i = 2$ ($\text{arr}[2] = 15$): $j = 2$: $\text{arr}[1] = 14 \not\gt 15 \implies$ already in correct position! Inner while body runs $0$ times.
      State: [9, 14, 15 | 12, 6, 8, 13]
    • $i = 3$ ($\text{arr}[3] = 12$): Swap $(15, 12)$ at $j = 3$, then swap $(14, 12)$ at $j = 2$, then check $\text{arr}[0] = 9 \not\gt 12$ at $j = 1$ and stop.
      State: [9, 12, 14, 15 | 6, 8, 13]
    • $i = 4$ ($\text{arr}[4] = 6$): Smaller than all four prefix elements (15, 14, 12, 9), so $j$ walks $4 \to 3 \to 2 \to 1 \to 0$, delivering 6 to index $0$.
      State: [6, 9, 12, 14, 15 | 8, 13]
    • $i = 5$ ($\text{arr}[5] = 8$): Swaps past 15, 14, 12, 9, then checks $\text{arr}[0] = 6 \not\gt 8$ and stops at index $1$.
      State: [6, 8, 9, 12, 14, 15 | 13]
    • $i = 6$ ($\text{arr}[6] = 13$): Swaps past 15 and 14, checks $\text{arr}[3] = 12 \not\gt 13$ and stops at index $4$.
      Final Sorted Array: [6, 8, 9, 12, 13, 14, 15]

    3. Boundary Guard (j > 0) & Swap vs. Shift Implementations

    Page 1 stresses why j runs from i down to 1 and cannot reach 0 inside the condition:

    • Because each comparison inspects the immediate left neighbor arr[j - 1] > arr[j], evaluating arr[j - 1] when $j = 0$ would access arr[-1] (out-of-bounds memory)!
    • Placing j > 0 first in while (j > 0 && arr[j - 1] > arr[j]) exploits left-to-right short-circuit evaluation (&&): as soon as $j$ decrements to $0$, arr[j - 1] is never evaluated.

    Progression: Handwritten Adjacent-Swap Code $\to$ Production Right-Shift Code

    In competitive programming interviews, the adjacent-swap loop from Page 1 is super clean and impossible to off-by-one. In performance-critical code, however, each std::swap performs $3$ assignments (tmp = a; a = b; b = tmp). Caching int key = arr[i] once and shifting arr[j + 1] = arr[j] cuts inner-loop memory writes by $3\times$!

    #include <utility>
#include <vector>

// 1. Handwritten adjacent-swap formulation (Page 1 of 03_Insertion_sort.pdf)
void insertionSortSwaps(std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    for (int i = 0; i < n; ++i) {
        int j = i;
        // Short-circuit 'j > 0' MUST come before 'arr[j - 1] > arr[j]'!
        while (j > 0 && arr[j - 1] > arr[j]) {
            std::swap(arr[j], arr[j - 1]);
            --j;
        }
    }
}

// 2. Production shift-only formulation (1 array write per shift instead of 3 per swap)
void insertionSort(std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    for (int i = 1; i < n; ++i) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) { // Strict '>' keeps equal elements stable!
            arr[j + 1] = arr[j];          // Right-shift by 1
            --j;
        }
        arr[j + 1] = key;                 // Drop key into its exact slot
    }
}

    4. Time & Space Complexity Proof & Exact Inversion Bound

    Best, Average & Worst Time + Inversion-Adaptive Formula

    • Best Case — Already Sorted Array ($\mathbf{\Theta(n)}$ naturally, Page 2): For every $i = 1 \dots n - 1$, the very first check $\text{arr}[i - 1] \gt \text{arr}[i]$ is false! The while body executes $0$ times across the entire run, performing exactly $n - 1$ comparisons and $0$ swaps—with no auxiliary boolean flag needed.
    • Worst Case — Reverse-Sorted Array ($\mathbf{\Theta(n^2)}$): Step $i$ shifts $\text{arr}[i]$ all the way across $i$ elements to index $0$: $$\sum_{i=1}^{n-1} i = \frac{n(n - 1)}{2} = \mathbf{\Theta(n^2)} \text{ comparisons and shifts.}$$
    • Exact Inversion-Count Runtime ($\mathbf{\Theta(n + I)}$): Let $I = |\{(p, q) : 0 \le p \lt q \lt n \text{ and } \text{arr}[p] \gt \text{arr}[q]\}|$ be the number of inversions in $\text{arr}$. Every iteration of the inner while loop fixes exactly one inversion! Thus Insertion Sort runs in exact time $\Theta(n + I)$:
      • On random arrays, $\mathbb{E}[I] = \frac{n(n-1)}{4} \implies \mathbf{\Theta(n^2)}$ average case.
      • On $k$-sorted arrays (every element is at most $k$ indices from its sorted position), $I \le n \cdot k \implies$ Insertion Sort runs in $O(nk)$ linear time for constant $k$!
    • Auxiliary Space: $\mathbf{O(1)}$.
    Property Verdict Why Engineers Prefer Insertion Sort Over Bubble & Selection
    Stable? Yes The inner loop stops as soon as arr[j - 1] <= arr[j] (strict >), so a later equal key always lands immediately to the right of an earlier equal key.
    In-Place & Online? Yes Uses $O(1)$ extra space and can sort elements online one by one as they arrive from a stream without needing the whole array upfront.
    Used in std::sort? Yes ($n \le 16$) Tiny constant factor, sequential L1-cache reads, predictable branches, and $\Theta(n + I)$ adaptivity beat Quick/Merge Sort recursion overhead on small subarrays.

    5. Key Edge Cases & Interview Nuances

    • Binary Insertion Sort Question: Since $\text{arr}[0 \dots i - 1]$ is sorted, can binary search reduce Insertion Sort to $O(n \log n)$? Binary search reduces comparisons to $O(n \log n)$ (useful when comparing strings or custom objects is expensive), but shifting array elements still takes $\Theta(n^2)$ memory writes in the worst case!
    • Single Out-of-Place Minimum at the End ([2, 3, 4, 5, 6, 1]): Insertion Sort takes $O(n)$ total steps ($n - 2$ instant $O(1)$ checks for $3..6$, plus $n - 1$ shifts for $1$, totaling $2n - 3$ comparisons), whereas even flagged Bubble Sort takes $n - 1$ full passes ($\Theta(n^2)$) because 1 only moves left by $1$ position per pass!
    • Operand Order in while: Writing while (arr[j - 1] > arr[j] && j > 0) in C++ is a classic bug—when $j = 0$, arr[-1] is read before j > 0 is checked! Always guard j > 0 on the left of &&.
