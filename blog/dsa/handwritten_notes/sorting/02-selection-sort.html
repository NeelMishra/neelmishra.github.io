    Selection Sort: Select Minimum, Swap Bounds & Why Best Case Stays $\Theta(n^2)$

    October 2026 · 7 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 02_Selection_sort.pdf

    As summarized in the opening line of the handwritten note, Selection Sort boils down to four words: "select minimum & swap." Unlike Bubble Sort—which swaps adjacent elements repeatedly on the way right—Selection Sort scans the entire remaining unsorted suffix first, remembers the index min_idx of its smallest element, and performs just one swap at the end of the pass to lock that minimum into the front.

    1. Core Intuition & Sorted-Prefix Loop Invariant

    At the start of pass $i$ ($i = 0, 1, \dots, n - 2$), the array is partitioned into two contiguous regions:

    Selection Sort Loop Invariant

    1. Sorted Prefix $\text{arr}[0 \dots i - 1]$: Contains the $i$ smallest elements of the entire array, already placed in their permanent final positions ($\text{arr}[0] \le \text{arr}[1] \le \dots \le \text{arr}[i - 1]$).
    2. Unsorted Suffix $\text{arr}[i \dots n - 1]$: Every element in $\text{arr}[i \dots n - 1]$ is $\ge \text{arr}[i - 1]$. Scanning $j = i \dots n - 1$ finds $\text{min\_idx} = \arg\min_{j \in [i, n-1]} \text{arr}[j]$, and swapping $\text{arr}[i] \leftrightarrow \text{arr}[\text{min\_idx}]$ extends the sorted prefix to $[0 \dots i]$.

    2. Step-by-Step Dry Run on [13, 46, 24, 52, 20, 9]

    Let's trace the exact $6$-element array from Page 1 of 02_Selection_sort.pdf (vertical bar | marks the growing sorted prefix on the left):

    Pass-by-Pass Prefix Growth ($n = 6$, outer loop $i = 0 \dots 4$)

    • Initial State: | 13, 46, 24, 52, 20, 9
    • Pass 1 ($i = 0$): Scan $[0 \dots 5] \implies$ minimum is 9 at $\text{min\_idx} = 5$. Swap $\text{arr}[0] \leftrightarrow \text{arr}[5]$:
      9 | 46, 24, 52, 20, 13
    • Pass 2 ($i = 1$): Scan $[1 \dots 5] \implies$ minimum is 13 at $\text{min\_idx} = 5$. Swap $\text{arr}[1] \leftrightarrow \text{arr}[5]$:
      9, 13 | 24, 52, 20, 46
    • Pass 3 ($i = 2$): Scan $[2 \dots 5] \implies$ minimum is 20 at $\text{min\_idx} = 4$. Swap $\text{arr}[2] \leftrightarrow \text{arr}[4]$:
      9, 13, 20 | 52, 24, 46
    • Pass 4 ($i = 3$): Scan $[3 \dots 5] \implies$ minimum is 24 at $\text{min\_idx} = 4$. Swap $\text{arr}[3] \leftrightarrow \text{arr}[4]$:
      9, 13, 20, 24 | 52, 46
    • Pass 5 ($i = 4 = n - 2$): Scan $[4 \dots 5] \implies$ minimum is 46 at $\text{min\_idx} = 5$. Swap $\text{arr}[4] \leftrightarrow \text{arr}[5]$:
      9, 13, 20, 24, 46 | 52 — "last element 52 is sorted by itself $\implies$ all elements are sorted!"

    Reader's note on the handwritten scan (Page 1): When copying 24 down in Pass 3 on paper, the digits were momentarily flipped to 42 (giving 9, 13, 20 | 52, 42, 46 $\to$ 9, 13, 20, 42, 46 | 52). The mechanics and swap indices are identical!

    3. Loop Bounds (Why Stop at n - 2?) & C++ Implementation

    Page 1 highlights two clean boundary choices:

    1. Why the outer loop runs i = 0 to n - 2 (and not n - 1): Once the first $n - 1$ smallest elements are locked into indices $0 \dots n - 2$, only a single element remains at index $n - 1$—and a $1$-element suffix (holding the global maximum) is trivially sorted!
    2. Starting the inner scan at j = i + 1 vs. j = i: In the handwritten pseudocode, min_idx is initialized to i and j runs from i to n - 1. Starting j at i + 1 produces the exact same result while skipping the redundant self-check arr[i] < arr[i] on every pass!
    #include <utility>
#include <vector>

void selectionSort(std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    // Outer loop stops at n - 2 because the single element left at [n - 1] is already sorted
    for (int i = 0; i <= n - 2; ++i) {
        int min_idx = i;
        for (int j = i + 1; j < n; ++j) {
            if (arr[j] < arr[min_idx]) { // Strict '<' keeps the earliest minimum occurrence
                min_idx = j;
            }
        }
        if (min_idx != i) { // Avoid unnecessary self-write when arr[i] is already minimum
            std::swap(arr[min_idx], arr[i]);
        }
    }
}

    4. Time & Space Complexity Proof & Why Best Case Is Worse Than Insertion Sort

    Input-Oblivious $\Theta(n^2)$ Comparison Count

    Regardless of whether arr is already sorted, reverse-sorted, or random, pass $i$ scans $n - 1 - i$ candidates ($j = i + 1 \dots n - 1$):

    $$\text{Comparisons} = \sum_{i=0}^{n-2} (n - 1 - i) = (n - 1) + (n - 2) + \dots + 1 = \frac{n(n - 1)}{2} = \mathbf{\Theta(n^2)}.$$
    • Best, Average & Worst Time Complexity: $\mathbf{\Theta(n^2)}$ in all cases.
    • Swap / Memory-Write Count: At most $\mathbf{n - 1}$ swaps ($O(n)$ writes total, $0$ writes if already sorted with if (min_idx != i)).
    • Auxiliary Space Complexity: $\mathbf{O(1)}$ (min_idx, i, j).

    Starred Note on Page 2: Why Selection Sort's Best Case Loses to Insertion & Bubble Sort

    Page 2 explicitly warns: "The best case of Selection Sort is worse than Insertion Sort." Why can't we add an early-exit flag like we did in Bubble Sort?

    • Finding that $\text{min\_idx} == 0$ on Pass 1 only proves $\text{arr}[0]$ is smaller than $\text{arr}[1 \dots n - 1]$; it tells us nothing about the relative order among $\text{arr}[1 \dots n - 1]$ (for example, [1, 52, 24, 9] has $\text{min\_idx} == 0$ on Pass 1!).
    • Therefore Selection Sort is completely non-adaptive: it always pays $\Theta(n^2)$ comparisons even on sorted or nearly-sorted arrays, whereas Insertion Sort and flagged Bubble Sort finish in $\Theta(n)$.
    Property Verdict Practical Takeaway
    Stable? No Swapping $\text{arr}[i]$ across a long distance with $\text{arr}[\text{min\_idx}]$ can leapfrog an equal element in between (e.g., [4a, 4b, 1] $\to$ [1, 4b, 4a]). Making Selection Sort stable requires either $O(n)$ right-shifts per pass (turning it into Insertion-like writes) or linked nodes.
    In-Place? Yes Uses $O(1)$ auxiliary memory.
    Minimum Writes? Yes ($\le n - 1$ swaps) Selection Sort's signature niche: if comparisons are cheap in RAM but writes are expensive (e.g., EEPROM/Flash wear or moving huge non-pointer structs by value), Selection Sort performs at most $3(n - 1)$ element assignments vs. up to $\frac{3}{2}n^2$ in Bubble Sort.

    5. Key Edge Cases & Implementation Traps

    • Unsigned size_t Underflow on $n = 0$ or $n = 1$: Notice the loop condition i <= n - 2! If n were kept as unsigned size_t (arr.size()), then for $n = 0$ or $n = 1$, arr.size() - 2 wraps around to 18446744073709551614ULL, causing an instant out-of-bounds crash! Always cast int n = static_cast<int>(arr.size()); (or write i + 1 < arr.size()).
    • Duplicate Minimums: Using strict arr[j] < arr[min_idx] (rather than <=) avoids needlessly updating min_idx when duplicate minimums appear later in the suffix.
