    Divide-and-Conquer Sorts: Merge Sort & Quick Sort

    October 2026 · 12 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (04_Merge_Sort.pdf, 05_Quick_sort.pdf)

    To break through the $\Theta(n^2)$ barrier of adjacent-comparison elementary sorts, Merge Sort and Quick Sort apply divide and conquer in complementary ways: Merge Sort splits trivially at the midpoint and does the heavy lifting while merging bottom-up, whereas Quick Sort does the heavy lifting top-down while partitioning around a pivot so no merge step is needed at all.

    1. Merge Sort: Divide Until Size 1, Then Merge Sorted Halves

    Given subarray bounds [low..high], if low >= high (a single element), the subarray is already sorted! Otherwise, compute $\text{mid} = \text{low} + (\text{high} - \text{low}) / 2$, recursively sort [low..mid] and [mid + 1..high], and merge the two sorted halves in linear time.

    Two-Pointer Merge Trace & The idx - low Offset Correction (Pages 1–3)

    Pages 1–2 trace the final merge of left_half = [1, 1, 2, 3, 4] (left = low .. mid) and right_half = [2, 4, 5, 6] (right = mid + 1 .. high) into temporary vector temp:

    1. Compare arr[left] vs. arr[right] using <= (so equal elements like 2 vs. 2 and 4 vs. 4 always take from the left half first—preserving stability!):
      • 1 <= 2 $\to$ push 1, left++
      • 1 <= 2 $\to$ push 1, left++
      • 2 <= 2 $\to$ push left's 2, left++
      • 3 > 2 $\to$ push right's 2, right++
      • 3 <= 4 $\to$ push 3, left++
      • 4 <= 4 $\to$ push left's 4, left++ (left half now exhausted!)
    2. Drain remaining tail: Run while (left <= mid) and while (right <= high) to append 4, 5, 6 $\to$ temp = [1, 1, 2, 2, 3, 4, 4, 5, 6].
    3. Index correction when copying back (Page 3): Because temp always starts at index 0 (size high - low + 1), while the destination slice in arr spans [low..high], copy back via arr[idx] = temp[idx - low] (at idx = low, idx - low == 0; at idx = high, idx - low == high - low).
    #include <vector>

void merge(std::vector<int>& arr, int low, int mid, int high) {
    std::vector<int> temp;
    temp.reserve(high - low + 1);

    int left = low;
    int right = mid + 1;

    while (left <= mid && right <= high) {
        if (arr[left] <= arr[right]) { // '<=' guarantees stability!
            temp.push_back(arr[left++]);
        } else {
            temp.push_back(arr[right++]);
        }
    }
    while (left <= mid) temp.push_back(arr[left++]);
    while (right <= high) temp.push_back(arr[right++]);

    // Index offset correction: map arr[low..high] <- temp[0..high-low]
    for (int idx = low; idx <= high; ++idx) {
        arr[idx] = temp[idx - low];
    }
}

void mergeSort(std::vector<int>& arr, int low, int high) {
    if (low >= high) return;
    int mid = low + (high - low) / 2;
    mergeSort(arr, low, mid);
    mergeSort(arr, mid + 1, high);
    merge(arr, low, mid, high);
}

    Merge Sort Complexity Proof (Pages 4–5)

    • Tree height: Problem size halves at every depth ($n \to n/2 \to n/4 \dots$) until $\dfrac{n}{2^k} = 1 \implies k = \lceil \log_2 n \rceil$ levels.
    • Work per level: Across all subproblems at depth $d$, subarray lengths sum to exactly $n$, so two-pointer merging + copying back costs $\Theta(n)$ at every single level ($T(n) = 2T(n/2) + \Theta(n)$).
    • Total Time & Space: $\text{depth} \times \text{work per level} = \mathbf{\Theta(n \log n)}$ in best, average, and worst cases; auxiliary space is $\mathbf{O(n)}$ for temp (dominating the $O(\log n)$ call stack).

    2. Quick Sort: Partition Around a Pivot In-Place

    Quick Sort chooses a pivot element (Page 1 lists the four classic choices: 1st element, last element, median, or random element) and rearranges arr[low..high] in-place so that:

    • Every element to the left of pIndex is $\le \text{pivot}$,
    • Every element to the right of pIndex is $> \text{pivot}$, and
    • pivot lands at arr[pIndex]—its permanent final index in the sorted array!

    It then recurses independently on [low..pIndex - 1] and [pIndex + 1..high].

    Handwritten Two-Pointer Partition Trace on [4, 6, 2, 5, 7, 9, 1, 3] (Pages 1–2)

    Let's trace the exact Hoare-style two-pointer partition with pivot = arr[low] = 4 (low = 0, high = 7), i starting at low, and j starting at high:

    Step-by-Step Pointer Crossings & Why pivot Swaps With j!

    • Initial array: [4, 6, 2, 5, 7, 9, 1, 3] (pivot = 4 at idx $0$).
    • Round 1:
      • Advance i while arr[i] <= 4: passes 4 (idx $0$), stops at i = 1 (arr[1] = 6 > 4).
      • Decrement j while arr[j] > 4: stops immediately at j = 7 (arr[7] = 3 <= 4).
      • Since $i < j$ ($1 < 7$), swap arr[1] and arr[7] $\to$ [4, 3, 2, 5, 7, 9, 1, 6].
    • Round 2:
      • Advance i past 3, 2, stops at i = 3 (arr[3] = 5 > 4).
      • Decrement j past 6, stops at j = 6 (arr[6] = 1 <= 4).
      • Since $i < j$ ($3 < 6$), swap arr[3] and arr[6] $\to$ [4, 3, 2, 1, 7, 9, 5, 6].
    • Round 3 (Crossing!):
      • Advance i stops at i = 4 (arr[4] = 7 > 4).
      • Decrement j past 6, 5, 9, 7, stops at j = 3 (arr[3] = 1 <= 4).
      • Now j has crossed i ($j = 3 < i = 4$)! Exit the while (i < j) loop.
    • Final Pivot Placement: Every index $> j$ ($4..7$) holds elements $> 4$, and every index in $1..j$ ($1..3$) holds elements $\le 4$! Swapping arr[low] (4) with arr[j] (1 at idx $3$) yields:
      [1, 3, 2, | 4 |, 7, 9, 5, 6] — 4 is locked in its exact sorted spot pIndex = 3!

    C++ Implementations: Handwritten Two-Pointer Partition vs. Lomuto Partition

    Pay close attention to the inner loop bounds i <= high - 1 and j >= low + 1 in C++: if pivot is the largest element in [low..high], checking i <= high - 1 before incrementing ++i guarantees i stops at high instead of reading out-of-bounds at arr[high + 1]!

    #include <cstdlib>
#include <utility>
#include <vector>

// 1. Two-pointer pivot-at-low partition (exact algorithm from Pages 2-3)
int partitionTwoPointer(std::vector<int>& arr, int low, int high) {
    // Optional anti-worst-case defense: swap random element into arr[low]
    // std::swap(arr[low], arr[low + std::rand() % (high - low + 1)]);
    int pivot = arr[low];
    int i = low;
    int j = high;

    while (i < j) {
        while (arr[i] <= pivot && i <= high - 1) {
            ++i;
        }
        while (arr[j] > pivot && j >= low + 1) {
            --j;
        }
        if (i < j) {
            std::swap(arr[i], arr[j]);
        }
    }
    std::swap(arr[low], arr[j]); // Place pivot at partition index j
    return j;
}

// 2. Lomuto partition alternative (pivot at high, single forward scan)
int partitionLomuto(std::vector<int>& arr, int low, int high) {
    int pivot = arr[high];
    int store = low;
    for (int k = low; k < high; ++k) {
        if (arr[k] <= pivot) {
            std::swap(arr[store++], arr[k]);
        }
    }
    std::swap(arr[store], arr[high]);
    return store;
}

void quickSort(std::vector<int>& arr, int low, int high) {
    if (low < high) {
        int pIndex = partitionTwoPointer(arr, low, high);
        quickSort(arr, low, pIndex - 1);
        quickSort(arr, pIndex + 1, high);
    }
}

    3. Quick Sort Recurrence Relations: Best/Average vs. Worst Case (Page 3)

    Page 3 contrasts the two extreme partition shapes:

    Balanced vs. Degenerate Partition Recurrences

    • Best & Average Case ($\Theta(n \log n)$ time, $O(\log n)$ stack space): When the pivot lands near the median (or at any constant fraction split like $10\% / 90\%$ under random pivot selection), the recurrence is:
      $$F(n) = 2F(n / 2) + \Theta(n) \implies F(n) = \mathbf{\Theta(n \log n)}.$$
    • Worst Case ($\Theta(n^2)$ time, $O(n)$ stack space): When the array is already sorted in increasing or decreasing order and a deterministic 1st-element or last-element pivot is used, every partition peels off $0$ elements on one side and $n - 1$ on the other:
      $$F(n) = F(0) + F(n - 1) + \Theta(n) = \sum_{k=1}^{n} \Theta(k) = \mathbf{\Theta(n^2)}.$$
    Why Two-Pointer Partition Beats Naive Lomuto on All-Equal Arrays Notice a subtle pitfall if an array has $n$ identical elements [5, 5, 5, ..., 5]: Lomuto's arr[k] <= pivot advances store all the way to high, degenerating to $F(n - 1) + \Theta(n) = \Theta(n^2)$! To make Quick Sort rock-solid against both sorted inputs and heavy duplicates in competitive programming, pair random pivot selection with 3-way Dutch National Flag partitioning (< pivot, == pivot, > pivot).
