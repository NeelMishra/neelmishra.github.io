    LC 1061: Lexicographically Smallest Equivalent String — Custom Min-Char Root Tie-Breaking

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 06_1061_lexicographically_smallest_equivalent_string.pdf (dated April 30, 2024, 08:42) · View original handwritten page

    1. Problem Statement

    You are given two strings of the same length s1 and s2 and a string baseStr ($1 \le |s_1|, |\text{baseStr}| \le 1000$, lowercase English letters). For every index $i$, s1[i] and s2[i] are equivalent characters under the three standard equivalence relation axioms:

    • Reflexivity: $a \equiv a$.
    • Symmetry: $a \equiv b \implies b \equiv a$.
    • Transitivity: $a \equiv b \text{ and } b \equiv c \implies a \equiv c$.

    Return the lexicographically smallest equivalent string of baseStr by replacing each character with the smallest character in its equivalence class.

    2. Core Intuition: Replacing Union-by-Rank with Deterministic Min-Char Roots

    By fundamental set theory, any equivalence relation partitions its universe into disjoint equivalence classes—which is literally what Disjoint Set Union maintains! Here our universe consists of just the $26$ lowercase letters 'a'..'z' ($0 \dots 25$).

    In standard DSU, we attach the lower-rank root under the higher-rank root, so the root of a component could be any arbitrary letter inside that class. Look at how the handwritten note simplifies this into a two-line rule:

    1. Custom Merge Rule: Whenever we unite $u$ and $v$, resolve their roots $p_u = \text{findPar}(u)$ and $p_v = \text{findPar}(v)$, and always make the lexicographically smaller root the parent of the larger root:
      $$\text{parent}[\max(p_u, p_v)] = \min(p_u, p_v)$$
    2. Zero-Overhead Rewrite: Iterate through baseStr and replace every character ch directly with findPar(ch)!

    Why Dropping rank[] Is 100% Safe on a 26-Letter Domain

    Even without union by rank or size, a DSU over $|\Sigma| = 26$ elements can have tree height at most $25$ before path compression—and the very first findPar call flattens any chain directly onto its minimum root! Thus sacrificing rank balance costs zero asymptotic performance while saving a second pass to compute per-component minimums.

    3. Two Classic Bugs When Implementing Min-Parent DSU

    Never Skip findPar During Either Phase!

    1. Updating parent[max(u, v)] instead of parent[max(pu, pv)]: Suppose pair ('c', 'a') sets parent['c'] = 'a', and next pair ('c', 'b') arrives. If you naively write parent['c'] = 'b' on raw characters, you overwrite 'c''s link to 'a' and leave 'b' disconnected from 'a'! Comparing roots $p_u = \text{'a'}$ and $p_v = \text{'b'}$ sets parent['b'] = 'a', keeping all three under 'a'.
    2. Reading parent[ch] instead of findPar(ch) when rewriting baseStr: If 'p' pointed to 'm' first, and later 'm' pointed to 'k', parent['p'] is still 'm' until findPar('p') walks up to 'k'!

    4. Brute $\to$ Better $\to$ Optimal Progression

    Comparing approaches for LC 1061 ($N = |s_1|$, $M = |\text{baseStr}|$, $|\Sigma| = 26$).
    Approach Time Space Notes
    DFS per Character of baseStr $\mathcal{O}(N + 26 M)$ $\mathcal{O}(26^2)$ Re-traverses the 26-letter adjacency graph up to $M$ times.
    Offline Component Precomputation $\mathcal{O}(N + 26^2 + M)$ $\mathcal{O}(26^2)$ Runs BFS from 'a' to 'z' to prefill a 26-char lookup table.
    26-Int DSU with Min-Char Root $\mathcal{O}(N + M)$ $\mathcal{O}(1)$ (26 ints) Zero graph allocation, single 26-int stack array, handles dynamic streaming equivalences effortlessly.

    5. Step-by-Step Dry Run (Both LeetCode Example 1 & Handwritten Sheet)

    Dry Run A — LeetCode Example 1: s1 = "parker", s2 = "morris", baseStr = "parser"

    • i=0 ('p','m'): parent['p'] = 'm'  (matches first oval on handwritten sheet!)
    • i=1 ('a','o'): parent['o'] = 'a'  (matches second oval on handwritten sheet!)
    • i=2 ('r','r'): same root 'r', skip.
    • i=3 ('k','r'): parent['r'] = 'k'.
    • i=4 ('e','i'): parent['i'] = 'e'.
    • i=5 ('r','s'): findPar('r') = 'k', findPar('s') = 's' $\implies$ parent['s'] = 'k'.
    Wait—what about 'm' and 'k'? Notice 'm' only paired with 'p' (root 'm'), while {'k','r','s'} have root 'k'! So:
    'p' → 'm', 'a' → 'a', 'r' → 'k', 's' → 'k', 'e' → 'e', 'r' → 'k' $\implies$ "makkek"!

    Dry Run B — Exact Letters Written on Handwritten Sheet: s1 = "parser", s2 = "morris", baseStr = "parser"

    Pairs: (p,m) → 'm', (a,o) → 'a', (r,r), (s,r) → 'r', (e,i) → 'e', (r,s) $\implies$ "parser" rewrites to "marrer".

    6. Clean C++ & Python Implementations

    #include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    string smallestEquivalentString(string s1, string s2, string baseStr) {
        array<int, 26> parent;
        iota(parent.begin(), parent.end(), 0); // parent[c] = c for 'a'..'z'

        auto findPar = [&](auto& self, int c) -> int {
            return parent[c] == c ? c : parent[c] = self(self, parent[c]);
        };

        for (size_t i = 0; i < s1.size(); ++i) {
            int p1 = findPar(findPar, s1[i] - 'a');
            int p2 = findPar(findPar, s2[i] - 'a');
            if (p1 != p2) {
                // Smaller lexical character ALWAYS becomes the parent root
                parent[max(p1, p2)] = min(p1, p2);
            }
        }

        for (char& ch : baseStr) {
            ch = static_cast<char>('a' + findPar(findPar, ch - 'a'));
        }
        return baseStr;
    }
};
    class Solution:
    def smallestEquivalentString(self, s1: str, s2: str, baseStr: str) -> str:
        parent = list(range(26))

        def find(c: int) -> int:
            if parent[c] != c:
                parent[c] = find(parent[c])
            return parent[c]

        for ch1, ch2 in zip(s1, s2):
            p1, p2 = find(ord(ch1) - 97), find(ord(ch2) - 97)
            if p1 != p2:
                if p1 < p2:
                    parent[p2] = p1
                else:
                    parent[p1] = p2

        return "".join(chr(97 + find(ord(ch) - 97)) for ch in baseStr)

    7. Complexity Proof & Key Edge Cases

    • Time Complexity — $\mathcal{O}(|s_1| + |\text{baseStr}|)$: Because $|\Sigma| = 26$ is a fixed constant, findPar performs $\mathcal{O}(1)$ work, making both the union loop and the rewrite loop strictly linear.
    • Space Complexity — $\mathcal{O}(1)$ auxiliary space: Just 26 integers on the stack (plus the output string).
    • Key Edge Cases:
      • Characters in baseStr that never appeared in s1 or s2: Because all 26 letters start initialized with parent[c] = c, unseen characters map cleanly to themselves without KeyError! (Avoid sparse dict initialization that only inserts chars from s1/s2.)
      • Self-equivalences (s1[i] == s2[i]): Guarded by if (p1 != p2).
      • Contrast with Note 07 (LC 1202): Here you may replace every occurrence with the single smallest equivalent char (cloning allowed); in LC 1202 you can only permute existing chars across indices!
