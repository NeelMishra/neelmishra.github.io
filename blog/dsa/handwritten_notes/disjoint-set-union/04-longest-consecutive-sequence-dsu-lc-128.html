    LC 128: Longest Consecutive Sequence (Part I) — Value-Keyed $+1/-1$ Merge Plan & Max-Root Propagation

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 04_128_Longest_consecutive_sequence.pdf (dated April 28, 2024) · See also Note 10 for the March 2025 index-mapped UF(n) template · View original handwritten page

    1. Problem Statement

    Given an unsorted array of integers nums ($0 \le n \le 10^5$, $-10^9 \le \text{nums}[i] \le 10^9$), return the length of the longest consecutive elements sequence (e.g., for nums = [100, 4, 200, 1, 3, 2], the longest consecutive run is [1, 2, 3, 4] of length 4). Your algorithm must run in $\mathcal{O}(n)$ expected time.

    2. The Handwritten Value-Keyed DSU Plan (04_128)

    How does an unsorted array problem turn into a graph connectivity problem? View every distinct integer $x \in \text{nums}$ as a vertex on the integer number line, with an implicit undirected edge between $x$ and $y$ iff $|x - y| = 1$. Then a consecutive sequence $[L, L+1, \dots, R]$ is literally a connected component, and its length is that component's vertex count!

    In this April 2024 note (04_128), the DSU stores distinct integer values directly as hash-map keys (parent[x] = x) and executes a three-step online plan as each $x \in \text{nums}$ arrives:

    1. Insert unseen value $x$: If $x$ is already a key in parent, skip it immediately (duplicate values do not lengthen a consecutive run!). Otherwise initialize parent[x] = x and component size compSize[x] = 1.
    2. Probe $+1$ and $-1$ neighbors: Check whether $x + 1$ and/or $x - 1$ already exist in the DSU parent keys.
    3. Merge valid neighbor components & update running ans:
      • Add component cardinalities: $\text{compSize}[\text{newRoot}] = \text{compSize}[\text{rootA}] + \text{compSize}[\text{rootB}]$ (written in the note as rank(component_a) + rank(curr_component)—note this is additive Union by Size, not tree-height rank!).
      • Return the combined size after each merge to update ans = max(ans, combinedSize) on the fly.

    Analyzing the Note's Tie-Break Rule: "Propagate the Larger Number as Parent"

    Look closely at the second sub-bullet under Step 3 of the handwritten sheet: "As of whom to set parent it is good to propagate the larger number as parent." Let's examine both the beauty and the asymptotic trade-off of setting $\text{parent}[\min(r_a, r_b)] = \max(r_a, r_b)$:

    • Canonical Interval Invariant: Every contiguous interval $[L, L+1, \dots, R]$ always elects its right endpoint $R$ as the canonical root! Merging $[1, 2]$ (root $2$) with $[3, 4]$ (root $4$) immediately sets parent[2] = 4, and compSize[4] = 4.
    • Worst-Case Complexity Nuance: If elements arrive in strictly descending order ($n, n - 1, \dots, 1$) and we always make the larger root the parent without considering tree sizes, each new singleton $(k)$ attaches under the giant root $(n)$ in $1$ hop ($\mathcal{O}(1)$!), whereas if elements arrive in strictly ascending order ($1, 2, \dots, n$), the giant root $(k - 1)$ repeatedly attaches under the new singleton $(k)$! With path compression, Tarjan's bound for arbitrary linking + path compression is $\mathcal{O}(n \log n)$ worst-case (and $\mathcal{O}(n)$ on typical inputs), whereas attaching the smaller-size tree under the larger-size tree guarantees strict $\mathcal{O}(n \cdot \alpha(n))$ even against adversarial ascending streams. Better yet, if you ever want both $\mathcal{O}(\alpha(n))$ balance and the interval's maximum value, maintain maxVal[pu] = max(maxVal[pu], maxVal[pv]) alongside union-by-size!

    3. Brute $\to$ Sorting $\to$ HashSet $\to$ Online DSU

    Comparing all four paradigms for Longest Consecutive Sequence.
    Approach Time Space Supports Dynamic Online Stream?
    Brute Linear Search $\mathcal{O}(n^3)$ $\mathcal{O}(1)$ No (re-scans whole array for $x+1, x+2, \dots$)
    Sort + Deduplicate Scan $\mathcal{O}(n \log n)$ $\mathcal{O}(1)$ / $\mathcal{O}(n)$ No (violates LC 128's $\mathcal{O}(n)$ requirement)
    Hash-Set Streak Start $\mathcal{O}(n)$ $\mathcal{O}(n)$ No — static batch only; interleaved queries re-walk streaks in $\mathcal{O}(n^2)$
    Value-Keyed DSU (04_128) $\mathcal{O}(n \cdot \alpha(n))$ $\mathcal{O}(n)$ Yes! Each new integer updates ans in $\mathcal{O}(\alpha(n))$ expected time

    4. Step-by-Step Dry Run on [100, 4, 200, 1, 3, 2]

    Tracing Value-Keyed DSU (ans initialized to 1 once first key inserts)

    1. x = 100: insert parent[100] = 100, sz[100] = 1. Neither 99 nor 101 present. ans = 1.
    2. x = 4: insert parent[4] = 4, sz[4] = 1. Neither 3 nor 5 present. ans = 1.
    3. x = 200: insert parent[200] = 200, sz[200] = 1. Neither 199 nor 201 present. ans = 1.
    4. x = 1: insert parent[1] = 1, sz[1] = 1. Neither 0 nor 2 present. ans = 1.
    5. x = 3: insert parent[3] = 3, sz[3] = 1; neighbor 3 + 1 = 4 exists! unite(3, 4) $\to$ combined size 1 + 1 = 2 $\implies$ ans = 2.
    6. x = 2: insert parent[2] = 2, sz[2] = 1:
      • neighbor 2 + 1 = 3 exists (root 4, size 2) $\to$ unite(2, 3) $\to$ size 3, ans = 3.
      • neighbor 2 - 1 = 1 exists (root 1, size 1) $\to$ unite(2, 1) $\to$ size 3 + 1 = 4, ans = 4!

    5. Clean C++ & Python Implementations

    Below is the value-keyed C++ implementation directly reflecting 04_128_Longest_consecutive_sequence.pdf (with 64-bit neighbor probes so INT_MIN - 1 and INT_MAX + 1 never trigger signed overflow UB), followed by Python:

    #include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        if (nums.empty()) return 0;

        unordered_map<long long, long long> parent;
        unordered_map<long long, int> compSize;
        parent.reserve(nums.size() * 2);
        compSize.reserve(nums.size() * 2);

        auto findPar = [&](auto& self, long long x) -> long long {
            return parent[x] == x ? x : parent[x] = self(self, parent[x]);
        };

        auto unite = [&](long long a, long long b) -> int {
            long long pa = findPar(findPar, a);
            long long pb = findPar(findPar, b);
            if (pa == pb) return compSize[pa];
            if (compSize[pa] < compSize[pb]) swap(pa, pb);
            parent[pb] = pa;
            compSize[pa] += compSize[pb];
            return compSize[pa];
        };

        int ans = 1;
        for (long long x : nums) {
            if (parent.count(x)) continue; // Duplicate value already in DSU
            parent[x] = x;
            compSize[x] = 1;

            if (parent.count(x + 1)) ans = max(ans, unite(x, x + 1));
            if (parent.count(x - 1)) ans = max(ans, unite(x, x - 1));
        }
        return ans;
    }
};
    class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        if not nums:
            return 0

        parent: dict[int, int] = {}
        comp_size: dict[int, int] = {}

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def unite(a: int, b: int) -> int:
            ra, rb = find(a), find(b)
            if ra == rb:
                return comp_size[ra]
            if comp_size[ra] < comp_size[rb]:
                ra, rb = rb, ra
            parent[rb] = ra
            comp_size[ra] += comp_size[rb]
            return comp_size[ra]

        ans = 1
        for x in nums:
            if x in parent:
                continue  # Ignore duplicates
            parent[x] = x
            comp_size[x] = 1
            if x + 1 in parent:
                ans = max(ans, unite(x, x + 1))
            if x - 1 in parent:
                ans = max(ans, unite(x, x - 1))

        return ans

    6. Complexity Proof & Key Edge Cases

    • Time Complexity — $\mathcal{O}(n \cdot \alpha(n))$ expected: For $U \le n$ unique values, we execute at most $2U$ hash-map neighbor lookups and $2U$ DSU merges, each costing amortized $\mathcal{O}(\alpha(U))$ pointer hops. (In Note 10, we eliminate hash-map lookups inside find/unite altogether by mapping values onto compact array indices $0 \dots n - 1$!)
    • Space Complexity — $\mathcal{O}(n)$: Two hash maps storing at most $n$ distinct keys.
    • Key Edge Cases:
      • Empty array nums = []: Must return 0 before initializing ans = 1.
      • Duplicates ([1, 2, 0, 1]): Skipping if (parent.count(x)) continue; ensures the second 1 neither resets parent[1] nor inflates compSize from 3 to 4.
      • Extreme 32-bit integers (INT_MAX = 2147483647 or INT_MIN = -2147483648): Casting x to long long in C++ avoids undefined signed overflow on x + 1 and x - 1.
