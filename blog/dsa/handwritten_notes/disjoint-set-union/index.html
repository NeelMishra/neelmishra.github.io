    Disjoint Set Union (DSU): Handwritten Notes, Templates & Problem Patterns

    October 2026 · 7 min read · 4-Part Series (15 Handwritten Pages)

    Expanded from handwritten competitive coding study notes (03_DSU: 11 notebooks, 15 pages covering core DSU theory and 9 LeetCode classics)

    Whenever a problem maintains dynamic equivalence classes—merging groups online, testing whether two vertices already belong to the same connected component, detecting the exact edge that closes a cycle, or tracking component sizes in near-constant $\mathcal{O}(\alpha(N))$ time—Disjoint Set Union (DSU / Union-Find) replaces repeated $\mathcal{O}(V + E)$ DFS/BFS traversals with two tiny array operations: findPar(u) and unite(u, v).

    Universal DSU Template Cheat Sheet

    In competitive programming, Union by Size is almost always preferred over Union by Rank because sz[find(u)] gives you the exact cardinality of any connected component at zero extra cost (needed directly in LC 128, LC 952, LC 928, and LC 1319).

    struct DSU {
    vector<int> parent, sz;
    int components;

    explicit DSU(int n) : parent(n), sz(n, 1), components(n) {
        iota(parent.begin(), parent.end(), 0); // parent[i] = i
    }

    int findPar(int node) {
        if (node == parent[node]) return node;
        return parent[node] = findPar(parent[node]); // Path compression
    }

    bool unite(int u, int v) {
        int pu = findPar(u), pv = findPar(v);
        if (pu == pv) return false; // Already in same group (redundant / cycle!)
        if (sz[pu] < sz[pv]) swap(pu, pv);
        parent[pv] = pu;
        sz[pu] += sz[pv];
        --components;
        return true;
    }

    int compSize(int u) { return sz[findPar(u)]; }
};

    Four Rules Written Across the Handwritten Notes

    1. Always guard if (pu == pv) return false; first: Prevents corrupting sz[pu] += sz[pu], avoids double-decrementing component counts, and directly flags cycles.
    2. Update metadata on roots (pu, pv), never raw inputs (u, v): Attaching or incrementing rank[u] instead of rank[pu] silently breaks tree balance.
    3. Prefer flat 0-indexed arrays over hash maps: Even for 2D grids, flattening $(r, c) \mapsto r \cdot C + c$ gives $\mathcal{O}(1)$ contiguous array lookups instead of hash/tuple overhead.
    4. Custom root tie-breaking is valid when domain is tiny: Over 26 letters (LC 1061), choosing parent[maxRoot] = minRoot sacrifices rank balance on $\le 26$ nodes while making findPar(c) return the smallest equivalent character directly.
