    Balance a Binary Search Tree (LC 1382): From Rough Pointer Fixes to $\mathcal{O}(N)$ Inorder Midpoint Rebuild

    October 2026 · 9 min read · Handwritten Notes

    1. Problem Statement & Height-Balance Invariant

    LeetCode 1382 — Balance a Binary Search Tree

    Given the root of a Binary Search Tree (BST), return a height-balanced BST with the exact same node values. If more than one balanced BST exists, return any one of them.

    A binary tree is height-balanced if and only if for every node $u$ in the tree (not merely the global root!), the depths of its left and right subtrees differ by at most $1$:

    $$\forall u \in T, \quad \bigl|\text{height}(u.\text{left}) - \text{height}(u.\text{right})\bigr| \le 1$$

    2. Brute & Ad-Hoc Instincts → Why Naive Pointer Fixes Break → Optimal Strategy

    The most instructive part of this note is the "Rough" exploration spanning the bottom half of Page 1 and top of Page 2. Before settling on the clean solution, three natural instincts are tested:

    Attempt 1: Track prev During Traversal and Attach as Left Child

    If we walk down 1 → 2 → 3 → 4 keeping a prev pointer (prev == None: skip; prev != None: curr.left = prev), lifting 2 above 1 works for two nodes, but blindly chaining every predecessor onto left turns a right-skewed vine into a left-skewed vine 4 → 3 → 2 → 1 of the exact same unbalanced height $4$!

    Attempt 2: Bottom-Up Local Re-Parenting When $\lvert \text{left} - \text{right} \rvert \gt 1$

    What if we recurse to the bottom first and locally rotate whenever $\lvert \text{depth}(L) - \text{depth}(R) \rvert \gt 1$? On the pure chain 1 → 2 → 3 → 4, Page 1 shows it seems to work: fixing at node 2 lifts 3 above (2, 4), and fixing again at node 1 lifts 3 above (2 → 1) and 4.

    Contest Lesson: Static Rebuild vs. Dynamic AVL Rotations

    Inserting all $N$ keys into a self-balancing AVL / Red-Black tree takes $\mathcal{O}(N \log N)$ time and ~100 lines of error-prone LL/RR/LR/RL rotation cases. Because all $N$ nodes are already known statically, flattening the BST via Inorder DFS and splitting at midpoints solves LC 1382 in $\mathcal{O}(N)$ worst-case time in 20 bug-free lines!

    3. Optimal $\mathcal{O}(N)$ Algorithm: Inorder DFS + Midpoint Divide-and-Conquer

    Every Binary Search Tree obeys a foundational structural equivalence: an inorder DFS traversal (Left → Root → Right) visits nodes in strictly non-decreasing sorted order in $\mathcal{O}(N)$ time. Once we collect the sorted array of nodes $A[0 \dots N-1]$, building a balanced BST reduces to LeetCode 108 (Convert Sorted Array to Binary Search Tree):

    1. Base case: If subarray bounds cross ($l \gt r$), return nullptr.
    2. Pick the exact midpoint: Choose $m = l + \lfloor (r - l) / 2 \rfloor$ as the root of $A[l \dots r]$.
    3. Recurse symmetrically: Set root->left = build(l, m - 1) (all elements $\le A[m]$) and root->right = build(m + 1, r) (all elements $\ge A[m]$).

    5. Clean C++ & Python Implementations

    Instead of storing vector<int> and allocating $N$ brand-new heap nodes with new TreeNode(...), storing vector<TreeNode*> rewires the existing nodes directly in-place (the base case l > r automatically overwrites old stale child pointers with nullptr!):

    // LeetCode 1382: Balance a Binary Search Tree — C++ (Zero new heap node allocations)
class Solution {
    vector<TreeNode*> sortedNodes;

    void inorder(TreeNode* curr) {
        if (!curr) return;
        inorder(curr->left);
        sortedNodes.push_back(curr);
        inorder(curr->right);
    }

    TreeNode* buildBalanced(int l, int r) {
        if (l > r) return nullptr;
        int mid = l + (r - l) / 2;
        TreeNode* root = sortedNodes[mid];
        root->left  = buildBalanced(l, mid - 1);
        root->right = buildBalanced(mid + 1, r);
        return root;
    }

public:
    TreeNode* balanceBST(TreeNode* root) {
        sortedNodes.clear();
        inorder(root);
        return buildBalanced(0, static_cast<int>(sortedNodes.size()) - 1);
    }
};
    # LeetCode 1382: Balance a Binary Search Tree — Python
class Solution:
    def balanceBST(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        nodes: List[TreeNode] = []

        def inorder(curr: Optional[TreeNode]) -> None:
            if not curr:
                return
            inorder(curr.left)
            nodes.append(curr)
            inorder(curr.right)

        def build(l: int, r: int) -> Optional[TreeNode]:
            if l > r:
                return None
            mid = (l + r) // 2
            node = nodes[mid]
            node.left = build(l, mid - 1)
            node.right = build(mid + 1, r)
            return node

        inorder(root)
        return build(0, len(nodes) - 1)

    6. Correctness Proof, Complexity & Key Edge Cases

    Inductive Balance Proof & Asymptotic Complexity

    • Why Every Node Is Height-Balanced: A subarray of length $k \ge 1$ splits into sizes $\lfloor (k - 1)/2 \rfloor$ and $\lceil (k - 1)/2 \rceil$. Because $f(s) = \lfloor \log_2 s \rfloor + 1$ (with $f(0) = 0$) is monotone and satisfies $f(\lceil (k-1)/2 \rceil) - f(\lfloor (k-1)/2 \rfloor) \in \{0, 1\}$, strong induction proves every subtree of $s$ nodes has exact height $\lfloor \log_2 s \rfloor + 1$ and $\lvert \text{height}(L) - \text{height}(R) \rvert \le 1$.
    • Time Complexity: $\mathcal{O}(N)$ — inorder visits each of the $N$ nodes once ($\mathcal{O}(N)$), and buildBalanced makes one call per array index ($\mathcal{O}(N)$).
    • Space Complexity: $\mathcal{O}(N)$ — sortedNodes holds $N$ pointers; recursion stack uses $\mathcal{O}(H) \le \mathcal{O}(N)$ during inorder and $\mathcal{O}(\log N)$ during buildBalanced. (Bonus interview note: the Day–Stout–Warren (DSW) algorithm achieves $\mathcal{O}(1)$ auxiliary space by flattening the BST into a right-leaning vine with right rotations and compressing it with $\mathcal{O}(N)$ left rotations.)
    • Stale Pointer Trap When Reusing TreeNode*: Never try to skip setting left/right on leaf indices ($l == r$)! An original internal node reused as a new leaf still carries old non-null children until buildBalanced(l, mid - 1) and buildBalanced(mid + 1, r) return nullptr to overwrite them.
    • Degenerate Skewed Chains ($N = 10^4$): In Python, LC 1382 caps $N \le 10^4$ (default recursion limit is $1000$, which LeetCode raises, or you can use an iterative stack for inorder to avoid deep call stacks on $10^5$-node inputs).
    • Single-Node or Already-Balanced BST: Runs cleanly in $\mathcal{O}(N)$ and returns a valid balanced tree (potentially choosing canonical lower-midpoints if multiple balanced layouts exist).
