    Bipartite Graph Check via Stack & Recursive DFS (Striver G-18)

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 02_Striver_g_18_dfs.pdf · View original handwritten page

    1. Concept: Swapping BFS's Queue for DFS's Stack

    Because every connected component's 2-coloring is uniquely fixed (up to swapping 0 and 1) the moment we color its starting vertex, traversal order does not affect correctness! In 02_Striver_g_18_dfs.pdf, we keep the exact same state design as Striver G-17 (BFS):

    • Allocate color[V] initialized to -1 (representing not colored).
    • Seed each uncolored component root source with color[source] = 0 (as noted on Page 1: // could be any color—starting with 0 or 1 is completely symmetric!).
    • Explore using a LIFO stack S (iteratively) or the call stack (recursively), assigning 1 - color[currentNode] to every uncolored neighbor and returning false whenever an edge connects two same-colored nodes.

    Crucial Bug Catch in the Handwritten Stack Sketch!

    Inspecting 02-striver-g-18-dfs-p1.jpg line by line reveals two essential lines to complete in production code:

    1. Inside if (color[adj] == -1), right after writing color[adj] = 1 - color[currentNode], you MUST push adj onto the stack (S.push(adj))! Without pushing adj, stack S empties immediately after source's direct neighbors and never explores depth $\ge 2$!
    2. Wrap seeding S.push(source) inside an outer loop for (int source = 0; source < V; ++source) if (color[source] == -1) so disconnected odd cycles in other components are never skipped.

    2. How DFS Discovers Odd-Cycle Conflicts Around a Loop

    3. Complete C++ Implementations (Iterative Stack + Recursive)

    // Method A: Iterative Stack DFS (Completing the exact sketch in 02_Striver_g_18_dfs.pdf) — C++
class SolutionIterativeStack {
public:
    bool isBipartite(const vector<vector<int>>& adjList) {
        int V = static_cast<int>(adjList.size());
        vector<int> color(V, -1); // -1 represents not colored

        for (int source = 0; source < V; ++source) {
            if (color[source] != -1) continue;

            stack<int> S;
            S.push(source);
            color[source] = 0; // Could be 0 or 1

            while (!S.empty()) {
                int currentNode = S.top();
                S.pop();

                for (int adj : adjList[currentNode]) {
                    if (color[adj] == -1) { // Uncolored neighbor
                        color[adj] = 1 - color[currentNode];
                        S.push(adj);        // Push onto stack to continue DFS!
                    } else if (color[adj] == color[currentNode]) {
                        return false;
                    }
                }
            }
        }
        return true;
    }
};
    // Method B: Striver's 15-Line Recursive DFS Contest Template (LC 785) — C++
class Solution {
    bool dfs(int node, int col, const vector<vector<int>>& adj, vector<int>& color) {
        color[node] = col;

        for (int nbr : adj[node]) {
            if (color[nbr] == -1) {
                if (!dfs(nbr, 1 - col, adj, color)) return false;
            } else if (color[nbr] == col) {
                return false; // Odd-cycle clash!
            }
        }
        return true;
    }

public:
    bool isBipartite(vector<vector<int>>& graph) {
        int V = graph.size();
        vector<int> color(V, -1);

        for (int i = 0; i < V; ++i) {
            if (color[i] == -1) {
                if (!dfs(i, 0, graph, color)) return false;
            }
        }
        return true;
    }
};

    Classic Contest Application: Possible Bipartition (LeetCode 886)

    In LC 886, given n people (1..n) and dislikes[i] = [a, b], build an undirected adjacency list from dislikes and run isBipartite directly—each dislike edge forces a and b into opposite rooms (color 0 vs. color 1)!

    4. Complexity Proof & Key Edge Cases

    • Time Complexity: $\mathcal{O}(V + 2E)$ — Each vertex is colored once (color[u] changes from -1 to 0 or 1 and never reverts!), so each vertex is popped/entered at most once and each undirected edge is checked twice.
    • Space Complexity: $\mathcal{O}(V)$ — color[V] plus stack depth $\le V$. Notice why Method A (explicit stack<int> S from the handwritten note) shines on skewed $10^5$-vertex path graphs: recursive DFS pushes $10^5$ OS call-stack frames (risking stack overflow under tight contest limits), whereas S.push(source) runs in $\mathcal{O}(V)$ heap-backed memory with zero recursion!
    • Coloring on Push vs. Pop in Stack DFS: In Method A, setting color[adj] = 1 - color[currentNode] before S.push(adj) acts just like visited-on-push—preventing duplicate stack entries and catching conflicts immediately!
    • Empty Edge Set ($E = 0$): Every vertex becomes a singleton component colored 0, returning true in $\mathcal{O}(V)$.
