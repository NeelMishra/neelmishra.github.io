    Container With Most Water (LeetCode 11): The [1, 2, 1] Greedy Counterexample & Shorter-Wall Elimination Proof

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 08_Container_with_most_water.pdf (1 page) · Jump to original scan

    In Container With Most Water (LeetCode 11), we are given $n$ thin vertical lines at x-coordinates $0, 1, \dots, n - 1$ where line $i$ connects $(i, 0)$ to $(i, \text{height}[i])$. Unlike Trapping Rain Water (LC 42), lines here have zero width and interior lines do not displace or block water — we simply choose one pair of walls $(l, r)$ ($0 \le l < r < n$) maximizing the rectangular area:

    $$A(l, r) = (r - l) \cdot \min\bigl(\text{height}[l],\, \text{height}[r]\bigr)$$

    On the classic LeetCode example height = [1, 8, 6, 2, 5, 4, 8, 3, 7], pairing $l = 1$ ($\text{height}[1] = 8$) with $r = 8$ ($\text{height}[8] = 7$) yields maximum area $(8 - 1) \times \min(8, 7) = 7 \times 7 = \mathbf{49}$.

    1. Brute Force & Why One-Sided Greedy Fails on [1, 2, 1]

    • Brute Force ($\mathcal{O}(n^2)$ time, $\mathcal{O}(1)$ space): Test all $\binom{n}{2} = \frac{n(n - 1)}{2}$ pairs $(l, r)$ with $l < r$ and track the maximum $A(l, r)$. Too slow for $n = 10^5$ ($\approx 5 \times 10^9$ pairs).

    Failed One-Sided Greedy Heuristic (08_Container_with_most_water.pdf, Page 1)

    A tempting first guess — explicitly tested and refuted at the bottom of Page 1 — is: "Fix the left wall $i$, and pick the best right column $j$ according to its height[j] * distance score."

    Look at the 3-element counterexample height = [1, 2, 1] drawn in the scan for left wall $i = 0$ ($\text{height}[0] = 1$):

    • Candidate $j = 1$ ($\text{height}[1] = 2$, distance $1 - 0 = 1$) has raw score $2 \times 1 = 2$, yet the short left wall $\text{height}[0] = 1$ clamps the actual water height to $\min(1, 2) = 1$, giving true area $1 \times 1 = \mathbf{1}$!
    • Candidate $j = 2$ ($\text{height}[2] = 1$, distance $2 - 0 = 2$) has raw score $1 \times 2 = 2$, and true area $\min(1, 1) \times 2 = \mathbf{2}$!

    Worse yet, on [1, 3, 1], $j = 1$ has raw score $3 \times 1 = 3 > 1 \times 2 = 2$, tricking the heuristic into returning area $1$ instead of area $2$! Because $\min(h[l], h[r])$ couples both walls simultaneously, no one-sided formula on $j$ alone can rank partners.

    2. Optimal $\mathcal{O}(n)$ Two Pointers & Shorter-Wall Elimination Proof

    Start with pointers at the maximum possible width: l = 0 and r = n - 1. At every step:

    1. Compute and record best = max(best, (r - l) * min(height[l], height[r])).
    2. Move whichever wall is shorter inward: if height[l] <= height[r] increment l++, otherwise decrement r--.

    Proof by Dominance: Why Discarding the Shorter Wall Never Misses the Optimum

    Assume at the start of an iteration our active window is $[l, r]$ (meaning no optimal pair touches any already-discarded endpoint outside $[l, r]$), and without loss of generality suppose $\text{height}[l] \le \text{height}[r]$:

    • We first record $A(l, r) = \text{height}[l] \cdot (r - l)$.
    • When we increment $l \to l + 1$, the only unexamined pairs we skip forever are pairs $(l, r')$ with $l < r' < r$. Pick any such interior partner $r'$:
      1. Width strictly decreases: $r' - l < r - l$.
      2. Effective height cannot exceed $\text{height}[l]$: $\min(\text{height}[l], \text{height}[r']) \le \text{height}[l]$ (even if $\text{height}[r'] = 10^9$, wall $l$ still caps the water level at $\text{height}[l]$!).
    • Multiplying the two inequalities (since heights are $\ge 0$ and widths are $> 0$): $$A(l, r') = \min\bigl(\text{height}[l], \text{height}[r']\bigr) \cdot (r' - l) \;\le\; \text{height}[l] \cdot (r' - l) \;\le\; \text{height}[l] \cdot (r - l) \;=\; A(l, r)$$

    Every skipped pair $(l, r')$ is dominated by $A(l, r)$, which we already recorded! What if $\text{height}[l] == \text{height}[r]$? Then neither $l$ nor $r$ can achieve an area larger than $A(l, r)$ with any interior partner $k \in (l, r)$, so advancing either pointer (or even advancing both l++, r-- simultaneously!) preserves the invariant.

    4. Clean C++ Reference Implementation

    #include <bits/stdc++.h>
using namespace std;

// LeetCode 11: Container With Most Water — O(n) time, O(1) extra space
int maxArea(const vector<int>& height) {
    int l = 0, r = (int)height.size() - 1;
    long long best = 0;

    while (l < r) {
        long long h = min(height[l], height[r]);
        best = max(best, h * (r - l));
        if (height[l] <= height[r]) ++l;
        else --r;
    }
    return (int)best;
}

    5. Contrast With LC 42 & Key Edge Cases

    Why identical if (h[l] <= h[r]) l++; else r--; movement solves two completely different geometric problems.
    Aspect Trapping Rain Water (LC 42) Container With Most Water (LC 11)
    Wall GeometrySolid width-$1$ blocks that displace waterZero-width dividers; interior lines ignored
    Formula$\sum_{i=0}^{n-1} \bigl(\min(L_i, R_i) - h[i]\bigr)$$\max_{0 \le l < r < n} (r - l)\min(h[l], h[r])$
    Invariant on l++Cell $l$'s exact column water is finalized ($\text{lMax} \le R_l$)All narrower pairs $(l, r')$ are dominated by $A(l, r)$
    Complexity$\mathcal{O}(n)$ time, $\mathcal{O}(1)$ space$\mathcal{O}(n)$ time, $\mathcal{O}(1)$ space
    • Zero-height lines (e.g., [0, 5, 0]): Area is $0$ whenever $\min(h[l], h[r]) = 0$; the pointer on 0 immediately steps inward.
    • Two-line minimum input (height = [1, 1], LeetCode Example 2): One iteration evaluates $(1 - 0) \times \min(1, 1) = 1$ and terminates.
