    Striver Array Lecture 6: Sort 0s, 1s & 2s — Dijkstra's Dutch National Flag Algorithm (LC 75)

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 06_Striver_lecture_6.pdf (1 page) · Jump to original scan

    Given an array nums containing only 0s, 1s, and 2s (representing red, white, and blue in LeetCode 75 — Sort Colors), sort the array in-place in a single pass using $\mathcal{O}(1)$ extra space. Beyond solving LC 75, Edsger Dijkstra's Dutch National Flag (DNF) 3-way partition is the exact engine that prevents Quicksort from degrading to $\mathcal{O}(N^2)$ on arrays with heavy duplicate keys!

    1. Brute Force $\to$ Better Progression

    1. Brute Force — Generic Comparison Sort ($\mathcal{O}(N \log N)$ time, $\mathcal{O}(1)$–$\mathcal{O}(\log N)$ space): Calling std::sort ignores that only three distinct values exist.
    2. Better — Two-Pass Counting Overwrite ($\mathcal{O}(2N)$ time, $\mathcal{O}(1)$ space): Pass 1 counts cnt0, cnt1, and cnt2; Pass 2 overwrites the first cnt0 slots with 0, the next cnt1 slots with 1, and the remaining cnt2 slots with 2. Notice two drawbacks: (a) it reads and writes the array in two passes instead of one, and (b) if array elements are objects keyed by color {0, 1, 2}, overwriting literals destroys satellite data instead of moving actual records!

    2. Optimal: Dutch National Flag 4-Zone Region Invariant

    Page 1 of Lecture 6 captures the entire algorithm in a single boundary diagram. Maintain three pointers — low, mid, and high — dividing indices $0 \dots N - 1$ into four contiguous zones at the start of every iteration:

    • [0 .. low - 1] $\longrightarrow$ all 0s (extreme left)
    • [low .. mid - 1] $\longrightarrow$ all 1s (middle settled band)
    • [mid .. high] $\longrightarrow$ unsorted / unknown (drawn as a wavy squiggle on Page 1!)
    • [high + 1 .. N - 1] $\longrightarrow$ all 2s (extreme right)

    2.1 The Three Transition Rules & Asymmetry Proof

    Inspect nums[mid] — the leftmost element of the unknown region [mid .. high] — while mid <= high:

    Why mid Advances on 0 and 1, Yet Freezes on 2

    1. Case nums[mid] == 0 $\implies$ swap(nums[low], nums[mid]); low++; mid++;
      Why don't we need to re-inspect what got swapped back into nums[mid]?
      • If low == mid (the 1s zone is currently empty), we swapped 0 with itself and both pointers step past that settled 0.
      • If low < mid, index low is the first slot of [low .. mid - 1], which by our loop invariant is 100% guaranteed to hold a 1! Swapping puts 0 at low (extending [0 .. low]) and puts 1 at mid (extending [low + 1 .. mid]), so advancing both low++ and mid++ preserves every zone!
    2. Case nums[mid] == 1 $\implies$ mid++;
      nums[mid] is already adjacent to the right boundary of [low .. mid - 1]; simply absorb it into the 1s zone!
    3. Case nums[mid] == 2 $\implies$ swap(nums[mid], nums[high]); high--; (DO NOT increment mid!)
      Index high is the rightmost slot of the unsorted zone [mid .. high]! After placing 2 at nums[high] and shrinking high--, the value newly sitting at nums[mid] came from unknown territory and could be 0, 1, or another 2 — leaving mid stationary forces the very next iteration to classify it properly.
    Complete single-pass DNF trace on nums = [2, 0, 2, 1, 1, 0] ($N = 6$).
    Step (low, mid, high) nums[mid] Action Array State After Step
    1(0, 0, 5)2swap(0, 5); high--[0, 0, 2, 1, 1 | 2]
    2(0, 0, 4)0swap(0, 0); low++; mid++[0 | 0, 2, 1, 1 | 2]
    3(1, 1, 4)0swap(1, 1); low++; mid++[0, 0 | 2, 1, 1 | 2]
    4(2, 2, 4)2swap(2, 4); high--[0, 0 | 1, 1 | 2, 2]
    5(2, 2, 3)1mid++[0, 0 | 1 | 1 | 2, 2]
    6(2, 3, 3)1mid++[0, 0 | 1, 1 | | 2, 2] (mid = 4 > high = 3 $\to$ stop!)

    3. Clean C++ Reference Implementation

    #include <bits/stdc++.h>
using namespace std;

// LeetCode 75: Sort Colors via Dutch National Flag
// Time: O(N) (exact N iterations), Extra Space: O(1)
void sortColors(vector<int>& nums) {
    int low = 0, mid = 0, high = (int)nums.size() - 1;

    while (mid <= high) {
        if (nums[mid] == 0) {
            swap(nums[low++], nums[mid++]);
        } else if (nums[mid] == 1) {
            ++mid;
        } else { // nums[mid] == 2
            swap(nums[mid], nums[high--]);
        }
    }
}

    4. Exact Iteration Count Proof & Edge Cases

    Exact $N$-Step Termination Proof: Define the potential function $\Phi = \text{high} - \text{mid} + 1$ (the exact number of elements remaining in the unknown zone). Initially $\Phi = (N - 1) - 0 + 1 = N$. In Cases 0 and 1, mid increases by $1$ while high stays fixed ($\Delta \Phi = -1$); in Case 2, high decreases by $1$ while mid stays fixed ($\Delta \Phi = -1$). Because $\Phi$ drops by exactly $1$ on every iteration and the loop stops as soon as $\Phi = 0$ (mid == high + 1), the while body executes literally $N$ times on every input of size $N$ — true single-pass $\mathcal{O}(N)$ time and $\mathcal{O}(1)$ extra space!

    • Loop condition mid <= high (not mid < high!): When mid == high, a single uninspected element still remains in [mid .. high]. Stopping at mid < high leaves [2, 0, 1] unsorted (at step 2: [1, 0, 2] with low = 0, mid = 1, high = 1, missing the final 0 swap!).
    • Missing bucket (e.g., all 2s or only 0s and 2s): All three branches still maintain valid empty ranges ($[a..a-1]$) cleanly without special cases.
