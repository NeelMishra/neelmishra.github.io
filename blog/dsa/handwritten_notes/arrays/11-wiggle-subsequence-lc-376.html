    Wiggle Subsequence (LeetCode 376): Corrupted-Run Recovery, Peak/Valley Greedy & 2-State DP

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 11_Wiggle_sequence.pdf (1 page) · Jump to original scan

    A sequence of numbers is called a wiggle sequence if the differences between successive elements strictly alternate between positive and negative (the first difference may be either positive or negative; a sequence of $1$ element, or $2$ unequal elements, trivially wiggles). On Page 1 of the handwritten note, [1, 7, 4, 9, 2, 5] has consecutive differences [+6, -3, +5, -7, +3], so the entire array of length 6 is a wiggle sequence.

    Given an integer array nums, LeetCode 376 asks for the length of the longest wiggle subsequence (obtained by deleting zero or more elements without reordering the survivors). At first glance this looks like $\mathcal{O}(N^2)$ Longest Increasing Subsequence DP — yet a clean greedy exchange argument collapses it to a single $\mathcal{O}(N)$ pass in $\mathcal{O}(1)$ extra space!

    1. Answering Page 1's Two Diagnostic Questions

    Page 1 walks through nums = [1, 17, 5, 10, 13, 15, 10, 5, 16, 8] by posing two sharp questions:

    1. Q1: When can the wiggle sequence length NOT be increased?
      Whenever the alternating sign pattern is corrupted — i.e., a +ve step is followed by another +ve step (such as the rising run $5 \to 10 \to 13 \to 15$), a -ve step is followed by another -ve step ($15 \to 10 \to 5$), or adjacent values tie ($\text{diff} = 0$).
    2. Q2: Is there recovery from a corrupted run, or is it best to start new?
      If the problem asked for a contiguous subarray (like LeetCode 978 Longest Turbulent Subarray), even one broken adjacent pair would force us to start a brand-new window. Here we are building a subsequence! Deleting intermediate elements inside a monotonic run heals the break completely without discarding our prefix — and even better, upgrading the endpoint to the run's extreme peak or valley strictly helps future steps!
    Greedy Extremum Replacement Proof (Why Local Peaks & Valleys Are Always Optimal) Suppose our wiggle prefix is [1, 17, 5, 10] (last step $+5$, so as written at the bottom of Page 1: "seek -ve if +ve, seek +ve if -ve"). Next come $13$ and $15$ (more +ve steps!). Should we keep $10$ or replace $10$ with $15$?
    • Replacing $10 \to 15$ keeps the current subsequence length identical ($4$ elements: [1, 17, 5, 15]).
    • To extend to length $5$, we need a future value $x$ strictly below our last element. Because $\{x : x < 15\} \supset \{x : x < 10\}$, every downward continuation valid after $10$ is also valid after $15$, plus values $x \in [10, 14]$ work ONLY after $15$! (Indeed, the very next number in the array is $10$ — which fails $10 < 10$ if we kept $10$, yet succeeds $10 < 15$ once we climbed to the peak $15$!)
    By symmetry, during any falling run ($15 \to 10 \to 5$), always slide all the way down to the lowest local valley ($5$) to maximize headroom for the next upward step. Therefore, the maximum wiggle length equals the number of alternating local peaks and valleys!

    2. Brute $\mathcal{O}(N^2)$ DP $\to$ Two Equivalent $\mathcal{O}(N)$ / $\mathcal{O}(1)$-Space Formulations

    1. Baseline — $\mathcal{O}(N^2)$ LIS-Style DP ($\mathcal{O}(N)$ space): Define up[i] and down[i] ending specifically at index $i$ by scanning all $j < i$: if nums[j] < nums[i] update up[i] = max(up[i], down[j] + 1); if nums[j] > nums[i] update down[i] = max(down[i], up[j] + 1).
    2. Optimal A — Greedy Sign-Flip Counter ($\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space — matches Page 1's note): Initialize prevDiff = 0 (accepting either sign for the very first turn) and count = 1. At each step $i = 1 \dots N - 1$, compute currDiff = nums[i] - nums[i - 1]:
      • Whenever (currDiff > 0 && prevDiff <= 0) || (currDiff < 0 && prevDiff >= 0), we just crossed a genuine direction turn $\implies$ increment count++ and set prevDiff = currDiff.
      • Critical Plateau Guard: Update prevDiff = currDiff only inside the if! If currDiff == 0 (e.g. [1, 2, 2, 1]) and you overwrote prevDiff = 0 outside the if, then [1, 2, 2, 3] would see prevDiff == 0 before 3 and falsely count 1 -> 2 -> 3 as two turns!
    3. Optimal B — Space-Optimized 2-State (up, down) DP ($\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space): Let up (resp. down) be the longest wiggle subsequence anywhere in prefix nums[0..i] ending with a rising (resp. falling) step, initialized to up = 1, down = 1:
      • If nums[i] > nums[i - 1]: up = down + 1 (during a monotone climb $5 \to 10 \to 13 \to 15$, down stays frozen at $3$, so up = 3 + 1 = 4 never double-counts!).
      • Else if nums[i] < nums[i - 1]: down = up + 1.

    3. Clean Reference Implementations (C++ & Python)

    #include <bits/stdc++.h>
using namespace std;

// Formulation A: Greedy Sign-Flip / Peak-Valley Counter — O(N) time, O(1) space
int wiggleMaxLength(const vector<int>& nums) {
    if (nums.empty()) return 0;
    int prevDiff = 0, count = 1;

    for (size_t i = 1; i < nums.size(); ++i) {
        int currDiff = nums[i] - nums[i - 1];
        if ((currDiff > 0 && prevDiff <= 0) || (currDiff < 0 && prevDiff >= 0)) {
            ++count;
            prevDiff = currDiff; // ONLY update on a non-zero direction change!
        }
    }
    return count;
}

// Formulation B: Equivalent 2-State (up, down) DP — O(N) time, O(1) space
int wiggleMaxLengthDP(const vector<int>& nums) {
    if (nums.empty()) return 0;
    int up = 1, down = 1;
    for (size_t i = 1; i < nums.size(); ++i) {
        if (nums[i] > nums[i - 1]) up = down + 1;
        else if (nums[i] < nums[i - 1]) down = up + 1;
    }
    return max(up, down);
}
    def wiggle_max_length(nums: list[int]) -> int:
    """LeetCode 376 in O(N) time, O(1) extra space."""
    if not nums:
        return 0
    up = down = 1
    for i in range(1, len(nums)):
        if nums[i] > nums[i - 1]:
            up = down + 1
        elif nums[i] < nums[i - 1]:
            down = up + 1
    return max(up, down)

    4. Complexity Summary & Key Edge Cases

    • Time & Space: Single linear scan $\mathcal{O}(N)$ time and $\mathcal{O}(1)$ extra space (down from $\mathcal{O}(N^2)$ time and $\mathcal{O}(N)$ space in naive LIS-style DP).
    • All-equal array ([3, 3, 3, 3]): Every currDiff == 0, so neither branch fires and both implementations cleanly return 1 (a single element is a valid wiggle sequence of length $1$, not $2$!).
    • Strictly monotonic array ([1, 2, 3, 4, 5]): Returns 2 (any pair such as [1, 5]).
