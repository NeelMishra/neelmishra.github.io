    Striver Array Lecture 9: Rearrange Array Elements by Sign Preserving Order (LC 2149)

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 10_Striver_lecture_9.pdf (1 page) · Jump to original scan

    Given an even-length integer array arr containing $N / 2$ positive and $N / 2$ negative integers — e.g. Page 1's arr = [3, 1, -2, -5, 2, -4] — rearrange its elements into alternating [+, -, +, -, ...] order starting with a positive integer, while preserving the relative order of elements of the same sign:

    $$[3,\, 1,\, -2,\, -5,\, 2,\, -4] \;\longrightarrow\; [3,\, -2,\, 1,\, -5,\, 2,\, -4]$$

    Notice that the positive subsequence remains 3, 1, 2 and the negative subsequence remains -2, -5, -4.

    1. Why $\mathcal{O}(N)$ Extra Space Is Required for $\mathcal{O}(N)$ Time

    Page 1 specifically remarks: "Works when in-place modification is not required." Why can't we just use an $\mathcal{O}(1)$-space Lomuto/Hoare swap like in Dutch National Flag?

    • Unstable swaps break relative order: Swapping an out-of-place element across multiple intervening elements scrambles their original sequence.
    • In-place order-preserving right-rotation costs $\mathcal{O}(N^2)$: On an adversarial input like [1, 2, ..., k, -1, -2, ..., -k], right-rotating each negative past up to $k = N / 2$ positives shifts $\Theta(N^2)$ elements in the worst case!

    Hence allocating an $\mathcal{O}(N)$ output array unlocks true $\mathcal{O}(N)$ linear time.

    2. Brute $\to$ Two Search Pointers $\to$ Stride-2 Parity Write Pointers

    1. Two-Pass Bucket Baseline ($\mathcal{O}(2N)$ time, $\mathcal{O}(N)$ auxiliary space):
      • Pass 1: Append positives to pos[] ([3, 1, 2]) and negatives to neg[] ([-2, -5, -4]).
      • Pass 2: For $i = 0 \dots N / 2 - 1$, write arr[2 * i] = pos[i] and arr[2 * i + 1] = neg[i].
    2. Handwritten Approach 1 — Two Read Search Pointers + Output Insert Pointer (Page 1 Top, $\mathcal{O}(2N)$ pointer steps, $\mathcal{O}(N)$ output space): Maintain posSearch = 0 (scanning for positives), negSearch = 0 (scanning for negatives), and output cursor ins = 0 .. N - 1:
      • When ins is even: advance while (arr[posSearch] < 0) posSearch++, then write ans[ins] = arr[posSearch++].
      • When ins is odd: advance while (arr[negSearch] > 0) negSearch++, then write ans[ins] = arr[negSearch++].
      Each search pointer walks $0 \to N$ at most once ($\le 2N$ reads total) without allocating intermediate pos[] / neg[] vectors!
    3. Handwritten Approach 2 (Cleanest Optimal) — Single-Pass Stride-2 Parity Write Pointers (Page 1 Bottom, $\mathcal{O}(N)$ single pass, $\mathcal{O}(N)$ output space): Flip the perspective from pulling to pushing! We already know upfront that in [+, -, +, -, ...]:
      • Every positive element lands at an even index: $0, 2, 4, \dots, N - 2$.
      • Every negative element lands at an odd index: $1, 3, 5, \dots, N - 1$.
      Keep posIdx = 0 and negIdx = 1 into ans, scan arr once left-to-right, drop each element into its parity slot, and increment that write pointer by +2!

    3. Follow-Up Variant: Unequal Counts of Positives & Negatives

    What if the array has $P$ positives and $Q$ negatives with $P \ne Q$ (e.g. [1, 2, -4, -5, 3, 4] where $P = 4, Q = 2$), and leftover elements of the majority sign must be appended contiguously at the tail ([1, -4, 2, -5, 3, 4])?

    • Because leftover elements switch from stride-2 alternation to stride-1 contiguous placement after index $2 \min(P, Q)$ — and we don't know $\min(P, Q)$ before scanning the array! — single-pass stride-2 indexing no longer knows where stride-2 ends.
    • Fall back cleanly to the Two-Bucket Method ($\mathcal{O}(2N)$ time, $\mathcal{O}(N)$ space): interleave the first $m = \min(P, Q)$ pairs into arr[0 .. 2m - 1], then copy the remaining $|P - Q|$ elements from the larger bucket into arr[2m .. N - 1]!

    4. Clean C++ Reference Implementations

    #include <bits/stdc++.h>
using namespace std;

// 1. LeetCode 2149 (Equal +ve & -ve): Single-pass stride-2 parity write pointers
//    Time: O(N), Space: O(N) output vector (O(1) extra working memory)
vector<int> rearrangeArray(const vector<int>& nums) {
    vector<int> ans(nums.size());
    int posIdx = 0, negIdx = 1;
    for (int x : nums) {
        if (x > 0) {
            ans[posIdx] = x;
            posIdx += 2;
        } else {
            ans[negIdx] = x;
            negIdx += 2;
        }
    }
    return ans;
}

// 2. Handwritten Approach 1: Two read search pointers + output insert pointer — O(2N) steps
vector<int> rearrangeArraySearchPtrs(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n);
    int p = 0, q = 0;
    for (int ins = 0; ins < n; ++ins) {
        if (ins % 2 == 0) {
            while (nums[p] < 0) ++p;
            ans[ins] = nums[p++];
        } else {
            while (nums[q] > 0) ++q;
            ans[ins] = nums[q++];
        }
    }
    return ans;
}

// 3. Follow-Up Variant (Unequal counts of +ve & -ve): O(2N) time, O(N) space
vector<int> rearrangeUnequal(vector<int> arr) {
    vector<int> pos, neg;
    for (int x : arr) {
        if (x >= 0) pos.push_back(x);
        else neg.push_back(x);
    }
    size_t m = min(pos.size(), neg.size());
    for (size_t i = 0; i < m; ++i) {
        arr[2 * i] = pos[i];
        arr[2 * i + 1] = neg[i];
    }
    size_t idx = 2 * m;
    for (size_t i = m; i < pos.size(); ++i) arr[idx++] = pos[i];
    for (size_t i = m; i < neg.size(); ++i) arr[idx++] = neg[i];
    return arr;
}

    • Classification of 0: LeetCode 2149 guarantees $a_i \ne 0$; in general interview statements where 0 can appear, ask the interviewer upfront whether 0 counts as non-negative (x >= 0) before coding!
    • All positives first ([1, 2, 3, -1, -2, -3]) or all negatives first ([-1, -2, -3, 1, 2, 3]): Stride-2 parity write pointers fill all even (or all odd) indices first without ever going out of bounds because exactly $N / 2$ of each sign exist.
