    Trapping Rain Water (LeetCode 42): Cell-by-Cell Decomposition & $\mathcal{O}(1)$-Space Two-Pointer Proof

    October 2026 · 10 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 07_Trapping_rainwater.pdf (2 pages) · Jump to original scans

    Given $n$ non-negative integers representing an elevation map where each solid bar has width $1$ — e.g. height = [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1] — compute how many total units of rainwater remain trapped after raining (6 units). Trapping Rain Water (LeetCode 42) is a quintessential Hard interview problem because everything hinges on switching from a messy basin-by-basin mental model to a local cell-by-cell equation.

    1. Physical Decomposition: Go Cell by Cell, Not Basin by Basin

    When people first sketch elevation bars, they instinctively stand on a bar $i$ and try to look forward for "the next bar at least as tall as $h[i]$" to bound a wide basin — which immediately breaks whenever $h[i]$ is the global peak and no taller bar ever appears to its right! Page 1 of the handwritten note states the clean reframing and backs it with three physical sketches:

    Cell-Wise Capacity Principle (Pages 1–2) "It's better to calculate water in each cell than to calculate water holding capacity of future cells given a cell — hence go cell by cell!"
    1. Sketch 1 (Left-Wall Bottleneck): If the tallest pillar to the left ($\text{leftMax}[i]$) is shorter than the tallest pillar to the right ($\text{rightMax}[i]$), water spills out over the left side above height $\text{leftMax}[i]$.
    2. Sketch 2 (Right-Wall Bottleneck): Symmetrically, if the right side is lower, water spills out over the right side above height $\text{rightMax}[i]$. Thus the water surface above column $i$ sits at $\min(\text{leftMax}[i], \text{rightMax}[i])$.
    3. Sketch 3 (Solid Block Displacement): Column $i$ is already occupied at the bottom by a solid bar of height $\text{height}[i]$, which displaces that much water!
    $$\text{Capacity}[i] = \underbrace{\min\bigl(\text{leftMax}[i],\, \text{rightMax}[i]\bigr)}_{\text{maximum cell holding surface}} \;-\; \underbrace{\text{height}[i]}_{\text{solid block displacement}}$$

    Defining $\text{leftMax}[i] = \max_{0 \le k \le i} \text{height}[k]$ and $\text{rightMax}[i] = \max_{i \le k < n} \text{height}[k]$ inclusively guarantees $\min(\text{leftMax}[i], \text{rightMax}[i]) \ge \text{height}[i]$ at every index $i$, so $\text{Capacity}[i] \ge 0$ without needing a separate clamp!

    2. Brute $\to$ Prefix/Suffix Max $\to$ Optimal Two Pointers

    1. Brute Force ($\mathcal{O}(N^2)$ time, $\mathcal{O}(1)$ space): For each index $i \in [0, N - 1]$, scan $0..i$ to compute $\text{leftMax}[i]$ and scan $i..N - 1$ to compute $\text{rightMax}[i]$, adding $\min(\text{leftMax}[i], \text{rightMax}[i]) - h[i]$.
    2. Better — Precomputed Prefix & Suffix Max Arrays ($\mathcal{O}(3N)$ time, $\mathcal{O}(2N)$ space): Precompute pref[i] = max(pref[i - 1], h[i]) left-to-right and suff[i] = max(suff[i + 1], h[i]) right-to-left, then sum min(pref[i], suff[i]) - h[i]. (You can halve memory to $\mathcal{O}(N)$ by storing only suff[] and tracking leftMax as a running scalar in the final pass.)
    3. Optimal — Converging Two Pointers ($\mathcal{O}(N)$ time, $\mathcal{O}(1)$ extra space): Maintain l = 0, r = N - 1, running prefix max lMax = 0 (over $0..l$), and running suffix max rMax = 0 (over $r..N - 1$):
      • If h[l] <= h[r]: update lMax = max(lMax, h[l]), add lMax - h[l] to water, and advance l++.
      • Else (h[l] > h[r]): update rMax = max(rMax, h[r]), add rMax - h[r] to water, and decrement r--.

    Rigorous Proof: How Can We Finalize Cell l Without Scanning $[l + 1 .. r - 1]$?

    Suppose at the current iteration $\text{h}[l] \le \text{h}[r]$ and we set $\text{lMax} \gets \max(\text{lMax}, \text{h}[l])$. Clearly $\text{lMax} = \text{trueLeftMax}[l] = \max_{0 \le k \le l} \text{h}[k]$ exactly. Why is $\min(\text{trueLeftMax}[l], \text{trueRightMax}[l])$ guaranteed to equal $\text{lMax}$ even though $[l + 1 .. r - 1]$ is still unseen?

    • Case A ($\text{lMax} = \text{h}[l]$): Since $r > l$, bar $r$ lies to the right of $l$, so $\text{trueRightMax}[l] \ge \text{h}[r] \ge \text{h}[l] = \text{lMax}$.
    • Case B ($\text{lMax} > \text{h}[l]$): Then $\text{lMax} = \text{h}[l^*]$ for some earlier index $l^* < l$ that pointer $l$ already stepped past. At the exact step when $l$ advanced past $l^*$, pointer $r$ stood at some position $r^* \ge r > l$ satisfying $\text{h}[l^*] \le \text{h}[r^*]$ (otherwise $r$ would have moved instead of $l^*$). Because $r^* > l$, bar $r^*$ lies to the right of $l$, proving $\text{trueRightMax}[l] \ge \text{h}[r^*] \ge \text{h}[l^*] = \text{lMax}$!

    In both cases $\text{lMax} \le \text{trueRightMax}[l]$, so $\min(\text{trueLeftMax}[l], \text{trueRightMax}[l]) = \text{lMax}$ identically — unseen interior bars in $(l, r)$ can only push $\text{trueRightMax}[l]$ even higher, never lowering the minimum! By symmetry, when $\text{h}[l] > \text{h}[r]$, $\text{rMax} \le \text{trueLeftMax}[r]$ holds identically.

    4. Clean Reference Implementations (C++ & Python)

    #include <bits/stdc++.h>
using namespace std;

// Better: Prefix & Suffix Max Arrays — O(3N) = O(N) time, O(2N) = O(N) space
int trapPrefixSuffix(const vector<int>& h) {
    int n = (int)h.size();
    if (n < 3) return 0;
    vector<int> pref(n), suff(n);
    pref[0] = h[0];
    for (int i = 1; i < n; ++i) pref[i] = max(pref[i - 1], h[i]);
    suff[n - 1] = h[n - 1];
    for (int i = n - 2; i >= 0; --i) suff[i] = max(suff[i + 1], h[i]);

    int water = 0;
    for (int i = 0; i < n; ++i) {
        water += min(pref[i], suff[i]) - h[i];
    }
    return water;
}

// Optimal: Converging Two Pointers — O(N) time, O(1) extra space
int trap(const vector<int>& h) {
    int l = 0, r = (int)h.size() - 1;
    int lMax = 0, rMax = 0, water = 0;

    while (l < r) {
        if (h[l] <= h[r]) {
            lMax = max(lMax, h[l]);
            water += lMax - h[l];
            ++l;
        } else {
            rMax = max(rMax, h[r]);
            water += rMax - h[r];
            --r;
        }
    }
    return water;
}
    def trap(height: list[int]) -> int:
    """LeetCode 42 optimal two pointers: O(N) time, O(1) space."""
    l, r = 0, len(height) - 1
    l_max = r_max = water = 0

    while l < r:
        if height[l] <= height[r]:
            l_max = max(l_max, height[l])
            water += l_max - height[l]
            l += 1
        else:
            r_max = max(r_max, height[r])
            water += r_max - height[r]
            r -= 1
    return water

    5. Complexity Summary & Key Edge Cases

    Complexity comparison for Trapping Rain Water (LeetCode 42).
    Method Time Complexity Extra Space
    Per-Cell Left/Right Scan (Brute)$\mathcal{O}(N^2)$$\mathcal{O}(1)$
    Prefix & Suffix Max Arrays$\mathcal{O}(3N) = \mathcal{O}(N)$$\mathcal{O}(2N) = \mathcal{O}(N)$
    Monotonic Decreasing Stack$\mathcal{O}(2N) = \mathcal{O}(N)$$\mathcal{O}(N)$
    Converging Two Pointers (Optimal)$\mathcal{O}(N)$ (1 pass)$\mathcal{O}(1)$
    • $N < 3$ bars ([], [5], [4, 2]): Need at least a left wall, an interior dip, and a right wall to hold water $\implies$ while (l < r) naturally returns 0.
    • Monotonic staircase ([1, 2, 3, 4] or [4, 3, 2, 1]) or flat roof ([3, 3, 3]): Every step updates lMax = h[l] (or rMax = h[r]), adding $0$ water at every column.
