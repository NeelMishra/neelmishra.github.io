    Part 4: Wiggle Subsequence (LC 376) & Pingala's (Pascal's) Triangle Combinatorics

    October 2026 · 15 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (11_Wiggle_sequence.pdf, 13_Pingalas_triangle.pdf — 3 pages) · Jump to original scans

    The final two standalone notebooks in the Arrays collection tackle two deceptive interview favourites: Wiggle Subsequence (LC 376), which looks like $\mathcal{O}(n^2)$ LIS-style dynamic programming until you spot the local extremum invariant, and Pingala's (Pascal's) Triangle (LC 118 / LC 119), where naive factorials overflow 64-bit integers at row 21 unless reduced to multiplicative step ratios.

    1. Wiggle Subsequence (LeetCode 376)

    1.1 Alternating Differences & Recovering From a "Corrupted" Monotonic Run

    A sequence is a wiggle sequence if successive differences $d_i = \text{nums}[i] - \text{nums}[i - 1]$ strictly alternate between positive and negative (the initial step may be either sign; sequences of length $1$, or length $2$ with unequal elements, trivially qualify). On Page 1 of 11_Wiggle_sequence.pdf, [1, 7, 4, 9, 2, 5] has differences [+6, -3, +5, -7, +3], so the entire array of length 6 wiggles.

    Now follow the two diagnostic questions written in the scan on nums = [1, 17, 5, 10, 13, 15, 10, 5, 16, 8]:

    1. When does a consecutive step fail to extend our wiggle length? Whenever the alternating sign pattern is corrupted — i.e., a +ve step is followed by another +ve step (such as $5 \to 10 \to 13 \to 15$), a -ve step is followed by another -ve step ($15 \to 10 \to 5$), or adjacent values tie ($\text{diff} = 0$).
    2. Should we restart a brand-new sequence when a pair breaks? No! Because we are choosing a subsequence (not a contiguous subarray), we can delete intermediate elements inside any monotonic run. Better yet, which element of the rising run $5 \to 10 \to 13 \to 15$ should represent the +ve step after $5$?
    Greedy Extremum Replacement Proof Suppose our wiggle subsequence currently ends with a rising step $5 \to 10$ (seeking a -ve step next), and the next two numbers are $13$ and $15$ (both +ve). Replacing endpoint $10$ with $15$ keeps the subsequence length unchanged right now ($1, 17, 5, 15$), while strictly enlarging the set of valid next downward values ($\{x : x < 15\} \supset \{x : x < 10\}$)! For instance, if the next number were $12$, keeping $10$ would fail ($12 \not< 10$) whereas upgrading to peak $15$ succeeds ($15 \to 12$)! By symmetry, inside a falling run ($15 \to 10 \to 5$), always slide down to the lowest valley ($5$).

    1.2 Sign-Flip Greedy vs. 2-State (up, down) DP ($\mathcal{O}(n)$ Time, $\mathcal{O}(1)$ Space)

    While a naive LIS-style 2-column DP checks all $j < i$ in $\mathcal{O}(n^2)$ time, both optimal formulations run in one $\mathcal{O}(n)$ pass and $\mathcal{O}(1)$ space:

    • Formulation A — Sign-Flip Counter (directly matching the handwritten note): Track prevDiff = 0 and count = 1. For each adjacent step currDiff = nums[i] - nums[i - 1], whenever (currDiff > 0 && prevDiff <= 0) || (currDiff < 0 && prevDiff >= 0), increment count++ and set prevDiff = currDiff. Crucial detail: do not update prevDiff when currDiff == 0, so flat plateaus like [1, 2, 2, 1] still remember the prior +1 climb when -1 arrives!
    • Formulation B — Space-Optimized 2-State DP: Let up (resp. down) be the longest wiggle subsequence in nums[0..i] ending with a rising (resp. falling) step, initialized to up = 1, down = 1. If nums[i] > nums[i - 1], set up = down + 1; if nums[i] < nums[i - 1], set down = up + 1. Notice that during $5 \to 10 \to 13 \to 15$, down stays frozen at $3$, so up = down + 1 repeatedly evaluates to $4$ without double-counting!
    // Formulation A: Greedy Sign-Flip / Peak-Valley Counter — O(n) time, O(1) space
int wiggleMaxLengthGreedy(const vector<int>& nums) {
    if (nums.empty()) return 0;
    int prevDiff = 0, count = 1;
    for (size_t i = 1; i < nums.size(); ++i) {
        int currDiff = nums[i] - nums[i - 1];
        if ((currDiff > 0 && prevDiff <= 0) || (currDiff < 0 && prevDiff >= 0)) {
            ++count;
            prevDiff = currDiff; // only update on non-zero turn!
        }
    }
    return count;
}

// Formulation B: Equivalent 2-State (up, down) DP — O(n) time, O(1) space
int wiggleMaxLengthDP(const vector<int>& nums) {
    if (nums.empty()) return 0;
    int up = 1, down = 1;
    for (size_t i = 1; i < nums.size(); ++i) {
        if (nums[i] > nums[i - 1]) up = down + 1;
        else if (nums[i] < nums[i - 1]) down = up + 1;
    }
    return max(up, down);
}

    2. Pingala's (Pascal's) Triangle — The 3 Interview Sub-Problems

    Long before Blaise Pascal's 1654 treatise, the binomial staircase was studied in ancient Indian prosody as Pingala's Meru Prastara (Chandas Shastra, c. 3rd–2nd century BCE, with explicit triangle commentary by Halayudha in the 10th century CE) to count $n$-syllable poetic metres with $k$ heavy syllables — which is why Notebook 13 is titled Pingala's Triangle.

    2.1 Sub-Problem 1: Return the Entry at Row $r$, Column $c$ in $\mathcal{O}(\min(c, r - c))$ Time

    For 1-indexed $(r, c)$, the entry equals $\binom{n}{k}$ with $n = r - 1$ and $k = c - 1$. Computing $n! / (k!(n - k)!)$ via three separate factorials is both wasteful ($\mathcal{O}(n)$ multiplications) and broken ($21! > 2^{63} - 1$ overflows long long even when $\binom{21}{2} = 210$ is tiny!).

    Cancelling $(n - k)!$ between numerator and denominator (as derived on Page 1 of 13_Pingalas_triangle.pdf) leaves exactly $k$ paired factors:

    $$\binom{n}{k} = \frac{n \times (n - 1) \times \dots \times (n - k + 1) \times (n - k)!}{k! \times (n - k)!} = \prod_{i=0}^{k-1} \frac{n - i}{i + 1} = \frac{n}{1} \times \frac{n - 1}{2} \times \frac{n - 2}{3} \times \dots \times \frac{n - k + 1}{k}$$

    Two Essential Implementation Details for nCr(n, k)

    1. Exploit symmetry first: Replace $k \gets \min(k, n - k)$ since $\binom{n}{k} = \binom{n}{n - k}$, bounding iterations at $\le n / 2$.
    2. Multiply BEFORE dividing in each step ($i = 0 \dots k - 1$): Write res = res * (n - i) / (i + 1), never res *= (n - i) / (i + 1)! After step $i$, res equals $\binom{n}{i + 1}$, which is an exact integer because the product of any $i + 1$ consecutive integers $n(n - 1)\cdots(n - i)$ is always divisible by $(i + 1)!$. (Note: on Page 1 of the scan, the algebraic numerator's final factor was jotted as n - r - 1 for $n - (r - 1) = n - r + 1$, whereas the Python loop right beneath it for i in range(0, r): res = res * (n - i); res = res / (i + 1) evaluates the exact $n - r + 1$ factor at $i = r - 1$!)

    2.2 Sub-Problem 2: Generate the Entire $N$-th Row in $\mathcal{O}(N)$ Time (LC 119)

    Calling nCr(N - 1, i) independently for each of the $N$ columns takes $\mathcal{O}(N^2)$ time. Instead, Page 2 of the scan inspects Row $N = 6$ ([1, 5, 10, 10, 5, 1], 0-indexed column $i \in [0, 5]$) and factors each entry out of its left neighbour:

    Row $N = 6$ Multiplicative Chain (13_Pingalas_triangle.pdf, Page 2)

    • $i = 0$: $\text{ans} = \mathbf{1}$
    • $i = 1$: $\text{ans} = 1 \times \frac{6 - 1}{1} = 1 \times \frac{5}{1} = \mathbf{5}$
    • $i = 2$: $\text{ans} = \left(\frac{5}{1}\right) \times \frac{6 - 2}{2} = 5 \times \frac{4}{2} = \mathbf{10}$
    • $i = 3$: $\text{ans} = \left(\frac{5 \times 4}{1 \times 2}\right) \times \frac{6 - 3}{3} = 10 \times \frac{3}{3} = \mathbf{10}$
    • $i = 4$: $\text{ans} = 10 \times \frac{6 - 4}{4} = 10 \times \frac{2}{4} = \mathbf{5}$  ·  $i = 5$: $5 \times \frac{1}{5} = \mathbf{1}$.

    In general, for 1-indexed row $N$ (or 0-indexed LeetCode 119 rowIndex $R = N - 1$):

    $$\text{row}[i] = \text{row}[i - 1] \times \frac{N - i}{i} = \text{row}[i - 1] \times \frac{R - i + 1}{i} \qquad (1 \le i \le R)$$

    Every element is produced from the previous element in $\mathcal{O}(1)$ arithmetic $\implies$ $\mathcal{O}(N)$ total time and $\mathcal{O}(1)$ extra space!

    2.3 Sub-Problem 3: Generate the First $N$ Rows (LC 118)

    To build all $N$ rows (containing $1 + 2 + \dots + N = \frac{N(N+1)}{2}$ entries total), either invoke the $\mathcal{O}(r)$ row generator for $r = 1 \dots N$, or apply Pingala's additive DP identity $\text{tri}[R][C] = \text{tri}[R - 1][C - 1] + \text{tri}[R - 1][C]$ (which never even needs 64-bit intermediate multiplication!). Both run in optimal $\mathcal{O}(N^2)$ time and $\mathcal{O}(1)$ auxiliary space beyond the output matrix.

    #include <bits/stdc++.h>
using namespace std;

// 1. Entry at 1-indexed (r, c) -> C(r - 1, c - 1) in O(min(c, r - c)) time, O(1) space
long long pingalaElement(int r, int c) {
    int n = r - 1;
    int k = min(c - 1, n - (c - 1));
    long long res = 1;
    for (int i = 0; i < k; ++i) {
        res = res * (n - i) / (i + 1); // multiply first -> exact integer division!
    }
    return res;
}

// 2. LC 119: Return 0-indexed rowIndex R (i.e. (R + 1)-th row) in O(R) time, O(1) aux space
vector<int> getRow(int rowIndex) {
    vector<int> row(rowIndex + 1, 1);
    long long cur = 1;
    for (int i = 1; i <= rowIndex; ++i) {
        cur = cur * (rowIndex - i + 1) / i;
        row[i] = (int)cur;
    }
    return row;
}

// 3. LC 118: Generate first numRows of Pingala's / Pascal's Triangle in O(numRows^2) time
vector<vector<int>> generate(int numRows) {
    vector<vector<int>> tri;
    tri.reserve(numRows);
    for (int r = 0; r < numRows; ++r) {
        tri.push_back(getRow(r));
    }
    return tri;
}
