    Striver Array Lecture 1: Largest, Second Largest, Sorted Check & In-Place Deduplication

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 01_Striver_lec_1.pdf (3 pages) · Jump to original scans

    The opening notebook of the Arrays series establishes both the interview communication discipline used throughout all 13 notebooks and four foundational single-pass array primitives: finding the maximum element, finding the strictly second-largest distinct element without sorting, verifying non-descending sorted order, and compacting unique elements in-place (LeetCode 26).

    Interview Framing Protocol (Page 1 Opening Note)

    Even when you immediately see the $\mathcal{O}(N)$-time, $\mathcal{O}(1)$-space solution, do not blurt out the final code in 10 seconds — drive the interview deliberately:

    1. Clarify test cases & constraints first: Can elements be negative or zero? Are duplicates allowed? What sentinel should be returned if no valid answer exists (e.g., [7, 7, 7] when asked for a strictly second-largest value)?
    2. Walk the Brute $\to$ Better $\to$ Optimal ladder: Present the sorting or set-based baseline, pinpoint its redundant work, step through a two-pass intermediate if natural, and then distil the single-pass invariant.
    3. Use judgment on trivial warmups: As noted right below the rule on Page 1 ("Don't do this for very dumb problems like below"), don't waste five minutes pretending to sort an array just to find its maximum element — reserve the full progression for non-trivial problems.

    1. Largest Element in an Array

    Given an unsorted array such as arr = [3, 2, 1, 5, 2] of length $N$, return its maximum element (5).

    • Brute Force ($\mathcal{O}(N \log N)$ time, $\mathcal{O}(1)$ extra space): Sort the array in ascending order ($\to$ [1, 2, 2, 3, 5]) and return arr[N - 1] in $\mathcal{O}(1)$. Sorting establishes the relative order of all $\binom{N}{2}$ pairs when we only needed the single winner.
    • Optimal Tournament Scan ($\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space): Initialize maxi = arr[0] (or $-\infty$, i.e. INT_MIN in C++) and sweep $i = 0 \dots N - 1$, updating maxi = max(maxi, arr[i]). Since any deterministic algorithm must inspect every index at least once (adversary argument: an uninspected slot could hold $10^9$), $N - 1$ comparisons is information-theoretically optimal.

    2. Second Largest Distinct Element Without Sorting

    Given an array arr of length $N$, return the strictly second-largest distinct value, or -1 (or a sentinel / std::optional if negatives exist) when fewer than two distinct values appear. Look at the handwritten example on Page 1:

    $$\text{arr} = [1,\, 2,\, 4,\, \underbrace{7,\, 7}_{\text{Largest} = 7},\, \underbrace{5}_{\text{Second Largest} = 5}]$$

    Duplicates create the central trap of this problem: the second-last slot after sorting is not guaranteed to be the second largest, and an array like [7, 7, 7] has no second-largest element at all.

    2.1 Brute $\to$ Better $\to$ Optimal Progression

    1. Brute Force — Sort + Backward Tail Scan ($\mathcal{O}(N \log N)$ time, $\mathcal{O}(1)$ extra space): Sort ascending to get [1, 2, 4, 5, 7, 7] with largest = arr[N - 1] = 7. Because duplicates of largest may occupy arr[N - 2], arr[N - 3], etc. (like the tail ... 5, 7, 7 sketched on Page 1), initialize secondL = -1 and walk backwards $i = N - 2$ down to $0$: the first element satisfying arr[i] != largest is the answer (break immediately). Worst-case time on [7, 7, ..., 7] is $\mathcal{O}(N \log N) + \mathcal{O}(N) = \mathcal{O}(N \log N)$.
    2. Better — Two-Pass Linear Scan ($\mathcal{O}(2N)$ time, $\mathcal{O}(1)$ space):
      • Pass 1: Sweep arr once to compute largest = max(arr) ($\mathcal{O}(N)$).
      • Pass 2: Initialize secondL = -infinity and sweep arr again: whenever num != largest, update secondL = max(secondL, num) ($\mathcal{O}(N)$).
      Total runtime is $\mathcal{O}(N) + \mathcal{O}(N) = \mathcal{O}(2N) = \mathcal{O}(N)$, using two full memory traversals.
    3. Optimal — Single-Pass Champion & Runner-Up ($\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space): Maintain both the current champion L (largest) and current runner-up SL (sLargest) in one pass:
      • Case 1 (arr[i] > L): A new overall maximum has arrived! Before overwriting L, demote the reigning champion directly into the runner-up slot: SL = L; L = arr[i];.
      • Case 2 (arr[i] < L && arr[i] > SL): The element is strictly smaller than the champion (so it is not a duplicate of L), yet beats our current runner-up: SL = arr[i];.
      • Case 3 (arr[i] == L || arr[i] <= SL): Do nothing! In particular, duplicate copies of L fail both conditions and leave SL untouched.
    Step-by-step single-pass dry run on arr = [1, 2, 4, 7, 7, 5] (assuming non-negative domain, sentinel SL = -1).

If $a_i$ can be negative (e.g. [-10, -20] where the second largest is -20, or [INT_MIN, INT_MIN] where none exists), initialize long long SL = LLONG_MIN (one wider integer type than int) and return SL == LLONG_MIN ? -1 : SL!

    3. Check if an Array is Sorted in Non-Descending Order

    An array is sorted in non-descending order iff $\text{arr}[i] \le \text{arr}[j]$ for every index pair $0 \le i < j < N$ (equal adjacent values like [1, 2, 2, 3] are valid). Because $\le$ is transitive ($\text{arr}[0] \le \text{arr}[1]$ and $\text{arr}[1] \le \text{arr}[2] \implies \text{arr}[0] \le \text{arr}[2]$), we never need an $\mathcal{O}(N^2)$ all-pairs check — testing the $N - 1$ adjacent pairs $\text{arr}[i - 1] \le \text{arr}[i]$ for $i = 1 \dots N - 1$ is both necessary and sufficient in $\mathcal{O}(N)$ time and $\mathcal{O}(1)$ space.

    Two Subtle Bugs in the Handwritten Pseudocode Sketches (Pages 2–3)

    1. Sortedness check (Page 3 top): The sketch writes if prev < num: num = prev. Two bugs hide in those two lines: first, strict < rejects valid non-descending arrays with duplicates such as [1, 2, 2, 3] (must be prev <= num); second, advancing the running tracker requires prev = num, not num = prev!
    2. Deduplication loop (Page 3 bottom): Writing arr[j+1] = arr[i++]; inside a for (int i = 1; i < n; i++) loop increments i twice whenever a unique element is copied, skipping the immediately following element (e.g., failing on [1, 2, 3])! Let the for header alone advance i, and write arr[++j] = arr[i];.

    4. Remove Duplicates from Sorted Array In-Place (LeetCode 26)

    Given a non-decreasing array such as arr = [1, 1, 2, 2, 2, 3, 3], modify arr in-place so that the first $k$ slots contain the unique elements in sorted order ([1, 2, 3, _, _, _, _] — anything may remain beyond index $k - 1$), and return the count $k = 3$.

    • Brute Force — Ordered Set ($\mathcal{O}(N \log N + N)$ time, $\mathcal{O}(N)$ space): Insert every element into a balanced BST std::set<int> ($N$ insertions at $\mathcal{O}(\log N)$ each), then iterate over the set and overwrite arr[0..k-1] in $\mathcal{O}(k) \le \mathcal{O}(N)$ time. This wastes $\mathcal{O}(N)$ heap nodes and ignores the fact that arr was already sorted!
    • Optimal — Read/Write Two Pointers ($\mathcal{O}(N)$ time, $\mathcal{O}(1)$ extra space): Because equal elements in a sorted array form contiguous runs, an element arr[i] is brand-new iff it differs from the last committed unique value arr[j]:
      • Fix write pointer j = 0 (since arr[0] is unconditionally the first unique element).
      • Sweep read pointer i from $1$ to $N - 1$: whenever arr[i] != arr[j], advance j++ and copy arr[j] = arr[i].
      • When the loop finishes, indices $0 \dots j$ hold all unique values, so the unique count is j + 1!

    5. Clean C++ Reference Implementations

    Complete bug-free C++ implementations for all four Lecture 1 problems:

    #include <bits/stdc++.h>
using namespace std;

// 1. Largest element in O(N) time, O(1) space
int largestElement(const vector<int>& arr) {
    int maxi = arr[0];
    for (int x : arr) maxi = max(maxi, x);
    return maxi;
}

// 2. Strictly Second Largest distinct element in O(N) single pass, O(1) space
// Works for arbitrary signed ints (returns -1 if no second distinct element exists).
long long secondLargest(const vector<int>& arr) {
    if (arr.size() < 2) return -1;
    long long largest = arr[0];
    long long sLargest = LLONG_MIN;

    for (size_t i = 1; i < arr.size(); ++i) {
        if (arr[i] > largest) {
            sLargest = largest;
            largest = arr[i];
        } else if (arr[i] < largest && arr[i] > sLargest) {
            sLargest = arr[i];
        }
    }
    return (sLargest == LLONG_MIN) ? -1 : sLargest;
}

// 3. Check if array is sorted in non-descending order: O(N) time, O(1) space
bool isSortedNonDescending(const vector<int>& arr) {
    for (size_t i = 1; i < arr.size(); ++i) {
        if (arr[i] < arr[i - 1]) return false;
    }
    return true;
}

// 4. LeetCode 26: Remove Duplicates from Sorted Array in-place: O(N) time, O(1) space
int removeDuplicates(vector<int>& nums) {
    if (nums.empty()) return 0;
    int j = 0; // index of last committed unique element
    for (int i = 1; i < (int)nums.size(); ++i) {
        if (nums[i] != nums[j]) {
            nums[++j] = nums[i];
        }
    }
    return j + 1;
}

    6. Complexity Summary & Key Edge Cases

    Complexity progression across all four problems in 01_Striver_lec_1.pdf.
    Problem Brute Force Better Optimal Time & Extra Space
    Largest Element Sort + last: $\mathcal{O}(N \log N)$, $\mathcal{O}(1)$ — Running max: $\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space
    Second Largest Element Sort + tail scan: $\mathcal{O}(N \log N)$, $\mathcal{O}(1)$ 2-pass max: $\mathcal{O}(2N)$, $\mathcal{O}(1)$ 1-pass (L, SL): $\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space
    Check Sorted ($a_i \le a_{i+1}$) All pairs $(i, j)$: $\mathcal{O}(N^2)$, $\mathcal{O}(1)$ — Adjacent check: $\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space
    Remove Duplicates (LC 26) Ordered set: $\mathcal{O}(N \log N)$, $\mathcal{O}(N)$ — Read/write pointers: $\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space
    • All-equal elements ([7, 7, 7]): Second Largest returns -1; Check Sorted returns true; Remove Duplicates returns $k = 1$ with arr[0] = 7.
    • Single-element or empty array ([42] / []): Second Largest returns -1; Check Sorted is vacuously true; Remove Duplicates returns $1$ on [42] and $0$ on [].
    • Strictly descending array ([9, 5, 2, -4]): Tests Case 2 (arr[i] < L && arr[i] > SL) immediately at index $1$ — if you only updated SL inside the arr[i] > L branch, descending inputs would falsely return -1!
