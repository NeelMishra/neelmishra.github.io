    BFS Implementation Tips vs. MST Visited Timing (LeetCode Study Guide, LC 733 & LC 399)

    October 2026 · 10 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 01_Leetcode_blog.pdf · View original handwritten page

    1. The Four Foundational BFS Implementation Rules

    This study sheet distills core implementation habits from the LeetCode Graph Algorithms Study Guide right at the front of the weighted-graph / MST notebook:

    Four BFS Rules Recorded in 01_Leetcode_blog.pdf

    1. FIFO Queue Engine: Breadth-First Search uses a First-In, First-Out queue so vertices are processed strictly in non-decreasing edge-count layers from the source.
    2. Check & Mark Explored Before Enqueueing: Always test whether a neighbor has been explored—and mark it explored—before pushing it into the queue, never lazily on pop!
    3. In-Place Matrix Tracking: On 2D grid problems (where mutating the input is allowed), overwriting grid[r][c] directly acts as an $\mathcal{O}(1)$-extra-space visited table.
    4. Shortest-Path Reconstruction via dist[] & parent[]: Recording dist[v] = dist[u] + 1 and parent[v] = u when $v$ is first discovered lets us reconstruct the exact shortest path by looping backward from endNode to source.

    2. Why This Note Sits Before Prim's MST: Visited-on-Enqueue vs. Visited-on-Pop

    Rule #2 ("check whether a vertex has been explored before enqueueing") is the single sharpest point of contrast when moving from unweighted BFS to weighted Min-Heap algorithms like Prim's MST and Dijkstra:

    Master Visited-Timing Rule Across Graph Traversals.
    Algorithm Frontier Structure When to Mark Optimal / Visited Why?
    Unweighted BFS FIFO queue On Enqueue (Push) All edges cost $1$; first discovery is already optimal—prevents duplicate pushes.
    Prim's MST Min-Heap priority_queue On Dequeue (Pop) Cheaper crossing edges to $v$ can enter the heap before $v$ is popped.
    Dijkstra's Shortest Path Min-Heap priority_queue Update dist[v] on push; finalize / skip stale d > dist[u] on Pop Relaxation filters strictly better paths while pop locks minimum non-negative distance.

    3. Shortest-Path Reconstruction Template (Rule #4: dist + parent)

    When a problem asks not merely for the shortest distance dist[target] in an unweighted graph, but for the actual vertex sequence $s = v_0 \to v_1 \to \dots \to v_k = t$, Rule #4 records parent[nbr] = u at the exact moment nbr is marked visited and enqueued:

    // Unweighted BFS Shortest Distance + Backward Path Reconstruction — C++
pair<int, vector<int>> shortestPathBFS(int n, const vector<vector<int>>& adj, int src, int dst) {
    vector<int> dist(n, -1), parent(n, -1);
    queue<int> q;

    dist[src] = 0; // dist[u] != -1 doubles as our visited-before-enqueue flag!
    q.push(src);

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        if (u == dst) break;

        for (int v : adj[u]) {
            if (dist[v] == -1) {       // Checked BEFORE enqueueing (Rule 2)
                dist[v] = dist[u] + 1;
                parent[v] = u;         // Record predecessor (Rule 4)
                q.push(v);
            }
        }
    }

    if (dist[dst] == -1) return {-1, {}}; // Unreachable

    vector<int> path;
    for (int cur = dst; cur != -1; cur = parent[cur]) {
        path.push_back(cur);
    }
    reverse(path.begin(), path.end());
    return {dist[dst], path};
}

    4. BFS Question Bank #1: Flood Fill (LeetCode 733)

    In LeetCode 733 (Flood Fill), starting from pixel (sr, sc), we recolor every 4-directionally connected pixel sharing the original starting color oldColor into color. Applying Rule #2 + Rule #3, recoloring image[nr][nc] = color immediately before enqueueing marks the cell visited in $\mathcal{O}(1)$ auxiliary grid memory!

    Classic Infinite-Loop Edge Case: oldColor == color

    If image[sr][sc] already equals the target color, changing pixels to color no longer distinguishes visited pixels from unvisited ones—neighboring pixels bounce back and forth forever! Always guard if (oldColor == color) return image; on line 1.

    // LeetCode 733: Flood Fill — In-Place Matrix BFS (Rules 2 & 3)
class Solution {
public:
    vector<vector<int>> floodFill(vector<vector<int>>& image, int sr, int sc, int color) {
        int oldColor = image[sr][sc];
        if (oldColor == color) return image; // Essential infinite-loop guard!

        int m = image.size(), n = image[0].size();
        queue<pair<int, int>> q;
        image[sr][sc] = color; // Mark visited in-place BEFORE enqueueing
        q.push({sr, sc});

        constexpr int dr[4] = {-1, 1, 0, 0};
        constexpr int dc[4] = {0, 0, -1, 1};

        while (!q.empty()) {
            auto [r, c] = q.front();
            q.pop();

            for (int d = 0; d < 4; ++d) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr >= 0 && nr < m && nc >= 0 && nc < n && image[nr][nc] == oldColor) {
                    image[nr][nc] = color; // In-place mark on enqueue!
                    q.push({nr, nc});
                }
            }
        }
        return image;
    }
};

    5. BFS Question Bank #2: Evaluate Division (LeetCode 399)

    In LeetCode 399 (Evaluate Division), we are given ratio equations $A_i / B_i = val_i$ (e.g., $a / b = 2.0,\; b / c = 3.0$) and asked to evaluate queries $C_j / D_j$ (e.g., $a / c = 6.0,\; b / a = 0.5$, or $-1.0$ if undetermined).

    • Graph Modeling Breakthrough: Division chains telescope multiplicatively: $$\frac{a}{c} = \frac{a}{b} \times \frac{b}{c}$$ Model each variable as a vertex, each equation $a / b = k$ as two directed weighted edges $a \xrightarrow{k} b$ and $b \xrightarrow{1/k} a$, and run BFS carrying (currVar, runningProduct)!
    • Progression: Per-query BFS runs in $\mathcal{O}(Q \cdot (V + E))$ (ideal when $V \le 40$ as in LC 399); if $Q$ is huge ($10^5$) over a static ratio graph, Weighted Union-Find (DSU with potential ratios to root) answers queries in $\mathcal{O}(\alpha(V))$!
    // LeetCode 399: Evaluate Division — Ratio-Graph BFS with Visited-on-Enqueue (C++)
class Solution {
    double bfsQuery(
        const string& src,
        const string& dst,
        const unordered_map<string, vector<pair<string, double>>>& adj
    ) {
        if (!adj.count(src) || !adj.count(dst)) return -1.0;
        if (src == dst) return 1.0;

        unordered_set<string> visited = {src}; // Marked BEFORE enqueueing!
        queue<pair<string, double>> q;
        q.push({src, 1.0});

        while (!q.empty()) {
            auto [curr, prod] = q.front();
            q.pop();
            if (curr == dst) return prod;

            for (const auto& [nbr, weight] : adj.at(curr)) {
                if (visited.insert(nbr).second) {
                    q.push({nbr, prod * weight});
                }
            }
        }
        return -1.0;
    }

public:
    vector<double> calcEquation(
        vector<vector<string>>& equations,
        vector<double>& values,
        vector<vector<string>>& queries
    ) {
        unordered_map<string, vector<pair<string, double>>> adj;
        for (size_t i = 0; i < equations.size(); ++i) {
            const string& u = equations[i][0];
            const string& v = equations[i][1];
            double val = values[i];
            adj[u].push_back({v, val});
            adj[v].push_back({u, 1.0 / val});
        }

        vector<double> ans;
        ans.reserve(queries.size());
        for (const auto& q : queries) {
            ans.push_back(bfsQuery(q[0], q[1], adj));
        }
        return ans;
    }
};

    6. Complexity Summary & Key Edge Cases

    • Shortest-Path BFS: $\mathcal{O}(V + E)$ time, $\mathcal{O}(V)$ space for dist, parent, and queue.
    • Flood Fill (LC 733): $\mathcal{O}(M \cdot N)$ time, $\mathcal{O}(M \cdot N)$ worst-case queue size (zero extra visited matrix thanks to in-place coloring).
    • Evaluate Division (LC 399): $\mathcal{O}(E)$ graph build + $\mathcal{O}(Q \cdot (V + E))$ across $Q$ queries, $\mathcal{O}(V + E)$ space.
    • Unknown Variable Self-Query in LC 399 (["x", "x"]): Must return -1.0, NOT 1.0! Always check !adj.count(src) || !adj.count(dst) before checking src == dst.
    • Disconnected Components: In path reconstruction, verify dist[dst] != -1 before walking parent[], otherwise a single-element [dst] path would be falsely returned for an unreachable target.
