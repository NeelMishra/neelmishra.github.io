    Part 1: MST Theory, Visited-on-Pop & Prim's Min-Heap Algorithm

    October 2026 · 11 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (01_Leetcode_blog.pdf, 02_MST_Theory.pdf & 03_Striver_MST_Prim_s.pdf) · View original handwritten pages

    1. Spanning Tree & Minimum Spanning Tree (MST) Fundamentals

    Suppose we are given a connected, undirected, weighted graph with $n$ vertices and $m$ edges ($m \ge n - 1$, with no fixed upper ratio up to $\binom{n}{2}$):

    Spanning Tree & Minimum Spanning Tree

    • Spanning Tree: A subgraph that is a tree containing all $n$ vertices and exactly $n - 1$ edges, such that every vertex is reachable from every other vertex (removing any 1 edge disconnects it; adding any 1 edge creates a cycle).
    • Minimum Spanning Tree (MST): Among all spanning trees of $G$, one whose sum of $n - 1$ edge weights is minimum. A graph can possess multiple distinct MSTs whenever equal edge weights allow tied swaps, though all MSTs share the exact same minimum total weight.

    2. Crucial Contrast: BFS Visited-on-Enqueue vs. Prim's Visited-on-Pop

    The first page of this notebook folder (01_Leetcode_blog.pdf) summarizes standard BFS implementation rules (using a FIFO queue, checking/marking a vertex explored before enqueueing, modifying grid matrices in-place, tracking parent/dist arrays to reconstruct shortest paths backward, and practicing on Evaluate Division (LC 399) and Flood Fill (LC 733)). Placed right next to Prim's notes, it highlights the single most important bug-prevention contrast in weighted graph algorithms:

    Three-Starred Rule in Prim's (***): NEVER Mark visited on Push!

    • Unweighted BFS (FIFO Queue): Every edge has equal unit cost, so the first time you see a neighbor is guaranteed to be its shortest path—you must mark visited on enqueue.
    • Prim's MST (Min-Heap Priority Queue): Pushing (weight, adjNode, parent) into the min-heap only means one candidate edge to adjNode was seen—a strictly cheaper edge to adjNode may be pushed later before adjNode is popped! Therefore, in Prim's you ONLY mark vis[node] = 1 when node is POPPED from the min-heap (and if an already-visited stale entry pops later, simply continue).

    3. Prim's Min-Heap Algorithm & Complete Dry Run

    To compute both the minimum weight edgeSum and the actual MST edge list:

    1. Create a min-heap storing tuples (weight, node, parent) (or pairs (weight, node) if only edgeSum is requested), vis[V] = {0}, edgeSum = 0, and MST = [].
    2. Start from any arbitrary node (e.g., 0) by pushing (0, 0, -1) into the min-heap (parent = -1 flags the virtual root so no dummy edge is added to MST).
    3. While the min-heap is non-empty, pop (wt, node, parent):
      • If vis[node] == 1, skip this stale candidate (continue).
      • Otherwise lock node into the MST: set vis[node] = 1, add wt to edgeSum, and if parent != -1, record (parent, node) in MST.
      • Scan every neighbor (adjNode, edW) of node: if !vis[adjNode], push (edW, adjNode, node) into the min-heap (without marking vis[adjNode]!).

    4. Implementation & Complexity Derivation

    Time & Space Complexity (Page 2 of Notes)

    • Time Complexity: $\mathcal{O}(E \log E)$ (equivalently $\mathcal{O}(E \log V)$ since $\log E \le \log V^2 = 2 \log V$ on simple graphs). Across the entire run, each undirected edge pushes at most $2$ entries into the min-heap ($\le 2E$ heap pushes at $\mathcal{O}(\log E)$ each) and pops at most $2E$ times ($\mathcal{O}(E \log E)$): $\mathcal{O}(E \log E + E \log E) = \mathcal{O}(E \log E)$.
    • Space Complexity: $\mathcal{O}(E + V)$ — up to $\mathcal{O}(E)$ tuples in the priority queue plus $\mathcal{O}(V)$ for vis[] and MST.
    // Striver's Prim's MST Algorithm — C++
// Version A: Returns minimum MST weight sum (only {wt, node} needed in min-heap)
class Solution {
public:
    int spanningTree(int V, vector<vector<int>> adj[]) {
        using P = pair<int, int>; // {weight, node}
        priority_queue<P, vector<P>, greater<P>> pq;
        vector<int> vis(V, 0);

        pq.push({0, 0});
        int sum = 0;

        while (!pq.empty()) {
            auto [wt, node] = pq.top();
            pq.pop();

            if (vis[node]) continue; // Skip stale heavier edges!

            // Lock `node` into the MST ONLY upon popping from min-heap
            vis[node] = 1;
            sum += wt;

            for (const auto& edge : adj[node]) {
                int adjNode = edge[0];
                int edW     = edge[1];
                if (!vis[adjNode]) {
                    pq.push({edW, adjNode});
                }
            }
        }
        return sum;
    }
};
    # Version B: Prim's MST Returning Both Total Weight AND MST Edge List — Python
import heapq

def prim_mst(V: int, adj: List[List[Tuple[int, int]]]) -> Tuple[int, List[Tuple[int, int]]]:
    vis = [False] * V
    # Min-heap stores (weight, node, parent)
    pq = [(0, 0, -1)]
    total_weight = 0
    mst_edges = []

    while pq:
        wt, node, parent = heapq.heappop(pq)
        if vis[node]:
            continue

        vis[node] = True
        total_weight += wt
        if parent != -1:
            mst_edges.append((parent, node))

        for adj_node, ed_w in adj[node]:
            if not vis[adj_node]:
                heapq.heappush(pq, (ed_w, adj_node, node))

    return total_weight, mst_edges
