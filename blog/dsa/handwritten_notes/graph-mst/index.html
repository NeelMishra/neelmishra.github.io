    Minimum Spanning Trees (MST): Cut Property, Prim's PQ & Kruskal's DSU

    October 2026 · 6 min read · 2-Part Series (7 Handwritten Pages)

    Expanded from handwritten competitive coding study notes (01_Leetcode_blog.pdf, 02_MST_Theory.pdf, 03_Striver_MST_Prim_s.pdf & 04_Striver_Krushkal_MST.pdf)

    Given a connected, undirected, weighted graph $G = (V, E)$ with $n = |V|$ vertices and $m = |E|$ edges, a spanning tree is a connected acyclic subgraph touching all $n$ vertices using exactly $n - 1$ edges. Among all possible spanning trees of $G$, a Minimum Spanning Tree (MST) minimizes the total sum of edge weights—powering minimum-cost network wiring, clustering, and bottleneck path problems.

    Why Greedy Works: The MST Cut Property

    The Cut Property (Exchange Proof Intuition)

    Partition the vertex set $V$ into any two non-empty disjoint subsets $S$ and $V \setminus S$. If $e = (u, v)$ is a minimum-weight edge crossing the cut ($u \in S,\; v \in V \setminus S$), then $e$ belongs to some Minimum Spanning Tree of $G$.

    Why? Suppose a spanning tree $T$ omits $e$. Adding $e$ to $T$ creates a unique cycle that must cross back from $V \setminus S$ to $S$ via some other crossing edge $e'$ with $w(e) \le w(e')$. Swapping $T' = T \cup \{e\} \setminus \{e'\}$ reconnects the tree with total weight $w(T') = w(T) + w(e) - w(e') \le w(T)$!

    Both classic MST algorithms are direct applications of this single theorem:

    • Prim's Algorithm keeps a single growing tree $S$ around the starting vertex and uses a min-heap to pick the lightest edge crossing $(S, V \setminus S)$.
    • Kruskal's Algorithm picks the globally lightest remaining edge $e = (u, v)$ that connects two distinct DSU components $C_u$ and $C_v$—making $e$ the lightest edge crossing cut $(C_u, V \setminus C_u)$!

    Master Comparison: Prim's PQ vs. Kruskal's DSU

    Choosing between Prim's and Kruskal's in competitive programming.
    Dimension Prim's Algorithm (Part 1) Kruskal's Algorithm (Part 2)
    Growth Strategy Vertex-centric: grows one connected tree outward from any source node. Edge-centric: merges $V$ isolated components into a forest until $1$ tree remains.
    Core Data Structure Min-Heap Priority Queue (wt, node, parent) + vis[V] Sorted edge list (wt, u, v) + Disjoint Set Union (findUPar, unionBySize)
    Cycle Prevention Skip popped vertex if vis[node] == 1 (mark visited on pop, never on push!) Skip edge if ds.findUPar(u) == ds.findUPar(v)
    Time Complexity $\mathcal{O}(E \log E)$ (or $\mathcal{O}(V^2)$ without heap on dense $E \approx V^2$ graphs like LC 1584!) $\mathcal{O}(E \log E + E \cdot \alpha(V)) = \mathcal{O}(E \log E)$
    Disconnected Graph? Covers only the starting component unless wrapped in a 0..V-1 loop. Naturally computes the Minimum Spanning Forest across all components in one pass!
    Best Input Format Adjacency list adj[u] = {{v, wt}, ...} Flat edge list edges = {{u, v, wt}, ...} (and problems already using DSU!)
