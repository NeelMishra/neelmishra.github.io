    MIT 6.006 Five-Step DP Framework: Subproblem DAGs, Text Justification, Blackjack, Matrix Chain & Piano Fingering

    October 2026 · 16 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 07_DP_MIT.pdf

    Erik Demaine's MIT 6.006 lectures strip the mystery out of Dynamic Programming: DP is simply "careful brute force" = guessing + recursion + memoization over a Directed Acyclic Graph (DAG) of subproblems. Across 9 handwritten pages, 07_DP_MIT.pdf develops the universal 5-step DP design recipe and applies it to six escalating subproblem geometries—from linear suffixes to 2D alignments, interval parenthesization hyperpaths, and state-augmented layered graphs.

    1. Lecture 1: Exponential Lower Bound, DP Time Law & the DAG Requirement

    Starting from $F_1 = F_2 = 1$ and $F_n = F_{n-1} + F_{n-2}$, the naive recursive runtime satisfies an immediate exponential lower bound:

    $$T(n) = T(n - 1) + T(n - 2) + O(1) \;\ge\; 2\,T(n - 2) \;=\; \Omega\bigl(2^{n/2}\bigr)$$

    Storing solved values in a memoization table (e.g., vector<long long> memo(n + 1, -1) or unordered_map<int, long long>) ensures every distinct subproblem $F_k$ recurses at most once; all subsequent calls hit if (memo[n] != -1) return memo[n]; in $\Theta(1)$ time. This yields the master runtime equation of Dynamic Programming:

    The Universal DP Runtime Formula

    $$\text{Total Time} \;=\; \bigl(\#\text{ of Distinct Subproblems}\bigr) \;\times\; \bigl(\text{Time per Subproblem, ignoring recursive calls}\bigr)$$

    In bottom-up DP (for (int k = 1; k <= n; ++k)), the loop order corresponds to a topological sort of the subproblem dependency graph.

    Why Cyclic Dependencies Break DP (Shortest-Path Counterexample, p.2)

    Suppose we attempt to find shortest paths $\delta(s, v)$ on a graph containing a directed cycle $a \to v \to b \to a$ via the naive recurrence $\delta(s, v) = \min_{(u,v)\in E}\bigl(\delta(s, u) + w(u, v)\bigr)$ with $\delta(s, s) = 0$. Expanding along the cycle gives:

    $$\begin{aligned} \delta(s, v) &= \delta(s, a) + w(a, v) \\ &= \delta(s, b) + w(b, a) + w(a, v) \\ &= \underbrace{\delta(s, v)}_{\text{not yet computed!}} + w(v, b) + w(b, a) + w(a, v) \end{aligned}$$

    Any cycle in subproblem dependencies causes infinite recursion top-down and has no valid bottom-up order! To fix cyclic graphs (Bellman-Ford), augment the state with path length $k$: $\delta_k(s, v) =$ shortest path using $\le k$ edges, turning edges into strictly acyclic layer transitions $(k-1, u) \to (k, v)$.

    2. The 5-Step MIT Checklist & Lecture 2 Applications

    MIT 6.006's 5-Step DP Checklist

    1. Define subproblems and count $\#\text{subproblems}$.
    2. Guess (part of the solution—which local choice comes first or last?) and count $\#\text{choices}$.
    3. Relate subproblem solutions via a recurrence + base cases, and compute $\text{time/subproblem}$.
    4. Recurse & memoize OR build a DP table bottom-up—always check that the subproblem graph is acyclic (topological order)!
    5. Solve the original problem (either a single DP state or an aggregation over entry states), verify total runtime, and follow parent pointers parent[state] = argmin/argmax(...) to reconstruct the actual solution.

    2.1 Text Justification (LaTeX Knuth–Plass Line Breaking, p.2–4)

    Given a list of $n$ words and target page width $W$, greedy line-wrapping (MS Word style) often leaves ugly trailing gaps on later lines. LaTeX instead minimizes the sum of cubic whitespace badness over all lines:

    $$\text{badness}(i, j) = \begin{cases} \bigl(W - \text{totalWidth}(i, j)\bigr)^3 & \text{if words } [i : j] \text{ fit on one line} \\ +\infty & \text{if } \text{totalWidth}(i, j) > W \end{cases}$$
    • 1. Subproblems: Suffixes words[i:] for $i \in \{0, 1, \dots, n\}$ $\implies \Theta(n)$ subproblems.
    • 2. Guess: Where to start the 2nd line, i.e., $j \in \{i+1, \dots, n\}$ $\implies n - i = O(n)$ choices.
    • 3. Recurrence: $\text{DP}(n) = 0$ (no words left), and $\text{DP}(i) = \min_{j \in [i+1,\, n]}\bigl(\text{badness}(i, j) + \text{DP}(j)\bigr)$ in $O(n)$ time/subproblem.
    • 4. Topological Order: $\text{DP}(i)$ depends on $\text{DP}(j)$ with $j > i$, so iterate backward $i = n, n - 1, \dots, 0$.
    • 5. Original Problem & Parent Pointers: Answer is $\text{DP}(0)$ in $\Theta(n) \times O(n) = O(n^2)$ total time. Setting parent[i] = best_j reconstructs every line break via $0 \to \text{parent}[0] \to \text{parent}[\text{parent}[0]] \dots$!
    #include <bits/stdc++.h>
using namespace std;

pair<long long, vector<int>> justifyText(const vector<string>& words, int pageWidth) {
    int n = (int)words.size();
    const long long INF = (1LL << 60);
    vector<long long> dp(n + 1, INF);
    vector<int> parent(n + 1, n);
    dp[n] = 0;

    for (int i = n - 1; i >= 0; --i) { // End-to-beginning topological order
        int width = 0;
        for (int j = i + 1; j <= n; ++j) {
            width += (int)words[j - 1].size() + (j > i + 1 ? 1 : 0);
            if (width > pageWidth) break; // badness = +infinity
            long long slack = pageWidth - width;
            long long cost = slack * slack * slack + dp[j];
            if (cost < dp[i]) {
                dp[i] = cost;
                parent[i] = j; // Parent pointer stores argmin j
            }
        }
    }

    vector<int> breaks;
    for (int cur = 0; cur < n; cur = parent[cur]) breaks.push_back(cur);
    return {dp[0], breaks};
}

    2.2 Perfect-Information Blackjack (p.4–5)

    Given a known $n$-card deck $c_0, c_1, \dots, c_{n-1}$, 1 player vs. a deterministic dealer, and $\$1$ bet per hand:

    • 1. Subproblems: Remaining deck suffix $c_i:$ ($\le n$ cards left $\implies \Theta(n)$ subproblems).
    • 2. Guess: How many times the player hits on the current hand ($\le n$ remaining cards $\implies O(n)$ choices).
    • 3. Recurrence: Each valid hit count $h$ forces the dealer's play deterministically, consuming cards up to $j \in [i + 4, n]$ with payoff $\text{outcome} \in \{-1, 0, +1\}$: $$\text{BJ}(i) = \max_{\substack{\text{valid hit play} \\ \text{ending at deck index } j}} \Bigl(\text{outcome}(i \to j) + \text{BJ}(j)\Bigr)$$
    • 4–5. Topology & Runtime: Edges jump strictly right ($i \to j \ge i + 4$), solved right-to-left in $O(n^2)$ time (if hit transitions are amortized; $O(n^3)$ if each hand simulation scans $O(n)$ cards).

    3. Lecture 3: Sequence Subproblem Catalog & Three Flagship Patterns

    Page 5 summarizes the standard subproblem templates whenever an input is a sequence $x$ of length $n$:

    Sequence Subproblem Shape Notation Count When to Use
    Suffixes $x[i:] \;\;\forall i$ $\Theta(n)$ Decisions scan left-to-right (Text Justification, Blackjack)
    Prefixes $x[:i] \;\;\forall i$ $\Theta(n)$ Decisions peel from the right end (1D DP, LCS prefixes)
    Substrings / Intervals $x[i:j] \;\;\forall i \le j$ $\frac{n(n+1)}{2} = \Theta(n^2)$ Splits produce arbitrary interior slices (Matrix Chain, Palindromes)

    3.1 Matrix Chain Parenthesization (p.5–7)

    Matrix multiplication is associative, $(AB)C = A(BC)$, yet parenthesization changes work dramatically! Look at the outer-product sketch on page 5: multiplying $A\,(n \times 1) \cdot B\,(1 \times n) \cdot C\,(n \times 1)$ as $((AB)C)$ builds an $n \times n$ intermediate matrix in $\Theta(n^2)$ time, whereas $(A(BC))$ collapses $(1 \times n)(n \times 1)$ into a $1 \times 1$ scalar first in $\Theta(n)$ time!

    • 1. Subproblems: Optimal cost $m[i][j]$ to evaluate substring $A_i \cdots A_j$ ($1 \le i \le j \le n$, where $A_i$ is $p_{i-1} \times p_i$) $\implies \Theta(n^2)$ subproblems.
    • 2. Guess: The outermost / last multiplication split $k \in \{i, \dots, j - 1\}$ splitting $(A_i \dots A_k) \cdot (A_{k+1} \dots A_j)$ $\implies O(j - i + 1) = O(n)$ choices.
    • 3. Recurrence: $m[i][i] = 0$, and for $i < j$: $$m[i][j] = \min_{i \le k < j}\Bigl(m[i][k] + m[k+1][j] + p_{i-1}\,p_k\,p_j\Bigr)$$
    • 4. Topological Order & Hyperpath Insight: Iterate by increasing chain length $L = 2, 3, \dots, n$. As emphasized on page 6: "DP $\ne$ shortest path in the DAG" here, because one transition sums two subproblems $m[i][k] + m[k+1][j]$ simultaneously!
    • 5. Complexity & Handwritten Dry Run: $\Theta(n^2) \times O(n) = \Theta(n^3)$ time, $\Theta(n^2)$ space. On page 7's example $p = [10, 30, 5, 60]$ ($A_1: 10 \times 30,\; A_2: 30 \times 5,\; A_3: 5 \times 60$):
      • $((A_1 A_2) A_3)$: $10 \cdot 30 \cdot 5 + 10 \cdot 5 \cdot 60 = 1500 + 3000 = \mathbf{4500}$ multiplications (optimal!)
      • $(A_1 (A_2 A_3))$: $30 \cdot 5 \cdot 60 + 10 \cdot 30 \cdot 60 = 9000 + 18000 = 27000$ multiplications ($6\times$ slower!).
    // Bottom-up Matrix Chain DP from 07_DP_MIT.pdf p.6-7.
// Matrix A_i (1-indexed) has dimensions p[i - 1] x p[i].
pair<vector<vector<long long>>, vector<vector<int>>> matrixChainOrder(const vector<int>& p) {
    int n = (int)p.size() - 1;
    const long long INF = (1LL << 60);
    vector<vector<long long>> m(n + 1, vector<long long>(n + 1, 0));
    vector<vector<int>> s(n + 1, vector<int>(n + 1, 0));

    for (int len = 2; len <= n; ++len) {        // Increasing substring size
        for (int i = 1; i <= n - len + 1; ++i) {
            int j = i + len - 1;
            m[i][j] = INF;
            for (int k = i; k < j; ++k) {       // Guess last multiplication split k
                long long q = m[i][k] + m[k + 1][j] + 1LL * p[i - 1] * p[k] * p[j];
                if (q < m[i][j]) {
                    m[i][j] = q;
                    s[i][j] = k;
                }
            }
        }
    }
    return {m, s};
}

string formatOptimalParens(const vector<vector<int>>& s, int i, int j) {
    if (i == j) return "A" + to_string(i);
    int k = s[i][j];
    return "(" + formatOptimalParens(s, i, k) + formatOptimalParens(s, k + 1, j) + ")";
}

    3.2 Character Edits / Edit Distance as a 2D Suffix DAG (p.6–7)

    To convert string $x$ into string $y$ at minimum cost using insert, delete, and replace $c \to c'$, we have two input sequences, so we take the Cartesian product of their suffixes $x[i:]$ and $y[j:]$ ($\Theta(|x| \cdot |y|)$ subproblems), with $3$ constant-time guesses per cell:

    $$\text{DP}(i, j) = \min\begin{cases} \text{cost}(\text{replace } x[i] \to y[j]) + \text{DP}(i + 1, j + 1) \\ \text{cost}(\text{insert } y[j]) + \text{DP}(i, j + 1) \\ \text{cost}(\text{delete } x[i]) + \text{DP}(i + 1, j) \end{cases}$$

    Notice the unification noted on page 6: setting $\text{insert} = \text{delete} = 1$, $\text{replace}(c \to c) = 0$, and $\text{replace}(c \to c' \ne c) = +\infty$ solves Longest Common Subsequence via $|x| + |y| - 2 \cdot \text{LCS} = \text{DP}(0, 0)$ in $\Theta(|x| \cdot |y|)$ time!

    3.3 Piano / Guitar Fingering: State Augmentation (p.7–8)

    Given $n$ sequential notes $0 \dots n-1$ and $F = 5$ fingers with transition difficulty $d(i, f, i+1, g)$, suffix state $\text{DP}(i)$ alone fails because the transition cost to note $i + 1$ depends on which finger $f$ played note $i$!

    • 1. Augmented Subproblems: $\text{DP}(i, f) =$ min difficulty to play suffix $i \dots n-1$ given finger $f \in \{1 \dots F\}$ plays note $i$ ($\#\text{subproblems} = n \cdot F$).
    • 2. Guess: Finger $g \in \{1 \dots F\}$ for note $i + 1$ ($F$ choices).
    • 3. Recurrence: $\text{DP}(n - 1, f) = 0$, and $\text{DP}(i, f) = \min_{g \in 1..F}\bigl(\text{DP}(i + 1, g) + d(i, f, i + 1, g)\bigr)$.
    • 4. Original Problem: Since any finger may start note $0$, minimize across all entry states: $\min_{f \in 1..F} \text{DP}(0, f)$.
    • 5. Layered Bipartite DAG & Complexity: Each column $i$ connects completely to column $i + 1$ like a dense neural-network layer, giving $(n \cdot F) \times O(F) = \Theta(n F^2)$ time—effectively linear in $n$ for $F = 5$!
    long long optimalPianoFingering(
    int n, int F,
    const function<long long(int, int, int, int)>& diff // d(i, f, i+1, g)
) {
    vector<long long> nextCol(F, 0), curCol(F, 0); // DP(n-1, f) = 0
    for (int i = n - 2; i >= 0; --i) {
        for (int f = 0; f < F; ++f) {
            long long best = (1LL << 60);
            for (int g = 0; g < F; ++g) {
                best = min(best, diff(i, f, i + 1, g) + nextCol[g]);
            }
            curCol[f] = best;
        }
        swap(nextCol, curCol);
    }
    return *min_element(nextCol.begin(), nextCol.end()); // O(n * F^2) time, O(F) space
}
