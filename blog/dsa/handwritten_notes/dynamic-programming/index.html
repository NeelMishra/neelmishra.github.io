    Dynamic Programming: Subproblem Geometries, Transitions & Optimization Roadmap

    October 2026 · 7 min read · Handwritten Notes

    Series overview & reference guide synthesized from 14 handwritten DP notebooks (MIT 6.006 lectures & Striver DP problem notes, 48 pages)

    Dynamic Programming is controlled brute force over a Directed Acyclic Graph (DAG) of overlapping subproblems. Almost every competitive programming DP question reduces to two design choices: choosing the minimal subproblem state (prefix, suffix, 2D coordinate, dual-string alignment, or interval $[i..j]$) that makes future choices independent of how we arrived there, and ordering those states topologically so each subproblem is solved once.

    This four-part series expands 48 pages of handwritten notes—spanning Erik Demaine's MIT 6.006 5-step DP framework and classic competitive programming patterns across 1D arrays, 2D grids, histograms, strings, increasing subsequences, and boolean expression parenthesization—preserving every original recurrence derivation, dry run, and edge-case trap.

    Two Complementary Mental Models

    The handwritten notes pair two ways of attacking an unfamiliar DP problem: MIT's structural 5-Step Checklist (ideal for proving polynomial complexity and designing states) and the competitive coder's Index-Action-Aggregate Recipe + 4-Stage Optimization Pipeline (ideal for writing bug-free code quickly).

    STEP 01 Subproblems Pick prefixes $x[:i]$, suffixes $x[i:]$, substrings $x[i:j]$, or augmented coordinates, and count $\#\text{states}$.
    STEP 02 Guess Identify the local decision (pick/skip, next line break $j$, split point $k$) and count $\#\text{choices}$.
    STEP 03 Recurrence Express $\text{DP}(\text{state})$ by aggregating guesses ($\sum$, $\min$, $\max$) plus base cases.
    STEP 04 Topological DAG Verify acyclicity! Memoize top-down or iterate bottom-up in reverse dependency order.
    STEP 05 Original & Space Solve target state (and follow parent pointers); compress table to rolling rows or scalars.

    The Universal DP Time Complexity Formula

    Once memoized (ignoring recursion overhead, since every solved state is cached in $O(1)$ lookup):

    $$\text{Total Time} \;=\; \bigl(\text{Number of Distinct Subproblems}\bigr) \;\times\; \bigl(\text{Non-Recursive Work per Subproblem}\bigr)$$

    For example: Fibonacci has $\Theta(n)$ states $\times\; O(1)$ addition $= O(n)$; Text Justification has $\Theta(n)$ suffixes $\times\; O(n)$ line-break guesses $= O(n^2)$; Matrix Chain & Boolean Parenthesization have $\Theta(n^2)$ intervals $\times\; O(n)$ split points $= O(n^3)$.

    Master Subproblem & Transition Cheat Sheet

    Problem / Pattern State Definition Core Transition Time Best Space
    Fibonacci / Climbing Stairs (Part 1) $f(i)$: ways / value at step $i$ $f(i) = f(i-1) + f(i-2)$ $O(n)$ $O(1)$ (prev, prev2)
    Frog Jump (Part 1) $f(i)$: min energy $0 \to i$ $\min\bigl(f(i-1)+|h_i-h_{i-1}|,\; f(i-2)+|h_i-h_{i-2}|\bigr)$ $O(n)$ $O(1)$
    House Robber / Non-Adjacent Sum (Part 1) $f(i)$: max sum in $a[0..i]$ $\max\bigl(a[i] + f(i-2),\; f(i-1)\bigr)$ $O(n)$ $O(1)$
    Text Justification (Part 1) $\text{DP}(i)$: min badness on suffix $w[i:]$ $\min_{j > i}\bigl(\text{badness}(i,j) + \text{DP}(j)\bigr)$ $O(n^2)$ $O(n)$ + parent[i]
    Piano / Guitar Fingering (Part 1) $\text{DP}(i, f)$: suffix $i:$ starting on finger $f$ $\min_{g \in 1..F}\bigl(d(i,f,i+1,g) + \text{DP}(i+1, g)\bigr)$ $O(n F^2)$ $O(F)$
    Unique Paths & Obstacles (Part 2) $dp[i][j]$: paths $(0,0) \to (i,j)$ $0$ if blocked, else $dp[i-1][j] + dp[i][j-1]$ $O(mn)$ $O(n)$ row
    Minimum Path Sum (Part 2) $dp[i][j]$: min cost to $(i,j)$ $g[i][j] + \min(dp[i-1][j], dp[i][j-1])$; OOB $= +\infty$ $O(mn)$ $O(n)$ row
    Triangle Min Path (Part 2) $dp[i][j]$: min sum $(i,j) \to$ bottom $T[i][j] + \min(dp[i+1][j], dp[i+1][j+1])$ $O(n^2)$ $O(n)$ bottom-up
    Maximal 1s Rectangle (DP-55) (Part 2) $h[j]$: consecutive vertical $1$s up to row $i$ $h[j] = g[i][j] ? h[j]+1 : 0$ + Monotonic Stack Histogram $O(mn)$ $O(n)$
    LCS / LPS / SCS / Min Del (Part 3) $dp[i][j]$: LCS of $s_1[:i], s_2[:j]$ Match: $1 + dp[i-1][j-1]$; else $\max(dp[i-1][j], dp[i][j-1])$ $O(mn)$ $O(n)$ ($O(mn)$ to print)
    Longest Common Substring (Part 3) $dp[i][j]$: common suffix ending at $i,j$ Match: $1 + dp[i-1][j-1]$; else $0$ (track global $\max$) $O(mn)$ $O(n)$
    Longest Palindromic Substring (Part 3) $dp[i][j] \in \{0,1\}$: is $s[i..j]$ palindrome? $s[i]==s[j] \;\land\; (j - i \le 2 \;\lor\; dp[i+1][j-1])$ $O(n^2)$ $O(n^2)$ ($O(1)$ expand)
    Edit Distance (Part 3) $dp[i][j]$: min ops $w_1[:i] \to w_2[:j]$ Match: $dp[i-1][j-1]$; else $1 + \min(\text{rep}, \text{del}, \text{ins})$ $O(mn)$ $O(n)$
    Distinct Subsequences (Part 3) $dp[i][j]$: matches of $t[:j]$ in $s[:i]$ Match: $dp[i-1][j-1] + dp[i-1][j]$; else $dp[i-1][j]$ $O(mn)$ $O(m)$ reverse loop
    Wildcard Matching (Part 3) $dp[i][j]$: does $p[:i]$ match $s[:j]$? '*': $dp[i-1][j] \lor dp[i][j-1]$; '?'/eq: $dp[i-1][j-1]$ $O(mn)$ $O(n)$
    Longest Increasing Subsequence (Part 4) 1D $dp[i]$ ending at $i$, or monotonic tails[] $\max_{j < i, a_j < a_i}(1 + dp[j])$, or lower_bound replace $O(n^2) \to O(n \log n)$ $O(n)$
    Matrix Chain & Boolean Eval (Part 4) $dp[i][j][\text{isTrue}]$ on $[i..j]$ Combine $(l_T, l_F) \otimes_{\text{op}_k} (r_T, r_F)$ over odd $k \in (i, j)$ $O(n^3)$ $O(n^2)$

    Five Recurring Pitfalls Highlighted in the Notes

    Checklist Before Submitting Any DP Solution
    1. Verify the subproblem graph is acyclic: Cyclic shortest-path equations like $\delta(s,v) = \min(\delta(s,u) + w(u,v))$ loop forever unless converted into an acyclic layered graph (e.g., $(k, v)$ edges in Bellman-Ford).
    2. Use $+\infty$ (`1e9`), never `0`, to prune invalid min-cost branches: Returning `0` when stepping out of a grid makes walking off the board look cheaper than any positive cell path; using `INT_MAX` overflows when adding `grid[i][j]`.
    3. Shift negative base-case indices by $+1$ for tabulation: Mapping `i = -1` (empty prefix or `prev_ind = -1` in LIS) to index `0` eliminates `if (i > 0)` clutter inside nested loops.
    4. Subsequences propagate; substrings reset to $0$: Never carry `max(dp[i-1][j], dp[i][j-1])` into Longest Common Substring, and never compute Longest Palindromic Substring via `LCSubstring(s, reverse(s))` (`"abcxyzcba"` falsely matches `"abc"` with `"cba"`!).
    5. Augment state when greedy local optimality fails: Just as Piano Fingering needs current finger $f$, Boolean Parenthesization needs both `waysTrue` and `waysFalse` because `False ^ True = True` and `False | True = True`.
