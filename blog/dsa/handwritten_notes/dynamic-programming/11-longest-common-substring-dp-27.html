    DP-27: Longest Common Substring & Maximum Length of Repeated Subarray

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 11_Vid_27_Longest_common_substring.pdf

    A subsequence may skip non-matching characters freely, whereas a substring (or contiguous subarray, LeetCode 718) requires matched elements to appear consecutively without gaps in both inputs. For example, on $s_1 = \texttt{"abcjklp"}$ and $s_2 = \texttt{"acjkp"}$, their Longest Common Subsequence is $\texttt{"acjkp"}$ (length $5$), whereas their Longest Common Substring is $\texttt{"cjk"}$ (length $3$).

    1. Why LCS's Mismatch Rule Breaks Continuity ("acd" vs. "axd")

    Handwritten Counterexample Tree from 11_Vid_27 Page 1

    Suppose we run the LCS recurrence on $s_1 = \texttt{"acd"}$ and $s_2 = \texttt{"axd"}$:

    1. At the end, $\texttt{'d'} == \texttt{'d'}$ contributes $+1$ and steps to $\texttt{"ac"}$ vs. $\texttt{"ax"}$.
    2. At $\texttt{'c'} \ne \texttt{'x'}$, LCS shrinks one string while holding the other ($\texttt{"a"}$ vs. $\texttt{"ax"}$, then $\texttt{"a"}$ vs. $\texttt{"a"}$) and propagates the previous count via $\max(dp[i-1][j], dp[i][j-1])$.
    3. When $\texttt{'a'} == \texttt{'a'}$ matches, it adds $1 + 1 = 2$ ($\texttt{"ad"}$), even though shrinking one side without the other broke contiguity! The true longest common substring of $\texttt{"acd"}$ and $\texttt{"axd"}$ has length $1$ ($\texttt{"a"}$ or $\texttt{"d"}$).

    Why Tabulation Beats Pure Recursion Here (p.1): Writing pure top-down recursion for Longest Common Substring requires passing a third state parameter $f(i, j, \text{count})$ tracking the active streak length, inflating memoization to $O(m \cdot n \cdot \min(m, n))$ states! By contrast, redefining our 2D table state as common suffix length ending right at $(i, j)$ keeps the state space strictly $O(m \cdot n)$.

    2. Diagonal-Only Recurrence & Full Table Trace on "abcd" vs. "abzd"

    Let $dp[i][j]$ be the length of the longest common substring ending simultaneously at $s_1[i - 1]$ and $s_2[j - 1]$ (using $+1$ index shifting so $dp[i][0] = dp[0][j] = 0$):

    $$dp[i][j] = \begin{cases} 1 + dp[i - 1][j - 1] & \text{if } s_1[i - 1] == s_2[j - 1] \\ \mathbf{0} & \text{if } s_1[i - 1] \ne s_2[j - 1] \quad \text{(break the chain immediately!)} \end{cases}$$

    Crucial observation: Notice that $dp[4][4] = 1$ (for trailing $\texttt{"d"}$), whereas the global maximum sits in the interior at $dp[2][2] = \mathbf{2}$ (for $\texttt{"ab"}$)! Because mismatches reset cells to $0$, you must track $\text{ans} = \max_{1 \le i \le m,\, 1 \le j \le n} dp[i][j]$ across the entire grid.

    3. Python Tabulation, $O(n)$ 1D Space Optimization & Printing the Substring

    Because $dp[i][j]$ only ever reads the top-left diagonal $dp[i-1][j-1]$ (never $dp[i-1][j]$ or $dp[i][j-1]$!), sweeping $j$ backward from $n$ down to $1$ updates a single 1D array dp[0..n] in-place without even needing a second temp row! And unlike LCS (which needs the full $O(mn)$ table to print), printing the Longest Common Substring only needs two integers (bestLen, endIdx1):

    #include <bits/stdc++.h>
using namespace std;

// Returns {maxLength, actualCommonSubstring} in O(m*n) time and O(n) space!
pair<int, string> longestCommonSubstring(const string& s1, const string& s2) {
    int m = (int)s1.size(), n = (int)s2.size();
    vector<int> dp(n + 1, 0);
    int bestLen = 0, endIdx1 = 0;

    for (int i = 1; i <= m; ++i) {
        for (int j = n; j >= 1; --j) { // Backward j preserves previous row's dp[j - 1]
            if (s1[i - 1] == s2[j - 1]) {
                dp[j] = 1 + dp[j - 1];
                if (dp[j] > bestLen) {
                    bestLen = dp[j];
                    endIdx1 = i; // Substring ends at s1[i - 1]
                }
            } else {
                dp[j] = 0; // Mandatory reset in 1D in-place array!
            }
        }
    }
    return {bestLen, s1.substr(endIdx1 - bestLen, bestLen)};
}
    # Exact LeetCode 718 Python solution from 11_Vid_27_Longest_common_substring.pdf p.2
class Solution:
    def findLength(self, nums1: list[int], nums2: list[int]) -> int:
        M, N = len(nums1), len(nums2)
        memo = [[0 for _ in range(N + 1)] for _ in range(M + 1)]

        ans = 0
        for i in range(1, M + 1):
            for j in range(1, N + 1):
                if nums1[i - 1] == nums2[j - 1]:
                    memo[i][j] = 1 + memo[i - 1][j - 1]
                    ans = max(ans, memo[i][j])

        return ans

    4. Complexity & Subtle Edge Cases

    • Time & Space: $\Theta(M \cdot N)$ time; $\Theta(M \cdot N)$ space in 2D tabulation, or $\Theta(\min(M, N))$ space in 1D backward-loop optimization. (Note: for very long strings $M, N \approx 10^5$, Suffix Automaton / Suffix Array + LCP or Rolling Hash + Binary Search solves Longest Common Substring in $O((M+N)\log(\min(M,N)))$ or $O(M+N)$.)
    • Forgetting dp[j] = 0 in 1D Space Optimization: In 2D memo = [[0]...], you can omit the else: memo[i][j] = 0 branch because every row is freshly zero-initialized. In a reused 1D array dp[j], omitting else: dp[j] = 0 leaves stale non-zero counts from earlier rows and produces wrong answers!
