    Longest Palindromic Substring: Why Reverse-LCSubstring Fails & Interval Boolean DP

    October 2026 · 10 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 13_Longest_comman_palindromic_substring.pdf

    After learning that $\text{LongestPalindromicSubsequence}(s) = \text{LCS}(s, \text{reverse}(s))$, almost every programmer tries to solve Longest Palindromic Substring (LeetCode 5) by computing $\text{LongestCommonSubstring}(s, \text{reverse}(s))$. Page 1 of 13_Longest_comman_palindromic_substring.pdf opens by demolishing that shortcut with a 9-character counterexample—and then builds the exact boolean interval DP from three elementary boundary rules.

    1. Why LCSubstring(s, reverse(s)) Fails: The "abcxyzcba" Counterexample

    Handwritten Counterexample (13_Longest_comman_palindromic_substring.pdf Page 1)

    Take $s = \texttt{"abcxyzcba"}$ and its reverse $s_{\text{rev}} = \texttt{"abczyxcba"}$:

    • The prefix $s[0..2] = \texttt{"abc"}$ and the reversed suffix $s_{\text{rev}}[0..2] = \texttt{"abc"}$ (which came from $s[6..8] = \texttt{"cba"}$) match character-for-character!
    • Therefore, the Longest Common Substring table writes $dp[1][1] = 1, dp[2][2] = 2, dp[3][3] = \mathbf{3}$ and falsely claims $\texttt{"abc"}$ (and $\texttt{"cba"}$) is a palindrome of length $3$, when the true longest palindromic substring has length $1$!
    • Why did it happen? Reversing $s$ turns any disjoint mirrored pair $(w, \text{rev}(w))$ at opposite ends of $s$ into matching substrings! (If you ever tried to salvage the reverse-table approach, you would have to check that the matched slice in $s_{\text{rev}}$ came from the exact same original index range in $s$, i.e., $1$-based $(i - L) == (n - j)$.)

    2. The Three Palindrome Observations & Interval State $(i, j)$

    Instead of reversing $s$, define boolean interval state $dp[i][j] \in \{\text{true}, \text{false}\}$ directly on $0 \le i \le j < n$: "Is substring $s[i \dots j]$ a palindrome?" Page 1 derives all cases from three observations:

    1. Observation 1 — Single character ($\text{len} = 1$, $i == j$): Every single letter ($\texttt{"a"}$) equals its own reverse $\implies dp[i][i] = \text{true}$ along the main diagonal.
    2. Observation 2 — Double character ($\text{len} = 2$, $j - i == 1$): Two adjacent letters ($\texttt{"aa"}, \texttt{"bb"}$ vs. $\texttt{"ab"}, \texttt{"ba"}$) form a palindrome iff $s[i] == s[j]$ (sits on the super-diagonal $j = i + 1$).
    3. Observation 3 — Length $\ge 3$ ($j - i \ge 2$, e.g. $\texttt{a}\text{[bcb]}\texttt{a}$): Substring $s[i \dots j]$ is a palindrome iff:
      (i) the outer boundary characters match ($s[i] == s[j]$), AND
      (ii) the non-boundary interior substring $s[i+1 \dots j-1]$ is already a palindrome ($dp[i+1][j-1] == \text{true}$)!

    Combining Observations 2 and 3 into one compact condition for $i < j$:

    $$dp[i][j] \;=\; \bigl(s[i] == s[j]\bigr) \;\land\; \bigl(j - i \le 2 \;\lor\; dp[i + 1][j - 1]\bigr)$$

    Trace why $dp[2][7] = 1$: first $dp[4][5] = 1$ ($\texttt{"bb"}$, len $2$) $\implies dp[3][6] = 1$ ($s[3]=s[6]=\texttt{'a'}$ wrapping $\texttt{"bb"} \to \texttt{"abba"}$, len $4$) $\implies dp[2][7] = \mathbf{1}$ ($s[2]=s[7]=\texttt{'a'}$ wrapping $\texttt{"abba"} \to \texttt{"aabbaa"}$, $\text{maxLength} = 6$)! Meanwhile $dp[1][7] = 0$ because interior $dp[2][6]$ ($\texttt{"aabba"}$) was $0$.

    4. Interval DP ($O(n^2)$ Space) vs. Center Expansion ($O(1)$ Space)

    #include <bits/stdc++.h>
using namespace std;

// 1. Boolean Interval DP (exact logic from 13_Longest_comman_palindromic_substring.pdf)
// Time: O(n^2), Space: O(n^2) — also directly counts ALL palindromic substrings (LeetCode 647)!
string longestPalindromeIntervalDP(const string& s) {
    int n = (int)s.size();
    if (n <= 1) return s;
    vector<vector<bool>> dp(n, vector<bool>(n, false));
    int bestStart = 0, maxLen = 1;

    for (int i = n - 1; i >= 0; --i) {
        dp[i][i] = true; // Observation 1: single character
        for (int j = i + 1; j < n; ++j) {
            if (s[i] == s[j] && (j - i <= 2 || dp[i + 1][j - 1])) {
                dp[i][j] = true; // Observations 2 & 3
                if (j - i + 1 > maxLen) {
                    maxLen = j - i + 1;
                    bestStart = i;
                }
            }
        }
    }
    return s.substr(bestStart, maxLen);
}

// 2. Space-Optimized Expand-Around-Center — Time: O(n^2), Auxiliary Space: O(1)
string longestPalindromeExpandCenter(const string& s) {
    int n = (int)s.size();
    int bestStart = 0, maxLen = 0;

    auto expand = [&](int L, int R) {
        while (L >= 0 && R < n && s[L] == s[R]) { --L; ++R; }
        int len = R - L - 1;
        if (len > maxLen) {
            maxLen = len;
            bestStart = L + 1;
        }
    };

    for (int c = 0; c < n; ++c) {
        expand(c, c);     // Odd-length palindromes centered at c
        expand(c, c + 1); // Even-length palindromes centered between c and c+1
    }
    return s.substr(bestStart, maxLen);
}
    def longest_palindrome_dp(s: str) -> str:
    n = len(s)
    if n <= 1:
        return s
    dp = [[False] * n for _ in range(n)]
    start, max_len = 0, 1

    for i in range(n - 1, -1, -1):
        dp[i][i] = True
        for j in range(i + 1, n):
            if s[i] == s[j] and (j - i <= 2 or dp[i + 1][j - 1]):
                dp[i][j] = True
                if j - i + 1 > max_len:
                    start, max_len = i, j - i + 1

    return s[start : start + max_len]

    5. Complexity & When Interval DP Beats Center Expansion

    • When to prefer $O(1)$-space Center Expansion: If you only need the single longest palindromic substring (or total count of palindromic substrings in LeetCode 647), expanding around all $2n - 1$ centers uses $\Theta(1)$ memory. (And Manacher's Algorithm reduces time to $\Theta(n)$ if $n \ge 10^5$.)
    • When the $O(n^2)$ Boolean dp[i][j] Table Is Essential: Whenever a larger Partition DP repeatedly queries "is $s[i..j]$ a palindrome?" in $O(1)$—such as Palindrome Partitioning II (Min Cuts, LeetCode 132 / Striver DP-53)—precomputing this exact dp[i][j] table drops overall complexity from $O(n^3)$ down to $O(n^2)$!
