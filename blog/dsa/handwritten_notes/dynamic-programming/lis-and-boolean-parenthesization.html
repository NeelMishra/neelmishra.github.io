    Longest Increasing Subsequence & Partition DP: Boolean Evaluation to True

    October 2026 · 13 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (14_Vid_41_42_43_Longest_increasing_subsequence.pdf, 15_Vid_52_Boolean_evaluation_to_true.pdf)

    This concluding chapter covers two flagship patterns where naive state definitions need a structural upgrade: Longest Increasing Subsequence (LIS)—tracing its evolution from $O(n \cdot 2^n)$ brute force to coordinate-shifted $O(n^2)$ 2D DP, $O(n)$-space parent-pointer reconstruction, and $O(n \log n)$ binary-search patience piles—and Partition DP: Boolean Evaluation to True, where parenthesizing `&`, `|`, and `^` forces us to count both `True` and `False` ways on every sub-interval $[i \dots j]$.

    1. Longest Increasing Subsequence (Vid 41–43, LeetCode 300)

    Given an integer array $\text{arr}[0 \dots n-1]$, find the length (or elements) of its longest strictly increasing subsequence. On the handwritten benchmark $\text{arr} = [10, 9, 2, 5, 3, 7, 101, 18]$, generating all $2^n$ subsequences and testing monotonicity in $O(n)$ takes $O(n \cdot 2^n)$ time and finds $\{2, 3, 7, 101\}$ (or $\{2, 3, 7, 18\}$) of length $4$.

    1.1 Coordinate-Shifted 2D Pick / Not-Pick DP (Vid 41)

    To decide whether $\text{arr}[\text{ind}]$ can be picked, we must know the index $\text{prev\_ind}$ of the most recently picked element (using $\text{prev\_ind} = -1$ when nothing has been picked yet):

    • State: $f(\text{ind}, \text{prev\_ind}) =$ LIS length in suffix $\text{arr}[\text{ind} \dots n-1]$ given previous index $\text{prev\_ind} \in \{-1, 0, \dots, \text{ind}-1\}$. Initial call: $f(0, -1)$; base case: $f(n, \cdot) = 0$.
    • Transitions: $$\text{notTake} = f(\text{ind} + 1, \text{prev\_ind}), \qquad \text{take} = \begin{cases} 1 + f(\text{ind} + 1, \text{ind}) & \text{if } \text{prev\_ind} == -1 \text{ or } \text{arr}[\text{ind}] > \text{arr}[\text{prev\_ind}] \\ 0 & \text{otherwise} \end{cases}$$
    • Coordinate Change ($\text{prev\_ind} + 1$): Because $\text{prev\_ind}$ starts at $-1$, store state $(\text{ind}, \text{prev\_ind})$ at table entry dp[ind][prev_ind + 1] across an $(n+1) \times (n+1)$ matrix!
    // Vid 41: Bottom-up 2D Tabulation with +1 coordinate shift on prev_ind
int lis2DTabulation(const vector<int>& arr) {
    int n = (int)arr.size();
    vector<vector<int>> dp(n + 1, vector<int>(n + 1, 0)); // dp[n][...] = 0 base case

    for (int ind = n - 1; ind >= 0; --ind) {
        for (int prev_ind = ind - 1; prev_ind >= -1; --prev_ind) {
            int len = dp[ind + 1][prev_ind + 1]; // notTake
            if (prev_ind == -1 || arr[ind] > arr[prev_ind]) {
                len = max(len, 1 + dp[ind + 1][ind + 1]); // take (ind shifted by +1!)
            }
            dp[ind][prev_ind + 1] = len;
        }
    }
    return dp[0][0]; // Represents f(0, -1); Time O(n^2), Space O(n^2) [or O(n)x2 rows]
}

    1.2 1D Ending-At-$i$ Tabulation & Printing the LIS (Vid 42)

    Instead of carrying two indices, define a cleaner 1D state $dp[i] =$ length of the longest increasing subsequence that ends at index $i$ (every element alone forms a subsequence of length $1$, so initialize $dp[i] = 1$). Pair it with a predecessor array $\text{hash}[i]$ (initialized to $\text{hash}[i] = i$) to reconstruct the actual subsequence!

    Handwritten Trace on $\text{arr} = [5, 4, 11, 1, 16, 8]$ (14_Vid_41_42_43 p.3)

    • $i = 0$ ($\text{arr}[0]=5$): $dp[0] = 1$, $\text{hash}[0] = 0$
    • $i = 1$ ($\text{arr}[1]=4$): $5 \not< 4 \implies dp[1] = 1$, $\text{hash}[1] = 1$
    • $i = 2$ ($\text{arr}[2]=11$): extends $5$ ($j=0$) $\implies dp[2] = 2$, $\text{hash}[2] = 0$
    • $i = 3$ ($\text{arr}[3]=1$): $dp[3] = 1$, $\text{hash}[3] = 3$
    • $i = 4$ ($\text{arr}[4]=16$): extends $11$ ($j=2$, $1 + dp[2] = 3$) $\implies dp[4] = \mathbf{3}$, $\text{hash}[4] = 2$
    • $i = 5$ ($\text{arr}[5]=8$): extends $5$ ($j=0$) $\implies dp[5] = 2$, $\text{hash}[5] = 0$

    Maximum sits at $\text{lastIndex} = 4$ ($dp[4] = 3$). Following $\text{hash}$: $4 \;(16) \to 2 \;(11) \to 0 \;(5)$ and reversing prints $[5, 11, 16]$!

    vector<int> printLIS(const vector<int>& arr) {
    int n = (int)arr.size();
    vector<int> dp(n, 1), parent(n);
    int maxLen = 1, lastIndex = 0;

    for (int i = 0; i < n; ++i) {
        parent[i] = i;
        for (int prev = 0; prev < i; ++prev) {
            if (arr[prev] < arr[i] && 1 + dp[prev] > dp[i]) {
                dp[i] = 1 + dp[prev];
                parent[i] = prev;
            }
        }
        if (dp[i] > maxLen) {
            maxLen = dp[i];
            lastIndex = i;
        }
    }

    vector<int> seq;
    seq.push_back(arr[lastIndex]);
    while (parent[lastIndex] != lastIndex) {
        lastIndex = parent[lastIndex];
        seq.push_back(arr[lastIndex]);
    }
    reverse(seq.begin(), seq.end());
    return seq; // O(n^2) time, O(n) space
}

    1.3 Optimal $O(n \log n)$ LIS via Binary Search / Patience Sorting (Vid 43)

    When $n = 10^5$, $O(n^2)$ times out. Look at the handwritten trace on $[1, 7, 8, 4, 5, 6, -1, 9]$: instead of cloning separate candidate lists ($\{1, 7, 8\}$, $\{1, 4, 5, 6\}$, $\{-1, 9\}$), maintain a single monotonically increasing vector tails where tails[k] stores the smallest possible ending value of any increasing subsequence of length $k + 1$ seen so far:

    1. Case 1 ($x > \text{tails.back()}$): $x$ extends the longest active subsequence by $1$ $\implies$ append tails.push_back(x).
    2. Case 2 ($x \le \text{tails.back()}$): Binary-search with lower_bound for the first index $\text{idx}$ where $\text{tails}[\text{idx}] \ge x$ and overwrite tails[idx] = x. Replacing a larger tail of length $\text{idx}+1$ with a smaller tail $x$ never reduces the current max length, and strictly widens future opportunities to extend length $\text{idx}+1$!
    Step Incoming $x$ Action on tails[] Updated tails[]
    1$1$Init first pile$[1]$
    2$7$$7 > 1 \implies$ append$[1, 7]$
    3$8$$8 > 7 \implies$ append$[1, 7, 8]$
    4$4$lower_bound $\to$ idx $1$ ($7 \ge 4$), replace$[1, \mathbf{4}, 8]$
    5$5$lower_bound $\to$ idx $2$ ($8 \ge 5$), replace$[1, 4, \mathbf{5}]$
    6$6$$6 > 5 \implies$ append (new length $4$!)$[1, 4, 5, \mathbf{6}]$
    7$-1$lower_bound $\to$ idx $0$ ($1 \ge -1$), replace$[\mathbf{-1}, 4, 5, 6]$
    8$9$$9 > 6 \implies$ append (new length $5$!)$[-1, 4, 5, 6, \mathbf{9}]$

    Crucial Subtlety: tails[] Gives the Exact Length, NOT the Subsequence Itself!

    Look at Step 7–8 above: tails ends as $[-1, 4, 5, 6, 9]$, which is not a subsequence of $[1, 7, 8, 4, 5, 6, -1, 9]$ because $-1$ appeared after $4, 5, 6$! Overwriting index $0$ with $-1$ did not corrupt the length because the top element $6$ remained untouched; $-1$ only prepared a better starting point in case four small numbers (e.g., $0, 1, 2, 3$) arrived later. The true length-$5$ LIS is $[1, 4, 5, 6, 9]$.

    int lisBinarySearch(const vector<int>& arr) {
    vector<int> tails;
    for (int x : arr) {
        if (tails.empty() || x > tails.back()) {
            tails.push_back(x);
        } else {
            auto it = lower_bound(tails.begin(), tails.end(), x); // First >= x
            *it = x;
        }
    }
    return (int)tails.size(); // Time O(n log n), Space O(n)
}

    2. Partition DP: Boolean Evaluation to True (Vid 52)

    Given an alternating boolean expression string $\text{exp}$ of length $n$ (always odd) where even indices $0, 2, 4, \dots, n-1$ hold operands 'T' or 'F' and odd indices $1, 3, 5, \dots, n-2$ hold bitwise operators '&' (AND), '|' (OR), or '^' (XOR)—for example $\texttt{T \^{} F | T \& F \^{} T | F}$—count the number of full parenthesizations that evaluate to True modulo $10^9 + 7$.

    2.1 Why State $(i, j)$ Must Track Both True and False

    Like Matrix Chain Multiplication, we guess the last operator evaluated at odd index $k \in \{i+1, i+3, \dots, j-1\}$, splitting $[i \dots j]$ into left sub-expression $[i \dots k-1]$ and right sub-expression $[k+1 \dots j]$.

    However, knowing only how many ways $[i \dots k-1]$ and $[k+1 \dots j]$ evaluate to True is not enough! For instance, $\text{Left} \oplus \text{Right} = \text{True}$ occurs when $(\text{True} \oplus \text{False})$ or $(\text{False} \oplus \text{True})$. Thus every interval $[i \dots j]$ must maintain both counts: $(l_T, l_F) = \text{DP}(i, k-1)$ and $(r_T, r_F) = \text{DP}(k+1, j)$ (equivalently a 3D state $f(i, j, \text{isTrue} \in \{0, 1\})$).

    2.2 Exact Operator Combination Formulas

    Operator exp[k] Ways to Evaluate to True Ways to Evaluate to False
    OR ('|') $l_T \cdot r_T + l_T \cdot r_F + l_F \cdot r_T$ $l_F \cdot r_F$
    AND ('&') $l_T \cdot r_T$ $l_T \cdot r_F + l_F \cdot r_T + l_F \cdot r_F$
    XOR ('^') $l_T \cdot r_F + l_F \cdot r_T$ $l_T \cdot r_T + l_F \cdot r_F$

    Mini Dry Run on $\texttt{"T|T\&F\^{}T"}$ ($n = 7$, $4$ operands $\implies C_3 = 5$ total parenthesizations)

    • Base cases ($i == j$): $dp[0][0]=(1,0),\; dp[2][2]=(1,0),\; dp[4][4]=(0,1),\; dp[6][6]=(1,0)$.
    • Gap $2$: $\texttt{T|T} \to (1,0)$;\; $\texttt{T\&F} \to (0,1)$;\; $\texttt{F\^{}T} \to (1,0)$.
    • Gap $4$:
      • $[0..4]$ ($\texttt{T|T\&F}$): split at $k=1$ ('|'): $(1,0) \mathbin{|} (0,1) \to (1,0)$; split at $k=3$ ('&'): $(1,0) \mathbin{\&} (0,1) \to (0,1)$ $\implies dp[0][4] = (1, 1)$.
      • $[2..6]$ ($\texttt{T\&F\^{}T}$): split at $k=3$ ('&'): $(1,0) \mathbin{\&} (1,0) \to (1,0)$; split at $k=5$ ('^'): $(0,1) \mathbin{\oplus} (1,0) \to (1,0)$ $\implies dp[2][6] = (2, 0)$.
    • Gap $6$ ($[0..6]$):
      • $k=1$ ('|'): $(1,0) \mathbin{|} (2,0) \implies 1\cdot 2 + 1\cdot 0 + 0\cdot 2 = 2$ True ways.
      • $k=3$ ('&'): $(1,0) \mathbin{\&} (1,0) \implies 1\cdot 1 = 1$ True way.
      • $k=5$ ('^'): $(1,1) \mathbin{\oplus} (1,0) \implies 1\cdot 0 + 1\cdot 1 = 1$ True way.
      Total $= 2 + 1 + 1 = \mathbf{4}$ parenthesizations evaluating to True!

    2.3 C++ 3D Memoization & Python Bottom-Up Tuple Tabulation

    #include <bits/stdc++.h>
using namespace std;

const long long MOD = 1000000007LL;

long long solveBool(int i, int j, int isTrue, const string& exp,
                    vector<vector<array<long long, 2>>>& dp) {
    if (i > j) return 0;
    if (i == j) {
        if (isTrue == 1) return exp[i] == 'T' ? 1 : 0;
        else             return exp[i] == 'F' ? 1 : 0;
    }
    if (dp[i][j][isTrue] != -1) return dp[i][j][isTrue];

    long long ways = 0;
    for (int k = i + 1; k <= j - 1; k += 2) { // Odd operator indices
        long long lT = solveBool(i, k - 1, 1, exp, dp);
        long long lF = solveBool(i, k - 1, 0, exp, dp);
        long long rT = solveBool(k + 1, j, 1, exp, dp);
        long long rF = solveBool(k + 1, j, 0, exp, dp);

        if (exp[k] == '&') {
            if (isTrue) ways = (ways + lT * rT) % MOD;
            else        ways = (ways + lT * rF + lF * rT + lF * rF) % MOD;
        } else if (exp[k] == '|') {
            if (isTrue) ways = (ways + lT * rT + lT * rF + lF * rT) % MOD;
            else        ways = (ways + lF * rF) % MOD;
        } else if (exp[k] == '^') {
            if (isTrue) ways = (ways + lT * rF + lF * rT) % MOD;
            else        ways = (ways + lT * rT + lF * rF) % MOD;
        }
    }
    return dp[i][j][isTrue] = ways;
}

int evaluateExpWays(const string& exp) {
    int n = (int)exp.size();
    vector<vector<array<long long, 2>>> dp(n, vector<array<long long, 2>>(n, {-1, -1}));
    return (int)solveBool(0, n - 1, 1, exp, dp); // Time O(n^3), Space O(n^2)
}

    And the exact bottom-up Python tuple formulation from 15_Vid_52_Boolean_evaluation_to_true.pdf p.2, stepping over even sub-expression gaps $\text{gap} = 2, 4, \dots, n - 1$:

    def evaluateExp(exp: str) -> int:
    mod = 1000000007
    n = len(exp)
    operator_map = {
        '|': lambda lt, lf, rt, rf: ((lt * rt + lt * rf + lf * rt) % mod, (lf * rf) % mod),
        '&': lambda lt, lf, rt, rf: ((lt * rt) % mod, (lt * rf + lf * rt + lf * rf) % mod),
        '^': lambda lt, lf, rt, rf: ((lt * rf + lf * rt) % mod, (lt * rt + lf * rf) % mod),
    }

    # dp[i][j] stores (waysTrue, waysFalse) for sub-expression exp[i..j]
    dp = [[(0, 0) for _ in range(n)] for _ in range(n)]
    for i in range(0, n, 2):
        dp[i][i] = (1, 0) if exp[i] == 'T' else (0, 1)

    for gap in range(2, n, 2):              # Even gaps between operand indices
        for i in range(0, n - gap, 2):
            j = i + gap
            ways_true, ways_false = 0, 0
            for k in range(i + 1, j, 2):    # Odd operator index k
                lt, lf = dp[i][k - 1]
                rt, rf = dp[k + 1][j]
                t, f = operator_map[exp[k]](lt, lf, rt, rf)
                ways_true = (ways_true + t) % mod
                ways_false = (ways_false + f) % mod
            dp[i][j] = (ways_true, ways_false)

    return dp[0][n - 1][0]
