    Maximum Sum of Non-Adjacent Elements (House Robber): Pick / Not-Pick 1D DP

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 10_Vid_5.pdf

    Whenever a problem asks you to choose an optimal subset or subsequence subject to local exclusion constraints, the Pick / Non-Pick pattern is your sharpest weapon. Across three detailed pages, 10_Vid_5.pdf solves Maximum Sum of Non-Adjacent Elements / House Robber (LeetCode 198, Striver DP-5), traces its recursion tree to verify overlapping subproblems, catches uninitialized negative-index bugs during bottom-up conversion, and reduces auxiliary memory down to two integers.

    1. Problem Goal & Pick / Non-Pick State Design

    Given an array $a[0 \dots n-1]$ of non-negative integers (money stashed in houses along a street), find the maximum sum of any subsequence in which no two chosen elements sit at adjacent indices.

    • Goal / State Definition (p.1): Let $f(\text{ind})$ be the maximum non-adjacent subsequence sum achievable within the prefix $a[0 \dots \text{ind}]$. We start from the back at $\text{ind} = n - 1$.
    • Actions at $\text{ind}$:
      • Pick $a[\text{ind}]$: Because adjacent index $\text{ind} - 1$ is now forbidden, jump straight to $\text{ind} - 2$: $$\text{pick} = a[\text{ind}] + f(\text{ind} - 2)$$
      • Not-Pick $a[\text{ind}]$: Gain $0$ here, leaving index $\text{ind} - 1$ free to consider: $$\text{notPick} = 0 + f(\text{ind} - 1)$$
    • Base Cases (and why they work!):
      • if (ind == 0) return a[0]; — As annotated in the margin of page 1: "If you reached $0$, then you didn't pick $1$. Hence you can pick it (because array has no negative)!" (Note: if negative numbers were allowed, this would become max(0, a[0]).)
      • if (ind < 0) return 0; — Triggered when $\text{ind} = 1$ chooses pick and calls $f(1 - 2) = f(-1)$.

    3. Converting to Tabulation & Two Critical Pitfalls

    Pages 2–3 convert memoization ($O(N)$ time, $O(N)$ stack $+ O(N)$ memo array) into bottom-up tabulation starting from dp[0] = a[0] and looping $i = 1 \dots n - 1$.

    Two Bugs Highlighted in 10_Vid_5.pdf (Pages 2 & 3)

    1. Out-of-bounds dp[i - 2] when $i = 1$: Page 2 circles dp[i - 2] inside the for (i = 1; i < n; i++) loop with the note: "this is not initialized, this needs handled!" When $i = 1$, $i - 2 = -1$ is negative! Always initialize int take = a[i]; if (i > 1) take += dp[i - 2];.
    2. Accidentally indexing a[i - 2] instead of dp[i - 2]: Look at the top of page 3: when rewriting the guard quickly by hand, it is super easy to write take += a[ind - 2] and notTake = a[ind - 1] instead of reading from the DP table dp[i - 2] and dp[i - 1]! On $[2, 1, 1, 2]$, reading a[] gives $\max(2+1, 1) = 3$, missing the true optimal sum $2 + 2 = 4$ stored in dp[1] = 2! Always map recursive calls $f(\cdot)$ strictly to dp[...].

    4. $O(1)$ Space Optimization & House Robber II (Circular Street)

    To compute index $i$, do we ever need $(i - 3)$ or $(i - 4)$? No—only $(i - 1)$ and $(i - 2)$! Maintain two scalars:

    • prev = a[0] (represents dp[i - 1], initially $i - 1 = 0$)
    • prev2 = 0 (represents dp[i - 2], initially the base case $\text{ind} = -1 \implies 0$!)

    Notice how cleaner $O(1)$ space optimization is than array tabulation: because prev2 starts at $0$, iteration $i = 1$ computes take = a[1] + prev2 = a[1] + 0 without needing an if (i > 1) branch at all!

    #include <bits/stdc++.h>
using namespace std;

// Stage 2: Top-Down Memoization — O(N) time, O(N) stack + O(N) dp
int solveMemo(int ind, const vector<int>& a, vector<int>& dp) {
    if (ind == 0) return a[0];
    if (ind < 0)  return 0;
    if (dp[ind] != -1) return dp[ind];

    int pick    = a[ind] + solveMemo(ind - 2, a, dp);
    int notPick = 0 + solveMemo(ind - 1, a, dp);
    return dp[ind] = max(pick, notPick);
}

// Stage 3: Bottom-Up Tabulation — O(N) time, O(N) dp
int robTabulation(const vector<int>& a) {
    int n = (int)a.size();
    if (n == 0) return 0;
    vector<int> dp(n, 0);
    dp[0] = a[0];

    for (int i = 1; i < n; ++i) {
        int take = a[i];
        if (i > 1) take += dp[i - 2]; // Guard i = 1 -> dp[-1]
        int notTake = 0 + dp[i - 1];
        dp[i] = max(take, notTake);
    }
    return dp[n - 1];
}

// Stage 4: Space-Optimized — O(N) time, O(1) space
int robLinear(const vector<int>& a, int lo, int hi) {
    if (lo > hi) return 0;
    int prev  = a[lo]; // dp[i - 1]
    int prev2 = 0;     // dp[i - 2] (virtual index -1 -> 0)

    for (int i = lo + 1; i <= hi; ++i) {
        int take    = a[i] + prev2;
        int notTake = 0 + prev;
        int curr    = max(take, notTake);
        prev2 = prev;
        prev  = curr;
    }
    return prev;
}

// Follow-up: House Robber II (LeetCode 213 — Houses in a Circle)
int robCircular(const vector<int>& nums) {
    int n = (int)nums.size();
    if (n == 0) return 0;
    if (n == 1) return nums[0]; // Single house has no distinct neighbor!
    // House 0 and House n-1 cannot BOTH be robbed: omit last OR omit first
    return max(robLinear(nums, 0, n - 2), robLinear(nums, 1, n - 1));
}

    5. Complexity & Edge Cases

    • Time & Space: Naive recursion takes $O(2^n)$ time ($O(\varphi^n)$ tightly); rolling-scalar DP takes $\Theta(n)$ time and $\Theta(1)$ auxiliary memory without modifying the input array.
    • Array Containing Negative Numbers (General Max Non-Adjacent Subsequence): If $a[i]$ can be negative, change dp[0] = max(0, a[0]) (or return 0 if empty subsequence is allowed; if non-empty is mandatory and all $a[i] < 0$, return $\max_i a[i]$).
    • Circular $n = 1$ Edge Case: In robCircular, robLinear(0, -1) and robLinear(1, 0) would both return $0$ unless if (n == 1) return nums[0]; is checked up front!
