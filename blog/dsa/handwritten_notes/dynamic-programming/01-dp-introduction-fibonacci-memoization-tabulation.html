    DP Introduction: Fibonacci, Memoization, Tabulation & $O(1)$ Space Optimization

    October 2026 · 8 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 01_Vid_1.pdf

    Those who cannot remember the past are condemned to repeat it. Every competitive programming Dynamic Programming solution follows the same four-stage engineering pipeline—Naive Recursion $\to$ Top-Down Memoization $\to$ Bottom-Up Tabulation $\to$ Space Optimization—and there is no cleaner laboratory to master all four transitions than computing the $n^{\text{th}}$ Fibonacci number.

    1. Memoization vs. Tabulation at a Glance

    The opening lines of 01_Vid_1.pdf distinguish the two complementary ways of caching overlapping recursive work:

    The Two Core DP Paradigms

    1. Memoization (Top-Down DP): Start from the required answer $f(n)$ and recurse downward toward the base cases, storing each newly solved state in a cache (dp[n]) so any future call returns immediately in $O(1)$ time.
    2. Tabulation (Bottom-Up DP): Eliminate recursion completely! Seed the base cases directly into dp[] and iterate forward from smaller states to $n$, guaranteeing every dependency is already computed before it is read.

    2. Spotting Overlapping Subproblems in Naive Recursion

    In the handwritten note's $0$-indexed staircase convention, the sequence starts at $1, 1, 2, 3, 5, 8, 13, 21, \dots$ with $f(0) = 1$, $f(1) = 1$, and recurrence:

    $$f(n) = f(n - 1) + f(n - 2) \qquad \text{for } n > 1$$

    (Note: standard LeetCode 509 uses $F(0) = 0, F(1) = 1$ giving $0, 1, 1, 2, 3, 5, 8, \dots$—the transition and complexity are identical; only dp[0] changes from $1$ to $0$.)

    Unrolling the call tree for $f(4)$ immediately exposes overlapping substructure: the subtree $f(2)$ is evaluated from scratch on the left inside $f(3)$ and then recomputed all over again on the right branch of $f(4)$. For $f(5)$, $f(3)$ is computed twice and $f(2)$ three times, blowing up into $O(2^n)$ calls (tightly $\Theta(\varphi^n)$ where $\varphi = \frac{1+\sqrt{5}}{2} \approx 1.618$).

    3. Stage 2: Top-Down Memoization & Two Classic Bugs

    To memoize $f(n)$, allocate an array dp of size $n + 1$ initialized to -1 (representing "uncomputed"). Before making recursive calls, check if (dp[n] != -1) return dp[n];.

    Two Subtle Memoization Slips to Catch in Interviews

    1. Forgetting to store into dp[n] before returning: In quick handwritten pseudocode (see 01_Vid_1.pdf p.1), it is tempting to check if dp[n] != -1: return dp[n] and then write bare return f(n-1) + f(n-2). Without dp[n] = ..., dp stays all -1s and runtime silently remains $O(2^n)$!
    2. Off-by-one array sizing (n vs. n + 1): Because we query index dp[n], initializing [-1 for _ in range(n)] only creates indices $0 \dots n-1$ and throws an IndexError / out-of-bounds read at dp[n]. Always allocate n + 1 slots!

    Space breakdown from p.1: Top-down memoization uses two $O(n)$ buffers simultaneously:

    $$\text{Auxiliary Space}_{\text{memo}} = \underbrace{O(n)}_{\text{recursion stack depth}} + \underbrace{O(n)}_{\text{dp[0..n] array}} = O(n)$$

    4. Stage 3 & Stage 4: Bottom-Up Tabulation $\to$ $O(1)$ Space

    Page 1–2 lays out the systematic recipe for converting any memoized recursion into bottom-up tabulation, and then stripping away the array entirely:

    1. Tabulation ($O(n)$ time, $O(n)$ array, $O(1)$ stack): Start at the base cases dp[0] = 1, dp[1] = 1, and iterate $i = 2 \dots n$ computing dp[i] = dp[i - 1] + dp[i - 2]. Removing recursion saves the $O(n)$ call stack frame overhead (preventing stack overflow when $n = 10^6$).
    2. Rolling Scalar Optimization ($O(n)$ time, $O(1)$ space): Look closely at dp[i] = dp[i - 1] + dp[i - 2]. At step $i$, we never touch dp[i - 3] or anything older! Rename dp[i - 1] to prev and dp[i - 2] to prev2: $$\text{curr} = \text{prev} + \text{prev2}, \qquad \text{prev2} \leftarrow \text{prev}, \qquad \text{prev} \leftarrow \text{curr}$$ After the loop finishes $i = n$, prev holds the final curr value!

    Step-by-Step Dry Run of Rolling Scalars ($n = 5$, 0-indexed $1, 1, 2, 3, 5, 8$)

    • Init: prev2 = 1 ($f(0)$), prev = 1 ($f(1)$)
    • $i = 2$: curr = 1 + 1 = 2 $\implies$ prev2 = 1, prev = 2
    • $i = 3$: curr = 2 + 1 = 3 $\implies$ prev2 = 2, prev = 3
    • $i = 4$: curr = 3 + 2 = 5 $\implies$ prev2 = 3, prev = 5
    • $i = 5$: curr = 5 + 3 = 8 $\implies$ prev2 = 5, prev = 8 $\implies$ return prev = 8.

    5. Complete C++ & Python Implementations (All 4 Stages)

    #include <bits/stdc++.h>
using namespace std;

// Stage 1: Naive Recursion — Time O(2^n), Space O(n) stack
long long fibRecursive(int n) {
    if (n <= 1) return 1; // Use `return n;` if 0-indexed F(0)=0, F(1)=1
    return fibRecursive(n - 1) + fibRecursive(n - 2);
}

// Stage 2: Top-Down Memoization — Time O(n), Space O(n) stack + O(n) dp
long long fibMemo(int n, vector<long long>& dp) {
    if (n <= 1) return 1;
    if (dp[n] != -1) return dp[n]; // Computed previously; skip subtree!
    return dp[n] = fibMemo(n - 1, dp) + fibMemo(n - 2, dp);
}

// Stage 3: Bottom-Up Tabulation — Time O(n), Space O(n) dp (zero recursion stack)
long long fibTabulation(int n) {
    if (n <= 1) return 1;
    vector<long long> dp(n + 1, 0);
    dp[0] = 1;
    dp[1] = 1;
    for (int i = 2; i <= n; ++i) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}

// Stage 4: Space-Optimized — Time O(n), Space O(1)
long long fibSpaceOptimized(int n) {
    if (n <= 1) return 1; // Note: if F(0)=0 convention, handle `if (n == 0) return 0;`!
    long long prev2 = 1;  // f(0)
    long long prev  = 1;  // f(1)
    for (int i = 2; i <= n; ++i) {
        long long curr = prev + prev2;
        prev2 = prev;
        prev  = curr;
    }
    return prev; // `prev` stepped forward to `curr` on the final iteration i = n
}
    def fib_memo(n: int) -> int:
    dp = [-1] * (n + 1)

    def f(k: int) -> int:
        if k <= 1:
            return 1
        if dp[k] != -1:
            return dp[k]
        dp[k] = f(k - 1) + f(k - 2)
        return dp[k]

    return f(n)


def fib_space_optimized(n: int) -> int:
    if n <= 1:
        return 1
    prev2, prev = 1, 1
    for _ in range(2, n + 1):
        curr = prev + prev2
        prev2 = prev
        prev = curr
    return prev

    6. Complexity Summary & Edge Cases

    Approach Time Complexity Auxiliary Space Contest Verdict
    Naive Recursion $\Theta(\varphi^n) \subset O(2^n)$ $O(n)$ stack TLE around $n \ge 42$
    Memoization $\Theta(n)$ $O(n)$ stack $+ O(n)$ array Stack risk for $n \ge 2 \cdot 10^5$ in Python
    Tabulation $\Theta(n)$ $O(n)$ array Fast, safe, reconstructible
    Rolling Variables $\Theta(n)$ $\Theta(1)$ Optimal linear-time DP
    Edge Cases to Double-Check
    • $n = 0$ under $F(0) = 0, F(1) = 1$: If prev = 1 and the loop range(2, n + 1) does zero iterations for $n = 0$, returning prev blindly returns $1$ instead of $0$! Always guard if (n <= 1) return n; (or return 1 under the staircase convention).
    • 64-bit Integer Overflow: $F(93)$ already exceeds signed 64-bit long long ($9.22 \times 10^{18}$). For large $n$, apply % 1000000007 inside the addition curr = (prev + prev2) % MOD.
