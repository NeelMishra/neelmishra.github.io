    Number of Ways to Arrive at Destination (LeetCode 1976)

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 01_1976_Number_of_Ways_to_Arrive_at_Destination.pdf

    Computing the minimum distance from a source to a destination is standard Min-Heap Dijkstra. LeetCode 1976 (Number of Ways to Arrive at Destination) asks a deeper combinatorial question: when multiple distinct routes tie for the exact minimum travel time, how do we count all of them modulo $10^9 + 7$ without enumerating exponentially many paths? The answer is one of the cleanest patterns in graph algorithms — piggybacking dynamic programming (ways[]) directly onto Dijkstra's greedy settlement order.

    1. Problem Statement & Constraints

    LeetCode 1976 — Number of Ways to Arrive at Destination

    You are in a city consisting of $n$ intersections numbered from $0$ to $n - 1$, connected by bidirectional roads. Each entry roads[i] = [u, v, time] indicates a road between $u$ and $v$ that takes $\text{time}$ minutes to traverse.

    Determine the number of distinct ways you can travel from intersection $0$ to intersection $n - 1$ in the shortest amount of time. Since the answer may be huge, return it modulo $10^9 + 7$.

    • $1 \le n \le 200$
    • $n - 1 \le \text{roads.length} \le \frac{n(n - 1)}{2}$ (connected simple graph; no self-loops or duplicate roads)
    • $1 \le \text{time}_i \le 10^9$ (strictly positive edge weights!)

    2. Core Intuition: Shortest Paths Form a Implicit DAG

    At first glance, counting paths in an undirected graph sounds dangerous because cycles allow infinite walks. Why don't cycles hurt us here?

    Because every road has strictly positive travel time ($w(u, v) \ge 1$), any shortest path from $0$ that steps across edge $u \to v$ must satisfy:

    $$\text{dist}[v] \;=\; \text{dist}[u] + w(u, v) \;\gt\; \text{dist}[u]$$

    Since $\text{dist}[\cdot]$ strictly increases at every hop along a shortest path, no shortest path can ever revisit a vertex! If we orient every road $u \to v$ that satisfies $\text{dist}[u] + w(u, v) = \text{dist}[v]$, those tight edges form a Directed Acyclic Graph (Shortest-Path DAG). Better yet, popping vertices in non-decreasing order of distance from Dijkstra's min-heap processes vertices in a valid topological order of that DAG on the fly!

    3. Brute $\to$ Better $\to$ Optimal Progression

    Evolution of approaches for counting shortest paths on weighted graphs
    Approach Core Mechanism Time Complexity Verdict
    1. Brute Force Backtracking DFS over all simple paths $0 \rightsquigarrow n - 1$, tracking minimum cost and resetting count whenever a smaller total is seen. $\mathcal{O}((n - 1)!)$ TLE for $n \gt 15$ (up to $200!$ simple paths on dense graphs).
    2. Better (Two-Pass DAG DP) Run Dijkstra first to fix dist[]; build the DAG of edges with $\text{dist}[u] + w = \text{dist}[v]$; run memoized DFS / Kahn's topological DP. $\mathcal{O}(E \log V)$ Accepted, but builds an extra graph and makes two traversals.
    3. Optimal (Single-Pass Dijkstra + ways[]) Maintain dist[] and ways[] simultaneously inside one Min-Heap Dijkstra pass using two relaxation branches (< vs ==). $\mathcal{O}(E \log V)$ Optimal — zero extra graph allocation, single heap pass.

    The Two Relaxation Branches Inside Optimal Dijkstra

    Initialize dist[0] = 0 (all other dist[i] = LLONG_MAX) and ways[0] = 1 (all other ways[i] = 0). When we pop the minimum-distance pair (dis, u) from the priority queue (and confirm dis == dist[u], so both dist[u] and ways[u] are permanently finalized), we inspect every neighbor (v, wt):

    Shortest-Path Counting Recurrence

    1. Strictly Shorter Path Found ($\text{dis} + \text{wt} \lt \text{dist}[v]$):
      Every previously discovered route to $v$ was strictly slower and is now obsolete. Overwrite the distance, reset the path count to match $u$, and push $v$ to the min-heap: $$\text{dist}[v] \leftarrow \text{dis} + \text{wt}, \qquad \text{ways}[v] \leftarrow \text{ways}[u], \qquad \text{pq.push}(\{\text{dist}[v],\, v\})$$
    2. Equal Shortest Distance Tied ($\text{dis} + \text{wt} = \text{dist}[v]$):
      Every shortest path to $u$ extends via $(u, v)$ into a distinct shortest path to $v$ of the exact same optimal cost! Accumulate modulo $10^9 + 7$ and do NOT push $v$ into the heap again: $$\text{ways}[v] \leftarrow (\text{ways}[v] + \text{ways}[u]) \bmod (10^9 + 7)$$
    Why Don't We Push v to the Priority Queue on a Tie (==)? When dist[v] was first set to its current value, {dist[v], v} was already pushed into the min-heap! Because $w(u, v) \ge 1 \implies \text{dist}[u] \lt \text{dist}[v]$, vertex $u$ is guaranteed to be popped strictly before {dist[v], v} pops. Thus all tied predecessors $u_1, u_2, \dots$ finish adding their counts into ways[v] before $v$ itself is ever popped once to propagate downstream!

    5. Clean C++ Implementation

    #include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int countPaths(int n, vector<vector<int>>& roads) {
        const long long MOD = 1'000'000'007LL;

        // Build bidirectional weighted adjacency list
        vector<vector<pair<int, long long>>> adj(n);
        for (const auto& road : roads) {
            int u = road[0], v = road[1];
            long long wt = road[2];
            adj[u].push_back({v, wt});
            adj[v].push_back({u, wt});
        }

        // Min-heap storing {tentative_distance, node}
        using State = pair<long long, int>;
        priority_queue<State, vector<State>, greater<State>> pq;

        vector<long long> dist(n, LLONG_MAX);
        vector<long long> ways(n, 0);

        dist[0] = 0;
        ways[0] = 1;
        pq.push({0LL, 0});

        while (!pq.empty()) {
            auto [dis, u] = pq.top();
            pq.pop();

            // Lazy deletion: skip outdated heap entries
            if (dis > dist[u]) continue;

            for (auto [v, wt] : adj[u]) {
                long long cand = dis + wt;
                if (cand < dist[v]) {
                    dist[v] = cand;
                    ways[v] = ways[u];
                    pq.push({cand, v});
                } else if (cand == dist[v]) {
                    ways[v] = (ways[v] + ways[u]) % MOD;
                }
            }
        }

        return static_cast<int>(ways[n - 1] % MOD);
    }
};

    6. Time & Space Complexity Proof

    Asymptotic Complexity ($V = n$, $E = \text{roads.length}$)

    • Time Complexity — $\mathcal{O}(E \log V)$ (more precisely $\mathcal{O}((V + E)\log V)$):
      Because of the stale-entry check if (dis > dist[u]) continue;, each vertex $u$ expands its adjacency list at most once (the exact moment $u$ is popped with dis == dist[u]). Across the entire run, each undirected road is inspected twice, causing at most $2E$ heap pushes (and only on strict distance decreases!). With at most $2E$ elements in the heap and $E \le \frac{V(V-1)}{2} \lt V^2$ on a simple graph, each push/pop costs: $$\mathcal{O}(\log E) \;\le\; \mathcal{O}(\log V^2) \;=\; \mathcal{O}(2 \log V) \;=\; \mathcal{O}(\log V)$$ Total runtime: $\mathcal{O}((V + E)\log V)$, which for $V \le 200, E \le 19{,}900$ performs fewer than $3 \times 10^5$ operations ($\lt 3\text{ ms}$ in C++).
    • Auxiliary Space — $\mathcal{O}(V + E)$:
      Adjacency list stores $2E$ pairs; dist[] and ways[] take $\mathcal{O}(V)$; the binary heap holds at most $\mathcal{O}(E)$ pairs.

    7. Key Edge Cases & Classic Contest Traps

    Four Bugs That Cause WA or TLE on LeetCode 1976

    1. 32-bit int / 1e9 Overflow on dist[]: With $n = 200$ vertices in a line and each road taking $10^9$ minutes, the true shortest distance to $n - 1$ is $199 \times 10^9 = 1.99 \times 10^{11}$, which overflows 32-bit int ($\approx 2.14 \times 10^9$) and beats a naive INF = 1e9 sentinel! Always use 64-bit long long initialized to LLONG_MAX.
    2. Pushing to pq Inside the cand == dist[v] Branch: Pushing duplicate equal-distance pairs causes vertex $v$ to pop $k$ times with dis == dist[v], multiplying downstream path counts by $k$ (Wrong Answer) and blowing up heap operations exponentially (TLE).
    3. Single Intersection ($n = 1$, roads = []): Start and destination are both node $0$. Initializing ways[0] = 1 before the loop ensures ways[n - 1] immediately returns 1 (the empty 0-minute walk).
    4. Taking Modulo on dist[] Instead of ways[]: Never reduce dist[v] modulo $10^9 + 7$! Comparing distances after modulo reduction destroys the total order ($10^9 + 8 \bmod M = 1 \lt 5$), corrupting which paths are shortest. Only ways[] is taken modulo $10^9 + 7$.
