    Min-Heap Dijkstra & Counting Shortest Paths (LeetCode 1976)

    October 2026 · 10 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (02_Striver_djikstra_PQ_g32.pdf & 01_1976_Number_of_Ways_to_Arrive_at_Destination.pdf)

    When all edge weights are non-negative ($w(u, v) \ge 0$), Dijkstra's algorithm computes the shortest path from a single source vertex to every vertex in $\mathcal{O}(E \log V)$ time. Moreover, because Dijkstra settles vertices in non-decreasing order of shortest distance, we can piggyback dynamic programming directly onto its relaxation loop — most famously to count the exact number of distinct shortest paths in LeetCode 1976 (Number of Ways to Arrive at Destination).

    1. Weighted Graph Representation & Core Data Structures

    Following page 1 of the handwritten notes, we represent a weighted graph as an adjacency list where each entry adj[u] stores pairs {adjNode, edgeWeight}:

    0 → {1, 4}, {2, 4}
    1 → {0, 4}, {2, 2}
    adj = [ [{1, 4}, {2, 4}], [{0, 4}, {2, 2}], ... ]

    Dijkstra maintains two structures side by side:

    1. Distance array dist[0..V-1]: Initialized to $\infty$ (1e9 or LLONG_MAX) everywhere except dist[source] = 0.
    2. Min-heap priority queue pq: Stores pairs in the exact order {distance, node} so C++'s lexicographical comparison always pops the smallest tentative distance first.

    2. Why a Plain Queue Fails & Why a Min-Heap Works

    Why can't we use a regular FIFO std::queue like BFS and just relax edges whenever dis + wt < dist[adj]?

    • What goes wrong with a plain FIFO queue: Suppose $0 \to 2$ has weight $100$, while $0 \to 1 \to 2$ has weights $1 + 1 = 2$, and vertex $2$ roots a large subgraph of $1{,}000$ vertices. A plain queue pops $2$ with tentative distance $100$ first, propagating $100 + \dots$ across all $1{,}000$ downstream vertices — only to pop $1$ afterward, improve dist[2] to $2$, and re-propagate updates across all $1{,}000$ downstream vertices again! On contrived DAGs, FIFO relaxation without min-first ordering degrades to $\mathcal{O}(V \cdot E)$ or worse.
    • Why the min-heap settles each vertex once: When all edge weights satisfy $w \ge 0$, let $(d, u)$ be the minimum-distance pair popped from the heap (with $d = \text{dist}[u]$). Any alternative path from source to $u$ that has not yet been explored must pass through some currently unpopped frontier vertex $x$ with $\text{dist}[x] \ge d$, followed by edges of weight $\ge 0$, so its total cost is at least $\text{dist}[x] + 0 \ge d$. Hence dist[u] is permanently optimal!
    Priority Queue vs. std::set As noted on page 1, Dijkstra can be implemented with either a min-heap (priority_queue) or std::set<pair<int,int>>. A set lets you erase({dist[adj], adj}) before inserting a better distance, keeping container size $\le V$. However, std::priority_queue is backed by a contiguous std::vector (cache-friendly, zero tree-node allocations); adding a 1-line stale check if (dis > dist[node]) continue; makes priority_queue noticeably faster in C++ contests while keeping the same $\mathcal{O}(E \log V)$ asymptotic bound!

    4. When Dijkstra Fails & $\mathcal{O}(E \log V)$ Complexity Proof

    Why Dijkstra Fails on Negative Edge Weights (Page 2)

    Suppose an undirected graph has a single negative edge $0 \leftrightarrow 1$ of weight $-2$. Starting with dist[0] = 0:

    • Pop (0, 0) $\implies$ dist[1] = -2, push (-2, 1).
    • Pop (-2, 1) $\implies$ dist[0] = -4 < 0, push (-4, 0).
    • Pop (-4, 0) $\implies$ dist[1] = -6 < -2, push (-6, 1) $\dots$ infinite loop!

    Even in a directed graph with no negative cycles (e.g., $0 \xrightarrow{2} 1$, $0 \xrightarrow{5} 2$, $2 \xrightarrow{-4} 1$), popping $1$ at distance $2$ prematurely assumes $1$ is settled before $0 \to 2 \to 1$ (cost $5 - 4 = 1$) is discovered. Whenever negative edges can exist, switch to Bellman–Ford.

    Why Is Time Complexity $\mathcal{O}(E \log V)$ (and Not $\mathcal{O}(E \log E)$)?

    Each directed edge $(u, v)$ is examined once when $u$ is settled (thanks to if (dis > dist[node]) continue;), so at most $E$ pairs are ever pushed into the binary heap. Although the heap may hold up to $E$ stale pairs, in any simple graph $E \le V^2$, which means:

    $$\mathcal{O}(E \log E) \;\le\; \mathcal{O}(E \log V^2) \;=\; \mathcal{O}(2 E \log V) \;=\; \mathcal{O}(E \log V)$$ 
    #include <bits/stdc++.h>
using namespace std;

// Standard Min-Heap Dijkstra (Striver G-32, upgraded with stale-entry guard)
vector<int> dijkstra(int V, const vector<vector<pair<int, int>>>& adj, int S) {
    using P = pair<int, int>; // {distance, node}
    priority_queue<P, vector<P>, greater<P>> pq;

    const int INF = 1e9;
    vector<int> dist(V, INF);
    dist[S] = 0;
    pq.push({0, S});

    while (!pq.empty()) {
        auto [dis, node] = pq.top();
        pq.pop();

        // Lazy deletion: ignore outdated heap entries
        if (dis > dist[node]) continue;

        for (auto [adjNode, edgeWeight] : adj[node]) {
            if (dis + edgeWeight < dist[adjNode]) {
                dist[adjNode] = dis + edgeWeight;
                pq.push({dist[adjNode], adjNode});
            }
        }
    }
    return dist;
}

    5. LeetCode 1976: Number of Ways to Arrive at Destination

    Problem Summary (LeetCode 1976)

    You are given $n$ intersections ($0$ to $n - 1$) connected by bidirectional roads roads[i] = [u, v, time] with strictly positive travel times ($1 \le \text{time} \le 10^9$, $1 \le n \le 200$). Return the number of distinct ways to travel from intersection $0$ to intersection $n - 1$ in the shortest amount of time, modulo $10^9 + 7$.

    How ways[] Works Inside Dijkstra

    Because every road has $\text{time} \ge 1$, every shortest path satisfies $\text{dist}[u] \lt \text{dist}[v]$ across every edge $u \to v$ it traverses. That means the subgraph of shortest-path edges is a Directed Acyclic Graph (DAG), and popping vertices from Dijkstra's min-heap processes them in valid topological order!

    We maintain two arrays initialized at the source: dist[0] = 0 (all others LLONG_MAX) and ways[0] = 1 (all others 0). When relaxing edge $(u, v, w)$ from a settled vertex $u$:

    1. Case 1 — Strictly faster path discovered (dis + w < dist[v]):
      Every previously counted path to $v$ was suboptimal and must be discarded! Update dist[v] = dis + w, reset ways[v] = ways[u], and push {dist[v], v} into pq.
    2. Case 2 — Tie with the current shortest distance (dis + w == dist[v]):
      All ways[u] shortest paths to $u$ extend into brand-new shortest paths to $v$! Accumulate ways[v] = (ways[v] + ways[u]) % MOD, and do NOT push v to pq again — v is already queued with dist[v], so when v finally pops, it will propagate the combined ways[v] once!

    Two Classic WA / TLE Bugs on LeetCode 1976

    • Overflowing 32-bit int for dist[]: With $n = 200$ and $\text{time} = 10^9$, a simple chain has shortest time $199 \times 10^9 \approx 2 \times 10^{11} \gt 2^{31} - 1$. Always declare dist and the min-heap distance as long long with LLONG_MAX!
    • Pushing to pq on dis + w == dist[v]: Re-pushing $v$ on every tie causes $v$ to pop multiple times with the exact same distance, double-counting downstream paths and triggering TLE/WA.

    Complete C++ & Python Solutions (LeetCode 1976)

    #include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int countPaths(int n, vector<vector<int>>& roads) {
        const long long MOD = 1'000'000'007LL;
        vector<vector<pair<int, long long>>> adj(n);
        for (const auto& r : roads) {
            adj[r[0]].push_back({r[1], r[2]});
            adj[r[1]].push_back({r[0], r[2]});
        }

        using State = pair<long long, int>; // {dist, node}
        priority_queue<State, vector<State>, greater<State>> pq;

        vector<long long> dist(n, LLONG_MAX);
        vector<long long> ways(n, 0);

        dist[0] = 0;
        ways[0] = 1;
        pq.push({0, 0});

        while (!pq.empty()) {
            auto [dis, u] = pq.top();
            pq.pop();

            if (dis > dist[u]) continue;

            for (auto [v, wt] : adj[u]) {
                if (dis + wt < dist[v]) {
                    dist[v] = dis + wt;
                    ways[v] = ways[u];
                    pq.push({dist[v], v});
                } else if (dis + wt == dist[v]) {
                    ways[v] = (ways[v] + ways[u]) % MOD;
                }
            }
        }
        return static_cast<int>(ways[n - 1] % MOD);
    }
};
    import heapq
import math

class Solution:
    def countPaths(self, n: int, roads: list[list[int]]) -> int:
        MOD = 10**9 + 7
        adj = [[] for _ in range(n)]
        for u, v, w in roads:
            adj[u].append((v, w))
            adj[v].append((u, w))

        dist = [math.inf] * n
        ways = [0] * n
        dist[0] = 0
        ways[0] = 1

        pq = [(0, 0)]  # (distance, node)
        while pq:
            dis, u = heapq.heappop(pq)
            if dis > dist[u]:
                continue
            for v, wt in adj[u]:
                cand = dis + wt
                if cand < dist[v]:
                    dist[v] = cand
                    ways[v] = ways[u]
                    heapq.heappush(pq, (cand, v))
                elif cand == dist[v]:
                    ways[v] = (ways[v] + ways[u]) % MOD

        return ways[n - 1] % MOD
