    Bellman–Ford & Floyd–Warshall: Negative Weights, Cycle Detection & All-Pairs DP

    October 2026 · 11 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (04_G_41_striver_bellmanford.pdf & 05_G_42_Floyd_Warshall.pdf)

    As soon as a graph contains negative edge weights, Dijkstra's greedy assumption collapses. Two dynamic-programming algorithms take over depending on whether you need distances from a single source (Bellman–Ford in $\mathcal{O}(V \cdot E)$) or across every pair of vertices (Floyd–Warshall in $\mathcal{O}(V^3)$) — and both cleanly detect negative-weight cycles.

    1. Bellman–Ford Algorithm (Striver G-41)

    Core Philosophy of Bellman–Ford

    Given a directed graph with $V$ vertices, $E$ edges $(u, v, \text{wt})$ in any arbitrary order, and a source vertex $S$:

    1. Initialize dist[S] = 0 and dist[i] = ∞ for all $i \neq S$.
    2. Relax every edge sequentially for exactly $V - 1$ iterations: $$\text{if } \text{dist}[u] \neq \infty \text{ and } \text{dist}[u] + \text{wt} \lt \text{dist}[v] \;\implies\; \text{dist}[v] = \text{dist}[u] + \text{wt}$$
    3. Run one extra ($V$-th) pass over all edges: if any distance still decreases, a negative cycle reachable from $S$ exists!

    Directed vs. Undirected Graphs (Page 1): Bellman–Ford is defined on directed edges. If you are given an undirected edge $1 \leftrightarrow 2$ of non-negative weight $5$, replace it with two directed edges $1 \xrightarrow{5} 2$ and $2 \xrightarrow{5} 1$. (Remember: if an undirected edge has weight $w \lt 0$, traversing $1 \to 2 \to 1$ immediately creates a negative cycle of weight $2w \lt 0$!)

    Worked Trace on the 6-Vertex Signed Graph (Page 1)

    Let us trace the exact 6-node directed graph ($V = 6$, source $S = 0$) and scrambled edge list from page 1 of 04_G_41_striver_bellmanford.pdf:

    Scanning the edges in the exact arbitrary order written in the notes — (3,2,6), (5,3,1), (0,1,5), (1,5,-3), (1,2,-2), (3,4,-2), (2,4,3):

    Iteration Edges That Successfully Relax dist[0..5] After Pass
    Init—[0, ∞, ∞, ∞, ∞, ∞]
    Pass 1(0,1,5)→5, (1,5,-3)→2, (1,2,-2)→3, (2,4,3)→6[0, 5, 3, ∞, 6, 2]
    Pass 2(5,3,1)→3, then later in same pass (3,4,-2)→1[0, 5, 3, 3, 1, 2]
    Passes 3–5No further decreases ($V - 1 = 5$ passes complete)[0, 5, 3, 3, 1, 2]

    Why Must We Run Exactly $V - 1$ Iterations? (Adversarial Chain Proof)

    Why might $2$ passes not be enough on a general $V$-node graph? Page 2 constructs the clean worst-case counterexample: a 5-vertex chain ($V = 5$)

    $$0 \xrightarrow{1} 1 \xrightarrow{1} 2 \xrightarrow{1} 3 \xrightarrow{1} 4$$

    whose edges are supplied in reverse order: (3,4,1), (2,3,1), (1,2,1), (0,1,1).

    Initial: dist = [0, ∞, ∞, ∞, ∞]
    Iteration 1: First 3 edges see ∞ + 1; only (0,1,1) relaxes at the very end $\implies$ [0, 1, ∞, ∞, ∞]
    Iteration 2: Only (1,2,1) has a finite source during its turn $\implies$ [0, 1, 2, ∞, ∞]
    Iteration 3: Only (2,3,1) relaxes $\implies$ [0, 1, 2, 3, ∞]
    Iteration 4 ($V - 1$): Finally (3,4,1) relaxes $\implies$ [0, 1, 2, 3, 4]
    Inductive Invariant After Pass $k$ In any graph without negative cycles, every simple shortest path visits at most $V$ distinct vertices and therefore traverses at most $V - 1$ edges. Regardless of edge ordering, pass $k$ guarantees that every shortest path containing $\le k$ edges has reached its final optimal distance. Thus $V - 1$ passes are both necessary (on reverse chains) and sufficient (for all $V$-node graphs without negative cycles)!

    C++ Implementation with $V$-th Pass Negative-Cycle Detection

    #include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    // Returns shortest distances from S, or {-1} if a negative cycle is reachable from S
    vector<int> bellman_ford(int V, vector<vector<int>>& edges, int S) {
        const int INF = 1e8;
        vector<int> dist(V, INF);
        dist[S] = 0;

        // Relax all edges sequentially V - 1 times
        for (int i = 0; i < V - 1; i++) {
            bool changed = false;
            for (const auto& it : edges) {
                int u = it[0], v = it[1], wt = it[2];
                if (dist[u] != INF && dist[u] + wt < dist[v]) {
                    dist[v] = dist[u] + wt;
                    changed = true;
                }
            }
            if (!changed) break; // early exit if already converged
        }

        // V-th relaxation pass: any further improvement proves a negative cycle!
        for (const auto& it : edges) {
            int u = it[0], v = it[1], wt = it[2];
            if (dist[u] != INF && dist[u] + wt < dist[v]) {
                return {-1};
            }
        }
        return dist;
    }
};
    • Time Complexity: $\mathcal{O}(V \cdot E)$ — $(V - 1)$ outer passes $\times E$ edges per pass, plus one $E$-edge check.
    • Space Complexity: $\mathcal{O}(V)$ for the dist array.

    2. Floyd–Warshall Algorithm (Striver G-42)

    Whereas Dijkstra and Bellman–Ford start from a single source, Floyd–Warshall is a multi-source (all-pairs) shortest path algorithm: it computes the shortest distance $\text{cost}[i][j]$ between every ordered pair $(i, j) \in V \times V$ simultaneously using an adjacency/cost matrix.

    Thought Process: "Go Via Every Intermediate Vertex"

    Consider the 5-node example on page 1 of 05_G_42_Floyd_Warshall.pdf, where we want the shortest path from $0$ to $1$. Instead of trusting the direct edge $0 \xrightarrow{6} 1$, we test routing through every intermediate candidate $\text{via} \in \{0, \dots, V - 1\}$:

    Direct $0 \to 1$: $\text{cost} = 6$
    Via $2$: $d[0][2] + d[2][1] = 2 + 3 = 5$
    Via $3$: $d[0][3] + d[3][1] = 4 + 1 = 5$
    Via $4$ (where $d[0][4] = 3$ via $2$): $d[0][4] + d[4][1] = 3 + 1 = \mathbf{4}$  ← shortest!

    Floyd–Warshall Dynamic Programming State & Transition

    Let $dp^{(k)}[i][j]$ be the length of the shortest path from $i$ to $j$ whose intermediate vertices are restricted to $\{0, 1, \dots, k - 1\}$. When we unlock vertex $\text{via} = k$, either the shortest path avoids $k$ or visits $k$ once:

    $$\text{cost}[i][j] \;=\; \min\!\Big(\text{cost}[i][j],\; \text{cost}[i][\text{via}] + \text{cost}[\text{via}][j]\Big)$$

    Base matrix initialization: $\text{cost}[i][i] = 0$, $\text{cost}[u][v] = w(u, v)$ if edge $(u, v)$ exists, and $\infty$ otherwise.

    Two Critical Implementation Traps in Floyd–Warshall

    1. Putting via ($k$) inside i, j instead of outermost: Writing for i: for j: for via: only tests 2-hop paths $i \to \text{via} \to j$ and misses multi-hop chains like $0 \to 2 \to 4 \to 1$! The via loop must be the outermost loop so $dp^{(k)}$ builds inductively on $dp^{(k-1)}$.
    2. Adding negative weights to INF without a guard: If $i$ cannot reach $k$ (cost[i][k] == 1e9) and edge $(k, j)$ has weight $-5$, computing min(1e9, 1e9 - 5) turns an unreachable pair into 999999995! Always guard with if (cost[i][k] < INF && cost[k][j] < INF) when negative edges can appear.

    How Floyd–Warshall Detects Negative Cycles (Page 2)

    In any graph free of negative cycles, the cheapest walk from any vertex $a$ back to itself is the empty 0-edge walk of cost $\text{cost}[a][a] = 0$. Now consider the 3-vertex cycle on page 2: $a \xrightarrow{-1} b \xrightarrow{-2} c \xrightarrow{+1} a$.

    • Going around $a \to b \to c \to a$ has total weight $(-1) + (-2) + 1 = -2 \lt 0$.
    • During the DP, once intermediate vertices $b$ and $c$ are unlocked, $\text{cost}[a][a]$ updates to $\min(0,\, \text{cost}[a][c] + \text{cost}[c][a]) = -2 \lt 0$!

    Therefore, after all $V$ phases finish, checking if (cost[i][i] < 0) for any $i \in [0, V - 1]$ immediately detects whether the graph contains any negative-weight cycle (even in components disconnected from node $0$!).

    Complete C++ Implementation (Striver G-42)

    #include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    // Modifies matrix in-place (-1 denotes no edge on input & output, per GFG G-42)
    // Returns false if a negative-weight cycle exists, true otherwise.
    bool shortest_distance(vector<vector<int>>& matrix) {
        int n = static_cast<int>(matrix.size());
        const int INF = 1e9;

        // 1. Initialize cost matrix
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (matrix[i][j] == -1) matrix[i][j] = INF;
                if (i == j) matrix[i][j] = 0;
            }
        }

        // 2. Relax via every intermediate vertex k (MUST be outermost loop!)
        for (int via = 0; via < n; via++) {
            for (int i = 0; i < n; i++) {
                if (matrix[i][via] == INF) continue;
                for (int j = 0; j < n; j++) {
                    if (matrix[via][j] == INF) continue;
                    matrix[i][j] = min(matrix[i][j], matrix[i][via] + matrix[via][j]);
                }
            }
        }

        // 3. Diagonal check for negative cycles
        for (int i = 0; i < n; i++) {
            if (matrix[i][i] < 0) {
                return false; // negative cycle detected!
            }
        }

        // 4. Restore -1 sentinel for unreachable pairs
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (matrix[i][j] == INF) matrix[i][j] = -1;
            }
        }
        return true;
    }
};
    • Time Complexity: $\mathcal{O}(V^3)$ — three nested loops of size $V$ ($V \le 450$ comfortably passes a 1-second contest limit).
    • Space Complexity: $\mathcal{O}(V^2)$ for the cost matrix ($\mathcal{O}(1)$ extra beyond the matrix itself).
    When Should You Run $V \times$ Dijkstra Instead of Floyd–Warshall? If your graph has no negative weights ($w \ge 0$) and is sparse ($E \approx V$), running Min-Heap Dijkstra from each of the $V$ vertices takes $\mathcal{O}(V \cdot E \log V)$, which beats $\mathcal{O}(V^3)$ whenever $E \ll V^2 / \log V$ (for example, $V = 2000, E = 5000$). Reserve Floyd–Warshall for $V \le 450$, dense matrices, or all-pairs graphs with negative edges!
