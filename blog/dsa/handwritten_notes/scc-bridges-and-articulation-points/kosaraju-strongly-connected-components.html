    Kosaraju's Algorithm: Strongly Connected Components in Directed Graphs

    October 2026 · 10 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 02_Directed_graph_Kosaraju_s.pdf

    In an undirected graph, connectivity is symmetric: if $u$ reaches $v$, $v$ automatically reaches $u$. In a directed graph, one-way edges break symmetry — $u \leadsto v$ says nothing about whether $v$ can get back to $u$. Partitioning a directed graph into maximal mutually-reachable clusters gives its Strongly Connected Components (SCCs), and Kosaraju's algorithm finds all of them in a remarkably clean 3-step $\mathcal{O}(V + E)$ pipeline.

    1. Problem Statement & What Is an SCC?

    Definition: Strongly Connected Component (SCC)

    Strongly Connected Components are valid strictly for directed graphs (highlighted with a star on Page 1). A maximal vertex subset $C \subseteq V$ is an SCC if for every pair of vertices $u, v \in C$, there exists a directed path $u \leadsto v$ and a directed path $v \leadsto u$.

    Note: Every single vertex $x$ reaches itself in $0$ edges ($x \leadsto x$), so a vertex that participates in no directed cycle (such as vertex 3 or vertex 7 below) forms a valid 1-vertex SCC $\{x\}$ on its own.

    2. Brute Force $\to$ Condensation Intuition $\to$ Optimal Kosaraju

    • Brute Force — All-Pairs Reachability ($\mathcal{O}(V \cdot (V + E))$): Run a full DFS from every vertex $u \in \{0, \dots, V-1\}$ to record an $N \times N$ reachability matrix $\text{reach}[u][v]$, then group $u, v$ together iff $\text{reach}[u][v] \land \text{reach}[v][u]$. This requires $V$ separate graph traversals and $\mathcal{O}(V^2)$ space or pairwise checks — infeasible for $V = 10^5$.
    • Condensation DAG Insight: If we contract each SCC in our example into a single supernode, the graph simplifies to the acyclic chain: $$\text{SCC}_1 \;(\{0,1,2\}) \;\longrightarrow\; \text{SCC}_2 \;(\{3\}) \;\longrightarrow\; \text{SCC}_3 \;(\{4,5,6\}) \;\longrightarrow\; \text{SCC}_4 \;(\{7\})$$ In general, collapsing every SCC of any directed graph always yields a Directed Acyclic Graph (Condensation DAG) — because if two supernodes had a cycle between them, all of their vertices would be mutually reachable and would have merged into one larger SCC!

    Now follow the exact thought experiment from Pages 1–2 of the notes:

    1. Why plain DFS fails: Starting a DFS at vertex $0$ visits $\{0, 1, 2\}$, then leaks across $2 \to 3$, then $3 \to 4 \to 5 \to 6 \to 7$, sweeping all $8$ nodes in one connected tree without telling us where $\text{SCC}_1$ ended and $\text{SCC}_2$ began.
    2. What happens when we reverse every edge ($G \to G^T$)?
      • Inside each SCC, nothing breaks! As sketched at the bottom-right of Page 1 ($u \leftrightarrows v \equiv v \leftrightarrows u$), reversing $0 \to 1 \to 2 \to 0$ gives $0 \leftarrow 1 \leftarrow 2 \leftarrow 0$, which is still a directed cycle over $\{0, 1, 2\}$. Every SCC of $G$ remains the exact same SCC in $G^T$.
      • Between SCCs, every one-way bridge flips backward: $\text{SCC}_1 \longleftarrow \text{SCC}_2 \longleftarrow \text{SCC}_3 \longleftarrow \text{SCC}_4$.
    3. Isolating components one by one: If we now start a DFS from $0 \in \text{SCC}_1$ on the reversed graph $G^T$, it visits $\{0, 2, 1\}$ and hits a wall because $2 \leftarrow 3$ points inward! Next, starting from $3 \in \text{SCC}_2$, the reversed edge $3 \to 2$ leads into already-visited $\text{SCC}_1$, so $3$ stops immediately! Each DFS call peels off one exact, isolated SCC.

    3. Why Sorting by Finish Time Finds the Right Order

    There is one crucial catch: isolation on $G^T$ only works if we start DFS in $\text{SCC}_1$ before $\text{SCC}_2$ before $\text{SCC}_3$ before $\text{SCC}_4$! (If we mistakenly started on $G^T$ from vertex $7 \in \text{SCC}_4$, reversed edges $7 \to 4 \to 3 \to 2 \to 0$ would spill across the whole graph again!) Since we don't know the SCCs ahead of time, how do we guarantee starting in $\text{SCC}_1$?

    Finish-Time Ordering Theorem

    Run a standard DFS across $G$ (from arbitrary starting vertices) and push each vertex onto a stack at the moment its DFS finishes (post-order backtrack). If there is a directed edge $\text{SCC}_A \to \text{SCC}_B$ in $G$, then:

    $$\max_{u \in \text{SCC}_A} \text{finish}[u] \;\gt\; \max_{v \in \text{SCC}_B} \text{finish}[v]$$
    • Case 1 ($\text{SCC}_A$ entered before $\text{SCC}_B$): Let $a \in \text{SCC}_A$ be the first vertex entered. Every vertex in $\text{SCC}_B$ is reachable from $a$, so all of $\text{SCC}_B$ becomes a descendant of $a$ and must finish before $a$ backtracks!
    • Case 2 ($\text{SCC}_B$ entered before $\text{SCC}_A$): Because the Condensation DAG has no path $\text{SCC}_B \leadsto \text{SCC}_A$, the DFS inside $\text{SCC}_B$ cannot reach $\text{SCC}_A$ at all — so every vertex in $\text{SCC}_B$ finishes completely before any vertex in $\text{SCC}_A$ is even discovered!

    Consequently, the vertex at the very top of the finish-time stack (last to finish) is guaranteed to belong to a source SCC of $G$ (which is a sink SCC of $G^T$), and the first vertex to finish at the bottom of the stack lies in a sink SCC of $G$!

    4. Complete 3-Step Trace on the 8-Vertex Graph (Pages 2–3)

    Step 1 — Sort Nodes by Finish Time via DFS on $G$ (starting at 0):
    DFS(0) → DFS(1) → DFS(2) → DFS(3) → DFS(4):
    • Branch 4 → 7: 7 has no outgoing edges $\implies$ 7 is the 1st guy to finish/backtrack (pushed to bottom of stack; lies in the last SCC).
    • Branch 4 → 5 → 6: neighbors 4 (visited) and 7 (visited) $\implies$ 6 finishes, then 5, then 4, then 3, then 2, then 1, and 0 finishes last (top of stack; lies in the first SCC)!

    5. Complete 3-Step $\mathcal{O}(V + E)$ C++ Implementation

    #include <bits/stdc++.h>
using namespace std;

class Solution {
private:
    void dfsFinishOrder(int node, const vector<vector<int>>& adj,
                        vector<int>& vis, stack<int>& st) {
        vis[node] = 1;
        for (int it : adj[node]) {
            if (!vis[it]) {
                dfsFinishOrder(it, adj, vis, st);
            }
        }
        st.push(node); // push AFTER all descendants finish
    }

    void dfsReversed(int node, const vector<vector<int>>& adjT,
                     vector<int>& vis, vector<int>& component) {
        vis[node] = 1;
        component.push_back(node);
        for (int it : adjT[node]) {
            if (!vis[it]) {
                dfsReversed(it, adjT, vis, component);
            }
        }
    }

public:
    // Returns all Strongly Connected Components in topological order of the Condensation DAG
    vector<vector<int>> kosarajuSCC(int V, const vector<vector<int>>& adj) {
        // Step 1: Order vertices by decreasing finish time
        vector<int> vis(V, 0);
        stack<int> st;
        for (int i = 0; i < V; i++) {
            if (!vis[i]) {
                dfsFinishOrder(i, adj, vis, st);
            }
        }

        // Step 2: Build transposed graph adjT (reverse every directed edge u -> v to v -> u)
        vector<vector<int>> adjT(V);
        for (int u = 0; u < V; u++) {
            vis[u] = 0; // reset visited array for Step 3
            for (int v : adj[u]) {
                adjT[v].push_back(u);
            }
        }

        // Step 3: Pop stack and run DFS on adjT; each tree is one isolated SCC
        vector<vector<int>> sccs;
        while (!st.empty()) {
            int node = st.top();
            st.pop();
            if (!vis[node]) {
                vector<int> component;
                dfsReversed(node, adjT, vis, component);
                sccs.push_back(move(component));
            }
        }
        return sccs;
    }
};

    6. Time & Space Complexity Proof & Edge Cases

    • Time Complexity — $\mathcal{O}(V + E)$:
      • Step 1 Finish-Time DFS visits each vertex and directed edge once: $\mathcal{O}(V + E)$.
      • Step 2 Graph Reversal scans every adjacency list entry once: $\mathcal{O}(V + E)$.
      • Step 3 Reversed DFS pops $V$ items and traverses each reversed edge once: $\mathcal{O}(V + E)$.
      • Total: $3 \cdot \mathcal{O}(V + E) = \mathcal{O}(V + E)$.
    • Space Complexity — $\mathcal{O}(V + E)$: $\mathcal{O}(V + E)$ for the transposed adjacency list adjT + $\mathcal{O}(2V)$ for vis[] and finish-time stack + $\mathcal{O}(V)$ recursion stack.
    • Key Edge Cases:
      • Why Discovery Time Fails (Must Use Finish Time!): If Step 1 started at vertex 3 instead of 0, 3 would be discovered before 0, yet on $G^T$ starting at 3 before 0 would cross $3 \to 2 \to 1 \to 0$ and falsely merge $\{3\}$ with $\{0,1,2\}$! Finish time handles this automatically: starting at 3 finishes 3, 4, 5, 6, 7 first, and the subsequent outer loop call on 0 finishes 0 after 3, placing 0 above 3 on the stack!
      • Disconnected Directed Graphs: Always wrap Step 1 in for (int i = 0; i < V; i++) if (!vis[i]) so unreachable source components are never missed.
      • Bonus Topological Order Property: Kosaraju naturally outputs the SCCs in valid topological order of the Condensation DAG ($\text{SCC}_1, \text{SCC}_2, \text{SCC}_3, \text{SCC}_4$), ready for DAG DP or 2-SAT assignment!
