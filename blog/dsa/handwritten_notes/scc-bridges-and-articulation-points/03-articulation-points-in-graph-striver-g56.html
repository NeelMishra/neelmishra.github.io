    Articulation Points (Cut-Vertices) in an Undirected Graph (Striver G-56)

    October 2026 · 13 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 03_G_56_Articulation_point.pdf

    While a bridge is a single critical edge whose failure disconnects a network, an articulation point (or cut-vertex) is a single critical router/node whose removal — along with every cable plugged into it — splits its connected component into two or more disconnected pieces. Adapting Tarjan's tin[]/low[] DFS from edges to vertices requires three surgical modifications, including one of the most famous traps in competitive graph algorithms: why a visited back-edge must take tin[it] instead of low[it].

    1. Problem Statement & 7-Vertex Example (Page 1)

    Definition: Articulation Point (Cut-Vertex)

    In an undirected graph $G = (V, E)$, a vertex $u \in V$ is an articulation point if removing $u$ (and all edges incident to $u$) strictly increases the number of connected components in the remaining graph $G \setminus \{u\}$.

    Goal: Return all articulation points in sorted ascending order, or {-1} if none exist.

    On Page 1 of 03_G_56_Articulation_point.pdf, we examine a 7-vertex graph (0..6) consisting of:

    • Vertex 0 attached to a degree-1 leaf 1 and an upper triangle 0–2–3–0.
    • A lower 4-cycle diamond 2–4–6–5–2 hanging exclusively off vertex 2.

    Removing 0 isolates leaf {1} from {2, 3, 4, 5, 6}; removing 2 severs {0, 1, 3} from the lower diamond {4, 5, 6}. Removing any of 1, 3, 4, 5, 6 leaves the remaining 6 vertices in a single connected piece. Thus only {0, 2} are articulation points.

    2. Brute Force $\to$ Optimal Single-Pass Tarjan DFS

    • Brute Force — Delete Each Vertex & Re-run DFS ($\mathcal{O}(V \cdot (V + E))$): For every candidate vertex $v \in \{0, \dots, V-1\}$, pre-mark vis[v] = 1 to simulate deleting $v$ and its incident edges, then count how many DFS calls are needed to visit the remaining vertices in $v$'s original component. If that count exceeds $1$, $v$ is an articulation point. At $V, E = 10^5$, $\mathcal{O}(V(V + E))$ reaches $2 \times 10^{10}$ operations and TLEs.
    • Optimal — Tarjan's Modified tin[]/low[] Pass ($\mathcal{O}(V + 2E)$): Compute all cut-vertices in one DFS pass by tracking when a child's DFS subtree has no back-edge jumping strictly above node, while handling the DFS starting root via its unvisited DFS child count.

    3. The Three Surgical Changes from Bridges to Articulation Points

    Change 1: Strict > Becomes >= for Non-Root Nodes (Page 1)

    For a bridge $(\text{node}, \text{it})$, reaching node itself ($\text{low}[\text{it}] = \text{tin}[\text{node}]$) kept it connected because vertex node remained alive. For an articulation point, vertex node itself is deleted! Any backup path from it's subtree that lands on node hits a deleted vertex. To survive without node, it's subtree must reach an ancestor discovered strictly before node ($\text{low}[\text{it}] \lt \text{tin}[\text{node}]$). Negating that survival condition gives the cut-vertex test:

    Non-Root Articulation Point Condition

    A non-root vertex node ($\text{parent} \neq -1$) is an articulation point if and only if it has at least one newly-discovered DFS tree child it satisfying:

    $$\text{low}[\text{it}] \;\ge\; \text{tin}[\text{node}] \quad \text{and} \quad \text{parent} \neq -1$$

    Handwritten note annotation: $\text{low}[\text{it}] \ge \text{tin}[\text{node}]$ means it can only reach node or timestamps greater than node — never an ancestor above node!

    Change 2 (The Red-Ink Proof): Visited Back-Edges MUST Use tin[it], NEVER low[it]! (Pages 1–2)

    Pages 1 and 2 highlight a critical asymmetry between the two places where low[node] is updated:

    • Returning from an unvisited DFS tree child it: Use low[node] = min(low[node], low[it]) — because it lies inside node's subtree, so any back-edge out of it's subtree is also a valid escape route for node.
    • Inspecting an already-visited non-parent neighbor it (a back-edge): Use low[node] = min(low[node], tin[it]) — NEVER low[it]!

    Change 3: Starting Root Rule (parent == -1 && child > 1) & mark[] Deduplication (Page 3)

    Why must we skip low[it] >= tin[node] when parent == -1? Because the starting vertex of a component has the smallest tin of all ($\text{tin}[\text{root}] = 0$ or $1$), so $\text{low}[\text{it}] \ge \text{tin}[\text{root}]$ is trivially true for every root — even when the root has only 1 edge!

    • Why child++ counts unvisited DFS calls, not adj[root].size(): Because undirected DFS has no cross-edges, if root's first DFS call dfs(v1) finishes without visiting neighbor v2, there is zero path between v1 and v2 outside root! Deleting root is guaranteed to separate v1 from v2.
    • Avoiding Duplicate Entries with mark[] (Page 3): A single hub vertex can have $3$ or $4$ disconnected subtrees hanging below it, triggering low[it] >= tin[node] multiple times. Marking mark[node] = 1 in a size-$N$ hash/boolean array deduplicates and automatically produces sorted output when scanned from $0 \to N - 1$.

    4. Complete Step-by-Step Dry Run on the 7-Vertex Graph (Pages 1–2)

    1. Start at Root 0 (tin=1, low=1, parent=-1):
      • Branch #1 (child = 1) — 0 → 1: Node 1 gets 2/2, sees only parent = 0, and returns to 0. Do we apply low[1] >= tin[0]? No! parent == -1 skips the formula.
      • Branch #2 (child = 2) — 0 → 2: Node 2 is still unvisited, so 0 increments child = 2 and enters 2 (3/3).
    2. Upper Triangle 2 → 3 → 0 (Page 1 bottom & Page 2 top):
      • 2 enters unvisited 3 (4/4). At 3, neighbor 2 is parent (ignored), while neighbor 0 is already visited $\implies$ low[3] = min(4, tin[0]) = min(4, 1) = 1 (4/1).
      • Returning from DFS(3) to 2: coming back from an unvisited child uses low[3], so low[2] = min(3, low[3]) = 1 (3/1).
      • Check AP condition at 2 for child 3: $\text{low}[3] \ge \text{tin}[2] \implies 1 \ge 3$ (False — 3 reaches 0 directly, so 2 is not yet marked).
    3. Lower Diamond 2 → 4 → 6 → 5 → 2 (Page 2 middle & bottom):
      • 2 (3/1) next explores unvisited child 4 (5/5) → 6 (6/6) → 5 (7/7).
      • At 5: neighbor 6 is parent; neighbor 2 is already visited! Using tin[2] = 3 (and NOT low[2] = 1!) sets low[5] = min(7, 3) = 3 (7/3).
      • Unwinding 5 → 6 sets low[6] = min(6, low[5]) = 3 (6/3); check at 6: $\text{low}[5] = 3 \ge \text{tin}[6] = 6$ (False).
      • Unwinding 6 → 4 sets low[4] = min(5, low[6]) = 3 (5/3); check at 4: $\text{low}[6] = 3 \ge \text{tin}[4] = 5$ (False).
      • Unwinding 4 → 2: low[2] = min(1, low[4]) = min(1, 3) = 1. Check AP condition at 2 for child 4: $$\text{low}[4] = 3 \;\ge\; \text{tin}[2] = 3 \quad \land \quad \text{parent}(0) \neq -1 \implies \mathbf{\text{mark}[2] = 1!}$$ (Remaining neighbor 5 of 2 is now already visited, updating low[2] = min(1, tin[5]) = 1.)
    4. Finish Root 0: Neighbor 3 of 0 is already visited (skipped from child count!). After the loop finishes at 0, check root rule: parent == -1 && child == 2 > 1 $\implies$ mark[0] = 1! Final answer: {0, 2}.

    5. Clean C++ Implementation (Pages 3–4)

    #include <bits/stdc++.h>
using namespace std;

class Solution {
private:
    int timer = 0;

    void dfs(int node, int parent, vector<int>& vis,
             vector<int>& tin, vector<int>& low,
             vector<int>& mark, vector<int> adj[]) {
        vis[node] = 1;
        tin[node] = low[node] = timer;
        timer++;
        int child = 0; // counts unvisited DFS tree branches from 'node'

        for (auto it : adj[node]) {
            if (it == parent) continue;
            if (!vis[it]) {
                dfs(it, node, vis, tin, low, mark, adj);
                low[node] = min(low[node], low[it]);

                // Non-root articulation point condition
                if (low[it] >= tin[node] && parent != -1) {
                    mark[node] = 1;
                }
                child++;
            } else {
                // Visited back-edge: MUST take tin[it], NEVER low[it]!
                low[node] = min(low[node], tin[it]);
            }
        }

        // Starting root articulation point condition
        if (child > 1 && parent == -1) {
            mark[node] = 1;
        }
    }

public:
    vector<int> articulationPoints(int n, vector<int> adj[]) {
        vector<int> vis(n, 0), tin(n, 0), low(n, 0), mark(n, 0);

        for (int i = 0; i < n; i++) {
            if (!vis[i]) {
                dfs(i, -1, vis, tin, low, mark, adj);
            }
        }

        vector<int> ans;
        for (int i = 0; i < n; i++) {
            if (mark[i] == 1) {
                ans.push_back(i);
            }
        }
        if (ans.size() == 0) return {-1};
        return ans;
    }
};

    6. Time & Space Complexity Proof (Page 4)

    • Time Complexity — $\mathcal{O}(V + 2E)$:
      • The DFS visits each of the $V$ vertices once and inspects all $2E$ undirected adjacency entries in $\mathcal{O}(V + 2E)$ time.
      • Collecting marked indices from mark[0..n-1] adds $\mathcal{O}(V)$. As written on Page 4: $\mathcal{O}(V + 2E) + \mathcal{O}(V) \cong \mathcal{O}(V + 2E)$.
    • Space Complexity — $\mathcal{O}(V)$ Auxiliary ($\mathcal{O}(3N)$ to $\mathcal{O}(4N)$):
      • Arrays vis[], tin[], low[], and mark[] each take $N$ integers ($\mathcal{O}(4N) = \mathcal{O}(V)$), plus $\mathcal{O}(V)$ worst-case recursion stack depth (the adjacency list adj[] is given as input).

    7. Key Edge Cases & Sanity Checks

    • Single-Edge 2-Node Graph (0 — 1): Edge 0–1 is a bridge, yet neither 0 nor 1 is an articulation point! Removing 0 leaves the 1-vertex graph {1}, which still has $1$ connected component (not $\ge 2$). Check our code: root 0 has child = 1 (not $\gt 1$), leaf 1 has $0$ children, and the function rightly returns {-1}!
    • Pure Cycle ($C_N$, $N \ge 3$): Removing any vertex turns the cycle into a connected path $P_{N-1}$, so zero articulation points exist $\implies$ returns {-1}.
    • Star Graph (Hub 0 Connected to $k \ge 2$ Leaves): Even if DFS starts at a leaf 1, 1 has child = 1 (not AP), while non-root 0 has $k - 1 \ge 1$ unvisited children satisfying $\text{low}[\text{leaf}] \ge \text{tin}[0]$, marking mark[0] = 1 once without duplicates!
    • Disconnected Graphs: Every connected component gets its own DFS root with parent = -1 via the outer for (int i = 0; i < n; i++) if (!vis[i]) loop.
