    Bridges in Graph: Rapid Revision, Bridge-Tree Intuition & Contest Edge Cases

    October 2026 · 10 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 04_Striver_bridges.pdf

    Written over a year after the original G-55 study notes as a compact 2026 recall sheet, 04_Striver_bridges.pdf distills Tarjan's bridge-finding algorithm down to its purest visual essence: red ovals around every non-cycle bottleneck edge and the two arrays (tin[] and low[]) that detect them in one $\mathcal{O}(V + 2E)$ DFS sweep. This post expands that single-page revision sheet into a complete pre-contest reference — connecting bridges to 2-Edge-Connected Components (Bridge Trees), contrasting every subtle invariant against Articulation Points, and hardening the C++ template for multigraph parallel edges.

    1. Concept Recap & The Bridge-Tree Decomposition

    Core Revision Definition (04_Striver_bridges.pdf)

    A bridge is an undirected edge whose removal disconnects its connected component into two separate components. To detect all bridges in one DFS pass, we maintain two size-$V$ arrays:

    • tin[u] (Time of Insertion): The DFS step counter stamped when vertex $u$ is first entered.
    • low[u] (Lowest Time of Insertion): The minimum insertion timestamp reachable from $u$ by considering only adjacent nodes apart from $u$'s direct DFS parent (propagating downward tree children's low[v] and upward back-edges' tin[v]).

    Notice what happens visually on the left side of the handwritten sheet when the three red-circled bridges — 4–5, 5–6, and 8–10 — are cut: the 12 vertices shatter into four cycle-protected islands: {1, 2, 3, 4}, {5}, {6, 7, 8, 9}, and {10, 11, 12}. Contracting each island into a supernode turns any connected undirected graph into an acyclic Bridge Tree (the undirected counterpart of Kosaraju's Condensation DAG!):

    2. Algorithmic Progression: Brute Force $\to$ Tree Prefix DP $\to$ Tarjan's tin[]/low[]

    Three Ways to Find All Bridges in an Undirected Graph
    Approach Core Mechanism Time Extra Space Why Upgrade?
    1. Brute Force Delete each edge $e \in E$ one by one and run DFS/BFS to test if $u$ still reaches $v$. $\mathcal{O}(E(V + E))$ $\mathcal{O}(V)$ TLE for $V, E \ge 10^4$.
    2. Back-Edge Span DP Build a DFS tree; for every back-edge $(u, \text{anc})$ add $+1$ at $u$ and $-1$ at $\text{anc}$. Tree edge $(p, u)$ is a bridge iff subtree sum $\text{dp}[u] == 0$. $\mathcal{O}(V + 2E)$ $\mathcal{O}(2V)$ Fast for bridges alone, but does not generalize cleanly to Articulation Points or Directed SCCs.
    3. Tarjan's tin[] & low[] Stamp arrival time tin[u] and propagate minimum reachable ancestor timestamp low[u]; test $\text{low}[v] \gt \text{tin}[u]$. $\mathcal{O}(V + 2E)$ $\mathcal{O}(3V)$ Universal template: powers Bridges, Articulation Points, Biconnected Components, and Tarjan SCCs!

    4. Pre-Contest Checklist: Why > vs. >= and tin[v] vs. low[v] Matter

    1. Strict low[v] > tin[u] (Bridges) vs. low[v] >= tin[u] (Articulation Points):
      • Look at row 11 (parent 10) in the table above: $\text{low}[11] = 10$ and $\text{tin}[10] = 10$.
      • Is edge 10–11 a bridge? No ($10 \not\gt 10$), because vertex 10 stays alive and 11 → 12 → 10 reconnects 11 to 10.
      • Is vertex 10 an articulation point? Yes ($10 \ge 10$ and $\text{parent}(8) \neq -1$), because deleting vertex 10 destroys both 10–11 and 12–10, marooning {11, 12}!
    2. Visited Back-Edge Update — Always Standardize on min(low[u], tin[v]):
      • In a simple undirected graph, writing min(low[u], low[v]) on a visited back-edge still gives the right answer for Bridges because $\text{low}[v] \le \text{tin}[v] \lt \text{tin}[u]$ cannot hide a true bridge nor invent a false one.
      • For Articulation Points, however, low[v] illegally tunnels through vertex $v$ into an upper cycle (as we proved on vertex 2 in G-56!). Writing low[u] = min(low[u], tin[v]) in both templates is 100% rigorous and prevents accidental copy-paste WA.
    3. Root Behavior (parent == -1):
      • Bridges: No special case at all — low[v] > tin[root] works identically for the root!
      • Articulation Points: Must bypass low[v] >= tin[root] and instead check unvisitedChildCount > 1.

    5. Contest-Hardened C++ & Python Implementation (Parallel-Edge Safe!)

    In competitive programming (Codeforces / AtCoder / CSES), undirected graphs frequently contain parallel multi-edges — two distinct edges connecting the same pair $(u, v)$. Naive if (v == parent) continue; skips both edges back to parent and falsely flags $(u, v)$ as a bridge! Passing the incoming edge ID parentEdgeId skips only the exact tree edge we arrived on, so any parallel twin edge properly updates low[u] = min(low[u], tin[v]):

    #include <bits/stdc++.h>
using namespace std;

struct BridgeFinder {
    int n, timer = 0;
    vector<vector<pair<int, int>>> adj; // {neighbor, edge_id}
    vector<int> vis, tin, low;
    vector<pair<int, int>> bridges;

    explicit BridgeFinder(int n) : n(n), adj(n), vis(n, 0), tin(n, 0), low(n, 0) {}

    void addEdge(int u, int v, int edgeId) {
        if (u == v) return; // self-loops can never be bridges
        adj[u].push_back({v, edgeId});
        adj[v].push_back({u, edgeId});
    }

    void dfs(int u, int parentEdgeId) {
        vis[u] = 1;
        tin[u] = low[u] = timer++;

        for (auto [v, id] : adj[u]) {
            if (id == parentEdgeId) continue; // skip ONLY the exact incoming tree edge
            if (!vis[v]) {
                dfs(v, id);
                low[u] = min(low[u], low[v]);
                if (low[v] > tin[u]) {
                    bridges.push_back({u, v});
                }
            } else {
                // Back-edge (or parallel edge to parent!) closes a cycle
                low[u] = min(low[u], tin[v]);
            }
        }
    }

    vector<pair<int, int>> findAllBridges() {
        for (int i = 0; i < n; i++) {
            if (!vis[i]) {
                dfs(i, -1);
            }
        }
        return bridges;
    }
};
    import sys
sys.setrecursionlimit(200_000)

def find_bridges_multigraph(n: int, edges: list[tuple[int, int]]) -> list[tuple[int, int]]:
    adj: list[list[tuple[int, int]]] = [[] for _ in range(n)]
    for eid, (u, v) in enumerate(edges):
        if u == v:
            continue
        adj[u].append((v, eid))
        adj[v].append((u, eid))

    vis = [False] * n
    tin = [0] * n
    low = [0] * n
    bridges: list[tuple[int, int]] = []
    timer = 0

    def dfs(u: int, parent_eid: int) -> None:
        nonlocal timer
        vis[u] = True
        tin[u] = low[u] = timer
        timer += 1

        for v, eid in adj[u]:
            if eid == parent_eid:
                continue
            if not vis[v]:
                dfs(v, eid)
                low[u] = min(low[u], low[v])
                if low[v] > tin[u]:
                    bridges.append((u, v))
            else:
                low[u] = min(low[u], tin[v])

    for i in range(n):
        if not vis[i]:
            dfs(i, -1)

    return bridges

    6. Complexity Proof & Edge-Case Summary

    • Time Complexity — $\mathcal{O}(V + 2E)$: Every vertex is entered once ($\mathcal{O}(V)$) and every undirected edge endpoint (v, id) is inspected once from each side ($\sum_{u \in V} \deg(u) = 2E$).
    • Space Complexity — $\mathcal{O}(V + 2E)$: $\mathcal{O}(V + 2E)$ for the adjacency list plus $\mathcal{O}(3V)$ for vis[], tin[], low[] and $\mathcal{O}(V)$ recursion stack.
    • Contest Edge Cases Handled Automatically:
      • Parallel Twin Edges $(u, v)$: First edge goes down the DFS tree (id_1); second parallel edge has id_2 != id_1 and sees vis[u] == 1, setting $\text{low}[v] = \text{tin}[u] \not\gt \text{tin}[u]$ — neither edge is reported as a bridge!
      • Self-Loops $(u, u)$: Removing a self-loop never disconnects two vertices; ignoring u == v (or letting it update $\text{low}[u] = \min(\text{low}[u], \text{tin}[u])$) leaves all bridges unaffected.
      • Disconnected Components & Isolated Nodes: Handled cleanly by the outer for (int i = 0; i < n; i++) if (!vis[i]) loop.
      • Minimum Edges Needed to Make a Connected Graph 2-Edge-Connected: Build the Bridge Tree above; if it has $L \ge 2$ degree-1 leaf components, adding $\lceil L / 2 \rceil$ edges eliminates every bridge in the network!
