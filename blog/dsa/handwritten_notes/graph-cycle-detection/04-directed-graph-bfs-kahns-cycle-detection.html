    Directed Graph Cycle Detection via BFS: Kahn's Algorithm & Indegree Starvation

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 04_Directed_graph_bfs_cycle_detection.pdf (Pages 1–2) · View original handwritten pages

    1. Problem Statement & The Topological Contrapositive

    In Directed DFS Cycle Detection, we relied on recursion to track ancestors via pathVis[]. How can Breadth-First Search—which is purely iterative and maintains no ancestor call stack—detect directed cycles?

    Kahn's Contrapositive Theorem (From 04_Directed_graph_bfs_cycle_detection.pdf)

    Recall Kahn's Topological Sort Algorithm: repeatedly peel off vertices with indegree == 0 and decrement their neighbors' indegrees. Because a linear topological ordering of all $N$ vertices exists if and only if the directed graph is a Directed Acyclic Graph (DAG):

    • $\text{poppedCount} == N \iff G$ is a valid DAG (no cycle).
    • $\text{poppedCount} < N \iff$ Kahn's queue starved early $\iff G$ contains a directed cycle!

    2. Why Cycles Starve the Queue + Complete 5-Node Dry Run

    Pages 1 and 2 trace the exact 5-vertex directed graph with edges $1 \to 2$, cycle $2 \to 3 \to 4 \to 2$, and outgoing tail $3 \to 5$:

    Step-by-step state table on Page 1's 5-node example ($N = 5$).
    Phase indegree[1..5] Queue $Q$ cnt Explanation
    1. Count indegrees [0, 2, 1, 1, 1] [] 0 Node 2 has two incoming arrows (1→2 and 4→2)
    2. Seed deg == 0 [0, 2, 1, 1, 1] [1] 0 Only vertex 1 has zero prerequisites
    3. Pop 1 [0, 1, 1, 1, 1] [] 1 --indegree[2] == 1 != 0 → nothing pushed!
    4. Termination [0, 1, 1, 1, 1] Empty 1 < 5 Early stop! return cnt != N → true (cyclic)

    3. Clean C++ Implementation (Zero-Vector Counter Optimization)

    When we only need a boolean cycle answer (not the topological array itself), we replace vector<int> topo with a single integer int cnt = 0;:

    // Directed Graph Cycle Detection via Kahn's BFS — C++
class Solution {
public:
    bool isCyclic(int V, const vector<vector<int>>& adj) {
        vector<int> indegree(V, 0);
        for (int u = 0; u < V; ++u) {
            for (int v : adj[u]) {
                indegree[v]++;
            }
        }

        queue<int> q;
        for (int i = 0; i < V; ++i) {
            if (indegree[i] == 0) {
                q.push(i);
            }
        }

        int cnt = 0;
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            cnt++;

            for (int v : adj[u]) {
                if (--indegree[v] == 0) {
                    q.push(v);
                }
            }
        }

        // Acyclic DAG iff cnt == V; stopped early (cnt < V) iff cycle exists!
        return cnt != V;
    }
};

    4. Complexity Proof, DFS vs. Kahn's Choice & Key Edge Cases

    • Time Complexity: $\mathcal{O}(V + E)$ — Computing indegree[] scans every vertex and directed edge once ($\mathcal{O}(V + E)$); each vertex enters $Q$ at most once when its indegree transitions $1 \to 0$, and its outgoing edges are decremented at most once ($\mathcal{O}(V + E)$).
    • Space Complexity: $\mathcal{O}(V)$ — indegree[V] plus queue $Q$ of size $\le V$ (zero call-stack recursion!).
    • When to Prefer Kahn's BFS Over pathVis DFS: On deep $10^5$-vertex DAG chains under tight contest stack limits, recursive DFS pushes $10^5$ OS call-stack frames and risks stack overflow; Kahn's BFS is 100% iterative out of the box and simultaneously produces a valid Course Schedule II (LC 210) ordering if acyclic!
    • Important Subtlety About Remaining Nodes (indegree[v] > 0): After Kahn's BFS stops, the unpopped set $\{v : \text{indegree}[v] > 0\}$ contains both actual cycle vertices (2, 3, 4) AND acyclic vertices downstream of cycles (5 in 3 → 5)! If a problem asks which vertices can reach a cycle (LC 802 Eventual Safe States), run Kahn's BFS on the reversed graph (outdegree == 0) instead!
    • Pure Cycle (0 → 1 → 2 → 0): Every vertex starts with indegree == 1, so $Q$ starts empty, the while loop runs $0$ times, and cnt (0) != 3 immediately returns true.
