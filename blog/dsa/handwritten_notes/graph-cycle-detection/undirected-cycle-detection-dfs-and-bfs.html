    Part 1: Undirected Graph Cycle Detection via DFS & BFS

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study notes (01_Undirected_DFS_cycle_detection.pdf & 02_Undirected_BFS_cycle_detection.pdf) · View original handwritten pages

    1. Why Undirected Graphs Require a parent Tracker

    In an undirected adjacency list, a single edge $1 - 2$ is stored symmetrically as $2 \in \text{adj}[1]$ and $1 \in \text{adj}[2]$. If we start at vertex $1$, mark $\text{vis}[1] = 1$, and step across to vertex $2$, scanning $\text{adj}[2] = \{1, 5\}$ immediately sees $\text{vis}[1] == 1$! Walking back across the exact edge we just arrived on ($2 \to 1$) is not a cycle.

    Undirected Cycle Invariant

    In a simple undirected graph (no parallel multi-edges or self-loops), a connected component contains a cycle if and only if during DFS or BFS from source $s$ (with parent = -1), some current vertex $u$ inspects an adjacent vertex $v \in \text{adj}[u]$ that is already visited (vis[v] == 1) AND is NOT the immediate parent of $u$ (v != parent).

    2. Method 1: Undirected Cycle Detection via DFS

    Following the 4 steps in 01_Undirected_DFS_cycle_detection.pdf:

    1. Iterate $i = 1 \dots V$ (or $0 \dots V-1$). Whenever visited[i] == 0, start dfs(i, -1) so disconnected components are never missed.
    2. On entering dfs(node, parent), immediately mark visited[node] = 1.
    3. For each adj in adjList[node]:
      • If !visited[adj]: recursively call dfs(adj, node); if it returns true, propagate true immediately.
      • Else if adj != parent: adj was already visited earlier in this component via a different route—return true (cycle detected!).
    4. If all neighbors finish without conflict, return false.

    DFS Call Trace on the 7-Vertex Graph

    dfs(1, -1) → dfs(2, 1) (skips parent 1) → dfs(5, 2) → dfs(7, 5) → dfs(6, 7) → dfs(3, 6).
    At node = 3 (with parent = 6), inspecting first neighbor adj = 1 finds visited[1] == 1 and 1 != 6 → returns true all the way up the call stack! 
    // Method 1: Undirected Graph Cycle Detection via DFS — C++
class Solution {
    bool dfs(int node, int parent, const vector<vector<int>>& adj, vector<int>& vis) {
        vis[node] = 1;

        for (int nbr : adj[node]) {
            if (!vis[nbr]) {
                if (dfs(nbr, node, adj, vis)) return true;
            } else if (nbr != parent) {
                // Visited neighbor that is NOT the node we came from -> cycle!
                return true;
            }
        }
        return false;
    }

public:
    bool isCycle(int V, const vector<vector<int>>& adj) {
        vector<int> vis(V, 0);
        for (int i = 0; i < V; ++i) {
            if (!vis[i]) {
                if (dfs(i, -1, adj, vis)) return true;
            }
        }
        return false;
    }
};

    3. Method 2: Undirected Cycle Detection via BFS

    In 02_Undirected_BFS_cycle_detection.pdf, we store pairs [node, parent] inside the FIFO queue $Q$, pushing [start, -1] for each unvisited component root. Whereas DFS walks all the way around the loop until hitting an ancestor, BFS expands two wavefronts simultaneously around both sides of the loop until they collide at the opposite end!

    BFS queue<{node, parent}> trace starting from [1, -1] on the 7-vertex graph.
    Popped [node, parent] Neighbors Checked Queue $Q$ After Step Visited Nodes
    Init Seed [1, -1] [(1, -1)] {1}
    (1, -1) Push 2 and 3 [(2, 1), (3, 1)] {1, 2, 3}
    (2, 1) Skip parent 1; push 5 [(3, 1), (5, 2)] {1, 2, 3, 5}
    (3, 1) Skip parent 1; push 4, 6 [(5, 2), (4, 3), (6, 3)] {1, 2, 3, 4, 5, 6}
    (5, 2) Skip parent 2; push 7 [(4, 3), (6, 3), (7, 5)] {1, 2, 3, 4, 5, 6, 7}
    (4, 3) Skip parent 3 (leaf!) [(6, 3), (7, 5)] {1..7}
    (6, 3) Skip 3; check nbr = 7: vis[7] == 1 and 7 != 3! Cycle Detected → return true! {1..7} 
    // Method 2: Undirected Graph Cycle Detection via BFS — C++
class Solution {
    bool bfsDetect(int start, const vector<vector<int>>& adj, vector<int>& vis) {
        queue<pair<int, int>> q;
        vis[start] = 1;
        q.push({start, -1});

        while (!q.empty()) {
            auto [node, parent] = q.front();
            q.pop();

            for (int nbr : adj[node]) {
                if (!vis[nbr]) {
                    vis[nbr] = 1;          // Mark visited ON ENQUEUE!
                    q.push({nbr, node});
                } else if (nbr != parent) {
                    // Another BFS branch already reached `nbr` -> cycle!
                    return true;
                }
            }
        }
        return false;
    }

public:
    bool isCycle(int V, const vector<vector<int>>& adj) {
        vector<int> vis(V, 0);
        for (int i = 0; i < V; ++i) {
            if (!vis[i]) {
                if (bfsDetect(i, adj, vis)) return true;
            }
        }
        return false;
    }
};
    # Undirected Cycle Detection (BFS & DFS) — Python
from collections import deque

def has_cycle_undirected_bfs(V: int, adj: List[List[int]]) -> bool:
    vis = [False] * V
    for start in range(V):
        if vis[start]:
            continue
        vis[start] = True
        q = deque([(start, -1)])
        while q:
            node, parent = q.popleft()
            for nbr in adj[node]:
                if not vis[nbr]:
                    vis[nbr] = True
                    q.append((nbr, node))
                elif nbr != parent:
                    return True
    return False

    4. Complexity & Parallel-Edge Subtlety

    • Time Complexity: $\mathcal{O}(V + 2E)$ — every vertex is visited once and the sum of adjacency degrees across an undirected graph is $2E$, plus $\mathcal{O}(V)$ for the outer multi-component loop.
    • Space Complexity: $\mathcal{O}(V)$ for vis[] and the queue / recursion stack.
    • Parallel Multi-Edges Edge Case: If the problem allows two parallel edges between the same pair $(u, v)$ (forming a 2-edge cycle), comparing nbr != parent by vertex ID would skip both copies! In multi-graphs, pass the incomingEdgeId instead of parentVertex and check edgeId != incomingEdgeId.
