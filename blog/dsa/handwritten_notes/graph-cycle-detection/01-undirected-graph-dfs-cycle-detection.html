    Undirected Graph Cycle Detection via DFS: The DFS(node, parent) Invariant

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 01_Undirected_DFS_cycle_detection.pdf · View original handwritten page

    1. Problem Statement & Why Naive visited[adj] Fails Immediately

    Given an undirected graph $G = (V, E)$ represented as an adjacency list (which may contain multiple disconnected components), determine whether $G$ contains at least one simple cycle.

    Naive Bug: Checking if (visited[adj]) return true; Without parent

    Consider a simple 2-node tree with a single undirected edge $1 - 2$ (clearly acyclic!). In an adjacency list, $1 - 2$ is stored symmetrically as $2 \in \text{adj}[1]$ and $1 \in \text{adj}[2]$. Starting at $1$, we mark $\text{visited}[1] = 1$ and recurse into $2$. Immediately inside $2$, scanning $\text{adj}[2]$ sees neighbor $1$ with $\text{visited}[1] == 1$! Walking backward across the exact undirected edge we just arrived on ($2 \to 1$) is a trivial U-turn, NOT a cycle.

    The 4-Step Undirected DFS Algorithm (From 01_Undirected_DFS_cycle_detection.pdf)

    1. Iterate $i = 0 \dots V - 1$ through the visited array; whenever visited[i] == 0, launch DFS(i, -1) (where parent = -1 signifies a component root with no incoming edge).
    2. Upon entering DFS(node, parent), immediately mark visited[node] = 1.
    3. For every adj in adj[node]:
      • If visited[adj] == 0: recursively call DFS(adj, node); if it returns true, propagate true immediately.
      • Else if adj != parent: adj was already visited earlier in this component via a genuinely distinct path—a cycle is detected, return true!
    4. If all neighbors finish without detecting a back-edge, return false.

    3. Clean C++ Implementation

    // Undirected Graph Cycle Detection via Recursive DFS — C++
class Solution {
    bool dfs(int node, int parent, const vector<vector<int>>& adj, vector<int>& vis) {
        vis[node] = 1;

        for (int nbr : adj[node]) {
            if (!vis[nbr]) {
                if (dfs(nbr, node, adj, vis)) return true;
            } else if (nbr != parent) {
                // Visited vertex that is NOT our immediate parent -> simple cycle!
                return true;
            }
        }
        return false;
    }

public:
    bool isCycle(int V, const vector<vector<int>>& adj) {
        vector<int> vis(V, 0);
        for (int i = 0; i < V; ++i) { // Outer loop covers all disconnected components
            if (!vis[i]) {
                if (dfs(i, -1, adj, vis)) return true;
            }
        }
        return false;
    }
};

    4. Complexity Proof & Key Edge Cases

    • Time Complexity: $\mathcal{O}(V + 2E) = \mathcal{O}(V + E)$ — The outer loop checks $V$ vertices in $\mathcal{O}(V)$; each vertex enters dfs at most once, and summing $\deg(u)$ across all $u \in V$ inspects $2E$ adjacency entries.
    • Space Complexity: $\mathcal{O}(V)$ — vis[V] array of size $V$ plus at most $\mathcal{O}(V)$ active frames on the recursion / explicit stack (e.g., on a path graph $0 - 1 - \dots - (V-1)$).
    • Parallel Multi-Edges (u == 0, v == 1 twice): Two parallel undirected edges between $(u, v)$ form a valid 2-edge cycle, yet checking nbr != parent by vertex ID skips both copies! On multigraphs (like Codeforces bridge/cycle problems), store (neighbor, edge_id) in adj[u], pass incoming_edge_id instead of parent_vertex, and trigger a cycle when vis[nbr] && edge_id != incoming_edge_id.
    • Self-Loops (u in adj[u]): At dfs(u, parent), vis[u] is already 1 and u != parent (since parent was either -1 or a distinct neighbor), so the algorithm automatically returns true!
    • Disconnected Forests: Never call dfs(0, -1) alone! Component {0, 1} may be a tree while component {2, 3, 4} is a triangle.
