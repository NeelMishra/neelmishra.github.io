    Graph Cycle Detection: The 2×2 Matrix (Undirected vs. Directed × DFS vs. BFS)

    October 2026 · 6 min read · 4-Note Series (6 Handwritten Pages)

    Expanded 1-to-1 from handwritten competitive coding study notes: 01_Undirected_DFS_cycle_detection.pdf, 02_Undirected_BFS_cycle_detection.pdf, 03_Directed_graph_dfs_cycle_detection.pdf & 04_Directed_graph_bfs_cycle_detection.pdf

    Cycle detection is one of the most deceptively subtle primitives in graph algorithms because an undirected cycle check and a directed cycle check test fundamentally different invariants. Applying the undirected visited[nbr] && nbr != parent condition to a directed graph fails immediately on a harmless diamond DAG! Each of the four cells in the 2×2 matrix has its own dedicated standalone note below.

    The 2×2 Cycle-Detection Cheat Sheet

    All 4 cycle-detection variants compared side-by-side (all run in $\mathcal{O}(V + E)$ time and $\mathcal{O}(V)$ auxiliary space).
    Graph Type Traversal State Tracked Exact Cycle Trigger Condition
    Undirected 01 · DFS vis[V] + parent param Neighbor nbr has vis[nbr] == 1 && nbr != parent
    Undirected 02 · BFS vis[V] + queue<{node, parent}> Neighbor nbr has vis[nbr] == 1 && nbr != parent (two wavefronts meet!)
    Directed 03 · DFS vis[V] + pathVis[V] (reset to 0 on exit!) Neighbor nbr has pathVis[nbr] == 1 (back-edge to active ancestor on call stack)
    Directed 04 · BFS (Kahn's) indegree[V] + FIFO queue + cnt Queue empties with cnt < V (cycle nodes retain indegree >= 1 forever)

    Core Insight: Why Undirected Parent-Check Fails on Directed Graphs

    In an undirected graph, every edge works in both directions: if two distinct paths from $u$ reach the same vertex $w$ ($u - x - w$ and $u - y - w$), you can walk $u \to x \to w \to y \to u$ to form a genuine cycle. In a directed graph, one-way arrows break that symmetry!
