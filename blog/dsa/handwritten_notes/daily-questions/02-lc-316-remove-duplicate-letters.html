    LC 316: Remove Duplicate Letters — From Two-Stack Swaps to Monotonic Stack

    October 2026 · 9 min read · Handwritten Notes

    Expanded from handwritten competitive coding study note: 02_316.pdf

    1. Problem Statement & Constraints

    Given a string s ($1 \le |s| \le 10^4$) consisting of lowercase English letters, remove duplicate letters so that every distinct letter in s appears once and only once. Among all valid subsequences (preserving relative order), return the one that is lexicographically smallest. (Identical to LeetCode 1081: Smallest Subsequence of Distinct Characters.)

    • Example 1: s = "bcabc" $\longrightarrow$ "abc"
    • Example 2: s = "cbacdcbc" $\longrightarrow$ "acdb"

    2. Scratchpad Evolution: Why Delayed Deletion Breaks on "cbacdcbc"

    In 02_316.pdf, we first explore a very natural contest hypothesis using present = [0] * 26 and two stacks (S1 and S2): keep pushing unseen characters onto S1, and whenever a duplicate char arrives, pop S1 into auxiliary buffer S2 back to the earlier copy of char and compare ord(S2[0]) < ord(char) (the character immediately following the old char) to decide whether to drop the old copy or the new copy.

    The Crucial Counterexample at the Bottom of 02_316.pdf

    Look at how the handwritten two-stack code behaves on the two sample inputs:

    • On "bcabc", it happens to succeed: "bcab" drops the first 'b' (since next char 'c'? Actually on "bcabc", "bcabc" → "babc" → "abc" works only when the immediately adjacent char is smaller).
    • On "cbacdcbc" (traced at the very bottom of the scan!), waiting until the duplicate 'c' arrives at index 3 sees "cba": the character right after the old 'c' is 'b', so removing old 'c' leaves "badbc", and later removing old 'b' leaves "adbc" instead of the true optimal "acdb"!

    Root Cause: By waiting until the second 'c' appeared, we missed our chance at index 2 (when 'a' arrived) to evict both 'b' and 'c' eagerly so 'a' could claim index 0 while 'c' was still available at index 3! Even better: instead of reacting late when a duplicate arrives, we should evict larger characters eagerly when a smaller character arrives—provided those larger characters appear again in the suffix!

    3. Brute $\to$ Better $\to$ Optimal Progression

    1. Brute Force ($\mathcal{O}(2^n)$): Enumerate subsequences containing all $k \le 26$ distinct letters of length $k$ and pick the lexicographically minimum one—exponential and infeasible for $n = 10^4$.
    2. Better Greedy Recursion ($\mathcal{O}(|\Sigma| \cdot n) = \mathcal{O}(26n)$): Find the leftmost index $p$ of the smallest character $c$ whose suffix $s[p..]$ still contains every distinct character of $s$. Output $c$, delete all copies of $c$ from $s[p+1..]$, and recurse (at most $26$ passes).
    3. Optimal Single-Pass Monotonic Increasing Stack ($\mathcal{O}(n)$): Precompute lastIdx[c] = final index where character c occurs in s, and maintain a stack st plus boolean lookup inStack[26]:
      • Rule 1 (Already Placed Guard): If inStack[c] is already true, skip s[i] immediately! Why? In our monotonic stack, any character sitting directly after the earlier c (say x) either satisfies c < x (so deleting the earlier c would shift a larger char x left and hurt lexicographical order!) or couldn't be popped because x had no future copies.
      • Rule 2 (Safe Eager Eviction): While !st.empty() and st.back() > c (current char beats stack top) and lastIdx[st.back()] > i (stack top appears again later at some index $\gt i$, so popping it won't lose that distinct letter!), pop st.back() and set inStack[st.back()] = false.
      • Rule 3: Push c onto st and mark inStack[c] = true.

    4. Step-by-Step Dry Run on s = "cbacdcbc"

    First pass records lastIdx: a: 2, b: 6, c: 7, d: 4.

    5. Clean C++ & Python Implementations

    // LC 316: Remove Duplicate Letters — O(n) Time, O(1) Alphabet Space
#include <array>
#include <string>
using namespace std;

class Solution {
public:
    string removeDuplicateLetters(string s) {
        array<int, 26> lastIdx{};
        for (int i = 0; i < (int)s.size(); ++i) {
            lastIdx[s[i] - 'a'] = i;
        }

        array<bool, 26> inStack{};
        string st; // String acts directly as our monotonic character stack

        for (int i = 0; i < (int)s.size(); ++i) {
            char c = s[i];
            int idx = c - 'a'; // Note: ord(c) - ord('a'), fixing scratchpad sign!
            if (inStack[idx]) continue;

            while (!st.empty() && st.back() > c && lastIdx[st.back() - 'a'] > i) {
                inStack[st.back() - 'a'] = false;
                st.pop_back();
            }
            st.push_back(c);
            inStack[idx] = true;
        }
        return st;
    }
};
    class Solution:
    def removeDuplicateLetters(self, s: str) -> str:
        last_idx = {ch: i for i, ch in enumerate(s)}
        in_stack: set[str] = set()
        stack: list[str] = []

        for i, ch in enumerate(s):
            if ch in in_stack:
                continue
            while stack and stack[-1] > ch and last_idx[stack[-1]] > i:
                in_stack.remove(stack.pop())
            stack.append(ch)
            in_stack.add(ch)

        return "".join(stack)

    6. Complexity Proof & Key Edge Cases

    • Time Complexity — $\mathcal{O}(n)$ amortized: Recording lastIdx takes $n$ operations. In the main loop, each index $i \in [0, n-1]$ is pushed onto st at most once and popped from st at most once, bounding total inner while pops across the entire run to $\le n$.
    • Space Complexity — $\mathcal{O}(|\Sigma|) = \mathcal{O}(1)$: Because every character in st is distinct, st.size() <= 26 at every instant, alongside two fixed 26-element arrays.
    • Key Edge Cases:
      • Why if (inStack[idx]) continue; MUST run before the while loop (e.g. "abacb"): At $i = 2$ ('a'), stack is "ab". If you forgot to skip 'a' before popping, 'a' would pop 'b' (since lastIdx['b'] = 4 > 2) and produce duplicate "aacb" or corrupt "ab" into "acb" instead of optimal "abc"!
      • Single-character string or all identical ("zzzz"): Pushes 'z' at $i = 0$ and skips $i = 1, 2, 3$ $\to$ "z".
      • Scratchpad ASCII Indexing Note: In Python/C++, map 'a'..'z' to 0..25 via ord(char) - ord('a') (in 02_316.pdf, ord('a') - ord(char) produced negative Python slice indices).
