    1. LC 34: Find First and Last Position of Element in Sorted Array

    Given a non-decreasing array nums (e.g., [5, 7, 7, 8, 8, 10]) and a target (8), return the starting and ending indices of target ([3, 4]), or [-1, -1] if absent, in strict $\mathcal{O}(\log n)$ time.

    Splitting Into Two Monotonic Boundary Searches (06_34.pdf)

    Expanding linearly left and right from the first mid that hits target degrades to $\mathcal{O}(n)$ when the entire array equals target (like the plateau [6, 7, 8, 8, 8, 8, 8, 8, 9, 10] traced on 06_34.pdf). Instead, run two clean L <= R binary searches using a candidate = -1 variable:

    • Search Left (First Occurrence): Whenever nums[mid] == target, record ans = mid and keep squeezing left via R = mid - 1.
    • Search Right (Last Occurrence): Whenever nums[mid] == target, record ans = mid and keep squeezing right via L = mid + 1.

    Why Checking the 2-Element Array [2, 2] Matters (Bottom of 06_34.pdf)

    Notice the deliberate 2-element trace on [2, 2] at the bottom of the handwritten note! When writing closed-interval binary searches that set L = mid (instead of L = mid + 1 after saving ans = mid), integer floor division mid = L + (R - L) / 2 evaluates to 0 when L = 0, R = 1, trapping L = 0 in an infinite loop! Recording ans = mid and strictly advancing L = mid + 1 / R = mid - 1 shrinks $[L, R]$ on every single iteration without midpoint bias headaches.

    // LC 34: Find First and Last Position of Element in Sorted Array — O(log n) Time
class Solution {
    int findBound(const vector<int>& nums, int target, bool findFirst) {
        int L = 0, R = (int)nums.size() - 1, ans = -1;
        while (L <= R) {
            int mid = L + (R - L) / 2;
            if (nums[mid] == target) {
                ans = mid;
                if (findFirst) R = mid - 1; // Squeeze left for first occurrence
                else           L = mid + 1; // Squeeze right for last occurrence
            } else if (nums[mid] < target) {
                L = mid + 1;
            } else {
                R = mid - 1;
            }
        }
        return ans;
    }

public:
    vector<int> searchRange(vector<int>& nums, int target) {
        int first = findBound(nums, target, true);
        if (first == -1) return {-1, -1}; // Early exit: target absent!
        int last = findBound(nums, target, false);
        return {first, last};
    }
};

    2. LC 2251: Number of Flowers in Full Bloom

    You are given $n$ inclusive intervals $\text{flowers}[i] = [\text{start}_i, \text{end}_i]$ ($1 \le \text{start}_i \le \text{end}_i \le 10^9$) and $q$ query arrival times $\text{people}[j]$. For each person arriving at time $t$, return how many flowers satisfy $\text{start}_i \le t \le \text{end}_i$.

    Why Decoupling Starts & Ends Works (07_2251.pdf)

    Because coordinates reach $10^9$, building a dense difference array up to $\max(\text{end}_i)$ would blow memory. On 07_2251.pdf, after briefly checking prefix sums on flowers = [[1, 6], [3, 7], [9, 12], [4, 13]] and people = [2, 3, 7, 11], the note lands on a classic inclusion–exclusion identity on the timeline:

    Bloomed Minus Debloomed Identity

    A flower $i$ is currently in full bloom at time $t$ if and only if it has already started blooming ($\text{start}_i \le t$) and it has NOT yet finished blooming (i.e., it is not the case that $\text{end}_i \lt t$). Since every flower satisfies $\text{start}_i \le \text{end}_i$, the set $\{i : \text{end}_i \lt t\}$ is a strict subset of $\{i : \text{start}_i \le t\}$!

    $$\text{Active}(t) = \bigl|\{i : \text{start}_i \le t\}\bigr| - \bigl|\{i : \text{end}_i \lt t\}\bigr|$$

    Notice that we no longer care which specific $\text{start}_i$ paired with which $\text{end}_i$! Sorting all start times into starts and all end times into ends independently lets us evaluate both counts in $\mathcal{O}(\log n)$ via binary search:

    • $\bigl|\{i : \text{start}_i \le t\}\bigr| =$ upper_bound(starts, t) (first index strictly $\gt t$).
    • $\bigl|\{i : \text{end}_i \lt t\}\bigr| =$ lower_bound(ends, t) (first index $\ge t$).
    // LC 2251: Number of Flowers in Full Bloom — O((n + q) log n) Time, O(n) Space
class Solution {
public:
    vector<int> fullBloomFlowers(vector<vector<int>>& flowers, vector<int>& people) {
        int n = flowers.size();
        vector<int> starts(n), ends(n);
        for (int i = 0; i < n; ++i) {
            starts[i] = flowers[i][0];
            ends[i]   = flowers[i][1];
        }
        sort(starts.begin(), starts.end());
        sort(ends.begin(), ends.end());

        vector<int> ans;
        ans.reserve(people.size());
        for (int t : people) {
            int bloomed   = upper_bound(starts.begin(), starts.end(), t) - starts.begin(); // start <= t
            int debloomed = lower_bound(ends.begin(), ends.end(), t) - ends.begin();       // end < t
            ans.push_back(bloomed - debloomed);
        }
        return ans;
    }
};
    from bisect import bisect_left, bisect_right


class Solution:
    def fullBloomFlowers(self, flowers: list[list[int]], people: list[int]) -> list[int]:
        starts = sorted(s for s, _ in flowers)
        ends = sorted(e for _, e in flowers)
        return [bisect_right(starts, t) - bisect_left(ends, t) for t in people]
