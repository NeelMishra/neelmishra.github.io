    Inclusion–Exclusion: Ugly Number III

    August 2026 · 24 min read

    Part 5 counted elements of an implicit multiset. This post pushes count(≤ x) one step further: the multiset is "all positive integers divisible by a, b, or c," and counting it correctly requires the inclusion–exclusion principle. We solve Ugly Number III (1201) with the same first-true template, but the interesting work is entirely in the condition: deriving the seven-term count formula, computing least common multiples without overflowing a 64-bit integer, and choosing bounds that keep the search tight. The template does not change at all — that is the whole point.

    The Problem

    Problem 1201: an "ugly number" here is a positive integer divisible by at least one of a, b, or c. Given n, a, b, c, return the n-th ugly number. (Despite the name, this is unrelated to the classic Ugly Number II with prime factors 2/3/5 — here a, b, c are arbitrary.)

    This is a $k$-th smallest problem in disguise, so we reuse Part 5's plan: binary search the value x, with the monotone condition count(≤ x) ≥ n, where count(≤ x) is how many ugly numbers do not exceed x. The first such x is the answer. Everything hinges on computing that count.

    Deriving the Count by Inclusion–Exclusion

    How many integers in $[1, x]$ are divisible by a? Exactly $\lfloor x/a \rfloor$. The naive sum $\lfloor x/a \rfloor + \lfloor x/b \rfloor + \lfloor x/c \rfloor$ over-counts: a number divisible by both a and b is counted twice. Inclusion–exclusion corrects this by alternately subtracting and re-adding overlaps.

    A number divisible by both a and b is exactly a multiple of $\operatorname{lcm}(a,b)$. So:

    $$\text{count}(x) = \left\lfloor\tfrac{x}{a}\right\rfloor + \left\lfloor\tfrac{x}{b}\right\rfloor + \left\lfloor\tfrac{x}{c}\right\rfloor - \left\lfloor\tfrac{x}{\operatorname{lcm}(a,b)}\right\rfloor - \left\lfloor\tfrac{x}{\operatorname{lcm}(a,c)}\right\rfloor - \left\lfloor\tfrac{x}{\operatorname{lcm}(b,c)}\right\rfloor + \left\lfloor\tfrac{x}{\operatorname{lcm}(a,b,c)}\right\rfloor$$

    The three positive singles, three negative pairs, one positive triple — the classic $|A \cup B \cup C| = \sum|A| - \sum|A\cap B| + |A\cap B\cap C|$ pattern, specialized to divisibility.

    Monotonicity. Every term $\lfloor x/d \rfloor$ is non-decreasing in x, and the whole expression counts a set that only grows as x increases. So count is non-decreasing — a valid first-true condition.

    Overflow-Safe gcd and lcm

    The count formula needs $\operatorname{lcm}(a,b)$, $\operatorname{lcm}(a,c)$, $\operatorname{lcm}(b,c)$, and $\operatorname{lcm}(a,b,c)$. Recall $\operatorname{lcm}(a,b) = a \cdot b / \gcd(a,b)$, computed as a / gcd(a,b) * b to divide before multiplying. But even so, with a, b, c up to $10^9$, a pairwise LCM can reach $10^{18}$ (near the top of long long), and the triple LCM could mathematically reach $10^{27}$ — far past what any 64-bit integer holds.

    The capped LCM trick

    Here is the saving observation: we only ever evaluate $\lfloor x / L \rfloor$ for x bounded by our search's upper limit. If an LCM L exceeds that upper limit, then $\lfloor x / L \rfloor = 0$ for every x we test. So we can cap any LCM at a value larger than the maximum x without changing a single count. Capping both prevents overflow and preserves correctness.

    gcd and capped lcm

    long long gcdll(long long a, long long b) {
    while (b) { long long t = a % b; a = b; b = t; }
    return a;
}

// Returns lcm(a, b), but clamped to CAP+1 if it would exceed CAP.
// CAP is chosen larger than any x the search evaluates, so a clamped
// value contributes floor(x / lcm) = 0 -- identical to the true count.
long long lcmCapped(long long a, long long b, long long CAP) {
    long long g = gcdll(a, b);
    long long q = a / g;                 // a / gcd, so q * b == lcm(a, b)
    if (q > CAP / b) return CAP + 1;      // would overflow / exceed CAP: clamp
    return q * b;
}
    The overflow guard q > CAP / b is the critical line: it checks whether q * b would exceed CAP before performing the multiplication, so the product never overflows. This is the same "test with division, not multiplication" discipline from the sqrt problem in Part 2.

    Bounds and Count Saturation

    The answer is at most $n \cdot \min(a,b,c)$: among any $\min(a,b,c)$ consecutive integers there is at least one multiple of the smallest of the three, so by the time we reach $n \cdot \min(a,b,c)$ we have seen at least n ugly numbers. That gives:

    • Lower bound = 1 (the smallest positive integer).
    • Upper bound = $n \cdot \min(a,b,c)$, a guaranteed-true sentinel: count(hi) ≥ n.

    With n and min each up to $10^9$, hi can reach $10^{18}$ — still inside long long. We set CAP = hi (or any value $\ge hi$) so that any LCM exceeding hi is clamped and contributes zero. This is what "count saturation" means here: overlaps whose LCM outruns the range simply saturate to a zero contribution, and the formula stays exact.

    Solution

    int nthUglyNumber(int n, int a, int b, int c) {
    long long A = a, B = b, C = c;
    long long lo = 1;
    long long hi = (long long)n * std::min({A, B, C});   // true sentinel
    long long CAP = hi;                                   // clamp LCMs beyond the range

    long long ab  = lcmCapped(A, B, CAP);
    long long ac  = lcmCapped(A, C, CAP);
    long long bc  = lcmCapped(B, C, CAP);
    long long abc = lcmCapped(ab, C, CAP);               // lcm(a,b,c) = lcm(lcm(a,b), c)

    auto count = [&](long long x) {
        return x/A + x/B + x/C - x/ab - x/ac - x/bc + x/abc;
    };
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        if (count(mid) >= n) hi = mid;     // enough ugly numbers so far: go lower
        else                 lo = mid + 1; // too few: go higher
    }
    return (int)lo;   // LeetCode guarantees the answer is at most 2*10^9
}
    Careful with lcm(ab, C) when ab is already clamped. If ab == CAP + 1, then lcmCapped(ab, C, CAP) sees a/gcd > CAP/C and returns CAP + 1 again — still $> hi$, so x/abc = 0 for all tested x. The clamp composes correctly: once a value is beyond the range it stays beyond, and its contribution stays zero.

    The Answer Is a Real Ugly Number

    Claim. The returned x* is divisible by a, b, or c, and it is the n-th such number.

    Proof. x* is the first value with count(x*) ≥ n, so count(x* - 1) < n ≤ count(x*). The count function increases only at ugly numbers (a non-ugly integer adds nothing to any $\lfloor x/d \rfloor$ that was not already counted). A strict jump from x* - 1 to x* therefore means x* itself is ugly. And since fewer than n ugly numbers are $< x*$ while at least n are $\le x*$, x* is precisely the n-th ugly number. $\blacksquare$

    n = 5, a = 2, b = 3, c = 5

    Ugly sequence: 2, 3, 4, 5, 6, 8, 9, 10, ... count(5) = ⌊5/2⌋+⌊5/3⌋+⌊5/5⌋ - ⌊5/6⌋-⌊5/10⌋-⌊5/15⌋ + ⌊5/30⌋ = 2+1+1-0-0-0+0 = 4 < 5. count(6) = 3+2+1-1-0-0+0 = 5 ≥ 5. First feasible = 6, and 6 is divisible by 2 and 3 — a real ugly number.

    Complexity

    The four LCMs are computed once in $O(\log(\max(a,b,c)))$ each (Euclid's algorithm). The search runs $O(\log(n \cdot \min))$ iterations, each doing $O(1)$ arithmetic in the count. Total: $O(\log(\max(a,b,c)) + \log(n\cdot\min))$ time, $O(1)$ space — effectively $O(\log(\text{answer}))$.

    Common Mistakes

    • Computing a * b before dividing by the gcd. a*b overflows for large inputs; use a / gcd * b, and guard even that with the q > CAP/b check.
    • Not capping the triple LCM. lcm(a,b,c) can be astronomically large; without a cap it overflows and corrupts the count.
    • Doing the count or bounds in 32-bit. hi = n * min reaches $10^{18}$; keep everything long long.
    • Forgetting a subtraction or the final addition. All six correction terms are required; dropping the + lcm(a,b,c) term under-counts triple overlaps.
    • Using hi = 2*10^9 blindly. It works within the official constraints, but n * min(a,b,c) is the principled, self-documenting bound.

    Key Takeaways

    • Ugly Number III is a $k$-th smallest value search; the only new ingredient is an inclusion–exclusion count(≤ x).
    • Count divisible-by-any with three singles ($+$), three pair LCMs ($-$), and one triple LCM ($+$).
    • Compute LCM as a / gcd * b and cap it beyond the search range so it never overflows and contributes zero — count saturation.
    • Bounds are [1, n * min(a,b,c)], a principled true sentinel.
    • The boundary is a real ugly number by the same step-function argument as Part 5.
    • What changed from Part 5: the condition uses inclusion–exclusion with overflow-safe LCMs; bounds and return are unchanged.
