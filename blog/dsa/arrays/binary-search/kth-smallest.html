    Kth Smallest: Multiplication Table and Pair Distance

    August 2026 · 26 min read

    So far the feasibility check answered "can we do it in time/space?" This post turns the same template toward order statistics: finding the $k$-th smallest element of a collection we never materialize. The trick is a new condition — count(≤ x) ≥ k — that counts how many elements of an implicit multiset are at most x. We cover Kth Smallest in a Multiplication Table (668) and Find K-th Smallest Pair Distance (719). The recurring worry — duplicates, value gaps, and whether the answer is even a real element — gets a clean proof, and we add a two-pointer counter that makes pair-distance counting linear.

    The count(≤ x) ≥ k Condition

    Suppose you have a multiset $M$ (possibly with repeats) and want its $k$-th smallest value. Define

    $$\text{condition}(x) = \big[\, |\{\, e \in M : e \le x \,\}| \;\ge\; k \,\big].$$

    As x increases, the count $|\{e \le x\}|$ can only grow, so once the count reaches k it stays $\ge k$ — the condition is monotone. The first x for which at least k elements are $\le x$ is exactly the $k$-th smallest value. We never build $M$; we only need a fast way to compute count(≤ x).

    Why "at least k", not "exactly k". Duplicates make "exactly k elements $\le x$" unattainable for many x (the count jumps past k at a repeated value). The monotone, always-answerable question is $\ge k$. Its first-true point is the answer even when the count leaps from k-2 to k+3 across a heavily repeated value.

    Kth Smallest in a Multiplication Table (LeetCode 668)

    Problem 668: the $m \times n$ multiplication table has entry $i \cdot j$ for $1 \le i \le m$, $1 \le j \le n$. Return the $k$-th smallest value among all $m \cdot n$ entries.

    Under LeetCode's $m,n \le 3\times10^4$ constraints, the table has up to $9\times10^8$ entries, so materializing and sorting it is out. Instead binary search the value. Counting entries $\le x$ is a one-line-per-row observation: in row i, the entries are $i, 2i, 3i, \dots, ni$, so the number that are $\le x$ is $\min(n, \lfloor x / i \rfloor)$.

    count(≤ x) for a multiplication table

    long long countLE(int m, int n, long long x) {
    long long cnt = 0;
    for (int i = 1; i <= m; i++)
        cnt += std::min((long long)n, x / i);   // entries i, 2i, ... , ni that are ≤ x
    return cnt;
}
    DecisionValue
    Bounds[1, m*n]. The largest entry is $m\cdot n$; at x = m*n all $mn$ entries are counted, which is $\ge k$ — a true sentinel.
    ConditioncountLE(m, n, mid) ≥ k.
    Returnleft — and, by the proof below, it is guaranteed to be a real table entry.

    Solution

    int findKthNumber(int m, int n, int k) {
    long long lo = 1, hi = (long long)m * n;   // hi = m*n is a true sentinel
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        if (countLE(m, n, mid) >= k) hi = mid;    // enough small entries: go lower
        else                         lo = mid + 1;// too few: go higher
    }
    return (int)lo;
}

    Proof: The Answer Is a Real Table Value

    We binary search over all integers in [1, m*n], but the table only contains products — there are big gaps (a $3\times3$ table has no 5, 7, or 8). So why does the returned x* land on an actual entry?

    Claim. Let x* be the first value with countLE(x*) ≥ k. Then (a) x* is a real table entry, and (b) x* is the $k$-th smallest entry.

    Proof. Because x* is the first feasible value, countLE(x* - 1) < k ≤ countLE(x*). The count function increases only by jumping at values that are actually in the table — between two consecutive table values it is flat. So a strict increase from x* - 1 to x* means at least one entry equals exactly x*; hence x* is a real entry, proving (a).

    For (b): countLE(x* - 1) < k says fewer than k entries are strictly below x*, and countLE(x*) ≥ k says at least k entries are $\le x*$. Therefore the $k$-th smallest entry, in sorted order, is exactly x*. $\blacksquare$
    Same argument as Part 3. This is the identical "the value just below the boundary is infeasible" squeeze that proved Split Array Largest Sum returns a real partition cost. Whenever the count/feasibility function only steps at real values, the first-true boundary must be a real value.

    m = 3, n = 3, k = 5

    Sorted entries: 1, 2, 2, 3, 3, 4, 6, 6, 9. countLE(2) = 3 < 5; countLE(3) = 5 ≥ 5. The first feasible value is 3, the 5th smallest — a real entry, matching the animation above.

    Find K-th Smallest Pair Distance (LeetCode 719)

    Problem 719: over all pairs $(i, j)$ with $i < j$, the distance is $|nums_i - nums_j|$. Return the $k$-th smallest distance among all $\binom{n}{2}$ pairs.

    The implicit multiset here is the set of pairwise distances — up to $\sim n^2/2$ of them, far too many to list. Binary search the distance value in [0, max - min], and count how many pairs have distance $\le x$.

    Counting with two pointers

    Sort nums first. After sorting, for a fixed right index r, the pairs $(l, r)$ with $nums_r - nums_l \le x$ are exactly those with l in a contiguous window ending at r. As r advances, the smallest valid l only moves right (a larger $nums_r$ needs an equal-or-larger $nums_l$ to stay within x), so a single left pointer sweeps forward — no restart. That gives an $O(n)$ count instead of $O(n\log n)$ per binary-search step.

    count(≤ x) via two pointers (sorted array)

    long long countPairsLE(const std::vector<int>& a, long long x) {
    long long cnt = 0;
    int l = 0;
    for (int r = 0; r < (int)a.size(); r++) {
        while ((long long)a[r] - a[l] > x) l++; // widen before subtraction
        cnt += r - l;                  // all pairs (l..r-1, r) have distance ≤ x
    }
    return cnt;
}
    DecisionValue
    Bounds[0, a[n-1] - a[0]]. The smallest possible distance is 0 (equal values); the largest is the spread of the sorted array, at which all $\binom{n}{2}$ pairs are counted — a true sentinel.
    ConditioncountPairsLE(mid) ≥ k.
    Returnleft — a real pairwise distance, by the same step-function argument.

    Solution

    int smallestDistancePair(std::vector<int>& nums, int k) {
    std::sort(nums.begin(), nums.end());
    int n = (int)nums.size();
    long long lo = 0, hi = (long long)nums[n - 1] - nums[0];
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        long long cnt = 0;
        int l = 0;
        for (int r = 0; r < n; r++) {
            while ((long long)nums[r] - nums[l] > mid) l++;
            cnt += r - l;
        }
        if (cnt >= k) hi = mid;    // enough small distances: try smaller
        else          lo = mid + 1;// too few: allow larger distances
    }
    return (int)lo;   // official constraints guarantee the answer fits int
}
    Value gaps and duplicates handled for free. If nums has repeats, distance 0 occurs multiple times and lo = 0 captures them. If the distances skip values (say no pair has distance 4), the count function stays flat across 4 and jumps at real distances — the boundary lands on a real distance exactly as in the multiplication-table proof.

    nums = [1, 3, 1], k = 1

    Sorted: [1, 1, 3]. Distances: |1-1|=0, |1-3|=2, |1-3|=2. Range [0, 2]. countPairsLE(0): pair (0,1) has distance 0 → count 1 $\ge 1$. First feasible = 0, the smallest distance. Correct.

    Complexity

    ProblemCount stepTotal
    Multiplication Table (668)$O(m)$ per row scan$O(m \log(mn))$
    Pair Distance (719)$O(n)$ two-pointer$O(n\log n + n\log(\text{spread}))$

    Both replace an infeasible $O(\text{size of multiset})$ enumeration with $O(\text{count cost} \times \log(\text{value range}))$. The multiplication table never materializes $mn$ entries; pair distance never lists $\binom{n}{2}$ distances.

    Common Mistakes

    • Counting with 32-bit types. The official table count reaches $9\times10^8$ and related variants can be larger; use long long for the count and for m*n so the pattern stays safe beyond the narrowest constraints.
    • Forgetting to sort before the two-pointer count. Pair-distance counting relies on sorted order; the left pointer's monotonic advance is only valid then.
    • Using "exactly k" as the condition. Duplicates make it non-monotone and often unattainable; always use count(≤ x) ≥ k.
    • Lower bound 1 for pair distance. The minimum distance can be 0 (duplicates); start at lo = 0.
    • Assuming the answer must be an element without the step-function argument. It is a real value — but for the specific reason that the count only increases at real values.

    Key Takeaways

    • To find the $k$-th smallest of an implicit multiset, binary search the value with the monotone condition count(≤ x) ≥ k.
    • Never materialize the multiset; design a fast count(≤ x): per-row $\min(n, x/i)$ for the table, a two-pointer sweep for pair distances.
    • The condition must be $\ge k$, not $= k$, so duplicates and value gaps do not break monotonicity.
    • The returned boundary is a real value because the count function only steps at real values (same squeeze proof as Part 3).
    • What changed from Part 4: the condition is a counting function; bounds are the value range; return stays left, now provably a genuine element.
