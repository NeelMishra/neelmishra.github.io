    Advanced & Contest Variants

    March 2026 · 22 min read

    Introduction

    The rest of this series combined a window with one auxiliary structure at a time: a hash map, a monotonic deque, a pair of deques. Genuinely hard contest problems often need the window combined with a second algorithmic idea — an order-statistics structure, or a DP recurrence. This post works through two such hybrids and closes with a note on circular windows.

    Problem: Sliding Window Median

    Given an array and window size k, return the median of each window of size k as it slides across the array.

    Example: arr = [1, 3, -1, -3, 5, 3, 6, 7], k = 3. Output: [1, -1, -1, 3, 5, 6].

    Why a Plain Window Isn't Enough

    The median needs order statistics — the middle element(s) of the window in sorted order, not insertion order. A monotonic deque only tracks extremes (front/back), not an arbitrary rank. The standard fix is an ordered structure, std::multiset<int>, kept in sync with the window via the same add/remove-on-slide skeleton as every other window in this series — plus a pointer into the multiset that tracks the median's position.

    Seed the multiset

    Insert the first k elements. Set mid to an iterator at position k / 2 (0-indexed) in sorted order.

    Read the median

    For odd k, the median is *mid. For even k, it's the average of *mid and *prev(mid).

    Insert the entering element

    Insert it into the multiset. If its value is less than *mid, it landed strictly before mid's position, so decrement mid to keep it pointing at the same logical rank.

    Remove the leaving element

    If its value is ≤ *mid, it sat at or before mid's position, so increment mid before erasing (to compensate for the removal shifting ranks), then erase it via multiset::find (never by value, which could target the wrong duplicate).

    Code

    vector<double> medianSlidingWindow(vector<int>& nums, int k) {
    multiset<int> window(nums.begin(), nums.begin() + k);
    auto mid = next(window.begin(), k / 2);
    vector<double> medians;

    for (int i = k; ; i++) {
        // k odd: next(mid, -1) with (k%2 - 1 = 0) gives mid itself, averaging mid with mid.
        // k even: next(mid, -1) gives the element just before mid.
        medians.push_back(((double)*mid + *next(mid, k % 2 - 1)) / 2.0);

        if (i == (int)nums.size()) break;

        window.insert(nums[i]);
        if (nums[i] < *mid) mid--;

        if (nums[i - k] <= *mid) mid++;
        window.erase(window.find(nums[i - k]));
    }
    return medians;
}
// Time: O(n log k), Space: O(k)
    Why the iterator adjustment is correct: think of mid as tracking a fixed rank (position k/2 in sorted order), not a fixed value. Inserting a value strictly less than *mid pushes everything at or after mid's old rank one slot to the right, so the same rank now lives one iterator step earlier — hence decrement. Symmetrically, removing a value at or before mid's rank pulls everything after it one slot to the left, so the rank you want now lives one step later — hence increment before the erase invalidates any iterator relationships.

    Problem: Constrained Subsequence Sum (Deque + DP)

    Given an array and an integer k, choose a subsequence (keeping relative order) such that any two chosen indices are at most k apart, maximizing the sum of chosen elements. Every non-empty subsequence is allowed (you may choose just one element).

    Example: arr = [10, -2, -10, -5, 20], k = 2. The answer is 23, achieved by the subsequence at indices 0, 1, 3, 4 (each consecutive pair at most k = 2 apart): 10 + (-2) + (-5) + 20 = 23.

    The Recurrence

    Let dp[i] be the best sum of a valid chosen subsequence that ends exactly at index i. Either i starts a fresh subsequence, or it extends the best subsequence ending in the previous k positions (only if that best is positive — otherwise starting fresh at i is better):

    dp[i] = arr[i] + max(0, max(dp[j] for j in [i-k, i-1]))

    The inner max(dp[j] for j in [i-k, i-1]) is a sliding window maximum over the dp array itself — exactly Part 7's monotonic deque, except the array being windowed is being built one entry at a time by the very same loop that queries it.

    long long constrainedSubsetSum(vector<int>& arr, int k) {
    int n = arr.size();
    vector<long long> dp(n);
    deque<int> dq;  // indices, dp[] values decreasing
    long long ans = LLONG_MIN;

    for (int i = 0; i < n; i++) {
        while (!dq.empty() && dq.front() < i - k) dq.pop_front();

        long long best = dq.empty() ? 0 : max(0LL, dp[dq.front()]);
        dp[i] = arr[i] + best;
        ans = max(ans, dp[i]);

        while (!dq.empty() && dp[dq.back()] <= dp[i]) dq.pop_back();
        dq.push_back(i);
    }
    return ans;
}
// Time: O(n), Space: O(n) for dp, O(k) for the deque

    A Note on Circular Windows

    Some problems ask for a window that may wrap around the end of the array back to the beginning. The standard trick is array doubling: concatenate the array with itself (length $2n$), run the ordinary window algorithm, and restrict which starting positions you accept so no window is counted twice or wraps more than once.

    // Sketch: maximum sum of a circular subarray of exactly length k.
// Double the array, then slide a fixed-size window of length k over
// the doubled array, but only accept windows starting at indices 0..n-1.
int maxSumCircularWindow(vector<int>& arr, int k) {
    int n = arr.size();
    if (k > n) return -1;  // a window of length k can't exceed one full wrap

    vector<int> doubled(arr);
    doubled.insert(doubled.end(), arr.begin(), arr.end());

    int windowSum = 0;
    for (int i = 0; i < k; i++) windowSum += doubled[i];
    int best = windowSum;

    for (int i = k; i < n + k - 1 && (i - k) < n; i++) {
        windowSum += doubled[i] - doubled[i - k];
        best = max(best, windowSum);
    }
    return best;
}
// Time: O(n), Space: O(n) for the doubled array
    Caveat: doubling works cleanly for fixed-size windows and for variable-size windows where the constraint doesn't itself depend on "distance around the circle." For variable-size circular windows, you must additionally cap the window length at n (a window can wrap at most once), or you'll silently allow a window that laps the array more than one full time.

    Edge Cases

    • Sliding window median with duplicate values: erasing by multiset::find (which returns an iterator to a matching value, not necessarily "the one you inserted") is still correct because all copies of an equal value are interchangeable for median purposes — but never erase by value directly in one step (window.erase(value) removes all copies).
    • Constrained Subsequence Sum, all negative array: the answer is the single largest (least negative) element, since max(0, ...) in the recurrence means never extending a negative-sum subsequence, and every dp[i] collapses to arr[i] alone in the worst case.
    • k ≥ n in constrained subsequence sum: the deque never evicts anything from the front; the whole problem degenerates to "max over all prior dp values," still handled correctly by the same code.
    • Circular window with k == n: the "window" is the entire array; both the doubled-array trick and a direct sum agree.

    Common Mistakes

    • Adjusting the median iterator in the wrong order: the increment for removal must happen before the erase call reads *mid; reordering silently corrupts the tracked rank.
    • Treating dp[] as static data for the deque: in the deque+DP hybrid, the deque is being filled with indices whose dp values were only just computed — make sure the push happens after computing dp[i], not before.
    • Doubling the array for a circular window but forgetting to bound the window length at n: this allows windows that wrap around more than once, which is never the intended interpretation.
    • Reaching for a full O(log n) order-statistics tree or Fenwick-tree-of-counts when a multiset with rank tracking already gives the same asymptotic complexity with far less code.

    Key Takeaways

    • Sliding window median needs an order-statistics structure (a multiset with a tracked rank iterator), not just a monotonic deque, because it needs an arbitrary rank, not an extreme.
    • The deque+DP hybrid uses a monotonic deque to answer "max dp value in the last k positions" in $O(1)$, inside a DP recurrence that's building the very array being windowed.
    • Circular windows are usually handled by doubling the array and bounding the window length/start position, not by writing genuinely circular indexing logic.
    • All three techniques are compositions of earlier tools in this series (Part 7's deque, Part 4's window template) with one additional idea (order statistics, DP, or array doubling) layered on top.
