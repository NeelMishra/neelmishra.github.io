    Variable-Size Window: Longest Valid Windows

    March 2026 · 22 min read

    Introduction

    Unlike the fixed-size variant, a variable-size sliding window lets the window grow and shrink dynamically. The right pointer expands the window to explore new elements, and the left pointer contracts it when a constraint is violated. This post covers the "find the longest" half of variable-size windows — expand, and shrink only enough to restore validity. Part 5 covers the mirror-image "find the shortest / coverage" half.

    This pattern is extremely common in string problems and subarray problems where you are asked to find the longest contiguous segment satisfying some condition.

    Key Invariant: Each element enters the window at most once (when the right pointer moves past it) and leaves the window at most once (when the left pointer moves past it). Total work across all steps: $O(n)$ — see Part 1 for the full amortized proof.

    Longest-Window Template

    "Find the longest" problems expand the right pointer every iteration, and shrink from the left only while the window is invalid, then update the answer once it's valid again:

    int left = 0;
// window state: hash map, counter, sum, etc.

for (int right = 0; right < n; right++) {
    // 1. Add arr[right] to window state

    // 2. While window is invalid, shrink from left
    while (/* window violates constraint */) {
        // Remove arr[left] from window state
        left++;
    }

    // 3. Window is now valid; update answer
    answer = max(answer, right - left + 1);
}

    The key decisions are:

    • What data structure maintains the window state? (hash map, counter, sum)
    • What is the validity condition? (no repeats, at most k distinct)
    • Is the update answer = max(...) placed after the shrink loop (as here, because we want the window valid before measuring it)?

    Problem: Longest Substring Without Repeating Characters

    Given a string s, find the length of the longest substring that contains no repeating characters.

    Example: s = "abcabcbb". The answer is 3 (the substring "abc").

    Approach

    Maintain a hash map that stores the last seen index of each character. When we encounter a character that is already in the window, move the left pointer past its previous occurrence.

    Expand

    Move right forward. Add s[right] to the hash map with its index.

    Check for duplicate

    If s[right] was already in the map and its stored index is at or after left, we have a repeat inside the window.

    Shrink

    Move left to one past the previous occurrence of s[right]. This skips over the duplicate.

    Update answer

    The current valid window length is right - left + 1. Take the maximum.

    Code

    int lengthOfLongestSubstring(string s) {
    int n = s.size();
    unordered_map<char, int> lastSeen;
    int left = 0, maxLen = 0;

    for (int right = 0; right < n; right++) {
        char c = s[right];
        if (lastSeen.count(c) && lastSeen[c] >= left) {
            left = lastSeen[c] + 1;  // shrink past duplicate
        }
        lastSeen[c] = right;
        maxLen = max(maxLen, right - left + 1);
    }
    return maxLen;
}
// Time: O(n), Space: O(min(n, |alphabet|))

    Problem: Longest Substring with At Most K Distinct Characters

    Given a string s and an integer k, find the length of the longest substring that contains at most k distinct characters.

    Example: s = "eceba", k = 2. The answer is 3 ("ece").

    Approach

    Use a hash map to track character frequencies in the window. Expand the window with the right pointer. When the number of distinct characters exceeds k, shrink from the left until the count drops back to k. This is the same longest-window template as above, with a different validity condition and a hash map instead of a last-seen-index table.

    Expand

    Add s[right] to the frequency map. If this is a new character, the distinct count grows.

    Shrink if needed

    While distinct count exceeds k, decrement the frequency of s[left]. If a frequency drops to zero, remove it from the map (distinct count decreases). Advance left.

    Update answer

    The current window [left..right] has at most k distinct characters. Update the maximum length.

    Code

    int lengthOfLongestSubstringKDistinct(string s, int k) {
    int n = s.size();
    if (k <= 0) return 0;
    unordered_map<char, int> freq;
    int left = 0, maxLen = 0;

    for (int right = 0; right < n; right++) {
        freq[s[right]]++;

        while ((int)freq.size() > k) {
            freq[s[left]]--;
            if (freq[s[left]] == 0) freq.erase(s[left]);
            left++;
        }
        maxLen = max(maxLen, right - left + 1);
    }
    return maxLen;
}
// Time: O(n), Space: O(k)
    Where this goes next: the identical freq.size() > k shrink condition, reused to count subarrays instead of measuring the longest one, is exactly the atMost(k) building block for Part 6's counting identities. The window-maximum-frequency variant (windowSize - maxFreq > k) is a budgeted-replacement problem, covered as a transformation in Part 10.

    The Longest-Window Recipe

    Both worked examples in this post follow one recipe: expand unconditionally, shrink only while invalid, then measure.

    // Longest subarray/substring satisfying condition
for (right = 0; right < n; right++) {
    // add arr[right]
    while (/* invalid */) {
        // remove arr[left]; left++
    }
    answer = max(answer, right - left + 1);
}

    Part 5 covers the mirror-image recipe for "find the shortest" problems, where the while loop's condition and the position of the answer update both flip.

    The Role of the Hash Map

    In most variable-size window problems, a hash map (or frequency array) is the core data structure maintaining window state. The map tracks:

    • Character frequencies: How many times each character appears in the current window.
    • Last seen index: The most recent index where a character was seen (useful for the "no repeats" problem).
    • Match count: How many characters have met their required frequency.

    For small alphabets (e.g., 26 lowercase letters), a fixed-size array is more efficient than a hash map. For larger character sets (e.g., Unicode), use an unordered_map.

    Edge Cases

    • Empty string/array: Return 0 immediately.
    • All identical characters: The window may never need to shrink (longest without repeats = 1; longest with k distinct = entire string if k ≥ 1).
    • k ≤ 0 for at-most-K problems: no non-empty window can satisfy "at most 0 distinct" — return 0 rather than letting the shrink loop run unbounded.
    • k larger than the alphabet: the constraint never binds; the answer is simply n.
    • Single character: The window is always of size 1. Make sure your code handles this without off-by-one errors.

    Key Takeaways

    • Longest-window problems expand with the right pointer, shrink from the left only while invalid, and measure after the shrink loop.
    • Each element enters and exits the window at most once, giving $O(n)$ amortized time (proved in Part 1).
    • A hash map or frequency array typically maintains the window state; a fixed-size array beats a hash map when the alphabet is small and known.
    • The same "expand, shrink-while-invalid, measure" skeleton solves both the last-seen-index problem (no repeats) and the frequency-size problem (at most K distinct) — only the validity check changes.
    • The technique requires a monotonic validity condition: expanding the window can only push it towards "more invalid," never towards both directions at once (Part 1, Part 9).
