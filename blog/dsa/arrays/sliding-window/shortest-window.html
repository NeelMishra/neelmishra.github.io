    Variable-Size Window: Shortest & Coverage Windows

    March 2026 · 20 min read

    Introduction

    Part 4 covered "find the longest": expand, shrink only while invalid, measure after the shrink loop. This post covers the mirror image — "find the shortest", sometimes called a coverage window because the classic examples ask for the smallest window that covers some requirement (all target characters, a sum threshold).

    Key difference from the longest-window recipe: here we shrink while the window is still valid, measuring on the way, and stop the moment it becomes invalid. The measurement happens inside the shrink loop, not after it.

    Shortest-Window Template

    int left = 0;
// window state: hash map, counter, sum, etc.
int answer = INT_MAX;

for (int right = 0; right < n; right++) {
    // 1. Add arr[right] to window state

    // 2. While window is valid, record and shrink
    while (/* window satisfies constraint */) {
        answer = min(answer, right - left + 1);
        // Remove arr[left] from window state
        left++;
    }
}
return (answer == INT_MAX) ? 0 : answer;

    Compare this carefully against Part 4's longest-window template: the loop condition is inverted (while valid instead of while invalid), and the answer update moves inside the loop body, executing on every shrink instead of once after the loop exits. Both templates still rely on the same amortized argument from Part 1 — left is monotonic and advances at most $n$ times in total.

    Problem: Minimum Window Substring

    Given strings s and t, find the shortest substring of s that contains all characters of t (including duplicates).

    Example: s = "ADOBECODEBANC", t = "ABC". The answer is "BANC".

    Approach

    Expand the window until it contains all characters of t, then shrink from the left as long as it stays valid, recording the smallest valid length seen.

    Build target frequency map

    Count the frequency of each character in t. Track how many unique characters need to be matched (required).

    Expand the window

    Move right forward. Update the window frequency map. If a character's count matches its target count, increment formed.

    Shrink while valid

    When formed == required (all characters matched), record the window size if it's the smallest so far, then remove the leftmost character and advance left. Keep shrinking until the window becomes invalid.

    Track minimum

    Keep track of the start index and length of the smallest valid window found across the entire scan.

    Code

    string minWindow(string s, string t) {
    int n = s.size(), m = t.size();
    if (t.empty() || m > n) return "";

    unordered_map<char, int> tFreq, wFreq;
    for (char c : t) tFreq[c]++;

    int required = tFreq.size();  // unique chars to match
    int formed = 0;               // unique chars currently matched
    int left = 0;
    int bestLen = INT_MAX, bestStart = 0;

    for (int right = 0; right < n; right++) {
        char c = s[right];
        wFreq[c]++;
        if (tFreq.count(c) && wFreq[c] == tFreq[c]) {
            formed++;
        }

        // Shrink while window is valid
        while (formed == required) {
            int len = right - left + 1;
            if (len < bestLen) {
                bestLen = len;
                bestStart = left;
            }
            char lc = s[left];
            wFreq[lc]--;
            if (tFreq.count(lc) && wFreq[lc] < tFreq[lc]) {
                formed--;
            }
            left++;
        }
    }
    return (bestLen == INT_MAX) ? "" : s.substr(bestStart, bestLen);
}
// Time: O(n + m), Space: O(|alphabet|)

    Problem: Minimum Size Subarray Sum

    Given an array of positive integers and a target, find the length of the shortest contiguous subarray whose sum is greater than or equal to the target. Return 0 if no such subarray exists.

    Example: arr = [2, 3, 1, 2, 4, 3], target = 7. The answer is 2 (the subarray [4, 3]).

    Approach

    Since all elements are positive, adding more elements can only increase the sum, and removing elements can only decrease it. This monotonic property is exactly what makes the "shrink while valid" loop correct: once windowSum ≥ target, shrinking can only be undone by expanding again, never by continuing to shrink past validity by accident.

    int minSubArrayLen(int target, vector<int>& arr) {
    int n = arr.size();
    int left = 0;
    long long windowSum = 0;
    int minLen = INT_MAX;

    for (int right = 0; right < n; right++) {
        windowSum += arr[right];

        while (windowSum >= target) {
            minLen = min(minLen, right - left + 1);
            windowSum -= arr[left];
            left++;
        }
    }
    return (minLen == INT_MAX) ? 0 : minLen;
}
// Time: O(n), Space: O(1)
    Why does this work? Each element is added once (when right passes it) and removed at most once (when left passes it). The total number of add + remove operations across the entire loop is at most $2n$, giving $O(n)$ time — the same amortized argument as Part 1, instantiated here.
    Positivity is load-bearing: this exact algorithm silently breaks if the array can contain negative numbers, because a longer window is no longer guaranteed to have a larger sum. Part 9 works through the failure in detail and shows the deque-based fix.

    Edge Cases

    • No valid window exists: for minimum window substring, if t contains characters not in s (or more copies than s has), formed never reaches required; return empty. For minimum size subarray sum, return 0 if the total sum of the array is still below target.
    • t is empty: decide up front whether the empty string counts as a trivially satisfied window, or guard against it explicitly.
    • Single element already satisfies the condition: the shrink loop must still correctly record length 1 before advancing left past it.
    • Whole array/string is the only valid window: the shrink loop runs zero extra iterations beyond the final expand; the algorithm still finds it correctly.
    • Integer overflow: for large positive arrays, accumulate windowSum in a long long.

    Common Mistakes

    • Using the longest-window shrink condition by habit: writing while (invalid) here silently produces the longest valid window instead of the shortest — the direction of the while condition is the entire difference between the two templates.
    • Recording the answer outside the shrink loop: for shortest-window problems this misses every intermediate valid length except the last one checked before invalidity.
    • Forgetting the "no answer" sentinel: initialize to INT_MAX (or similar) and check for it before returning, rather than defaulting to 0 (which looks like a valid answer).
    • Assuming positivity without checking: applying the min-size-subarray-sum template to an array that can contain negative numbers is the single most common misuse of this pattern (Part 9).

    Key Takeaways

    • Shortest/coverage windows shrink while valid, recording the answer on every shrink, and stop the moment the window becomes invalid.
    • This is a mirror image of the longest-window recipe from Part 4: the while condition and the position of the answer update both flip.
    • Minimum size subarray sum relies on positivity: only positive values guarantee that shrinking monotonically decreases the sum, which is what makes "shrink while ≥ target" well-defined.
    • Both problems still cost $O(n)$ total by the same amortized argument from Part 1 — left is monotonic and moves at most $n$ times across the whole scan.
