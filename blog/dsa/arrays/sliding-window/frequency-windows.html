    Fixed-Size Frequency & Multiset Windows

    March 2026 · 18 min read

    Introduction

    Part 2 rolled scalar aggregates — sums, averages, predicate counts — across a fixed-size window. This post rolls a richer aggregate: the multiset of elements currently inside the window, represented as a frequency table. Anagram detection, permutation checks, and "does this window contain the same multiset as that target" problems are all instances of one template.

    Fixed-size frequency window invariant: at every step, windowFreq is exactly the frequency table of arr[i-k+1..i], and a single integer counter matches tracks how many distinct keys currently have windowFreq[key] == targetFreq[key].

    The key trick that makes this $O(1)$ per step instead of $O(|\Sigma|)$ per step (where $\Sigma$ is the alphabet) is not re-comparing the whole frequency table on every slide. Instead, maintain a running count of how many keys currently agree, and update that count incrementally whenever a single frequency changes.

    Problem: Permutation in String

    Given strings s1 and s2, determine whether s2 contains a contiguous substring that is a permutation (anagram) of s1.

    Example: s1 = "ab", s2 = "eidbaooo". The answer is true: s2[3..4] = "ba" is a permutation of "ab".

    Approach

    Slide a window of size |s1| across s2. Maintain a frequency array for the window and one for s1. Instead of comparing all 26 letters on every step, maintain matches: the count of letters whose window frequency currently equals the target frequency. The window is a permutation exactly when matches == 26.

    Build target frequency

    Count each character of s1. Initialize matches to the number of letters where both frequencies start at 0 (they trivially agree).

    Add the entering character

    Increment its window frequency. If the new count now equals the target count, increment matches. If it just moved from equal to one more than the target, decrement matches.

    Remove the leaving character (once the window is full)

    Decrement its window frequency, applying the same equal/no-longer-equal logic to matches in the opposite direction.

    Check matches == 26

    If all 26 letters agree, the current window is a permutation of s1.

    Code

    bool checkInclusion(string s1, string s2) {
    int n = s1.size(), m = s2.size();
    if (n > m) return false;

    vector<int> target(26, 0), window(26, 0);
    for (char c : s1) target[c - 'a']++;

    int matches = 0;
    for (int i = 0; i < 26; i++) if (target[i] == 0) matches++;

    for (int i = 0; i < m; i++) {
        int idx = s2[i] - 'a';
        window[idx]++;
        if (window[idx] == target[idx]) matches++;
        else if (window[idx] == target[idx] + 1) matches--;

        if (i >= n) {
            int ridx = s2[i - n] - 'a';
            window[ridx]--;
            if (window[ridx] == target[ridx]) matches++;
            else if (window[ridx] == target[ridx] - 1) matches--;
        }

        if (matches == 26) return true;
    }
    return false;
}
// Time: O(m), Space: O(1) (26-letter alphabet)

    Problem: Find All Anagrams in a String

    Given strings s and p, return the start indices of every substring of s that is an anagram of p. This is the same mechanism as Permutation in String, generalized from "does one exist" to "collect all of them" — and, by counting instead of collecting, also answers "how many exist."

    Example: s = "cbaebabacd", p = "abc". Output: [0, 6] (substrings "cba" and "bac").

    vector<int> findAnagrams(string s, string p) {
    int n = s.size(), m = p.size();
    vector<int> result;
    if (m > n) return result;

    vector<int> pFreq(26, 0), wFreq(26, 0);
    for (char c : p) pFreq[c - 'a']++;

    int matches = 0;
    for (int i = 0; i < 26; i++) if (pFreq[i] == 0) matches++;

    for (int i = 0; i < n; i++) {
        int idx = s[i] - 'a';
        wFreq[idx]++;
        if (wFreq[idx] == pFreq[idx]) matches++;
        else if (wFreq[idx] == pFreq[idx] + 1) matches--;

        if (i >= m) {
            int ridx = s[i - m] - 'a';
            wFreq[ridx]--;
            if (wFreq[ridx] == pFreq[ridx]) matches++;
            else if (wFreq[ridx] == pFreq[ridx] - 1) matches--;
        }

        if (i >= m - 1 && matches == 26) result.push_back(i - m + 1);
    }
    return result;
}
// Time: O(n), Space: O(1) (26-letter alphabet)
    Counting instead of collecting: replace result.push_back(...) with count++ and you have the "count anagram occurrences" variant — identical algorithm, different output.

    Generalizing the Matches Counter

    The matches trick is not specific to strings or to 26 letters. It applies to any fixed-size window whose validity is "the window's frequency table equals a target frequency table." The three-way update rule is always the same:

    // When freq[key] changes by +1 or -1 after an add/remove:
if (freq[key] == target[key])            matches++;   // just became equal
else if (freq[key] == target[key] + 1 ||
         freq[key] == target[key] - 1)   matches--;   // just became unequal
// (the "+1"/"-1" branch to check depends on whether you just incremented or decremented freq[key])
    Alphabet sizeStructureSpace
    Small & fixed (lowercase letters, digits, DNA bases)array<int, 26> or similar$O(1)$
    Unicode / arbitrary integersunordered_map<T, int>$O(\min(k, |\Sigma|))$
    Need matches == distinctKeysInTarget instead of == 26Same map-based structure; compare against target.size()$O(\min(k, |\Sigma|))$

    With a hash map, initialize matches = 0 (not "count of zero-agreements", since absent keys are implicitly zero on both sides and you only care about the keys that actually appear in the target), and compare matches == (int)target.size() instead of == 26. The update logic is otherwise identical.

    This exact template also answers numeric multiset equality: "does any window of size $k$ in array a have the same multiset of values as array b?" — just swap char for the array's element type and use a hash map.

    Edge Cases

    • |s1| > |s2| (or |p| > |s|): no window of the right size exists — return early.
    • Repeated characters in the target: the frequency-based approach handles duplicates correctly automatically; do not dedupe the target before counting.
    • Target is empty: every window (including the empty one) trivially matches; special-case this if the problem allows an empty pattern.
    • Whole string equals the target length: the loop still runs correctly; there is exactly one window to check.
    • Case sensitivity: decide up front whether 'a' and 'A' are the same key — this changes which array/map you build.

    Common Mistakes

    • Recomputing matches from scratch every step: defeats the purpose — that is $O(|\Sigma|)$ per step, turning an $O(n)$ algorithm into $O(n|\Sigma|)$.
    • Wrong comparison target after decrementing: after a decrement, the "just became unequal" check is freq[key] == target[key] - 1, not + 1 — mixing these up silently corrupts matches.
    • Off-by-one on the removal index: the character leaving when the right edge is at i is at i - m (using the window's own length m), matching the same pattern as Part 2's fixed windows.
    • Forgetting the removal step only starts once the window is full (guard with if (i >= m) or equivalent).

    Key Takeaways

    • Fixed-size frequency windows generalize scalar rolling aggregates to a whole multiset, updated incrementally with add/remove on a frequency table.
    • The matches counter avoids re-comparing the entire alphabet on every slide, keeping each step $O(1)$ instead of $O(|\Sigma|)$.
    • Use a fixed-size array for small, known alphabets; use a hash map for large or unbounded alphabets, comparing against target.size() instead of a hardcoded 26.
    • The same template answers "does a window exist," "find all windows," and "count all windows" — only the action taken when matches reaches its target changes.
