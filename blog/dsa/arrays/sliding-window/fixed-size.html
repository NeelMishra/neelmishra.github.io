    Fixed-Size Fundamentals & Rolling Aggregates

    March 2026 · 22 min read

    Introduction

    A fixed-size sliding window maintains a window of exactly $k$ elements that moves one position at a time across the array. At each step, one element enters the window on the right and one element leaves on the left. The window size never changes.

    This is the simpler of the two sliding window variants. The pattern is mechanical: build the initial window, then slide it forward, updating your running aggregate with each move.

    Fixed-size window invariant: At every step after initialization, the window contains exactly $k$ consecutive elements: arr[i-k+1..i].

    Problem: Maximum Sum Subarray of Size K

    Given an integer array and a number $k$, find the maximum sum among all contiguous subarrays of size $k$.

    Example: arr = [4, 2, 1, 7, 8, 1, 2, 8, 1, 0], k = 3. The answer is 16. The first maximum window is [1, 7, 8] at indices 2 through 4; [7, 8, 1] at indices 3 through 5 ties it.

    Step-by-Step Walkthrough

    Build the initial window

    Sum the first $k = 3$ elements: 4 + 2 + 1 = 7. Set maxSum = 7.

    Slide to position 1

    Remove arr[0] = 4, add arr[3] = 7. New sum: 7 - 4 + 7 = 10. Max: 10.

    Slide to position 2

    Remove arr[1] = 2, add arr[4] = 8. New sum: 10 - 2 + 8 = 16. Max: 16.

    Continue sliding

    The next window also sums to 16, while every later window is smaller. The answer therefore stays 16.

    Code

    int maxSumSubarray(vector<int>& arr, int k) {
    int n = arr.size();
    if (k <= 0 || k > n) {
        throw invalid_argument("k must be in [1, arr.size()]");
    }
    int windowSum = 0;

    // Build initial window
    for (int i = 0; i < k; i++) {
        windowSum += arr[i];
    }
    int maxSum = windowSum;

    // Slide the window
    for (int i = k; i < n; i++) {
        windowSum += arr[i];       // new element enters
        windowSum -= arr[i - k];   // old element leaves
        maxSum = max(maxSum, windowSum);
    }
    return maxSum;
}
// Time: O(n), Space: O(1)

    Problem: Averages of Subarrays of Size K

    Given an array of $n$ numbers and an integer $k$, compute the average of every contiguous subarray of size $k$.

    Example: arr = [1, 3, 2, 6, -1, 4, 1, 8, 2], k = 5.

    Expected output: [2.2, 2.8, 2.4, 3.6, 2.8].

    vector<double> subarrayAverages(vector<int>& arr, int k) {
    int n = arr.size();
    vector<double> result;
          if (k <= 0 || k > n) return result;

          double windowSum = 0;
    for (int i = 0; i < k; i++) {
        windowSum += arr[i];
    }
    result.push_back(windowSum / k);

    for (int i = k; i < n; i++) {
        windowSum += arr[i] - arr[i - k];
        result.push_back(windowSum / k);
    }
    return result;
}
// Time: O(n), Space: O(n-k+1) for output

    Generalizing: Rolling Aggregates

    Max-sum and averages are both instances of a broader pattern: any aggregate that supports an $O(1)$ add and an $O(1)$ remove can be rolled across a fixed-size window with the same skeleton.

    AggregateAdd arr[i]Remove arr[i-k]Rolls in $O(1)$?
    Sumsum += xsum -= xYes
    Averagesum += xsum -= x, divide by $k$Yes
    Count matching a predicate (e.g. evens)if (pred(x)) cnt++if (pred(x)) cnt--Yes
    Frequency table / distinct countfreq[x]++freq[x]--Yes (covered in Part 3)
    Product (no zero, positive only)prod *= xprod /= xYes, but fragile — a zero entering breaks division on removal (Part 9)
    Maximum / minimumpush to structureRemoving an arbitrary element (possibly the current max) needs the next-largest, which a scalar can't tell youNo — needs a monotonic deque (Part 7)

    The reason max/min don't roll with a plain variable is worth internalizing now: a sum "forgets" which element contributed what, so subtracting the leaving element is always safe. A maximum does not "forget" safely — if the maximum is the element leaving the window, you need to already know the second-largest remaining element, and that information was never tracked. This is exactly the gap Part 7's monotonic deque fills.

    // Count of elements satisfying a predicate in every window of size k
// (a stand-in for "rolling count", the same shape as rolling sum)
vector<int> countMatchingInWindows(vector<int>& arr, int k, bool (*pred)(int)) {
    int n = arr.size();
    vector<int> result;
    if (k <= 0 || k > n) return result;

    int cnt = 0;
    for (int i = 0; i < k; i++) if (pred(arr[i])) cnt++;
    result.push_back(cnt);

    for (int i = k; i < n; i++) {
        if (pred(arr[i]))     cnt++;   // add entering element
        if (pred(arr[i - k])) cnt--;   // remove leaving element
        result.push_back(cnt);
    }
    return result;
}
// Time: O(n), Space: O(n-k+1) for output

    Problem: Maximum of Each Window (Naive)

    Given an array and window size $k$, find the maximum element in each window of size $k$.

    The naive approach scans each window for its maximum, giving $O(n \times k)$ time. We present the naive version here as a motivating failure case; the optimized deque-based $O(n)$ solution is the entire subject of Part 7.

    vector<int> maxInWindow_naive(vector<int>& arr, int k) {
    int n = arr.size();
    vector<int> result;
    for (int i = 0; i <= n - k; i++) {
        int windowMax = arr[i];
        for (int j = i + 1; j < i + k; j++) {
            windowMax = max(windowMax, arr[j]);
        }
        result.push_back(windowMax);
    }
    return result;
}
// Time: O(n*k), Space: O(n-k+1)
    Why naive here? As the table above shows, a plain fixed-size window cannot maintain the maximum in $O(1)$ per step, because removing the maximum requires knowing the next-largest element — information a scalar variable doesn't retain. Part 7 solves this with a monotonic deque.

    Edge Cases

    • k > n: No valid window exists. Return empty or an appropriate sentinel value.
    • k = 1: Each element is its own window. The answer is simply the max/min/average of the array itself.
    • k = n: Only one window (the entire array). Return the aggregate of all elements.
    • All elements equal: Every window produces the same result. The algorithm still works correctly.
    • Negative numbers: The sliding window technique handles negatives correctly for sum-based problems. The max sum might be negative if all elements are negative.

    Common Mistakes

    • Off-by-one in loop bounds: The sliding loop runs from i = k to i < n, not i <= n.
    • Forgetting the initial window: The initial window must be built separately before the sliding loop starts.
    • Using the wrong removal index: When the right edge is at index i, the element leaving is at index i - k, not i - k + 1.
    • Integer overflow: For large arrays with large values, use long long instead of int for the sum.

    Key Takeaways

    • Fixed-size windows maintain exactly $k$ elements. The window slides one position per step.
    • Build the initial window first, then slide by removing one element and adding another.
    • The technique generalizes to any aggregate with $O(1)$ add and $O(1)$ remove: sums, averages, predicate counts, and frequency tables (Part 3).
    • Maximum/minimum are the classic counterexample — they don't support $O(1)$ removal from a scalar, so they need the monotonic deque of Part 7.
    • When the aggregate supports an $O(1)$ add/remove update, a complete fixed-window scan takes $O(n)$ time.
