    Dual-Deque / Range-Constrained Windows

    March 2026 · 16 min read

    Introduction

    Part 7 tracked a window's maximum or minimum with one monotonic deque. Some problems need both extrema of the same window at the same time: "find the longest subarray where max − min ≤ limit." The fix is exactly what it sounds like — run a max-deque and a min-deque in parallel over the same left/right pointers, and shrink whenever their difference exceeds the limit.

    Invariant: at every step, maxDeque.front() and minDeque.front() give the max and min of arr[left..right] respectively, and the window is valid iff arr[maxDeque.front()] - arr[minDeque.front()] ≤ limit.

    Problem: Longest Continuous Subarray With Absolute Diff ≤ Limit

    Given an array of integers and an integer limit, find the length of the longest contiguous subarray such that the absolute difference between any two elements is at most limit. Since the maximum absolute difference in any subarray is exactly max - min of that subarray, this reduces to "longest subarray with max - min ≤ limit."

    Example: arr = [8, 2, 4, 7], limit = 4. The answer is 2 (the subarray [4, 7], or equivalently [8]/[2] alone — but [2, 4] also has diff 2 ≤ 4, giving length 2 as well; the longest valid run is length 2).

    Approach

    This is the Part 4 longest-window recipe (expand, shrink while invalid, measure) with the validity check upgraded from a hash-map lookup to a pair of monotonic deques.

    Expand

    Push right onto both deques, maintaining each one's monotonicity (pop smaller/larger-or-equal trailing entries as in Part 7).

    Check validity

    Compare arr[maxDeque.front()] - arr[minDeque.front()] against limit.

    Shrink while invalid

    Advance left. If left now exceeds the index at the front of either deque, pop that deque's front too — the element has left the window in both structures.

    Measure

    Once valid, update answer = max(answer, right - left + 1).

    Code

    int longestSubarray(vector<int>& arr, int limit) {
    int n = arr.size();
    if (limit < 0) return 0;

    deque<int> maxDq, minDq;  // indices; maxDq decreasing, minDq increasing
    int left = 0, answer = 0;

    for (int right = 0; right < n; right++) {
        while (!maxDq.empty() && arr[maxDq.back()] <= arr[right]) maxDq.pop_back();
        maxDq.push_back(right);

        while (!minDq.empty() && arr[minDq.back()] >= arr[right]) minDq.pop_back();
        minDq.push_back(right);

        while ((long long)arr[maxDq.front()] - arr[minDq.front()] > limit) {
            if (maxDq.front() == left) maxDq.pop_front();
            if (minDq.front() == left) minDq.pop_front();
            left++;
        }

        answer = max(answer, right - left + 1);
    }
    return answer;
}
// Time: O(n) amortized, Space: O(n) worst case for each deque
    Why the shrink loop terminates: each shrink strictly increases left, and once the window shrinks enough to exclude the current global max or min offender, the new front of the corresponding deque is a value close enough to the other extreme. In the worst case the loop shrinks down to a single element, which trivially satisfies max - min = 0 ≤ limit (assuming limit ≥ 0), so termination is guaranteed.

    Why This Is Still $O(n)$

    Nothing new is needed beyond Part 1's amortized argument, applied twice: each index is pushed onto maxDq exactly once and popped at most once (from either end), and the same holds independently for minDq. left is still monotonic and advances at most $n$ times total. Total work is $O(n) + O(n) + O(n) = O(n)$ — the constant factor roughly doubles compared to a single monotonic deque, but the asymptotic bound is unchanged.

    Edge Cases

    • limit = 0: only runs of identical consecutive values are valid; the algorithm handles this correctly since max - min = 0 is required.
    • All elements identical: both deques degenerate to holding a single index at a time; the whole array is one valid window.
    • Negative limit: no non-empty window can be valid because max - min ≥ 0. Return 0 before building the deques; otherwise a shrink loop that tries to make an impossible window valid can empty both deques and dereference their fronts.
    • Single element: trivially valid for any limit ≥ 0; answer is at least 1.
    • Negative array values: unlike Part 9's sum/product windows, this problem never sums anything — only compares max and min — so negative values inside the array cause no correctness issues at all.

    Common Mistakes

    • Popping only one deque's front when shrinking: both deques must be checked (with independent if, not else if) because the element leaving the window might be the current front of neither, one, or both deques.
    • Inconsistent duplicate handling: strict </> keeps equal-valued indices, while ≤/≥ keeps only the newest equal value. Both policies are correct when index expiry is handled consistently; the non-strict policy simply stores fewer redundant entries.
    • Recomputing max/min by scanning the window on every step: defeats the entire purpose — that's $O(nk)$, not $O(n)$.
    • Forgetting that both deques store indices, not values — needed to detect when the window's boundary passes a deque's front entry.

    Key Takeaways

    • Range-constrained windows ("max − min ≤ limit") need both extrema of the same window at once, so run a max-deque and a min-deque in parallel.
    • The overall algorithm is still the Part 4 longest-window recipe; only the validity check and the window-state maintenance change.
    • When shrinking, check both deques' fronts independently against the departing index — the element leaving might be tracked by one, both, or neither deque.
    • The amortized $O(n)$ bound from Part 1 still holds, applied independently to each deque.
