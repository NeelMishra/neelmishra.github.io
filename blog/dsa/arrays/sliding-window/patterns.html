    Monotonic Deque: Window Maxima & Minima

    March 2026 · 18 min read

    Introduction

    Part 2 flagged the gap: a plain fixed-size window cannot maintain the maximum (or minimum) element in $O(1)$ per step, because removing the current maximum requires knowing the next-largest element — information a scalar variable never retained. This post fills that gap with the monotonic deque, a data structure that answers "what is the max of the current window?" in $O(1)$ while still processing the whole array in amortized $O(n)$.

    Monotonic deque invariant: the deque stores array indices, never values directly, in strictly decreasing order of arr[index] (for a maximum deque) restricted to indices still inside the current window. The front is always the index of the window's maximum.

    Problem: Sliding Window Maximum

    Given an array and window size k, find the maximum element in each window of size k as the window slides from left to right.

    Example: arr = [1, 3, -1, -3, 5, 3, 6, 7], k = 3. Output: [3, 3, 5, 5, 6, 7].

    Approach: Monotonic Deque

    A deque (double-ended queue) maintains indices of array elements in decreasing order of their values. The front of the deque always holds the index of the current window's maximum.

    Remove expired elements

    If the front of the deque is outside the window (its index is less than i - k + 1), pop it from the front.

    Maintain monotonicity

    Pop elements from the back of the deque whose values are less than or equal to arr[i]. They can never be the maximum for any future window.

    Push current index

    Add the current index i to the back of the deque.

    Record the maximum

    Once the window is fully formed (i >= k - 1), the front of the deque is the index of the maximum element. Record arr[deque.front()].

    Code

    vector<int> maxSlidingWindow(vector<int>& arr, int k) {
    int n = arr.size();
    deque<int> dq;  // stores indices
    vector<int> result;
    if (k <= 0 || k > n) return result;

    for (int i = 0; i < n; i++) {
        // Remove indices outside the window
        if (!dq.empty() && dq.front() < i - k + 1) {
            dq.pop_front();
        }

        // Remove smaller elements from back
        while (!dq.empty() && arr[dq.back()] <= arr[i]) {
            dq.pop_back();
        }

        dq.push_back(i);

        // Record maximum once window is formed
        if (i >= k - 1) {
            result.push_back(arr[dq.front()]);
        }
    }
    return result;
}
// Time: O(n), Space: O(k)
    Why $O(n)$? Each index is pushed onto the deque exactly once and popped at most once. Across all iterations, the total number of push and pop operations is at most $2n$.

    Why the Monotonic Deque Works

    The deque contains indices sorted in decreasing order of their array values. Here is why each operation is correct:

    • Pop from front (expired): If the front index is outside the current window, it cannot be the maximum. Remove it.
    • Pop from back (smaller): If arr[dq.back()] ≤ arr[i], then dq.back() can never be the maximum in any window that includes index i. The new element is larger and has a later index (stays in the window longer). Remove the smaller element.
    • Front is always the max: After the two removal steps, the front of the deque holds the index of the largest element in the current window.

    The Symmetric Case: Window Minima

    Everything above mirrors exactly for minima: keep the deque increasing instead of decreasing, and pop from the back while arr[dq.back()] ≥ arr[i]. The front is then always the index of the window's minimum. This symmetric structure is exactly what Part 8 needs, run twice in parallel (once for max, once for min) to maintain both extrema of the same window simultaneously.

    // Same algorithm, minimum instead of maximum: flip both comparisons.
vector<int> minSlidingWindow(vector<int>& arr, int k) {
    int n = arr.size();
    deque<int> dq;
    vector<int> result;
    if (k <= 0 || k > n) return result;

    for (int i = 0; i < n; i++) {
        if (!dq.empty() && dq.front() < i - k + 1) dq.pop_front();
        while (!dq.empty() && arr[dq.back()] >= arr[i]) dq.pop_back();
        dq.push_back(i);
        if (i >= k - 1) result.push_back(arr[dq.front()]);
    }
    return result;
}
// Time: O(n), Space: O(k)

    Edge Cases

    • k > n or k ≤ 0: no window exists; return an empty result rather than iterating.
    • Duplicate values: both ≤ and < are correct. Using ≤ discards the older equal value and keeps the deque smaller; using < retains equal-valued indices until they expire from the front.
    • Strictly increasing or strictly decreasing arrays: the deque degenerates to holding only 1 or up to k indices respectively — both are handled correctly by the same code.
    • k == 1: every element is its own window; the deque always holds exactly one index.
    • k == n: exactly one output value, the max/min of the whole array.

    Common Mistakes

    • Storing values instead of indices: you cannot check "is the front outside the window" without the index — storing raw values loses the position information needed for expiry.
    • Changing the equality rule without understanding tie handling: ≤ keeps only the newest equal maximum, while < keeps all equal maxima. Either is correct when expiry uses indices consistently, but document the chosen policy.
    • Forgetting to check i >= k - 1 before recording an output: emits values for partial windows that haven't reached size k yet.
    • Reasoning about amortized cost per iteration instead of in aggregate: a single iteration's back-popping loop can run many times, but summed across the whole algorithm each index is pushed once and popped at most once — the same amortized argument as Part 1, applied to deque operations instead of pointer advances.

    Key Takeaways

    • A monotonic deque stores indices in decreasing (max) or increasing (min) order of their values, restricted to the current window.
    • Two removal rules keep it correct: pop expired indices from the front, and pop dominated indices from the back before pushing the new index.
    • The front of the deque is always the current window's extremum, answered in $O(1)$.
    • Total cost is $O(n)$ amortized: each index is pushed exactly once and popped at most once across the whole scan.
    • This is the standard fix for the gap identified in Part 2: extrema don't support $O(1)$ removal from a scalar, but they do from a monotonic deque.
