    Agent Reliability & Debugging: Step-Level Fault Localization, Trajectory Uncertainty Estimation, and Failure-to-Fix Flywheels

    October 2026 · 5 min read

    Why a $95\%$ per-step accuracy degrades to $0.95^8 = 66.3\%$ across an 8-step agent trajectory, how to isolate the exact step $t^*$ and tool invocation $a_{t^*}$ where a multi-step agent run went wrong using OpenTelemetry DAG spans and counterfactual prefix replay, how to quantify step-level uncertainty via token log-probabilities and semantic entropy, and how we debugged and hardened “Aria” at VogueCart to drive +58.86% engaged MAU and +31.74% repeat usage.

    In a multi-step agent, failures rarely announce themselves at the step where they actually occur. When an e-commerce shopping assistant recommends an out-of-budget polyester gown to a user who asked for an olive linen midi dress under \$90, looking only at the final synthesizer prompt suggests a generation hallucination. In reality, the failure happened two steps earlier when a tool call serialized an overly strict attribute filter (color="olive_drab"), received $0$ catalog hits, and triggered a naive fallback that wiped the user’s budget and fabric constraints.

    $$t^* = \arg\max_{t \in \{1,\dots,T\}} \Delta Q(t), \qquad \Delta Q(t) = \mathbb{P}\!\left(\text{Pass} \mid \tau_{1:t-1},\, a_t^*\right) - \mathbb{P}\!\left(\text{Pass} \mid \tau_{1:t}\right).$$
