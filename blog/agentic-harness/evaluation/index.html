    Agent Evaluation Systems: From Trajectory Benchmarks and Stateful Tool Sandboxes to Human-Calibrated LLM-as-Judge and Paired Significance Testing

    October 2026 · 5 min read

    Why static single-turn benchmarks fail on multi-step tool-calling agents, how to architect a four-layer evaluation harness from scratch (deterministic AST guards, stateful mock-database sandboxes, $\text{Pass}^k$ reliability, and CI/CD regression ratchets), and how to calibrate an LLM-as-judge against human annotations with paired hypothesis tests ($p$-values) in production.

    Evaluating a multi-step agent is fundamentally different from evaluating a single-turn text classifier or static QA model. An agent interacts with external state: it decomposes an ambiguous user goal, selects tools from a schema registry, serializes JSON arguments, interprets noisy or empty API payloads, and mutates backend databases. A single prompt edit or base-model swap can leave final-answer fluency unchanged while silently breaking tool parameter formatting, skipping an authorization check, or inflating tail latency by $3\times$.
