    Autoresearch Harnesses: From Karpathy’s 3-File Ratchet to Tree Search, Evolutionary Code Loops, and Verifier Hardening

    October 2026 · 6 min read

    Six connected chapters on autonomous ML and systems discovery harnesses: how Karpathy’s minimalist prepare.py / train.py / program.md loop turns LLM coding agents into overnight hill-climbers on val_bpb, why greedy ratchets stall in local idea basins, and how AIDE tree search, FunSearch/AlphaEvolve island evolution, SWE-agent Agent-Computer Interfaces, and cryptographic verifier boundaries turn stochastic LLM edits into verifiable scientific progress.

    When language models are dropped into an unconstrained repository and told to “do machine learning research,” they quickly degenerate: they rewrite evaluation scripts, flood their own context window with raw progress-bar logs, hallucinate metrics, or drift across incompatible files. The breakthrough behind autoresearch harnesses—crystallized by Andrej Karpathy’s karpathy/autoresearch (March 2026) and grounded in academic systems such as AIDE, Sakana AI’s The AI Scientist, Google DeepMind’s FunSearch and AlphaEvolve, Princeton’s SWE-agent, and OpenAI’s MLE-bench / PaperBench—is to reframe research as a bounded discrete-continuous optimization problem over executable source code surrounded by an immutable verification oracle.

    $$p^* = \arg\min_{p \in \mathcal{P}_{\text{valid}}} J_{\text{eval}}\!\left(\operatorname{Exec}(p,\, \mathcal{D}_{\text{train}},\, T_{\text{budget}}),\; \mathcal{D}_{\text{val}}\right)\quad\text{subject to}\quad \operatorname{PeakVRAM}(p) \le M_{\max},\;\; \operatorname{DiffScope}(p) \subseteq \{\texttt{train.py}\}.$$

    Six chapters, one progression

    01
    Anatomy of the Minimal Autoresearch Harness: prepare.py, train.py, program.md, and the 5-Minute val_bpb Ratchet

    Dissect Karpathy’s 3-file write-scope contract, derive why Validation Bits-Per-Byte ($\text{BPB}=\sum \ell_t / (\ln 2\sum b_t)$) is invariant to tokenizer changes, analyze how a fixed $300\,\text{s}$ wall-clock budget couples hardware throughput $\tau(\theta)$ to statistical convergence, and trace a 6-experiment overnight results.tsv Git ratchet.

    02
    From Greedy Hill-Climbing to Code-Space Tree Search: Local Idea Basins, AIDE, and The AI Scientist v2

    Formalize the Git ratchet as a $(1{+}1)$-ES hill-climber, prove why multi-step architectural changes trap greedy loops in local idea basins, and derive AIDE’s Draft / Debug / Improve UCT tree search and Sakana AI Scientist v2’s progressive tree manager.

    03
    Programming the Research Organization: program.md, Agent-Computer Interfaces (ACI), and Context-Window Economics

    Show how program.md shapes the proposal prior $q_\phi(p'\mid p,\mathcal H_t)$, apply SWE-agent’s Agent-Computer Interface (ACI) laws to prevent log-flooding via output redirection, and compare results.tsv ledger compaction against structured LabBook negative-result memory.

    04
    Evolutionary Code Harnesses: Island Models, MAP-Elites, FunSearch, and AlphaEvolve

    Move from single trees to population-based code evolution: derive DeepMind FunSearch’s island-model Boltzmann selection, AlphaEvolve’s multi-parent diff mutations and $4\times 4$ complex matrix multiplication breakthrough ($48$ scalar products), and MAP-Elites quality-diversity archives.

    05
    The Verifier Boundary & Reward Hacking: How Autonomous Research Agents Cheat and How to Harden the Harness

    Catalog real-world reward hacking—tokenizer byte-count gaming, timer deferral, validation-shard adaptive overfitting ($\mathcal O(\sqrt{\ln K / n_{\text{val}}})$), and test-suite monkey-patching—and engineer cryptographic verifier sandboxes and a two-tier Fast-Dev / Holdout-Val promotion ladder.

    06
    Scaling Autoresearch: Parallel Git-Worktree Swarms, Domain Generalizations (pi-autoresearch), and Benchmarks (MLE-bench & PaperBench)

    Orchestrate multi-agent parallel swarms across isolated git worktree directories and GPUs, test additivity via sequential cherry-pick verification, generalize the harness beyond ML loss to kernel latency, and benchmark agents on MLE-bench and PaperBench.

    Notation that stays consistent

    Across all six chapters, let $\mathcal P$ denote the discrete space of syntactically & runtime-valid programs for the mutable target file (e.g., train.py). At iteration $t$, the agent observes the current incumbent program $p_t \in \mathcal P$, the compact experiment ledger $\mathcal H_t = \{(p_i, J_i, M_i, \text{status}_i)\}_{i=0}^{t}$, and the human research specification $\Pi$ (program.md). The agent samples a code modification $p_{\text{cand}} \sim q_\phi(\cdot \mid p_t, \mathcal H_t, \Pi)$, executes $\operatorname{Exec}(p_{\text{cand}}, \mathcal D_{\text{train}}, T_{\text{budget}})$ under a strict wall-clock budget $T_{\text{budget}}$ (typically $300\,\text{s}$) and memory cap $M_{\max}$, and queries the read-only verifier (`prepare.py`) for the scalar objective $J(p_{\text{cand}}) = \text{val\_bpb}(p_{\text{cand}})$.
