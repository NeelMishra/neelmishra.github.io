    Agent Harness Design: Parallel DAG Planning, Self-Verification Loops, KV-Cache Context Engineering, and E-Commerce System Design

    October 2026 · 6 min read

    Why sequential ReAct loops bottleneck on serial tool latency, how LLMCompiler-style DAG planners reduce critical-path latency from $\sum_i L_i$ to $\max_{\pi \in \text{Paths}(G)} \sum_{i \in \pi} L_i$, why intrinsic LLM self-correction fails without external deterministic verifiers, how append-only prefix stability preserves $92\%+$ KV-cache hit rates across multi-turn trajectories, and how to architect and evaluate a production shopping-assistant agent for OmniMart.

    An LLM is only a conditional next-token distribution $p_\theta(y_t \mid x, y_{<t})$. Turning that distribution into a reliable, sub-second production system requires an agent harness: the surrounding orchestration runtime that compiles user requests into parallel execution graphs, verifies intermediate tool outputs against deterministic constraints, manages working context without invalidating GPU KV-cache prefixes, and persists long-term user preferences across sessions.

    $$L_{\text{DAG}}(G) = \max_{\pi \in \text{Paths}(G)} \sum_{v \in \pi} \left(L_{\text{LLM}}(v) + L_{\text{tool}}(v)\right) \ll \sum_{t=1}^{T} \left(L_{\text{LLM},t} + L_{\text{tool},t}\right) = L_{\text{ReAct}}.$$
