    4. System & New-Market Cold-Start: Day-0 Priors, Cross-Domain Signals & Unbiased Logging

    October 2026 · System Cold-Start · 12 min read

    The hardest cold-start regime is System Cold-Start (also called New-Market or Day-0 Cold-Start): launching a brand-new product, marketplace, or regional vertical when the interaction matrix is completely empty ($R = \emptyset$)—neither users nor items have any local click history. Worse still, how you rank items on Day 0 determines which items get seen, which directly biases the training logs you collect for your first learned ranker! This chapter covers the four core pillars of System Cold-Start: (1) Day-0 Calibrated Scoring & Wilson Lower Bounds, (2) Cross-Domain & Cross-Market Signal Transfer, (3) Synthetic Relevance Bootstrapping, and (4) Propensity-Logged Stochastic Ranking for unbiased policy upgrades.

    1. Day-0 Zero-Interaction Scoring & Wilson Lower Bound Priors

    On Day 0 ($R = \emptyset$), a search or recommendation service cannot train a collaborative filtering model or a click-through-rate (CTR) classifier. Instead, it constructs a Zero-Interaction Prior Score $S_0(q, d)$ combining standardized lexical matching (such as BM25), off-the-shelf semantic similarity (using any pretrained text or multimodal encoder), catalog quality completeness $Q(d)$ (image resolution, description completeness, seller rating), and a confidence-penalized popularity term:

    $$S_0(q, d) = w_{\text{lex}}\,\tilde{s}_{\text{BM25}}(q, d) + w_{\text{sem}}\,\text{sim}(q, d) + w_{\text{qual}}\,Q(d) + w_{\text{pop}}\,\text{WLB}(s_d, n_d)$$

    Why use the Wilson Lower Bound ($\text{WLB}$) as the early popularity/rating signal during the first week of traffic instead of raw CTR $\hat{p} = s_d / n_d$ or simple Laplace smoothing? Because on Day 1, an item with $2$ clicks out of $2$ impressions ($\hat{p} = 100\%$) would outrank a proven item with $95$ clicks out of $100$ impressions ($\hat{p} = 95\%$). Solving for the lower bound of the binomial confidence interval at confidence level $z = z_{1-\alpha/2}$ (e.g., $z = 1.96$ for $95\%$ confidence) yields:

    $$\text{WLB}(s_d, n_d) = \frac{\hat{p} + \frac{z^2}{2n_d} - z\sqrt{\frac{\hat{p}(1 - \hat{p})}{n_d} + \frac{z^2}{4n_d^2}}}{1 + \frac{z^2}{n_d}}, \qquad \hat{p} = \frac{s_d}{n_d}$$

    At $n_d = 0$, $\text{WLB}(0, 0) = 0$; at $s_d = 2, n_d = 2$ ($100\%$ raw CTR), $\text{WLB}(2, 2) = \mathbf{34.2\%}$, whereas at $s_d = 95, n_d = 100$ ($95\%$ raw CTR), $\text{WLB}(95, 100) = \mathbf{88.8\%}$.

    2. Cross-Domain & Cross-Market Signal Transfer

    Often an organization is not launching its very first product, but expanding into a new vertical or region—for instance, a food-delivery app launching grocery delivery, an e-commerce platform entering a new country, or a music app adding podcasts. Even when the target domain $\mathcal{D}_T$ starts with zero interactions, the mature source domain $\mathcal{D}_S$ provides valuable warm-start structure:

    • Overlapping Users (User Bridge): When existing users try the new vertical, their historical preferences in the source domain provide an immediate prior for their tastes in the target domain.
    • Overlapping Items or Shared Taxonomy (Catalog Bridge): When launching in a new region with a shared product catalog or category hierarchy, item popularity and co-purchase statistics from mature markets serve as strong priors until local interactions accumulate.

    To operationalize this transfer, cross-domain recommendation models (such as embedding-mapping bridges like EMCDR or PTUPCDR, domain-adaptation regularizers, or shared multi-task bottom towers) can be used to map source representations into the target space.

    3. Bootstrapping with Synthetic Relevance Judgments

    Before real users generate enough clicks to train a supervised ranker, teams can bootstrap an initial labeled dataset $\mathcal{D}_{\text{syn}}$ offline:

    1. Synthetic Query Generation: Sample catalog items and prompt an LLM to generate realistic head, torso, and tail queries that a user might type when looking for those items.
    2. Candidate Grading: Retrieve candidate items for each query using lexical and semantic matching, and score them with a rubric-calibrated LLM judge (e.g., 0 = Irrelevant to 3 = Exact Match) to tune feature weights or distill a lightweight Day-0 ranker before launch.

    4. Propensity-Instrumented Stochastic Logging for Unbiased Day-7 LTR

    If your Day-0 ranker deterministically sorts by $S_0(q, d)$ and only displays the top $K = 10$ items, then every item ranked at position $\ge 11$ by the initial heuristic receives zero impressions ($\pi_0(d \mid q) = 0$). When you train your first Learning-to-Rank model on Day 7, it is completely blind to those items (selection bias deadlock).

    To guarantee nonzero exposure ($\pi_0(d \mid q) > 0$) across reasonable candidates while preserving Day-0 relevance, systems sample the displayed top-$K$ slate sequentially without replacement from a temperature-controlled Plackett–Luce distribution over the top-$M$ ($M \approx 50$) candidates and log the exact inclusion propensity $\pi_0(d_i \mid q)$ alongside every impression for Inverse Propensity Scoring (IPS / SNIPS):

    $$P_{\text{PL}}(d_i \text{ at slot } 1 \mid q) = \frac{\exp\!\big(S_0(q, d_i) / T_{\text{log}}\big)}{\sum_{j=1}^{M} \exp\!\big(S_0(q, d_j) / T_{\text{log}}\big)}, \qquad \mathcal{L}_{\text{SNIPS}}(\theta) = \frac{\sum_{(q, i, c_i)} \frac{c_i}{\text{clip}(\pi_0(i \mid q), \epsilon)} \,\ell\big(f_\theta(q, d_i)\big)}{\sum_{(q, i, c_i)} \frac{1}{\text{clip}(\pi_0(i \mid q), \epsilon)}}$$

    6. Reference Implementation: Wilson Lower Bound & Plackett–Luce Logger

    import numpy as np

def wilson_lower_bound(clicks: np.ndarray, views: np.ndarray, z: float = 1.96) -> np.ndarray:
    """Computes the exact Binomial Wilson Lower Bound (WLB) for small-sample Day-0/Day-1 items."""
    safe_n = np.maximum(views, 1.0)
    p_hat = clicks / safe_n
    z2 = z * z
    denom = 1.0 + z2 / safe_n
    center = p_hat + z2 / (2.0 * safe_n)
    rad = z * np.sqrt((p_hat * (1.0 - p_hat) + z2 / (4.0 * safe_n)) / safe_n)
    wlb = (center - rad) / denom
    return np.where(views > 0, wlb, 0.0)

def plackett_luce_propensities(scores: np.ndarray, temperature: float = 0.15) -> np.ndarray:
    """Computes slot-1 inclusion propensities for stochastic top-K logging."""
    logits = (scores - np.max(scores)) / temperature
    exp_s = np.exp(logits)
    return exp_s / np.sum(exp_s)

views  = np.array([2.0, 100.0, 10.0, 50.0])
clicks = np.array([2.0,  48.0,  6.0, 25.0])
wlb = wilson_lower_bound(clicks, views)
propensities = plackett_luce_propensities(wlb, temperature=0.05)
print("95% WLB (%):              ", (wlb * 100).round(2))
print("Slot-1 Propensities (%):  ", (propensities * 100).round(1))
