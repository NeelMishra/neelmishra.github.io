2. Learning to Rank: Pointwise, Pairwise (RankNet) & Listwise (LambdaRank / LambdaMART)

Learning to Rank · 13 min read

We evaluate search rankings at the top of the page using position-discounted metrics like nDCG@K, where rank position $r(i)$ comes from sorting model scores $s_i$. Because sorting is a piecewise-constant step function, the gradient of nDCG with respect to $s_i$ is zero almost everywhere and undefined at ties. Learning to Rank (LTR) bridges this gap across three paradigms—Pointwise, Pairwise (RankNet), and Listwise (LambdaRank / LambdaMART)—culminating in multiplying pairwise gradients by $|\Delta \text{nDCG}_{ij}|$.

1. Pointwise LTR: Why Regression Misses the Goal

Given a query $q$ and candidate documents with human relevance grades $y_i \in \{0, 1, 2, 3, 4\}$, Pointwise LTR trains a regression or classification model on each query-document feature vector $x_i$ independently:

$$\mathcal{L}_{\text{Pointwise}} = \sum_{i} \big(s_i - y_i\big)^2$$

While simple, Pointwise LTR wastes model capacity in two ways:

  1. Absolute Offset Doesn't Affect Sorting: If a model predicts $[3.0, 2.0, 1.0]$ for grades $[4, 2, 0]$, its ranking is already $100\%$ perfect ($\text{nDCG} = 1.0$), yet MSE still penalizes the absolute offset.
  2. Bottom-of-List Dominance: Because $90\%$ of candidates in a pool have grade $y_i = 0$, a pointwise loss spends most of its gradient budget perfecting scores among irrelevant items at ranks $40$–$100$ rather than fixing an inversion between Rank 1 and Rank 2.

2. Pairwise LTR: RankNet

RankNet (Burges et al., 2005) reframes ranking as binary classification over ordered pairs. For any two documents $(i, j)$ belonging to the same query where item $i$ is more relevant than item $j$ ($y_i > y_j$), RankNet models the probability that item $i$ is ranked above item $j$ using a logistic sigmoid of their score difference:

$$P_{ij} = \Pr(i \succ j) = \sigma(s_i - s_j) = \frac{1}{1 + e^{-(s_i - s_j)}}$$

Minimizing the binary cross-entropy for all pairs with $y_i > y_j$ gives the smooth RankNet loss:

$$\mathcal{L}_{\text{RankNet}}(i, j) = -\ln P_{ij} = \ln\!\big(1 + e^{-(s_i - s_j)}\big)$$

Differentiating $\mathcal{L}_{\text{RankNet}}(i, j)$ with respect to score $s_i$ produces the pairwise "force" $\lambda_{ij}$:

$$\frac{\partial \mathcal{L}_{ij}}{\partial s_i} = \lambda_{ij} = \frac{-1}{1 + e^{s_i - s_j}}, \qquad \frac{\partial \mathcal{L}_{ij}}{\partial s_j} = -\lambda_{ij}$$

Intuitively, if $y_i > y_j$ but the model currently scores $s_i < s_j$, $|\lambda_{ij}|$ is close to $1$, pushing $s_i$ up and $s_j$ down with equal magnitude.

3. Listwise LTR: LambdaRank & LambdaMART

RankNet treats every pairwise inversion equally: swapping a relevant item with an irrelevant item at Rank 1 vs. Rank 2 produces the exact same gradient magnitude as swapping two items at Rank 50 vs. Rank 51.

LambdaRank (Burges et al., 2006) observed that we do not even need an explicit closed-form loss function to train a model—we only need the gradients $\lambda_i = \partial \mathcal{L} / \partial s_i$ after sorting the current scores! LambdaRank directly multiplies the RankNet pairwise gradient by $|\Delta \text{nDCG}_{ij}|$, the absolute change in nDCG that would occur if documents $i$ and $j$ swapped their current rank positions $r(i)$ and $r(j)$:

$$\lambda_{ij} = \frac{-1}{1 + e^{s_i - s_j}} \times \big|\Delta \text{nDCG}_{ij}\big|$$

where the swap impact $|\Delta \text{nDCG}_{ij}|$ has a clean, exact formula:

$$\big|\Delta \text{nDCG}_{ij}\big| = \frac{1}{\text{IDCG}} \cdot \big|\,(2^{y_i} - 2^{y_j})\,\big| \cdot \left|\frac{1}{\log_2(r(i) + 1)} - \frac{1}{\log_2(r(j) + 1)}\right|$$

Summing over all pairs for a given query gives the total pseudo-gradient $\lambda_i$ for document $i$, and LambdaMART (available out-of-the-box in LightGBM and XGBoost as objective="lambdarank") fits Gradient Boosted Decision Trees directly to these $\lambda_i$ gradients and their second derivatives.

4. Worked Numerical Example: RankNet vs. LambdaRank

Suppose a query has $4$ documents with ground-truth relevance grades $y = [3, 0, 2, 0]$, so the ideal ordering $[3, 2, 0, 0]$ has:

$$\text{IDCG} = \frac{2^3 - 1}{\log_2(2)} + \frac{2^2 - 1}{\log_2(3)} = \frac{7}{1.0} + \frac{3}{1.585} = 7.0 + 1.893 = \mathbf{8.893}$$

Suppose our model currently outputs scores that sort the four documents in a flawed order:

  • Rank 1 ($r=1$): Doc B ($y_B = 0$, score $s_B = 2.0$)
  • Rank 2 ($r=2$): Doc A ($y_A = 3$, score $s_A = 1.0$)
  • Rank 3 ($r=3$): Doc D ($y_D = 0$, score $s_D = -1.0$)
  • Rank 4 ($r=4$): Doc C ($y_C = 2$, score $s_C = -2.0$)

Notice that both inverted pairs—$(A, B)$ at Ranks $1 \leftrightarrow 2$, and $(C, D)$ at Ranks $3 \leftrightarrow 4$—have the exact same score gap $s_{\text{rel}} - s_{\text{irrel}} = -1.0$. Let us compare the RankNet force vs. the LambdaRank force on both pairs:

Inverted Pair $(i, j)$ Ranks $r(i) \leftrightarrow r(j)$ Score Diff $s_i - s_j$ RankNet Force $\frac{1}{1 + e^{s_i - s_j}}$ Swap $|\Delta \text{nDCG}_{ij}|$ LambdaRank Force $|\lambda_{ij}|$
Doc A ($y=3$) vs. Doc B ($y=0$) Rank $2 \leftrightarrow$ Rank $1$ $1.0 - 2.0 = -1.0$ $\frac{1}{1 + e^{-1}} = \mathbf{0.731}$ $\frac{|7 - 0|}{8.893} \left|\frac{1}{1.585} - \frac{1}{1.0}\right| = \mathbf{0.290}$ $0.731 \times 0.290 = \mathbf{0.212}$
Doc C ($y=2$) vs. Doc D ($y=0$) Rank $4 \leftrightarrow$ Rank $3$ $-2.0 - (-1.0) = -1.0$ $\frac{1}{1 + e^{-1}} = \mathbf{0.731}$ $\frac{|3 - 0|}{8.893} \left|\frac{1}{2.322} - \frac{1}{2.0}\right| = \mathbf{0.023}$ $0.731 \times 0.023 = \mathbf{0.017}$

Look at the difference:

  • RankNet applies the exact same force ($0.731$) to both pairs.
  • LambdaRank / LambdaMART applies a $12.5\times$ stronger gradient ($0.212$ vs. $0.017$) to fixing the Rank $1 \leftrightarrow 2$ error on the highly relevant $y=3$ document!

5. Minimal Python Implementation of LambdaRank Gradients

import numpy as np

def compute_lambdarank_gradients(scores: np.ndarray, labels: np.ndarray) -> np.ndarray:
    """
    Compute per-document LambdaRank pseudo-gradients for a single query list.
    scores: [N] model predictions
    labels: [N] integer relevance grades (e.g., 0..4)
    """
    N = len(scores)
    # 1. Compute 1-based ranks of current predictions (descending)
    order = np.argsort(-scores)
    ranks = np.empty(N, dtype=np.int32)
    ranks[order] = np.arange(1, N + 1)

    # 2. Compute ideal DCG (IDCG)
    ideal_labels = np.sort(labels)[::-1]
    discounts = 1.0 / np.log2(np.arange(1, N + 1) + 1.0)
    idcg = float(np.sum((2.0 ** ideal_labels - 1.0) * discounts))
    if idcg == 0.0:
        return np.zeros(N)

    gains = (2.0 ** labels - 1.0) / idcg
    pos_discounts = 1.0 / np.log2(ranks + 1.0)

    # 3. Accumulate pairwise forces for all (i, j) with labels[i] > labels[j]
    lambdas = np.zeros(N, dtype=np.float64)
    for i in range(N):
        for j in range(N):
            if labels[i] > labels[j]:
                delta_ndcg = abs(gains[i] - gains[j]) * abs(pos_discounts[i] - pos_discounts[j])
                rho_ij = 1.0 / (1.0 + np.exp(scores[i] - scores[j]))
                force = rho_ij * delta_ndcg
                lambdas[i] += force   # Push relevant item i UP
                lambdas[j] -= force   # Push less-relevant item j DOWN
    return np.round(lambdas, 4)

# Verify worked example: DocA(y=3, s=1), DocB(y=0, s=2), DocC(y=2, s=-2), DocD(y=0, s=-1)
scores = np.array([1.0, 2.0, -2.0, -1.0])
labels = np.array([3, 0, 2, 0])
print("Lambda forces [DocA, DocB, DocC, DocD]:", compute_lambdarank_gradients(scores, labels))
