    Heaps & Priority Queues in C++

    July 2026 · 9 posts

    A heap is the answer to one specific question: what is the best item right now, in a collection that keeps changing? Sorting answers it too, but sorting gives you a total order you did not ask for and charges you $O(n \log n)$ every time the data changes. A heap gives you only the extreme element — and gives it to you in $O(1)$, with $O(\log n)$ to insert or remove.

    That single trade is why heaps sit underneath Dijkstra's algorithm, every task scheduler, k-way merges, streaming top-K, and the running-median problem. In C++ the abstraction is std::priority_queue, and it is one of the most-used and most-misunderstood containers in the standard library — mostly because of one design decision that surprises nearly everyone the first time.

    The surprise, up front: std::priority_queue is a max-heap by default. Its comparator defaults to std::less, yet top() returns the largest element. To get a min-heap you pass std::greater. That inversion trips up almost everyone, and Part 3 explains exactly why the standard is written that way.

    What a Heap Actually Is

    A binary heap is a complete binary tree that satisfies the heap property: every parent compares no worse than its children. In a max-heap every parent is $\ge$ its children; in a min-heap every parent is $\le$ its children. That is the entire invariant.

    Two consequences do all the work. First, the extreme element is always at the root, so reading it is $O(1)$. Second — and this is the part people underrate — because the tree is complete, it can be packed into a flat array with no pointers at all:

    parent(i) = (i - 1) / 2
left(i)   = 2 * i + 1
right(i)  = 2 * i + 2

    So a heap is a plain std::vector that you have agreed to interpret in a particular way. No nodes, no allocations per element, and traversal that walks contiguous memory. Compare that to a std::map, where every element is a separately allocated red-black tree node reached by chasing pointers. It is also why a heap is not sorted: the array satisfies a parent/child constraint, not a left-to-right one.

    ▶ Sift Up & Sift Down

    The only two operations a heap needs. Push appends to the end and sifts the new value up until its parent is larger; pop moves the last element to the root and sifts it down. Watch the array below the tree — both views are the same memory.

    C++ Gives You Two Heap APIs

    This confuses people, so it is worth stating plainly at the start. The standard library exposes heaps at two different levels, and they are not competitors — one is built out of the other.

    std::priority_queue<algorithm> heap functions
    Header<queue><algorithm>
    What it isA container adaptor that owns its storageFree functions operating on any random-access range
    Interfacepush, pop, top, emplacemake_heap, push_heap, pop_heap, sort_heap
    Can you iterate?No — deliberately hiddenYes — it is just your vector

    std::priority_queue is a thin wrapper that calls the very same push_heap and pop_heap internally. It hides the container so you cannot accidentally break the heap invariant by writing to the middle — a genuinely good default. But when you need to iterate, mutate, or heapify in place, drop to the algorithms; Part 6 covers that layer in full.

    The Cost Model

    Memorise this table. Nearly every "should I use a heap here?" decision falls out of it.

    OperationComplexityNote
    top()$O(1)$Just reads element 0.
    push()$O(\log n)$Amortised — the underlying vector may reallocate.
    pop()$O(\log n)$Always a full sift-down of the last element.
    make_heap()$O(n)$Not $O(n \log n)$. The proof is in Part 1.
    sort_heap()$O(n \log n)$Repeated pops; this is heapsort.
    Search for arbitrary value$O(n)$A heap is not a search structure. Use a set.
    Delete arbitrary element$O(n)$Finding it dominates. See the lazy-deletion trick in Part 8.
    Decrease-key—Not supported. The standard workaround is in Part 7.
    The line that decides it: a heap is the right structure when you repeatedly need the single best element from changing data. The moment you need the second-best without removing the best, or need to search, or need ordered iteration, you want std::set/std::multiset instead. Part 8 compares them head to head.

    Max-Heap, Min-Heap, Custom — The Three Shapes You Need

    Practically every heap you write in C++ is one of three declarations. Here they are together for reference; each gets a full post.

    #include <queue>
#include <vector>
#include <functional>

// 1. Max-heap — the default. top() is the LARGEST.
std::priority_queue<int> maxHeap;

// 2. Min-heap — top() is the SMALLEST. Note all three template arguments
//    are required: you cannot name the comparator without naming the container.
std::priority_queue<int, std::vector<int>, std::greater<int>> minHeap;

// 3. Custom order — any strict weak ordering you like.
struct ByAbsValue {
    bool operator()(int a, int b) const {
        return std::abs(a) < std::abs(b);   // largest magnitude on top
    }
};
std::priority_queue<int, std::vector<int>, ByAbsValue> customHeap;

    The rule that unifies all three, and the one worth carrying around: the comparator answers "does a have lower priority than b?" and the element that never has lower priority ends up on top. With std::less, "lower priority" means "smaller", so the largest wins. With std::greater, "lower priority" means "larger", so the smallest wins. Once you read it that way the inversion stops being surprising.

    Read in order. Parts 1–4 are the core; Parts 5–8 are what you reach for once heaps are routine.
