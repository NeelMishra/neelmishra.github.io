In Part 5, our DP states indexed positions in a string. In Knapsack DP, our state indexes a capacity / target sum $s \in [0, T]$. Few areas of Dynamic Programming illustrate the power of recurrence shape better than Knapsack: two tiny loop modifications — reversing the inner loop direction and swapping the outer and inner loops — completely change the combinatorial meaning of the recurrence. (See also our complementary DSA Knapsack DP guide for additional 2D table visualizations.)

1. Pattern 13: 0/1 Knapsack — Each Item Can Be Used at Most Once

In 0/1 Knapsack, we process items one by one. For the $i$-th item with weight/value $v$, each capacity `sum` can either skip the item (retaining its value from round $i-1$) or take the item once (transitioning from `sum - v` of round $i-1$): 

// Core Recurrence Shape (1D space-compressed):
for (int v : items) {
    for (int sum = target; sum >= v; --sum) { // MUST iterate BACKWARD
        dp[sum] = combine(dp[sum], dp[sum - v]);
    }
}
Structural Connection #1: 0/1 Knapsack vs. Unbounded Knapsack

Why does iterating sum backward (`target` down to `v`) enforce using each item at most once, while iterating forward (`v` up to `target`) allows unlimited reuse?

  • Backward (0/1 Knapsack): When we update dp[sum] using dp[sum - v], the smaller index sum - v has not yet been modified during the current item's loop. It still holds the value from the previous row $i-1$. Thus item $v$ is added at most once.
  • Forward (Unbounded Knapsack): When we update dp[sum] going left-to-right, dp[v] is updated first (using item $v$ once), then dp[2v] reads the already updated dp[v] (using item $v$ twice), then dp[3v] uses it three times, and so on within the same pass!

Algebraic Reductions to 0/1 Subset Sum

All three LeetCode problems in Pattern 13 disguise a 0/1 subset-sum recurrence behind an algebraic partition identity. Let $\text{total} = \sum_{x \in \text{nums}} x$, and suppose we partition the elements into two disjoint subsets $P$ (positive / group 1) and $N$ (negative / group 2) so that $S_P + S_N = \text{total}$:

  • Equal Partition (LC 416): $S_P = S_N \implies 2 S_P = \text{total} \implies S_P = \text{total} / 2$.
  • Minimum Remainder After Cancellation (LC 1049): Minimizing $|S_P - S_N| = |\text{total} - 2 S_P|$ is equivalent to finding the largest achievable subset sum $S_P \le \lfloor \text{total} / 2 \rfloor$.
  • Target Sum With $\pm$ Signs (LC 494): $S_P - S_N = \text{target} \implies S_P - (\text{total} - S_P) = \text{target} \implies S_P = (\text{total} + \text{target}) / 2$.

416. Partition Equal Subset Sum Medium · Boolean 0/1 Knapsack

State: dp[s] = whether subset sum $s$ is achievable Time: $O(n \cdot \text{total})$ Space: $O(\text{total})$

Recurrence & Intuition: If $\text{total}$ is odd, an equal split is impossible. Otherwise, set $T = \text{total} / 2$ and run boolean 0/1 Knapsack: `dp[s] = dp[s] || dp[s - num]` with $s$ running backward from $T$ down to `num`. 

class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int total = accumulate(nums.begin(), nums.end(), 0);
        if (total % 2 != 0) return false;
        int target = total / 2;

        vector<bool> dp(target + 1, false);
        dp[0] = true;

        for (int num : nums) {
            for (int s = target; s >= num; --s) {
                dp[s] = dp[s] || dp[s - num];
            }
        }
        return dp[target];
    }
};

1049. Last Stone Weight II Medium · Subset Sum Closest to Half

State: dp[s] = whether subset sum $s \le \lfloor\text{total}/2\rfloor$ is achievable Time: $O(n \cdot \text{total})$ Space: $O(\text{total})$

Recurrence & Intuition: Every smash $(y - x)$ replaces two stones with their difference, which is algebraically identical to assigning a $+$ or $-$ sign to each stone weight so that the resulting sum is non-negative and as small as possible. We find the largest reachable subset sum $s \le \lfloor\text{total}/2\rfloor$ and return $\text{total} - 2s$. 

class Solution {
public:
    int lastStoneWeightII(vector<int>& stones) {
        int total = accumulate(stones.begin(), stones.end(), 0);
        int half = total / 2;

        vector<bool> dp(half + 1, false);
        dp[0] = true;

        for (int w : stones) {
            for (int s = half; s >= w; --s) {
                dp[s] = dp[s] || dp[s - w];
            }
        }

        for (int s = half; s >= 0; --s) {
            if (dp[s]) return total - 2 * s;
        }
        return 0;
    }
};

494. Target Sum Medium · Counting 0/1 Knapsack

State: dp[s] = number of subsets summing to $s$ Time: $O(n \cdot P)$ Space: $O(P)$

Recurrence & Intuition: Using $S_P = (\text{total} + \text{target}) / 2$, if $|\text{target}| > \text{total}$ or $\text{total} + \text{target}$ is odd, return $0$. Otherwise, count subsets summing to $P$ via `dp[s] += dp[s - num]` iterating $s$ from $P$ down to `num`. Notice how cleanly zeros are handled: when `num == 0`, the loop runs down to $s = 0$ and executes `dp[s] += dp[s]`, doubling every count because $+0$ and $-0$ are two valid sign choices! 

class Solution {
public:
    int findTargetSumWays(vector<int>& nums, int target) {
        int total = accumulate(nums.begin(), nums.end(), 0);
        if (abs(target) > total || (total + target) % 2 != 0) {
            return 0;
        }
        int P = (total + target) / 2;

        vector<int> dp(P + 1, 0);
        dp[0] = 1;

        for (int num : nums) {
            for (int s = P; s >= num; --s) {
                dp[s] += dp[s - num];
            }
        }
        return dp[P];
    }
};

2. Pattern 14: Unbounded Knapsack — Items Can Be Reused

When each item (coin, perfect square, etc.) can be chosen an unlimited number of times, we iterate the capacity `amount` forward from `coin` up to `target`: 

// Core Recurrence Shape (Unbounded Min/Max or Combinations):
for (int coin : coins) {
    for (int amount = coin; amount <= target; ++amount) { // FORWARD loop
        dp[amount] = combine(dp[amount], dp[amount - coin]);
    }
}
Structural Connection #2: Coin Change II (Combinations) vs. Combination Sum IV (Permutations)

Both 518. Coin Change II and 377. Combination Sum IV execute the exact same line inside the inner loop: dp[amount] += dp[amount - coin]. Yet LC 518 counts unordered combinations ($1+2$ and $2+1$ count as $1$ way), whereas LC 377 counts ordered permutations ($1+2$ and $2+1$ count as $2$ ways). Why?

  • Coins Outer, Amount Inner (LC 518 — Combinations): Because we finish all transitions using `coin_1` before ever touching `coin_2`, every counted sequence is forced to use coins in canonical index order $(\text{coin}_1, \dots, \text{coin}_1, \text{coin}_2, \dots)$. You can never append `coin_1` after `coin_2`, so $(2, 1)$ is never generated.
  • Amount Outer, Coins Inner (LC 377 — Permutations): At each `amount`, we try every possible last coin `coin` added to reach `amount`. Thus `dp[3]` adds both `dp[2]` (ending in $+1$, giving $(2,1)$) and `dp[1]` (ending in $+2$, giving $(1,2)$).

Note: For $\min/\max$ optimization problems like 322. Coin Change, loop nesting order does not affect correctness because $\min$ is idempotent ($\min(a, a) = a$).

322. Coin Change Medium · Unbounded Minimum Cost

State: dp[a] = fewest coins to make amount $a$ Time: $O(\text{amount} \cdot |coins|)$ Space: $O(\text{amount})$

Recurrence & Intuition: Initialize `dp[0] = 0` and all other entries to $\infty$ (`amount + 1`). For each coin, sweep `a` forward from `coin` to `amount` and relax `dp[a] = min(dp[a], dp[a - coin] + 1)`. 

class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        const int INF = amount + 1;
        vector<int> dp(amount + 1, INF);
        dp[0] = 0;

        for (int coin : coins) {
            for (int a = coin; a <= amount; ++a) {
                dp[a] = min(dp[a], dp[a - coin] + 1);
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];
    }
};

279. Perfect Squares Medium · Unbounded Knapsack with Square Coins

State: dp[i] = fewest perfect squares summing to $i$ Time: $O(n \sqrt{n})$ Space: $O(n)$

Recurrence & Intuition: Identical to Coin Change (LC 322), where the "coins" are the perfect squares $1^2, 2^2, 3^2, \dots, \lfloor\sqrt{n}\rfloor^2$. 

class Solution {
public:
    int numSquares(int n) {
        vector<int> dp(n + 1, n + 1);
        dp[0] = 0;

        for (int r = 1; r * r <= n; ++r) {
            int sq = r * r;
            for (int a = sq; a <= n; ++a) {
                dp[a] = min(dp[a], dp[a - sq] + 1);
            }
        }
        return dp[n];
    }
};

518. Coin Change II Medium · Unbounded Combinations (Coins Outer)

State: dp[a] = number of unordered coin combinations summing to $a$ Time: $O(\text{amount} \cdot |coins|)$ Space: $O(\text{amount})$

Recurrence & Intuition: Outer loop over `coins`, inner forward loop over `a` from `coin` to `amount`. Use `uint64_t` for intermediate additions to avoid signed 32-bit overflow on unreached intermediate states. 

class Solution {
public:
    int change(int amount, vector<int>& coins) {
        vector<uint64_t> dp(amount + 1, 0);
        dp[0] = 1;

        for (int coin : coins) {
            for (int a = coin; a <= amount; ++a) {
                dp[a] += dp[a - coin];
            }
        }
        return static_cast<int>(dp[amount]);
    }
};

377. Combination Sum IV Medium · Unbounded Permutations (Target Outer)

State: dp[a] = number of ordered sequences summing to $a$ Time: $O(\text{target} \cdot |nums|)$ Space: $O(\text{target})$

Recurrence & Intuition: Despite the problem title saying "Combination Sum", the problem statement explicitly counts different orderings as distinct sequences (permutations). Thus we put the `target` loop on the outside and the `nums` loop on the inside: `dp[a] = sum over num of dp[a - num]`. 

class Solution {
public:
    int combinationSum4(vector<int>& nums, int target) {
        vector<uint64_t> dp(target + 1, 0);
        dp[0] = 1;

        for (int a = 1; a <= target; ++a) {
            for (int num : nums) {
                if (a >= num) {
                    dp[a] += dp[a - num];
                }
            }
        }
        return static_cast<int>(dp[target]);
    }
};
