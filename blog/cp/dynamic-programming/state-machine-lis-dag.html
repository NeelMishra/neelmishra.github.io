    State-Machine Stock DP, LIS, and DAG DP

    October 2026 · 27 min read · Patterns 4–6 (11 Problems)

    When a single scalar at index $i$ is no longer enough to capture which decisions remain legal, we either expand each index into a small finite state machine (Pattern 4), look back over all valid ordered predecessors $j < i$ (Pattern 5: LIS), or generalize ordered chains onto an arbitrary Directed Acyclic Graph (Pattern 6: DAG DP).

    Pattern 4: State-Machine DP — Stock Buy and Sell

    How to Recognize It

    At each day $i$, you occupy one of a small number of discrete modes — such as holding a share, not holding a share (cash), waiting in a 1-day cooldown, or having completed $t \in \{0,\dots,k\}$ transactions. Every permitted action (buy, sell, rest) is a directed edge between states from day $i-1$ to day $i$.

    Core Template

    $$\text{dp}[i][\text{state}] = \max_{\text{prev} \to \text{state}} \big(\text{dp}[i - 1][\text{prev}] + \text{gain}(\text{prev} \to \text{state}, \text{prices}[i])\big)$$

    In the canonical two-state formulation:

    $$\text{hold}[i] = \max(\text{hold}[i - 1],\; \text{cash}[i - 1] - \text{prices}[i])$$ $$\text{cash}[i] = \max(\text{cash}[i - 1],\; \text{hold}[i - 1] + \text{prices}[i] - \text{fee})$$

    ▶ Step-Through: 3-State Stock Machine with Cooldown (LC 309)

    Prices [1, 2, 3, 0, 2]. Track hold (holding stock), sold (just sold today → enters cooldown), and rest (cash, free to buy).

    4.1 121. Best Time to Buy and Sell Stock (At Most 1 Transaction)

    State Machine: `hold` = max balance after buying once ($\max(\text{hold}, -p)$); `cash` = max profit after selling once ($\max(\text{cash}, \text{hold} + p)$).

    class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int hold = -prices[0], cash = 0;
        for (int p : prices) {
            cash = max(cash, hold + p);
            hold = max(hold, -p);
        }
        return cash;
    }
}; // Time: O(n), Space: O(1)

    4.2 122. Best Time to Buy and Sell Stock II (Unlimited Transactions)

    State Machine: Unlike LC 121, buying uses accumulated `cash` instead of $0$: $\text{hold} = \max(\text{hold}, \text{cash} - p)$.

    class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int hold = -prices[0], cash = 0;
        for (int p : prices) {
            int nextCash = max(cash, hold + p);
            int nextHold = max(hold, cash - p);
            cash = nextCash;
            hold = nextHold;
        }
        return cash;
    }
}; // Time: O(n), Space: O(1)

    4.3 714. Best Time to Buy and Sell Stock with Transaction Fee

    State Machine: Identical to LC 122, except selling subtracts `fee`: $\text{cash} = \max(\text{cash}, \text{hold} + p - \text{fee})$.

    class Solution {
public:
    int maxProfit(vector<int>& prices, int fee) {
        int hold = -prices[0], cash = 0;
        for (int p : prices) {
            int nextCash = max(cash, hold + p - fee);
            int nextHold = max(hold, cash - p);
            cash = nextCash;
            hold = nextHold;
        }
        return cash;
    }
}; // Time: O(n), Space: O(1)

    4.4 309. Best Time to Buy and Sell Stock with Cooldown

    3-State Machine: Split non-holding into `sold` (just sold today; cannot buy tomorrow) and `rest` (cooldown finished; eligible to buy):

    • $\text{hold}[i] = \max(\text{hold}[i-1],\; \text{rest}[i-1] - p)$
    • $\text{sold}[i] = \text{hold}[i-1] + p$
    • $\text{rest}[i] = \max(\text{rest}[i-1],\; \text{sold}[i-1])$
    class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int hold = -prices[0], sold = 0, rest = 0;
        for (size_t i = 1; i < prices.size(); ++i) {
            int prevHold = hold, prevSold = sold, prevRest = rest;
            hold = max(prevHold, prevRest - prices[i]);
            sold = prevHold + prices[i];
            rest = max(prevRest, prevSold);
        }
        return max(sold, rest);
    }
}; // Time: O(n), Space: O(1)

    4.5 123. Best Time to Buy and Sell Stock III (At Most 2 Transactions)

    4-State Chain: Track `buy1`, `sell1`, `buy2`, `sell2` in sequence.

    class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int buy1 = -prices[0], sell1 = 0;
        int buy2 = -prices[0], sell2 = 0;
        for (int p : prices) {
            buy1  = max(buy1, -p);
            sell1 = max(sell1, buy1 + p);
            buy2  = max(buy2, sell1 - p);
            sell2 = max(sell2, buy2 + p);
        }
        return sell2;
    }
}; // Time: O(n), Space: O(1)

    4.6 188. Best Time to Buy and Sell Stock IV (At Most $k$ Transactions)

    $2k$-State Generalization: Maintain arrays `buy[1..k]` and `sell[1..k]`, where $\text{buy}[t] = \max(\text{buy}[t], \text{sell}[t-1] - p)$ and $\text{sell}[t] = \max(\text{sell}[t], \text{buy}[t] + p)$.

    class Solution {
public:
    int maxProfit(int k, vector<int>& prices) {
        if (prices.empty() || k == 0) return 0;
        vector<int> buy(k + 1, -prices[0]), sell(k + 1, 0);
        for (int p : prices) {
            for (int t = 1; t <= k; ++t) {
                buy[t]  = max(buy[t], sell[t - 1] - p);
                sell[t] = max(sell[t], buy[t] + p);
            }
        }
        return sell[k];
    }
}; // Time: O(n * k), Space: O(k)
    Key observation (Pattern 4): Once you write down the state graph, transaction fees, cooldowns, and $k$-transaction caps are just edge-weight or state-count tweaks to the exact same framework. See also Stock Problems in DSA.

    Pattern 5: LIS — Longest Increasing Subsequence

    How to Recognize It

    You must select a subsequence of elements in their original order (or after a canonical sort) such that every chosen element satisfies a strict comparison with the previously chosen element.

    Core Template

    $$\text{dp}[i] = 1 + \max_{\substack{0 \le j < i \\ \text{nums}[j] < \text{nums}[i]}} \text{dp}[j]$$

    If no valid $j$ exists, $\text{dp}[i] = 1$. This $O(n^2)$ formulation computes exact LIS lengths ending at every index $i$. When only the global LIS length is needed, maintaining the minimal tail element of each increasing subsequence length via `std::lower_bound` (patience sorting) achieves $O(n \log n)$.

    5.1 646. Maximum Length of Pair Chain

    LIS vs. Interval Greedy: Sorting pairs by left endpoint allows the classic $O(n^2)$ LIS recurrence $\text{dp}[i] = 1 + \max_{b_j < a_i} \text{dp}[j]$; sorting by right endpoint even permits an $O(n \log n)$ greedy interval selection.

    class Solution {
public:
    int findLongestChain(vector<vector<int>>& pairs) {
        sort(pairs.begin(), pairs.end());
        int n = pairs.size(), best = 1;
        vector<int> dp(n, 1);
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < i; ++j) {
                if (pairs[j][1] < pairs[i][0])
                    dp[i] = max(dp[i], dp[j] + 1);
            }
            best = max(best, dp[i]);
        }
        return best;
    }
}; // Time: O(n^2) DP (or O(n log n) when sorted by right endpoint)

    5.2 300. Longest Increasing Subsequence

    Both $O(n^2)$ DP and $O(n \log n)$ Patience Sorting: Below we show both the canonical $O(n^2)$ recurrence and the $O(n \log n)$ minimal-tails binary search.

    class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> tails;
        for (int x : nums) {
            auto it = lower_bound(tails.begin(), tails.end(), x);
            if (it == tails.end()) tails.push_back(x);
            else *it = x;
        }
        return tails.size();
    }
}; // Time: O(n log n), Space: O(n)

    5.3 673. Number of Longest Increasing Subsequence

    Dual State `(len[i], cnt[i])`: Alongside `len[i]` (length of LIS ending at $i$), maintain `cnt[i]` (number of such subsequences). When `len[j] + 1 > len[i]`, reset `cnt[i] = cnt[j]`; when `len[j] + 1 == len[i]`, accumulate `cnt[i] += cnt[j]`.

    class Solution {
public:
    int findNumberOfLIS(vector<int>& nums) {
        int n = nums.size(), maxLen = 0, ans = 0;
        vector<int> len(n, 1), cnt(n, 1);
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < i; ++j) {
                if (nums[j] < nums[i]) {
                    if (len[j] + 1 > len[i]) {
                        len[i] = len[j] + 1;
                        cnt[i] = cnt[j];
                    } else if (len[j] + 1 == len[i]) {
                        cnt[i] += cnt[j];
                    }
                }
            }
            maxLen = max(maxLen, len[i]);
        }
        for (int i = 0; i < n; ++i)
            if (len[i] == maxLen) ans += cnt[i];
        return ans;
    }
}; // Time: O(n^2), Space: O(n)

    5.4 354. Russian Doll Envelopes

    Critical Sorting Trick: Sort envelopes by width ascending, and on width ties sort by height descending. Why descending height on ties? Because two envelopes with the same width cannot nest, and sorting heights descending prevents the 1D LIS on heights from picking two envelopes of equal width.

    class Solution {
public:
    int maxEnvelopes(vector<vector<int>>& envelopes) {
        sort(envelopes.begin(), envelopes.end(), [](const auto& a, const auto& b) {
            return a[0] != b[0] ? a[0] < b[0] : a[1] > b[1];
        });
        vector<int> tails;
        for (const auto& env : envelopes) {
            int h = env[1];
            auto it = lower_bound(tails.begin(), tails.end(), h);
            if (it == tails.end()) tails.push_back(h);
            else *it = h;
        }
        return tails.size();
    }
}; // Time: O(n log n), Space: O(n)

    Pattern 6: DAG DP — Longest Increasing Path in a Matrix

    How to Recognize It

    A matrix or graph contains transitions that move in a strictly increasing or otherwise acyclic direction. Because you can only step from $(r, c)$ to $(nr, nc)$ when $\text{matrix}[nr][nc] > \text{matrix}[r][c]$, no cycle can ever occur — the grid is an implicit Directed Acyclic Graph (DAG).

    Core Template

    $$\text{dp}[\text{node}] = 1 + \max_{\text{nextNode} \in \text{Adj}(\text{node})} \text{dp}[\text{nextNode}]$$

    6.1 329. Longest Increasing Path in a Matrix

    Top-Down DFS + Memoization on the Implicit DAG: Since there are no cycles, `memo[r][c] != 0` immediately returns the cached longest path starting at $(r, c)$ without needing a separate `visiting` recursion-stack state.

    class Solution {
    int R, C;
    vector<vector<int>> memo;
    static constexpr int dr[4] = {-1, 1, 0, 0};
    static constexpr int dc[4] = {0, 0, -1, 1};

    int dfs(const vector<vector<int>>& mat, int r, int c) {
        if (memo[r][c] != 0) return memo[r][c];
        int best = 1;
        for (int d = 0; d < 4; ++d) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr >= 0 && nr < R && nc >= 0 && nc < C && mat[nr][nc] > mat[r][c]) {
                best = max(best, 1 + dfs(mat, nr, nc));
            }
        }
        return memo[r][c] = best;
    }
public:
    int longestIncreasingPath(vector<vector<int>>& matrix) {
        R = matrix.size(); C = matrix[0].size();
        memo.assign(R, vector<int>(C, 0));
        int ans = 0;
        for (int r = 0; r < R; ++r)
            for (int c = 0; c < C; ++c)
                ans = max(ans, dfs(matrix, r, c));
        return ans;
    }
}; // Time: O(R * C), Space: O(R * C)
    Structural Connection #5 (LIS vs. Longest Increasing Path in a Matrix): Both build a longer chain by extending a smaller valid one (`1 + max`), but LIS follows the 1D index order of an array ($O(n^2)$ or $O(n \log n)$), whereas Longest Increasing Path follows 2D grid adjacency along an implicit DAG ($O(RC)$ via memoized DFS or topological sort). See also Graph DP in DSA.
