    RAG: separate retrieval from generation

    October 2026 · 6 min read

    A model answering from its parameters and a model answering from retrieved documents have different failure modes. Retrieval-augmented generation gives the generator access to external evidence. It does not guarantee that the evidence is useful, current, authorized, or used faithfully.

    This series follows the decisions between a question and an answer. Its first focus is approximate nearest-neighbor search: how an index finds candidate vectors, what it can miss, and how that miss affects the rest of a RAG system.

    Trace one question through the system

    Consider a constructed support query: Which flag enables the new cache for tenant West? The corpus contains the current West deployment guide, an older West guide, and an East guide with similar wording. A high vector score for the East guide would not make it the right evidence.

    Keep the passage text outside the ANN index if that is how your storage is designed. The index can return IDs and scores; another store resolves IDs into text and metadata. That separation also makes it possible to inspect exactly which evidence reached the generator.

    Do not confuse an index update with an embedding-model update. A new model can change the meaning of vector coordinates even if their dimension stays the same. Query and corpus representations must be compatible; a successful API call does not establish that compatibility.

    What the original RAG model formalized

    Lewis and colleagues' Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks combines a learned retriever with a sequence-to-sequence generator. A document is a latent variable. In the sequence-level variant, one document conditions an entire candidate output:

    $$p(y\mid x)\approx \sum_{z\in\operatorname{topK}(x)} p_\eta(z\mid x)\,p_\theta(y\mid x,z).$$

    Here $x$ is the input, $z$ a retrieved document, $y$ the output, $\eta$ the retriever parameters, and $\theta$ the generator parameters. The top-K sum approximates a larger document space. The paper also considers a token-level variant in which the latent document can vary across output tokens.

    An application that retrieves passages and inserts them into one prompt need not implement this latent-document objective or jointly train the retriever and generator. The equation explains the original model; it is not a description of every system called RAG.

    What an ANN index is responsible for

    Suppose the query embedding is $q$, stored vectors are $x_i$, and lower distance is better. Exact search selects the eligible items with the smallest values of $d(q,x_i)$. An ANN index tries to recover that set while examining less of the corpus.

    Three different questions require three different references.
    QuestionReferencePossible failure
    Did the index reproduce vector search?Exact neighbors under the same metric and eligibility ruleA graph route never discovers a near vector
    Did retrieval find useful evidence?Relevance judgments or task-specific evidence labelsThe embedding prefers a similar but wrong guide
    Did the answer follow the evidence?Claims checked against the retrieved sourcesThe generator invents a flag that no source contains

    Perfect ANN recall can reproduce an unhelpful exact ranking. Conversely, a relevant passage can be available to a reranker only if candidate discovery actually returns it. Keep these boundaries visible before changing index settings or generation prompts.

    Vector scores are not automatically calibrated probabilities that a passage answers the question. Their scale depends on the metric, representation, and normalization. A larger inner product can reflect vector norm as well as alignment.

    Make eligibility part of the retrieval task

    For the West query, the exact reference must exclude East-only documents if those documents are unavailable to this request. Searching globally and discarding forbidden IDs afterward can leave a short list, even when the global vector search is exact.

    Never pass unauthorized passages into the generator merely because they scored well. Whether an index may internally traverse vectors outside a result filter is a separate storage and access-policy decision. Database filtering semantics, retrieval eligibility, and application authorization must agree.

    A context budget adds another constraint. Retrieving ten passages does not mean all ten fit in the prompt. Track the candidates, the reranked list, and the final context separately so that a missing citation can be traced to the correct stage.

    A reading route with clear boundaries

    Begin with ANN methods: define the target before choosing the index. It establishes distance conventions, the exact reference, and the difference between candidate misses and score approximation. The existing comparison of HNSW and Annoy contrasts graph routes with partition boundaries.

    For evaluation, use retrieval and reranking diagnostics and evidence-to-answer evaluation. For application assembly, use the MLOps RAG guide. The information retrieval textbook companion supplies lexical and dense retrieval context.

    Check the causal story

    ANN recall is 100%, but the answer is wrong. Is the graph exonerated?

    It reproduced the declared exact neighbor set at that cutoff. That narrows the diagnosis; it does not validate the embedding ranking, eligibility rules, context assembly, source freshness, or generator behavior. Check those stages against their own references.

    A reranker finds excellent evidence when given all documents. Does that prove the deployed pipeline works?

    No. The deployed reranker only sees its candidate set. Its result on all documents can show ranking capability, but candidate discovery may withhold the passages it needs.

    Can changing efSearch repair a corpus embedded with the wrong model?

    No. More graph exploration changes how thoroughly the index searches its stored geometry. It does not restore compatibility between incompatible query and corpus representations.
