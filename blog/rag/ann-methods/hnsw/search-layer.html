    HNSW search: trace both heaps before changing ef

    October 2026 · 9 min read

    The HNSW search setting ef controls how many promising results remain retained, not how many vectors may be seen. Understanding that distinction requires keeping two queues separate: candidates waiting for exploration and the best candidates found so far.

    This chapter isolates the paper's unfiltered layer-search rule. The hierarchy chooses an entry point; here we supply A directly so that every queue transition can be inspected. The graph is constructed for teaching, not built by Faiss or hnswlib.

    Three collections answer three different questions

    Smaller distance is better. A node can be present in more than one collection.
    CollectionQuestionUseful operation
    Candidate frontier CWhich discovered node should have its neighborhood examined next?Pop the smallest distance from a min-heap
    Retained results WWhich discovered results are currently best, up to ef?Inspect or remove the largest distance from a max-heap
    Visited IDs VHave we already evaluated this node for the query?Membership check before another distance computation

    Visited does not mean expanded. A rejected neighbor has been seen and scored but can remain unexplored. Retained does not mean returned either: if ef is larger than K, only the closest K retained results become the output.

    A node evicted from W need not be removed immediately from C. The frontier and retained set have different jobs. Consequently the frontier is not generally capped at ef, and neither the visited count nor the number of distance evaluations is bounded by ef.

    Python's heapq is a min-heap. The reference stores (distance, ID) in C and (-distance, ID) in W. The most negative distance in W represents its farthest member. Displays below sort the collections for readability; they are not pictures of a heap's internal array layout.

    Write the admission and stopping decisions

    Initialize C and W with the entry and V with its ID. Pop the nearest pending node c, then inspect the farthest retained node f. The paper's unfiltered stopping condition is:

    $$d(q,c)>d(q,f).$$

    If that condition does not hold, inspect c's neighbors. Mark each previously unseen neighbor e as visited and calculate its distance. Admit it into C and W when there is room or it improves the retained cutoff:

    $$|W|<\mathrm{ef} \quad\text{or}\quad d(q,e)<\max_{w\in W}d(q,w).$$

    If admission makes W larger than ef, remove its farthest member. Marking a node visited before admission prevents repeated scoring through different incoming routes, including repeated attempts to admit a previously rejected node.

    The cutoff can change as better results are discovered. It is a bound on retained scores, not on the scores hidden in unexpanded neighborhoods. The rule is approximate because a farther routing node can lead to a much closer neighbor.

    Trace a barrier graph

    Query $q=(0,0)$, entry A=(8,0), and K=1. A links to B=(7,0) and C=(9,0); C links to D=(0.5,0). Reverse links make this small teaching graph connected. The squared distances are:

    $$d_A^2=64,\quad d_B^2=49,\quad d_C^2=81,\quad d_D^2=0.25.$$

    ef = 1: improving the result closes the bridge

    Start with C=[A:64] and W=[A:64]. Expanding A sees B:49, admits it, and evicts A from W. C:81 is then scored but rejected because it is worse than the retained B:49. The frontier contains only B.

    Expanding B sees only the already visited A. The frontier empties and the result is B. We evaluated A, B, and C: three distances despite ef = 1. We expanded only A and B. D was never discovered.

    ef = 2 still fails on this graph. B:49 and A:64 fill W before C is considered, so C:81 remains outside the retained cutoff. A higher setting can fail to change a particular result; there is no universal one-step improvement rule.

    ef = 3: allow a worse candidate to reveal a better result

    When C:81 is popped, the worst retained score is also 81. The stopping rule uses a strict greater-than comparison, so equality does not stop expansion. That permits the discovery of D. Replacing the condition with greater-than-or-equal would change this trace.

    Squared L2 and ordinary L2 preserve the comparisons, so square roots are unnecessary. A library's similarity score may require reversing the ordering instead; do not use a distance-heap implementation unchanged on a score where larger is better.

    Reproduce the state and the work count

    Save the reference helper beside this snippet, or run the complete test script from the examples directory:

    from reference import GRAPH, QUERY, VECTORS, search_layer

for ef in (1, 2, 3):
    run = search_layer(QUERY, VECTORS, GRAPH, "A", ef)
    print(ef, run["nearest"][:1],
          run["distance_evaluations"],
          run["traces"][-1]["expanded"])
# 1 ['B'] 3 ['A', 'B']
# 2 ['B'] 3 ['A', 'B']
# 3 ['D'] 4 ['A', 'B', 'C', 'D']

    The helper computes a query distance when a node is first discovered and caches it. Its work counter therefore counts actual unique distance evaluations, not the size of the final retained heap. The output includes all states used by the interactive viewer.

    Production implementations add memory layouts, pooled visited arrays, prefetching, native kernels, thread coordination, and library-specific conditions. This Python helper is deliberately auditable and small. Do not benchmark its Python overhead as the speed of HNSW itself.

    What the stopping rule does not establish

    A frontier cutoff can leave reachable neighborhoods unexplored. It cannot certify that the returned neighbor is the global nearest. Our narrow run returns B even though the graph is connected and D is strictly closer.

    If the graph itself lacks a route to D, more ef cannot create one. Conversely, a connected graph can still need enough retained alternatives to cross a bad local route. Distinguish an exploration problem from a construction/connectivity problem.

    Finite precision and ties need a declared convention. This reference orders equal heap priorities by ID but admits only a strictly better score when W is full. Its exact reference sorts ties by ID. Equal-distance neighbors can therefore require tie-aware recall rather than pretending that a unique ID set is mathematically mandatory.

    Filtering and deletion add another distinction: a node can be usable for routing while ineligible for results. Native filtered search can keep exploring until its eligible retained set is full. That is not exactly the unfiltered rule traced here; use the actual engine's behavior and filtered exact ground truth.

    A node is visited but absent from W. Was its distance necessarily wasted?

    No. Its score was needed to decide admission, or it may have been evicted after better results appeared. Visited records completed scoring, not final output usefulness.

    Can the frontier contain nodes that W no longer retains?

    Yes. The algorithm can evict a node from W without deleting its pending frontier entry. A later cutoff check may prevent its expansion. Maintaining the two collections as identical sets would change the algorithm.

    Why is K=1 compatible with ef=3?

    K chooses the final output count. ef chooses retained exploration capacity. Keeping three alternatives can uncover the one best returned result, as this graph demonstrates.
