    ScaNN: weight parallel quantization error for inner-product search

    October 2026 · 8 min read

    Classical Product Quantization trains codebooks by minimizing Euclidean reconstruction error $\lVert x - \tilde{x}\rVert_2^2$, treating quantization error in every direction as equally harmful. Yet retrieval-augmented generation and dense dual encoders usually rank documents by Maximum Inner Product Search (MIPS) or cosine similarity.

    Google's ScaNN (Scalable Nearest Neighbors) shows that for inner-product retrieval, quantization error parallel to $x$ damages top-K ranking far more than quantization error orthogonal to $x$. Penalizing parallel error more heavily during codebook learning and vector assignment improves recall at the exact same bit budget and lookup-table speed.

    Why smaller Euclidean error can pick the wrong inner-product neighbor

    One target vector · two codebook candidates · a ranking flip

    Database vector $x=(1.0,0.0)$ competes with $y=(0.88,0.0)$ on query $q=(1.0,0.1)$. Exact inner products are $q^\top x = 1.00$ and $q^\top y = 0.88$, so $x$ is the true winner. Codebook candidate $\tilde{x}_1=(0.8,0.0)$ has smaller Euclidean error ($0.04$) than $\tilde{x}_2=(1.0,0.3)$ ($0.09$), yet picking $\tilde{x}_1$ drops $x$'s estimated score to $0.80$ and hands the win to $y$.

    Why did the larger Euclidean error produce a $6.7\times$ smaller inner-product error? Because a query $q$ for which $x$ is a top inner-product match must point nearly in the same direction as $x$. Its component parallel to $x$ is large ($q_\parallel = 1.0$), while its component orthogonal to $x$ is small ($q_\perp = 0.1$).

    Decompose the residual into parallel and orthogonal components

    For any nonzero database vector $x\in\mathbb{R}^d$ and quantized approximation $\tilde{x}$, write the residual $r = x - \tilde{x}$ as the sum of its projection onto $x$ and its orthogonal complement:

    $$r_\parallel = \frac{x^\top(x - \tilde{x})}{\lVert x\rVert_2^2}\, x, \qquad r_\perp = (x - \tilde{x}) - r_\parallel, \qquad r_\parallel^\top r_\perp = 0.$$

    For any query $q$, the inner-product approximation error is $q^\top(x - \tilde{x}) = q^\top r_\parallel + q^\top r_\perp$. If $x$ is a relevant candidate for $q$ with inner product $q^\top x \ge T$ (or angle $\theta(q,x)$ small), the query's energy along the one-dimensional direction of $x$ is large, whereas its remaining energy $\lVert q\rVert_2^2 - (q^\top x / \lVert x\rVert_2)^2$ is spread across all $d-1$ orthogonal dimensions:

    $$\mathbb{E}_q\bigl[(q^\top r)^2 \,\big|\, q^\top x = T\bigr] = \frac{T^2}{\lVert x\rVert_2^2}\lVert r_\parallel\rVert_2^2 + \frac{\mathbb{E}\bigl[\lVert q\rVert_2^2\bigr] - T^2/\lVert x\rVert_2^2}{d - 1}\lVert r_\perp\rVert_2^2.$$

    Look at the denominator $d - 1$ on the orthogonal term. In high dimensions ($d=768$), random orthogonal error averages out by a factor of $d - 1$, while parallel error directly scales the dominant inner product $T$.

    ScaNN's anisotropic vector quantization objective

    Guo and colleagues replace the isotropic squared error $\lVert r_\parallel\rVert_2^2 + \lVert r_\perp\rVert_2^2$ with the weighted anisotropic quantization loss:

    $$\ell_{\text{aniso}}(x, \tilde{x};\, h_\parallel, h_\perp) = h_\parallel \lVert r_\parallel\rVert_2^2 + h_\perp \lVert r_\perp\rVert_2^2, \qquad h_\parallel > h_\perp > 0.$$

    Setting $h_\parallel = h_\perp = 1$ recovers standard Euclidean k-means and Product Quantization. Setting $h_\parallel / h_\perp > 1$ (guided by the threshold $T$ of top-K inner products) forces both codebook updates and vector-to-codeword assignments to preserve the parallel projection $x^\top \tilde{x} / \lVert x\rVert_2$ even at the expense of slightly larger perpendicular jitter.

    Verify the parallel-orthogonal decomposition and ranking preservation

    import numpy as np

x = np.array([1.0, 0.0])
y = np.array([0.88, 0.0])
q = np.array([1.0, 0.1])
candidates = {
    "x_tilde_1": np.array([0.8, 0.0]),
    "x_tilde_2": np.array([1.0, 0.3]),
}

def decompose_error(target, recon, h_par=4.0, h_perp=1.0):
    r = target - recon
    unit = target / np.linalg.norm(target)
    r_par = np.dot(r, unit) * unit
    r_perp = r - r_par
    par_sq = round(float(np.dot(r_par, r_par)), 4)
    perp_sq = round(float(np.dot(r_perp, r_perp)), 4)
    iso_loss = round(par_sq + perp_sq, 4)
    aniso_loss = round(h_par * par_sq + h_perp * perp_sq, 4)
    return par_sq, perp_sq, iso_loss, aniso_loss

stats = {name: decompose_error(x, vec) for name, vec in candidates.items()}
assert stats["x_tilde_1"] == (0.04, 0.0, 0.04, 0.16)
assert stats["x_tilde_2"] == (0.0, 0.09, 0.09, 0.09)

# Isotropic minimizes iso_loss -> picks x_tilde_1; Anisotropic minimizes aniso_loss -> picks x_tilde_2
iso_choice = min(candidates, key=lambda k: stats[k][2])
aniso_choice = min(candidates, key=lambda k: stats[k][3])
assert iso_choice == "x_tilde_1" and aniso_choice == "x_tilde_2"

exact_qx = round(float(q @ x), 4)
exact_qy = round(float(q @ y), 4)
iso_qx = round(float(q @ candidates[iso_choice]), 4)
aniso_qx = round(float(q @ candidates[aniso_choice]), 4)

assert exact_qx > exact_qy          # True ranking: x > y (1.00 > 0.88)
assert iso_qx < exact_qy            # Isotropic flips ranking: 0.80 < 0.88
assert aniso_qx > exact_qy          # Anisotropic preserves ranking: 1.03 > 0.88
print("Isotropic choice:", iso_choice, "score:", iso_qx, "vs y:", exact_qy)
print("Anisotropic choice:", aniso_choice, "score:", aniso_qx, "vs y:", exact_qy)

    Does anisotropic weighting still help on unit-normalized vectors?

    A common misconception is that normalizing vectors to unit length makes anisotropic quantization identical to standard k-means. Even when $\lVert x\rVert_2=1$, a standard k-means centroid is the Euclidean mean of its assigned points and sits strictly inside the unit sphere ($\lVert\tilde{x}\rVert_2 < 1$), shrinking the parallel component $x^\top \tilde{x}$. Furthermore, for a high-cosine neighbor where $q^\top x = \cos\theta$ is close to $1$, $q$ still aligns strongly with $x$, so parallel shrinkage $r_\parallel$ still dominates inner-product error over orthogonal jitter $r_\perp$. Look at the TurboQuant inner-product bias derivation for another perspective on why MSE codebooks systematically shrink inner products.

    Check the operating assumptions

    Does ScaNN change the query-time lookup table cost compared to standard PQ?

    No. Anisotropic weighting changes how the sub-centroids and stored codes are learned and assigned at build time. At query time, scoring still sums M lookup-table entries per candidate using the exact same SIMD shuffle instructions.

    Why is parallel error weighted more heavily only because we care about the top-K inner products?

    If queries were paired with completely random database vectors (where E[q^T x] = 0), q would have no preferred alignment with x, and parallel and orthogonal directions would carry equal expected variance. The anisotropy comes from conditioning on pairs where q^T x is large enough to compete for top-K.

    Can anisotropic quantization fix a candidate miss caused by probing too few coarse partitions?

    No. Just like IVFPQ, ScaNN's quantization stage only scores vectors inside the partitions selected by the coarse search. If the coarse search skips the partition containing the true neighbor, neither anisotropic PQ nor final rescoring can recover it.
