    Product quantization: split subspaces and score with lookup tables

    October 2026 · 9 min read

    Storing a 64-bit code per vector with standard vector quantization would require learning, storing, and searching $2^{64}$ full-dimensional centroids—an impossible codebook. Product Quantization (PQ) solves this combinatorial barrier by splitting each $d$-dimensional vector into $M$ subvectors of width $d^*=d/M$ and quantizing each subspace independently with $K^*$ sub-centroids.

    With $M=8$ subspaces and $K^*=256$ centroids per subspace (one byte per subvector), PQ stores only $8\times 256=2{,}048$ sub-centroids while implicitly defining a Cartesian product codebook of $256^8 = 2^{64}$ reconstruction points in just 8 bytes per stored vector.

    Cartesian product codebooks and asymmetric lookup tables

    Write $x\in\mathbb{R}^d$ as the concatenation of $M$ subvectors $x = \bigl[x^{(1)},\dots,x^{(M)}\bigr]$, where each $x^{(m)}\in\mathbb{R}^{d^*}$. Subspace $m$ has its own k-means codebook $\mathcal{C}^{(m)}=\{c_{m,0},\dots,c_{m,K^*-1}\}$ and quantizer $q_m(x^{(m)}) = \arg\min_k \lVert x^{(m)} - c_{m,k}\rVert_2^2$. The reconstructed vector is:

    $$\hat{x} = \bigl[c_{1,q_1(x^{(1)})},\, c_{2,q_2(x^{(2)})},\, \dots,\, c_{M,q_M(x^{(M)})}\bigr] \in \mathcal{C}^{(1)}\times\cdots\times\mathcal{C}^{(M)}.$$

    In Asymmetric Distance Computation (ADC), the query $q$ is kept uncompressed while stored vectors $x$ are replaced by their reconstructions $\hat{x}$. Because the subspaces are orthogonal, squared L2 decomposes into a sum of $M$ subspace terms:

    $$\hat{d}_{\mathrm{ADC}}^2(q, x) = \lVert q - \hat{x}\rVert_2^2 = \sum_{m=1}^{M} \underbrace{\lVert q^{(m)} - c_{m, q_m(x^{(m)})}\rVert_2^2}_{\mathrm{LUT}[m,\, q_m(x^{(m)})]}.$$

    Before scanning any stored codes, the query precomputes the $M\times K^*$ Distance Lookup Table $\mathrm{LUT}[m,k] = \lVert q^{(m)} - c_{m,k}\rVert_2^2$ in $O(K^* d)$ operations. Scoring each candidate vector then requires only $M$ table lookups and additions instead of $d$ floating-point multiply-adds.

    Trace a two-subspace lookup table and a quantization collision

    Four coordinates · two subspaces · two-bit codes

    Split $d=4$ into $M=2$ subspaces of width $2$. Subspace 1 uses centroids $c_{1,0}=(0,0)$ and $c_{1,1}=(2,0)$. Subspace 2 uses $c_{2,0}=(0,0)$ and $c_{2,1}=(0,2)$. Query $q=(1.2, 0.0, 0.0, 1.4)$ is closest to $B$, but $A$ and $B$ quantize to the same PQ code $(1,1)$.

    First precompute the four entries of $\mathrm{LUT}[m,k]$ for $q^{(1)}=(1.2,0.0)$ and $q^{(2)}=(0.0,1.4)$:

    • $\mathrm{LUT}[1,0] = \lVert(1.2,0.0)-(0.0,0.0)\rVert_2^2 = 1.44$, and $\mathrm{LUT}[1,1] = \lVert(1.2,0.0)-(2.0,0.0)\rVert_2^2 = 0.64$.
    • $\mathrm{LUT}[2,0] = \lVert(0.0,1.4)-(0.0,0.0)\rVert_2^2 = 1.96$, and $\mathrm{LUT}[2,1] = \lVert(0.0,1.4)-(0.0,2.0)\rVert_2^2 = 0.36$.

    Fixed query q = (1.2, 0.0, 0.0, 1.4). ADC adds one LUT entry per subspace.

    Even if the index exhaustively scans all three PQ codes, $A$ and $B$ share code $(1,1)$ and receive identical approximate distance $1.00$. Under lower-ID tie breaking, a top-1 PQ scan returns $A$ ($0.65$) instead of the true nearest neighbor $B$ ($0.17$). Fetching the top-2 PQ shortlist $\{A,B\}$ and reranking with full-precision coordinates immediately restores $B$.

    Compare asymmetric, symmetric, and residual product quantization

    Three ways to combine subspace codebooks with distance scoring.
    VariantHow distances are computedKey tradeoff
    Symmetric (SDC)Quantize both $q$ and $x$; sum precomputed centroid-to-centroid tablesZero per-query LUT build cost, but double the quantization distortion
    Asymmetric (ADC)Keep $q$ exact; build an $M\times K^*$ LUT per query and sum $M$ entries per codeLower distortion than SDC; per-query LUT overhead is amortized across candidates
    IVFPQ (Residual ADC)Assign $x$ to coarse centroid $c_j$, then PQ-encode the residual $r(x)=x-c_j$Much lower reconstruction error at the same bit budget because coarse location is already known

    In IndexIVFPQ, each vector $x$ assigned to coarse cell $c_j$ stores only the PQ code of its residual $r(x)=x-c_j$. For squared L2, probing coarse cell $c_j$ replaces $q$ with the query residual $q - c_j$ and builds the subspace LUT against the residual codebooks, or expands:

    $$\lVert q - (c_j + \hat{r})\rVert_2^2 = \lVert q - c_j\rVert_2^2 + \lVert \hat{r}\rVert_2^2 + 2c_j^\top \hat{r} - 2q^\top \hat{r},$$

    allowing the query-dependent inner-product table $-2q^\top\hat{r}$ to be computed once per query across all probed lists rather than rebuilding a separate L2 table for every coarse cell.

    Verify the lookup table and shortlist reranking in Python

    import numpy as np

q = np.array([1.2, 0.0, 0.0, 1.4])
codebooks = [
    np.array([[0.0, 0.0], [2.0, 0.0]]),  # Subspace 1 (coords 0..1)
    np.array([[0.0, 0.0], [0.0, 2.0]]),  # Subspace 2 (coords 2..3)
]
vectors = {
    "A": np.array([1.8, 0.0, 0.2, 1.9]),
    "B": np.array([1.6, 0.0, 0.0, 1.5]),
    "C": np.array([0.2, 0.0, 0.0, 1.7]),
}

def encode_pq(x):
    parts = np.split(x, 2)
    return tuple(
        int(np.argmin(np.sum((cb - part) ** 2, axis=1)))
        for cb, part in zip(codebooks, parts)
    )

def build_lut(query):
    parts = np.split(query, 2)
    return [np.sum((cb - part) ** 2, axis=1) for cb, part in zip(codebooks, parts)]

codes = {vid: encode_pq(x) for vid, x in vectors.items()}
assert codes == {"A": (1, 1), "B": (1, 1), "C": (0, 1)}

lut = build_lut(q)
np.testing.assert_allclose(lut[0], [1.44, 0.64])
np.testing.assert_allclose(lut[1], [1.96, 0.36])

adc_scores = {
    vid: round(float(sum(lut[m][code[m]] for m in range(2))), 4)
    for vid, code in codes.items()
}
exact_scores = {
    vid: round(float(np.sum((q - x) ** 2)), 4)
    for vid, x in vectors.items()
}
assert adc_scores == {"A": 1.0, "B": 1.0, "C": 1.8}
assert exact_scores == {"A": 0.65, "B": 0.17, "C": 1.09}

# Top-1 ADC picks A on ID tie-break; top-2 ADC + exact rerank recovers B
top2_candidates = [vid for _, vid in sorted((s, vid) for vid, s in adc_scores.items())[:2]]
reranked_winner = min(top2_candidates, key=lambda vid: exact_scores[vid])
assert reranked_winner == "B"
print("ADC scores:", adc_scores)
print("Exact scores:", exact_scores)
print("Reranked top-1 from 2 PQ candidates:", reranked_winner)

    Subspace variance balance and SIMD register packing

    Standard PQ slices the coordinate vector along its natural indices. If the embedding model concentrates most variance into the first few coordinates, the first subspace codebook suffers severe quantization error while later subspaces quantize near-zero noise. Optimized Product Quantization (OPQ) applies a learned orthogonal rotation matrix $R\in\mathbb{R}^{d\times d}$ ($R^\top R = I$) before slicing so that variance and correlation are distributed evenly across all $M$ subspaces without changing Euclidean distances ($\lVert Rx - Ry\rVert_2 = \lVert x - y\rVert_2$).

    In CPU engines such as Faiss's IndexPQFastScan, setting $K^*=16$ (4-bit sub-codes) lets an entire 16-entry quantized LUT for a subspace fit inside a single 128-bit SIMD register, replacing memory-bound table lookups with single-cycle pshufb / vtbl register shuffles.

    Check the operating assumptions

    Does scanning 100% of a flat IndexPQ guarantee 100% recall@K?

    No. Exhaustive scanning guarantees that every stored code is scored, eliminating candidate discovery misses, but quantization distortion can still swap the relative ranking of vectors or tie distinct vectors that share a PQ cell.

    Why does IndexIVFPQ usually beat a standalone IndexPQ at the same byte budget per vector?

    In IndexIVFPQ, the coarse centroid captures the global position of the vector, so the PQ code only needs to quantize the smaller local residual r(x) = x - c(x). That lowers reconstruction error while IVF simultaneously restricts the scan to nprobe posting lists.

    What extra storage is required if you rerank the top 50 PQ candidates with exact distances?

    You must retain access to the uncompressed (or lightly compressed, such as FP16/SQ8) vectors in RAM or on fast SSD. PQ reduces the in-memory working set needed for candidate scanning, not the need for higher-precision coordinates during a final rerank pass.
