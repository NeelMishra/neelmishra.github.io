    LSH: turn angular similarity into hash collisions

    October 2026 · 8 min read

    Cryptographic and dictionary hash functions try to scatter similar inputs across unrelated buckets. Locality-Sensitive Hashing (LSH) reverses that goal: it designs randomized hash functions where nearby vectors collide in the same bucket with much higher probability than distant vectors.

    Unlike IVF or HNSW, classical LSH is data-oblivious—its projections can be drawn before seeing a single document, and it carries provable sub-linear query guarantees. Understanding how LSH amplifies collision probabilities also explains why learned indexes usually overtake it in memory efficiency on real RAG embedding corpora.

    Derive the random-hyperplane collision law

    For cosine similarity on nonzero vectors $q,x\in\mathbb{R}^d$ separated by angle $\theta(q,x)=\arccos\!\left(\frac{q^\top x}{\lVert q\rVert_2\lVert x\rVert_2}\right)\in[0,\pi]$, Charikar's hyperplane LSH (SimHash) samples an isotropic Gaussian normal vector $r\sim\mathcal{N}(0,I_d)$ and records the sign bit:

    $$h_r(x) = \mathbf{1}\bigl[r^\top x \ge 0\bigr] \in \{0, 1\}.$$

    Project $r$ onto the two-dimensional plane spanned by $q$ and $x$. By rotational symmetry of the standard normal distribution, the projected normal direction is uniform on $[0, 2\pi)$. The hyperplane $r^\top z=0$ separates $q$ from $x$ if and only if its normal falls inside one of the two opposite wedges of angle $\theta(q,x)$, giving the exact collision probability:

    $$P\bigl[h_r(q) \ne h_r(x)\bigr] = \frac{2\theta(q,x)}{2\pi} = \frac{\theta(q,x)}{\pi}, \qquad p(\theta) = P\bigl[h_r(q) = h_r(x)\bigr] = 1 - \frac{\theta(q,x)}{\pi}.$$

    Shape the collision S-curve with K bits and L tables

    Three angles · AND within a table · OR across tables

    A single hyperplane bit gives a near neighbor at $\theta=15^\circ$ a $91.67\%$ collision chance, but a distant vector at $\theta=120^\circ$ still collides $33.33\%$ of the time. Concatenating $K=4$ bits per bucket and taking the union across $L=5$ tables suppresses the $120^\circ$ false positive to $6.02\%$ while lifting the $15^\circ$ neighbor to $99.78\%$.

    To sharpen the gentle linear drop $1-\theta/\pi$ into a steep step function, LSH combines two operations:

    1. AND construction ($K$ bits per table): Concatenate $K$ independent bits into a table key $g(x)=\bigl(h_{r_1}(x),\dots,h_{r_K}(x)\bigr)\in\{0,1\}^K$. Two vectors land in the exact same bucket in one table with probability $p(\theta)^K$.
    2. OR construction ($L$ independent tables): Build $L$ hash tables with independent keys $g_1,\dots,g_L$ and take the union of buckets $g_\ell(q)$ across all $L$ tables. A vector is discovered in at least one table with probability:
    $$P_{\text{discover}}(\theta; K, L) = 1 - \Bigl(1 - p(\theta)^K\Bigr)^L = 1 - \left(1 - \left(1 - \frac{\theta}{\pi}\right)^K\right)^L.$$

    Larger $K$ increases bucket selectivity (fewer distant false positives per table), while larger $L$ restores recall for true near neighbors at the cost of storing $L$ hash tables and performing $L$ bucket lookups per query.

    Multi-probe LSH inspects nearby buckets instead of adding tables

    Storing $L=50$ or $100$ hash tables duplicates bucket ID lists across memory. Lv and colleagues' Multi-Probe LSH observes that if a near neighbor $x$ misses $q$'s bucket $g(q)$ in a table, it likely differs only in a bit $j$ where the query itself sat very close to the splitting hyperplane ($|r_j^\top q| \approx 0$).

    Suppose a 3-bit table in $\mathbb{R}^2$ uses normals $r_1=(0,1)$, $r_2=(1,0)$, and $r_3=(1,1)$. Query $q=(1.0, 0.05)$ has projections $r^\top q = (0.05, 1.00, 1.05)$, placing it in bucket $g(q)=(1,1,1)$. Its nearest neighbor $A=(1.0,-0.05)$ has projections $(-0.05, 1.00, 0.95)$, landing in bucket $g(A)=(0,1,1)$. Sorting $q$'s margins $|r_j^\top q|$ identifies bit 1 ($0.05 \ll 1.00$) as the most fragile boundary; flipping bit 1 probes bucket $(0,1,1)$ in the existing table and finds $A$ immediately.

    import math
import numpy as np

def lsh_curve(deg, k_bits, l_tables):
    theta = math.radians(deg)
    p = 1.0 - theta / math.pi
    p_table = p ** k_bits
    p_union = 1.0 - (1.0 - p_table) ** l_tables
    return round(p, 4), round(p_table, 4), round(p_union, 4)

assert lsh_curve(15, 4, 5) == (0.9167, 0.7061, 0.9978)
assert lsh_curve(60, 4, 5) == (0.6667, 0.1975, 0.6672)
assert lsh_curve(120, 4, 5) == (0.3333, 0.0123, 0.0602)

# Multi-probe LSH trace on a 3-hyperplane table
normals = np.array([[0.0, 1.0], [1.0, 0.0], [1.0, 1.0]])
q = np.array([1.0, 0.05])
A = np.array([1.0, -0.05])

def hash_key(vec):
    return tuple(int(v >= 0.0) for v in normals @ vec)

q_key = hash_key(q)
a_key = hash_key(A)
assert q_key == (1, 1, 1) and a_key == (0, 1, 1)

# Rank bits by query margin |r_j^T q| and flip the smallest margin first
margins = np.abs(normals @ q)
weakest_bit = int(np.argmin(margins))
assert weakest_bit == 0
probed_key = tuple(1 - b if i == weakest_bit else b for i, b in enumerate(q_key))
assert probed_key == a_key
print("K=4, L=5 discovery (15, 60, 120 deg):",
      [lsh_curve(d, 4, 5)[2] for d in (15, 60, 120)])
print("Query bucket:", q_key, "-> 1-bit multi-probe bucket:", probed_key)

    In RAG pipelines, dense embeddings lie on lower-dimensional semantic manifolds rather than uniform spheres. Data-oblivious random hyperplanes often slice through empty space or bisect dense clusters, whereas IVF and HNSW adapt their partitions and routes directly to the corpus distribution. LSH remains valuable for streaming deduplication (MinHash/SimHash), online sketching without index training, and theoretical worst-case guarantees.

    Check the operating assumptions

    Does random-hyperplane LSH distinguish between two collinear vectors of different norms?

    No. Scaling x by any positive constant c > 0 leaves the sign of r^T (cx) unchanged for every hyperplane through the origin. Hyperplane LSH is sensitive only to angle; use E2LSH or normalize vectors if Euclidean norm matters.

    What happens if you increase K while keeping L = 1 fixed?

    False positives drop exponentially as p(theta)^K, but the recall of true neighbors in that single table also drops as p(theta_near)^K. High K requires either a larger L or multi-probe bucket expansion to prevent recall collapse.

    If two candidates collide with the query in the same K-bit bucket, do they have the exact same cosine similarity to q?

    No. A bucket collision only means their signs agreed on those K random projections. You still need to score the discovered bucket candidates (using exact vectors or a wider sketch) to rank the top-K results.
