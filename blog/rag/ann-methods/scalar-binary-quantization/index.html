    Scalar and binary quantization: compress coordinates and rerank the shortlist

    October 2026 · 8 min read

    Product Quantization learns multi-dimensional codebooks via k-means. When you want fast, training-light coordinate compression that pairs directly with graph traversal or hardware bitwise instructions, two simpler families dominate: Scalar Quantization (SQ8 / SQ4), which rounds each coordinate independently onto an integer grid, and Binary Quantization (BQ), which keeps only the sign bit of each coordinate ($32\times$ compression over float32).

    Because coordinate rounding discards magnitude precision—and 1-bit sign coding discards coordinate magnitudes entirely—deployed RAG engines almost always pair binary or low-bit scalar scans with oversampling and higher-precision reranking.

    Why two vectors in the same orthant collide under 1-bit quantization

    Four coordinates · identical signs · opposite magnitude profiles

    Query $q=(0.9,0.8,-0.1,-0.2)$ has large magnitudes in its first two coordinates. Vector $A=(0.85,0.75,-0.05,-0.15)$ matches that profile ($d^2=0.01$), whereas $B=(0.20,0.20,-0.80,-0.80)$ puts its weight in the last two coordinates ($d^2=1.70$). Yet both $A$ and $B$ have signs $(+,+,-,-)$, so 1-bit binary quantization gives both Hamming distance $0$ to $q$.

    Define 1-bit binary quantization by thresholding each coordinate at zero: $b_j(x)=\mathbf{1}[x_j\ge 0]\in\{0,1\}$. For $q$, $A$, and $B$, the resulting 4-bit code is $(1,1,0,0)$, while $C=(0.80,-0.70,-0.10,-0.20)$ maps to $(1,0,0,0)$.

    Binary quantization cannot distinguish $A$ from $B$ because it records only which orthant of $\mathbb{R}^d$ a vector occupies. Uniform 4-bit scalar quantization (SQ4) preserves enough coordinate magnitude to separate $A$ ($0.0067$) from $B$ ($1.8822$) by more than two orders of magnitude.

    Affine scalar quantization and its coordinate error bound

    A $b$-bit uniform scalar quantizer (such as Faiss's QT_8bit or QT_4bit) maps coordinate $j$ from range $[x_{\min,j}, x_{\max,j}]$ with step size $\Delta_j = (x_{\max,j} - x_{\min,j})/(2^b - 1)$ to an integer index $q_j\in\{0,\dots,2^b-1\}$:

    $$q_j(x) = \operatorname{clip}\!\left(\operatorname{round}\!\left(\frac{x_j - x_{\min,j}}{\Delta_j}\right),\, 0,\, 2^b - 1\right), \qquad \hat{x}_j = x_{\min,j} + \Delta_j\, q_j(x).$$

    For any coordinate $x_j \in [x_{\min,j}, x_{\max,j}]$ that does not clip, the rounding error satisfies $|x_j - \hat{x}_j| \le \Delta_j / 2$. Summing across all $d$ coordinates bounds the worst-case Euclidean reconstruction error:

    $$\lVert x - \hat{x}\rVert_2^2 = \sum_{j=1}^{d} (x_j - \hat{x}_j)^2 \le \frac{1}{4}\sum_{j=1}^{d} \Delta_j^2.$$

    At $b=8$ bits ($255$ intervals), $\Delta_j$ is tiny and SQ8 routinely matches float32 recall@10 within fractions of a percent while cutting vector memory by $4\times$. See the quantization grids and scales guide for clipping vs rounding tradeoffs and TurboQuant for spherical rotation quantizers that achieve optimal distortion bounds without per-vector scales.

    Binary quantization, XOR + POPCNT, and asymmetric scoring

    Map each binary bit $u_j\in\{0,1\}$ to a bipolar coordinate $\tilde{u}_j = 2u_j - 1 \in \{-1, +1\}$. The Hamming distance $d_H(u,v)$—the count of coordinates where signs differ—is an exact affine transform of the bipolar inner product:

    $$d_H(u, v) = \sum_{j=1}^{d} (u_j \oplus v_j) = \frac{d - \tilde{u}^\top \tilde{v}}{2}.$$

    Packing 64 dimensions into a single `uint64` word allows a CPU to evaluate 64 coordinates with one bitwise `XOR` and one hardware `POPCNT` instruction. For a 768-dimensional embedding, a stored vector shrinks from $3{,}072$ bytes (float32) to $96$ bytes (12 `uint64` words).

    Recover ranking fidelity with oversampled reranking

    When binary quantization collapses intra-orthant magnitudes, a query requesting $K$ final passages first retrieves an oversampled shortlist of $K_{\text{cand}} = \gamma K$ candidates ($\gamma$ typically $4$ to $32$) using fast Hamming distance in RAM, then fetches full-precision (or SQ8/FP16) vectors for only those $K_{\text{cand}}$ IDs to compute exact distances:

    import numpy as np

q = np.array([0.9, 0.8, -0.1, -0.2])
vectors = {
    "A": np.array([0.85, 0.75, -0.05, -0.15]),
    "B": np.array([0.20, 0.20, -0.80, -0.80]),
    "C": np.array([0.80, -0.70, -0.10, -0.20]),
}

def binary_code(x):
    return (x >= 0.0).astype(np.int32)

def hamming(u, v):
    return int(np.sum(u ^ v))

def sq4_quantize(x, vmin=-1.0, vmax=1.0):
    delta = (vmax - vmin) / 15.0
    codes = np.clip(np.round((x - vmin) / delta), 0, 15).astype(np.int32)
    recon = vmin + delta * codes
    return codes, recon

bq = binary_code(q)
hamming_scores = {vid: hamming(bq, binary_code(x)) for vid, x in vectors.items()}
assert hamming_scores == {"A": 0, "B": 0, "C": 1}

sq4_codes = {}
sq4_l2 = {}
exact_l2 = {}
for vid, x in vectors.items():
    codes, recon = sq4_quantize(x)
    sq4_codes[vid] = tuple(int(c) for c in codes)
    sq4_l2[vid] = round(float(np.sum((q - recon) ** 2)), 4)
    exact_l2[vid] = round(float(np.sum((q - x) ** 2)), 4)

assert sq4_codes["A"] == (14, 13, 7, 6)
assert sq4_codes["B"] == (9, 9, 1, 1)
assert sq4_l2 == {"A": 0.0067, "B": 1.8822, "C": 2.3533}
assert exact_l2 == {"A": 0.01, "B": 1.7, "C": 2.26}

# Oversample top-2 binary candidates, then rerank with exact L2
shortlist = [vid for _, vid in sorted((d, vid) for vid, d in hamming_scores.items())[:2]]
assert shortlist == ["A", "B"]
winner = min(shortlist, key=lambda vid: exact_l2[vid])
assert winner == "A"
print("Hamming distances:", hamming_scores)
print("SQ4 L2 distances:", sq4_l2)
print("Oversampled binary + exact rerank winner:", winner)

    Centering and coordinate correlation pitfalls

    If an embedding model produces strictly positive coordinates in several dimensions (for example, after an uncentered activation or asymmetric layer), thresholding at zero sets $b_j(x)=1$ for almost every document, wasting that bit's entropy. Subtracting the corpus mean $\mu$ before sign extraction ($b_j(x)=\mathbf{1}[x_j - \mu_j \ge 0]$) restores balanced bit probabilities. Similarly, rotating coordinates with a random orthogonal matrix before binarization (as in RaBitQ and QJL) spreads concentrated coordinate energy across all $d$ sign bits so no single coordinate dominates the inner product.

    Check the operating assumptions

    Does 1-bit binary quantization reduce total storage by 32x if exact reranking is enabled?

    It reduces the in-memory index used for initial candidate discovery by 32x, but the full-precision (or SQ8/FP16) vectors still need to live on SSD or in a secondary store to serve the oversampled reranking step.

    Why can binary quantization perform better on 1024-dimensional embeddings than on 16-dimensional vectors?

    In higher dimensions, the angle between two isotropic vectors is estimated from d sign comparisons with standard error scaling as O(1/sqrt(d)). With only 16 bits, only 17 discrete Hamming distances exist, creating massive ties across the corpus.

    When can uniform SQ8 fail despite having 256 levels per coordinate?

    If a few outlier vectors expand [xmin, xmax] to a huge interval while normal embeddings live in [-0.1, 0.1], most of the 256 levels sit in empty outer tails and normal coordinates collapse onto a handful of central bins. Clipping percentiles or normalizing vectors before quantization prevents outlier range inflation.
