    GPTQ: fixed order, lazy batches, and Cholesky

    October 2026 · 7 min read

    Part 2 derived the compensation after rounding one weight. Applying that update separately to every weight in a large layer would be expensive. GPTQ makes it practical by sharing one column order, preparing a triangular factor once, and delaying writes to columns outside the current block.

    Process the same column across every output row

    Let $W$ have $m$ output rows and $d$ input columns. Greedy OBQ chooses the cheapest next weight independently in each row. After those choices, different rows may have different sets of free columns and need different active inverses.

    GPTQ chooses a column order in advance and shares it across all output rows. In left-to-right order, step $j$ rounds column $j$ in every row. Each entry may land on a different grid point, but every row has the same free set $F=\{j,\ldots,d-1\}$.

    The Hessian depends only on calibration inputs, not the row's weights. A shared free set therefore means a shared active inverse. One preparation serves all $m$ output rows.

    The paper finds that on its large layers, fixed-order reconstruction is competitive with the greedy method. This is an empirical trade-off, not a guarantee that every fixed order is equally accurate. Order can change the final rounding decisions.

    With separate greedy orders, OBQ's repeated inverse updates cost $O(md^3)$. GPTQ instead pays $O(d^3)$ for matrix preparation and $O(md^2)$ for weight corrections. This operation-count reduction is not a universal wall-clock speedup; matrix sizes, hardware, and kernels still matter.

    The authors' later actorder option permutes input columns by descending Hessian diagonal before the pass. It still uses one shared order. It is not OBQ's adaptive greedy selection.

    Prepare the directions, not the rounded values

    Use the same sample-row table $A\in\mathbb R^{n\times d}$ as before and $H=2A^{\mathsf T}A$. The paper's $X=A^{\mathsf T}$ gives the identical matrix $2XX^{\mathsf T}$. Neither form requires transposing the stored PyTorch weight matrix away from its $(\text{out},\text{in})$ layout.

    In a fixed order, every future active Hessian is known from the start. It depends on which columns remain free, not on the grid values chosen for earlier columns. We can prepare the correction directions before rounding any weight.

    The rounded values cannot be prepared independently. Column $j$ must include compensation from columns $0,\ldots,j-1$ before its grid point is chosen. Precomputing the matrix removes repeated inverse work, not this sequential dependence between weights.

    Update nearby columns now; later columns can wait

    After each column, an immediate update to every later weight would repeatedly read and write a large matrix. Lazy batching reduces that traffic. Choose an update block of $B$ consecutive input columns; the paper and authors' code use 128 by default.

    1. Round the first column in the block using its current weights.
    2. Immediately compensate the unrounded columns inside the block.
    3. Round the next column using those updated values and repeat.
    4. At the block's end, apply all its recorded corrections to columns after the block in one matrix multiplication.

    Waiting to update those distant columns is safe: none is rounded until the current block finishes. Rounding all columns inside the block at once would not be equivalent. The next rounding decision depends on the previous correction.

    Here is the actual blocked update in triangular-factor notation, defined below. Let $Q$ be the quantized weight matrix and $U$ the $d\times d$ upper-triangular factor. For column $j$, the vector $E_{:,j}$ contains one normalized rounding discrepancy per output row:

    $$Q_{:,j}=\operatorname{quant}(W_{:,j}),\qquad E_{:,j}=\frac{W_{:,j}-Q_{:,j}}{U_{jj}}.$$

    The quantizer uses the relevant grid for each entry. $E_{:,j}$ has shape $m\times1$. If the block ends just before column $b$, apply its outer-product correction inside the block:

    $$W_{:,j:b}\leftarrow W_{:,j:b}-E_{:,j}U_{j,j:b}.$$

    The slice $j:b$ includes $j$ but excludes $b$. The product has shape $m\times(b-j)$. Its first column subtracts $W_{:,j}-Q_{:,j}$, placing column $j$ exactly on the grid. Later columns in the block receive compensation before they are rounded.

    At the end, let $J$ be the completed block and $T$ the columns after it. Stack its recorded vectors into $E_{:,J}$, of shape $m\times B$. The delayed correction is:

    $$W_{:,T}\leftarrow W_{:,T}-E_{:,J}U_{J,T}.$$

    With $|T|$ later columns, $U_{J,T}$ has shape $B\times|T|$, so this one product updates an $m\times|T|$ region. The final block may have fewer than $B$ columns. This reorganizes the same sequential corrections; it does not solve a joint rounding problem for the whole block.

    A quantization group has a different purpose: its entries share scale and zero-point parameters. groupsize changes the grids and storage overhead; blocksize changes the correction schedule. Group-wise implementations may estimate grids as groups are reached, or keep them fixed. Either way, groups are not the update blocks.

    Damp the Hessian, then store a triangular factor

    Input features may be correlated or rarely active, making $H$ singular or nearly singular. Direct inversion and repeated inverse downdates can then amplify numerical error. GPTQ adds a positive diagonal term before factorization.

    Let $\lambda$ be the damping strength, $I_d$ the $d\times d$ identity, and $\alpha$ a chosen fraction of the average Hessian diagonal. Call the resulting Hessian $H_{\mathrm{damped}}$ and its inverse $G$. The authors' default is $\alpha=0.01$:

    $$\lambda=\alpha\frac{\operatorname{tr}(H)}{d},\qquad H_{\mathrm{damped}}=H+\lambda I_d,\qquad G=H_{\mathrm{damped}}^{-1}.$$

    Damping makes the solve less sensitive to weakly observed directions. It also changes the objective: with our sum convention it adds $\tfrac{\lambda}{2}\lVert v-w\rVert_2^2$ to the reconstruction cost. The resulting updates optimize this regularized quadratic, not exactly the undamped output error in Part 2. Consistently scaling $H$ and $\lambda$ preserves the compensation.

    The authors' code also handles input columns with zero Hessian diagonal before damping: those features are absent on calibration data, so their weights can be set to zero without changing the observed outputs. This alone says nothing about unseen inputs.

    Now factor the inverse as follows. $U$ is upper triangular with positive diagonal entries:

    $$U^{\mathsf T}U=G=H_{\mathrm{damped}}^{-1}.$$

    This orientation matters: $U$ factors the inverse, not the Hessian. The authors' implementation first factors the damped Hessian to compute its inverse, then takes an upper Cholesky factor of that inverse.

    Why can this one triangle replace the active inverse at every step? Let $G^{(j)}$ be the inverse on the columns still free at step $j$, after eliminating earlier columns. Upper Cholesky performs those same rank-one eliminations while storing scaled pivot rows:

    $$G^{(j)}_{jj}=U_{jj}^2,\qquad G^{(j)}_{j,j:}=U_{jj}U_{j,j:}.$$

    Each stored row is the corresponding active-inverse row divided by the square root of its pivot. For a single output row with discrepancy $a=v_j-t$, substituting these identities into the inverse update gives:

    $$\delta_{j:}^{\mathsf T} =-\frac{a}{G^{(j)}_{jj}}G^{(j)}_{j,j:} =-\frac{a}{U_{jj}}U_{j,j:}.$$

    This explains the normalizer in the block loop. Divide the weight discrepancy by $U_{jj}$, then multiply by the stored factor row. Do not divide by the original inverse diagonal $G_{jj}$, or by the Hessian diagonal $H_{jj}$.

    For the undamped numerical example in Part 2, the original inverse starts with row $(1.92250,-2.56343,-0.35974)$. Its upper factor starts with row approximately $(1.38654,-1.84880,-0.25945)$. Since $1.38654^2\approx1.92250$, dividing the inverse row by $1.38654$ produces the factor row.

    Later pivots correspond to reduced active inverses, not the original inverse's diagonals. The triangular factor supplies those pivots without repeatedly modifying a running inverse during quantization. This improves numerical robustness; it is not a promise of exact arithmetic or a fixed speed multiplier.

    The complete pass

    1. Collect representative calibration inputs, form the input-feature Hessian, and choose the quantization scheme.
    2. Choose one shared column order, damp the Hessian, and compute $U$ with $U^{\mathsf T}U=H_{\mathrm{damped}}^{-1}$ in that order.
    3. Within each update block, round columns sequentially. Divide each current rounding discrepancy by $U_{jj}$ and immediately correct the remaining columns inside the block.
    4. Apply the accumulated block correction to later columns in one product. Keep completed columns fixed and continue.

    The result is a low-bit weight matrix chosen to preserve calibration outputs. Test the finished model's quality and serving performance separately. Calibration error is not task accuracy, and compressed storage is not by itself a fast serving kernel.

    Why not use the whole inverse directly?

    The first step can use it directly. Later steps need inverses on smaller free sets. The factor stores the required reduced directions and their normalizers in advance, without repeated downdates.

    Does a block of 128 mean all 128 columns round together?

    No. Rounding and compensation remain sequential inside the block. Only the writes to columns outside it are delayed and combined.
