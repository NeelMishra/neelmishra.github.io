    GPTQ: the layer objective and compensation loop

    October 2026 · 5 min read

    A trained layer contains floating-point weights. Quantization replaces them with values from a much smaller grid. Simple rounding does this independently for every weight. GPTQ adds a second step: after rounding, change the weights still free to move so that the layer's output changes less.

    Why shrink the weights?

    Low-bit weights take less space to store and transfer. A 4-bit weight needs one quarter of the raw storage of a 16-bit weight, before accounting for scales, zero points, and packing overhead.

    That can help inference when moving weights from memory is the bottleneck. It does not promise a particular speedup. The serving kernel must use the compressed format effectively; unpacking and other work can offset the savings. A compute-bound workload may benefit differently from a memory-bound one.

    GPTQ is the offline procedure that builds the low-bit weights. Its own runtime and the finished model's inference runtime are separate measurements.

    The grid decides where a weight can land

    A quantizer maps a real number to a legal grid point. A scale determines the spacing; a zero point can shift the grid. More bits allow more points. A narrow range gives finer spacing but may clip values outside that range.

    One grid for a whole tensor can be too coarse if different output channels have different ranges. Per-output-channel grids fit each weight row separately. Group-wise quantization can use a separate grid for a smaller group of input columns within each row.

    These choices reduce rounding error before any compensation. They are not GPTQ by themselves: round-to-nearest can use exactly the same grids.

    Also distinguish groupsize from blocksize. Groups share scale and zero-point parameters. Update blocks collect correction writes to make the solver more efficient. Both may be 128 columns, but changing one does not automatically change the other.

    One rounded weight changes every sample's output

    Consider one output channel. Its weights form a column vector $w$ of length $d$. The calibration table $A$ has $n$ rows of samples and $d$ input columns, so the original output vector is $y=Aw$, of length $n$.

    If weight $w_q$ is rounded to $t$, its change is $t-w_q$. Column $A_{:,q}$ contains the value of that input feature in every sample. With all other weights unchanged, the new output minus the original output is:

    $$\Delta y=(t-w_q)A_{:,q}.$$

    This is a vector of $n$ output errors, not just one weight error. A small weight change can matter a lot if that input feature has large values.

    Now let $\delta$ be the full vector of weight changes, including the rounded coordinate and any compensation. We keep $\delta_q=t-w_q$ and choose the other entries to reduce:

    $$\lVert A\delta\rVert_2^2 =\sum_{s=1}^{n}\bigl((A\delta)_s\bigr)^2.$$

    The expression is the sum of squared output changes over the calibration samples. If two input columns are related, changing one weight can partly cancel the output error caused by changing the other. The best compensation is a constrained least-squares solution, derived in Part 2.

    Already rounded weights stay fixed. As the process continues, fewer weights remain available to compensate. The final column has no later column to help it.

    The update and the order are different choices

    Optimal Brain Quantization (OBQ), described in Optimal Brain Compression, uses this compensation idea. Within each output row, it estimates the extra compensated error of rounding each remaining weight and chooses the smallest. Different rows can therefore choose different columns next.

    GPTQ keeps the compensation but drops that repeated greedy search. It chooses an order once and rounds the same input column across every output row at each step. Because those rows saw the same inputs, they share the matrix needed for the correction.

    The constrained-update algebra also appears in Optimal Brain Surgeon, where the target value is zero for pruning. That connection is useful, but GPTQ's objective here is linear-layer reconstruction, not a Taylor approximation to the whole model's training loss.

    The GPTQ loop, step by step

    1. Collect calibration inputs. Run representative data through the model and retain the inputs to the layer. They tell the solver which output changes matter.
    2. Prepare the correction matrix and grids. Compute input correlations, add damping for numerical stability, and prepare the triangular factor used for updates.
    3. Round the next column. Use the current, already-compensated weight values. Each output row rounds its entry in this same input column to its grid.
    4. Compensate later columns. Adjust the unfixed weights using the input correlations. Keep every rounded column on its chosen grid point.
    5. Continue in the chosen order. Inside an update block, corrections are applied immediately to columns that will be rounded next. Corrections to columns beyond the block can wait until its end.

    There is no GPTQ step that selects the “easiest row.” The greedy candidate scores belong to OBQ. GPTQ's fixed order is what makes one shared precomputation possible; Part 3 explains the savings.

    For a concrete check, Part 2 rounds $-0.85$ to $-1$ in a three-weight layer. Moving the other two weights lowers output squared error from $0.05265$ to about $0.003090$. It demonstrates one update; it does not yet quantize the whole layer.

    Does calibration retrain the model?

    No. GPTQ uses calibration activations to reconstruct layer outputs. It does not run the original pretraining objective or update weights by backpropagation through the whole model.

    What if calibration data is unrepresentative?

    The correction can fit the observed inputs well and still be poor on different inputs. Evaluate the finished quantized model on the workloads you actually need.
