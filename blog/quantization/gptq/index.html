    GPTQ: quantize the layer, then compensate

    October 2026 · 4 min read

    Rounding a weight changes a layer's output. GPTQ reduces that change by adjusting weights that have not been rounded yet. Those weights can partly compensate for the error because different input features often carry related information.

    The aim is not to keep every weight close to its original value. It is to keep the layer's answers close on representative inputs. An unrounded weight may move farther from its original value if that makes the output more accurate.

    1. Collect inputs from a small calibration set.
    2. Round one input column of weights, across all output rows.
    3. Adjust the remaining columns to reduce the resulting output error.
    4. Repeat in a fixed order, keeping rounded columns fixed.

    GPTQ shares the same input-dependent correction across output rows. A triangular factor prepares those corrections in advance; blocks let the implementation apply them with fewer large weight-matrix writes. Neither change removes the need to update a column before rounding it.

    Keep the output, not each individual weight

    Let $A$ be a table with $n$ calibration samples and $d$ input features: its shape is $n\times d$. Let $W$ contain the original weights, with shape $m\times d$, where $m$ is the number of output channels. PyTorch nn.Linear stores weights in this order and computes $Y=AW^{\mathsf T}$, an $n\times m$ output table.

    We want a low-bit matrix $\widehat W$ whose outputs are similar. The loss below adds up squared differences over every sample and output channel; the subscript $F$ denotes the Frobenius norm, not a set of free weights.

    $$\min_{\widehat W\ \text{on the quantization grid}} \lVert AW^{\mathsf T}-A\widehat W^{\mathsf T}\rVert_F^2.$$

    Zero would mean identical outputs on the calibration set. This is a sum, not a mean. Dividing by $nm$ gives mean squared error but does not change which weights minimize it.

    The paper puts samples in columns instead: $X=A^{\mathsf T}$ has shape $d\times n$, and its output is $WX=Y^{\mathsf T}$. Thus its loss $\lVert WX-\widehat W X\rVert_F^2$ is the same sum. Part 2 shows why this transpose matters when building the correction matrix.

    The distinctions to keep straight

    • Rounding versus compensation: the grid chooses a legal value; compensation changes the weights still free to move.
    • OBQ versus GPTQ: greedy OBQ chooses the cheapest next weight separately in each output row. GPTQ processes the same input column across all rows in a fixed order.
    • Group versus block: a group shares quantization parameters. A block controls when corrections are written to later columns.
    • Layer error versus model quality: matching calibration outputs is useful, but it does not guarantee identical generated text or unchanged task accuracy.

    These posts explain weight-only quantization. Low-bit weights do not imply low-bit activations. Inference speed also depends on the hardware, kernels, and workload, not just the number of bits.

    A small result you can check

    In the worked example, one output uses three weights and five calibration samples. Rounding the middle weight from $-0.85$ to $-1$ alone gives output squared error $0.05265$. Adjusting the other two weights reduces it to about $0.003090$.

    That is one compensated step, not the error of the finished low-bit layer. The other two weights still need rounding. The existing tools/check_gptq_update.py verifies the step against a direct least-squares solve.
