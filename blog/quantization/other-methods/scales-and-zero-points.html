    Scales, zero points, and clipping

    October 2026 · 5 min read

    Quantization stores a code instead of the original real number. The code only has meaning together with the rule that reconstructs it. Before comparing algorithms, write that rule down.

    An affine quantizer

    Let $s>0$ be a scale, $z$ an integer zero point, and $[q_{\min},q_{\max}]$ the available integer codes. A common round-to-nearest quantizer is

    $$q(x)=\operatorname{clip}\!\left(\operatorname{round}(x/s)+z,q_{\min},q_{\max}\right),\qquad \widehat{x}=s(q(x)-z).$$

    For a nondegenerate observed range $[a,b]$ that includes zero, one starting choice is $s=(b-a)/(q_{\max}-q_{\min})$ and $z=\operatorname{clip}(\operatorname{round}(q_{\min}-a/s),q_{\min},q_{\max})$. Include zero by extending a wholly positive or negative range before applying this recipe. Handle constant or all-zero tensors explicitly so the scale never becomes zero. Actual libraries also specify the tie-breaking rule for rounding.

    In symmetric quantization, zero has a fixed code. For example, using signed four-bit codes $[-7,7]$ deliberately leaves one of the sixteen codes unused and gives a balanced grid. That is a convention, not the only signed INT4 scheme.

    A four-bit calculation

    Use that symmetric grid with $s=0.5$ and $z=0$. The values $[-1.1,0.2,2.9]$ become codes $[-2,0,6]$ and reconstruct to $[-1,0,3]$. Their squared errors sum to $0.01+0.04+0.01=0.06$, so the mean squared error is $0.02$.

    A value of $5$ would round to code $10$, but the grid stops at $7$. It reconstructs to $3.5$ with error $1.5$. Inside the grid, nearest rounding has absolute error at most $s/2$; clipping does not have that bound. This is why an outlier can dominate the error even when most values round well.

    One scale for which values?

    • Per tensor: one scale is cheap to store, but a single large value makes the grid coarse for everybody.
    • Per channel: separate channels get separate ranges. Always state the axis; input and output channels are not interchangeable.
    • Per group: subsets of weights share parameters. Smaller groups can improve resolution while increasing metadata and kernel complexity.
    • Per token: activation ranges can be chosen from each token at runtime. Dynamic scaling adds work; static scaling uses ranges selected before deployment.

    Calibration chooses ranges or other quantizer parameters using representative examples. Weight ranges are available directly from the checkpoint, but activation ranges depend on inputs. A calibration corpus that never exercises a difficult feature can produce a deceptively good local reconstruction.

    Bits on disk versus bits in a multiplication

    For $N$ weights, a $b$-bit payload needs about $Nb/8$ bytes before padding. If each group of $g$ weights also stores one FP16 scale, that adds $2N/g$ bytes, ignoring rounding of the group count. Zero points, unquantized tensors, and alignment add more. Four-bit weights therefore do not make the whole serving process exactly four times smaller than FP16.

    Some runtimes unpack low-bit weights into floating-point operands. Others use integer operands with wider accumulators. Neither follows from file size alone. Weight compression also does not shrink the KV cache unless a separate cache quantizer is enabled.

    Would widening the range always reduce error?

    No. It reduces clipping but increases the spacing between grid points for a fixed number of codes. Good range selection balances clipping against rounding, ideally under a relevant output-quality objective.
