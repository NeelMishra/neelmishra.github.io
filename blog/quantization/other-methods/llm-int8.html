    LLM.int8: separate the outliers

    October 2026 · 4 min read

    An activation row containing $[0.2,-0.1,50]$ illustrates the problem. A symmetric INT8 scale set by $50$ is roughly $50/127=0.394$. Both small values round poorly even though they might matter to the output. LLM.int8 handles difficult feature dimensions separately instead of forcing all their values through one low-precision path.

    Fix the matrix layout

    Use $X\in\mathbb{R}^{T\times C}$ for token activations and $W\in\mathbb{R}^{C\times D}$ for weights, so $Y=XW$. A PyTorch linear layer stores its weight tensor as $D\times C$; here $W$ is its transpose. Let $O$ be the input-feature indices flagged as outliers, and $R$ the remaining indices. Then, before quantization,

    $$XW=X_{:,R}W_{R,:}+X_{:,O}W_{O,:}.$$

    This identity is exact: it just partitions the sum over input features. The first term becomes the INT8 matrix multiplication; the second is evaluated in higher precision and added back. Detection uses activation magnitudes and a threshold, not an assumption that only the largest weights are important.

    The ordinary path still needs scales

    Vector-wise quantization assigns a scale $a_t$ to each ordinary activation row and $b_d$ to each ordinary weight column. With symmetric integer codes, the ordinary output is approximated by

    $$\widehat{Y}_{td}^{\,R}=a_t b_d\sum_{c\in R}Q^X_{tc}Q^W_{cd}.$$

    The sum needs a wider accumulator than INT8. Rescaling and adding the outlier term produces a floating-point output. Thus “eight-bit” describes the main operands, not every operation in the network.

    Trace the split

    For $x=[0.2,-0.1,50]$ and $w=[1,2,0.5]$, the original dot product is $0.2-0.2+25=25$. If feature 3 is flagged, the ordinary contribution is $0$ before quantization and the high-precision contribution is $25$. The INT8 path may perturb the first two terms, but it no longer has to use a grid wide enough for $50$.

    Real inference batches have many rows. A feature flagged by an outlier in one row can be routed through the exception path for the multiplication, so the cost depends on how many feature dimensions are selected, not merely how many individual scalar values exceed the threshold.

    What to evaluate

    The split protects quality but introduces detection, extraction, and another multiplication. Lowering the threshold can route more features through higher precision; raising it can leave harmful outliers on the INT8 path. Benchmark the implementation and model rather than assuming the mixed-precision path beats FP16 at every batch size.

    There is no gradient-based model retraining in this method. That does not mean there are no configuration choices: threshold, supported modules, and runtime behavior still matter. The next method, SmoothQuant, addresses the same activation-range problem by changing the equivalent representation before quantization.

    Is LLM.int8 simply a smaller weight file?

    No. Its central contribution includes vector-wise quantization and a mixed-precision decomposition of the matrix multiplication. Weight storage alone does not describe that execution.
