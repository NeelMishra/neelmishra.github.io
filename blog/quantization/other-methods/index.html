    Beyond GPTQ: choose what to quantize

    October 2026 · 5 min read

    A four-bit checkpoint, an eight-bit matrix multiplication, and a quantized model being fine-tuned are three different things. This independent series starts with that distinction, then follows methods other than GPTQ. The existing GPTQ derivation series remains a separate reading path; it is not a prerequisite.

    Reading route

    1. Scales, zero points, and clipping: build a quantizer and measure its error before choosing an algorithm.
    2. LLM.int8: separate the outliers: split a matrix multiplication into an INT8 path and a higher-precision exception path.
    3. SmoothQuant: move the difficult range: rescale channels so both weights and activations can use eight bits.
    4. AWQ: protect important weight channels: use activation statistics to choose a weight-only quantizer.
    5. NF4 and QLoRA: storage is not training precision: distinguish a nonuniform codebook from adapter fine-tuning.
    6. QAT: train with the error in the loop: simulate quantization during optimization, then validate the exported model.

    Match the method to the job

    Start with the bottleneck. If weight reads dominate decoding, weight-only compression such as AWQ may help. If a supported INT8 kernel can accelerate the large matrix multiplications in your workload, SmoothQuant's W8A8 path is worth testing. LLM.int8 handles difficult activation features using mixed precision rather than smoothing them away. QLoRA addresses fine-tuning memory; it is not an inference-kernel specification.

    Then ask what can change. Post-training quantization (PTQ) keeps the trained model parameters conceptually fixed while constructing a compressed approximation; it can still require calibration data and searches over scales. Quantization-aware training (QAT) changes trainable parameters under simulated quantization. QLoRA trains adapters while keeping its quantized base frozen, so it should not be confused with QAT.

    Finally check the runtime. W4A16 means four-bit weights and sixteen-bit activations, not four-bit arithmetic everywhere. W8A8 says nothing by itself about accumulation, normalization, attention softmax, or the KV cache. GGUF is a model container with several quantization formats, not one optimization algorithm. Use the deployment comparison after the method notes.

    One evaluation contract for every method

    • Keep the full-precision baseline, tokenizer, prompts, and evaluation split fixed. Keep calibration separate from the held-out evaluation set.
    • Report downstream quality as well as perplexity where appropriate. Include long contexts, rare tokens, and domain-specific inputs that may expose outliers.
    • Measure peak device memory, prefill latency, time per output token, and throughput separately, under stated batch sizes and context lengths.
    • Record weight and activation formats, scale granularity, group size, excluded layers, runtime, hardware, and actual kernels. Include scale metadata and KV-cache memory in the budget.
    Is there one best quantization method?

    No. Calibration quality, the architecture, hardware kernels, and the workload can change the ranking. A smaller checkpoint is evidence of compression, not proof of faster serving.
