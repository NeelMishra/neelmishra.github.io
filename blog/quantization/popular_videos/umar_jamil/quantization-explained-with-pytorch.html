    Quantization explained with PyTorch - Post-Training Quantization, Quantization-Aware Training

    October 2026 · Umar Jamil's video

    Based on Umar Jamil's video. The figures are his actual accompanying slides, reproduced under CC BY-NC 4.0. Click a figure to view it at full size.

    A 7B-parameter model in FP32 ($4\text{ bytes/param}$) requires $7\times10^9\times4=28\text{ GB}$ just to store its weights. Quantization replaces floating-point weights and activations with low-bit integers (typically 8-bit), shrinking that weight footprint to $7\text{ GB}$ and accelerating matrix multiplications.

    While an 8-bit integer maps its $2^8=256$ bit patterns uniformly to $[0,255]$ (unsigned) or $[-128,127]$ (signed two's-complement), IEEE 754 FP32 splits 32 bits into 1 sign bit, 8 exponent bits (bias $127$), and 23 fraction bits, decoding normal numbers as $(-1)^\sigma 2^{E-127}(1+f)$. For example, $0.15625 = 1.01_2\times 2^{-3} = 1.25\times 2^{-3}$ ($E=124$, $f=0.25$):

    In 16-bit floating point, standard IEEE 754 FP16 (1 sign, 5 exponent, 10 fraction; max $65{,}504$) narrows the exponent and risks overflow. BFloat16 (bf16) instead keeps FP32's full 8-bit exponent (same $\pm 3.4\times 10^{38}$ range) and truncates the fraction from 23 bits to 7 bits:

    Integer quantization discards the sign/exponent/fraction split entirely, mapping a real interval onto a uniform grid of integer codes for the inputs, weights, and outputs of $Y=XW+B$:

    Given an integer code $q$, step scale $s$, and zero point $z$ (the integer code representing real $0$), dequantization reconstructs:

    $$\widehat{x}=s(q-z).$$

    An asymmetric grid maps an arbitrary interval $[\beta,\alpha]$ to $[0,2^b-1]$; a symmetric grid centers the interval on zero ($[-A,A]$) with $z=0$:

    For asymmetric quantization over $[\beta,\alpha]$ with $b$ unsigned bits ($2^b-1$ steps):

    $$s=\frac{\alpha-\beta}{2^b-1},\qquad z=\operatorname{round}(-\beta/s),\qquad q=\operatorname{clip}\!\left(\operatorname{round}(x/s)+z,\ 0,\ 2^b-1\right).$$

    With $\beta=-44.93$ and $\alpha=43.31$, $s=88.24/255\approx0.3460$ and $z=130$. The entry $43.31$ maps to $q=255$ and reconstructs to $s(255-130)\approx43.25$. Real zero is code $z=130$ (whereas code $0$ is $-44.99$), so zero-padding must write $z$ rather than $0$.

    For symmetric quantization, set $A=\max|x|$ and map $[-A,A]$ to signed codes $[-Q,Q]$ with $Q=2^{b-1}-1=127$ (dropping $-128$ for symmetry, $z=0$):

    $$s=\frac{A}{Q},\qquad q=\operatorname{clip}\!\left(\operatorname{round}(x/s),-Q,Q\right),\qquad \widehat{x}=sq.$$

    Here $s=44.93/127\approx0.3538$, mapping $43.31 \mapsto q=122 \mapsto \widehat{x}\approx43.16$ with no zero-point offset. Symmetric grids suit zero-centered weights; asymmetric grids better fit one-sided activations like ReLU (see Umar's first notebook).

    Weights are fixed after training, whereas activation ranges depend on the input—estimated at runtime (dynamic quantization) or ahead of time by passing representative unlabeled inputs through observers (static calibration). Once quantized, an INT8 dot product accumulates into a wider INT32 register to prevent overflow:

    Substituting $x_i\approx s_x(q_{x,i}-z_x)$ and $w_i\approx s_w(q_{w,i}-z_w)$ with quantized INT32 bias $q_b=\operatorname{round}(b/(s_xs_w))$ gives the integer accumulator $a$ and rescaled output code $q_y$ (gemmlowp derivation):

    $$\widehat{y}=s_xs_w\sum_i(q_{x,i}-z_x)(q_{w,i}-z_w)+b,\qquad a=\sum_i(q_{x,i}-z_x)(q_{w,i}-z_w)+q_b,$$
    $$q_y=\operatorname{clip}\!\left(\operatorname{round}\!\left(\frac{s_xs_w}{s_y}a\right)+z_y,\ q_{\min,y},q_{\max,y}\right).$$

    Min-max range selection is sensitive to outliers: a single $1000$ entry stretches $[-50,150]$ ($s=200/255\approx0.78$) to $[-50,1000]$ ($s=1050/255\approx4.12$), coarsening every non-outlier value:

    Percentile calibration (e.g., $0.01\text{st}$–$99.99\text{th}$ in Umar's comparison notebook) or MSE/cross-entropy search clips extreme outliers to preserve resolution for the bulk distribution. Likewise, per-channel quantization gives each output row of PyTorch's [out_features, in_features] weight matrix (axis $0$) its own scale rather than sharing a single per-tensor scale.

    Post-Training Quantization (PTQ) attaches observers to a pretrained float model, calibrates activation ranges on unlabeled data, and swaps float modules for quantized kernels without retraining (PTQ notebook):

    import torch
from torch.ao import quantization as quant

torch.backends.quantized.engine = "qnnpack"
prepared = net_with_stubs.cpu().eval()
prepared.qconfig = quant.get_default_qconfig("qnnpack")
prepared = quant.prepare(prepared, inplace=False)

with torch.no_grad():
    for images, _ in calibration_loader:
        prepared(images.cpu())

int8_model = quant.convert(prepared, inplace=False)

    Quantization-Aware Training (QAT) inserts fake-quantization nodes (quantize $\to$ dequantize in float) during training so the loss accounts for rounding noise while the optimizer updates FP32 master weights:

    Because $\operatorname{round}(\cdot)$ has zero derivative almost everywhere, QAT uses the Straight-Through Estimator (STE) in the backward pass—treating fake quantization as the identity ($\partial\widehat{x}/\partial x = 1$) inside the clipping bounds and $0$ outside (QAT notebook):

    qat_model = net_with_stubs.cpu().train()
qat_model.qconfig = quant.get_default_qat_qconfig("qnnpack")
qat_model = quant.prepare_qat(qat_model, inplace=False)

optimizer = torch.optim.Adam(qat_model.parameters(), lr=0.001)
for images, labels in training_loader:
    optimizer.zero_grad()
    logits = qat_model(images.cpu())
    loss = torch.nn.functional.cross_entropy(logits, labels.cpu())
    loss.backward()
    optimizer.step()

qat_model.eval()
qat_int8 = quant.convert(qat_model, inplace=False)
