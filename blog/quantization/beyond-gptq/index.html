    Beyond GPTQ: a reading guide

    October 2026 · 4 min read

    A quantized model is not described completely by its bit count. The grid, scale sharing, treatment of activations, and execution kernel all matter. This series starts after the GPTQ derivation, but stands alone: the question here is which numerical problem each alternative solves, not which acronym wins.

    Ask three questions first

    • What changes numerically? Weight-only quantization stores weights compactly while usually keeping activations in floating point. W8A8 quantizes both operands of selected matrix multiplications; it does not promise every operation uses eight bits.
    • What kind of thing is the name? AWQ is a weight-quantization method, GGUF is a file format, and QLoRA is a training strategy. They occupy different layers of a system.
    • Where does the saving survive? Packed weights, scale metadata, dequantization, activation memory, and the KV cache all contribute. A compact checkpoint is not proof of a faster serving path.

    Read in this order

    1. Grids, scales, and what low-bit actually means: reconstruct a value before comparing bit counts.
    2. LLM.int8: isolate the outlier features: split an inner product instead of sacrificing its largest channels.
    3. AWQ: protect weights with activation-aware scaling: use activation statistics to allocate weight precision.
    4. SmoothQuant: move the activation difficulty into weights: rebalance the two operands for W8A8.
    5. NF4 and QLoRA: quantization for adapter training: separate a four-bit codebook from a trainable adapter.
    6. GGUF and K-quants: format versus quantizer: inspect what a runtime actually loads.
    7. FP8 and evaluation: match the format to the workload: connect exponent range to a reproducible deployment test.

    Carry one equation forward

    $$y=Wx,\qquad \Delta y=(\widehat W-W)x.$$

    The same weight error matters differently on different inputs. Calibration supplies examples of those inputs, not a universal certificate. Keep the model revision, tokenizer, calibration distribution, and evaluation prompts fixed when comparing methods. Then measure prefill and decode separately on the intended hardware. The final note turns these distinctions into a practical checklist.
