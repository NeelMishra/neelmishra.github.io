    Grids, scales, and what low-bit actually means

    October 2026 · 5 min read

    Four bits give sixteen codes, not sixteen universally defined numbers. A decoder must know how those codes become weights. An integer grid uses a scale and perhaps a zero point; a codebook such as NF4 uses nonuniform reconstruction values. Calling both “four-bit” describes their payload width, not their arithmetic or their error.

    Build an affine grid

    For a positive scale $s$, integer zero point $z$, and bounded code range, a common quantizer is

    $$q=\operatorname{clip}\!\left(\operatorname{round}(w/s)+z,q_{\min},q_{\max}\right),\qquad \widehat w=s(q-z).$$

    The zero point makes the code $z$ represent real zero. Symmetric quantization fixes $z=0$ and centers the grid around zero; asymmetric quantization can place the available levels across a shifted interval. Implementations differ in whether they use the entire signed range or reserve its most negative code. Those conventions must match the decoder.

    Use a toy symmetric grid with codes from $-7$ to $7$ and $s=0.1$. The weights $(-0.62,0.13,0.70)$ become $(-6,1,7)$ and reconstruct as $(-0.6,0.1,0.7)$. Their reconstruction errors are $(0.02,-0.03,0)$. A weight of $1.2$ clips to $0.7$, however: its error is $-0.5$, not a rounding error bounded by half a step.

    A scale has a neighborhood

    A single scale per tensor is simple, but one extreme weight can enlarge the step for every other weight. Per-output-channel scales separate rows of a matrix under $y=Wx$. Groupwise schemes split rows into smaller blocks, so an unusually large value affects fewer neighbors. Smaller groups usually add metadata and can alter kernel efficiency; they are not a free improvement.

    For example, four-bit codes plus one sixteen-bit scale for each group of 64 weights cost $4+16/64=4.25$ bits per weight before alignment and other fields. If the design also stores a sixteen-bit zero-point field per group, that becomes $4.5$. This is an illustrative layout, not a specification for every four-bit format. Unquantized tensors and container metadata further increase the checkpoint size.

    The layer sees a weighted error

    $$\Delta y=(\widehat W-W)x.$$

    Using the three reconstruction errors above and $x=(1,10,1)$ gives a scalar output error $0.02-0.30=-0.28$. With $x=(1,0,1)$ it is only $0.02$. The same stored weights can therefore be harmless on one input and consequential on another. Activation-aware calibration tries to capture this distinction; GPTQ uses layer reconstruction, while AWQ chooses scaling using activation information.

    Calibration can also select clipping thresholds instead of blindly preserving the largest observed value. Clipping sacrifices tails to give common values a finer grid. Its success depends on representative data, sequence lengths, and consistent preprocessing. A rare feature absent from the sample can still fail after deployment.

    Storage is not execution

    • Weight-only: W4A16 commonly means four-bit stored weights and sixteen-bit floating activations. A kernel may unpack and dequantize tiles while computing; the label does not require native four-bit multiplication.
    • W8A8: both selected matrix operands are eight-bit. Accumulation, bias, normalization, and residual paths may use wider types.
    • Runtime: packing order, supported group sizes, device instructions, and dequantization fusion determine whether a particular representation is useful.
    Does a smaller file guarantee a faster model?

    No. It may reduce weight traffic, but unpacking costs, unsupported kernels, batch size, activation memory, and the KV cache can change the bottleneck. Measure the actual runtime rather than infer latency from the filename.
