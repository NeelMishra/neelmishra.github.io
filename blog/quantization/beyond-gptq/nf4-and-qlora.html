    NF4 and QLoRA: quantization for adapter training

    October 2026 · 5 min read

    NF4 and QLoRA answer different questions. NF4 describes how four-bit codes reconstruct normalized weights. QLoRA describes how to fine-tune adapters while the large base model stays frozen and quantized. Neither name means that gradients, activations, and optimizer states are all four-bit, or that the deployed model must use the same training-time representation.

    NF4 is not a uniform integer grid

    NormalFloat 4 uses sixteen nonuniform levels designed around a normal-distribution assumption for weights, with finer resolution near the densely populated center. Blocks are normalized using scale constants, and each weight stores the index of a reconstruction level. Unlike an ordinary four-bit float, NF4 does not encode a conventional sign, exponent, and mantissa in each code.

    $$q_i=\operatorname*{argmin}_{k}|w_i/a-c_k|,\qquad \widehat w_i=a\,c_{q_i}.$$

    Here $a$ is the block scale and $c_k$ is a codebook entry. Suppose $a=2$ and $w=0.35$: the normalized value is $0.175$. Nearby NF4 reconstruction levels are approximately $0.16093$ and $0.24611$. The nearer level is $0.16093$, giving $\widehat w\approx0.32186$ and error about $-0.02814$. These rounded codebook values illustrate decoding; use the runtime's exact constants for a bit-exact check.

    The distribution assumption explains the placement of levels, not universal optimality for every tensor. A heavy-tailed or differently distributed block may behave differently, and the block scale influences all its members. Quantizing an already adapted or merged model can change that distribution again.

    Train around the frozen approximation

    For $y=Wx$ with $W$ shaped output by input, a low-rank adapter adds

    $$y=\widehat W_{\mathrm{base}}x+\lambda BAx,\qquad A\in\mathbb R^{r\times d_{\mathrm{in}}},\quad B\in\mathbb R^{d_{\mathrm{out}}\times r}.$$

    The base codes remain frozen. During computation, the quantized base is dequantized to the chosen compute precision; gradients flow through the computation to the adapters and to earlier trainable components, without updating those base codes. The QLoRA paper uses BF16 computation. Four-bit storage is therefore distinct from four-bit arithmetic.

    For a $4096$ by $4096$ matrix, the base has $16{,}777{,}216$ weights. A rank-8 adapter has $8(4096+4096)=65{,}536$ parameters, before any additional trainable modules. Its small parameter count reduces trainable state, but forward and backward activations still consume memory, especially at long sequence lengths.

    Scales can also be quantized

    Double quantization compresses the quantization constants themselves. As a simple accounting example, a 32-bit scale for every 64 four-bit weights adds $32/64=0.5$ bits per weight. Replacing those scales with eight-bit codes reduces that first-level overhead to $0.125$ bits per weight, but second-level scales and other bookkeeping must still be counted. This arithmetic explains the opportunity; it is not a complete serialized-layout estimate.

    QLoRA also introduces paged optimizers to manage memory spikes using unified memory. Paging is a memory-management strategy, not another quantizer, and transfers can affect execution. The paper's components should not be collapsed into the claim “NF4 alone makes training fit.”

    Training data is not calibration data

    Basic NF4 block quantization derives scales from weights rather than an activation calibration corpus. Adapter training then uses task examples to fit the low-rank update; that is supervised optimization, not merely calibrating a fixed quantizer. Evaluate held-out tasks after training and again after any deployment conversion.

    Merging an adapter into floating weights and requantizing produces a new approximation, not necessarily the same outputs as keeping the adapter separate. Record the base revision, adapter, compute dtype, and merge procedure. Finally, check hardware support for BF16 and the actual dequantization kernels: a training-memory success does not establish inference latency.
