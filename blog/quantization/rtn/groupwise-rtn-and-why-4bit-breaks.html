    2. RTN in LLMs: Per-group scaling, outlier magnification, and why RTN breaks below 4 bits

    October 2026 · 8 min read

    At 8 bits ($256$ levels), per-channel Round-to-Nearest (RTN) preserves LLM weight accuracy almost losslessly. Drop to 4 bits ($16$ levels) or 3 bits ($8$ levels) with one scale per output row, however, and language model perplexity degrades sharply. This post explains why heavy-tailed weight rows break per-channel RTN, how sub-channel groupwise RTN ($G \in \{32, 64, 128\}$) isolates outliers, and why even groupwise RTN fails at 3 bits compared to GPTQ and AWQ.

    1. How one outlier ruins a 4-bit row: crest-factor dilation

    Consider a single output row $w \in \mathbb{R}^d$ of an LLM projection matrix (say $d = 4096$) with root-mean-square magnitude $\sigma_w = \sqrt{\frac{1}{d}\sum_{c=1}^{d} w_c^2}$ and maximum magnitude $M = \max_{1 \le c \le d}|w_c|$. Define the row's crest factor $\kappa = M / \sigma_w$.

    Substituting $\Delta = M / (2^{b-1}-1) = \kappa \sigma_w / (2^{b-1}-1)$ into the $\Delta^2 / 12$ variance law expresses the relative weight error directly in terms of $\kappa$:

    $$\frac{\mathrm{MSE}_{\mathrm{RTN}}}{\sigma_w^2} = \frac{\Delta^2}{12\,\sigma_w^2} = \frac{\kappa^2}{12\,(2^{b-1}-1)^2}.$$
    • In a trained Transformer row of length $d = 4096$, heavy tails routinely push $\kappa = M / \sigma_w \in [6, 12]$.
    • At $b = 4$ bits ($2^{b-1}-1 = 7$), a crest factor of $\kappa = 8$ makes $\Delta = \frac{8}{7}\sigma_w \approx 1.14\,\sigma_w$. Any weight with $|w_c| < \frac{\Delta}{2} \approx 0.57\,\sigma_w$—typically over $40\%$ of the weights in the row—rounds straight to $0$!

    2. Sub-channel groupwise RTN and effective bit-width

    Instead of sharing one scale across all $d = 4096$ columns of a row, groupwise RTN slices each row into $d / G$ contiguous groups of $G$ weights (commonly $G = 128$ or $G = 64$) and computes a separate scale $\Delta_{r,g}$ (and optional zero-point $z_{r,g}$) for each group $g \in \{1, \dots, d/G\}$:

    $$\Delta_{r,g} = \frac{\max_{j \in \mathcal{I}_g} |W_{r,j}|}{2^{b-1}-1}, \qquad \widehat{W}_{r,j} = \Delta_{r,g}\cdot\operatorname{clip}\!\left(\left\lfloor \frac{W_{r,j}}{\Delta_{r,g}} \right\rceil,\; -(2^{b-1}-1),\; +(2^{b-1}-1)\right) \quad (j \in \mathcal{I}_g).$$

    Now a single large weight only stretches $\Delta_{r,g}$ for the $G - 1$ other weights in its own group, leaving the remaining $d - G$ weights in the row untouched.

    Effective bits per weight ($\text{bits}_{\mathrm{eff}}$)

    Each group of $G$ weights stores $G \times b$ payload bits plus metadata for its scale (typically 16-bit FP16) and, for asymmetric RTN, a $b$-bit integer zero-point:

    $$\text{bits}_{\mathrm{eff}}^{\mathrm{sym}} = b + \frac{16}{G}, \qquad \text{bits}_{\mathrm{eff}}^{\mathrm{asym}} = b + \frac{16 + b}{G}.$$

    3. Worked 8-weight numerical comparison: per-row vs. groupwise RTN ($G=4$)

    Take an 8-weight row where the first seven weights have typical magnitudes in $[-0.18, +0.22]$ and the last weight is an outlier $w_8 = +1.40$:

    $$w = \bigl[\underbrace{-0.18,\; +0.06,\; +0.15,\; -0.21}_{\text{Group 1}},\; \underbrace{+0.09,\; -0.04,\; +0.22,\; +1.40}_{\text{Group 2}}\bigr].$$
    • 4-bit symmetric per-row RTN ($G = 8$): The row maximum is $M = 1.40$, so the single step size is $\Delta = 1.40 / 7 = 0.20$. Dividing by $0.20$ and rounding gives $$\widehat{w}_{\mathrm{row}} = \bigl[-0.20,\; 0.00,\; +0.20,\; -0.20,\; 0.00,\; 0.00,\; +0.20,\; +1.40\bigr].$$ Notice that three of the eight weights ($+0.06, +0.09, -0.04$) are wiped out to $0.00$, and the squared errors sum to $\sum_{i=1}^{8}(\widehat{w}_i - w_i)^2 = 0.0004 + 0.0036 + 0.0025 + 0.0001 + 0.0081 + 0.0016 + 0.0004 + 0 = 0.0167$ ($\mathrm{MSE} = 0.002088$).
    • 4-bit symmetric groupwise RTN ($G = 4$):
      • Group 1 ($[-0.18, +0.06, +0.15, -0.21]$) has $M_1 = 0.21$ and $\Delta_1 = 0.21 / 7 = 0.03$. Every single weight in Group 1 is an exact multiple of $0.03$: $q^{(1)} = [-6, +2, +5, -7]$, reconstructing $\widehat{w}^{(1)} = [-0.18, +0.06, +0.15, -0.21]$ with zero error!
      • Group 2 ($[+0.09, -0.04, +0.22, +1.40]$) contains the outlier $1.40$, so $\Delta_2 = 1.40 / 7 = 0.20$ and $\widehat{w}^{(2)} = [0.00, 0.00, +0.20, +1.40]$ with squared error $0.0081 + 0.0016 + 0.0004 + 0 = 0.0101$.
      Splitting the row into two groups cuts the error in Group 1 to zero and drops total row MSE from $0.002088$ to $0.0101 / 8 = 0.001263$. In a full $d = 4096$ row with $32$ groups of $G = 128$, one outlier only affects $1/32$ of the row instead of $100\%$.

    4. Why even groupwise RTN breaks at 3–4 bits (and what AWQ/GPTQ change)

    Even with $G = 128$, plain RTN minimizes the wrong objective for low-bit LLM layers. For a linear layer computing $y = Wx$ on an input token $x \in \mathbb{R}^d$, the actual error injected into the network's hidden state is

    $$\lVert Wx - \widehat{W}x \rVert_2^2 = \sum_{r=1}^{m} \left(\sum_{c=1}^{d} \bigl(W_{r,c} - \widehat{W}_{r,c}\bigr)\,x_c\right)^2.$$

    Compare this output error to RTN's elementwise weight objective $\sum_{r,c}(W_{r,c} - \widehat{W}_{r,c})^2$:

    1. RTN treats all input channels $c$ as equally important ($x_c \equiv 1$): In pre-trained LLMs, $0.1\%$ to $1\%$ of input activation channels have magnitudes $10\times$ to $100\times$ larger than typical channels. A small RTN rounding error $\delta W_{r,c}$ on a salient activation channel $c$ is multiplied by $x_c$ and dominates $\lVert Wx - \widehat{W}x \rVert_2^2$. AWQ fixes this while keeping RTN rounding by scaling up salient weight columns ($W_{:,c} \leftarrow s_c W_{:,c}$) before calling RTN.
    2. RTN rounds each column independently without error cancellation: Inside the inner sum $\sum_{c=1}^{d} \delta W_{r,c}\,x_c$, if rounding column $1$ pushes the dot product up by $\delta W_{r,1} x_1 > 0$ and input features $x_1, x_2$ are correlated, nudging $W_{r,2}$ slightly in the opposite direction before rounding it can cancel most of $\delta W_{r,1} x_1$. Because RTN never updates remaining weights after rounding a column, these errors accumulate across all $d$ columns. GPTQ fixes this by applying an inverse-Hessian compensation step to the remaining unquantized columns after each RTN column step.

    5. Minimal PyTorch implementation of groupwise RTN

    The function below implements both symmetric and asymmetric groupwise RTN on any 2D weight matrix W of shape [out_features, in_features]:

    import torch

def rtn_quantize_groupwise(
    W: torch.Tensor,
    bits: int = 4,
    group_size: int = 128,
    symmetric: bool = True,
) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
    """Groupwise Round-to-Nearest (RTN) quantization and dequantization."""
    out_features, in_features = W.shape
    assert in_features % group_size == 0, "in_features must be divisible by group_size"
    w_groups = W.view(out_features, in_features // group_size, group_size)

    if symmetric:
        q_max = (1 << (bits - 1)) - 1
        q_min = -q_max
        scales = w_groups.abs().amax(dim=-1, keepdim=True).clamp(min=1e-8) / q_max
        zeros = torch.zeros_like(scales)
        q = torch.clamp(torch.round(w_groups / scales), q_min, q_max)
        w_hat = (q * scales).view(out_features, in_features)
    else:
        q_min, q_max = 0, (1 << bits) - 1
        w_min = w_groups.amin(dim=-1, keepdim=True)
        w_max = w_groups.amax(dim=-1, keepdim=True)
        scales = ((w_max - w_min).clamp(min=1e-8)) / (q_max - q_min)
        zeros = torch.clamp(torch.round(-w_min / scales), q_min, q_max)
        q = torch.clamp(torch.round(w_groups / scales) + zeros, q_min, q_max)
        w_hat = ((q - zeros) * scales).view(out_features, in_features)

    return w_hat, scales.squeeze(-1), zeros.squeeze(-1)
    When is plain groupwise RTN good enough in practice?

    At 8-bit (per-channel) and often at 4-bit with $G \in \{64, 128\}$ on larger models ($\ge 13\text{B}$ parameters), groupwise RTN is fast, requires zero calibration data, and comes within $0.1\text{--}0.4$ perplexity points of calibration-based methods. Below 4 bits (INT3/INT2) or on smaller models ($1\text{B}\text{--}8\text{B}$), calibration-aware methods like AWQ or GPTQ are essential.
