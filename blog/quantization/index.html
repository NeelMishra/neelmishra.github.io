    Quantization: shrink the weights, then repair the layer

    October 2026 · 4 min read

    This series is about post-training weight quantization: take a trained network, store its weights with fewer bits, and keep the layer outputs close to the full-precision outputs. The first path is GPTQ.

    The GPTQ chapters explain the method directly, using the GPTQ paper and the authors' implementation as references. Each equation is connected to the problem it solves and to a small worked example.

    What this series is for

    Generating text can be limited by how quickly the GPU reads model weights. Storing weights with fewer bits reduces that memory traffic. Some runtimes then unpack those weights for floating-point multiplication, so smaller weights do not automatically mean faster arithmetic.

    Rounding weights changes a layer's output. GPTQ reduces this error by adjusting the weights that have not yet been rounded. It uses a small set of representative inputs, called calibration data, and processes one layer at a time. It does not retrain the model.

    Each method has its own folder and guide: quantization fundamentals, LLM.int8, SmoothQuant, AWQ, NF4/QLoRA, QAT, GGUF and K-quants, and FP8 and evaluation. The method-selection guide compares their goals. GPTQ has its own three-chapter derivation path. The shorter serving notes stay in the MLOps comparison. The existing GPTQ inference note is the deployment-side summary.

    Reading route

    Read them in that order. The third chapter uses the column index and the inverse-Hessian update from the second, and the second uses the layer objective from the first.

    Choose a method-specific guide

    Start with Quantization: choose the method for the job when your question is about activation outliers, weight-only scaling, four-bit adapter training, or training with simulated quantization. It links to the dedicated method guides, their primary-paper references, and a shared evaluation contract.

    Quantization methods: compare the tradeoffs connects the supplementary guides without requiring the GPTQ Hessian derivation or replacing it.

    • Grids and scales: rounding, clipping, group size, and effective storage.
    • LLM.int8: keep outlier features in a higher-precision path.
    • AWQ and SmoothQuant: activation-aware weight compression versus weight-and-activation quantization.
    • NF4 and QLoRA: a nonuniform codebook and adapter training over a frozen quantized base.
    • GGUF and K-quants: a container is not a quantization algorithm.
    • FP8 and evaluation: format, kernel support, and workload-specific measurements.

    Boundaries

    GPTQ quantizes weights. The paper does not quantize activations, and it says the method does not speed up the multiplications themselves on hardware without mixed-precision operands. A smaller file and a faster load are different claims from a faster tensor core instruction.

    Group size and the lazy-update block size are also different knobs. A group of input channels can share a scale and a zero. The number 128 in Algorithm 1 is how many columns are quantized before the rest of the matrix is updated. The notes keep those apart.
