    NormalFloat 4 (NF4) & Double Quantization Explained

    October 2026 · 18 min read · Quantization & Video Companion

    Illustrated using slide frames from the Discover AI lecture: "Understanding 4bit Quantization: QLoRA explained (w/ Colab)" and mathematical derivations from Dettmers et al. (2023), QLoRA: Efficient Finetuning of Quantized LLMs. For the full end-to-end QLoRA training and Colab walkthrough, see the companion post in the LLM → QLoRA series.

    1. The 4-Bit Representation Bottleneck: Only 16 Discrete Levels

    When we quantize a neural network's weights from 32-bit floating point (FP32) or 16-bit BrainFloat (BF16) down to 4 bits per weight, we reduce the raw weight memory footprint by 8× (versus FP32) or 4× (versus BF16)—shrinking a 65-billion-parameter model's weights from 130 GB (in 16-bit) down to ~33 GB so it fits on a single 48 GB GPU.

    However, a 4-bit code has only $2^4 = \mathbf{16}$ possible bit patterns (`0000` through `1111`):

    With only 16 reconstruction levels available for an entire block of weights, where we place those 16 levels along the real line determines whether the quantized model preserves its pretrained knowledge or suffers severe accuracy loss. Standard 4-bit integer (`Int4`) and standard 4-bit floating-point (`FP4`) formats waste many of their 16 levels in regions where very few neural network weights actually live.

    2. Storage Data Type (NF4) vs. Computation Data Type (BF16)

    Before examining how NormalFloat 4 places its 16 levels, remember a foundational distinction from Dettmers et al. (2023): 4-bit NormalFloat (NF4) is strictly a storage data type, not an arithmetic computation data type.

    Unlike an IEEE floating-point format (where hardware ALUs parse sign, exponent, and mantissa bits directly), a 4-bit NF4 code $k \in \{0, 1, \dots, 15\}$ is an index into a 16-entry lookup codebook $q_0, q_1, \dots, q_{15} \in [-1, 1]$. Whenever a linear layer runs in the forward or backward pass, the GPU kernel looks up $q_k$, multiplies by the block's scaling factor to produce a 16-bit BrainFloat (`BF16`) or FP16 tensor, executes the Tensor Core matrix multiplication, and immediately discards the dequantized buffer.

    3. The Three Steps of 4-Bit NormalFloat Quantization

    In the lecture, the 4-bit NormalFloat quantization lifecycle is broken down into three clear stages:

    1. Normalization: Pretrained neural network weights naturally follow a zero-centered normal (Gaussian) distribution $W \sim \mathcal{N}(0, \sigma^2)$, where $\sigma$ varies from block to block. By normalizing each weight block by its maximum absolute value $a = \operatorname{absmax}(W_b)$, we bring all weights into the shared canonical range $[-1, 1]$ with zero mean and comparable spread.
    2. Quantization: Each normalized weight $\tilde{w}_i = w_i / a \in [-1, 1]$ is compared against the 16 reconstruction levels $\{q_0, q_1, \dots, q_{15}\} \subset [-1, 1]$ and mapped to the 4-bit integer index of the nearest level:
      $$k_i = \operatorname*{argmin}_{k \in \{0,\dots,15\}} \left|\frac{w_i}{a} - q_k\right|$$
      Only the 4-bit index $k_i$ (4 bits per weight) and the block scale $a$ are stored in GPU memory.
    3. Dequantization: During the forward and backward passes, each 4-bit index $k_i$ is mapped back through the 16-entry lookup table and multiplied by the block scale $a$ to reconstruct the high-precision approximation:
      $$\widehat{w}_i = a \cdot q_{k_i}$$

    4. Worked Numerical Walkthrough: Quantizing $0.5678$ and Measuring Dequantization Error

    Let's first follow the video's exact arithmetic walkthrough using a simplified evenly spaced 16-level grid on $[-1, 1]$ to build rock-solid intuition for index lookup and dequantization error, and then compare the exact same weight $w = 0.5678$ on the true Gaussian-quantile NF4 codebook.

    Suppose a normalized 32-bit floating-point weight is $w_{\text{FP32}} = 0.5678$. If we place 16 evenly spaced levels across $[-1, 1]$ with step size $\Delta = \frac{1 - (-1)}{16 - 1} = \frac{2}{15} \approx 0.1333$, our 16 levels are:

    $$\bigl[-1.0,\ -0.8667,\ -0.7333,\ -0.6,\ -0.4667,\ -0.3333,\ -0.2,\ -0.0667,\ 0.0667,\ 0.2,\ 0.3333,\ 0.4667,\ \mathbf{0.6},\ 0.7333,\ 0.8667,\ 1.0\bigr]$$
    • Quantization: Comparing $0.5678$ to its two neighbors $0.4667$ and $0.6$, the closer level is $0.6$ (the 13th level counting from 1, or index `12` counting from 0). We store the 4-bit integer 13.
    • Dequantization & Error: When the forward pass looks up the 13th level, it recovers $\widehat{w} = 0.6$. Because quantization is lossy, the true digits $.5678$ are gone forever, leaving a dequantization error of:
      $$\varepsilon_{\text{dequant}} = \widehat{w} - w = 0.6 - 0.5678 = \mathbf{0.0322}$$

    5. How Exact NormalFloat 4 (NF4) Places Its 16 Levels Using Gaussian Quantiles

    In the simplified walkthrough above, the 16 levels were spaced uniformly ($\Delta = 0.1333$) so the arithmetic was easy to follow by hand. Now let's ask: How does the true NormalFloat 4 (NF4) data type in `bitsandbytes` place its 16 levels to minimize that red dequantization error across billions of normally distributed weights?

    Because pretrained transformer weights follow a zero-centered bell curve $X \sim \mathcal{N}(0, \sigma^2)$, most weights cluster densely near $0$ while very few lie near the extremes $\pm 1$. A uniform grid wastes half of its 16 bins out in the tails where almost no weights live, and leaves too few bins near $0$ where the vast majority of weights sit.

    Information-Theoretic Quantile Quantization

    Dettmers et al. (2023) build NF4 using quantile quantization (Dettmers & Zettlemoyer, 2022), which is information-theoretically optimal for a known distribution because it assigns an equal number of expected weights ($1/16$ of the probability mass) to every 4-bit code.

    Let $Q_X(p) = \Phi^{-1}(p)$ be the quantile function (inverse cumulative distribution function) of the standard normal distribution $X \sim \mathcal{N}(0, 1)$, where $\Phi(z) = \frac{1}{\sqrt{2\pi}}\int_{-\infty}^z e^{-t^2/2}\,dt$. To construct $2^k = 16$ representative centroids $q_0, \dots, q_{15}$, the general formula averages adjacent equal-probability quantiles:

    $$\tilde{q}_i = \frac{1}{2}\!\left(Q_X\!\left(\frac{i}{2^k + 1}\right) + Q_X\!\left(\frac{i + 1}{2^k + 1}\right)\right), \qquad i = 0, 1, \dots, 2^k - 1.$$

    Why NF4 Uses an Asymmetric $7 + 1 + 8$ Split Around Exact Zero

    There is one crucial subtlety in symmetric quantile formula above: if you divide $\mathcal{N}(0,1)$ into $2^4 = 16$ symmetric bins (8 negative and 8 positive), $0.0$ sits on the boundary between bin 7 and bin 8, meaning none of the 16 centroids equals exact $0.0$! Yet exact zero representation is essential in neural networks so that zero-padding, masked weights, and pruned entries produce strictly $0.0$ without introducing phantom bias.

    To guarantee an exact $0.0$ level while keeping all 16 codes in $[-1, 1]$:

    1. NF4 splits the normal distribution into two halves around $0$: the negative half $[-1, 0]$ receives 7 non-zero quantiles plus $0.0$ ($8$ values total), and the positive half $[0, 1]$ receives $0.0$ plus 8 non-zero quantiles ($9$ values total).
    2. Both halves are independently normalized so that the minimum quantile is $-1.0$ and the maximum quantile is $+1.0$, and then merged by removing the duplicate $0.0$ at index 7—yielding the exact 16-entry `bitsandbytes` NF4 codebook below!

    6. Blockwise Quantization ($B = 64$) & Double Quantization

    Even with the optimal 16-level NF4 codebook on $[-1, 1]$, normalizing an entire $4096 \times 4096$ weight matrix by a single maximum value $\operatorname{absmax}(W)$ would be vulnerable to **outlier weights**: a single large entry would inflate $\operatorname{absmax}(W)$ and compress the other $16.7$ million weights into a narrow central fraction of $[-1, 1]$.

    1. Blockwise Absmax Scaling ($B = 64$)

    QLoRA flattens weight tensor $W$ and partitions it into contiguous blocks of size $B = 64$ weights. Each block $b$ computes its own independent absmax constant $c_{1,b}^{\text{FP32}} = \max_{j \in b} |w_j|$. This confines any outlier to its local 64-weight neighborhood.

    2. Double Quantization (Quantizing the Quantization Constants)

    Storing one 32-bit scale $c_{1,b}^{\text{FP32}}$ for every $B = 64$ weights adds a metadata overhead of:

    $$\text{Overhead}_{\text{single}} = \frac{32\text{ bits}}{64\text{ weights}} = \mathbf{0.500\text{ bits per weight}}$$

    turning a 4.0-bit model into a 4.5-bit model. To eliminate this overhead, Double Quantization (DQ) groups every $256$ block scales $c_1^{\text{FP32}}$ into a second-level super-block, subtracts the mean (since all $c_1$ values are positive), and quantizes them to 8-bit floating point ($c_2^{\text{FP8}}$) with a single second-level 32-bit scale $c_1^{\text{FP32}}$ per $256$ blocks:

    $$\text{Overhead}_{\text{DQ}} = \frac{8\text{ bits}}{64\text{ weights}} + \frac{32\text{ bits}}{64 \times 256\text{ weights}} = 0.125 + 0.00195 = \mathbf{0.127\text{ bits per weight}}$$

    This reduces total storage from 4.500 bits/weight to 4.127 bits/weight—saving $0.373$ bits per parameter, or ~3.0 GB of GPU RAM on a 65B model!

    8. Runnable Python Verification: Uniform-16 vs. Exact NF4 vs. Double Quantization

    The self-contained Python script below verifies both our single-weight example ($w = 0.5678$) and blockwise reconstruction RMSE across $65{,}536$ Gaussian weights $\mathcal{N}(0, 0.02^2)$ with block size $B = 64$ and Double Quantization super-blocks of $256$:

    import math
import random

# 1. Video's 16 evenly-spaced levels on [-1, 1] (step = 2/15 = 0.1333)
UNIFORM_16 = [-1.0 + i * (2.0 / 15.0) for i in range(16)]

# 2. Exact bitsandbytes NormalFloat 4 (NF4) 16-entry Gaussian quantile codebook
NF4_CODEBOOK = [
    -1.0,
    -0.6961928009986877,
    -0.5250730514526367,
    -0.39491748809814453,
    -0.28444138169288635,
    -0.18477343022823334,
    -0.09105003625154495,
    0.0,
    0.07958029955625534,
    0.16093020141124725,
    0.24611230194568634,
    0.33791524171829224,
    0.44070982933044434,
    0.5626170039176941,
    0.7229568362236023,
    1.0,
]

# Single-weight check from Video Slides 8 & 9: w = 0.5678
w = 0.5678
u_idx = min(range(16), key=lambda i: abs(w - UNIFORM_16[i]))
nf_idx = min(range(16), key=lambda i: abs(w - NF4_CODEBOOK[i]))
print(f"Target weight w = {w}")
print(f"Uniform-16 : 1-based level={u_idx+1} (code {u_idx}), recon={UNIFORM_16[u_idx]:.4f}, error={UNIFORM_16[u_idx]-w:+.4f}")
print(f"Exact NF4  : 1-based level={nf_idx+1} (code {nf_idx}), recon={NF4_CODEBOOK[nf_idx]:.4f}, error={NF4_CODEBOOK[nf_idx]-w:+.4f}\n")

# Blockwise (B=64) + Double Quantization (SB=256) benchmark over 65,536 Gaussian weights
random.seed(42)
weights = [random.gauss(0.0, 0.02) for _ in range(65536)]

def blockwise_rmse(w_list, codebook, B=64, double_quant=False):
    num_blocks = len(w_list) // B
    scales, codes = [], []
    for b in range(num_blocks):
        blk = w_list[b * B : (b + 1) * B]
        amax = max(abs(x) for x in blk) or 1.0
        scales.append(amax)
        for x in blk:
            xn = x / amax
            codes.append(min(range(16), key=lambda i: abs(xn - codebook[i])))
    if double_quant:
        q_scales = []
        for s in range(0, num_blocks, 256):
            sblk = scales[s : s + 256]
            s_max = max(sblk) or 1.0
            for sc in sblk:
                q_scales.append((round((sc / s_max) * 255.0) / 255.0) * s_max)
        scales = q_scales
    sq_err = sum(
        (scales[b] * codebook[codes[b * B + j]] - w_list[b * B + j]) ** 2
        for b in range(num_blocks) for j in range(B)
    )
    return math.sqrt(sq_err / len(w_list))

print(f"Uniform 4-bit (B=64) RMSE       : {blockwise_rmse(weights, UNIFORM_16, 64, False):.6f} (4.500 bits/weight)")
print(f"Exact NF4 (B=64) RMSE           : {blockwise_rmse(weights, NF4_CODEBOOK, 64, False):.6f} (4.500 bits/weight)")
print(f"Exact NF4 + Double Quant RMSE   : {blockwise_rmse(weights, NF4_CODEBOOK, 64, True):.6f} (4.127 bits/weight)")
