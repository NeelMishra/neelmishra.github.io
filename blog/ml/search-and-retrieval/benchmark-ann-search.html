    Benchmark Vector Search: Recall, Tail Latency, Memory, and Filters

    September 2026 · 4 min read

    Before you start: HNSW and Annoy mechanics.

    “Three milliseconds” is not a complete vector-search result. Was that one query or a batch? Did it include embedding generation and network time? Was the index warm? What recall did it achieve? A useful benchmark makes those conditions explicit and lets readers compare operating points.

    Build the reference with the same metric

    For a manageable corpus, compute all query–item scores, apply the same eligibility rules, and select exact top-K. For a large corpus, use blocked matrix multiplication or an exact flat index. The reference must use the same normalization, vector version, and distance convention as the approximate run. Otherwise “ANN error” may actually be a preprocessing mismatch.

    import numpy as np

def exact_topk(query, items, k):
    if not 1 <= k <= len(items):
        raise ValueError("k must fit the corpus")
    scores = items @ query  # Inner product; normalize first for cosine.
    ids = np.arange(len(items))
    # Descending score, ascending ID for deterministic ties.
    return np.lexsort((ids, -scores))[:k]

def ann_recall(exact_ids, approximate_ids):
    if len(set(approximate_ids)) != len(approximate_ids):
        raise ValueError("duplicate IDs")
    return len(set(exact_ids) & set(approximate_ids)) / len(exact_ids)

    Measure the service boundary you intend to claim

    Separate index-only time from end-to-end time. The latter can include tokenization or image processing, embedding inference, network transport, index lookup, filtering, reranking, and serialization. Report both when useful. For accelerators, synchronize around the timed region so asynchronous submission is not mistaken for completed work.

    Warm up kernels and caches for a warm benchmark, and explicitly run a separate cold-start or cold-page experiment if it matters. Use a monotonic high-resolution timer. Record batch size, query concurrency, worker count, hardware, thread settings, and index residency. A batch-throughput result cannot be relabeled as single-query latency.

    Load changes the distribution

    Measure p50, p95, and p99 over enough representative queries, along with throughput and error rate. Queueing can dominate at high utilization. A closed-loop client that waits for each response can hide overload by reducing offered load when the service slows; an open-loop load generator better exposes that failure mode when appropriate. Report offered versus achieved throughput.

    Tail quantiles need enough samples and uncertainty awareness. A p99 estimate from a hundred requests is mostly a statement about one or two observations. Repeat runs, retain per-query timings, and inspect outliers. Shared machines, background jobs, and page faults can change results substantially.

    Compare matched-quality operating points

    Sweep efSearch or search_k and plot ANN recall against latency. Repeat for meaningful build configurations or compression levels. A point is dominated when another point provides at least as much recall with no more cost, with one strict improvement. Compare memory-constrained frontiers too: an extremely fast graph may use too much RAM to deploy.

    Filtered search deserves its own experiment

    Vary filter selectivity and correlation with vector neighborhoods. A random 10% filter and a category filter retaining 10% of items can behave differently because eligible items occupy different regions. Evaluate post-filter oversampling, native filtering, and partitioned indexes under the same task. Report empty-result rates and final relevant recall, not just raw candidate count.

    Finally, keep a relevance report beside the ANN report. A faithful approximation can still serve irrelevant neighbors. Use stage diagnostics to locate representation, index, filter, and reranker losses before choosing the next optimization.

    Check your understanding: Can a higher-throughput batched GPU index be assumed to have lower interactive latency?

    No. Throughput and single-query latency are different measurements, and batching can add waiting time. Measure the intended workload and service boundary.
