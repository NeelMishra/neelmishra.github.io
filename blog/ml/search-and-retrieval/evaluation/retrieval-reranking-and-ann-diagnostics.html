    Evaluate Retrieval and Reranking Separately

    September 2026 · 4 min read

    Before you start: nDCG and its ideal ranking.

    A search stack can fail even when each component reports a good-looking score. The index may closely reproduce the wrong embedding model’s nearest neighbors. The retriever may find useful items that a filter removes. The reranker may receive an excellent candidate set and bury its best result. One final nDCG number cannot identify which change to make.

    Two recalls with different ground truth

    Let $E_K(q)$ be exact top-K neighbors under the deployed embedding score, and $A_K(q)$ the approximate index results. ANN recall is $|E_K\cap A_K|/K$. It measures index approximation fidelity. Relevance recall uses human-judged relevant items as its target and measures useful retrieval.

    The approximate index gets two of three exact neighbors, so ANN recall@3=2/3. It finds neither useful document, so relevance recall@3=0/2=0.

    Making the index exact would recover A and raise relevance recall to 1/2; it still would not recover B. The remaining miss is a representation or retrieval-objective problem at that cutoff. This is why tuning HNSW search effort and retraining a two-tower model solve different problems.

    Measure the best a reranker could possibly do

    Suppose a query has catalog grades A=3, B=2, C=1, D=0, and the candidate set contains B,C,D. The best candidate ordering is [B,C,D], with DCG@3=3+1/log₂3≈3.6309. The full-catalog ideal is [A,B,C], with DCG≈9.3928. The oracle candidate-set nDCG is therefore about 0.3866. No reranker limited to these candidates can exceed that ceiling under these judgments.

    Now compare the actual reranker with that oracle. If actual nDCG is 0.38, retrieval is the primary bottleneck. If actual nDCG is 0.12, both stages have room to improve. The oracle uses labels and is a diagnostic, not a deployable policy. Include judgment coverage because the ceiling is only as complete as your qrels.

    Filters change the candidate problem

    An unfiltered ANN query may return ten excellent matches that are all out of stock. Filtering afterward can leave an empty list. Oversampling before filtering helps only if eligible matches are nearby enough to enter the expanded set. Prefiltered search or partitioned indexes may be needed for strict constraints, but benchmark their actual recall and latency. Do not compare a filtered approximate run to an unfiltered exact baseline.

    Run controlled swaps

    Freeze queries, corpus, qrels, and eligibility rules. Compare exact search versus ANN with the same embeddings; old versus new embeddings under exact search; old versus new candidate generators with the same reranker; and old versus new rerankers on identical candidate IDs. Finally test the complete proposed stack. These experiments isolate mechanisms before interactions make attribution difficult.

    Sweep candidate count. More candidates can improve recall but increase reranking cost and sometimes introduce distractors that the reranker mishandles. Plot final relevance quality against end-to-end p95 latency, not just index lookup time. Include embedding computation, filtering, network serialization, and reranking in the budget.

    Diagnose the query classes you care about

    Report exact-match identifiers, lexical specificity, semantic paraphrases, rare entities, long queries, cold-start items, and strict filters separately. A lexical retriever and a dense retriever may fail on different slices; hybrid retrieval is useful when their errors complement one another. The union’s gain must still justify extra work and candidate count.

    For recommendations, include user-history length and item age. An index benchmark with uniformly sampled random vectors does not reproduce the geometry or traffic distribution of a real embedding space. Use synthetic data to test implementation properties, then use a frozen representative workload for product comparisons.

    Check your understanding: ANN recall rises from 0.90 to 0.99 while human relevance stays flat. Is that contradictory?

    No. The index became a more faithful approximation to the embedding score. The recovered neighbors may still be irrelevant, or later stages may remove them.
