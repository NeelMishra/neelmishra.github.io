    Did Search Improve? Paired Tests, Bootstrap Intervals, and Slices

    September 2026 · 4 min read

    Before you start: Per-query ranking metrics.

    System B improves average nDCG from 0.61 to 0.62. That is a one-point absolute increase, but it does not tell you whether the gain is stable, who benefits, or whether the experiment can support a launch. Keep the per-query scores: the useful object is a distribution of paired changes.

    Why pairing matters

    For query $q$, define $d_q=m_B(q)-m_A(q)$. Estimate the mean change with $\bar d=Q^{-1}\sum_qd_q$. A difficult query may be difficult for both systems; pairing removes much of that shared variation. Comparing independent score samples throws away this information.

    The illustrative mean change is +0.025. Four queries are enough for arithmetic, not a reliable launch study.

    A paired bootstrap you can inspect

    import random

def paired_bootstrap(a, b, repeats=10000, seed=7):
    if len(a) != len(b) or not a:
        raise ValueError("Use equal, nonempty paired score lists")
    differences = [y - x for x, y in zip(a, b)]
    rng = random.Random(seed)
    n = len(differences)
    means = sorted(
        sum(differences[rng.randrange(n)] for _ in range(n)) / n
        for _ in range(repeats)
    )
    # Percentile interval; simple integer order-statistic convention.
    return (sum(differences) / n,
            means[int(0.025 * repeats)],
            means[min(repeats - 1, int(0.975 * repeats))])

    Each bootstrap draw samples query indices with replacement. The same index selects both systems’ scores, preserving the comparison. The interval describes sampling uncertainty under the resampling assumptions. It does not account automatically for label errors, test-set contamination, or a changed future traffic distribution. Tiny test sets and rare slices can produce unstable intervals even with many bootstrap repetitions.

    The independent unit may be larger than a query

    If one user contributes a hundred similar searches, those queries are not a hundred independent users. Resample users and retain all their queries for a user-cluster bootstrap. Repeated sessions, related query templates, and organizations can require analogous grouping. Choose the unit to match the deployment question. A query-weighted mean and a user-weighted mean can differ even on the same logs.

    For traffic-weighted offline evaluation, keep sampling weights explicit. A diagnostic set that intentionally oversamples rare queries needs either separate slice reporting or appropriate reweighting to estimate traffic impact. Do not bootstrap a balanced set and interpret its narrow interval as uncertainty about an unweighted production average.

    A p-value does not measure improvement size

    A paired randomization test can swap the A/B labels within independent units under an exchangeability null and compare the observed difference with the resulting distribution. A paired t-test uses a different set of assumptions about the mean difference. Choose and document the method before looking for the most favorable answer. A very small p-value for a negligible gain can still be uninteresting; a large practical gain with a wide interval can require more data.

    Specify a minimum useful improvement and acceptable guardrail degradation. Report absolute differences first, then relative change where useful: moving 0.61 to 0.62 is +0.01 absolute and approximately +1.64% relative. State the denominator. For latency, report the quantile difference and its uncertainty rather than assuming a mean-based test answers a tail-latency question.

    Protect the test set from repeated decisions

    Trying twenty configurations and selecting the best test score turns the test set into validation data. Tune on validation, select a candidate, then evaluate on a held-out test. If many hypotheses or slices drive formal decisions, address multiplicity and identify primary versus exploratory comparisons. Repeatedly peeking at an online experiment also changes error guarantees unless the analysis supports sequential monitoring.

    A useful report contains the overall change and interval, query counts, exclusions, per-slice differences, judged coverage, latency, and examples of regressions. Slice estimates with few observations should look uncertain; hiding that uncertainty behind a green percentage is misleading. Save the paired scores and evaluation manifest so someone else can reproduce every aggregate.

    Check your understanding: Can one million queries from ten highly active users be treated as one million independent observations about users?

    No. The dependence and target population matter. Use a user-level design or clustered analysis, and make clear which users the result can generalize to.
