    Search & Retrieval · Evaluation: Reading Guide

    September 2026 · 9 min read

    “Search improved” can mean four completely different claims: the ANN index recovered more exact vector neighbors, the offline top-$K$ list placed higher-grade documents near rank 1, users completed more tasks in a randomized experiment, or a RAG answer cited sufficient evidence without hallucinating. Each claim requires its own measurement—and a jump in one metric never automatically proves another.

    This seven-part series builds search and RAG evaluation from first principles. Every equation defines its notation up front and pairs immediately with small, hand-verifiable rankings and zero-dependency Python checks.

    Core offline metrics at a glance

    For a single query evaluated at rank cutoff $K \ge 1$, let $i \in \{1, \dots, K\}$ index rank position, let $r_i \in \{0, 1\}$ be the binary relevance indicator at rank $i$ (or graded relevance $g(r_i) \ge 0$ for nDCG), let $R \ge 1$ be the total count of relevant documents in the eligible catalog, and let $\operatorname{IDCG}@K$ be the ideal discounted cumulative gain of the best $K$ catalog documents:

    Quick reference comparing the five standard single-query ranking metrics.
    Metric Formula Order-sensitive inside $K$? Primary blind spot
    Precision@$K$ $\frac{1}{K}\sum_{i=1}^K r_i$ No Ignores rank order inside top $K$ and ignores total catalog relevant count $R$
    Recall@$K$ $\frac{1}{R}\sum_{i=1}^K r_i$ No Ignores rank order; rises monotonically with $K$ even when junk fills top slots
    RR@$K$ (MRR) $1 / \min\{i \le K : r_i = 1\}$ First hit only Completely blind to all relevant documents after the first relevant hit
    AP@$K$ (MAP) $\frac{1}{R}\sum_{i=1}^K r_i (P@i)$ Yes (all hits) Treats a marginally acceptable hit ($r=1$) identically to a perfect match ($r=3$)
    nDCG@$K$ $\frac{1}{\operatorname{IDCG}@K}\sum_{i=1}^K \frac{g(r_i)}{\log_2(i+1)}$ Yes (graded) Blind to page redundancy/duplicates; sensitive to gain choice ($2^r-1$ vs $r$)

    Seven chapters, each with one main job

    01
    Define what counts as useful

    Build a relevance rubric, see how incomplete judgment pools affect a comparison, and distinguish diagnostic query samples from traffic-weighted estimates.

    02
    Read binary metrics through one ranking

    Follow each relevant hit into precision, recall, AP and reciprocal rank. Inspect the denominators before averaging over queries.

    03
    Give better results more credit

    Build nDCG from grades, gains and positions. Compare the full judged ideal with an ideal restricted to what the system happened to return.

    04
    Locate the loss in the pipeline

    Separate exact-neighbor overlap from relevance, calculate a candidate ceiling, and inspect filtering and reranking with controlled changes.

    05
    Compare systems with the pairs intact

    Inspect all 256 resamples of a four-query example, then group repeated users correctly and distinguish an interval from a hypothesis test.

    06
    Interpret feedback and measure outcomes

    Swap result positions, reweight action choices, and see why missing support, clipped weights and changing experiment denominators matter.

    07
    Trace evidence into a supported answer

    Follow missing context, inspect individual claims and citations, and evaluate abstention with both answer quality and coverage visible.

    Build an evaluation you can explain one query at a time

    Carry four connected artifacts through every evaluation run. A run stores the ordered list of document IDs returned for each query; relevance judgments (qrels) map query–document pairs to integer grades. Preserving query and document IDs end-to-end lets you jump directly from a $-0.03$ aggregate delta to the exact queries that regressed.

    Run the standard-library metric lab

    Download retrieval_metrics.py and run both commands from its directory:

    python retrieval_metrics.py
python retrieval_metrics.py --self-test

    The first command prints our worked six-document benchmark at $K=5$: $P@5 = 0.6000$, $\operatorname{Recall}@5 = 0.7500$, $\operatorname{AP}@5 = 53/120 \approx 0.4417$, $\operatorname{RR}@5 = 0.5000$, and $\operatorname{nDCG}@5 \approx 0.6417$. The second runs 11 unit assertions covering short runs, duplicate IDs, unjudged items, and zero-relevant edge cases using only Python’s standard library.
