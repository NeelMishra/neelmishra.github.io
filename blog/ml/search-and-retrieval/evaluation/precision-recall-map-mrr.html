    Precision, Recall, MAP, and MRR: One Ranking, Four Questions

    September 2026 · 4 min read

    Before you start: Relevance judgments and test collections.

    Suppose a query has four relevant documents in the catalog: A, C, D, and F. Your engine returns B, A, C, E, D, F. The first result is wrong, the next two are useful, and one useful result is buried at rank six. Which metric should improve when you move a relevant document upward? That depends on the question you want the metric to answer.

    Precision counts returned usefulness; recall counts recovered usefulness

    Let $r_i$ be 1 if the document at rank $i$ is relevant and 0 otherwise. Let $R$ be the number of relevant documents in the eligible catalog according to the qrels. Precision at $K$ divides the number of relevant returned documents by $K$. Recall divides that same count by $R$.

    $$P@K=\frac{\sum_{i=1}^{K}r_i}{K},\qquad \operatorname{Recall}@K=\frac{\sum_{i=1}^{K}r_i}{R}.$$

    At K=5, A, C, and D are found: P@5=3/5=0.6 and Recall@5=3/4=0.75. Moving A to rank one leaves these two values unchanged as long as the top-five membership stays the same. They measure set quality at the cutoff, not the ordering within that set.

    For a short result list, this series keeps the precision denominator at K: returning two useful items for five requested slots gives P@5=0.4. This penalizes empty slots. State that choice because some application code divides by the actual returned count. Deduplicate IDs first; showing the same useful item three times does not recover three relevant items.

    Average precision rewards getting each useful document earlier

    At every relevant hit, record the precision of the prefix ending there. A is at rank 2, so its prefix precision is 1/2. C is at rank 3, giving 2/3. D is at rank 5, giving 3/5. Sum those contributions, then divide by the number of relevant documents in the catalog.

    $$\operatorname{AP}@K=\frac{1}{R}\sum_{i=1}^{K}r_i(P@i).$$
    $$\operatorname{AP}@5=\frac{\frac12+\frac23+\frac35}{4}=\frac{53}{120}\approx0.4417.$$

    The missing relevant document F contributes zero at this cutoff. For the complete six-item ranking, add P@6=4/6 before dividing by four, yielding AP≈0.6083. AP is not the average of all prefix precisions: irrelevant ranks make no direct contribution. MAP is the mean AP across queries, usually giving each included query equal weight.

    AP@K needs a named convention

    This series divides by all R known relevant documents. Another common implementation divides by min(R,K). If R=4 and K=2, the same numerator 0.5 produces 0.125 under our convention and 0.25 under the alternative. Never compare two reported MAP@K values until you check their denominators.

    Reciprocal rank cares only about the first useful result

    $$\operatorname{RR}@K=\begin{cases}1/j,&j=\min\{i\le K:r_i=1\},\\0,&\text{no relevant hit in the first }K.\end{cases}$$

    Here the first hit is at rank two, so RR@5=0.5. Mean reciprocal rank averages this across queries. Move A to rank one and RR becomes 1; making ranks two through five terrible will not lower it if that first hit stays. MRR fits a task where one acceptable answer ends the search. It says little about the completeness of a recommendation carousel.

    Queries and edge cases are part of the definition

    Macro recall averages per-query recall. Micro recall pools recovered relevant documents and total relevant documents across queries, so queries with more relevant documents weigh more. Neither is automatically correct for all products. Store per-query values so the aggregation can be audited.

    When R=0, recall and AP are undefined mathematically. Our downloadable lab returns None and reports how many such queries were excluded. Do not quietly replace them with perfect scores. Answerable and no-answer queries deserve separate evaluation; a search system might be expected to abstain when nothing is eligible. MRR can still record zero for a failed search, but the report must say which queries were included.

    The standard-library Python lab implements these definitions, validates duplicate IDs, and offers both AP denominators explicitly. It includes the calculations above and edge-case checks. Run it with Python, then substitute a small ranking of your own.

    Check your understanding: Two systems retrieve the same five documents in different orders. Which metrics can change?

    P@5 and Recall@5 cannot change. AP@5 and RR@5 can, because their contributions depend on positions. Graded nDCG can change too.
