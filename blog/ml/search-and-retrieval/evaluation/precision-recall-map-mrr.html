    Precision, Recall, MAP, and MRR: One Ranking, Four Questions

    September 2026 · 15 min read

    Before you start: relevance judgments and test collections. Here every catalog document is judged and eligible so we can isolate exactly what each binary metric counts.

    Suppose a search engine returns six documents in order B, A, C, E, D, F, and human assessors judge four of them relevant: A, C, D, and F ($R = 4$). Rank 1 is an irrelevant miss (B), three relevant documents appear within the top five slots ($K = 5$), and the fourth relevant document (F) sits just past the cutoff at rank 6.

    Keeping that single ranking fixed lets us watch four standard metrics answer four distinct engineering questions: Precision@$K$ measures result purity inside the top-$K$ window; Recall@$K$ measures coverage of the catalog’s relevant set; Average Precision ($\operatorname{AP}@K$) rewards front-loading every relevant hit; and Reciprocal Rank ($\operatorname{RR}@K$) cares solely about the first relevant hit.

    One hit count, two denominators: Precision@$K$ vs Recall@$K$

    Define the set-cutoff quantities before writing their equations:

    • $K \ge 1$: the rank cutoff (number of displayed or candidate slots evaluated; here $K = 5$).
    • $i \in \{1, 2, \dots, K\}$: the 1-based rank index in the returned list.
    • $r_i \in \{0, 1\}$: binary relevance indicator equal to $1$ if the document at rank $i$ is relevant and $0$ otherwise.
    • $R \ge 1$: total number of judged-relevant documents across the entire eligible catalog (here $R = |\{\text{A, C, D, F}\}| = 4$, including items missed below rank $K$).
    $$P@K = \frac{1}{K}\sum_{i=1}^{K} r_i, \qquad \operatorname{Recall}@K = \frac{1}{R}\sum_{i=1}^{K} r_i.$$

    Average Precision ($\operatorname{AP}@K$) credits prefix precision at every hit

    To make rank order inside the top $K$ matter across all relevant documents, scan down the ranking from $i = 1$ to $K$. Whenever rank $i$ holds a relevant document ($r_i = 1$), record the prefix precision $P@i = \frac{1}{i}\sum_{m=1}^{i} r_m$ at that exact rank, then divide the sum of those hit precisions by the catalog’s total relevant count $R$:

    $$\operatorname{AP}@K = \frac{1}{R}\sum_{i=1}^{K} r_i \cdot (P@i) = \frac{1}{R}\sum_{i=1}^{K} r_i \left(\frac{1}{i}\sum_{m=1}^{i} r_m\right).$$

    Why two evaluators can report different AP@K ($R$ vs $\min(R, K)$)

    Our formula divides by all $R$ relevant items, matching NIST trec_eval’s map_cut. Some recommender libraries instead divide by $\min(R, K)$ so a list of length $K < R$ can still reach $1.0$. At $K = 2$ on our ranking, numerator $1/2$ divided by $R = 4$ gives $0.125$, whereas dividing by $\min(4, 2) = 2$ gives $0.250$. State the denominator convention explicitly whenever $K < R$.

    Reciprocal Rank ($\operatorname{RR}@K$) stops at the first relevant hit

    When a user needs just one known item (for example, navigating to a login page or finding one exact error-code article), let $j = \min\{i \in \{1,\dots,K\} : r_i = 1\}$ be the rank of the earliest relevant hit within the top $K$ slots:

    $$\operatorname{RR}@K = \begin{cases} 1 / j, & \text{if } \{i \le K : r_i = 1\} \ne \varnothing \text{ with minimum } j, \\ 0, & \text{if } r_1 = r_2 = \dots = r_K = 0. \end{cases}$$

    Here A appears at $j = 2$, so $\operatorname{RR}@5 = 1/2 = 0.5000$. Promoting A to rank 1 jumps $\operatorname{RR}@5$ to $1.0000$—and leaves $\operatorname{RR}@5$ completely blind to whether C, D, and F appear at ranks 2–4 or vanish altogether.

    Averaging over a query set: $\operatorname{MAP}@K$, $\operatorname{MRR}@K$, and Macro vs Micro Recall

    Let $\mathcal{Q}$ be the set of evaluated queries with $R_q \ge 1$ relevant items per query $q \in \mathcal{Q}$, and let $|\mathcal{Q}|$ be the number of included queries. Mean Average Precision ($\operatorname{MAP}@K$) and Mean Reciprocal Rank ($\operatorname{MRR}@K$) weight every query $q \in \mathcal{Q}$ equally:

    $$\operatorname{MAP}@K = \frac{1}{|\mathcal{Q}|}\sum_{q \in \mathcal{Q}} \operatorname{AP}_q@K, \qquad \operatorname{MRR}@K = \frac{1}{|\mathcal{Q}|}\sum_{q \in \mathcal{Q}} \operatorname{RR}_q@K.$$

    Adding a second query $q_2$ that has $R_2 = 1$ relevant item placed right at rank 1 ($\operatorname{AP}_{q_2}@5 = 1.0, \operatorname{RR}_{q_2}@5 = 1.0$) illustrates equal query weighting versus pooled document weighting:

    Keep edge-case rules explicit in code

    • Short runs ($|L| < K$): $P@K$ still divides by $K$ so under-filled result pages are not artificially rewarded for returning one lucky item.
    • Duplicate IDs: reject runs containing repeated document IDs before scoring.
    • Zero-relevant queries ($R_q = 0$): exclude from $\operatorname{Recall}$ and $\operatorname{MAP}$ denominators while logging the excluded query count explicitly.
    Python: reproduce the ranking, both AP conventions, and query averages

    Save retrieval_metrics.py beside this snippet:

    from retrieval_metrics import ranking_metrics, evaluate

qrels = {"A": 3, "B": 0, "C": 2, "D": 1, "E": 0, "F": 1}
run = ["B", "A", "C", "E", "D", "F"]
scores = ranking_metrics(run, qrels, 5)
print({key: round(scores[key], 4)
       for key in ("precision", "recall", "ap", "rr")})
# {'precision': 0.6, 'recall': 0.75, 'ap': 0.4417, 'rr': 0.5}

print(ranking_metrics(run, qrels, 2)["ap"])  # 0.125
print(ranking_metrics(run, qrels, 2, ap_denominator="min")["ap"])  # 0.25

report = evaluate({"q1": run, "q2": ["X"]},
                  {"q1": qrels, "q2": {"X": 1}}, 5)
print(report["macro"]["ap"])  # mean=0.720833..., included=2, excluded=0
print(report["macro"]["rr"])  # mean=0.75, included=2, excluded=0

    Notice that qrels actually gave A grade $3$, C grade $2$, and D/F grade $1$—differences that binary metrics completely flatten into $1$. Continue to Chapter 3: Graded Gain and nDCG to preserve those distinctions.
