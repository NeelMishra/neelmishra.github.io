    Local Explainability: Comparing LIME and SHAP

    September 2026 · 7 min read

    This comparison builds on LIME’s local surrogate, Shapley values and Kernel SHAP. Read those worked examples first: they introduce the fitted line, the reference prediction and the feature contributions used below.

    “Why did the model make this prediction?” can mean two different things: describe its behavior near this input, or account for the difference between its output and a reference. LIME addresses the first question; SHAP addresses the second. Now that we have calculated both, we can compare their answers and the checks each needs.

    Keep the predictor and its output clear

    A local explanation concerns one input row. The original predictor stays fixed while the explanation method constructs modified inputs and inspects the resulting outputs. It may fit a second, simpler model; that does not retrain the predictor being explained.

    Include preprocessing in the prediction path: a perturbed raw row should pass through the same encoding, scaling, and feature construction used for the original row. Also choose the output explicitly. “Class-1 probability” and “raw class-1 score” are different explanation targets even when they come from the same classifier.

    Know what would make an answer useful

    QuestionWhat the result needsWhere to inspect it
    LIME: nearby behaviorA meaningful neighborhood, readable feature units, and adequate local agreement.Row and probe errors
    SHAP: reference differenceA declared background, hidden-feature rule, output scale, and reliable allocation.Background inputs and mask coverage
    Predictive performanceEvaluation targets, a named dataset and metric, and an appropriate comparison.The label-switch example

    A contribution can be large while a predictor is inaccurate. A line can sound intuitive while fitting badly. The checks above concern the particular question each method answers; the final chapter shows those differences with fixed model outputs and changing evaluation targets.

    Revisit an example, then choose an explainer

    The first three chapters supply the calculations behind this comparison, which is chapter 4. Revisit any unfamiliar step below. Then continue to chapter 5 to choose a method and test whether its answer is useful.

    01
    LIME: fit local behavior

    Change the row, neighborhood width, and sample seed. Compare the fitted line against the model and read its slope in hours or minutes.

     02
    Shapley values: share a prediction difference

    Calculate model inputs behind coalition values. Inspect reveal order, interaction bonuses, and reference changes; the general formula is optional.

     03
    Kernel SHAP: compute the allocation by regression

    Try candidate contributions, see why endpoint constraints and kernel weights matter, and diagnose incomplete mask coverage.

     05
    Next: choose and validate an explainer

    Separate local behavior, output attribution, and predictive reliance. Learn which check can expose a misleading result.

    If your immediate task is explaining a tree model, read the Shapley example first and continue to TreeSHAP. Kernel SHAP remains useful for understanding the generic computation, but it is not a prerequisite for using tree structure.
