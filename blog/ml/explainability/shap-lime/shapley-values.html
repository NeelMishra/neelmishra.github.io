    Shapley Values for Model Explanations

    September 2026 · 14 min read

    A prediction is a number. An explanation needs a comparison: higher or lower than what, and how should the difference be shared among the inputs? Shapley values answer the sharing question by averaging each feature’s contribution over every order in which features could become known.

    We will keep one tiny predictor fixed, first explain its output by hand, then change the reference used for comparison. The factorial formula is optional; the two reveal orders carry the central idea.

    Give the numbers a model behind them

    Our constructed model reads two binary features, A and B. Each is either 0 or 1. It starts at score 0.10, adds 0.30 when A is 1, adds 0.10 when B is 1, and adds another 0.30 when both are 1. These are arbitrary score units, with no fitted probability or real-world risk interpretation.

    Explain the row A = 1, B = 1, whose score is 0.80. For now, compare it with the single reference row A = 0, B = 0, whose score is 0.10. A hidden feature takes its reference value. Revealing a feature means replacing that value with the explained row’s value; the model itself stays fixed.

    The four complete inputs we actually send to the model
    Features revealedModel input (A, B)Score
    None(0, 0)0.10
    A(1, 0)0.40
    B(0, 1)0.20
    A and B(1, 1)0.80

    Share the increase by averaging both reveal orders

    Reveal A first: it gets the increase from 0.10 to 0.40, or 0.30. Reveal A after B: it gets the increase from 0.20 to 0.80, or 0.60. Neither order should have special status, so A receives their average, 0.45. B receives the average of 0.10 and 0.40, which is 0.25.

    The last feature revealed receives the entire interaction in that particular order. Averaging the orders shares it equally between the two participants: A gets its 0.30 standalone increase plus half the 0.30 bonus; B gets 0.10 plus the other half. With no interaction, order makes no difference.

    Try the penalty. B’s average contribution becomes zero: its +0.10 when first cancels its −0.10 when second. A zero average therefore need not mean that the feature never changes a prediction. The explanation describes this row and this comparison.

    A background dataset changes the comparison

    Real explanations often use several reference rows, called the background. For each reveal mask, keep the explained values where the mask is 1. Where it is 0, copy values from one background row. Repeat for every background row and average the model’s outputs. The hidden coordinates from a row travel together.

    A set of revealed features is a coalition, written $S$. Write $v(S)$ for the average just calculated. The empty set, $\varnothing$, gives the baseline $v(\varnothing)$; revealing every feature gives the prediction. This explains where a table of coalition values comes from. KernelExplainer’s background-data interface uses this replacement approach.

    With all four binary rows as the background, the baseline is (0.10 + 0.20 + 0.40 + 0.80) / 4 = 0.375. Revealing A gives 0.60; revealing B gives 0.50. Averaging both orders now assigns A 0.2625 and B 0.1625. Their sum is smaller because the comparison starts closer to 0.80. The prediction has not changed.

    Hidden does not mean the observed input was missing. It is an explanation operation. Also, replacing hidden values from background rows differs from choosing rows conditional on the revealed values. With correlated features, those rules can give different coalition values. See the TreeSHAP reference example for that distinction; Janzing et al. examine why the distributional choice matters.

    Read the general rule after the example

    Write $\phi_j$ for feature $j$’s averaged contribution. Let $F$ be the full set of $M$ features. The reconstruction rule says that the baseline plus all feature contributions equals the model’s output $f(x)$ at the explained row $x$:

    $$f(x)=v(\varnothing)+\sum_{j\in F}\phi_j.$$

    With more features, keep the same recipe: shuffle the feature names, record what each adds when revealed, and average over all shuffles. The following expansion shows why simply averaging all subsets is different.

    Optional: three features make the weighting visible

    Add a third binary feature C to our model. It contributes 0.20 alone, and there is an extra 0.60 bonus when A, B, and C are all 1. Keep the A–B bonus of 0.30. Explain (1, 1, 1) relative to (0, 0, 0): the prediction is 1.60 and the baseline is 0.10.

    For A, the four marginal increases are 0.30, 0.60, 0.30, and 1.20, with weights 2/6, 1/6, 1/6, and 2/6. Their weighted sum is 0.65. Equal subset weights would give 0.60 instead. The full allocation is A: 0.65, B: 0.45, C: 0.40.

    In the formula below, $S$ contains the features preceding $j$ and $|S|$ is their count. Factorial, written $!$, counts arrangements; $0!=1$. There are $M!$ total orders. Arrange $S$ first, put $j$ next, then arrange everything else:

    $$\phi_j=\sum_{S\subseteq F\setminus\{j\}}\frac{|S|!(M-|S|-1)!}{M!}\,[v(S\cup\{j\})-v(S)].$$

    The bracket is the increase from revealing $j$. The fraction is the share of orders with exactly $S$ before it. This is the order average written as a subset sum.

    What the allocation guarantees

    PropertyFor the fixed coalition game
    EfficiencyAll contributions add to prediction minus baseline.
    SymmetryInterchangeable features with identical marginal effects receive equal contributions.
    Dummy / null featureA feature adding zero to every coalition receives zero. The converse need not hold, as the penalty example shows.
    AdditivityFor two games on the same features, explaining their sum adds their contributions.

    Every reveal order telescopes from the baseline to the prediction, so averaging preserves reconstruction. That numerical check cannot tell you whether the background is appropriate or whether a contribution is causal. A positive value means above the reference on the chosen output scale; it does not mean that increasing the input will always raise the output.

    Compute the game once, then choose an algorithm

    There are $2^M$ reveal masks but $M!$ orders. For a small example, cache every coalition value and reuse it across orders. With $K$ background rows, a direct implementation can require up to $K\,2^M$ model-row evaluations before such reuse. Batching helps runtime but does not change what is being averaged.

    For larger problems, Kernel SHAP fits contributions from sampled coalition values; TreeSHAP uses supported tree structure. These are computation choices for a specified explanation problem, not permission to leave its reference or output unnamed.

    All figures are reproducible with the standard-library Python game calculator and its complete inputs, scores, and reveal orders. Run python explanation_games.py > assets/shapley-games.json. The script evaluates our constructed predictor; it does not call the SHAP package.
