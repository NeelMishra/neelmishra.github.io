    Choosing SHAP, LIME, and Other Explainers

    September 2026 · 12 min read

    A feature can strongly influence a model’s output without helping it predict the true outcome. A local line can fit well near one row and poorly elsewhere. Choose the explanation question first; then choose the method and the check that could reveal a misleading answer.

    Choose the quantity you actually want

    Choose LIME when you need a readable approximation near a row. Declare the output, input representation, perturbation rule, neighborhood width, and allowed surrogate complexity. Check agreement with the original model both at the row and on meaningful nearby inputs. A convincing coefficient plot cannot repair a poor local fit.

    Choose SHAP when you need to allocate a prediction’s difference from a reference. Declare the background, rule for hidden features, and output scale. Then choose the calculator: Kernel SHAP can query a general predictor; TreeSHAP uses supported tree structure. Verify that the chosen implementation explains the intended output under the intended reference semantics.

    Choose permutation importance when you need to inspect predictive reliance on a dataset. With a fixed model, shuffle one feature, recompute predictions, and compare a named metric against its unshuffled value. For an error metric such as mean squared error, an increase means worse predictions. The scikit-learn guide recommends evaluating model quality first and explains repeated shuffles and metric dependence.

    An output explanation is not an accuracy explanation

    Use the earlier two-feature predictor on all four binary inputs. Its scores are 0.10, 0.20, 0.40, and 0.80. Use those same four inputs as an equally weighted SHAP background. This constructed example has numerical targets, so we can measure mean squared error: average the squared difference between each prediction and its target.

    The figure keeps the model, inputs, and SHAP background fixed. Switch between targets that equal the model scores and targets equal to one minus those scores. The latter makes this model a poor predictor. These are illustrative target sets, not observations from a fitted application.

    For A, the shuffle changes the predictions to 0.40, 0.80, 0.10, and 0.20. With matching targets, mean squared error rises from 0 to 0.225. With reversed targets, it falls from 0.350 to 0.125: the same shuffle now has error increase −0.225. It improves this model’s predictions on this particular evaluation set.

    A’s mean absolute SHAP contribution stays 0.225 score units in both cases. Its numerical equality to the first loss increase is incidental: mean squared error uses squared score units. SHAP never consulted these targets. When targets are unavailable, the output explanation remains computable, but this performance comparison does not.

    This is one fixed shuffle so its inputs remain inspectable. A permutation-importance report normally averages repeated random shuffles and reports their spread. That spread reflects shuffle variation for the fixed dataset and model, not every source of uncertainty about future performance. The permutation-importance companion develops the calculation.

    Name the rows behind a global summary

    A local SHAP explanation belongs to one row. To summarize a population, a common choice averages the absolute contribution of each feature across those rows. In our four-row example, A’s signed contributions are −0.1875, −0.2625, +0.1875, and +0.2625. Their signed average is zero, but their average magnitude is 0.225.

    The magnitude describes how strongly the feature shifts model outputs relative to the specified background, while losing direction. It also depends on the evaluation population. A summary over routine cases need not describe rare alerts; show the cohort and retain access to individual explanations. The global TreeSHAP notes continue this distinction.

    Separate a numerical problem from a different question

    What you observeWhat to inspect next
    LIME has a large row or probe errorInspect the fitted curve and neighborhood; do not rely on its coefficients as a faithful description.
    A different seed changes the explanationRepeat with a larger sample budget and inspect whether the important conclusions stabilize.
    SHAP does not reconstruct the intended outputCheck output units, feature order, preprocessing, numerical settings, and which model function was explained.
    SHAP reconstructs but gives implausible sharesInspect the reference and the estimator. The wrong-weight example shows why reconstruction is insufficient.
    A new background changes SHAP valuesYou changed the comparison. Decide which population matches the question; more sampling cannot choose it for you.

    Correlated features need particular care. A second feature can preserve information after the first is shuffled; masking can also create combinations absent from the data. A small individual importance does not prove that the shared information is useless. Inspect the perturbed rows and consider whether a meaningful feature group is the right unit for the question.

    An explanation of the predictor does not establish what a real-world intervention will cause. For example, a score decrease after changing a recorded input establishes how the model reacts to that edited row; it does not establish that making the real change will produce the desired outcome.

    Write a conclusion someone else can reproduce

    Start with one row whose model input and prediction you can verify through the real preprocessing path. For a dataset summary, fix the evaluation rows and metric too. Record the model version, selected output, feature names and order, reference or neighborhood, and sampling settings.

    A useful local report can say: “At 5.3 hours, the fitted line has slope 0.847 score units per hour under a width-1-hour neighborhood. Its prediction differs from the model by 0.091, and its separate local probe RMSE is 0.104.” This names the actual fit and its limitations, instead of saying only that duration is important.

    For SHAP, pair a contribution with the observed feature value, reference population, output units, and reconstructed prediction. Keep a readable short display linked to the complete allocation; the production scoring notes cover that handoff. For anomaly cases, the queue chapter adds the evidence and admission rule a reviewer needs.
