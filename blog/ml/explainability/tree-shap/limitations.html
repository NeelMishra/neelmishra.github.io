    Tree SHAP Limitations and Validation

    September 2026 · 5 min read

    An explanation needs a reference point. “Why is this prediction high?” can mean high compared with all customers, or high compared with similar customers. The model can stay unchanged while those two comparisons produce different contributions.

    Decide what a hidden feature means

    SHAP repeatedly asks for a prediction when some of this row’s features are revealed and others are hidden. Hidden here means unknown to the explanation, not necessarily missing in the input data. We need a rule for averaging over the unrevealed values.

    TreeExplainer modeHow it supplies the missing information
    InterventionalKeep the revealed values from this row; use background rows to supply the other values.
    Tree-path-dependentUse stored training cover statistics to weight branches when a split feature is hidden.

    These define different comparison rules and can yield different values. In particular, tree-path-dependent weights do not generally recover the full conditional distribution of correlated features. Set the mode explicitly when reproducibility matters; see the TreeExplainer documentation.

    The prediction stays fixed when the reference changes

    Return to our two-feature tree. With all four input combinations equally represented, the baseline is 3.5 and the contributions are A: 2.75, B: 1.75.

    Now use a background containing only (A=1, B=0) and (A=1, B=1), equally often. Their predictions are 4 and 8, so the baseline becomes 6. A=1 is already true everywhere in this background: revealing it adds nothing. Revealing B=1 adds 2.

    ▶ Background Choice Changes the Baseline

    Use the four-leaf tree from the worked chapter. The explained row remains A=1, B=1 and the prediction remains 8. Switch which rows define the background.

    Both explanations reconstruct 8. They differ because the second comparison already expects A=1. Changing the background did not change the trained model or the explained row.

    Validate the question as well as the sum

    CheckWhat it catches
    Baseline + contributions = explained outputWrong output units, row order, or model version
    Tiny hand-calculated exampleAn incorrect allocation that happens to add up
    Named background and explicit modeComparisons changing silently between runs
    Correlated or redundant featuresAttribution shifts caused by how information is shared

    A large contribution is evidence about the model’s calculation under this reference rule. It does not establish a causal effect or tell you what would happen after changing a feature in the real world. Interventional masking can also create combinations unlike real observations; inspect whether the comparison fits the question you intend to answer.
