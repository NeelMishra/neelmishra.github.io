    Tree SHAP Limitations and Validation

    September 2026 · 13 min read

    A contribution answers “higher or lower than what?” Exact arithmetic cannot choose that comparison for you. In this chapter, the prediction stays at 8 while we change the reference rows, the rule for hiding features, and finally the tree’s structure. Each change isolates a different interpretation issue.

    The worked tree chapter explains how to allocate a prediction. Here we keep its four binary inputs and scores: (0, 0) → 0, (0, 1) → 2, (1, 0) → 4, and (1, 1) → 8. A and B are just two input features; the scores are regression outputs, not probabilities.

    First choose what “typical” means

    Keep the fitted tree and the explained row (A, B) = (1, 1) fixed. Use replacement from background rows: retain the revealed feature values, fill the others from each reference row, and average the predictions. In TreeExplainer this is the interventional mode.

    With all four combinations equally common, the baseline is their average prediction, 3.5. Now select a reference containing only A=1 rows. Its baseline is (4 + 8) / 2 = 6. Revealing A=1 supplies no new information relative to this reference, so A receives zero. B receives the remaining 2.

    The correlated reference contains three copies of (0, 0), one of (0, 1), one of (1, 0), and three of (1, 1). Matching A and B values are more common. The baseline becomes 3.75; the replacement contributions become A: 2.625 and B: 1.625. The reference changed, not the model. A zero contribution under the A=1 reference therefore does not mean the model never uses A.

    Then choose what a hidden feature means

    A feature hidden from an explanation still needs a value or an averaging rule. It is not the same thing as a missing-value marker passed to the model. These are three distinct ways to answer the partially revealed prediction question:

    RuleWhat happens to hidden features?
    Replacement / interventionalCopy hidden values from the full background. Revealing B does not filter the background’s A values.
    Tree-path-dependentAt a hidden split, divide weight according to the tree’s stored training covers. At a revealed split, follow the row’s branch.
    Empirical conditionalKeep only reference rows matching the revealed values, then average their predictions. Revealing B can change which A values remain.

    The third rule is a direct reference calculation here, not a TreeExplainer option. Exact matching is possible because our example has only four binary combinations, all observed. With continuous or sparse data, estimating conditional distributions requires additional modeling choices.

    A correlated example where the rules disagree

    For this comparison, fit a new tree on the eight correlated rows above. It retains the same four predictions, but its stored covers now reflect counts 3, 1, 1, 3. The root splits on A. On the A=1 side, three of four training rows have B=1.

    Reveal only B=1. The path rule first meets hidden A at the root, so it splits weight equally between the A branches. It then follows B=1 on each side, averaging scores 2 and 8 to get 5. Revealing B later in the tree does not revise the earlier A split.

    The conditional rule instead filters the reference to the four B=1 rows: one has A=0 and three have A=1. It gives scores 2 and 8 weights 1/4 and 3/4, so the answer is 6.5. Replacement keeps the full reference’s evenly divided A values and gives 5.

    Now reveal only A=1. Path covers and conditioning both use the observed 1:3 split of B within that branch, giving 7. Replacement uses the full background’s equally common B values, giving 6. Across the four reveal sets, the differences become different allocations:

    An optional check: does tree structure matter?

    Same binary predictions, different first split

    Fit another depth-two tree on those same eight rows, using random feature selection so B becomes the root. It predicts exactly the same scores on all four binary inputs. Its path explanation for (1, 1) is now A: 1.875 and B: 2.375.

    The path rule uses local covers along a particular representation. Switching the root changes the partial-information averages, even though the fully observed predictions agree. Replacement uses the model’s outputs on completed reference rows. Those outputs agree for both trees here, so its contributions remain 2.625 and 1.625. This example makes a claim about these binary inputs; it does not assume arbitrary models agree elsewhere.

    Validate the explanation you intend to report

    Check reconstruction first: baseline plus contributions should recover the chosen output. Then test a small case by enumerating feature sets, because an incorrect allocation can still add up. Our reproduction checks both library modes on all four input rows, not only the displayed row.

    Record the model, feature order and preprocessing, explained output, explicit mode, and reference data. If changing the background changes your conclusion, report that sensitivity together with the comparison you chose. The global-summary chapter separately explains how the set of rows being summarized affects a plot.

    Replacement can create combinations uncommon in the observed population. Conditional averaging asks what the observed features predict about hidden ones. Neither a feature contribution nor the API word “interventional” alone identifies the effect of changing a real-world variable. Janzing and colleagues explain why the feature-removal question must be specified. For model quality, pair explanations with the separate outcome-based evaluation.
