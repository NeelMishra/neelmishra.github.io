    Choose What a Hidden Feature Means

    October 2026 · 10 min read

    The preceding chapters weighted unknown splits using the sample counts stored inside the tree. We now compare that rule with a second exact definition: filling hidden columns from the ten original customer rows. Maya remains Returning, Premium, High usage ($x = [1, 1, 1]$), and the tree still predicts 90. Changing what “hidden” means changes only two intermediate coalition values—yet shifts $1\tfrac{1}{3}$ dollars of credit from customer group $A$ to usage $C$.

    Rule 1: Stored Branch Counts (tree_path_dependent)

    Let $v_{\mathrm{path}}(S)$ denote the tree’s expected output when feature subset $S \subseteq \{A, B, C\}$ is revealed for Maya and hidden splits average their children in proportion to the training sample counts reaching that split. When $S = \{A\}$, we follow Maya’s known $A = \text{Returning}$ branch to the usage split, where $2$ of the $6$ Returning customers have Low usage ($50$) and $4$ of the $6$ have High usage ($90$):

    $$v_{\mathrm{path}}(\{A\})= \frac{2}{6}(50)+\frac{4}{6}(90)=76\tfrac{2}{3}.$$

    Notice the conditioning implicit in those fractions: because $A$ correlated positively with usage $C$ in our ten rows ($4/6 \approx 66.7\%$ High usage among Returning customers vs. $2/4 = 50\%$ among New customers), revealing $A = \text{Returning}$ already nudges the usage expectation upward inside the subtree. TreeExplainer calls this setting tree_path_dependent.

    Rule 2: Splicing Against Reference Rows (interventional)

    A second rule treats known features and hidden features as independent draws by overwriting Maya’s known columns $S$ onto every row of a reference dataset while keeping the hidden complement $\bar{S} = \{A, B, C\} \setminus S$ intact from each reference row.

    For $S = \{A\}$, overwrite every customer’s column $A$ with Returning, leave each customer’s own plan $B$ and usage $C$ untouched, run all ten hybrid rows down the tree, and average the ten outputs. Every hybrid row now enters the Returning subtree, where only usage $C$ is tested:

    Why $v(\{A\})$ differs between the two rules: usage $C$ is weighted within two different populations.
    Usage $C$Among 6 Returning rows (Path)Among all 10 rows (Replacement)Leaf prediction when $A=\text{Returning}$
    Low ($C=0$)$2 / 6$ ($33.3\%$)$4 / 10$ ($40.0\%$)$50$
    High ($C=1$)$4 / 6$ ($66.7\%$)$6 / 10$ ($60.0\%$)$90$

    Let $v_{\mathrm{ref}}(S)$ denote this replacement expectation over $N = 10$ reference rows, where $x_S$ holds Maya’s values on known features $S$, $r_{\bar{S}}^{(i)}$ holds reference row $i$’s values on hidden features $\bar{S}$, and $f(x_S, r_{\bar{S}}^{(i)})$ is the tree prediction on the spliced row. Evaluating $S = \{A\}$ and writing the general formula gives:

    $$v_{\mathrm{ref}}(\{A\})=\frac{4}{10}(50)+\frac{6}{10}(90)=74,\qquad v_{\mathrm{ref}}(S)=\frac{1}{N}\sum_{i=1}^{N}f\!\left(x_S,\,r_{\bar S}^{(i)}\right).$$

    Because the four originally New customers include two Low-usage rows, splicing $A = \text{Returning}$ onto all ten rows raises the Low-usage weight from $2/6$ to $4/10$ and lowers the coalition expectation from $76\tfrac{2}{3}$ to $74$. TreeExplainer calls this setting interventional.

    Why do $\{B\}$, $\{C\}$, and $\{B, C\}$ agree across both rules? Whenever root feature $A$ is hidden, the path rule weights the New and Returning branches by $4/10$ and $6/10$—and in our dataset, plan $B$ and usage $C$ happen to be split identically inside the branches they affect ($1/4$ Premium in New; $2/4$ High in New), matching the ten-row marginal hybrid evaluation. Only when $A = \text{Returning}$ is fixed and $C$ remains hidden does the $2\tfrac{2}{3}$ gap appear in $\{A\}$ and $\{A, B\}$.

    Why Neither Rule Equals Pure Empirical Conditioning

    Replacement overwrites known columns across all ten reference rows; it does not filter the dataset down to rows matching Maya. Filtering to the four Premium customers (Dev, Farah, Hari, Jay) yields model predictions $30, 50, 90, 90$, whose empirical conditional mean $\mathbb{E}[f(X) \mid B = \text{Premium}]$ is $65$—whereas both of our tree rules give $v(\{B\}) = 58$. Why? In the dataset, three of the four Premium customers also happen to be Returning, so conditioning on $B = \text{Premium}$ pulls in $A = \text{Returning}$ even though the root split on $A$ never inspected $B$. Neither stored branch counts nor interventional splicing performs full observational conditioning across arbitrary splits.
