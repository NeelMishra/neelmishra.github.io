    Use TreeExplainer and Verify the Result

    October 2026 · 10 min read

    From the preceding four chapters, we have two exact hand-calculated explanations for Maya’s spending prediction of $90$ dollars above a baseline of $52$ dollars. Using the tree’s stored branch counts gives contributions $(24\tfrac{1}{3}, 3, 10\tfrac{2}{3})$ for customer group $A$, plan $B$, and usage $C$; replacing hidden inputs from our ten reference rows gives $(23, 3, 12)$. In this final chapter, we encode that exact seven-node tree into Python, run shap.TreeExplainer under both modes, and verify every coalition value and feature share independently.

    Encode the Seven-Node Tree Without Refitting

    Save maya_tree_shap.py, tree_shap_lab.py, and requirements.txt in one directory and run:

    python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python maya_tree_shap.py

    Rather than fitting a new estimator whose split thresholds or leaf averages might differ, maya_tree_shap.py passes the exact seven tree nodes, child indices, split thresholds, sample counts, and node values directly through SHAP’s custom-tree dictionary interface. Leaves store -1 in children_left, children_right, and features.

    Calculate the Path-Dependent Result

    The feature column order is $A$ (customer group: $0=\text{New}, 1=\text{Returning}$), $B$ (plan: $0=\text{Basic}, 1=\text{Premium}$), and $C$ (usage: $0=\text{Low}, 1=\text{High}$). Maya’s feature vector is [[1., 1., 1.]]. Import the prepared tree dictionary and request the stored branch-count calculation:

    import numpy as np
import shap
from maya_tree_shap import model, maya, reference, predict

path_explainer = shap.TreeExplainer(
    model,
    feature_perturbation="tree_path_dependent",
    model_output="raw",
)
path_result = path_explainer(maya, approximate=False)

print(path_result.base_values)  # [52.]
print(path_result.values)       # [[24.33333333, 3., 10.66666667]]

    Here path_result.values has shape (1, 3): one row for Maya and three columns for $(A, B, C)$. Because model_output="raw" leaves the regression tree’s leaf outputs untouched, the baseline $52$ and every contribution are expressed in dollars.

    Switch Only the Hidden-Input Rule

    Hold the tree and Maya’s row fixed, pass the $10 \times 3$ customer matrix as data=reference, and select feature_perturbation="interventional" to reproduce the replacement calculation from Part 4:

    reference_explainer = shap.TreeExplainer(
    model,
    data=reference,
    feature_perturbation="interventional",
    model_output="raw",
)
reference_result = reference_explainer(maya, approximate=False)

print(reference_result.base_values)  # [52.]
print(reference_result.values)       # [[23., 3., 12.]]

    Passing approximate=False instructs TreeExplainer to run the exact polynomial-time TreeSHAP recursion rather than the faster single-path Saabas heuristic (which would erroneously assign $0$ to off-path feature $B$).

    Verify Baseline and Local Accuracy (Efficiency)

    Before writing the baseline and efficiency equations, define the symbols. Let $L = \{2, 3, 5, 6\}$ index the four leaves, $n_\ell$ be the training sample count stored at leaf $\ell$, $N = \sum_{\ell \in L} n_\ell = 10$ be the total root sample weight, and $y_\ell$ be the dollar prediction at leaf $\ell$. With no features revealed ($S = \varnothing$), the expected baseline $\phi_0$ weights each leaf by $n_\ell / N$:

    $$\begin{aligned} \phi_0 = \sum_{\ell \in L}\frac{n_\ell}{N}\,y_\ell &=\frac{3}{10}(10)+\frac{1}{10}(30)+\frac{2}{10}(50)+\frac{4}{10}(90)=52. \end{aligned}$$

    Let $\phi_A, \phi_B, \phi_C$ denote the Shapley attributions assigned to features $A, B, C$ for Maya’s input $x = (1, 1, 1)$, and let $f(x) = 90$ denote Maya’s full-tree prediction at leaf #6. Local accuracy (efficiency) requires:

    $$\phi_0+\phi_A+\phi_B+\phi_C=f(x)=90.$$
    for result in (path_result, reference_result):
    np.testing.assert_allclose(result.base_values, [52.])
    np.testing.assert_allclose(
        result.base_values + result.values.sum(axis=1),
        predict(maya),
        atol=2e-6, rtol=0,
    )

    Keep each attribution vector paired with its own base_values. If you later pass a filtered background cohort (for instance, only recently onboarded accounts) to data=, both $\phi_0$ and the individual shares shift together so their sum still equals $90$.

    Verify Individual Shares Against Explicit $2^3$ Coalition Enumeration

    Summing to $90$ is necessary but not sufficient: assigning $(38, 0, 0)$ would also add $52 + 38 = 90$. To verify that TreeSHAP computed the exact Shapley allocation, evaluate all $2^3 = 8$ feature subsets independently and apply the Shapley formula directly.

    Let $F = \{A, B, C\}$ be the set of $p = 3$ features, $j \in F$ the target feature, $S \subseteq F \setminus \{j\}$ any subset of the remaining $p - 1 = 2$ features, $|S| \in \{0, 1, 2\}$ its size, and $v(S)$ the value function under either rule. The exact Shapley value $\phi_j$ is:

    $$\phi_j = \sum_{S \subseteq F \setminus \{j\}} \frac{|S|!\,(p - |S| - 1)!}{p!}\,\big[v(S \cup \{j\}) - v(S)\big].$$

    For $p = 3$, the combinatorial factor $\frac{|S|!(2 - |S|)!}{6}$ equals $\frac{1}{3}$ when $|S| = 0$ (neither other feature known), $\frac{1}{6}$ when $|S| = 1$ (one other feature known), and $\frac{1}{3}$ when $|S| = 2$ (both other features known). Checking every coalition side by side confirms both vectors:

    from maya_tree_shap import exact_values

for rule, result in [
    ("path", path_result),
    ("replacement", reference_result),
]:
    baseline, expected, groups = exact_values(maya[0], rule)
    np.testing.assert_allclose(
        result.base_values[0], float(baseline), atol=1e-12,
    )
    np.testing.assert_allclose(
        result.values[0], np.asarray(expected, dtype=float),
        atol=2e-6, rtol=0,
    )

    exact_values traverses branches or constructs $10$-row hybrids from scratch without touching shap, and maya_tree_shap.py runs this assertion across all $2^3 = 8$ possible binary input vectors $(x_A, x_B, x_C) \in \{0, 1\}^3$.

    Three Practical Checks When Calling TreeExplainer on Real Ensembles

    Production safeguards before logging or plotting TreeExplainer outputs.
    SettingWhat can go wrongVerification check
    model_outputTree classifiers default to log-odds margins in some wrappers and probabilities in others; probability mode requires an interventional background dataset.Assert whether base_values + values.sum(-1) matches predict, decision_function, or predict_proba.
    approximate=TrueComputes fast single-path Saabas attributions instead of Shapley values, dropping off-path interactions (giving $\phi_B = 0$ instead of $+3$ here).Keep approximate=False whenever exact Shapley consistency is required.
    Background sizeLarge data matrices scale interventional runtime linearly in $N_{\text{ref}}$, while tiny random subsamples introduce baseline variance.Fix a versioned, stratified reference sample (typically $100\text{–}1{,}000$ rows) and check stability across two seeds.

    Read the Verified Numbers in Plain Language

    Under stored branch counts, the tree’s population average is $52$ dollars, and Maya’s $38$-dollar uplift to $90$ splits into $+24\tfrac{1}{3}$ for Returning status, $+3$ for Premium plan, and $+10\tfrac{2}{3}$ for High usage. Under replacement across the ten customer rows, the same $38$-dollar uplift splits into $+23$, $+3$, and $+12$. Both answers are exact Shapley solutions to their respective value functions—and you can now verify both from raw leaf arithmetic up to Python code.

    The recorded results store the exact group values, library outputs, maximum numerical differences ($\le 10^{-6}$), and tested package versions.
