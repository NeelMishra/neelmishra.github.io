    Why Tree SHAP Beats Generic Explainers for Trees

    September 2026 · 4 min read

    Suppose you want to explain one prediction from a forest containing hundreds of trees. You could repeatedly hide features, query the whole model, and estimate each feature’s contribution. TreeSHAP saves work by using the splits and leaves directly.

    The explanation still asks the Shapley question: how much does revealing this feature change the prediction, averaged over the orders in which features could be revealed?

    Separate the question from the calculation

    LIME and SHAP answer different questions. Kernel SHAP and TreeSHAP can target the same Shapley values when the output and missing-feature rules match.

    MethodWhat it calculatesWhere the work goes
    LIMEA simple model fitted near the rowGenerate nearby inputs, query the model, fit the local approximation
    Kernel SHAPShapley contributions through weighted regressionEvaluate sets of revealed features; sampling many sets can be expensive
    TreeSHAPShapley contributions using supported tree structuresReuse branch calculations rather than evaluate every feature set separately

    ▶ Query the model, or use its tree structure

    TreeSHAP can reuse branch calculations when different sets of features are known. It must account for alternative paths as well as the fully observed path.

    Reading one prediction path is insufficient. If a split feature is hidden, both branches may contribute to the expected prediction. The next chapter’s two-feature tree makes this visible with four leaves.

    The TreeSHAP paper gives an efficient exact algorithm for its tree-based attribution rules. “Exact” refers to the chosen explanation problem: it does not mean the background assumptions are automatically correct. A generic explainer with enough evaluations can agree with TreeSHAP when both solve the same problem.

    A global plot summarizes many local explanations

    A global SHAP chart is a view of already computed contributions, not another algorithm competing with TreeSHAP. First explain individual rows; then summarize how large each feature’s contributions are across a chosen dataset. The global-summary chapter explains what that aggregation preserves and loses.

    For a supported tree model, start by checking TreeSHAP’s output and background settings. When tree internals are unavailable, Kernel SHAP offers a model-agnostic route. If you want an understandable local approximation rather than a Shapley allocation, consider LIME.
