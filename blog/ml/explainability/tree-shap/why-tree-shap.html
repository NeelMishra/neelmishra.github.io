    How TreeSHAP Avoids Listing Every Feature Group

    October 2026 · 10 min read

    The previous chapter explained Maya’s $90 prediction by evaluating eight combinations of her details. With 20 features, the same strategy needs more than a million groups. TreeSHAP avoids that enumeration by using the structure of the prediction function.

    We will derive a leaf-based dynamic program for our path-dependent rule. It calculates the same Shapley average as before. The change is in how we organize the arithmetic. The downloadable implementation is deliberately small and uses exact fractions so each step can be checked.

    Write the partial prediction as a sum of leaves

    For any revealed group, assign each leaf the weight that reaches it. Multiply each leaf’s prediction by that weight and add the results. With no inputs known, the four weights are 0.30, 0.10, 0.20, and 0.40. With everything known, only the 90 leaf has weight one.

    This decomposes the prediction into four smaller functions: “the contribution of the 10 leaf,” “the contribution of the 30 leaf,” and so on. Shapley values are linear in the group values. We can therefore calculate each leaf function’s Shapley values and add the results feature by feature.

    Linearity follows directly from the subtraction in a marginal contribution. The difference between two sums is the sum of their differences. Averaging those differences over the same reveal orders preserves the sum.

    Describe one leaf using two fractions per feature

    Focus on the $90 leaf containing Gia, Hari, Isha, and Jay. Its path requires a Returning customer (A = 1) with High usage (C = 1). Six of our ten customers are Returning, so the hidden fraction at the first split is 6/10. Four of those six have High usage, so the next hidden fraction is 4/6.

    For each feature on this leaf’s path, store two numbers. Call its hidden fraction $z$: the path weight when the feature is not revealed. Call its revealed fraction $o$: one if the customer satisfies the path condition and zero otherwise.

    Feature on the 90 pathHidden fraction zRevealed fraction o
    A3/51
    C2/31

    For A, the table gives us $z=6/10=3/5$. Since Maya is Returning, she follows this branch when A is revealed, so $o=1$. For C, the corresponding values are $z=4/6=2/3$ and $o=1$ because Maya has High usage.

    For the 90 leaf, neither feature known gives weight $(3/5)(2/3)=2/5$. Only A known gives $1\times2/3$. Only C known gives $3/5\times1$. Both known gives one. Multiply these weights by 90 to get this leaf’s part of each group value.

    Calculate A’s share of the 90 leaf

    This leaf function depends on A and C. B does nothing to it. We can ignore B while explaining this individual function: in a uniformly random ordering of A, B, and C, the relative order of A and C is still equally likely in either direction.

    If A joins before C, revealing A replaces its hidden fraction 3/5 with 1 while C remains hidden at 2/3. The change in this leaf’s output is $90(1-3/5)(2/3)=24$.

    If A joins after C, the change is $90(1-3/5)\times1=36$. Average them: A receives $(24+36)/2=30$ from this leaf. For C, the analogous average is $90(1-2/3)(3/5+1)/2=24$.

    The leaf’s baseline is 36. Its two contributions sum to 54, and $36+54=90$. Other leaves supply their own baselines and contributions; some contributions will be negative because revealing the customer’s inputs rules those leaves out.

    Longer paths: group products by how many inputs are known

    Suppose a leaf path has $d$ distinct features. To calculate one feature j’s contribution, consider the other $d-1$ features. Each contributes either its hidden fraction $z$ or its revealed fraction $o$, depending on whether it precedes j.

    We need the sum of these products for each possible number of preceding features. Store those sums in a list: entry 0 for none preceding, entry 1 for one preceding, and so on. Features with the same group size have the same Shapley weight, so their products can be added before applying that weight.

    A polynomial is a convenient way to organize the list. For each other feature, form $(z+ot)$ and multiply the factors. The variable $t$ is a counting device: selecting the $ot$ term means that feature is revealed. The coefficient of $t^k$ adds all products with exactly $k$ revealed features.

    $$Q_j(t)=\prod_{i\ne j}(z_i+o_i t).$$

    Here the product runs only over the other distinct features on this leaf’s path. Write $q_k$ for its coefficient of $t^k$. For a leaf value $u$, j’s contribution from this leaf is:

    $$\begin{aligned}\phi_{j,\mathrm{leaf}}&=u(o_j-z_j)W_j,\\W_j&=\sum_{k=0}^{d-1}\frac{q_k}{d\binom{d-1}{k}}.\end{aligned}$$

    Each part has a job. The difference $o_j-z_j$ is the change when j is revealed. The coefficient $q_k$ totals the route weights for groups of size k. The denominator supplies the Shapley weight for each such group. Finally, the leaf value converts route weight into model-output units.

    A three-feature coefficient calculation

    For a separate three-feature leaf, suppose the two features other than j have factors $(1/2+t)$ and $(1/4+t)$. Multiplying gives:

    $$(1/2+t)(1/4+t)=1/8+(3/4)t+t^2.$$

    The middle coefficient combines two groups: the first feature revealed and the second hidden contributes 1/4; the second revealed and the first hidden contributes 1/2. Their sum is 3/4. We have kept both possibilities without storing them as separate groups.

    With three distinct features, the weights by group size are 1/3, 1/6, and 1/3. Thus $W_j=(1/8)/3+(3/4)/6+1/3=1/2$. If the leaf predicts 100, j’s hidden fraction is 0.4, and its revealed fraction is 1, then this leaf contributes $100(1-0.4)(1/2)=30$ to j.

    Update the coefficient list without enumerating groups

    Start with the list [1]. Multiplying an existing polynomial by $(z+ot)$ updates each coefficient using only its old value and its left neighbor:

    $$c'_k=z\,c_k+o\,c_{k-1}.$$

    Treat entries outside the old list as zero. The first term keeps the new feature hidden, preserving the group size. The second reveals it, increasing the group size by one. This is the dynamic program: many individual group products share the same coefficient entry.

    coeff = [1]
for z, o in factors:
    new = [0] * (len(coeff) + 1)
    for k, value in enumerate(coeff):
        new[k] += z * value
        new[k + 1] += o * value
    coeff = new

    Build the product for all features on the path once. For each j, remove its factor to get $Q_j$. If $P=(z_j+o_jt)Q_j$, coefficient comparison gives $q_0=p_0/z_j$ and $q_k=(p_k-o_jq_{k-1})/z_j$. This removes one factor in linear time. Our toy covers are strictly positive, so the divisions are defined; exact rational arithmetic avoids numerical cancellation.

    Where the speed improvement comes from

    For a leaf with d distinct features, building the polynomial takes quadratic work in d. Removing one factor and summing its weighted coefficients takes linear work; repeating that for d features is again quadratic. Across L leaves with path depth at most D, this takes $O(LD^2)$ arithmetic operations per tree, plus the feature-output bookkeeping. For T trees, the corresponding bound is $O(TLD^2)$.

    This is an arithmetic-operation count, not a promise about exact-fraction runtime: large rational numerators and denominators make individual operations more expensive. The teaching script also optionally retains per-leaf details for the tables. Disable that collection when inspecting the algorithm’s working storage.

    The original TreeSHAP algorithm organizes path weights with extend and unwind operations. SHAP’s reference Python implementation exposes those operations. Our leaf-polynomial lab is an equivalent derivation of the same path-cover game, verified against exhaustive groups and the compiled library. It is intended for understanding, not production speed.

    So far, each path used a feature only once. Real trees can split on the same input again lower down. The next chapter shows how to preserve the meaning of “reveal one feature” in that situation.
