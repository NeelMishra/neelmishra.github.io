    Calculate Tree SHAP Values by Hand

    October 2026 · 8 min read

    We have a prediction of 90, a baseline of 52, and three features. To calculate Shapley values directly, we need the model’s average output for every group of revealed features. Three features give only eight groups, so we can inspect the complete calculation.

    Keep the four-leaf tree and customer A = B = C = 1 fixed. We continue to use stored branch covers when a feature is hidden. Write $v(S)$ for the result when the group $S$ is revealed. For example, $v(\{A\})$ means “A is known; B and C are hidden.” The empty group $\varnothing$ means no values are revealed.

    Calculate the eight group values

    With nothing known, the left subtree averages to $(30\times10+10\times30)/40=15$. The right averages to $(20\times50+40\times90)/60=76\frac23$. Combining them gives $0.4\times15+0.6\times76\frac23=52$.

    Revealing A sends all weight right, giving $76\frac23$. Revealing only B leaves A unknown: the left subtree now returns 30, while the right still averages to $76\frac23$. Thus $v(\{B\})=0.4\times30+0.6\times76\frac23=58$.

    Revealing only C leaves the left subtree at 15 and makes the right subtree return 90. This gives $v(\{C\})=0.4\times15+0.6\times90=60$. Notice that “only C known” still visits the left subtree. Knowing C does not tell us A.

    The two-feature rows follow the same rule. In particular, B has no further effect after A is known to be 1. That does not mean B is irrelevant in every group. When A remains hidden, B raises the partial prediction by 6.

    Reveal the features in all six orders

    For the order A → B → C, the successive values are 52 → $76\frac23$ → $76\frac23$ → 90. Attribute each change to the feature just revealed: A gets $24\frac23$, B gets 0, and C gets $13\frac13$.

    For B → C → A, the values are 52 → 58 → 66 → 90. B gets 6, C gets 8, and A gets 24. These contributions still sum to 38, but the allocation changed. Neither order gets to decide the final answer alone.

    Every row distributes 38. Averaging each column gives the Shapley allocation. B appears before A in three of the six orders, contributing 6 each time. It appears after A in the other three, contributing zero. Its final value is therefore $(6+6+6)/6=3$.

    Group equivalent orders together

    Listing reveal orders is intuitive, but we can reuse calculations. For A, there are four possible groups before it joins: none, B alone, C alone, or B and C together. A is first in two orders and last in two orders. Each of the two one-feature groups precedes A in one order.

    Consequently, the weights for these four groups are $1/3,1/6,1/6,1/3$. Apply them to A’s changes:

    $$\begin{aligned}\phi_A={}&\tfrac13(76\tfrac23-52)\\&+\tfrac16(76\tfrac23-58)\\&+\tfrac16(90-60)\\&+\tfrac13(90-66)=24\tfrac13.\end{aligned}$$

    For $M$ total features, a particular preceding group containing $k$ features has weight $k!(M-k-1)!/M!$. The factorial counts how many reveal orders put precisely those features before the one being explained. We average over orders uniformly; we do not average the groups uniformly.

    A useful equivalent expression for the weight is $1/[M\binom{M-1}{k}]$. There are $\binom{M-1}{k}$ possible preceding groups of size $k$, and together they receive weight $1/M$. The exact lab uses this form.

    Why ordinary path differences give another answer

    We can walk the customer’s actual path and attribute the change in the subtree average at each step. At A, the average changes from 52 to $76\frac23$. At C, it changes from $76\frac23$ to 90. That gives A $24\frac23$, B 0, and C $13\frac13$.

    This path-difference explanation adds up correctly. It also matches the orders in which A is revealed before either relevant lower split. It does not average the other orders. In our example, it misses the situations in which B changes the partial prediction before A is revealed.

    The lesson is precise: adding up to the prediction is necessary, but it does not prove that a set of values is the Shapley allocation. Our direct path values and our Shapley values pass the same total-sum check and disagree feature by feature.

    Reproduce every number without an ML library

    from tree_shap_lab import TREE, X, coalition_value, enumerate_shap

baseline, phi, groups = enumerate_shap(
    lambda known: coalition_value(TREE, X, known), m=3
)
print(baseline, phi)
# 52 [Fraction(73, 3), Fraction(3, 1), Fraction(32, 3)]
assert baseline + sum(phi) == 90

    The script uses rational numbers, so these are exact fractions rather than rounded floating-point approximations. It evaluates every group recursively and applies the Shapley weights. This makes it a useful small-example reference, but the number of groups doubles whenever we add a feature.

    The Tree SHAP paper develops an efficient alternative to exhaustive groups and discusses the distinction from path-difference attributions. Next we will derive the efficient idea directly from our four leaves.
