    Tree SHAP Path Contributions

    September 2026 · 5 min read

    A tree follows one path when every feature is known. Explaining the prediction requires more: when a feature is unknown, several paths may remain possible. TreeSHAP efficiently accounts for those possibilities and averages marginal effects over feature orders. A sequence of changes along the observed path alone is not the Shapley calculation.

    A complete small tree

    The full prediction is 8. With neither feature known, average all four equally likely leaves: (0+2+4+8)/4=3.5. Knowing A=1 leaves outputs 4 and 8 equally likely, so v({A})=6. Knowing B=1 leaves outputs 2 and 8 equally likely, so v({B})=5. Knowing both gives v({A,B})=8.

    The B-only coalition requires information from both sides of the root, even though the fully observed row takes the right branch.
    Known featuresReachable outputsExpected output
    None0, 2, 4, 83.5
    A=14, 86
    B=12, 85
    A=1 and B=188

    Average both feature orders

    $$\phi_A=\tfrac12[(6-3.5)+(8-5)]=2.75,\qquad \phi_B=\tfrac12[(5-3.5)+(8-6)]=1.75.$$

    Check reconstruction: 3.5+2.75+1.75=8. If you only traversed the observed order A then B, you would assign A the change 2.5 and B the change 2.0. Those numbers sum correctly but are not the Shapley allocation. Additivity is necessary for a valid explanation, but it is not sufficient to identify the method.

    What path fractions represent

    When a split feature is known, follow the branch consistent with the explained row. When it is unknown, integrate over branches according to the chosen missing-feature rule. In a tree-path-dependent method, training cover statistics help determine those branch weights. An interventional method uses a background dataset under its intervention convention. Our equally likely independent example makes these expectations easy to calculate by hand.

    TreeSHAP keeps bookkeeping for paths with features present or absent and combines their weighted contributions. A feature may appear at several splits, so the algorithm must handle repeated occurrences without treating them as separate players. This is why a correct implementation is more involved than summing node-value differences.

    A feature can matter through alternative paths

    The observed prediction uses the right subtree, but v({B}) above averages a B=1 leaf in each subtree. Ignoring the left subtree gives the wrong coalition value. More generally, paths reachable under missing-feature combinations can contribute even when the fully observed row never visits them. Explanations depend on the comparison game, not only on the final leaf.

    For an ensemble whose raw output is a sum of trees plus a base value, add the tree contributions and base value in that output space. A nonlinear link such as sigmoid is applied afterward unless using a separately defined probability-space explainer. Do not average tree explanations when the model sums tree outputs.

    Validate on a tiny tree before scaling

    Enumerate all coalitions for a small model and compare them with the fast explainer under matching background assumptions. Check baseline plus contributions against the declared model output. Test repeated split features, constant features, missing branches, and correlated backgrounds. A reconstruction check alone will not catch an incorrect allocation that still sums to the prediction.

    Then use the production explanation pipeline to version backgrounds, batch computations, preserve evidence, and display contributions in meaningful units. Small exact examples provide an anchor when a large model’s explanation is too complex to inspect directly.

    Check your understanding: The observed path gives contributions 2.5 and 2.0 that add correctly. Are they necessarily SHAP values?

    No. For this tree the Shapley values are 2.75 and 1.75 after averaging both feature orders. Correct summation alone does not establish the attribution rule.
