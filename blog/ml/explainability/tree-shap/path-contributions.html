    Tree SHAP Path Contributions

    September 2026 · 5 min read

    We will explain a prediction of 8 using a tree with just two features. The calculation has two steps: find the prediction when only some features are revealed, then average how much each feature adds.

    Start with four possible outcomes

    Features A and B each take value 0 or 1. The tree first tests A, then B. Explain the row A=1, B=1. As our background, use all four input combinations equally often; A and B are independent in this example.

    “Hide A” means average over its background values while retaining any revealed value of B. It does not mean replace A with zero or send the row down the tree’s missing-value branch.

    What we knowOutputs to averageExpected prediction
    Neither feature0, 2, 4, 83.5
    A=1 only4, 86
    B=1 only2, 85
    Both88

    The first row is the baseline: the expected prediction before revealing this row’s features. A set of revealed features is often called a coalition; its expected prediction is written $v(S)$, where $S$ is that set.

    Reveal the features in both orders

    If we reveal A first, the prediction rises from 3.5 to 6: A adds 2.5. Revealing B then raises it from 6 to 8: B adds 2. Now reverse the order:

    Reveal orderA’s increaseB’s increase
    A, then B6 − 3.5 = 2.58 − 6 = 2
    B, then A8 − 5 = 35 − 3.5 = 1.5

    SHAP gives both reveal orders equal weight. Write $\phi_A$ and $\phi_B$ for the resulting feature contributions. Their averages are:

    $$\phi_A=\frac{2.5+3}{2}=2.75,\qquad \phi_B=\frac{2+1.5}{2}=1.75.$$

    They reconstruct the prediction: 3.5 + 2.75 + 1.75 = 8. Merely following the observed order A then B gives 2.5 and 2; those also add correctly, but use only one ordering.

    Where branch weights enter

    Our example used equal weights. With a different background, hidden features may send more weight to one branch than the other. Tree-path-dependent explanations use stored training cover statistics; interventional explanations use an explicit background dataset. The background chapter explains that choice.

    A hidden feature can reopen another branch

    When only B=1 is revealed, A is still unknown. We must average the output 2 on the left with output 8 on the right. Looking only at the observed right-hand path would miss half this calculation.

    TreeSHAP reuses these branch calculations across feature sets. It also handles a feature tested more than once along a path: repeated splits still belong to one feature, not several separate contributors. The original algorithm supplies that bookkeeping.

    Use this example to check an implementation

    On this tree and background, verify both contributions, not just their sum. A result of (2.5, 2) would pass reconstruction but fail the Shapley calculation. Keep the model output and background fixed when comparing implementations.
