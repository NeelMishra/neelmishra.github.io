    Tree SHAP: Row-Level Explanations for Tree Models

    September 2026 · 4 min read

    A tree tells us which leaf produced a prediction. SHAP asks a further question: how should we share the difference between this prediction and a reference prediction among the features? TreeSHAP calculates that allocation efficiently for supported tree models.

    Explain one row first

    Imagine a small regression tree whose average prediction over a reference population is 3.5. For one row, it predicts 8. A SHAP explanation allocates the increase of 4.5 across that row’s features.

    The reference average is the baseline. Each feature gets a signed contribution: positive pushes the explained output above the baseline; negative pushes it below. Together they obey:

    Prediction = baseline + feature contributions

    For the tree below: 8 = 3.5 + 2.75 + 1.75.

    ▶ From a background average to one prediction

    Explain A=1, B=1 in the two-feature tree below. All four input combinations are equally common in this example. At each split, 0 goes left and 1 goes right. The contributions average both feature reveal orders.

    These contributions are measured in the same units as the explained output. They are not the size of a split or the effect of changing one feature in the real world. The worked chapter derives 2.75 and 1.75 by revealing the features in both possible orders.

    What the tree structure saves

    A general SHAP calculation may repeatedly evaluate many sets of known features. TreeSHAP reuses calculations within the tree structure, including branches that become possible when features are hidden. Following the fully observed prediction path alone does not do that averaging.

    The TreeSHAP paper develops this efficient computation. Exactness depends on the output and missing-feature rule being explained; we introduce those choices after the small example.
