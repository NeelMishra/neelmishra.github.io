    Machine Learning Explainability

    October 2026 · Reading guide · 12 min read

    A prediction gives us a single number, log-odds margin, or class label. An explanation tells us how the fitted function $f$ transformed its inputs to reach that number. Most disagreements about “feature importance” happen before any code runs because people ask one word—why?—to answer three mathematically distinct questions.

    Three Questions You Must Never Conflate

    Let $x = (x_1, \dots, x_p)$ denote an input row with $p$ features, $f(x)$ the fitted model’s output, $Y$ the real-world outcome, and $\mathcal{L}(Y, f(X))$ an evaluation loss on held-out data. Before choosing an algorithm, separate what changes and where:

    1 · Global Behavior

    How does $f$ rely on feature $j$ overall?

    Summarizes sensitivity or predictive contribution across an entire dataset—for example, standardized slope $\beta_j$, mean absolute attribution $\frac{1}{n}\sum_{i=1}^n |\phi_{i,j}|$, or the jump in held-out loss $\mathcal{L}$ when column $j$ is permuted.

    2 · Local Attribution

    Why did row $x$ score $f(x)$ instead of $\phi_0$?

    Explains a single customer, claim, or alert relative to a declared baseline expectation $\phi_0 = \mathbb{E}[f(X)]$, partitioning the shift $f(x) - \phi_0 = \sum_{j=1}^p \phi_j$ or fitting a local tangent plane around $x$.

    3 · Causal Intervention

    What happens to $Y$ if we change $X_j$ in reality?

    Asks for the interventional expectation $\mathbb{E}[Y \mid \operatorname{do}(X_j = x_j')]$. Observational model explanations audit the function $f(x)$, not the causal graph of the external world.

    A concrete mental check keeps these three apart. Suppose a credit-risk classifier uses recent_credit_inquiries alongside debt_to_income. Globally, debt_to_income may drive 70% of validation log-loss reduction while recent_credit_inquiries drives 10% (global behavior). Locally, for one applicant with flawless income but eight inquiries this week, recent_credit_inquiries may supply $+1.4$ of their $+1.5$ log-odds jump above baseline (local attribution). Yet advising that applicant to “stop checking loan rates” does not erase the underlying cash-flow emergency that prompted those inquiries (causal intervention). Post-hoc explainers audit $f$; causal claims require experimental or structural assumptions beyond $f$.

    Which Explainer Answers Your Question?

    Start from the decision you need to support rather than from a plotting library. Follow the flowchart below to match your model family, baseline contract, and runtime budget to the right tool.

    Side-by-Side Comparison of Core Explainability Methods

    Let $p$ denote the number of features, $N_{\text{ref}}$ the background sample size, $M$ the number of sampled coalitions or perturbations per explained row, and $(T, L, D)$ the tree count, leaf count, and maximum depth of a tree ensemble. For an explained row $x$, efficiency (local accuracy) means the baseline $\phi_0$ and feature attributions $\phi_1, \dots, \phi_p$ reconstruct the exact model output: $\phi_0 + \sum_{j=1}^p \phi_j = f(x)$.

    Production Checklist & Implementation Links

    Never ship bare attribution numbers without their contract: Always log (1) the exact model artifact version, (2) the explained output scale (raw dollars, log-odds margin, class probability, or isolation path length), (3) the background dataset version and perturbation rule, (4) the baseline value $\phi_0$, and (5) an additivity assertion $|\phi_0 + \sum_j \phi_j - f(x)| < \varepsilon$.
