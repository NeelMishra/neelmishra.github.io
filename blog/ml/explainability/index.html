    Machine Learning Explainability

    September 2026 · 3 min read

    Explainability helps inspect a trained model: why one output is high, which inputs influence its predictions, or which features support its held-out performance. Start by choosing one of those questions.

    Choose an explainer

    Compare local explanations, global SHAP summaries, and held-out permutation importance.

    Separate one-row explanations from dataset summaries

    A local explanation describes one row. A global summary describes behavior across a named dataset. For example, a SHAP waterfall connects the baseline to one prediction; a global bar chart summarizes contribution magnitudes across many rows.

    A large contribution does not mean a feature improves prediction accuracy. To study performance reliance, permutation importance measures how a chosen evaluation metric changes after shuffling a feature. Its interpretation also depends on the dataset and correlations; see the official guide.

    Model explanations can expose a spurious shortcut faithfully. They do not, by themselves, show that a feature causes the real outcome.

    Connect the notes to implementation

    The C++ companions implement small examples of permutation importance, LIME, and Kernel SHAP. Start with a case whose prediction and reference values you can check manually.

    Keep explanations readable in production

    The production explanation notes cover versioned backgrounds, output units, reconstruction checks, and concise displays. For anomaly detection, the review-queue chapter connects contributions to inspectable evidence.
