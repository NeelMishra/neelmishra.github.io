    From Neighborhood Evidence to a Risk Score

    September 2026 · 4 min read

    Before you start: Typed graph construction.

    Suppose application A has an intrinsic risk score of 0.20. Three neighbors have scores 0.90, 0.60, and 0.10, connected with weights 2, 1, and 1. A neighborhood average is (2×0.90+0.60+0.10)/4=0.625. That is a useful feature. It is not yet a calibrated probability that A is malicious.

    A prior makes the denominator visible

    $$z_a=\frac{\sum_{b\in N(a)}w_{ab}s_b+\lambda\mu}{\sum_{b\in N(a)}w_{ab}+\lambda}.$$

    Here s is a neighbor score or trusted binary label, w is a nonnegative edge weight, μ is a baseline risk level, and λ is prior strength measured in the same units as total weight. With μ=0.2 and λ=2, A’s feature becomes 2.9/6≈0.4833. With no neighbors it becomes μ, rather than dividing by zero. Also provide the model with total weight or degree so it can distinguish a prior-only value from strong agreeing evidence.

    Smoothing does not fix a biased neighborhood. Ten copies of the same evidence should not count like ten independent observations. Deduplicate sources and consider whether several neighbors belong to one publisher or one incident. Bootstrap or evaluate at the appropriate group level when assessing uncertainty.

    Use graph features in a supervised model

    A simple model consumes both intrinsic features $x_a$ and graph features $z_a$: $p_a=\sigma(f_\theta([x_a,z_a]))$ for a binary logit model. A boosted-tree classifier can learn interactions such as “high neighborhood risk matters more when the app is newly created.” Start with the intrinsic-only baseline, add graph features, and measure the incremental gain on the same held-out decisions.

    If neighboring base-model predictions supply s, generate training-time predictions out of fold where needed. Otherwise graph features can contain an overfit model’s knowledge of training labels. When using known neighbor labels, never include the target’s own label in its feature computation, directly or through a propagation loop. Label availability must match deployment time.

    Propagation repeats an update across the graph

    $$s^{(t+1)}=\alpha P s^{(t)}+(1-\alpha)y,\qquad 0\le\alpha<1.$$

    P is a row-normalized nonnegative adjacency operator and y is a fixed initial signal. Under a suitable norm, multiplication by αP contracts differences, so this restart iteration has a stable fixed point. That mathematical convergence does not prove that its scores are accurate. It only says the chosen computation settles. Specify how isolated nodes are handled, such as a self-loop or a prior-valued row.

    Unclamped propagation lets signals move repeatedly; clamped label propagation restores trusted seed labels after updates. They are different algorithms. High α spreads information farther and can blur boundaries. If a generic shared domain connects unrelated populations, more iterations can amplify the modeling mistake. Evaluate hop count and relation type rather than assuming deeper propagation is better.

    Where a graph neural network changes the story

    A message-passing layer learns how to aggregate: $h_a^{(\ell+1)}=\sigma(W_\ell[h_a^{(\ell)}\,\Vert\,\operatorname{AGG}\{h_b^{(\ell)}:b\in N(a)\}])$. The concatenation keeps self-information separate from neighbor information. Relation-specific transformations can preserve edge meaning. GraphSAGE learns an aggregation function that can be applied to new nodes with features, rather than relying only on a table of node IDs.

    A GNN adds training, sampling, serving, and explanation complexity. A graph feature plus LightGBM baseline is valuable because it tells you whether the relationships help before introducing that complexity. Compare at matched data availability and resource budgets. A neural architecture should earn its cost through held-out gains or capabilities the simpler baseline lacks.

    Explain the source of a score change

    Keep an evidence record: which relation contributed, which neighbor snapshot was used, how much weight it carried, and whether the evidence came from a label or a model prediction. A feature attribution can say that neighborhood risk increased the score; the evidence record lets a reviewer inspect the underlying relationship. These answer different questions and should be shown together.

    Check your understanding: If propagation converges, have we proved that the risk scores are correct?

    No. Convergence concerns the iteration. Predictive correctness depends on labels, relationships, leakage controls, and evaluation under deployment conditions.
