    Isolation Forest

    September 2026 · 3 min read

    Isolation Forest can help identify rows worth inspecting during data preparation. It does not tell you, by itself, which rows should be deleted. A rare but valid customer, a measurement error, and an interesting event can all receive unusual scores.

    Use the score to find candidates

    The method repeatedly cuts randomly chosen features. A point far from the others can often be separated in few cuts; crowded points usually take longer. The main Isolation Forest chapter explains the algorithm and score with [1, 2, 3, 4, 20].

    Match treatment to the actual problem

    FindingPossible response
    Confirmed unit or parsing errorCorrect it from the original record when possible.
    Valid rare observationRetain it and check whether the predictive model handles it well.
    Outside the intended populationDefine and document the exclusion rule.
    Cause unknownKeep the evidence and avoid treating the score as a confirmed error.

    Keep evaluation independent of the filtering decision

    Split the data before fitting learned preprocessing and the detector. If filtering training rows, evaluate the resulting predictive model on a held-out set representative of deployment. Removing difficult test rows because they score unusually can make performance look better without improving the model.

    Compare the original training set with the proposed treatment on the same evaluation workload. Record which rows were changed and why. For rate features and sparse observations, the telemetry notes explain why large counts and missing data need context.
