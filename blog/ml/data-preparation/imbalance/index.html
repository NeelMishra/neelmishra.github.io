    Class Imbalance and Resampling

    September 2026 · 9 min read

    This series teaches how to train and evaluate a classifier when one class is rare. Begin with the decisions the model must support, then compare ways to change its training data, loss or decision threshold. Each chapter follows one small example far enough to explain what the method actually does.

    Unequal class counts alone do not tell you which method will help. A 1% class could contain ten labeled examples or ten thousand; those datasets provide very different amounts of evidence. Label quality, class overlap and the cost of mistakes also matter.

    Useful background: training, validation and test splits and fitted preprocessing pipelines. The first chapter introduces the confusion counts, so you can start here without memorizing a set of metrics.

    Choose what a useful improvement looks like

    Suppose a quality-control team uses model scores to select items for inspection. Missing a defect matters, but so does spending the inspection budget on sound items. “Higher accuracy” does not specify how to trade those outcomes. A concrete goal might be to find as many defects as possible within a fixed inspection capacity.

    Write down the positive class, the decision being made and the population being served. Then choose the evidence needed for that decision:

    A model that catches more positives may also create more false alerts. Report both counts, plus the number of actual positives evaluated. With few positives, one additional miss can change the reported recall substantially. The evaluation chapter explains the metrics and shows why changing the positive-class frequency changes precision.

    Locate the part of the system you are changing

    All six interventions below are candidates to evaluate. They act at different places, so a result such as “we balanced the data” is too vague to describe an experiment.

    Keep the original validation population fixed while comparing these choices.
    InterventionWhat changes?What to inspect
    Random oversamplingRepeat selected training rows from the class being expanded.Repeated identities add exposure, not new independent observations.
    Random undersamplingFit on a random subset of the class being reduced.Which regions and informative examples were excluded?
    SMOTEAdd feature vectors between selected same-class neighbors.Are those distances and interpolated feature combinations meaningful?
    ADASYNAllocate more synthetic rows to seeds with more opposite-class neighbors.Does the allocation emphasize a useful boundary or questionable seeds?
    Class weightsMultiply per-example losses according to their class.How do relative penalties and fitted probabilities change?
    Threshold movingChange the score cutoff used to choose an action.Does the resulting tradeoff meet the task’s cost or capacity constraint?

    These choices can interact. Repeating minority rows and also increasing their loss weight compounds their influence. Moving a threshold leaves the fitted scores unchanged. Separating those effects makes a comparison easier to interpret; introduce combinations only after you understand the individual changes.

    Choose a reading route

    Read the first two chapters to establish the task and evaluation. Then follow the training method you want to understand. The sampling chapters progress from copying rows, to selecting rows, to constructing new feature vectors; ADASYN builds on SMOTE’s interpolation explanation.

    Choose minority parents and move a synthetic point between them. Inspect a constraint that valid endpoints satisfy but their midpoint violates.

    Use all-class neighbors to allocate a budget, then minority-only neighbors to generate rows. Explore what happens when quotas require rounding.

    Follow weighted losses into a fitted prediction. Distinguish balancing aggregate class contributions from choosing the costs appropriate to a task.

    Sweep a fixed validation score list, handle tied scores together and select a rule against an explicit objective. Learn when probability-based cost thresholds apply.

    The main explanations provide the mechanism and its assumptions. Expand the code and derivation sections when you want to reproduce a result; they are optional on a first pass.

    Build a comparison whose result you can trust

    Start with a classifier trained on the original data. Give it a validation-selected operating rule, then compare a small set of justified interventions using the same splits and decision objective. This lets you distinguish the benefit of retraining from the benefit of changing the cutoff.

    Stratification can help maintain class representation across ordinary random splits. It cannot make observations from the same entity independent or turn a random split into a forecast test; use group splits or time-based splits when the deployment question requires them.

    Keep a compact experiment record: original class counts, split design, preprocessing, sampling target or class weights, random seed, validation objective and final decision rule. For synthetic methods, record the actual generated counts too. Those details let another reader reconstruct the comparison and understand what the result supports.
