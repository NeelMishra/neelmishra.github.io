    XGBoost — Architecture, Regularized Split Gain & StatQuest Notes

    September 2026 · 12 min read · Chen & Guestrin (2016) guide + five worked notes

    Why did Tianqi Chen and Carlos Guestrin's 2016 paper (XGBoost: A Scalable Tree Boosting System) dominate structured-data machine learning? Classical Gradient Boosting chooses splits using only first-order pseudo-residuals $r_{im}$, applies regularization mostly after the fact via ad-hoc heuristics, and re-sorts dense feature arrays repeatedly. XGBoost fuses two ideas from start to finish: (1) a second-order regularized tree objective that yields closed-form Newton leaf weights and split gains for any twice-differentiable loss, and (2) co-designed data structures—weighted quantile sketches, sparsity-aware default branches, and cache-aligned compressed column blocks—that turn split search into fast streaming scans.

    1. Second-Order Taylor Expansion + Explicit Tree Complexity $\Omega(f_t)$

    At boosting round $t$, let $\hat y_i^{(t-1)}$ denote the existing ensemble prediction for row $i$, and let $f_t(x)$ be the candidate CART tree we want to add so $\hat y_i^{(t)} = \hat y_i^{(t-1)} + f_t(x_i)$. Represent tree $f_t$ by a structure mapping $q: \mathbb R^p \to \{1, \dots, T\}$ that routes each input into one of $T$ leaves, together with a leaf-weight vector $w = (w_1, \dots, w_T)^\top \in \mathbb R^T$. XGBoost minimizes a penalized objective:

    $$\mathcal L^{(t)} = \sum_{i=1}^{n} l\bigl(y_i,\, \hat y_i^{(t-1)} + f_t(x_i)\bigr) + \Omega(f_t), \qquad \Omega(f_t) = \gamma T + \frac{1}{2}\lambda \sum_{j=1}^{T} w_j^2.$$

    Define every symbol right beside its role:

    • $g_i = \partial_{\hat y^{(t-1)}} l\bigl(y_i, \hat y_i^{(t-1)}\bigr)$: first-order gradient of row $i$'s loss (for half squared error, $g_i = \hat y_i^{(t-1)} - y_i$; for binary log-loss, $g_i = p_i - y_i$).
    • $h_i = \partial^2_{\hat y^{(t-1)}} l\bigl(y_i, \hat y_i^{(t-1)}\bigr) \ge 0$: second-order Hessian / local curvature of row $i$'s loss (for half squared error, $h_i = 1$; for binary log-loss, $h_i = p_i(1 - p_i)$, called cover).
    • $T$: number of terminal leaves in tree $f_t$; $\gamma \ge 0$: minimum objective reduction required to justify adding one extra leaf.
    • $\lambda \ge 0$: $L_2$ ridge penalty shrinking leaf weights $w_j$ smoothly toward zero (especially when a leaf has tiny cover $H_j$).

    Expanding $l\bigl(y_i, \hat y_i^{(t-1)} + f_t(x_i)\bigr)$ to second order around $\hat y_i^{(t-1)}$, dropping the constant $l\bigl(y_i, \hat y_i^{(t-1)}\bigr)$, and grouping rows by leaf $I_j = \{i : q(x_i) = j\}$ with summed statistics $G_j = \sum_{i \in I_j} g_i$ and $H_j = \sum_{i \in I_j} h_i$ decouples the tree into $T$ independent 1D parabolas:

    $$\tilde{\mathcal L}^{(t)} = \sum_{j=1}^{T} \left[ G_j w_j + \frac{1}{2}(H_j + \lambda) w_j^2 \right] + \gamma T.$$

    2. Closed-Form Optimal Leaf Weight $w_j^*$ and Exact Split Gain

    Setting $\frac{\partial \tilde{\mathcal L}^{(t)}}{\partial w_j} = G_j + (H_j + \lambda)w_j = 0$ immediately gives the regularized Newton-Raphson leaf output and the resulting optimal objective:

    $$w_j^* = -\frac{G_j}{H_j + \lambda}, \qquad \tilde{\mathcal L}^{(t)*}(q) = -\frac{1}{2}\sum_{j=1}^{T} \underbrace{\frac{G_j^2}{H_j + \lambda}}_{\text{Similarity Score}} + \gamma T.$$

    Look at how StatQuest's vocabulary maps directly onto Chen & Guestrin's formula: $\frac{G_j^2}{H_j + \lambda}$ is the leaf's Similarity Score! When gradients inside a leaf have mixed signs ($+0.5$ and $-0.5$), they cancel inside $G_j^2$, producing a tiny similarity score; when a split separates positive gradients left ($G_L$) and negative gradients right ($G_R$), $G_L^2$ and $G_R^2$ jump upward. Subtracting the parent objective from the child objectives yields the exact Split Gain:

    $$\mathcal L_{\text{split}} = \frac{1}{2}\left[ \frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda} \right] - \gamma.$$

    If $\mathcal L_{\text{split}} < 0$, adding the extra leaf costs more in complexity $\gamma$ than it saves in quadratic loss—pruning happens automatically!

    4. Three System Optimizations Behind XGBoost's Speed

    1. $h_i$-Weighted Quantile Sketch: On millions of rows, testing every distinct threshold is unnecessary, yet ordinary unweighted quantiles place too few cuts where the loss curves sharply. Completing the square on $\sum_i [g_i f_t(x_i) + \frac{1}{2} h_i f_t(x_i)^2]$ gives $\sum_{i=1}^n \frac{1}{2} h_i \bigl(f_t(x_i) - (-g_i / h_i)\bigr)^2 + \text{const}$: each row's second derivative $h_i$ acts as an exact instance precision weight! XGBoost's distributed weighted quantile sketch places candidate cuts so equal sums of $h_i$ fall into each bucket.
    2. Sparsity-Aware Split Finding (Learned Default Directions): Real tabular matrices are full of NaNs, zeros, and one-hot indicators. At each split on feature $k$, XGBoost visits only the present entries $I_k$, accumulating $(G, H)$ once while testing both routing policies—all missing rows sent left vs. all missing rows sent right—and stores the higher-gain direction as that node's learned default path.
    3. Cache-Aware Compressed Column (CSC) Blocks: Instead of re-sorting features at every node ($O(n\log n)$ per depth), XGBoost pre-sorts each feature once before training into compressed column blocks in memory. Split finding across an entire depth level becomes a single linear pass with software prefetching into CPU L1/L2 cache to hide random $(g_i, h_i)$ gather latency, plus block compression and sharding when data spills out of RAM.
    Verify all 4-row split gains and Newton leaf weights in Python 
    import numpy as np

y = np.array([0.0, 0.0, 1.0, 1.0])
p = np.array([0.4, 0.5, 0.5, 0.8])
g = p - y             # [+0.4, +0.5, -0.5, -0.2]
h = p * (1.0 - p)     # [0.24, 0.25, 0.25, 0.16]
lam, gam = 1.0, 0.10

sim_root = (g.sum() ** 2) / (h.sum() + lam)
for k, cut in [(1, 1.5), (2, 2.5), (3, 3.5)]:
    GL, HL = g[:k].sum(), h[:k].sum()
    GR, HR = g[k:].sum(), h[k:].sum()
    sim_L, sim_R = GL**2 / (HL + lam), GR**2 / (HR + lam)
    gain = 0.5 * (sim_L + sim_R - sim_root) - gam
    wL, wR = -GL / (HL + lam), -GR / (HR + lam)
    print(f"x < {cut}: wL*={wL:+.4f}, wR*={wR:+.4f}, Gain={gain:+.6f}")
