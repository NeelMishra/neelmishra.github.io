    AdaBoost: Weights, Votes & the Proof

    September 2026 · 12 min read

    AdaBoost changes the importance of training examples and combines the resulting classifiers with weighted votes. This chapter uses binary discrete AdaBoost: every label and learner prediction is −1 or +1.

    The two kinds of weight do different jobs. Example weights tell the next learner which mistakes cost the most. Learner votes tell the final ensemble which classifiers have more influence. Follow five rows through two rounds to keep those roles separate.

    Separate example weights from learner votes

    At round $t$, $D_t(i)$ is the training importance of row $i$. These nonnegative weights sum to 1; initially, each of the $n$ rows gets $1/n$. Fitting $h_t$ with these weights makes high-weight rows contribute more to its training objective. For a stump, the weights affect split selection and the majority label in each leaf. See how a tree uses these weights.

    After fitting, compare $h_t(x_i)$ with the true label $y_i$. Add the weights of just the rows it misclassifies to obtain its weighted error:

    $$\epsilon_t=\sum_{i:\,h_t(x_i)\ne y_i}D_t(i).$$

    There is no further division by $n$: the weights already total 1. With equal weights, this equals the fraction of rows missed. After reweighting, a few high-weight mistakes can cost more than many low-weight mistakes. The correctly classified rows carry the remaining weight, $1-\epsilon_t$.

    Now choose how strongly this classifier should influence the ensemble. Its vote strength $\alpha_t$ multiplies its prediction: it contributes $+\alpha_t$ when it predicts +1 and $-\alpha_t$ when it predicts −1. The ensemble adds these contributions and takes their sign. Unlike the row weights, learner votes do not need to sum to 1.

    For $0<\epsilon_t<0.5$, binary AdaBoost chooses:

    $$\alpha_t=\frac12\ln\frac{1-\epsilon_t}{\epsilon_t}.$$

    The ratio compares correctly classified weight to misclassified weight. Below 0.5 error, the numerator is larger, so its natural logarithm is positive. Lower error gives a larger ratio and a stronger vote. As error approaches 0.5, the ratio approaches 1 and the vote approaches zero: correct and incorrect weight nearly balance.

    Derive the vote from exponential loss

    Hold the newly fitted classifier $h_t$ fixed. The question is: which vote makes the ensemble’s loss smallest? Write $F_{t-1}(x)$ for its current combined score. Adding the new classifier changes that score to $F_{t-1}(x)+\alpha h_t(x)$. Here $\alpha$ is a trial vote; $\alpha_t$ will be the value we choose.

    1. Write the loss as a function of the vote

    For labels $y_i\in\{-1,+1\}$, the signed score $y_iF(x_i)$ is positive when the prediction is correct and negative when it is wrong. AdaBoost uses exponential loss, $e^{-y_iF(x_i)}$: a more negative signed score gets a larger penalty, while a more positive one gets a smaller penalty.

    Why are the initial losses equal to 1? Before any learners have been added, the ensemble has no votes, so its score is $F_0(x)=0$ for every input. Each row therefore has loss $e^{-y_i\cdot0}=e^0=1$, for either label. With $n$ rows, the total loss is $n$. Normalizing each row’s loss gives $D_1(i)=1/n$. Later rounds can have unequal losses and weights.

    How does one row’s loss change? At any round $t$, call row $i$’s old loss $\ell_i^{\mathrm{old}}=e^{-y_iF_{t-1}(x_i)}$. Replace its old score by $F_{t-1}(x_i)+\alpha h_t(x_i)$ in the loss formula:

    $$\begin{aligned} &\ell_i^{\mathrm{new}}(\alpha)\\ &=e^{-y_i[F_{t-1}(x_i)+\alpha h_t(x_i)]}\\ &=e^{-y_iF_{t-1}(x_i)}\,e^{-\alpha y_i h_t(x_i)}\\ &=\ell_i^{\mathrm{old}}\,e^{-\alpha y_i h_t(x_i)}. \end{aligned}$$

    The score changes by addition. Its exponential loss changes by multiplication because $e^{a+b}=e^a e^b$. The first factor is the old loss; the second is the multiplier introduced by this new vote.

    How does this become a weighted sum? Let $L_{\mathrm{old}}$ be the total loss before adding the vote. The training weight $D_t(i)$ is row $i$’s share of that total:

    $$\begin{aligned} L_{\mathrm{old}}&=\sum_j\ell_j^{\mathrm{old}},\\ D_t(i)&=\frac{\ell_i^{\mathrm{old}}}{L_{\mathrm{old}}}. \end{aligned}$$

    Why put the new loss over the old loss? We want to measure how much a proposed vote changes the ensemble’s loss. The numerator is the total loss after adding that vote; the denominator is the total loss before. As we try different values of $\alpha$, the numerator changes, while the old total remains the same positive baseline.

    Our goal is still to minimize the new total loss. Dividing every candidate’s loss by the same fixed number preserves which one is smallest, so it gives the same best $\alpha$. Dividing the new total by itself would always give 1 and tell us nothing about whether the vote helps.

    Using the old total also lets us express the ratio in terms of the current weights $D_t(i)$. Write the new total as a sum of row losses, then move the common denominator inside the sum:

    $$\begin{aligned} Z_t(\alpha) &=\frac{\sum_i\ell_i^{\mathrm{new}}(\alpha)}{L_{\mathrm{old}}}\\ &=\sum_i\frac{\ell_i^{\mathrm{old}}}{L_{\mathrm{old}}}\,e^{-\alpha y_i h_t(x_i)}\\ &=\sum_i D_t(i)e^{-\alpha y_i h_t(x_i)}. \end{aligned}$$

    The fraction in each term is exactly $D_t(i)$. Thus $Z_t(\alpha)$ is a weighted average of the row-loss multipliers: rows contributing more to the old total loss have more influence. A ratio below 1 means the new vote reduced the total loss.

    This loss comparison is separate from normalizing the next round’s row weights. For those weights, divide each new row loss by the new total, so the weights sum to 1.

    2. Group the rows by the new classifier’s mistakes

    • Correct: $y_i h_t(x_i)=+1$. These rows have total weight $1-\epsilon_t$, and their loss multiplier is $e^{-\alpha}$.
    • Incorrect: $y_i h_t(x_i)=-1$. These rows have total weight $\epsilon_t$, and their loss multiplier is $e^{\alpha}$.
    $$\begin{aligned} Z_t(\alpha)&=(1-\epsilon_t)e^{-\alpha}\\ &\quad+\epsilon_t e^\alpha. \end{aligned}$$

    A larger vote reduces the first group’s loss but increases the second group’s loss. We need the value that best balances these effects.

    3. Find the minimizing vote

    Differentiate with respect to $\alpha$ and set the derivative to zero:

    $$\begin{aligned} Z_t'(\alpha)&=-(1-\epsilon_t)e^{-\alpha}\\ &\quad+\epsilon_t e^\alpha=0. \end{aligned}$$

    Move the negative term to the other side, then divide by $\epsilon_t e^{-\alpha}$:

    $$\begin{aligned} \epsilon_t e^\alpha&=(1-\epsilon_t)e^{-\alpha},\\ e^{2\alpha}&=\frac{1-\epsilon_t}{\epsilon_t}. \end{aligned}$$

    The exponent is $2\alpha$ because $e^\alpha/e^{-\alpha}=e^{2\alpha}$. Taking the natural logarithm gives the chosen vote:

    $$\begin{aligned} 2\alpha_t&=\ln\frac{1-\epsilon_t}{\epsilon_t},\\ \alpha_t&=\frac12\ln\frac{1-\epsilon_t}{\epsilon_t}. \end{aligned}$$

    This is a minimum because $Z_t''(\alpha)=Z_t(\alpha)>0$. The logarithm and factor $1/2$ follow from optimizing the exponential loss with ±1 predictions. This derivation uses the standard update without a learning-rate multiplier. See Schapire’s exponential-loss explanation.

    Use the vote to set the next round’s priorities

    Use the chosen vote to update the training priorities: multiply each missed row’s weight by $e^{\alpha_t}$ and each correct row’s by $e^{-\alpha_t}$. Divide all updated weights by their new total so they sum to 1 again. The next learner trains on these revised weights.

    Keep the earlier fitted learners fixed. Only the next learner is trained with the new example weights. A shallow decision tree is one possible base learner; the update does not require a particular kind of classifier.

    Where the first learner comes from

    Use input values $x=[1,2,3,4,5]$ and labels $y=[+1,-1,-1,+1,+1]$. Initially all five rows weigh 0.2. Our weak learner searches the four midpoint thresholds. Each leaf predicts its weighted-majority label, choosing +1 if class weights tie. We also allow constant +1 and −1 classifiers; on equal total error, prefer a constant, then the smaller threshold.

    How do weights affect a tree’s split?

    The feature values determine which rows go left or right for a candidate threshold. To choose a threshold, the tree scores how well each candidate separates the labels. Weights change this score. A row with more weight contributes more to the class totals used in that calculation.

    For a Gini-based tree, each class proportion $p_k$ is its total weight divided by the node’s total weight. Compute Gini from these proportions. Then combine the child impurities $G_L,G_R$ using their total weights $W_L,W_R$, with $W=W_L+W_R$:

    $$\begin{aligned} G&=1-\sum_k p_k^2,\\ \text{split score}&=\frac{W_L}{W}G_L+\frac{W_R}{W}G_R. \end{aligned}$$

    The smallest score gives the largest impurity reduction at that node. At a leaf, predict the class with the largest total weight. These are the weighted counts used by a tree’s sample-weight calculation.

    Work through two rounds

    Start with five rows weighted 0.2 each. The fitted first learner misses only row 1, so its weighted error is $\epsilon_1=0.2$. Substitute this into the vote formula:

    $$\begin{aligned} \alpha_1&=\frac12\ln\frac{1-0.2}{0.2}\\ &=\frac12\ln4\\ &=\ln2\approx0.693. \end{aligned}$$

    Why multiply the weights by 2 and 0.5? The update uses $e^{\alpha_1}$ for a missed row and $e^{-\alpha_1}$ for a correct row. Exponentiation with base $e$ undoes the natural logarithm:

    $$\begin{aligned} e^{\alpha_1}&=e^{\ln2}=2,\\ e^{-\alpha_1}&=\frac{1}{e^{\alpha_1}}=\frac12=0.5. \end{aligned}$$

    Before normalization, the missed row weighs $0.2\times2=0.4$, and each of the four correct rows weighs $0.2\times0.5=0.1$. Their total is $0.4+4(0.1)=0.8$. Divide every weight by 0.8 to make the total 1 again.

    Row 1 now has weight $0.2\times2/0.8=0.5$; each other row has $0.2\times0.5/0.8=0.125$. Missing row 1 alone now costs as much as missing the other four rows together. This gives the next learner a reason to choose a different rule.

    On the updated weights, the best candidate error is 0.25. The constant +1 rule and the threshold candidates attain that value; our tie rule selects the constant +1 learner, which misses rows 2 and 3. They each weigh 0.125, so its weighted error is 0.25 even though it misses two of five rows. Its vote is $\alpha_2=\tfrac12\ln3\approx0.549$.

    Round 2 multiplies its missed rows by $\sqrt3$ and correct rows by $1/\sqrt3$, then renormalizes. Every column sums to 1. These are training weights, not relabelings or new observations.

    For example, the second normalization constant is $0.25\sqrt3+0.75/\sqrt3=\sqrt3/2$. Row 2 becomes $(\tfrac18\sqrt3)/(\sqrt3/2)=1/4$, while row 1 becomes $(\tfrac12/\sqrt3)/(\sqrt3/2)=1/3$. The newest learner’s two missed rows now carry half the total weight between them.

    Check your understanding: could round 2 simply reuse learner 1?

    Learner 1 still misses only row 1, which now carries weight 0.5. Its new weighted error would therefore be 0.5, giving vote $\tfrac12\ln(0.5/0.5)=0$. Repeating it would make no progress. Its original vote remains 0.693; earlier votes are not recomputed using later weights.

    A correct new prediction need not fix the ensemble immediately

    At prediction time, add each learner’s vote times its ±1 output, then use the sign of the total. Example weights $D_t(i)$ are training quantities; they are not needed to predict a new row.

    Suppose row 1’s true label is +1. Learner 1 predicts −1 and learner 2 predicts +1, as required by our error pattern. The combined score is $0.693(-1)+0.549(+1)=-0.144$, so the ensemble still predicts −1. The first learner has the larger vote.

    Yet row 1’s weight fell from 0.5 to 1/3. There is no contradiction: the latest learner got it right, so this round reduced its relative weight and moved its score toward the correct side. The update is based on the new learner’s prediction. It does not promise that every reweighted row changes its ensemble label immediately.

    A stump’s error is not the ensemble’s error

    At round 3, the stump misses rows 5, 6, 13, and 16. Each enters with weight 0.025, so its weighted error is 0.10, even though it misses 4 of 16 rows: an unweighted error of 25%. Meanwhile, the combined classifier has zero training errors. These quantities answer different questions.

    Follow row 5, at (2, 6), whose true class is B / −1. The third stump predicts A because x₂ = 6 exceeds 4. Its weight therefore rises from 0.025 to 0.125. But the first two stumps both predicted B for this row, and their votes still win:

    $$F_3(x_5)=-0.549-0.805+1.099\approx-0.255.$$

    The combined score is negative, so the ensemble correctly predicts B. Reweighting responds to the new stump’s mistake even though the accumulated classifier gets this row right. The update can continue improving margins after training accuracy reaches 100%; validation performance determines whether more rounds help on new data.

    Why zero classification error need not end learning

    The signed margin is $y_iF(x_i)$. Once it is positive, the label is correct, but increasing it still reduces exponential loss. This explains why more rounds can change the model after it has classified every training row correctly.

    What does the training-error guarantee assume?

    Let $Z_t=2\sqrt{\epsilon_t(1-\epsilon_t)}$ be the optimized loss ratio for round $t$, and let $\gamma_t=1/2-\epsilon_t$ be its advantage over chance. Starting with equal weights, the fraction of training mistakes, counting ties as errors, obeys

    $$\text{training error}\leq\prod_t Z_t\leq\exp\!\left(-2\sum_t\gamma_t^2\right).$$

    The first inequality holds because a wrong or tied prediction has exponential loss at least 1. The second uses $Z_t=\sqrt{1-4\gamma_t^2}$ and $\ln(1-u)\leq-u$. A fixed lower bound $\gamma_t\geq\gamma>0$ gives exponential decay in the number of rounds. Merely being below 50% by an ever-shrinking amount does not give that uniform rate. This bounds training error, not test error.

    Carry the right state between rounds

    D = [1/n] * n
learners = []
for t in range(max_rounds):
    h = fit_weighted_classifier(X, y, D)
    error = sum(D[i] for i in rows if h(X[i]) != y[i])
    if error == 0: handle_perfect_learner_and_stop(h)
    if error >= 0.5: stop_or_retry_with_another_learner()
    alpha = 0.5 * log((1 - error) / error)
    D = normalize(D[i] * exp(-alpha * y[i] * h(X[i])) for i in rows)
    learners.append((alpha, h))
# Prediction needs the fitted learners, not the training-row weights.
score(x) = sum(alpha * h(x) for alpha, h in learners)

    The two edge-case handlers above must end or skip the iteration; they are not ordinary functions that return and let the invalid logarithm run. For a perfect weak learner, one finite policy is to give it a vote greater than the sum of previous absolute votes and stop, making its sign dominate the ensemble. Another explicit policy is to return that perfect learner. State the policy rather than silently evaluating log(0).

    For long runs, keep log weights and normalize by subtracting a log-sum-exp to reduce numerical underflow. If you introduce vote shrinkage, apply it consistently in both the score and the example-weight update, and remember that the exact unshrunk line-search proof no longer describes that smaller step.

    Handle the cases the formula excludes

    • Perfect learner: error zero would require an infinite vote. Handle it explicitly and stop.
    • Error 0.5: the vote is zero, so this round makes no progress.
    • Error above 0.5: reject or refit the learner; flipping every binary prediction is another option.
    • Noisy labels: repeated mistakes can accumulate excessive weight. Validate the number of rounds and learner capacity.

    A combined score is not automatically a calibrated probability. For corrections under other losses, continue to gradient boosting.
