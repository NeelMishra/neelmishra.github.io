    Decision Tree Threshold Search & Edge Cases

    September 2026 · 5 min read

    Training chooses a threshold by comparing the groups it creates. The useful question is “which rows change sides?” Once that is clear, a huge feature range and repeated values become straightforward to handle.

    Try one boundary per observed gap

    Suppose the sorted feature values are [2, 2, 5, 11, 1000000000]. Use the rule x < threshold to send a row left. These three thresholds produce all possible nonempty partitions:

    ThresholdLeft valuesRight values
    3.52, 25, 11, 1000000000
    82, 2, 511, 1000000000
    500000005.52, 2, 5, 111000000000

    Between 5 and 11, any threshold greater than 5 and at most 11 gives the same training partition. A midpoint is a convenient representative. Its precise position can still affect predictions for future rows inside that gap.

    ▶ Sorted Sweep over Observed Values Only

    The feature range is huge, but only adjacent observed gaps create different partitions. Duplicate values are moved together before a candidate threshold is scored.

    Move rows once instead of rebuilding each child

    Start with every row on the right. Move equal-valued groups to the left in sorted order, updating the two children’s label counts. Score the boundary only when both children satisfy the leaf-size limit.

    sort rows by this feature
left = empty; right = all rows
for each group of equal values:
    move the group from right to left
    if right is empty: stop
    if either child is too small: continue
    score the weighted child impurity
    keep the best boundary seen so far

    Repeat for each feature. The impurity chapter supplies the score; the number of candidates depends on distinct observed values, not the size of the numeric range.

    Equal values must stay together

    The two rows with value 2 cannot be separated by a threshold on this feature, even if their labels differ. Another feature might distinguish them. If their entire feature vectors are identical, feature tests cannot resolve conflicting labels.

    Make the stored threshold match the scored partition

    For finite adjacent distinct values low < high, our strict < rule needs low < threshold <= high. Floating-point arithmetic can round a midpoint to an endpoint. Also, both (low + high) / 2 and low + (high - low) / 2 can overflow on some finite inputs.

    In C++20, std::midpoint from <numeric> avoids arithmetic overflow. Guard against rounding to the lower endpoint:

    double threshold = std::midpoint(low, high);
if (!(threshold > low)) threshold = high;

    This keeps the training partition correct for the stated comparison rule. An implementation using <= needs the corresponding opposite endpoint convention.

    Decide these behaviors explicitly

    SituationBehavior
    All values equalSkip this feature at this node.
    Missing or non-finite valuesReject unsupported inputs, preprocess them, or implement an explicit routing rule.
    Child below the minimum sizeReject that candidate before choosing the best split.
    No acceptable gainReturn a leaf; choose any numerical tolerance consistently.
    Category IDs stored as numbersDo not assume their numeric order is meaningful; use an appropriate encoding or categorical split algorithm.

    Keep the search; change its statistics

    Classification uses label counts to score impurity. Squared-error regression uses counts and target statistics to score deviations from each child’s mean. Both can use the same sorted boundaries. When maintaining sums and squared sums, account for floating-point cancellation on large, nearly equal targets.
