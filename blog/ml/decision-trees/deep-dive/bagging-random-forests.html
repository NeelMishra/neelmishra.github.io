    Bagging & Random Forests

    September 2026 · 5 min read

    A small change to a training sample can change a tree’s first split and everything below it. Bagging reduces that instability by combining trees fitted to different resamples. A random forest also varies the features available at each split.

    Train on repeated draws, then combine predictions

    A bootstrap sample draws rows with replacement. With original row IDs [1, 2, 3, 4], a possible four-draw sample is [2, 2, 4, 1]: row 2 appears twice and row 3 is absent. Fit a separate tree to each such sample.

    For regression, average the trees’ numeric predictions. Classification can combine hard votes or average class probabilities; check the implementation. For example, scikit-learn’s random forest averages class probabilities. A vote from each tree is the simpler convention illustrated below.

    ▶ Bootstrap, Train, Vote

    Fixed bootstrap samples illustrate repeats and omitted rows. The five example votes are supplied, not computed by training trees in this animation.

    The supplied votes are A, A, B, A, A, so the committee predicts A. This shows aggregation, not a guarantee that the majority is correct. Errors shared by all trees survive averaging.

    Give different features a chance to split

    Bootstrap samples overlap. If one feature dominates, many trees may choose it near the root and make similar mistakes. A random forest chooses a random subset of candidate features at each node, then searches for a useful split within that subset.

    Imagine four features: age, income, visits, and region. If only visits and region are available at this node, income cannot dominate that split. Another node gets a fresh subset. The result can be less correlated predictions, although hiding useful features can also weaken individual trees.

    The ensemble chapter quantifies the tradeoff between tree count and correlation. Here, the practical lesson is that adding near-identical trees offers little extra stability.

    Evaluate each row using trees that did not train on it

    A row omitted from a tree’s bootstrap sample is out of bag for that tree. To evaluate row 3, combine only trees whose samples omitted row 3. Compare that prediction with row 3’s known target, then repeat for other rows.

    With a bootstrap containing as many draws as original rows, roughly 37% of rows are omitted when the dataset is large. The OOB calculation explains that fraction.

    OOB evaluation avoids training a separate model for each row. It does not protect against preprocessing leakage, repeated measurements of the same entity, or future-to-past leakage. Use evaluation splits that match deployment, and retain an independent final test when tuning against OOB results.

    Choose controls by their effect

    ControlQuestion to ask
    Number of treesHave predictions and validation performance stabilized enough for the added compute?
    Candidate features per nodeDoes extra diversity compensate for hiding useful split choices?
    Depth and minimum leaf sizeAre individual leaves fitting noise or missing useful structure?

    The trees can train in parallel because they do not wait for previous trees’ predictions; that does not make their outputs statistically independent. Boosting instead builds a sequence of corrective models. For code and an experiment, see the C++ random forest.
