    Isolation Forest: Follow One Point Through a Forest

    September 2026 · 15 min read

    Put five observations on a number line: 1, 2, 3, 4, and 20. Most of the empty space is between 4 and 20. A random cut landing there immediately separates 20 from the other four observations. That is the idea behind Isolation Forest: observations separated after fewer cuts receive higher anomaly scores.

    The algorithm measures unusualness relative to its training sample and feature representation. It does not know whether a large value is harmful, a legitimate large customer, or a collection error. We will first inspect the cuts, then build the score, and finally translate it into the library’s API.

    A random cut is uniform in feature space

    At a node, an isolation tree chooses a feature and a cut between the feature’s observed minimum and maximum. The cut divides the rows; each child is split again. These choices do not use target labels or optimize class purity. The original Isolation Forest paper describes this random partitioning procedure.

    With one feature ranging from 1 to 20, the possible cut interval has length 19. The interval between 4 and 20 has length 16, so a uniform first cut isolates 20 with probability 16/19 ≈ 84.2%. Isolating 1 takes a cut between 1 and 2: only 1/19 ≈ 5.3%. An interior value such as 3 cannot be isolated by a single threshold on this feature.

    Repeat the process until a row is alone, a node cannot be split, or the depth limit is reached. A path length counts the cuts from root to leaf. A forest repeats this with multiple trees and, usually, a random training subsample for each tree. Let $\psi$ (psi) be that subsample size. More trees average over more random choices; changing $\psi$ changes the population each tree tries to separate.

    Follow an actual fitted tree

    The next figure comes from a reproducible scikit-learn fit: three trees, all five training rows per tree, and random seed 1. The implementation limits depth to the ceiling of $\log_2\psi$, which is 3 here. A leaf may therefore still contain several training rows.

    In this forest, 3 and 4 remain together at depth 3. We add a correction for that unfinished isolation. For two remaining rows, the correction is one additional cut, so their corrected path length is 3 + 1 = 4. A leaf with one training row adds zero.

    In tree 1, query 20 first fails “≤ 1.78” and takes the right branch. It then fails “≤ 4.22” and takes another right branch, reaching the leaf [20]. That makes two cuts, not three nodes. Query 3 instead reaches the mixed leaf [3, 4] after three cuts; the extra unit estimates isolation that the depth limit left unfinished.

    For 20, the corrected paths are 2, 1, and 1. Their mean is 4/3 ≈ 1.3333. For 3, all three corrected paths are 4. A different random seed could produce different paths; averaging reduces sensitivity to a particular tree, while the chosen features and reference population still determine what can be isolated.

    Convert the average path into a score

    A tree with a larger subsample usually needs longer paths. The reference length $c(\psi)$ adjusts for that size. Let $\bar h(x)$ be the mean corrected path for query $x$, and let $s(x)$ be the anomaly score with larger meaning more unusual. For $\psi>1$, the score is:

    $$s(x)=2^{-\bar h(x)/c(\psi)}.$$

    Read it in order: divide the mean path by the reference, negate that ratio, and raise 2 to the result. A path equal to the reference gives 0.5. A shorter path gives a larger score. Average the corrected paths before applying this nonlinear transform; averaging separately transformed tree scores is a different computation.

    For our fitted forest, the library uses $c(5)\approx2.3270$. Query 20 has mean path 1.3333, giving $2^{-1.3333/2.3270}\approx0.6722$. Query 3 has mean path 4, giving about 0.3038. These calculations match the saved library scores.

    Where do the reference and unfinished-leaf correction come from?

    For a group of $n$ rows, define the harmonic sum $H_{n-1}=1+1/2+\cdots+1/(n-1)$. The reference from random search-tree analysis is:

    $$c(n)=2H_{n-1}-\frac{2(n-1)}{n}\quad(n>1),\qquad c(1)=0.$$

    The same function serves two roles: $c(\psi)$ normalizes the forest, and $c(n)$ estimates the remaining path in a leaf containing $n$ training rows. It is a reference correction, not a claim that every arrangement of those rows has the same exact isolation depth.

    An exact harmonic sum gives $c(5)=2.5667$. The verified library implementation uses a logarithmic approximation for $n>2$, giving 2.3270, with explicit values 0 for $n\le1$ and 1 for $n=2$. That is why substituting the exact small-sample reference does not reproduce its scores. The paper also discusses the harmonic approximation.

    Three output names, two different decisions

    Scikit-learn returns score_samples = −s, so lower values mean more abnormal. To rank from most unusual to least, sort −score_samples descending. Its decision_function subtracts the fitted offset_ from score_samples; values below zero receive the outlier label −1 from predict.

    With contamination="auto", the offset is −0.5. With a numeric fraction, the implementation takes a percentile of training score_samples. In this example, 0.2 targets the bottom fifth and leaves one of five training rows below the cutoff. Ties and finite-sample quantiles can make the realized fraction differ in other data. This parameter does not provide the unknown fraction of harmful cases.

    Run the fitted example 
    import numpy as np
from sklearn.ensemble import IsolationForest

X_train = np.array([1, 2, 3, 4, 20], dtype=np.float32).reshape(-1, 1)
X_query = np.array([1, 2, 3, 4, 20, 100], dtype=np.float32).reshape(-1, 1)
model = IsolationForest(
    n_estimators=3, max_samples=5, contamination="auto", random_state=1,
).fit(X_train)

unusualness = -model.score_samples(X_query)
decision = model.decision_function(X_query)
# Higher unusualness ranks first; decision < 0 is the library cutoff.
print(np.round(unusualness, 4))
# [0.6087 0.4092 0.3038 0.3038 0.6722 0.6722]

    What this example does not establish

    Queries 20 and 100 take identical paths, so their scores are equal. A tree routes an unseen observation into existing leaves; it does not keep measuring how far the value extends beyond the training maximum. This is a concrete limit of interpreting an isolation score as a distance or severity measure.

    Feature geometry also matters. A monotone log transform preserves the ordering of values but changes the spacing from which random cuts are drawn. Raw counts can isolate a large legitimate customer; arbitrary numeric identifiers can create meaningless cut locations. The telemetry chapter shows how units, exposure, and transformations change the comparison.

    Change one design choice at a time.
    ChoiceWhat changes
    Number of treesHow many randomized path measurements contribute to the average.
    Subsample sizeWhich density and rarity patterns a tree encounters, its depth limit, and its reference length.
    Feature representationThe coordinates and spacings in which cuts occur.
    Reference populationWhich observations define ordinary behavior.
    Decision cutoffWhich scores trigger a label or review; the fitted ranking can stay unchanged.

    Evaluate a useful ranking, not just a stable calculation

    Fit the feature pipeline and forest on the training period, then score later observations with the same feature meanings. Compare seeds and subsample sizes, but also inspect which customers and collection states dominate the highest scores. A stable ranking of logging outages is still the wrong result if the task is to find harmful application behavior.

    The queue chapter separates anomaly scores from admission rules, reviewer workload, and confirmed outcomes. That final evaluation determines whether this unsupervised ranking helps the task.
