    Anomaly Detection: Reading Guide

    September 2026 · 6 min read

    Isolation Forest finds observations that random cuts separate quickly. A useful anomaly workflow also needs meaningful inputs and a review policy. This series connects those three pieces without treating an unusualness score as a probability of harm.

    The examples start small enough to inspect: five points for the fitted forest, one application across three tenants for telemetry, and three synthetic days for queue admission. The queue chapter returns to the same fitted forest to explain why attribution units matter.

    Three artifacts make the workflow reviewable

    Three chapters, three questions

    01
    How do cuts become an anomaly score?

    Compare first-cut intervals, follow queries through a reproducible three-tree forest, and reconstruct its corrected path scores. Inspect the library’s score sign and contamination offset.

    02
    Which behavior should count as unusual?

    Switch between app and app–tenant rows, smooth low-exposure rates, inspect the geometry of log-transformed cuts, and separate observed zeros from collection gaps.

    03
    Which cases should reviewers receive?

    Compare cutoffs and capacity rules across changing days, group before applying a case budget, and reconstruct explanations in path or anomaly-score units.

    Read chapter 1 for the algorithm. Continue through chapters 2 and 3 to design a scoring-and-review workflow. The display of a stable score is not the final validation: inspect what entered the queue and whether later review found useful outcomes.

    Use the figures before opening the optional calculations

    Each chapter introduces its quantities in a small example before showing equations or code. Change one control and predict what should happen. The harmonic normalization, cut-mapping formula, and grouping implementation are optional details for a second pass.

    Reproduce a figure rather than guessing its numbers

    The forest script generates the saved trees and query scores, with the verified library version recorded. The cut-geometry script exports the downloadable SVG plots and their selected values. The queue chapter provides a grouping function and the complete synthetic fixture.

    These are teaching artifacts, not evidence that the same detector or threshold works on a real service. A small practical project should save a feature contract, fit on an earlier reference period, replay a later cohort under a frozen admission rule, and preserve the resulting case evidence.

    Reuse the evaluation and explanation foundations

    The graph-risk evaluation chapter already derives precision, recall, validation-based threshold selection, and outside-queue auditing. Apply those ideas to your declared row or case unit rather than learning a second set of metric conventions here.

    For multi-feature attributions, continue to the TreeSHAP notes and check the output and background used by the explainer. For the underlying detector, the Isolation Forest paper explains random partitioning and normalization, while the scikit-learn API reference documents the implementation’s score conventions.
