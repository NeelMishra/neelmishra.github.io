    Evaluate Embeddings and Choose Their Dimension

    September 2026 · 16 min read

    Before you start: how behavioral skip-gram learns vectors. Training loss tells us whether the model solves its training comparisons. This chapter asks whether the resulting representation helps the intended task.

    An embedding is useful when its neighbors support the decision you need to make. Eyeballing three plausible nearest-neighbor examples is a sanity check, not a model-selection protocol. Here we separate task relevance from approximate nearest-neighbor (ANN) index fidelity, link unit-norm Euclidean distance to cosine similarity, calculate vector memory footprints, and show geometrically why naive coordinate truncation breaks rankings.

    Define what a good neighbor means before scoring

    For a product catalog, “related” can mean an interchangeable substitute, a cross-category complement, or an item casually browsed in the same session. Boots and wool socks are strong complements and useless substitutes. Write the task rubric before inspecting any model’s output.

    Construct held-out queries with explicit relevance judgments matching that rubric—including hard negatives (such as a visually similar fashion boot lacking waterproofing). Keep the temporal cutoff, eligible candidate catalog, self-exclusion rule, and out-of-vocabulary (OOV) accounting identical across every candidate embedding; evaluating only queries that happen to exist in a model’s vocabulary hides coverage regressions. See relevance judgments and test collections for collection design.

    Separate useful task retrieval from accurate ANN search

    Evaluate every candidate embedding in two distinct stages: first run exact brute-force search over all eligible items to measure the representation’s true neighborhood quality; only then wrap the vectors in an approximate nearest-neighbor (ANN) index to measure index-induced recall loss against latency.

    Consider a six-item catalog for the query “waterproof substitutes for hiking boot Q”: items A, C, and D are judged relevant substitutes ($|R| = 3$), whereas B (socks), E (jacket), and F (mug) are non-substitutes. Suppose our embedding’s exact top-$2$ ranking is $E_2 = \{\text{B}, \text{A}\}$ because co-occurrence placed socks ahead of boot A.

    Define every symbol before comparing metrics at rank cutoff $K \ge 1$:

    • $K \ge 1$: number of top retrieved items returned to the caller.
    • $S_K$: set of $K$ items actually returned by the evaluated system ($|S_K| = K$).
    • $R$: set of all judged task-relevant items in the eligible catalog ($|R| \ge 1$).
    • $E_K$: set of exact top-$K$ highest-scoring items under the embedding’s own similarity function ($|E_K| = K$).
    • $|\cdot|$ and $\cap$: set cardinality (element count) and set intersection (shared items).
    $$\text{Task recall}@K = \frac{|S_K \cap R|}{|R|}, \qquad \text{ANN overlap}@K = \frac{|S_K \cap E_K|}{K}.$$

    Notice the two different reference sets and denominators: $\text{Task recall}@2$ divides by $|R| = 3$ relevant boots, whereas $\text{ANN overlap}@2$ (often called “ANN recall@K” in vector-database benchmarks) divides by $K = 2$ exact neighbors and knows nothing about whether B is a boot or a pair of socks!

    Exact numerical breakdown of Task Recall@2 ($R=\{\text{A,C,D}\}$) vs ANN Overlap@2 ($E_2=\{\text{B,A}\}$).
    Retrieval run Returned $S_2$ Relevant hits $S_2 \cap R$ Task recall@2 Exact hits $S_2 \cap E_2$ ANN overlap@2
    Exact brute-force $[\text{B}, \text{A}]$ $\{\text{A}\}$ ($1$) $1/3 \approx 0.3333$ $\{\text{B}, \text{A}\}$ ($2$) $2/2 = 1.0000$
    ANN: lose useful item $[\text{B}, \text{E}]$ $\varnothing$ ($0$) $0/3 = 0.0000$ $\{\text{B}\}$ ($1$) $1/2 = 0.5000$

    Logging both numbers prevents two classic attribution blunders: blaming HNSW index parameters when exact brute-force search already retrieves socks ($33.3\%$ ceiling), or mistaking $99\%$ ANN overlap for product relevance. Pair set recall with rank-sensitive metrics—AP and MRR for binary relevance or nDCG for graded substitutes.

    Align your distance metric before building an index

    Many ANN libraries expose separate index modes for inner product, $\ell_2$ (Euclidean) distance, and cosine similarity. Let $\hat{u} = u / \|u\|_2$ and $\hat{v} = v / \|v\|_2$ be $\ell_2$-normalized unit vectors in $\mathbb{R}^d$ satisfying $\|\hat{u}\|_2 = \|\hat{v}\|_2 = 1$, and let $\cos(u, v) = \hat{u}^\top \hat{v}$ denote their cosine similarity. Expanding the squared Euclidean distance $\|\hat{u} - \hat{v}\|_2^2$ gives an exact identity:

    $$\|\hat{u} - \hat{v}\|_2^2 = \|\hat{u}\|_2^2 + \|\hat{v}\|_2^2 - 2\hat{u}^\top \hat{v} = 2\bigl(1 - \cos(u, v)\bigr).$$

    Once every query and catalog vector is normalized to unit length ($\|\hat{v}\|_2 = 1$), minimizing Euclidean distance, maximizing inner product, and maximizing cosine similarity return the exact same nearest-neighbor ranking. Crucially, if you later truncate or project vectors to fewer coordinates, their truncated norms are no longer $1$—you must re-normalize if cosine ranking is still intended!

    Choose dimension through a controlled cost–quality comparison

    For $N$ catalog items stored at dimension $d$ in 32-bit floating point ($b = 4$ bytes per coordinate), the raw dense matrix payload in bytes is $N \times d \times 4$. At $N = 1{,}000{,}000$ items and $d = 32$, raw vectors occupy $128{,}000{,}000$ bytes ($128$ decimal MB; $\approx 122.1$ MiB)—before adding HNSW graph adjacency lists (often $1.5\times$–$3\times$ overhead at high degree $M$), string-to-row dictionaries, and serving replicas.

    Select $d$ on a held-out validation split—never on the final test split—and use paired per-query confidence intervals to check whether moving from $d = 128$ to $d = 64$ sacrifices meaningful task nDCG.

    Retraining, PCA projection, Matryoshka prefixes, and naive slicing

    Standard skip-gram and dual-encoder losses are invariant to shared orthogonal rotations: if $Q \in \mathbb{R}^{d \times d}$ satisfies $Q^\top Q = I_d$, replacing every $v$ with $Qv$ and every $u$ with $Qu$ leaves all dot products $(Qu)^\top(Qv) = u^\top Q^\top Q v = u^\top v$ and Euclidean distances completely unchanged. Consequently, ordinary embedding coordinates $1, \dots, d$ have no privileged importance ordering—slicing vec[:k] throws away arbitrary directions!

    Watch this happen in 2D: place query $q = (1, 0)$, item $A = (0.8, 0.2)$, and item $B = (-0.5, 0)$. In full 2D space, $\|A - q\|_2 = \sqrt{(-0.2)^2 + 0.2^2} = \sqrt{0.08} \approx 0.2828$ while $\|B - q\|_2 = 1.5000$, so $A$ is decisively closer at every rotation angle. Yet rotating all three vectors together by $90^\circ$ maps $q \mapsto (0, 1)$, $A \mapsto (-0.2, 0.8)$, and $B \mapsto (0, -0.5)$—making $q$ and $B$ collide at $x_1 = 0$ when the second coordinate is deleted!

    Python: reproduce the two metric denominators and the rotation example
    import numpy as np

relevant = {"A", "C", "D"}
exact = ["B", "A"]
cases = {"exact": exact, "lost useful item": ["B", "E"],
         "fortunate replacement": ["A", "C"]}
for name, result in cases.items():
    assert len(result) == len(set(result)) == 2
    task_recall = len(set(result) & relevant) / len(relevant)
    ann_overlap = len(set(result) & set(exact)) / len(exact)
    print(name, round(task_recall, 6), ann_overlap)
# exact                  0.333333 1.0
# lost useful item       0.000000 0.5
# fortunate replacement  0.666667 0.5

# Rotate query and both items together; then retain the first coordinate.
points = np.array([[1., 0.], [.8, .2], [-.5, 0.]])  # query, A, B
for degrees in [0, 90]:
    angle = np.deg2rad(degrees)
    c, s = np.cos(angle), np.sin(angle)
    rotation = np.array([[c, -s], [s, c]])
    rotated = points @ rotation.T
    full = np.linalg.norm(rotated[1:] - rotated[0], axis=1)
    first = np.abs(rotated[1:, 0] - rotated[0, 0])
    print(degrees, np.round(full, 6), np.round(first, 6))
# 0  [0.282843, 1.5]  [0.2, 1.5]
# 90 [0.282843, 1.5]  [0.2, 0.0]

    Version query encoders, item tables, and ANN indexes as one atomic bundle

    Even with identical hyperparameters, two independent SGNS training seeds learn spaces related by an unknown rotation (plus optimization noise): raw coordinate $1$ of Run A has no alignment with raw coordinate $1$ of Run B. Never serve new item embeddings against cached query vectors or an un-rebuilt ANN index from an earlier training run. Ship the vocabulary map, centering/projection matrices, normalization flag, item vectors, and ANN index together under a single immutable model version.
