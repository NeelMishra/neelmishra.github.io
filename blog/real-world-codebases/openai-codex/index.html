    Inside OpenAI Codex (openai/codex): Source-Level Architecture Across 120+ Rust Crates

    October 2026 · 12 min read · Master Overview

    OpenAI’s open-sourced codex repository—anchored by a workspace of more than 120 Rust crates under codex-rs/—is far more than a CLI wrapper around an LLM endpoint. It is a production reference architecture for building low-latency, stateful, defense-in-depth coding agents, and simultaneously a rare look into how OpenAI structures a large systems monorepo to be safely read, tested, and maintained by coding agents themselves.

    This series inaugurates Real World Codebases: line-by-line systems dissections of open-source production software. Rather than summarizing READMEs, every chapter traces real Rust data structures, state machines, wire protocols, kernel syscalls, and compiler plugins directly from openai/codex—explaining why naive agent designs fail in production and how Codex solves those failure modes mechanically.

    1. The Systems Equation Governing Multi-Step Coding Agents

    In a single-turn chatbot, a $500\text{ ms}$ prefill penalty or a re-serialized system prompt barely registers. In a software engineering agent executing $K = 35$ sequential tool steps over an $80{,}000$-token context window, small harness inefficiencies compound quadratically. Across an $S$-step trajectory with prefix token length $L_s$, newly appended delta tokens $\Delta L_s$, KV-cache hit ratio $\eta_s \in [0, 1]$, and overlapped tool execution time $\tau_{\text{overlap}, s}$, total wall-clock turn latency $T_{\text{turn}}$ satisfies:

    $$T_{\text{turn}} = \sum_{s=1}^{S} \Biggl[ \underbrace{t_{\text{dial}, s} + \bigl(1 - \eta_s\bigr)\, c_{\text{prefill}}\, L_s + c_{\text{cached}}\, \eta_s\, L_s + c_{\text{prefill}}\, \Delta L_s}_{\text{Transport + Prompt Prefill Latency}} + \underbrace{c_{\text{decode}}\, M_s + \max\!\bigl(0,\; T_{\text{tools}, s} - \tau_{\text{overlap}, s}\bigr)}_{\text{Decode + Pipelined Tool Execution}} \Biggr].$$

    Almost every architectural decision in codex-rs attacks a specific term in this sum:

    • Driving $t_{\text{dial}, s} \to 0$ and $\eta_1 \to 1$ before Turn 1 even begins: A custom 250ms dual-stack Happy Eyeballs WebSocket dialer opens a persistent session on TUI startup and transmits a response.create frame with generate: false, pre-populating GPU KV blocks for system instructions, tool schemas, and AGENTS.md while the user is still typing their prompt.
    • Keeping $\eta_s \approx 1$ across mid-session mutations: Instead of rewriting the system prompt or top-level tools array when permissions, working directories, Collaboration Modes, or MCP servers change (which drops $\eta_s \to 0$ and re-bills $L_s$ uncached tokens), WorldState models ~18 environment sections and appends RFC 7386 JSON Merge Patch diffs and UUIDv5 AdditionalTools items strictly at the conversation tail.
    • Shrinking $S$ and $\Delta L_s$ via V8 Code Mode & Two-Layer Truncation: Out-of-process V8 isolates let the model chain dozens of MCP calls inside JavaScript/TypeScript memory—passing megabytes of untruncated JSON directly between tools without round-tripping intermediate payloads through the LLM context window—while HeadTailBuffer preserves exact 50/50 head+tail slices of build logs.
    • Maximizing $\tau_{\text{overlap}, s}$: Rather than waiting for response.completed, try_run_sampling_request dispatches completed tool call items into FuturesOrdered while subsequent tool-call tokens are still streaming from the model, gated by an async RwLock<()> that admits read-only calls in parallel.

    4. Questions worth answering

    Why does OpenAI forbid codex-tui from importing codex-core directly, even when both compile into the exact same single CLI binary?

    If the local TUI bypassed the RPC protocol and mutated internal Rust structs directly, every new feature (approvals, streaming diffs, subagent status,elicitation modals) would silently ship in the CLI first and drift out of sync with VS Code, the macOS Desktop app, and SDK clients. Enforcing a hard CI boundary (verify_tui_core_boundary.py) and routing local CLI traffic through an in-process channel transport of codex-app-server guarantees every surface consumes the exact same typed JSON-RPC contract.

    Why can’t an OS sandbox alone replace responses-api-proxy or WorldState tail-diffing?

    Concerns at different layers are orthogonal: an OS kernel sandbox (Landlock/Seatbelt) restricts filesystem and socket syscalls of child tool processes, but if OPENAI_API_KEY lives in environment variables or unzeroed heap buffers of an agent container, an attacker with container code execution can exfiltrate the raw credential or upload private code to /v1/files. Similarly, correctness at the security layer does nothing to stop a naive prompt builder from invalidating $80{,}000$ cached prefix tokens on every directory change.
