    October 2026 · 4-Chapter Sub-Series · Reading Guide

    Why do most prototype coding agents freeze when you hit Ctrl+C, deadlock when an MCP server prompts for approval, leak zombie child processes when a thread closes, or wait idly until the model finishes streaming three tool calls before starting the first? Across four source-level chapters in codex-rs/core/src/session/, we trace the exact Rust actor topology that keeps Codex sub-millisecond responsive under load.

    $$T_{\text{control}} = O(1) \;\perp\; T_{\text{LLM}}, \qquad T_{\text{step}} = T_{\text{first\_tool\_done}} + \max\!\bigl(T_{\text{remaining\_stream}},\; T_{\text{tools}}\bigr) \le T_{\text{stream}} + T_{\text{tools}}.$$
