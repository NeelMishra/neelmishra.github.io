    Hierarchical AGENTS.md Resolution: Root Discovery, Override Precedence, Untrusted Repo Gates & Mid-Session Replacements

    October 2026 · 15 min read

    Loading AGENTS.md files from a Git repository sounds like a 20-line recursive directory walk—until an untrusted repository plants a prompt-injection payload in AGENTS.md, a malicious .codex/config.toml redefines project_root_markers to walk into $HOME, or a UNC path in project_doc_fallback_filenames leaks Windows NTLMv2 hashes during a metadata probe. We dissect all 563 lines of core/src/agents_md.rs and world_state/agents_md.rs to see how OpenAI Codex hardens instruction discovery end-to-end.

    1. Four Security Defenses Hidden Inside AGENTS.md Discovery

    Repository instruction files sit directly on an attacker-controlled trust boundary: anyone who convinces a developer to clone a repository controls every byte of its AGENTS.md and project-local .codex/config.toml. Before reading a single byte of project documentation, core/src/agents_md.rs enforces four distinct security invariants:

    1. Zero-Click Untrusted Repo Gate (load_project_instructions, lines 63–66): 
      let mut loaded = LoadedAgentsMd::from_user_instructions(user_instructions);
if config.active_project.is_untrusted() {
    return Ok((!loaded.is_empty()).then_some(loaded));
}
      If the user has not explicitly marked the workspace trusted, Codex loads only host-supplied global instructions (~/.codex/AGENTS.md) and skips repository discovery completely—neutralizing zero-click prompt injection when opening unfamiliar repos.
    2. Anti-Traversal Config Layer Exclusion (agents_md_paths, lines 200–206): 
      let mut merged = TomlValue::Table(toml::map::Map::new());
for layer in config.config_layer_stack.layers_low_to_high() {
    if matches!(layer.name, ConfigLayerSource::Project { .. }) {
        continue;
    }
    merge_toml_values(&mut merged, &layer.config);
}
      Why exclude ConfigLayerSource::Project when reading project_root_markers? Suppose a trusted repository’s .codex/config.toml set project_root_markers = [".ssh"] or a marker present in /home/alice. Walking upward until that marker matched would let the repo escape its own .git boundary and ingest files from parent directories! Only user-, system-, or MDM-controlled config layers may define where upward traversal stops.
    3. Executor-OS Path Convention & Windows SMB/NTLM Leak Prevention (candidate_filenames, lines 281–290): 
      // Use the executor's path convention, not the host's: resolving a Windows
// network path can send ambient credentials even during metadata probes.
if matches!(candidate, "." | "..")
    || candidate.contains(['/', '\0'])
    || cwd.infer_path_convention() == Some(PathConvention::Windows)
        && candidate.contains(['\\', ':'])
{
    tracing::warn!("ignoring project_doc_fallback_filenames entry that is not a filename");
    continue;
}
      Look at the threat model in that comment: on Windows, calling stat() (get_metadata) on a UNC path such as \\198.51.100.7\share\AGENTS.md causes the OS SMB redirector to initiate an outbound authentication handshake, leaking the user’s NTLMv2 hash before any file is even opened! Even sharper: Codex checks cwd.infer_path_convention() rather than compile-time cfg!(windows), because a macOS or Linux control plane may be driving a remote Windows ExecutorFileSystem over exec-server.
    4. Sandbox-Enforced File Reads & Fail-Closed Errors (lines 75–112): Whenever a turn environment lacks unrestricted disk read access (!has_full_disk_read_access()), Codex constructs a FileSystemSandboxContext and threads it into find_nearest_ancestor_with_markers, fs.get_metadata, and fs.read_file. Unsandboxed I/O errors log and continue; sandboxed errors fail closed (return Err(...)).

    2. Top-Down Cascade, Override Precedence & Concurrent Remote Probes

    Once root discovery locates the nearest ancestor containing a root marker (defaulting to [".git"], or [cwd] only when project_root_markers = []), Codex reverses the ancestor chain into top-down order $D = (d_0, d_1, \dots, d_k)$ where $d_0 = \text{project\_root}$ and $d_k = \text{cwd}$.

    Within each directory $d_i$, let $C = (\texttt{AGENTS.override.md},\, \texttt{AGENTS.md},\, f_1, \dots, f_m)$ be the deduplicated candidate filename list. Codex selects at most one regular file per directory—the first match $c^* \in C$—and concatenates winners from root to leaf subject to a shared saturating byte budget $B = \texttt{project\_doc\_max\_bytes}$:

    $$w(d_i) = \min_{\prec_C} \bigl\{ c \in C \;\big|\; \operatorname{is\_file}(d_i / c) \bigr\}, \qquad B_{i+1} = \max\bigl(0,\, B_i - \lvert \operatorname{bytes}(w(d_i)) \rvert\bigr).$$

    Two engineering details in agents_md_paths and read_agents_md (lines 142–180 and 244–269) make this fast and resilient across remote containers:

    • Single-Winner Directory Shadowing: Placing a gitignored AGENTS.override.md in /repo cleanly overrides /repo/AGENTS.md for local experimentation without silencing subdirectory-specific rules in /repo/codex-rs/core/AGENTS.md.
    • buffered(MAX_CONCURRENT_ANCESTOR_PROBES) (256): In remote SSH/container setups backed by ExecutorFileSystem, sequential stat() calls across a 12-level monorepo hierarchy would pay 12 sequential network RTTs at startup. Piping futures::stream::iter(search_dirs) through .buffered(256) collapses discovery into a single batched flight while preserving deterministic root-to-leaf order!
    • UTF-8-Safe Truncation: If an oversized file exceeds remaining bytes, data.truncate(remaining as usize) slices raw bytes and decodes via String::from_utf8_lossy(&data), guaranteeing that cutting mid-codepoint never panics.

    4. Questions worth answering

    What happens if a user configures project_root_markers = [] (an empty array) in their global ~/.codex/config.toml?

    Per the module docs (line 14) and find_nearest_ancestor_with_markers, an empty marker list disables upward parent traversal completely: project_root resolves to None, search_dirs becomes vec![cwd] (line 239), and only cwd itself is probed for AGENTS.md.

    Why does AgentsMdSnapshot store the full rendered text: Option<String> (or compare against it) rather than caching file modification timestamps (mtime)?

    Filesystem mtime changes on git checkout, rebase, or touch operations even when file contents are identical, and remote executors may skew clocks. Comparing the exact rendered (directory, text) tuple guarantees zero false-positive KV-cache tail emissions while immediately catching real edits to AGENTS.md mid-session.
