    Attention from First Principles: One Complete Calculation

    Updated September 2026 · 6 min read

    ↔ Try it∑ Read the explanation
    Attention is a learned weighted read. Each position constructs a query, compares it with available keys, and mixes the corresponding value vectors. The output is a new representation for that position. It is not a token prediction until later layers and the vocabulary head turn it into logits.

    Start with a representation that needs context

    In “the animal did not cross the street because it was tired,” a useful representation of “it” should contain information about the animal. An embedding lookup alone cannot do this: the same token ID initially selects the same vector. Attention makes the representation depend on the surrounding sequence. The example motivates a dependency; it does not assert that a particular trained head must learn a human-readable coreference rule.

    Let $X\in\mathbb R^{n\times d}$ contain one row per token. A single head constructs $Q=XW_Q$, $K=XW_K$, and $V=XW_V$, where $W_Q,W_K\in\mathbb R^{d\times d_k}$ and $W_V\in\mathbb R^{d\times d_v}$. Rows of $Q$ ask questions, rows of $K$ provide matching features, and rows of $V$ provide information to retrieve. These are learned projections of the current layer's input, not three separate tokenizations.

    Read the formula by following its dimensions

    $$S=\frac{QK^\top}{\sqrt{d_k}}+M,\qquad A=\operatorname{softmax}_{\mathrm{row}}(S),\qquad O=AV.$$
    ObjectShapeMeaning of one entry
    $S$$n\times n$$S_{ij}$ scores source position $j$ for query position $i$
    $A$$n\times n$$A_{ij}$ is its normalized weight
    $O$$n\times d_v$$O_i=\sum_jA_{ij}V_j$ is the retrieved vector

    Softmax runs across the keys for each query. Normalizing columns answers a different question. The mask $M_{ij}$ is zero for allowed pairs and $-\infty$ for forbidden pairs. For a causal model, query $i$ may use $j\le i$.

    A calculation small enough to do by hand

    Consider one query $q=(1,0)$, three keys $k_1=(1,0)$, $k_2=(0,1)$, $k_3=(1,1)$, and values $v_1=(2,0)$, $v_2=(0,2)$, $v_3=(2,2)$. These deliberately chosen vectors are an illustration, not measurements from a trained model. The unscaled dot products are $(1,0,1)$; since $d_k=2$, the scaled scores are approximately $(0.7071,0,0.7071)$.

    Subtract the largest score before exponentiation. The exponentials become $(1,0.4931,1)$, so the weights are approximately $(0.4011,0.1978,0.4011)$. Their sum is one. The retrieved vector is

    $$o\approx0.4011(2,0)+0.1978(0,2)+0.4011(2,2)=(1.6044,1.1978).$$

    Notice why keys and values have separate roles. Keys 1 and 3 tie in this query's score, but their values contribute different information. Changing $v_3$ changes the output without changing any attention weight. Changing $k_3$ can change every weight in the row because softmax renormalizes the entire row.

    Why softmax, and what its gradient says

    For row scores $s_j$, define $a_j=e^{s_j-c}/\sum_re^{s_r-c}$ with $c=\max_rs_r$. Subtracting the same number from every score cancels between numerator and denominator, while avoiding overflowing exponentials. Softmax gives nonnegative weights summing to one; before dropout, the output is a convex combination of values.

    $$\frac{\partial a_j}{\partial s_k}=a_j(\mathbf1[j=k]-a_k).$$

    Increasing one score raises its weight and lowers others. When a row becomes almost one-hot, many derivatives are small: the model has little sensitivity to small score changes. This explains why controlling score scale matters. It does not imply that confident attention is inherently undesirable.

    Softmax also solves a small optimization problem: maximize $\sum_ja_js_j+H(a)$ over probability vectors, where $H(a)=-\sum_ja_j\log a_j$. Scores reward preferred values while entropy rewards spreading mass. With temperature $T$, maximize score plus $T H(a)$. This is a local weighting interpretation, not a proof that the model's final language distribution has any particular entropy.

    Where the square root comes from

    If query and key coordinates are independent, zero mean, and unit variance, the dot product sums $d_k$ unit-variance products. Its variance is $d_k$. Dividing by $\sqrt{d_k}$ keeps variance near one as the head dimension changes. Learned coordinates need not satisfy those assumptions exactly; the calculation explains the initial scale choice, not a law guaranteeing unit-variance logits throughout training.

    Apply the mask before normalization

    If position 3 is forbidden in our example, remove its contribution before softmax. The remaining weights are approximately $(0.6698,0.3302,0)$, giving $(1.3395,0.6605)$. Multiplying the previous unmasked weights by a binary mask would instead leave a row summing below one.

    A row with no allowed key is not defined by ordinary softmax: subtracting a maximum of $-\infty$ can produce NaNs. Ensure each valid query can attend to at least one key, or define an explicit zero-output convention for padded rows. Attention-mask Boolean conventions vary across APIs; check the specific operation instead of assuming that True always means “blocked.”

    A transparent reference implementation

    import numpy as np

def attention(q, k, v, allowed):
    # q: [nq, dk], k: [nk, dk], v: [nk, dv]
    assert allowed.shape == (len(q), len(k))
    assert allowed.any(axis=-1).all()  # no fully masked row
    scores = q @ k.T / np.sqrt(q.shape[-1])
    scores = np.where(allowed, scores, -np.inf)
    probs = np.exp(scores - scores.max(axis=-1, keepdims=True))
    probs /= probs.sum(axis=-1, keepdims=True)
    return probs @ v, probs

    This materializes the full score and probability matrices for clarity. Production kernels can compute the same function without retaining those matrices; see FlashAttention. A function that uses Q @ (K.T @ V) has removed softmax and is a different attention mechanism.

    What self-attention does and does not mean

    Self-attention means queries, keys, and values come from the same sequence. It does not mean each token attends only to itself. Cross-attention takes queries from one sequence and keys/values from another. Causality and head sharing are separate choices.

    Without positional information or a position-dependent mask, permuting the input rows permutes the outputs in the same way. Formally, for a permutation matrix $P$, attention on $PX$ produces $PO$. This is permutation equivariance, not invariance: the order of output rows still follows the input order. Position encodings make relative or absolute location available.

    Try it: If every value vector equals the same vector $v$, can changing the query change the output?

    Without attention dropout, no: the weights sum to one, so their weighted sum is always $v$. The attention pattern can change while the retrieved representation stays identical.
