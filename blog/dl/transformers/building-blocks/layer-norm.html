    LayerNorm, RMSNorm, and Residual Scale

    Updated September 2026 · 4 min read

    Normalization controls the scale of the vector presented to a sublayer. It is not an instruction to erase everything the residual stream knows about magnitude. The axis being normalized and the location of the operation are both part of the architecture.

    Normalize features within one token

    For a token vector $x\in\mathbb R^d$, LayerNorm computes a mean and variance across its $d$ features:

    $$\mu=\frac1d\sum_jx_j,\qquad\sigma^2=\frac1d\sum_j(x_j-\mu)^2,\qquad\operatorname{LN}(x)_j=\gamma_j\frac{x_j-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_j.$$

    For an activation tensor $[B,n,d]$, there are $Bn$ separate sets of statistics when normalizing only the last dimension. No statistic is shared across examples or token positions. The scale and shift parameters $\gamma,\beta\in\mathbb R^d$ are shared across those examples and positions.

    LayerNorm uses the population variance with denominator $d$, not an unbiased estimate with denominator $d-1$. It does not maintain the running means used by common BatchNorm implementations. A batch of one is therefore not a special case for this computation. See the Layer Normalization paper.

    A four-dimensional numerical example

    Take $x=(1,2,3,4)$, $\gamma=(1,1,1,1)$, $\beta=0$, and ignore $\epsilon$ only for this hand calculation. The mean is $2.5$. The centered vector is $(-1.5,-0.5,0.5,1.5)$ and the variance is $(2.25+0.25+0.25+2.25)/4=1.25$. Dividing by $\sqrt{1.25}$ yields approximately $(-1.342,-0.447,0.447,1.342)$.

    Those normalized features have mean zero and variance one before the learned affine transform. After multiplying by a nonuniform $\gamma$ and adding $\beta$, neither property need hold. Statements such as “LayerNorm makes every hidden state zero mean” omit this final learned transformation and the subsequent residual addition.

    RMSNorm removes centering

    $$\operatorname{RMSNorm}(x)_j=\gamma_j\frac{x_j}{\sqrt{\frac1d\sum_rx_r^2+\epsilon}}.$$

    For the same vector, the mean square is $7.5$, so the normalized output is approximately $(0.365,0.730,1.095,1.461)$. All entries remain positive. RMSNorm controls root-mean-square magnitude without subtracting the feature mean. The common form has a learned scale and no learned shift; implementation variants should be identified explicitly. The primary reference is Root Mean Square Layer Normalization.

    Ignoring $\epsilon$, both operations are invariant to a positive rescaling of the input before the learned affine transform. LayerNorm also removes adding a constant to every feature; RMSNorm does not. These are different invariances, not merely alternative implementations of the same function.

    The small constant changes the edge cases

    If all features equal the same constant, LayerNorm's centered vector is zero and its output equals $\beta$. If all features are zero, RMSNorm returns zero in its scale-only form. A positive $\epsilon$ prevents division by zero and affects derivatives when the variance is tiny. Its placement inside the square root matters.

    In low precision, computing the mean square or variance in higher precision can prevent loss of accuracy. A cast back to the model's activation dtype may follow. “Uses BF16” does not imply every internal reduction runs in BF16. Inspect the actual primitive before reproducing numerical behavior.

    Pre-norm and post-norm have different paths

    $$\text{pre-norm: }y=x+F(N(x)),\qquad\text{post-norm: }y=N(x+F(x)).$$

    For pre-norm, the derivative is $I+J_FJ_N$ at the appropriate inputs. There is an explicit identity contribution from the residual branch. For post-norm, it is $J_N(I+J_F)$: normalization also transforms the path through the residual sum. This is a structural distinction that helps explain differences in optimization behavior.

    An identity term does not guarantee that the total gradient stays close to one; the other term can reinforce or cancel it. Pre-norm also allows the unnormalized residual stream to accumulate updates and change scale with depth. Residual initialization, learning rate, final normalization, and model depth still matter. On Layer Normalization in the Transformer Architecture analyzes normalization placement and training dynamics.

    A reference implementation exposes the axes

    def layer_norm(x, gamma, beta, eps=1e-5):
    mean = x.mean(axis=-1, keepdims=True)
    variance = ((x - mean) ** 2).mean(axis=-1, keepdims=True)
    return gamma * (x - mean) / np.sqrt(variance + eps) + beta

def rms_norm(x, gamma, eps=1e-5):
    mean_square = (x ** 2).mean(axis=-1, keepdims=True)
    return gamma * x / np.sqrt(mean_square + eps)

    Changing axis=-1 to include the sequence axis changes the function and can introduce dependencies between tokens, including future information in a supposedly causal model. The shape of gamma is not enough to establish the normalization axes; read the reduction itself.

    Try it: Adding 100 to every feature leaves which normalized vector unchanged, ignoring epsilon and affine parameters?

    LayerNorm: centering subtracts the added constant. RMSNorm generally changes because both its numerator and its root-mean-square denominator change without removing the offset.
