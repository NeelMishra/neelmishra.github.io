    Token Embeddings and the Vocabulary Head

    Updated September 2026 · 5 min read

    ◉ See the idea↔ Try it∑ Read the explanation
    An embedding table is a trainable array indexed by token ID. The lookup gives a token its initial vector. Attention and feed-forward layers then turn it into a context-dependent representation. The vocabulary head maps the final representation back to scores over token IDs.

    Trace one token through the boundary of the model

    Assume a tokenizer produces IDs $(4,1,4)$. Let $E\in\mathbb R^{V\times d}$ be the embedding table. The input matrix consists of rows $E_4,E_1,E_4$. Repeated IDs initially receive identical token embeddings, although added position embeddings can immediately make their complete input vectors different.

    For a tiny table, take $E_1=(0,2,-1)$ and $E_4=(1,0,1)$. The lookup returns $[(1,0,1),(0,2,-1),(1,0,1)]$. There is no search for the nearest vector and no multiplication by the integer ID. Renumbering token IDs and permuting the corresponding table rows leaves the represented computation unchanged.

    $$X=\operatorname{onehot}(\mathrm{ids})E.$$

    This identity is useful mathematically, but an implementation gathers rows rather than constructing a huge one-hot matrix. For a batch, ids has shape $[B,n]$ and the output has shape $[B,n,d]$.

    How an embedding learns

    During the backward pass, the gradient for a table row is the sum of gradients from every place where that row was looked up. In our sequence, row 4 receives contributions from both positions 1 and 3. Rows absent from the lookup receive no gradient through this input path. They can still receive gradients through a tied output head, and optimizer weight decay may also change them.

    This makes the distinction between a parameter and an activation concrete. $E_4$ is a shared parameter used across examples. The contextual state at position 1 is an activation specific to this sequence and this forward pass. Saying “the embedding of this word changed with context” usually refers to the latter, not a rewrite of the table during inference.

    The output head scores the vocabulary

    Let a final hidden row be $h\in\mathbb R^d$. A vocabulary projection produces $\ell=hW_U+b$ with $W_U\in\mathbb R^{d\times V}$. Softmax turns logits into probabilities. In an autoregressive model the vector at input position $i$ usually predicts token $i+1$; that alignment is established by the training loss, not by the embedding operation.

    $$p(v\mid\text{context})=\frac{\exp(\ell_v)}{\sum_{u=1}^{V}\exp(\ell_u)}.$$

    For a tied head, $W_U=E^\top$. Each logit becomes an inner product $h\cdot E_v$ plus any bias. This connects the coordinates used to represent input tokens with the directions used to recognize output tokens. The head still scores the entire vocabulary; it does not merely return whichever token appeared most recently.

    Count what weight tying actually saves

    With vocabulary size 50,000 and width 768, an embedding table contains 38,400,000 parameters. An independent output matrix adds the same amount. Tying removes one matrix, saving 76.8 million bytes if stored in two-byte precision, before counting optimizer states. It does not eliminate the computation of vocabulary logits, and it does not require tying position embeddings.

    Tying also couples the gradients: a row can be pushed by its uses as an input and by its role as a possible output. That constraint can help or hurt depending on the task and training setup. The original discussions include Press and Wolf and Inan et al..

    Why scaling and position must be specified together

    The original Transformer scales token embeddings by $\sqrt d$ before adding sinusoidal positions. That is one architecture's convention, not a required property of embedding lookup. Other models use learned absolute positions or apply position transformations later inside attention. Do not add a $\sqrt d$ multiplier to a pretrained model merely because a textbook diagram contains one.

    Likewise, token-type embeddings in the original BERT indicate which of two segments a token belongs to. They are neither universal transformer components nor substitutes for padding masks. A padding ID is also not automatically ignored: the attention mask and loss mask must agree about which positions are valid.

    A useful limit on geometric intuition

    Nearby embedding vectors can encode related usage, but raw distances are not a universal dictionary of meaning. Training objectives, frequency, anisotropy, the tokenizer, and subsequent linear maps all affect the geometry. Two representations can implement the same function after a coordinated change of basis while having different Euclidean distances.

    Use embedding visualizations to ask a concrete question—such as whether a tokenizer splits similar strings consistently—rather than assuming that two-dimensional clusters explain what an entire language model knows. The distinction becomes especially important for rare subwords and byte tokens.

    Try it: If token 4 occurs twice, does the model store two separate copies of its trainable embedding?

    No. The two activations are gathered from one shared table row. Their backward contributions accumulate into that row. After contextual layers, the two activations can be different.
