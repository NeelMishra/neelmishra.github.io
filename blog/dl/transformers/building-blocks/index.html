    Transformer Foundations: Follow the Model Diagram

    Updated September 2026 · 4 min read

    ∑ Read the explanation
    Keep the whole model in view as you learn each piece. Start with token IDs, follow the vectors through the blocks, and finish with a next-token prediction. The diagram below returns in every Foundations chapter with that chapter’s component highlighted.

    What you need before starting

    You should be comfortable with matrix multiplication, basic derivatives, and probabilities that sum to one. Batch dimensions and broadcasting can be learned as you go. Each technical chapter states its shapes and includes a small calculation or invariant to check.

    For now, remember just two sizes: $n$ is the number of tokens and $d$ is the number of features in each token’s vector. The chapters introduce the other symbols when you need them. A block changes the vectors while preserving their $n\times d$ shape.

    Eight chapters, one model diagram

    The reading order introduces one idea at a time. It differs from execution order: for example, you will study normalization after understanding what its attention and MLP branches do. Use the arrows in the diagram to locate each operation in the forward pass.

    1. Token embeddings: start at the left box. How does an ID select the starting vector for a token?
    2. One attention head: zoom inside the blue box. How does a query retrieve a weighted combination of values?
    3. Multi-head attention: zoom back out to the blue box. How do several reads become one update?
    4. Causal masking: inspect the restriction inside each head. Which token positions may it read?
    5. The feed-forward network: move to the second branch. How does it transform the features at each position?
    6. Normalization: find the boxes before both branches and after the stack. How are vectors prepared for the next operation?
    7. The complete block: follow both skip paths and + circles. How do the updates combine, and what enters the next block?
    8. Dropout: inspect the dashed boxes. What changes during training, and what disappears at evaluation?

    Then study position information and assemble GPT-2, including its vocabulary head. The diagram uses a causal decoder with normalization before each branch; the architecture chapter explains encoder and encoder–decoder arrangements.

    Three questions to ask at every operation

    Which axis is being mixed? Attention combines positions, an MLP combines features within one position, and head concatenation joins feature subspaces. Normalization over the wrong axis can silently couple examples or tokens.

    What does the output represent? An attention output is a contextual feature vector. Vocabulary logits score token IDs. An attention weight distribution and a next-token distribution are not interchangeable just because both can use softmax.

    What changes between training and inference? Dropout is disabled for deterministic evaluation; generation consumes chosen continuation tokens; causal caches reuse valid prior state. The underlying prediction alignment must stay consistent.

    Then choose a branch

    For encoder-decoder tasks, continue to cross-attention and architecture families. For language generation, assemble GPT-2. For long-context behavior, begin with cost accounting before choosing an optimization.

    GQA, MLA, sparse attention, and recurrent attention each have their own canonical chapter. They build on the basic weighted-read equation but should not repeat its derivation. Use the comparison map to see which component each one changes.

    Try it: Which operation directly mixes different sequence positions: the ordinary token-wise MLP or self-attention?

    Self-attention. The standard MLP applies the same learned function independently to each position, though its input can already contain context from earlier attention.

    Check the math with small arrays

    The runnable math lab checks causality, recurrence equivalences, rotary identities, latent projection absorption, and speculative correction. Use it after reading the relevant derivation.
