    Fine-Tune CLIP and Build a Two-Tower Retriever

    September 2026 · 4 min read

    Before you start: The symmetric contrastive loss.

    A general image–text model may understand “shoe” while confusing the distinctions a fashion catalog needs: heel type, material, occasion, or fit. Domain fine-tuning should teach those distinctions without destroying broad retrieval behavior. The training dataset, negatives, and evaluation slices define what “better” means.

    Construct pairs that match the serving task

    A product image and its title are not automatically a clean positive. Titles may contain seller boilerplate or attributes invisible in the image. Decide whether text represents visual description, catalog facts, or a user query. If serving uses conversational queries but training uses polished descriptions, include query-like supervision or evaluate that shift explicitly.

    Split by product family and time where needed. Near-identical color variants across train and test can exaggerate generalization. Deduplicate images and descriptions before negative construction. Keep category, brand, availability, and item-age slices so the average cannot hide a cold-start failure.

    Hard negatives should be hard for the right reason

    Random negatives teach broad category separation. Hard negatives can distinguish two similar shoes with different material or intended use. Mine them using a frozen earlier model or a training-only process, then audit whether they are genuinely invalid matches. An item that is relevant but unclicked should not become a trusted negative merely because the logs omit its exposure.

    Mix negative difficulty. If every negative is almost indistinguishable or mislabeled, the model may learn noise. If every negative is a completely different category, the model can solve the loss without learning useful fine distinctions. Track retrieval performance on a separate hard-negative test instead of using training loss as the only signal.

    Choose the adaptation budget

    Compare a frozen encoder baseline, a trained projection head, partial unfreezing, and full fine-tuning. A small learning rate for pretrained encoders and a larger one for new layers is a possible recipe, not a guarantee. Record the optimizer, temperature handling, batch-negative scope, augmentations, and early-stopping rule. Evaluate both domain quality and broad holdout behavior to detect forgetting.

    Select using held-out retrieval under a fixed evaluation protocol.
    AdaptationWhat it can changeWhat to watch

    Partial encoder tuningHigher-level domain featuresLayer choice and stability
    Full fine-tuningAll visual/text representationsData size, forgetting, and overfitting

    Personalized retrieval adds a query-side representation

    For recommendations, a user tower can encode history and context into $u$, while an item tower produces $v$. A dot-product score $u^\top v$ makes large-scale retrieval possible. Include only history available before the recommendation time. A query tower that uses the future clicked item as an input will produce impressive but invalid offline results.

    A cross-encoder reads query and item jointly and can model interactions that one dot product cannot express. Use it to rerank a candidate set when the latency budget allows. Evaluate the retrieval ceiling first: the reranker cannot recover a relevant product missing from the candidates.

    Encoder and index are one versioned unit

    Export the exact item-side transform, normalization, vocabulary/tokenizer, image preprocessing, and model revision used during evaluation. Build a new index for the new item vectors. Query vectors from one embedding version and item vectors from another generally live in incompatible spaces. Switch them together or use a verified compatibility strategy.

    Measure exact-search relevance before ANN approximation. Then benchmark index recall, filters, end-to-end latency, and memory. Include Recall@K, MAP or nDCG with their declared conventions, plus diversity and cold-start slices where the product needs them. The evaluation series provides the full protocol.

    A compact experiment matrix

    Keep data and evaluation fixed while changing one major axis: baseline versus domain pairs; random versus mixed hard negatives; frozen versus partially tuned encoders; exact versus approximate search. Then compare complete serving configurations at matched latency or quality. Record failures such as visually plausible but attribute-wrong matches, because they often reveal a missing supervision signal.

    Check your understanding: Why rebuild the item index after changing the encoder?

    The new encoder changes vector geometry. An old item index and a new query encoder do not generally form a valid matching system, even when vector dimensions are unchanged.
