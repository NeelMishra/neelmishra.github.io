    CLIP: Understand the Entire Contrastive Loss Through One Batch

    September 2026 · 4 min read

    Before you start: Vision Transformers, dot products, softmax, and cross-entropy.

    Put three images and their three matching captions in a batch. A model should score each matching pair above the mismatched pairs. CLIP learns image and text encoders together through this identification task. The central object is a small matrix: every image compared with every caption.

    Normalize the representations before comparing them

    Let $f_\theta(I_i)$ encode image $i$ and $g_\phi(T_j)$ encode caption $j$. Normalize each vector to unit length, producing $u_i$ and $v_j$. Their dot product is cosine similarity. Divide by positive temperature $\tau$ to obtain a logit $z_{ij}=u_i^\top v_j/\tau$.

    $$p_{ij}=\frac{\exp(z_{ij})}{\sum_{k=1}^{B}\exp(z_{ik})},\qquad L_{I\to T}=-\frac1B\sum_{i=1}^{B}\log p_{ii}.$$

    The row-softmax asks which caption matches each image. A column-softmax asks which image matches each caption. CLIP averages these two directional cross-entropies. Both encoders receive gradients because both sides participate in every similarity.

    $$L=\tfrac12(L_{I\to T}+L_{T\to I}).$$

    One row with actual probabilities

    For similarities [0.8,0.2,0.1] and τ=0.2, the logits are [4,1,0.5]. Subtract the maximum for numerical stability, giving exponentials [1,e⁻³,e⁻³·⁵]. The matching-caption probability is approximately 0.9259, so the row loss is −log(0.9259)≈0.0769. The model is already doing well on this row; a harder row would contribute more loss.

    The derivative of a row’s cross-entropy with respect to logit $z_{ij}$ is $p_{ij}-\mathbf1\{i=j\}$. The positive logit is pushed upward; negative logits are pushed downward in proportion to their predicted probabilities. A hard negative gets more pressure than an obviously unrelated caption. The derivative with respect to similarity also carries a factor $1/\tau$.

    Temperature changes more than the displayed confidence

    Lower temperature sharpens the distribution and increases sensitivity to similarity differences. For an already correct row it can drive the loss close to zero; for an incorrectly ranked positive it can make the loss and gradients large. A very low temperature can therefore exaggerate noisy or false-negative supervision. Temperature is an optimization parameter to validate, not a universal “make embeddings better” knob.

    The original CLIP formulation learns a logit scale. In a teaching implementation, a fixed positive temperature makes the calculation transparent. If you learn a scale, constrain it according to the chosen training recipe and monitor it alongside the loss. A falling loss caused only by sharper logits does not automatically imply better held-out retrieval.

    The full loss in a few lines

    import torch
import torch.nn.functional as F

def clip_loss(image_features, text_features, temperature=0.2):
    if temperature <= 0:
        raise ValueError("temperature must be positive")
    images = F.normalize(image_features, dim=-1)
    texts = F.normalize(text_features, dim=-1)
    logits = images @ texts.T / temperature
    targets = torch.arange(len(images), device=images.device)
    return (F.cross_entropy(logits, targets)
            + F.cross_entropy(logits.T, targets)) / 2

    The diagonal assumption can be wrong

    If two captions both describe the same product, treating the off-diagonal match as a negative gives contradictory supervision. Duplicate images, product variants, and generic captions create similar issues. Deduplicate or use a multi-positive objective that sums probability over valid positives, with an explicitly chosen normalization. More in-batch negatives help only when the negative assumptions are sufficiently accurate.

    Ordinary gradient accumulation over small micro-batches does not create the same contrastive denominator as one large batch: each micro-batch sees a smaller negative set. Distributed all-gather can expose more negatives, but gradients and duplicate handling must match the intended global objective. Compare the actual loss definition, not just the advertised effective batch size.

    Check your understanding: If two captions are both valid for one image, should one always be penalized as a negative?

    No. The one-positive-per-row objective is misspecified for that batch. Use data construction or a multi-positive objective that represents the valid matches.
