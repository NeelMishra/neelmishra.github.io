    Random Oversampling

    September 2026 · 13 min read

    Random oversampling gives selected classes more appearances during training by drawing existing rows with replacement. Replacement means a row remains eligible after it has been drawn, so the same row can be copied repeatedly.

    No new measurement is collected. The useful question is whether giving existing examples more training influence improves the evaluation objective, compared with the original data and with class weighting.

    Follow the row identities

    Start with six negative examples A–F and two positive examples G and H. To reach six positives, retain the eight original rows and make four additional draws from {G, H}. One possible draw sequence is H, G, H, H.

    The resulting training set has six negatives and six positives. G appears twice in total; H appears four times. Equal class counts do not imply that every member of a class is repeated equally.

    A target count is the final count

    With sampling_strategy={1: 6}, the dictionary means “make class 1 contain six rows.” It does not mean “add six rows.” Since two positives already exist, the sampler adds four.

    For binary classification, a float specifies the desired minority-to-majority count ratio after resampling. Here sampling_strategy=0.5 means three positives against six negatives, so it adds one positive. The ratio 0.5 means one positive per two negatives; the positive fraction of all rows is then 1/3, not 1/2.

    A dictionary avoids ambiguity and also supports multiple classes. With the default "auto", RandomOverSampler brings the other classes up to the largest class’s count. Balancing every class is a candidate to validate, not a required preprocessing step.

    Repeating a row acts like an integer loss weight

    In sequence B, H is evaluated four times whenever we compute the loss over the complete resampled set. If its prediction is fixed, those four identical rows contribute four identical loss terms. G contributes two terms, and each negative contributes one.

    Write the loss using the original row identities

    Let $c_i$ be the number of times original row $i$ appears and $\ell_i$ its per-row loss. There are $n$ original rows and $N'=\sum_i c_i$ resampled rows. Their mean loss can be written as

    $$L_{\mathrm{resampled}}=\frac{1}{N'}\sum_{i=1}^{n}c_i\ell_i.$$

    For sequence B, the weights of G and H are 2 and 4. Across repeated uniform draws, each positive has expected multiplicity 3, but one realized sample need not give both that multiplicity. This is why random oversampling and a fixed equal weight for every positive are related without being identical datasets.

    Full integer repetition matches an integer-weighted sum of losses. Actual training can still differ through regularization conventions, minibatch composition and optimization. An oversampled epoch contains more rows and, with a fixed batch size, more optimizer steps. Keep that training-budget change visible when comparing methods.

    What the extra appearances cannot add

    Repeated G rows do not supply new examples of a positive subtype absent from G and H. They also repeat any measurement or labeling mistake in those rows. A flexible learner can devote more effort to memorizing the repeated examples without improving on new positives.

    The sampler’s counts therefore measure training appearances, not independent evidence. Evaluate on untouched observations, inspect minority subtypes and compare against a no-resampling baseline. Where the estimator accepts them, class weights can change the objective without storing extra rows.

    By default, shrinkage=None produces exact copies. A positive shrinkage setting requests a smoothed bootstrap that perturbs features; that is a different assumption about valid nearby observations. The examples here use exact copying.

    Split before copying, and sample only while fitting

    If copies are made before a train/validation split, versions of the same observation can land on both sides. Validation then partly tests recognition of already-seen examples. Split original identities first, respecting any group or time boundary.

    Python: inspect which rows were copied

    Keep identifiers separately from model features. Here the one-dimensional feature is 0–5 for A–F and 10–11 for G–H; the letters are only tracing labels.

    Run exact oversampling and inspect source indices
    import numpy as np
from imblearn.over_sampling import RandomOverSampler

X = np.array([0, 1, 2, 3, 4, 5, 10, 11]).reshape(-1, 1)
y = np.array([0] * 6 + [1] * 2)
ids = np.array(list("ABCDEFGH"))
sampler = RandomOverSampler(sampling_strategy={1: 6}, random_state=5)
X_resampled, y_resampled = sampler.fit_resample(X, y)
print(np.bincount(y_resampled).tolist())
print(ids[sampler.sample_indices_].tolist())

    [6, 6]
['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H', 'H', 'G', 'H', 'H']

    The sample_indices_ array maps every output row back to its input row. Use the same indices for any row-aligned metadata you retain. It also makes the repeated identities visible during debugging.

    Fit a sampling pipeline and predict two new rows
    from imblearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression

model = make_pipeline(
    RandomOverSampler(random_state=5),
    LogisticRegression(),
).fit(X, y)
print(model.predict([[2.5], [10.5]]).tolist())

    [0, 1]

    The default target follows the class counts in each training fold. Two inputs produce two predictions. This tiny example demonstrates the fit/predict contract; it is not a performance estimate. For model selection, pass the whole pipeline into the cross-validation procedure.

    C++: return source indices to preserve alignment

    The function below retains all original indices, then draws from the positive indices until the requested final count is reached. It uses a seeded generator; its sequence need not match NumPy’s even with the same seed.

    Compile a binary positive-class oversampler
    #include <algorithm>
#include <iostream>
#include <numeric>
#include <random>
#include <stdexcept>
#include <vector>

std::vector<std::size_t> oversample_indices(const std::vector<int>& y,
        std::size_t target_positive, unsigned seed) {
    std::vector<std::size_t> positive;
    for (std::size_t i=0; i<y.size(); ++i) {
        if (y[i]!=0 && y[i]!=1) throw std::invalid_argument("binary labels required");
        if (y[i]==1) positive.push_back(i);
    }
    if (positive.empty() || target_positive<positive.size())
        throw std::invalid_argument("positive class required; target cannot shrink it");
    std::vector<std::size_t> output(y.size());
    std::iota(output.begin(),output.end(),0);
    std::mt19937 rng(seed);
    std::uniform_int_distribution<std::size_t> pick(0,positive.size()-1);
    for (std::size_t n=positive.size(); n<target_positive; ++n)
        output.push_back(positive[pick(rng)]);
    return output;
}
int main() {
    const std::vector<int> y{0,0,0,0,0,0,1,1};
    const auto indices=oversample_indices(y,6,5);
    const auto positives=std::count_if(indices.begin(),indices.end(),
        [&](std::size_t i){return y[i]==1;});
    std::cout << "rows=" << indices.size() << " positives=" << positives << "\n";
}

    rows=12 positives=6

    Choose the target through validation, save the sampler settings with the fitted pipeline, and keep the evaluation prevalence representative of the intended workload.
