    Modern Feed-Forward Blocks: Expansion Ratios, GLU / SwiGLU, Residuals, and Memory Profile

    October 2026 · 10 min read

    Two-thirds of the parameters and FLOPs in a modern Transformer or MLP-Mixer live inside its Feed-Forward Network (FFN) blocks. See how classical 2-layer MLPs evolved into Pre-LN residual inverted bottlenecks and three-matrix SwiGLU blocks, and calculate their exact parameter, FLOP, and activation-memory budgets.

    1. The expand-and-project FFN ($d_{\text{model}} \to d_{\text{ff}} \to d_{\text{model}}$) and Key–Value memory

    Rather than stacking uniform hidden layers $h^{(\ell)} = \phi(W^{(\ell)} h^{(\ell-1)} + b^{(\ell)})$ directly on the main path, modern architectures (Transformers, ConvNeXt, MLP-Mixer) maintain a persistent residual stream $x \in \mathbb{R}^{d_{\text{model}}}$ and attach a 2-layer expand-and-project FFN block of intermediate width $d_{\text{ff}} = 4\,d_{\text{model}}$:

    $$\operatorname{FFN}_{\text{std}}(x) = W_{\text{down}}\,\phi\bigl(W_{\text{up}}\,x + b_{\text{up}}\bigr) + b_{\text{down}}, \qquad W_{\text{up}} \in \mathbb{R}^{d_{\text{ff}} \times d_{\text{model}}},\quad W_{\text{down}} \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ff}}}.$$

    Why expand to $d_{\text{ff}} = 4 d_{\text{model}}$ and then project back down to $d_{\text{model}}$? Let $k_i^\top \in \mathbb{R}^{1 \times d_{\text{model}}}$ be row $i$ of $W_{\text{up}}$ and let $v_i \in \mathbb{R}^{d_{\text{model}} \times 1}$ be column $i$ of $W_{\text{down}}$ (for $i = 1, \dots, d_{\text{ff}}$). Expanding the matrix product as a sum of rank-1 outer products reveals that an FFN block is an unnormalized Key–Value associative memory (Geva et al., 2021):

    $$\operatorname{FFN}_{\text{std}}(x) = \sum_{i=1}^{d_{\text{ff}}} \underbrace{\phi\bigl(k_i^\top x + b_{\text{up},i}\bigr)}_{\text{sparse scalar memory coefficient } m_i(x) \ge 0} v_i + b_{\text{down}}.$$

    Each row $k_i^\top$ of $W_{\text{up}}$ acts as a pattern detector (key) on the input token $x$; whenever $k_i^\top x + b_{\text{up},i} > 0$, unit $i$ fires and adds $m_i(x)\,v_i$—its stored value vector in $W_{\text{down}}$—into the residual stream.

    2. Gated Linear Units (GLU, GeGLU, SwiGLU) and the $\frac{8}{3}d_{\text{model}}$ rule

    Shazeer (2020) showed that replacing the single upward projection $W_{\text{up}} x$ with two parallel upward projections—a gate branch $W_{\text{gate}} x$ passed through $\operatorname{SiLU}(z) = z\sigma(z)$ and a linear value branch $W_{\text{up}} x$ combined via element-wise multiplication $\odot$—consistently lowers perplexity at equal compute. Modern LLMs (LLaMA, Gemma, Mistral, Qwen, DeepSeek) drop biases and use SwiGLU:

    $$\operatorname{SwiGLU}(x) = W_{\text{down}}\Bigl(\operatorname{SiLU}\bigl(W_{\text{gate}} x\bigr) \odot \bigl(W_{\text{up}} x\bigr)\Bigr),$$

    where $W_{\text{gate}}, W_{\text{up}} \in \mathbb{R}^{d_{\text{ff}} \times d_{\text{model}}}$ and $W_{\text{down}} \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ff}}}$. Why does SwiGLU use $d_{\text{ff}} = \frac{8}{3} d_{\text{model}}$ instead of $4 d_{\text{model}}$?

    • Standard 2-matrix FFN at $d_{\text{ff}} = 4 d_{\text{model}}$: Has $2$ matrices of size $d_{\text{model}} \times 4 d_{\text{model}}$, giving
      $$P_{\text{std}} = 2 \cdot d_{\text{model}} \cdot (4 d_{\text{model}}) = 8\,d_{\text{model}}^2\quad\text{parameters}, \qquad \operatorname{FLOPs}_{\text{fwd}} = 16\,B\,d_{\text{model}}^2.$$
    • 3-matrix SwiGLU FFN at $d_{\text{ff}} = \frac{8}{3} d_{\text{model}}$: Has $3$ matrices ($W_{\text{gate}}, W_{\text{up}}, W_{\text{down}}$) of size $d_{\text{model}} \times d_{\text{ff}}$, so setting $d_{\text{ff}} = \frac{8}{3} d_{\text{model}}$ (rounded to the nearest multiple of $256$ for Tensor Core alignment) matches both parameters and FLOPs identically:
      $$P_{\text{SwiGLU}} = 3 \cdot d_{\text{model}} \cdot \left(\frac{8}{3} d_{\text{model}}\right) = 8\,d_{\text{model}}^2\quad\text{parameters}, \qquad \operatorname{FLOPs}_{\text{fwd}} = 16\,B\,d_{\text{model}}^2.$$

    3. Residual highways and forward activation memory footprint

    Wrapping the FFN block in a Pre-Norm residual connection (He et al., 2016; Xiong et al., 2020) gives the recurrence

    $$x^{(\ell)} = x^{(\ell-1)} + \operatorname{FFN}_\ell\!\left(\operatorname{RMSNorm}\bigl(x^{(\ell-1)}\bigr)\right).$$

    While inference can discard intermediate activations immediately after computing $x^{(\ell)}$, training must cache intermediate tensors from the forward pass in GPU HBM until the backward pass reaches layer $\ell$. For a batch of $B$ sequences of length $T$ (so $N_{\text{tok}} = B \cdot T$ tokens) in `bf16` ($2$ bytes per element):

    • Standard FFN activation cache per layer: Must save normalized input $\hat{x} \in \mathbb{R}^{N_{\text{tok}} \times d}$ ($2 N_{\text{tok}} d$ bytes) and pre-activation $z_{\text{up}} \in \mathbb{R}^{N_{\text{tok}} \times 4d}$ ($8 N_{\text{tok}} d$ bytes) = $10 N_{\text{tok}} d$ bytes per layer.
    • SwiGLU FFN activation cache per layer: Must save $\hat{x}$ ($2 N_{\text{tok}} d$ bytes), gate pre-activation $z_{\text{gate}} \in \mathbb{R}^{N_{\text{tok}} \times \frac{8}{3}d}$, and linear branch $z_{\text{up}} \in \mathbb{R}^{N_{\text{tok}} \times \frac{8}{3}d}$ = $\frac{38}{3} N_{\text{tok}} d \approx 12.67 N_{\text{tok}} d$ bytes per layer.

    4. Questions worth answering

    Why do high-performance implementations fuse $W_{\text{gate}}$ and $W_{\text{up}}$ into a single matrix of shape $(2 d_{\text{ff}}, d_{\text{model}})$?

    Because both $W_{\text{gate}} x$ and $W_{\text{up}} x$ multiply the exact same input tensor $x$! Concatenating them into $W_{\text{fused}} = \begin{bmatrix} W_{\text{gate}} \\ W_{\text{up}} \end{bmatrix}$ launches 1 large GEMM instead of 2 smaller GEMMs, reading $x$ from GPU memory only once and eliminating kernel-launch overhead.

    Why does the FFN block operate independently on each token position $t \in \{1, \dots, T\}$ in a Transformer?

    In a Transformer, cross-token mixing happens exclusively inside the Attention block. The FFN is a position-wise MLP applied identically to each token vector $x_{b,t} \in \mathbb{R}^{d_{\text{model}}}$, which means the FFN simply flattens $(B, T, d_{\text{model}})$ into a 2D batch $(B \cdot T, d_{\text{model}})$ for maximum GEMM efficiency.
