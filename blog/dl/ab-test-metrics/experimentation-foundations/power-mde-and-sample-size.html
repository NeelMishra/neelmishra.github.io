    Hypothesis Testing, Statistical Power ($1-\beta$), MDE & Sample Size Formulas

    October 2026 · ML System Design · Experiment Sizing & Sequential Testing

    Before launching any online A/B test, you must answer two sizing questions: "Given our daily active traffic, what is the smallest relative lift ($\text{MDE}$) we can reliably detect in 14 days?" and "How many users per arm ($n$) do we need so our false positive rate is $\alpha = 0.05$ and our statistical power is $1-\beta = 0.80$?" Here we derive the exact sample size equations from first principles, show why continuous dashboard peeking inflates Type I error past $25\%$, and introduce Sequential Testing ($\text{mSPRT}$) and False Discovery Rate ($\text{FDR}$) control.

    1. First-Principles Derivation of Sample Size & MDE

    Let $Y_{C,1}, \dots, Y_{C,n}$ and $Y_{T,1}, \dots, Y_{T,n}$ be independent user-level metric observations in Control and Treatment with population means $\mu_C, \mu_T$ and common variance $\sigma^2$. By the Central Limit Theorem, the difference in sample means $\hat{\Delta} = \bar{Y}_T - \bar{Y}_C$ is asymptotically normal:

    $$\hat{\Delta} \sim \mathcal{N}\!\left(\delta, \; \text{SE}^2\right), \qquad \text{where } \delta = \mu_T - \mu_C \;\text{ and }\; \text{SE} = \sqrt{\frac{\sigma_C^2}{n_C} + \frac{\sigma_T^2}{n_T}} \approx \sigma\sqrt{\frac{2}{n}}$$

    For a two-sided hypothesis test of $H_0: \delta = 0$ vs. $H_1: \delta \ne 0$ at significance level $\alpha$, we reject $H_0$ whenever $|\hat{\Delta}| / \text{SE} \ge z_{1-\alpha/2}$. To achieve statistical power $1 - \beta$ when the true effect is $\delta = \text{MDE}_{\text{abs}} > 0$ (ignoring the negligible probability of rejecting in the wrong tail), the critical threshold $z_{1-\alpha/2}\cdot \text{SE}$ must sit $z_{1-\beta}$ standard errors below the true mean $\delta$:

    $$\delta = \left(z_{1-\alpha/2} + z_{1-\beta}\right) \cdot \text{SE} = \left(z_{1-\alpha/2} + z_{1-\beta}\right) \sigma \sqrt{\frac{2}{n}}$$

    Solving for the required sample size $n$ per arm (or solving for the Minimum Detectable Effect $\text{MDE}_{\text{abs}}$):

    $$n = \frac{2\sigma^2 \left(z_{1-\alpha/2} + z_{1-\beta}\right)^2}{\delta_{\text{abs}}^2}, \qquad \text{MDE}_{\text{abs}} = \left(z_{1-\alpha/2} + z_{1-\beta}\right)\sigma\sqrt{\frac{2}{n}}$$
    The Famous $16\sigma^2 / \delta^2$ Interview Shortcut: At the industry-standard setting $\alpha = 0.05$ ($z_{0.975} = 1.96$) and $1-\beta = 0.80$ ($z_{0.80} = 0.8416$), we have $(1.96 + 0.8416)^2 = 2.8016^2 = 7.849$, so $2(7.849) = 15.70 \approx 16$: $$n_{\text{per arm}} \approx \frac{16\sigma^2}{\delta_{\text{abs}}^2} = \frac{16 \cdot \text{CV}^2}{\delta_{\text{rel}}^2}$$ where $\text{CV} = \sigma / \mu_C$ is the coefficient of variation and $\delta_{\text{rel}} = \delta_{\text{abs}} / \mu_C$ is the relative percentage lift! Notice the quadratic penalty: detecting a $2\times$ smaller lift requires $4\times$ as many users.

    1.1 Special Case: Binary Conversion Rate $p$ & Unequal Traffic Splits

    For a binary user conversion metric $Y_u \in \{0, 1\}$ with baseline conversion probability $p$, the variance is $\sigma^2 = p(1-p)$, giving:

    $$n_{\text{per arm}} \approx \frac{16 \, p(1-p)}{\left(p \cdot \delta_{\text{rel}}\right)^2} = \frac{16(1-p)}{p \cdot \delta_{\text{rel}}^2}$$

    What if total traffic $N$ is split unequally with fraction $q \in (0,1)$ in Treatment and $1-q$ in Control (e.g., a $10\% / 90\%$ ramp-up test)? Then:

    $$\text{SE}^2 = \frac{\sigma^2}{N q (1 - q)} \implies N_{\text{total}}(q) = \frac{1}{4 q(1-q)} N_{\text{total}}(0.5)$$

    A $50/50$ split ($q=0.5 \implies 4q(1-q) = 1$) minimizes variance. A $10/90$ split ($4(0.1)(0.9) = 0.36$) inflates the required total traffic by $1 / 0.36 = 2.78\times$!

    2. Continuous Peeking & Always-Valid Sequential Testing (mSPRT)

    In fixed-horizon testing, the $p$-value is valid only if you check it once at $n = n_{\text{target}}$. If an engineer checks the dashboard daily for 14 days and stops the test the first day $p_t < 0.05$, the actual Type I false positive rate jumps from $5\%$ to $\approx 22\%\text{–}30\%$ because the random walk $Z_t$ has multiple opportunities to cross the $\pm 1.96$ boundary.

    Modern experimentation platforms (Optimizely, Uber XP, Netflix) use the Mixture Sequential Probability Ratio Test (mSPRT), which mixes the likelihood ratio over a prior $\mathcal{N}(0, \tau^2)$ on the unknown effect size $\delta$. The resulting mixture likelihood ratio $\Lambda_t$ is a nonnegative martingale under $H_0$ with $\mathbb{E}_{H_0}[\Lambda_t] = 1$:

    $$\Lambda_t = \sqrt{\frac{V_t}{V_t + \tau^2}} \exp\!\left(\frac{\hat{\Delta}_t^2 \, \tau^2}{2 V_t (V_t + \tau^2)}\right), \qquad \text{where } V_t = \text{SE}_t^2 = \frac{2\sigma^2}{n_t}$$

    By Ville's Maximal Inequality for martingales, $\mathbb{P}_{H_0}\!\left(\sup_{t \ge 1} \Lambda_t \ge \frac{1}{\alpha}\right) \le \alpha$. Therefore, $p_t^{\text{anytime}} = \min\!\left(1, \min_{s \le t} \Lambda_s^{-1}\right)$ is an always-valid $p$-value that can be monitored after every single user without inflating Type I error!

    3. Multiple Hypothesis Testing: FWER vs. FDR

    When evaluating $K$ secondary metrics or $K$ treatment arms simultaneously, testing each at $\alpha = 0.05$ yields $1 - (1-\alpha)^K$ chance of at least one false positive.

    Correction Method Error Controlled Threshold Rule (sorted $p_{(1)} \le \dots \le p_{(K)}$) When to Use in A/B Testing
    Bonferroni / Holm Family-Wise Error Rate $\text{FWER} = \mathbb{P}(V \ge 1) \le \alpha$ $p_{(k)} \le \frac{\alpha}{K - k + 1}$ (Holm step-down) Strict launch gates across 3–5 primary/guardrail metrics or multiple treatment arms
    Benjamini–Hochberg (BH) False Discovery Rate $\text{FDR} = \mathbb{E}\!\left[\frac{V}{\max(R, 1)}\right] \le q$ Find largest $k^*$ with $p_{(k)} \le \frac{k}{K} q$; reject $1\dots k^*$ Exploring 50+ diagnostic, slice, or feature-level metrics on an experiment scorecard

    4. Worked Numerical Example: Sizing a Checkout Conversion Experiment

    Suppose an e-commerce site has baseline user purchase conversion rate $p_C = 4.0\%$ ($0.04$) and wants to detect a relative lift of $\delta_{\text{rel}} = +2.0\%$ (so $p_T = 4.08\%$, $\delta_{\text{abs}} = 0.0008$) at $\alpha = 0.05$ and $80\%$ power:

    $$n_{\text{per arm}} \approx \frac{15.70 \times 0.04 \times (1 - 0.04)}{(0.0008)^2} = \frac{15.70 \times 0.0384}{6.4 \times 10^{-7}} = \frac{0.60288}{6.4 \times 10^{-7}} \approx 942{,}000\text{ users per arm}$$

    Thus, total experiment sample size is $2n \approx 1.884\text{ million unique users}$. If the site receives $200{,}000$ new unique visitors per day, the test must run for at least $\lceil 1.884\text{M} / 200\text{k} \rceil = 10\text{ days}$ (and in practice 14 full days to capture two complete weekly day-of-week cycles).

    5. Production Python Implementation: Sizing, mSPRT & BH-FDR

    import numpy as np
from scipy import stats

def sample_size_per_arm(
    sigma: float,
    delta_abs: float,
    alpha: float = 0.05,
    power: float = 0.80,
    treatment_Allocation: float = 0.5,
) -> int:
    """Exact normal-approximation sample size per arm (or total if allocation != 0.5)."""
    z_alpha = stats.norm.ppf(1.0 - alpha / 2.0)
    z_beta = stats.norm.ppf(power)
    q = treatment_Allocation
    n_total = ((z_alpha + z_beta) ** 2 * (sigma ** 2)) / ((delta_abs ** 2) * q * (1.0 - q))
    return int(np.ceil(n_total * q))

def msprt_always_valid_pvalue(delta_hat: float, se: float, tau: float) -> float:
    """Computes the mSPRT always-valid p-value safe under continuous peeking."""
    v = se ** 2
    lambda_stat = np.sqrt(v / (v + tau ** 2)) * np.exp(
        (delta_hat ** 2 * tau ** 2) / (2.0 * v * (v + tau ** 2))
    )
    return float(min(1.0, 1.0 / lambda_stat))

def benjamini_hochberg(p_values: list[float], q: float = 0.05) -> list[bool]:
    """Returns boolean mask of discoveries controlling False Discovery Rate at q."""
    p = np.asarray(p_values, dtype=float)
    K = len(p)
    order = np.argsort(p)
    ranked_p = p[order]
    thresholds = (np.arange(1, K + 1) / K) * q
    passed = np.where(ranked_p <= thresholds)[0]
    reject = np.zeros(K, dtype=bool)
    if len(passed) > 0:
        max_idx = passed.max()
        reject[order[: max_idx + 1]] = True
    return reject.tolist()

if __name__ == "__main__":
    p_base = 0.04
    sigma_bin = np.sqrt(p_base * (1.0 - p_base))
    n_arm = sample_size_per_arm(sigma_bin, delta_abs=0.04 * 0.02)
    print(f"Required users per arm: {n_arm:,}")
    print("mSPRT p-value:", round(msprt_always_valid_pvalue(0.0012, 0.0004, tau=0.002), 5))

    6. Self-Check & Interview Exercises

    Exercise 1 — Why Do We Always Run Tests in Multiples of 7 Days?

    Suppose our power calculation says we reach $n_{\text{per arm}}$ in 4 days of traffic. Why is stopping an A/B test after 4 days (Tuesday–Friday) dangerous in consumer ML systems?

    Check solution

    User behavior exhibits strong day-of-week seasonality: weekend traffic (Saturday/Sunday) has a completely different mix of casual vs. high-intent users, mobile vs. desktop devices, and entertainment vs. work queries compared to Tuesday–Friday. Running for full 7-day multiples (typically 14 days) ensures every day of the week is weighted equally in the treatment effect estimate.
