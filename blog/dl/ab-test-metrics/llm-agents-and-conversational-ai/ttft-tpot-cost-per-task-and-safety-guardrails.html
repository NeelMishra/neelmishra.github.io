    TTFT, TPOT, Token Cost Per Resolved Task & Over-Refusal / Safety Guardrails

    October 2026 · 10 min read

    Deploying a larger model, adding chain-of-thought reasoning tokens, expanding RAG top-$K$ context, or tightening safety classifiers directly impacts three production guardrails: streaming latency ($\text{TTFT}$ and $\text{TPOT}$), inference unit economics ($\text{Cost Per Resolved Task}$), and safety precision ($\text{False Refusal Rate}$). Master the exact formulas and Service Level Objectives ($\text{SLOs}$) used to evaluate LLM serving and alignment in online A/B tests.

    1. Streaming LLM Latency Decomposition: TTFT, TPOT (ITL) & End-to-End Latency

    Unlike traditional REST microservices that return a complete JSON payload at once, autoregressive LLMs stream tokens $y_1, y_2, \dots, y_{M_{\text{out}}}$ as they are generated. A single end-to-end latency number is uninterpretable because a 500-token response naturally takes $10\times$ longer than a 50-token response. Production LLM telemetry decomposes request latency $L_{\text{E2E}}$ into two orthogonal phases corresponding to GPU compute-bound prefill and memory-bandwidth-bound decode:

    $$L_{\text{E2E}} = \underbrace{\operatorname{TTFT}}_{\text{Queueing + Retrieval + Prompt Prefill (+ Thinking)}} + \bigl(M_{\text{out}} - 1\bigr) \times \underbrace{\operatorname{TPOT}}_{\text{Mean Inter-Token Decode Latency}}.$$
    • Time-to-First-Token ($\operatorname{TTFT}$, tracked at $p_{50}, p_{90}, p_{99}$): The elapsed wall-clock time from when the user hits `Enter` ($t_{\text{req}}$) to when the first visible output token arrives at the client ($t_1$):
      $$\operatorname{TTFT} = t_1 - t_{\text{req}} = T_{\text{network+guardrail}} + T_{\text{RAG}} + T_{\text{queue}} + T_{\text{prefill}}(M_{\text{in}}) + T_{\text{reasoning}}(M_{\text{think}}).$$
      $\operatorname{TTFT}$ governs perceived responsiveness. In interactive chat, $p_{90}\,\operatorname{TTFT} > 1.5\text{–}2.0\text{s}$ significantly increases session abandonment; in inline IDE code completion, $p_{90}\,\operatorname{TTFT}$ must stay under $250\text{–}350\text{ ms}$.
    • Time-Per-Output-Token ($\operatorname{TPOT}$ / Inter-Token Latency $\operatorname{ITL}$): The average time between consecutive visible output tokens during autoregressive decoding:
      $$\operatorname{TPOT} = \frac{t_{M_{\text{out}}} - t_1}{M_{\text{out}} - 1} = \frac{1}{M_{\text{out}} - 1}\sum_{k=2}^{M_{\text{out}}} (t_k - t_{k-1}),\qquad \operatorname{Throughput} = \frac{1}{\operatorname{TPOT}}\text{ tokens/sec}.$$
      Human reading speed is roughly $4\text{–}6\text{ words/sec} \approx 6\text{–}8\text{ tokens/sec}$ ($\operatorname{TPOT} \approx 125\text{–}160\text{ ms/token}$). As long as $p_{95}\,\operatorname{TPOT} \le 50\text{ ms/token}$ ($\ge 20\text{ tok/s}$) without mid-stream stalls (chunk jitter caused by unchunked prefill preemption), faster decoding yields diminishing UX returns in text chat—whereas in agentic tool loops and whole-file code edits, $\operatorname{TPOT}$ directly dictates total wall-clock completion time!
    • Goodput under Latency SLOs: Serving infrastructure experiments (e.g., speculative decoding, FP8 quantization, chunked prefill) evaluate Goodput—the maximum requests/second per GPU replica that simultaneously satisfies both $p_{95}\,\operatorname{TTFT} \le \tau_{\text{TTFT}}$ and $p_{95}\,\operatorname{TPOT} \le \tau_{\text{TPOT}}$.

    2. Token Cost Per Resolved Task (CPRT) & KV-Cache Economics

    In LLM router and agent experiments, evaluating Cost Per Turn (or Cost Per API Call) is a classic trap: routing complex coding or support queries to a $5\times$ cheaper small model often cuts single-turn inference cost by $-70\%$, but forces the user or agent loop into $3\times$ more follow-up turns, tool retries, and human escalations!

    For task/session $s$, let $K_s$ be the number of LLM calls (turns + internal agent sub-calls), where call $k$ processes $M_{s,k}^{\text{in, cached}}$ cached prefix input tokens (at discounted unit cost $c_{\text{cache}}$), $M_{s,k}^{\text{in, uncached}}$ fresh input tokens (at unit cost $c_{\text{in}}$), and generates $M_{s,k}^{\text{out}} = M_{s,k}^{\text{think}} + M_{s,k}^{\text{vis}}$ output tokens (at unit cost $c_{\text{out}}$, typically $3\times\text{–}5\times$ higher than $c_{\text{in}}$ because decode is memory-bandwidth bound), plus external tool/search API costs $C_{s,k}^{\text{tool}}$. Total session compute cost is:

    $$C_s = \sum_{k=1}^{K_s} \Bigl(c_{\text{cache}}\,M_{s,k}^{\text{in, cached}} + c_{\text{in}}\,M_{s,k}^{\text{in, uncached}} + c_{\text{out}}\,M_{s,k}^{\text{out}} + C_{s,k}^{\text{tool}}\Bigr).$$

    Dividing total compute spend across all sessions by the number of successfully resolved tasks ($R_s \in \{0, 1\}$) gives the true economic efficiency metric, Cost Per Resolved Task ($\text{CPRT}$):

    $$\operatorname{CPRT} = \frac{\sum_{s=1}^N C_s}{\sum_{s=1}^N R_s} = \frac{\text{Mean Session Cost }\bar{C}}{\text{Task Resolution Rate }\bar{R}}.$$
    • KV-Cache Prefix Hit Rate ($\text{CHR}$): Multi-turn agents and system prompts rely heavily on prefix KV-cache reuse:
      $$\operatorname{KV\text{-}Cache\ Hit\ Rate} = \frac{\sum_{s,k} M_{s,k}^{\text{in, cached}}}{\sum_{s,k} \bigl(M_{s,k}^{\text{in, cached}} + M_{s,k}^{\text{in, uncached}}\bigr)}.$$
      A prompt-engineering change that inserts a dynamic timestamp or user-specific random UUID at the top of the system prompt invalidates prefix caching, crashing $\operatorname{CHR}$ from $85\%$ to $0\%$ and spiking both $\operatorname{TTFT}$ and $\operatorname{CPRT}$!

    3. Online Safety & Trust Guardrails: Attack Block Rate vs. False Refusal (Over-Refusal) Rate

    Production LLMs wrap generation in input/output safety guardrails and RLHF refusal alignment. In online experimentation, safety is a two-sided classification trade-off:

    1. Violative Output / Jailbreak Leak Rate (False Negative Rate on Unsafe Prompts): Estimated via an online high-precision audit judge on a stratified sample of production traffic, plus Prompt Injection Block Rate on tool-using agents.
    2. False Refusal / Over-Refusal Rate ($\text{FRR}$, False Positive Rate on Benign Prompts): An overly aggressive safety classifier or RLHF checkpoint frequently refuses completely benign prompts that happen to contain sensitive lexical triggers (e.g., a developer asking "How do I kill a zombie process in Linux?" or a historian asking about "trench warfare casualties in WWI").
      $$\operatorname{False\ Refusal\ Rate\ (FRR)} = \Pr\bigl(\text{Model Refuses or Preaches} \;\big|\; \text{Prompt is Benign}\bigr).$$
      In online A/B tests, a spike in $\operatorname{FRR}$ manifests immediately as a surge in Post-Refusal Thumbs-Down Rate and Immediate Prompt Rewording / Abandonment Rate.
    3. Groundedness / Uncited Claim Rate (in RAG Systems): Fraction of factual statements in the generated response that are not entailed by the retrieved source passages $\mathcal{D}_{\text{ret}}$, monitored continuously via an asynchronous NLI / faithfulness judge on a $1\%\text{–}5\%$ production sample.

    Worked numerical example: Cheap Model vs. Smart Router on Cost Per Resolved Task (CPRT)

    Compare two architectures over $10{,}000$ coding agent tasks:

    • Policy A (Small Model Only): Costs $\$0.008$ per turn, requires an average of $K_A = 4.5$ retry turns per session ($\bar{C}_A = \$0.036/\text{session}$), and resolves only $\bar{R}_A = 45\%$ of tasks.
      • $\operatorname{CPRT}_A = \frac{\$0.036}{0.45} = \mathbf{\$0.080\text{ per resolved task}}$ (plus $55\%$ frustrated users!).
    • Policy B (Difficulty Router: $70\%$ Small Model, $30\%$ Frontier Model): Blended cost is $\$0.022$ per turn, resolves tasks in $K_B = 2.0$ turns ($\bar{C}_B = \$0.044/\text{session}$), and resolves $\bar{R}_B = 78\%$ of tasks.
      • $\operatorname{CPRT}_B = \frac{\$0.044}{0.78} = \mathbf{\$0.0564\text{ per resolved task}}$—$29.5\%$ cheaper per resolved task while boosting task resolution by $+33\text{ percentage points}$!

    4. Python Implementation: TTFT/TPOT SLO Goodput & Delta-Method CPRT

    import numpy as np
from scipy import stats

def evaluate_llm_serving_and_cprt(
    ttft_ms: np.ndarray, tpot_ms: np.ndarray,
    session_cost_usd: np.ndarray, task_resolved: np.ndarray,
    is_refusal: np.ndarray, is_benign_audit: np.ndarray,
    ttft_slo_ms: float = 1500.0, tpot_slo_ms: float = 50.0
):
    """
    Computes TTFT/TPOT percentiles, Goodput SLO compliance rate,
    Cost Per Resolved Task (CPRT) with Delta Method SE, and False Refusal Rate.
    """
    slo_met = (ttft_ms <= ttft_slo_ms) & (tpot_ms <= tpot_slo_ms)
    cprt = float(np.sum(session_cost_usd) / np.sum(task_resolved))

    # Delta method linearized residual for CPRT = mean(Cost) / mean(Resolved)
    mean_res = float(np.mean(task_resolved))
    z_s = (session_cost_usd - cprt * task_resolved) / mean_res
    cprt_se = float(np.std(z_s, ddof=1) / np.sqrt(len(z_s)))

    benign_mask = (is_benign_audit == 1)
    false_refusal_rate = float(np.mean(is_refusal[benign_mask]))

    return {
        "TTFT_p50_ms": round(float(np.percentile(ttft_ms, 50)), 1),
        "TTFT_p95_ms": round(float(np.percentile(ttft_ms, 95)), 1),
        "TPOT_p50_ms": round(float(np.percentile(tpot_ms, 50)), 2),
        "TPOT_p95_ms": round(float(np.percentile(tpot_ms, 95)), 2),
        "SLO_Goodput_Compliance_%": round(float(100 * np.mean(slo_met)), 2),
        "Task_Resolution_Rate_%": round(100 * mean_res, 2),
        "Cost_Per_Resolved_Task_$": round(cprt, 4),
        "CPRT_SE_$": round(cprt_se, 5),
        "False_Refusal_Rate_Benign_%": round(100 * false_refusal_rate, 2),
    }

if __name__ == "__main__":
    rng = np.random.default_rng(303)
    N = 10_000
    ttft = rng.lognormal(6.4, 0.45, N)  # ~600ms median
    tpot = rng.lognormal(3.3, 0.25, N)  # ~27ms/tok median
    resolved = rng.binomial(1, 0.76, N)
    cost = rng.gamma(2.5, 0.018, N)
    benign = rng.binomial(1, 0.97, N)
    refusal = np.where(benign == 1, rng.binomial(1, 0.014, N), rng.binomial(1, 0.92, N))
    print(evaluate_llm_serving_and_cprt(ttft, tpot, cost, resolved, refusal, benign))

    5. Self-Check Questions

    A new reasoning model uses hidden "thinking tokens" before emitting its first visible answer token. Should $\operatorname{TTFT}$ be measured to the first hidden thinking token or the first visible answer token?

    Log both as distinct metrics! Infrastructure and GPU scheduling monitors need Server Time-to-First-Generated-Token ($\operatorname{TTFT}_{\text{server}}$) to verify prefill health, while product UX guardrails need User Time-to-First-Visible-Answer-Token ($\operatorname{TTFA}$) (alongside streamed thinking-summary indicators) because a user waiting $18\text{ seconds}$ for a simple factual query experiences $18\text{ seconds}$ of blocking latency.

    When running a 50/50 user-level A/B test comparing two different LLM checkpoints, why must both models be served with equivalent GPU capacity / batching load rather than giving the experimental model an idle dedicated cluster?

    If the Treatment model runs on a lightly loaded experimental GPU pool with zero queueing delay ($T_{\text{queue}} \approx 0$) while the Control model runs on a saturated production cluster ($p_{95}\,T_{\text{queue}} = 800\text{ ms}$), Treatment will show an artificial $\operatorname{TTFT}$ and engagement advantage that completely disappears when rolled out to $100\%$ of production traffic! Always match effective GPU utilization / concurrency per replica across arms.
