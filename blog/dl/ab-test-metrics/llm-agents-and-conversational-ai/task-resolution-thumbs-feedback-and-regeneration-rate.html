    Task Resolution / Deflection Rate, Thumbs Feedback, Copy Rate & Regeneration Rate

    October 2026 · 11 min read

    How do you know if a production LLM or RAG agent actually solved the user's problem when $98.5\%$ of users never click the Thumbs-Up or Thumbs-Down button? Learn how to define gaming-proof Automated Support Deflection Rate, correct non-random reporting bias in explicit Thumbs feedback via Inverse Propensity Weighting ($\text{IPW}$), and combine high-signal implicit telemetry—Copy/Export Rate, Regeneration Rate, and Prompt Scolding/Reformulation—into a calibrated Session Satisfaction OEC.

    1. Task Resolution Rate & True 24-Hour Automated Support Deflection

    In goal-oriented AI agents (customer support, IT helpdesk, banking/travel assistants, and coding agents), the primary North Star metric is whether the user's underlying task was resolved.

    In automated support systems, a naive metric called Raw Containment Rate ($1 - \frac{N_{\text{escalated to human}}}{N_{\text{sessions}}}$) is famously easy to game: if a bot refuses to show the "Connect to an Agent" button or loops the user in endless clarifying questions until they give up and close the window, Raw Containment Rate jumps to $95\%$ while customer satisfaction craters!

    Production AI agent platforms therefore define True Automated Resolution / Deflection Rate ($\text{TADR}$) as the conjunction of three conditions for session $s \in \{1, \dots, N_{\text{sessions}}\}$:

    1. Zero Human Escalation ($E_s = 0$): The session was handled end-to-end by the AI agent without transferring to a live human representative or opening a manual ticket.
    2. Zero Repeat Contact within $W = 24\text{–}72\text{ Hours}$ ($R_{s, 24\text{h}} = 0$): The user did not initiate another support session, call the phone hotline, or email support on the same issue within 24 hours.
    3. Verified Resolution State ($V_s = 1$): Either an explicit tool-verified state change occurred (e.g., refund processed, password reset completed, tracking link clicked), an explicit positive CSAT/Thumbs-Up was given, or an online classifier/LLM-Judge confirmed the final turn resolved the user's intent without user abandonment/scolding.
    $$\operatorname{TADR}_{24\text{h}} = \frac{1}{N_{\text{sessions}}} \sum_{s=1}^{N_{\text{sessions}}} \mathbf{1}\bigl[E_s = 0 \;\land\; R_{s, 24\text{h}} = 0 \;\land\; V_s = 1\bigr].$$

    2. Explicit Thumbs Up / Down Feedback & Correcting Reporting Bias via IPW

    Most LLM chat interfaces display a binary Thumbs Up ($Y_i = +1$) and Thumbs Down ($Y_i = 0$) widget on every assistant response $i$. However, explicit feedback suffers from two severe statistical pathologies:

    • Extreme Sparsity: The feedback response indicator $R_i \in \{0, 1\}$ is $1$ on only $0.4\%\text{–}1.8\%$ of assistant turns.
    • Missing-Not-At-Random (MNAR) Reporting Bias: Users are $3\times\text{–}8\times$ more likely to click a button when the model fails catastrophically (code throws a syntax error, model refuses a benign prompt, or formatting breaks) than when the model quietly gives a good answer. Worse, UI or latency changes alter the reporting propensity $\Pr(R_i = 1 \mid X_i)$ itself!

    Let $e(X_i) = \Pr(R_i = 1 \mid X_i)$ denote the probability that a user leaves explicit thumbs feedback given turn/session covariates $X_i$ (task category, response length, latency, code block presence, user historical rating frequency). Instead of the biased raw ratio $\frac{\sum_i R_i Y_i}{\sum_i R_i}$, we estimate population satisfaction using the Hajek / Self-Normalized Inverse Propensity Weighted (IPW) Estimator or Doubly Robust (DR) Estimator (combining $\hat{e}(X_i)$ with an implicit satisfaction reward model $\hat{\mu}(X_i) = \widehat{\mathbb{E}}[Y_i \mid X_i]$):

    $$\hat{\mu}_{\text{IPW}} = \frac{\sum_{i=1}^M \frac{R_i}{\hat{e}(X_i)}\,Y_i}{\sum_{i=1}^M \frac{R_i}{\hat{e}(X_i)}},\qquad \hat{\mu}_{\text{DR}} = \frac{1}{M}\sum_{i=1}^M \left[\hat{\mu}(X_i) + \frac{R_i}{\hat{e}(X_i)}\bigl(Y_i - \hat{\mu}(X_i)\bigr)\right].$$

    Notice why $\hat{\mu}_{\text{DR}}$ is ideal for online A/B testing: it uses dense implicit behavioral signals $\hat{\mu}(X_i)$ on $100\%$ of turns to slash variance, while the residual correction $\frac{R_i}{\hat{e}(X_i)}(Y_i - \hat{\mu}(X_i))$ guarantees asymptotic unbiasedness against ground-truth human ratings!

    3. Implicit Behavioral Signals: Copy Rate, Regeneration Rate & Prompt Scolding

    Because explicit ratings are sparse, production LLM ranking and routing experiments rely on high-volume implicit behavioral actions logged on every turn $i$:

    • Positive Implicit Value Signals:
      1. Copy / Code-Block Copy / Export / Share Rate: $\Pr(\text{Copy}_i = 1 \mid \text{Turn } i)$. When a user clicks "Copy code", highlights text and presses `Ctrl+C`, or exports to Docs/Gmail, it is a strong revealed-preference signal that the generation was useful enough to transfer into their workflow.
      2. Follow-Up Deepening vs. Healthy Session Termination: Ending the session after copying an answer or asking a natural next-step question indicates task progress.
    • Negative Implicit Frustration Signals (Lower is Better):
      1. Regeneration / Retry Rate: $\Pr(\text{Regenerate}_i = 1 \mid \text{Turn } i)$—the user clicks the "Regenerate response" icon or switches model selector on the same prompt because the answer was low quality.
      2. Immediate Prompt Reformulation / Edit Rate: The user edits their previous prompt within $<30\text{ seconds}$ because the assistant misunderstood their intent.
      3. Conversational Repair / User Scolding Rate: Detected via a lightweight rubrics classifier on the user's next turn $u_{i+1}$ matching frustration patterns (e.g., "No, I asked for...", "That doesn't work", "You forgot to...", "Stop apologizing").
      4. Generation Stop / Abort Rate: The user clicks the "Stop generating" square button mid-stream because the model started rambling or hallucinating in the wrong direction.

    Worked numerical example: Naive Thumbs-Up Ratio vs. Doubly Robust Satisfaction

    Suppose an LLM assistant handles $10{,}000$ turns split into $8{,}000$ Satisfied turns (true $Y=1$) and $2{,}000$ Dissatisfied turns (true $Y=0$, true satisfaction $= 80.0\%$).

    • Biased Reporting Mechanism: Satisfied users click Thumbs-Up only $1\%$ of the time ($80$ clicks), whereas dissatisfied users click Thumbs-Down $10\%$ of the time ($200$ clicks).
    • Naive Raw Thumbs-Up Rate: $\frac{80}{80 + 200} = \frac{80}{280} = \mathbf{28.6\%}$—off by more than $51$ percentage points from the true $80.0\%$ satisfaction!
    • IPW / Doubly Robust Correction: Weighting satisfied ratings by $1/\hat{e}_1 = 1/0.01 = 100$ and dissatisfied ratings by $1/\hat{e}_0 = 1/0.10 = 10$ recovers:
      $$\hat{\mu}_{\text{IPW}} = \frac{80 \times 100}{80 \times 100 + 200 \times 10} = \frac{8{,}000}{10{,}000} = \mathbf{80.0\%}.$$

    4. Python Implementation: Doubly Robust LLM Turn Satisfaction & Deflection OEC

    import numpy as np
from scipy import stats

def evaluate_llm_conversation_metrics(
    escalated: np.ndarray, repeat_24h: np.ndarray, verified_res: np.ndarray,
    copied: np.ndarray, regenerated: np.ndarray, scolded: np.ndarray,
    rating_obs: np.ndarray, rating_val: np.ndarray, prop_hat: np.ndarray, mu_implicit_hat: np.ndarray
):
    """
    Computes True 24h Support Deflection Rate (TADR), Implicit Signal Rates,
    Naive Thumbs-Up Rate, and Doubly-Robust (DR) Turn Satisfaction with SE.
    """
    tadr = float(np.mean((escalated == 0) & (repeat_24h == 0) & (verified_res == 1)))
    raw_containment = float(np.mean(escalated == 0))

    # Naive observed thumbs-up rate among rated turns
    naive_thumbs = float(np.sum(rating_obs * rating_val) / np.maximum(np.sum(rating_obs), 1))

    # Doubly-Robust (DR) estimator per turn
    dr_scores = mu_implicit_hat + (rating_obs / np.clip(prop_hat, 1e-4, 1.0)) * (rating_val - mu_implicit_hat)
    dr_mean = float(np.mean(dr_scores))
    dr_se = float(np.std(dr_scores, ddof=1) / np.sqrt(len(dr_scores)))

    return {
        "Raw_Containment_%": round(100 * raw_containment, 2),
        "True_24h_Deflection_TADR_%": round(100 * tadr, 2),
        "Copy_Rate_%": round(float(100 * np.mean(copied)), 2),
        "Regeneration_Rate_%": round(float(100 * np.mean(regenerated)), 2),
        "User_Scolding_Rate_%": round(float(100 * np.mean(scolded)), 2),
        "Naive_ThumbsUp_Rate_%": round(100 * naive_thumbs, 2),
        "DoublyRobust_Satisfaction_%": round(100 * dr_mean, 2),
        "DoublyRobust_SE_%": round(100 * dr_se, 3),
    }

if __name__ == "__main__":
    rng = np.random.default_rng(101)
    M = 20_000
    copied = rng.binomial(1, 0.22, M)
    regen = rng.binomial(1, 0.06, M)
    scold = rng.binomial(1, 0.05, M)
    # Latent satisfaction driven by implicit signals
    mu_true = np.clip(0.75 + 0.20 * copied - 0.45 * regen - 0.55 * scold, 0.05, 0.98)
    y_true = rng.binomial(1, mu_true)
    # Dissatisfied turns are 6x more likely to leave explicit thumbs feedback
    prop = np.where(y_true == 1, 0.012, 0.072)
    r_obs = rng.binomial(1, prop)
    esc = rng.binomial(1, 0.18, M)
    rep24 = rng.binomial(1, 0.09, M)
    ver = rng.binomial(1, 0.82, M)
    print(evaluate_llm_conversation_metrics(
        esc, rep24, ver, copied, regen, scold, r_obs, y_true, prop, mu_true + rng.normal(0, 0.03, M)
    ))

    5. Self-Check Questions

    Why is "Average Conversation Turn Length (Number of Turns per Session)" an ambiguous metric in conversational AI A/B tests?

    Like search dwell time, session turn count is U-shaped: in open-ended creative brainstorming or tutoring, more turns indicate deep engagement; in transactional coding, Q&A, or customer support, more turns indicate failure—the user is fighting with the model over multiple retries to get working code or a straight answer! Always disambiguate turn count by conditioning on whether intervening turns are conversational repair/scolding turns vs. new sub-task progression turns.

    A prompt-formatting treatment adds collapsible markdown code blocks with a larger, more prominent "Copy Code" button. Copy Rate jumps by $+19\%$. Does that prove the LLM's code quality improved?

    No! Changing the UI affordance of the Copy button directly inflates the observation propensity $\Pr(\text{Copy Click} \mid \text{Useful Code})$ without changing underlying answer quality. Whenever a treatment modifies feedback or copy UI elements, evaluate downstream task outcomes (e.g., Regeneration Rate, Scolding Rate, and follow-up error-paste turns).
