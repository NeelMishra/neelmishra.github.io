    Session Success Rate, Time-to-First-Click (TTFC) & Mean Reciprocal Click Rank (MRCR)

    October 2026 · Online Search Evaluation · Variance & Survival Analysis

    Suppose a new neural cross-encoder reranker increases offline $\text{nDCG}@10$ by $+2.1\%$, yet in your online A/B test, raw query Click-Through Rate ($\text{CTR}$) drops by $-0.8\%$ and queries per user drop by $-3.4\%$. Did the reranker fail—or did it place the right answer at rank $1$ so effectively that users stopped clicking three wrong results and stopped reformulating failed queries? To answer this rigorously, production search systems evaluate Session Success Rate ($\text{SSR}$) as the North Star OEC, paired with Time-to-First-Click ($\text{TTFC}$) and Online Mean Reciprocal Click Rank ($\text{MRCR}$) as high-sensitivity ranking drivers.

    1. Search Sessionization & Why Query-Level Denominators Fail

    Before defining any search metric, we must specify the unit of aggregation vs. the unit of randomization. In almost all search A/B tests, randomization happens at the user (or browser cookie / device) level $u \in \{1, \dots, N\}$. During the experiment window, user $u$ initiates $M_u \ge 1$ search sessions $s \in \mathcal{S}_u$, and each session $s$ consists of an ordered sequence of $K_s \ge 1$ queries:

    $$s = \bigl(q_{s,1},\, q_{s,2},\, \dots,\, q_{s,K_s}\bigr)$$

    How are sessions segmented from raw query logs? Production search engines use a two-rule boundary detector between consecutive queries $q_i$ and $q_{i+1}$ from the same user:

    1. Temporal Inactivity Boundary: If $t(q_{i+1}) - t_{\text{last\_event}}(q_i) > \tau_{\text{gap}}$ (standard $\tau_{\text{gap}} = 30\text{ minutes}$), start a new session.
    2. Semantic Task Boundary (Intent Segmentation): Even if $\Delta t \le 30\text{ minutes}$, if a user searches "python asyncio gather timeout" and $4$ minutes later searches "best thai restaurants near me", these belong to two distinct information needs. A lightweight bi-encoder + lexical overlap classifier splits $q_i$ and $q_{i+1}$ into separate task sessions whenever $\cos(\mathbf{e}(q_i), \mathbf{e}(q_{i+1})) < \theta_{\text{task}}$ and shared entity/category overlap is zero.
    Why Query-Level CTR Is Vulnerable to Denominator Contamination:

    Suppose $100$ users each have $1$ information need. In Control, poor ranking forces $40$ users to reformulate their query a second time ($140$ total queries, $80$ total clicks $\implies \text{Query CTR} = 80/140 = 57.1\%$). In Treatment, better query understanding eliminates half of those retry queries ($120$ total queries) while producing $82$ satisfied clicks ($\text{Query CTR} = 82/120 = 68.3\%$). Conversely, if retry queries had higher click propensity than initial broad queries, eliminating retries can artificially depress query-level CTR. Evaluating at the session or task level keeps the denominator anchored to distinct user intents.

    2. Session Success Rate (SSR): Mathematical Formulation

    A search session $s$ is successful if and only if the user satisfies their information or transactional need before abandoning the session. Because modern search engines satisfy users through three distinct pathways—long-dwell document reading, explicit downstream task completion, or on-SERP instant answers—we define the binary Session Success Indicator $Y_s \in \{0, 1\}$ as the logical union of three mutually reinforcing events:

    $$Y_s = \mathbb{I}\!\left[\underbrace{\Bigl(\max_{c \in \mathcal{C}(s)} d(c) \ge \tau_{\text{sat}}\Bigr)}_{\text{1. Long-Dwell Click}} \;\lor\; \underbrace{\Bigl(\mathcal{A}_{\text{term}}(s) \ne \emptyset\Bigr)}_{\text{2. Terminal Task Action}} \;\lor\; \underbrace{\Bigl(\mathcal{C}(s) = \emptyset \;\land\; G(s) = 1\Bigr)}_{\text{3. Good SERP Abandonment}}\right]$$

    where:

    • $\mathcal{C}(s)$ is the set of all organic result clicks across all queries in session $s$, and $d(c) = t_{\text{return}}(c) - t_{\text{click}}(c)$ is the post-click dwell time spent on the landing page (with $d(c) = \infty \ge \tau_{\text{sat}}$ if the user clicks out to the destination page and never returns to the SERP within the session window). Typically $\tau_{\text{sat}} = 30\text{ seconds}$ for web/enterprise search (calibrated via human side-by-side satisfaction surveys where $d(c) \ge 30\text{s}$ achieves $>85\%$ precision for true satisfaction).
    • $\mathcal{A}_{\text{term}}(s)$ is the set of domain-specific terminal conversion events occurring during or after a click, even if dwell time is short ($d(c) < 30\text{s}$):
      • E-Commerce Search: Add-to-Cart ($\text{ATC}$), Wishlist Save, or Purchase.
      • Enterprise / Workspace Search (Slack, Google Drive, Jira): File download, link copy, document edit, or message jump.
      • Maps / Local Search: "Navigate / Get Directions", "Call Business", or "Book Table".
    • $G(s) \in \{0, 1\}$ is the Good Abandonment indicator (derived in Note 02), which triggers when a clickless session displays a high-confidence Direct Answer / Knowledge Panel / AI Overview that remains in the user's viewport for $\ge \tau_{\text{read}}$ without a frustrated follow-up query.

    Graded & Friction-Penalized Session Success

    A session that succeeds on the first query in $4$ seconds is strictly better than a session that succeeds only after $3$ query reformulations and $2$ pogo-stick bounces. Many mature search teams therefore generalize binary $Y_s$ to a continuous Discounted Session Utility $U_s \in [0, 1]$:

    $$U_s = Y_s \cdot \gamma_{\text{query}}^{\,K_s - 1} \cdot \gamma_{\text{pogo}}^{\,B_s}, \qquad \gamma_{\text{query}} \in (0, 1],\;\; \gamma_{\text{pogo}} \in (0, 1]$$

    where $K_s$ is the number of queries in session $s$ and $B_s$ is the number of short-dwell bounces ($d(c) < 10\text{s}$) prior to the satisfied click. Setting $\gamma_{\text{query}} = 0.85$ and $\gamma_{\text{pogo}} = 0.80$ allows $U_s$ to capture efficiency improvements even when the user would eventually have persisted until finding the result in Control.

    User-Clustered Ratio Estimator & Delta Method Variance

    Across $N$ randomized users in a treatment group, let $M_u = |\mathcal{S}_u|$ be the number of sessions initiated by user $u$, and let $S_u = \sum_{s \in \mathcal{S}_u} Y_s$ be the number of successful sessions for user $u$. The overall Session Success Rate is the ratio of user totals:

    $$\widehat{\text{SSR}} = \frac{\sum_{u=1}^N S_u}{\sum_{u=1}^N M_u} = \frac{\bar{S}}{\bar{M}}$$

    Because heavy users generate dozens of sessions whose success rates are correlated ($M_u$ is random and $\operatorname{Cov}(S_u, M_u) > 0$), treating $\sum_u M_u$ as a set of independent Bernoulli trials underestimates the standard error by $20\%\text{–}50\%$. By the Delta Method, each user $u$ has a linearized influence value $L_u$:

    $$L_u = \frac{1}{\bar{M}}\bigl(S_u - \widehat{\text{SSR}}\cdot M_u\bigr), \qquad \widehat{\operatorname{Var}}\bigl(\widehat{\text{SSR}}\bigr) = \frac{1}{N(N-1)}\sum_{u=1}^N (L_u - \bar{L})^2 = \frac{s_L^2}{N}$$

    Always check $\Delta \bar{M} = \bar{M}_T - \bar{M}_C$ alongside $\Delta \widehat{\text{SSR}}$: if $\bar{M}$ changes significantly, verify whether users are returning more often (positive retention) or splitting single intents across broken sessions.

    3. Time-to-First-Click (TTFC): Distribution, Log-Transform & Survival Analysis

    Time-to-First-Click ($\text{TTFC}$) measures the elapsed time from the moment the SERP finishes rendering in the client viewport ($t_{\text{render},q}$) to the user's first result click ($t_{\text{click},1,q}$):

    $$T_q = t_{\text{click},1,q} - t_{\text{render},q} > 0$$

    Crucially, $T_q$ must be measured from client-side paint / render time (`performance.mark('serp_first_contentful_paint')`), not from backend query arrival time. If $T_q$ is computed from backend arrival time, any backend latency regression ($\Delta \text{Latency} = +150\text{ms}$) mechanically inflates $\text{TTFC}$ even if ranking quality is unchanged!

    Why Raw Mean TTFC Fails and How to Fix It

    In production logs, $T_q$ follows a heavily right-skewed Log-Normal or Weibull distribution: the median $\text{TTFC}$ is typically $1.8\text{s}\text{–}3.2\text{s}$, but a user who leaves a browser tab open while answering a phone call and clicks $12\text{ minutes}$ ($720\text{s}$) later contributes $300\times$ the median to a raw arithmetic mean, destroying statistical power. We use three complementary estimators:

    1. Winsorized Log-Mean (Geometric Mean $\text{TTFC}$): Cap $T_q$ at a ceiling $\tau_{\max}$ (typically $60\text{s}$ or $120\text{s}$) and floor at $\tau_{\min} = 0.1\text{s}$ (filtering bot clicks), then average on the log scale:
      $$\widetilde{T}_q = \min\bigl(\max(T_q, \tau_{\min}), \tau_{\max}\bigr), \qquad \mu_{\ln T} = \frac{\sum_{u=1}^N \sum_{q \in \mathcal{Q}_{c,u}} \ln \widetilde{T}_q}{\sum_{u=1}^N |\mathcal{Q}_{c,u}|}, \qquad \text{GM-TTFC} = \exp(\mu_{\ln T})$$
      Because $\Delta \mu_{\ln T} = \mu_{\ln T, T} - \mu_{\ln T, C} \approx \frac{\text{GM-TTFC}_T - \text{GM-TTFC}_C}{\text{GM-TTFC}_C}$, a difference in log-means directly estimates the relative percentage change in geometric mean $\text{TTFC}$ while reducing variance by $3\times\text{–}8\times$ compared to the raw mean.
    2. Qualified-Click TTFC ($\text{TTFC}_{\text{sat}}$): Only measure $T_q$ when the first click is a satisfied click ($d(c_1) \ge \tau_{\text{sat}}$). Otherwise, a sensational clickbait snippet that tricks users into clicking instantly at $T_q = 0.9\text{s}$ and bouncing back $3\text{s}$ later would look like a "win" on raw $\text{TTFC}$.
    3. Censored Survival / Click-Within-$t$ Rate: Because $T_q$ is only defined on clicked queries $\mathcal{Q}_c \subset \mathcal{Q}$, conditioning on $\mathcal{Q}_c$ introduces selection bias if Treatment changes overall click propensity. For example, if Treatment helps users click on hard tail queries that previously had zero clicks, those newly clicked hard queries take longer to scan ($T_q \approx 8\text{s}$), which can artificially raise conditional $\mathbb{E}[T_q \mid \text{Click}]$! To eliminate conditioning bias, define an unconditional survival / cumulative incidence metric over all queries $\mathcal{Q}$:
      $$F_{\text{sat}}(\tau) = \Pr\bigl(\text{Satisfied Click occurs with } T_q \le \tau\bigr) = \frac{1}{|\mathcal{Q}|}\sum_{q \in \mathcal{Q}} \mathbb{I}\!\left[\text{SatClick}_1(q) \;\land\; T_q \le \tau\right]$$
      Evaluating $F_{\text{sat}}(5\text{s})$ ("Fraction of all queries resulting in a satisfied first click within $5$ seconds") has fixed denominator $|\mathcal{Q}|$, requires no imputation for unclicked queries, and is immune to selection bias.

    The Rich Snippet / UI Paradox for TTFC

    Be careful when interpreting $\text{TTFC}$ across UI vs. ranking experiments:

    • Pure Ranking Experiment (Same UI): Moving the most relevant item from Rank $4$ to Rank $1$ reduces eye-fixation scan path length, so $\text{TTFC}\downarrow$ is unambiguously positive.
    • Snippet / UI Experiment (Adding Price, Ratings, Code Previews, or Longer Summaries): Users spend an extra $+0.4\text{s}$ reading richer metadata on the SERP before clicking, so $\text{TTFC}$ increases slightly ($\text{TTFC}\uparrow$), while post-click Pogo-Sticking drops sharply ($\text{Pogo}\downarrow$) and post-click conversion rises ($\text{CVR}\uparrow$) because users pre-qualify their clicks on the SERP.

    4. Online Mean Reciprocal Click Rank (MRCR)

    In offline evaluation, Mean Reciprocal Rank ($\text{MRR}$) uses human-labeled ground truth. In online A/B testing, we define Mean Reciprocal Click Rank ($\text{MRCR}$)—and specifically Satisfied Mean Reciprocal Click Rank ($\text{sMRCR}$)—using the rank position $r_{\text{sat}}(q) \in \{1, 2, \dots, K\}$ of the first satisfied click on query $q$:

    $$\text{sMRCR}_{\text{cond}} = \frac{1}{|\mathcal{Q}_{\text{sat}}|}\sum_{q \in \mathcal{Q}_{\text{sat}}} \frac{1}{r_{\text{sat}}(q)}, \qquad \text{sMRCR}_{\text{all}} = \frac{1}{|\mathcal{Q}|}\sum_{q \in \mathcal{Q}} \frac{\mathbb{I}[q \in \mathcal{Q}_{\text{sat}}]}{r_{\text{sat}}(q)}$$

    Pairing $\text{sMRCR}$ with $\text{TTFC}$ gives a clean diagnostic $2\times 2$ matrix in any search experiment:

    Observed $\text{sMRCR}$ Shift Observed $\text{TTFC}$ Shift Diagnostic Interpretation
    $\text{sMRCR} \uparrow$ (clicks move closer to Rank 1) $\text{TTFC} \downarrow$ (users click faster) True Ranking Improvement: Relevant items moved to higher ranks, reducing visual scan depth and time.
    $\text{sMRCR} \uparrow$ (clicks move closer to Rank 1) $\text{TTFC} \uparrow$ (users take longer before clicking) Snippet / Cognitive Load Effect or Client Latency: Users find the answer higher up, but either read a richer snippet longer or experience slower client rendering.
    $\text{sMRCR} \downarrow$ (clicks move to lower ranks) $\text{TTFC} \downarrow$ (users click faster) UI / Visual Salience Distraction: Thumbnails or badges at Ranks 3–5 draw fast impulsive clicks away from Rank 1 (check Pogo-Sticking rate!).
    $\text{sMRCR} \downarrow$ (clicks move to lower ranks) $\text{TTFC} \uparrow$ (users take longer to click) Ranking Degradation: Top results are less relevant; users must scroll further down the page and spend more time hunting for a clickable result.

    5. Worked Numerical Example: Delta Method on Session Success & Log-TTFC

    Consider a miniature illustration with $N_C = 3$ Control users and $N_T = 3$ Treatment users (scaled in production to $N \sim 10^6$). For each user $u$, we log total sessions $M_u$, successful sessions $S_u$, and the post-render click times $T_{u,q}$ (in seconds) for their clicked queries:

    Group & User $u$ Sessions $M_u$ Successes $S_u$ Clicked Query Times $T_{u,q}$ (s) Log-Times $\ln T_{u,q}$
    Control $u=1$ $4$ $2$ $[3.0,\, 5.0,\, 4.0]$ $[1.0986,\, 1.6094,\, 1.3863]$ (sum $= 4.0943$)
    Control $u=2$ $2$ $1$ $[2.5,\, 6.0]$ $[0.9163,\, 1.7918]$ (sum $= 2.7081$)
    Control $u=3$ $4$ $2$ $[4.5,\, 3.5,\, 5.5]$ $[1.5041,\, 1.2528,\, 1.7047]$ (sum $= 4.4616$)
    Treatment $u=1$ $3$ $2$ $[1.8,\, 2.2]$ $[0.5878,\, 0.7885]$ (sum $= 1.3763$)
    Treatment $u=2$ $2$ $2$ $[1.5,\, 2.0]$ $[0.4055,\, 0.6931]$ (sum $= 1.0986$)
    Treatment $u=3$ $3$ $2$ $[2.1,\, 1.9,\, 2.4]$ $[0.7419,\, 0.6419,\, 0.8755]$ (sum $= 2.2593$)

    Step 1 — Session Success Rate ($\widehat{\text{SSR}}$):

    • Control: $\sum M_u = 10$, $\sum S_u = 5 \implies \widehat{\text{SSR}}_C = 5/10 = 50.0\%$. Notice that for every Control user, $S_u - 0.5 M_u = 0$, illustrating zero cluster residual in this symmetric toy sample.
    • Treatment: $\sum M_u = 8$ (fewer sessions needed or fewer broken retries), $\sum S_u = 6 \implies \widehat{\text{SSR}}_T = 6/8 = 75.0\%$ ($+25.0\text{ pp}$ lift).

    Step 2 — Geometric Mean TTFC via User-Clustered Delta Method:

    • Control: Total clicked queries $\sum C_u = 3 + 2 + 3 = 8$. Total $\sum \ln T = 4.0943 + 2.7081 + 4.4616 = 11.2640$. $$\mu_{\ln T, C} = \frac{11.2640}{8} = 1.4080 \implies \text{GM-TTFC}_C = \exp(1.4080) = 4.088\text{ s}$$
    • Treatment: Total clicked queries $\sum C_u = 2 + 2 + 3 = 7$. Total $\sum \ln T = 1.3763 + 1.0986 + 2.2593 = 4.7342$. $$\mu_{\ln T, T} = \frac{4.7342}{7} = 0.6763 \implies \text{GM-TTFC}_T = \exp(0.6763) = 1.967\text{ s}$$
    • Relative TTFC Reduction: $$\frac{\text{GM-TTFC}_T - \text{GM-TTFC}_C}{\text{GM-TTFC}_C} = \frac{1.967 - 4.088}{4.088} = -51.9\%$$

    6. Production Python Implementation

    The script below computes user-clustered Session Success Rate ($\text{SSR}$), Winsorized Log-Mean TTFC, Unconditional Fast-Satisfied-Click Rate $F_{\text{sat}}(5\text{s})$, and Satisfied Mean Reciprocal Click Rank ($\text{sMRCR}$) using the exact Delta Method variance estimator. 

    import numpy as np
from dataclasses import dataclass
from typing import List, Dict
from scipy import stats

@dataclass
class QueryEvent:
    user_id: int
    session_id: int
    has_click: bool
    first_click_rank: int       # 0 if no click, else 1..K
    ttfc_sec: float             # NaN or 0 if no click
    max_dwell_sec: float        # Max post-click dwell on this query
    terminal_action: bool       # E.g. add-to-cart, download, copy
    good_abandonment: bool      # SERP answer card viewport read without retry

def delta_method_ratio_test(
    num_c: np.ndarray, den_c: np.ndarray,
    num_t: np.ndarray, den_t: np.ndarray
) -> Dict[str, float]:
    """
    Two-sample Welch z-test for a user-clustered ratio metric R = sum(Y_u) / sum(X_u)
    using Delta Method linearization L_u = (Y_u - R_hat * X_u) / mean(X).
    """
    r_c = num_c.sum() / den_c.sum()
    r_t = num_t.sum() / den_t.sum()

    lin_c = (num_c - r_c * den_c) / den_c.mean()
    lin_t = (num_t - r_t * den_t) / den_t.mean()

    var_c = np.var(lin_c, ddof=1) / len(lin_c)
    var_t = np.var(lin_t, ddof=1) / len(lin_t)

    se_diff = np.sqrt(var_c + var_t)
    diff = r_t - r_c
    z_stat = diff / se_diff if se_diff > 0 else 0.0
    p_val = 2.0 * (1.0 - stats.norm.cdf(abs(z_stat)))

    return {
        "control": float(r_c),
        "treatment": float(r_t),
        "abs_diff": float(diff),
        "rel_lift_pct": float(100.0 * diff / r_c) if r_c != 0 else np.nan,
        "se": float(se_diff),
        "z_stat": float(z_stat),
        "p_value": float(p_val),
    }

def evaluate_search_ab_test(
    events_c: List[QueryEvent],
    events_t: List[QueryEvent],
    dwell_sat_sec: float = 30.0,
    ttfc_cap_sec: float = 60.0,
    fast_click_tau: float = 5.0,
) -> Dict[str, Dict[str, float]]:
    def aggregate_by_user(events: List[QueryEvent]):
        # Group into sessions per user
        user_sessions = {}
        user_queries = {}
        for ev in events:
            user_sessions.setdefault(ev.user_id, {}).setdefault(ev.session_id, []).append(ev)
            user_queries.setdefault(ev.user_id, []).append(ev)

        users = sorted(user_queries.keys())
        m_u, s_u = [], []
        q_u, fast_sat_q_u, smrcr_sum_u = [], [], []
        clicked_q_u, log_ttfc_sum_u = [], []

        for u in users:
            sessions = user_sessions[u]
            m_u.append(len(sessions))
            succ_count = 0
            for _, s_events in sessions.items():
                has_long_dwell = any(e.has_click and e.max_dwell_sec >= dwell_sat_sec for e in s_events)
                has_terminal = any(e.terminal_action for e in s_events)
                no_clicks = all(not e.has_click for e in s_events)
                has_good_aband = no_clicks and any(e.good_abandonment for e in s_events)
                if has_long_dwell or has_terminal or has_good_aband:
                    succ_count += 1
            s_u.append(succ_count)

            q_list = user_queries[u]
            q_u.append(len(q_list))
            fast_sat = 0
            smrcr_sum = 0.0
            c_cnt = 0
            l_ttfc = 0.0
            for e in q_list:
                is_sat_click = e.has_click and (e.max_dwell_sec >= dwell_sat_sec or e.terminal_action)
                if is_sat_click and e.first_click_rank > 0:
                    smrcr_sum += 1.0 / e.first_click_rank
                    if e.ttfc_sec <= fast_click_tau:
                        fast_sat += 1
                if e.has_click and e.ttfc_sec > 0:
                    c_cnt += 1
                    clipped_t = np.clip(e.ttfc_sec, 0.1, ttfc_cap_sec)
                    l_ttfc += np.log(clipped_t)
            fast_sat_q_u.append(fast_sat)
            smrcr_sum_u.append(smrcr_sum)
            clicked_q_u.append(c_cnt)
            log_ttfc_sum_u.append(l_ttfc)

        return (
            np.array(s_u, dtype=float), np.array(m_u, dtype=float),
            np.array(fast_sat_q_u, dtype=float), np.array(smrcr_sum_u, dtype=float),
            np.array(q_u, dtype=float),
            np.array(log_ttfc_sum_u, dtype=float), np.array(clicked_q_u, dtype=float),
        )

    s_c, m_c, fs_c, mrcr_c, q_c, lttfc_c, cq_c = aggregate_by_user(events_c)
    s_t, m_t, fs_t, mrcr_t, q_t, lttfc_t, cq_t = aggregate_by_user(events_t)

    # Filter to users with >=1 clicked query for conditional log-TTFC
    mask_c, mask_t = cq_c > 0, cq_t > 0

    return {
        "Session_Success_Rate": delta_method_ratio_test(s_c, m_c, s_t, m_t),
        "Unconditional_sMRCR": delta_method_ratio_test(mrcr_c, q_c, mrcr_t, q_t),
        "Fast_Sat_Click_5s_Rate": delta_method_ratio_test(fs_c, q_c, fs_t, q_t),
        "Log_TTFC_Conditional": delta_method_ratio_test(
            lttfc_c[mask_c], cq_c[mask_c], lttfc_t[mask_t], cq_t[mask_t]
        ),
    }

    7. Self-Check & ML System Design Interview Exercises

    1. Your team launches a heavy cross-encoder reranker that adds $+180\text{ms}$ to p95 backend latency. You notice that backend-logged $\text{TTFC}$ increased by $+140\text{ms}$, while client-render-logged $\text{TTFC}$ decreased by $-40\text{ms}$. Which metric reflects ranking relevance, and should you ship?

    Client-render-logged $\text{TTFC}$ ($-40\text{ms}$) reflects the true visual search improvement once the SERP is visible on screen, whereas backend-logged $\text{TTFC}$ conflates network/inference latency ($+180\text{ms}$) with post-render scan time ($-40\text{ms}$, net $+140\text{ms}$). However, users experience total wall-clock time from pressing Enter to clicking! You should evaluate Total Time-to-Satisfied-Click from Query Submission alongside the latency guardrail—and distill or quantize the cross-encoder (or restrict top-$K$ reranking depth) so that the $-40\text{ms}$ scan-time savings are not wiped out by a $+180\text{ms}$ serving regression.

    2. In an e-commerce search test, Session Success Rate (defined purely via dwell $\ge 30\text{s}$) drops by $-1.2\%$, yet Purchase Conversion Rate increases by $+2.4\%$. How could a better search ranker reduce $30\text{s}$ dwell clicks?

    In e-commerce (especially repeat grocery or consumable purchases like "aa batteries 24 pack"), when the exact desired item is ranked at position $1$ with an inline "Add to Cart" button on the SERP card—or when the user clicks onto the product page, immediately clicks "Buy Now" in $8$ seconds, and returns—dwell time is under $30\text{s}$! Defining Session Success purely via $d(c) \ge 30\text{s}$ misclassifies fast transactional completions as bounces. Including $\mathcal{A}_{\text{term}}(s) \ne \emptyset$ (Add-to-Cart, Purchase, Save) inside the Session Success union resolves the contradiction.

    3. Why can conditional $\text{TTFC}$ (computed over clicked queries $\mathcal{Q}_c$) increase even when the ranking model strictly improves at every rank position?

    This is classic post-treatment selection bias (collider bias). Suppose in Control, $10\%$ of queries are complex informational tail queries where the SERP is so poor that users abandon without clicking (so these queries are excluded from $\mathcal{Q}_{c,C}$). In Treatment, the improved ranker surfaces a helpful result at Rank $4$ on these hard queries, causing users to scan Ranks $1\text{–}4$ for $7.5\text{s}$ and click. Even if every existing query's click time improved from $2.2\text{s} \to 2.0\text{s}$, adding newly rescued hard queries with $T_q = 7.5\text{s}$ into $\mathcal{Q}_{c,T}$ raises the conditional average $\mathbb{E}[T_q \mid \text{Click}]$. Measuring the unconditional cumulative incidence $F_{\text{sat}}(\tau) = \Pr(\text{SatClick} \land T_q \le \tau)$ over all queries $\mathcal{Q}$ eliminates this bias.
