    Modern LLM, RAG, Code & Judge Metrics: Unbiased $\text{pass}@k$, $\text{Maj}@k$, the RAGAS Triad, FActScore, Bradley–Terry Elo, and Judge Debiasing

    Open-ended reasoning, code synthesis, Retrieval-Augmented Generation (RAG), and instruction following cannot be evaluated with $n$-gram overlap alone. In this final chapter of the Evaluation Metrics series, we derive the unbiased hypergeometric $\text{pass}@k$ estimator for functional code and math verification, compare $\text{pass}@k$ against Self-Consistency $\text{Maj}@k$, formalize the four metrics of the RAGAS Triad (Context Precision, Context Recall, Faithfulness, and Answer Relevance) alongside atomic FActScore, and derive the statistical mechanics of LLM-as-a-Judge: pairwise Bradley–Terry MLE vs. sequential Elo, Length-Controlled Win Rate (LC-AlpacaEval), and the Rogan–Gladen prevalence correction for imperfect LLM judges.

    1. Code Synthesis & Verifiable Reasoning: Unbiased $\text{pass}@k$, $\text{Maj}@k$, and Exact Match

    1.1 Why Naive $\text{pass}@k$ Has High Variance — and the Unbiased Hypergeometric Estimator

    In code generation (HumanEval, MBPP, SWE-bench, LiveCodeBench) and competition mathematics (MATH, AIME), an LLM samples $k$ independent candidate solutions $(y_1, \dots, y_k) \sim p_\theta(y \mid x)$ at temperature $T > 0$. A deterministic unit-test suite or symbolic verifier checks whether each sample $y_j$ is functionally correct.

    $\text{pass}@k$ is the probability that at least one of the $k$ sampled solutions passes all unit tests. However, drawing just $k$ samples (say $k=1$ or $k=10$) once per problem produces noisy binary $\{0, 1\}$ estimates. Instead, Chen et al. (2021, Codex) showed that if we draw $n \ge k$ total samples for a problem (e.g., $n = 200$) and observe that $c \in \{0, 1, \dots, n\}$ of them pass the unit tests, we can compute the minimum-variance unbiased estimator (MVUE) of $\text{pass}@k$ by computing the exact hypergeometric probability that a uniformly chosen subset of size $k$ from the $n$ samples contains at least one of the $c$ correct solutions:

    $$\widehat{\text{pass}@k} = 1 - \frac{\binom{n - c}{k}}{\binom{n}{k}} = 1 - \prod_{j=0}^{k-1} \frac{n - c - j}{n - j}$$
    Why Naive $1 - (1 - \hat{p})^k$ Is Biased: It is tempting to estimate $\hat{p} = c/n$ and plug it into the binomial formula $1 - (1 - \hat{p})^k$. However, because $f(p) = 1 - (1-p)^k$ is strictly concave in $p$ for $k \ge 2$, Jensen's Inequality guarantees $\mathbb{E}\bigl[1 - (1 - \hat{p})^k\bigr] < 1 - (1 - p)^k$—meaning the plug-in binomial formula systematically underestimates $\text{pass}@k$ at finite $n$! The hypergeometric product formula above is exact and numerically stable.

    1.2 Majority Voting ($\text{Maj}@k$ / Self-Consistency) and the Verification Gap

    Note that achieving a high $\text{pass}@64$ requires an external oracle verifier (such as a compiler or unit-test runner) at inference time to pick the winning sample among the 64 candidates. When no external verifier is available at test time, Wang et al. (2023) introduced Self-Consistency ($\text{Maj}@k$ or $\text{cons}@k$), which extracts the final canonical answer $a(y_j)$ from each of the $k$ reasoning chains and selects the most frequent answer:

    $$\hat{a}_{\text{Maj}@k} = \arg\max_{a} \sum_{j=1}^{k} \mathbb{I}\bigl[a(y_j) = a\bigr], \qquad \text{Maj}@k = \mathbb{I}\bigl[\hat{a}_{\text{Maj}@k} = a^*\bigr]$$

    The gap $\text{pass}@k - \text{Maj}@k$ is known as the Verification (or Selection) Gap: it measures how often the model already knows how to generate a correct reasoning path somewhere in its distribution ($\text{pass}@k$) but fails to assign high enough probability mass to make it the mode ($\text{Maj}@k$). Reinforcement Learning with Verifiable Rewards (RLVR / GRPO) primarily works by compressing probability mass from the $\text{pass}@k$ tail into $\text{pass}@1$ and $\text{Maj}@k$.

    1.3 Exact Match (EM) and Token-Level $F_1$

    For extractive and short-form question answering (SQuAD, HotpotQA, Natural Questions), predictions are normalized (lowercased, punctuation/articles stripped) and scored via:

    $$\text{EM}(\hat{y}, y) = \mathbb{I}[\text{norm}(\hat{y}) = \text{norm}(y)], \qquad F_{1,\text{token}}(\hat{y}, y) = \frac{2\,|\mathcal{T}(\hat{y}) \cap \mathcal{T}(y)|}{|\mathcal{T}(\hat{y})| + |\mathcal{T}(y)|}$$

    2. Retrieval-Augmented Generation (RAG): The RAGAS Triad

    A Retrieval-Augmented Generation (RAG) pipeline has two distinct failure points: (1) the Retriever might fail to fetch the relevant passages from the vector/hybrid index, or (2) the Generator LLM might ignore the retrieved passages and hallucinate unsupported claims. Evaluating only the final answer makes it impossible to know which component broke.

    Es et al. (2024, RAGAS) and TruLens formalized the RAG Triad over query $q$, retrieved context list $C = (c_1, \dots, c_K)$, generated answer $a$, and ground-truth reference answer $y$:

    2.1 Retriever Evaluation: Context Precision@$K$ and Context Recall

    1. Context Precision@$K$: Let $v_k \in \{0, 1\}$ indicate whether retrieved chunk $c_k$ is relevant to answering $q$. Context Precision@$K$ is identical to Average Precision over the retrieved context chunks, rewarding retrievers that rank relevant chunks at the very top of the context window (preventing "Lost in the Middle" degradation):
      $$\text{Context Precision@}K = \frac{\sum_{k=1}^{K} \left(\frac{1}{k}\sum_{i=1}^{k} v_i\right) v_k}{\sum_{k=1}^{K} v_k}$$
    2. Context Recall: Decompose the ground-truth reference answer $y$ into atomic sentences/claims $\mathcal{S}(y) = \{y_1, \dots, y_L\}$. Context Recall measures the fraction of reference claims that are supported by (entailed by) the retrieved context $C$:
      $$\text{Context Recall}(C, y) = \frac{\bigl|\{\,y_l \in \mathcal{S}(y) : C \models y_l\,\}\bigr|}{|\mathcal{S}(y)|} \in [0, 1]$$

    2.2 Generator Evaluation: Faithfulness (Groundedness) and Answer Relevance

    1. Faithfulness (Groundedness / Hallucination-Free Rate): Decompose the model's generated answer $a$ into atomic statements $\mathcal{S}(a) = \{s_1, \dots, s_m\}$, and use an NLI verifier or judge LLM to check whether each statement $s_j$ can be inferred directly from the retrieved context $C$:
      $$\text{Faithfulness}(a, C) = \frac{\bigl|\{\,s_j \in \mathcal{S}(a) : C \models s_j\,\}\bigr|}{|\mathcal{S}(a)|} \in [0, 1]$$
      The complement $1 - \text{Faithfulness}(a, C)$ is the Intrinsic/Extrinsic Context Hallucination Rate.
    2. Answer Relevance: A model can achieve $\text{Faithfulness} = 1.0$ by simply copying a random sentence from $C$ that does not actually answer the user's question $q$! To measure whether $a$ directly addresses $q$ without needing a ground-truth answer, RAGAS prompts an LLM to reverse-engineer $M$ questions $\{\hat{q}_1, \dots, \hat{q}_M\}$ that $a$ appears to be answering, and averages their embedding cosine similarity with the original query $q$:
      $$\text{Answer Relevance}(a, q) = \frac{1}{M}\sum_{m=1}^{M} \frac{\mathbf{e}_q^\top \mathbf{e}_{\hat{q}_m}}{\|\mathbf{e}_q\|_2\,\|\mathbf{e}_{\hat{q}_m}\|_2}$$

    3. Long-Form Factuality & Hallucination Detection: FActScore and SAFE

    When an LLM generates a 300-word biography or technical report $a$, a single binary "True/False" label is meaningless because almost every long response mixes true facts with fabricated details. Min et al. (2023) introduced FActScore (Fine-grained Atomic Evaluation of Factual Precision):

    1. Break the generated response $a$ into a set of atomic facts $\mathcal{A}(a) = \{f_1, \dots, f_m\}$ (short declarative sentences each containing a single piece of information).
    2. Retrieve passages from a trusted knowledge source $\mathcal{K}$ (e.g., Wikipedia or search engine in Google's SAFE—Search-Augmented Factuality Evaluator) and verify whether each atomic fact $f_j$ is supported ($\mathbb{I}[\mathcal{K} \models f_j]$).
    3. Multiply raw factual precision by a length penalty $\text{LP} = \min\bigl(1,\, \exp(1 - \mu / |\mathcal{A}(a)|)\bigr)$ if the model abstains or outputs fewer than $\mu$ expected facts:
      $$\text{FActScore}(a, \mathcal{K}) = \min\!\left(1,\; \exp\!\left(1 - \frac{\mu}{|\mathcal{A}(a)|}\right)\right) \cdot \frac{1}{|\mathcal{A}(a)|}\sum_{f \in \mathcal{A}(a)} \mathbb{I}[\mathcal{K} \models f]$$

    4. Pairwise Arena & LLM-as-a-Judge: Bradley–Terry MLE vs. Elo Ratings

    For open-ended instruction following, creative writing, and multi-turn chat, human raters (Chatbot Arena / LMSYS) and automated LLM judges (MT-Bench, AlpacaEval, Arena-Hard) are far more reliable at making pairwise comparisons ("Is Response A better than Response B?") than assigning calibrated absolute scalar scores.

    4.1 The Bradley–Terry Probabilistic Ranking Model

    In the Bradley–Terry (1952) model, each model $i \in \{1, \dots, M\}$ possesses a latent log-strength parameter $\beta_i \in \mathbb{R}$ (or on the standard chess Elo scale, $R_i$ where $\beta_i = \frac{\ln 10}{400} R_i$). The probability that model $i$ beats model $j$ is given by the logistic sigmoid of their strength difference:

    $$P(i \succ j) = \sigma(\beta_i - \beta_j) = \frac{e^{\beta_i}}{e^{\beta_i} + e^{\beta_j}} = \frac{1}{1 + 10^{(R_j - R_i)/400}}$$

    A $400$-point rating advantage ($R_i - R_j = 400$) corresponds to $10:1$ odds, or a $1/(1 + 10^{-1}) = 90.91\%$ expected win rate; a $100$-point advantage corresponds to a $1/(1 + 10^{-0.25}) \approx 64.01\%$ win rate.

    4.2 Online Sequential Elo vs. Stationary Bradley–Terry MLE

    • Online Sequential Elo Update: After a single match between $i$ and $j$ with outcome $S_{ij} \in \{1, 0.5, 0\}$ (win, tie, loss) and expected score $E_{ij} = P(i \succ j)$, classical Elo updates:
      $$R_i \leftarrow R_i + K\,(S_{ij} - E_{ij}), \qquad R_j \leftarrow R_j + K\,(S_{ji} - E_{ji})$$
      However, sequential Elo depends on the chronological order of matches, which is undesirable when evaluating static LLM checkpoints!
    • Stationary Bradley–Terry Maximum Likelihood Estimation (MLE): Given the complete matrix of pairwise win counts $W_{ij}$ across all battles, Chatbot Arena solves the convex logistic regression log-likelihood globally (fixing a reference model $\beta_1 = 1000$ for identifiability) and computes confidence intervals via bootstrap resampling:
      $$\hat{\boldsymbol{\beta}}_{\text{MLE}} = \arg\max_{\boldsymbol{\beta}} \sum_{i \ne j} W_{ij} \ln \sigma(\beta_i - \beta_j)$$

    5. Judge Biases, Length-Controlled Win Rate, and Rogan–Gladen Judge Calibration

    Using an LLM as an automated judge (Zheng et al. 2023) introduces three well-documented statistical biases that must be corrected at the metric level:

    1. Position Bias: LLM judges systematically favor whichever response is presented in the first slot (or second slot). Fix: Always run bidirectional swap evaluation—evaluate both $(A, B)$ and $(B, A)$, and only count a win if the judge selects the same model in both orders (treating inconsistent flips as a tie).
    2. Verbosity / Length Bias & Length-Controlled Win Rate (LC-AlpacaEval): Both human raters and LLM judges favor longer, bulleted responses even when they contain no additional substance. Dubois et al. (2024) eliminated length gaming by fitting a generalized linear model (logistic regression) to the pairwise win probability between candidate $m$ and baseline $b$:
      $$q_{\theta, \phi, \psi}(y_m \succ y_b \mid x) = \sigma\!\Bigl(\theta_m - \theta_b + \phi_{m,b}\cdot \tanh\!\left(\frac{\text{len}(y_m) - \text{len}(y_b)}{\sigma_{\Delta\text{len}}}\right) + \cdots\Bigr)$$
      Setting the length-difference term $\text{len}(y_m) - \text{len}(y_b) = 0$ during inference predicts the counterfactual Length-Controlled Win Rate $\text{LC-WinRate}(m, b) = \frac{1}{N}\sum_{x} \sigma(\hat{\theta}_m - \hat{\theta}_b)$, boosting correlation with Chatbot Arena from $0.94$ to $0.98$.
    3. Calibrating an Imperfect Judge (Rogan–Gladen Prevalence Correction): Suppose you use a fast LLM judge to evaluate a binary rubric $Y \in \{0, 1\}$ across $N$ production traces. On a small human-verified gold calibration set, you measure the judge's true positive rate (sensitivity) $q_1 = P(\hat{J}=1 \mid Y=1)$ and true negative rate (specificity) $q_0 = P(\hat{J}=0 \mid Y=0)$. By the law of total probability, the raw observed judge pass rate $p_{\text{obs}} = P(\hat{J}=1)$ is:
      $$p_{\text{obs}} = \theta\,q_1 + (1 - \theta)(1 - q_0)$$
      where $\theta = P(Y=1)$ is the true underlying pass rate of the system. Solving for $\theta$ yields the unbiased Rogan–Gladen (1978) / Bias-Corrected Judge Estimator:
      $$\hat{\theta}_{\text{corr}} = \text{clip}_{[0,1]}\!\left(\frac{\hat{p}_{\text{obs}} + q_0 - 1}{q_1 + q_0 - 1}\right)$$

    6. Complete Worked Numerical Examples

    6.1 Worked Unbiased $\text{pass}@k$ Computation

    Suppose on a coding problem we generate $n = 10$ candidate programs and $c = 2$ pass all unit tests. What are the unbiased estimates for $\text{pass}@1$, $\text{pass}@2$, and $\text{pass}@5$?

    • $\widehat{\text{pass}@1} = 1 - \frac{10 - 2}{10} = \frac{2}{10} = 0.2000$.
    • $\widehat{\text{pass}@2} = 1 - \frac{\binom{8}{2}}{\binom{10}{2}} = 1 - \frac{8 \times 7}{10 \times 9} = 1 - \frac{56}{90} = \frac{34}{90} \approx 0.3778$. (Compare with the biased plug-in binomial estimate $1 - (1 - 0.2)^2 = 0.3600$, which underestimates by $-1.78\%$!)
    • $\widehat{\text{pass}@5} = 1 - \frac{\binom{8}{5}}{\binom{10}{5}} = 1 - \frac{56}{252} = \frac{196}{252} = \frac{7}{9} \approx 0.7778$. (Compare with the biased plug-in estimate $1 - 0.8^5 = 0.6723$, which underestimates by more than $-10.5\%$!)

    6.2 Worked Rogan–Gladen Judge Calibration

    Suppose an LLM judge has sensitivity $q_1 = 0.90$ and specificity $q_0 = 0.80$ on a factual rubric. Across $1{,}000$ production responses, the judge marks $620$ as passing ($\hat{p}_{\text{obs}} = 0.6200$). What is the true corrected pass rate $\hat{\theta}_{\text{corr}}$?

    $$\hat{\theta}_{\text{corr}} = \frac{0.6200 + 0.80 - 1}{0.90 + 0.80 - 1} = \frac{0.4200}{0.7000} = 0.6000 \quad (60.0\%)$$

    7. Reference Python Implementation

    import math
from typing import Sequence, Dict

def unbiased_pass_at_k(n: int, c: int, k: int) -> float:
    """Chen et al. (2021) numerically stable unbiased pass@k estimator."""
    if n - c < k:
        return 1.0
    prod = 1.0
    for j in range(k):
        prod *= (n - c - j) / (n - j)
    return 1.0 - prod

def rag_context_precision_at_k(relevance_flags: Sequence[int]) -> float:
    total_rel = sum(relevance_flags)
    if total_rel == 0:
        return 0.0
    hits = 0
    score = 0.0
    for k, v_k in enumerate(relevance_flags, start=1):
        if v_k:
            hits += 1
            score += hits / k
    return score / total_rel

def bradley_terry_win_prob(elo_i: float, elo_j: float) -> float:
    return 1.0 / (1.0 + 10.0 ** ((elo_j - elo_i) / 400.0))

def rogan_gladen_judge_correction(p_obs: float, sensitivity_q1: float, specificity_q0: float) -> float:
    youden_j = sensitivity_q1 + specificity_q0 - 1.0
    if youden_j <= 0:
        raise ValueError("Judge must be better than random (q1 + q0 > 1).")
    theta = (p_obs + specificity_q0 - 1.0) / youden_j
    return max(0.0, min(1.0, theta))

if __name__ == "__main__":
    for k in (1, 2, 5):
        print(f"pass@{k} (n=10, c=2) = {unbiased_pass_at_k(10, 2, k):.4f}")
    print(f"RAG Context Precision = {rag_context_precision_at_k([1, 0, 1, 1, 0]):.4f}")
    print(f"P(Elo 1250 > 1150)    = {bradley_terry_win_prob(1250, 1150):.4f}")
    print(f"Corrected Judge Rate  = {rogan_gladen_judge_correction(0.62, 0.90, 0.80):.4f}")

    8. Self-Check Questions & Summary

    Question 1: In a RAG pipeline, suppose Context Recall is $0.95$ and Context Precision is $0.92$, but Faithfulness is $0.55$. Which component should you fix?

    Answer: The Generator LLM (or its system prompt / decoding temperature), not the retriever! High Context Recall ($0.95$) and Context Precision ($0.92$) prove that the retriever is already fetching almost all necessary facts and placing them at the top of the prompt, whereas low Faithfulness ($0.55$) shows that $45\%$ of the generator's atomic statements are ungrounded hallucinations not entailed by the retrieved passages.

    Question 2: Why does Chatbot Arena fit stationary Bradley–Terry MLE over all historical matches rather than using standard sequential chess Elo updates?

    Answer: Sequential chess Elo was designed for human players whose true skill drifts over time, so recent games overwrite older games with step size $K$. Because an LLM checkpoint is a fixed, stationary probability distribution, sequential Elo ratings fluctuate depending on the arbitrary order in which user battles arrived. Stationary Bradley–Terry MLE finds the unique global maximum-likelihood rating vector invariant to match ordering.
