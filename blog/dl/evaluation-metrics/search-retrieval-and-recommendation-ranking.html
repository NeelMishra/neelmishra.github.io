    Search, Retrieval & Recommendation Ranking Metrics: Precision@K, MRR, MAP@K, and nDCG@K

    October 2026 · 6 min read

    A search engine or recommender system shows the user an ordered list of $K$ results (ranks $k = 1, 2, \dots, K$). Because users mostly click results near the top of the page, ranking metrics measure two things: how many relevant items appear in the top $K$, and how close to rank $1$ they are placed.

    1. What Is $\text{rel}_k$? Precision@$K$ and Recall@$K$

    At each rank position $k \in \{1, 2, \dots, K\}$, we label the result with a relevance score $\text{rel}_k$. For binary metrics (hit vs. miss), $\text{rel}_k$ is simply $1$ or $0$:

    $$\text{rel}_k = \begin{cases} 1, & \text{if the item at rank } k \text{ is relevant (a hit)}, \\ 0, & \text{if the item at rank } k \text{ is not relevant (a miss)}. \end{cases}$$

    Summing $\text{rel}_k$ from $k = 1$ to $K$ counts how many relevant items landed inside the top $K$. If $R$ is the total number of relevant items that exist in the entire catalog for this query:

    $$\operatorname{Precision@}K = \frac{\text{Hits in Top } K}{K} = \frac{1}{K}\sum_{k=1}^{K} \text{rel}_k, \qquad \operatorname{Recall@}K = \frac{\text{Hits in Top } K}{R} = \frac{1}{R}\sum_{k=1}^{K} \text{rel}_k.$$

    Hit Rate@$K$ is even simpler: it equals $1$ if at least one relevant item appears anywhere in the top $K$, and $0$ otherwise. Note that Precision@$K$, Recall@$K$, and Hit Rate@$K$ ignore rank order inside the top $K$: a hit at rank $k = 1$ gets the exact same credit as a hit at rank $k = K$.

    2. Rewarding Top Positions: MRR and MAP@$K$

    To reward models that push relevant items to the very top of the list, we weight hits by their rank position $k$:

    1. Reciprocal Rank ($\operatorname{RR}$) and $\operatorname{MRR}$: When the user only needs one good answer (like finding a login page), let $k_{\text{first}}$ be the rank of the first relevant result:
      $$\operatorname{RR} = \frac{1}{k_{\text{first}}}, \qquad \operatorname{MRR} = \frac{1}{Q}\sum_{q=1}^{Q} \operatorname{RR}_q.$$
      If the first hit is at rank $1$, $\operatorname{RR} = 1/1 = 1.0$; if it drops to rank $4$, $\operatorname{RR} = 1/4 = 0.25$. Averaging $\operatorname{RR}$ across $Q$ queries gives Mean Reciprocal Rank ($\operatorname{MRR}$).
    2. Average Precision ($\operatorname{AP@}K$) and $\operatorname{MAP@}K$: When the user wants multiple relevant items, we compute $\operatorname{Precision@}k$ at every rank where a hit occurs ($\text{rel}_k = 1$) and average over the total possible hits $\min(K, R)$:
      $$\operatorname{AP@}K = \frac{1}{\min(K, R)} \sum_{k=1}^{K} \operatorname{Precision@}k \cdot \text{rel}_k, \qquad \operatorname{MAP@}K = \frac{1}{Q}\sum_{q=1}^{Q} \operatorname{AP@}K_q.$$
      Because $\text{rel}_k = 0$ on misses, non-relevant ranks add zero to the sum, but they push subsequent hits to larger denominators $k$, lowering their $\operatorname{Precision@}k$.

    3. Graded Relevance: DCG@$K$ and nDCG@$K$

    In many search and recommendation tasks, some results are much better than others. Instead of binary $0/1$, we assign a multi-level relevance grade $\text{rel}_k \in \{0, 1, 2, 3\}$ at rank $k$ (for example: $0 = \text{irrelevant}$, $1 = \text{somewhat relevant}$, $2 = \text{relevant}$, $3 = \text{exact match}$).

    • Discounted Cumulative Gain ($\operatorname{DCG@}K$): Gives each item a numerator gain of $2^{\text{rel}_k} - 1$ (so grade $3 \to 7$, grade $2 \to 3$, grade $1 \to 1$, grade $0 \to 0$) and divides by $\log_2(k + 1)$ to penalize lower ranks:
      $$\operatorname{DCG@}K = \sum_{k=1}^{K} \frac{2^{\text{rel}_k} - 1}{\log_2(k + 1)}.$$
    • Normalized DCG ($\operatorname{nDCG@}K$): Because raw $\operatorname{DCG@}K$ is larger for queries with many relevant items, we divide it by the Ideal DCG ($\operatorname{IDCG@}K$)—the best possible $\operatorname{DCG@}K$ achieved by sorting all relevant items in the catalog from highest grade to lowest:
      $$\operatorname{nDCG@}K = \frac{\operatorname{DCG@}K}{\operatorname{IDCG@}K} \in [0, 1].$$

    4. Step-by-Step Worked Example ($K = 5$)

    Suppose $R = 4$ relevant items exist in the catalog with grades $[3, 2, 2, 1]$. Our model returns a top-$5$ list whose grades are $\text{rel}_{1:5} = [3, 0, 2, 1, 0]$ (missing one grade-$2$ item). Converting grades $> 0$ to $1$ gives binary hits $\text{rel}_{1:5} = [1, 0, 1, 1, 0]$:

    5. Beyond Accuracy: Diversity, Novelty, and Catalog Coverage

    A recommender that shows $5$ nearly identical sequels can score high on $\operatorname{nDCG@5}$ while boring the user. Production systems track three simple health checks alongside ranking accuracy:

    MetricPlain-English DefinitionWhat It Prevents
    Intra-List DiversityAverage pairwise distance (e.g., $1 - \text{cosine similarity}$) between items in the top $K$Showing $K$ near-duplicate items on the same screen
    NoveltyAverage $-\log_2 P(\text{item})$ across the top $K$, where $P(\text{item})$ is historical click shareRecommending only obvious, already-famous blockbusters
    Catalog CoveragePercentage of all catalog items recommended to at least one userStarving long-tail items of impressions

    6. Reference Python Implementation

    import math
from typing import Sequence

def average_precision_at_k(binary_rels: Sequence[int], k: int, total_relevant: int) -> float:
    """AP@K over binary relevance labels rel_k in {0, 1}."""
    if total_relevant == 0:
        return 0.0
    hits, score_sum = 0, 0.0
    for rank, rel_k in enumerate(binary_rels[:k], start=1):
        if rel_k == 1:
            hits += 1
            score_sum += hits / rank
    return score_sum / min(k, total_relevant)

def dcg_at_k(graded_rels: Sequence[float], k: int) -> float:
    """DCG@K over graded relevance labels rel_k in {0, 1, 2, 3}."""
    return sum((2.0 ** rel_k - 1.0) / math.log2(rank + 1.0) for rank, rel_k in enumerate(graded_rels[:k], start=1))

def ndcg_at_k(graded_rels: Sequence[float], all_catalog_rels: Sequence[float], k: int) -> float:
    ideal_dcg = dcg_at_k(sorted(all_catalog_rels, reverse=True), k)
    return dcg_at_k(graded_rels, k) / ideal_dcg if ideal_dcg > 0 else 0.0

graded_top5 = [3, 0, 2, 1, 0]
binary_top5 = [1 if r > 0 else 0 for r in graded_top5]
catalog_grades = [3, 2, 2, 1]

print("AP@5   :", round(average_precision_at_k(binary_top5, k=5, total_relevant=4), 4))
print("nDCG@5 :", round(ndcg_at_k(graded_top5, catalog_grades, k=5), 4))
