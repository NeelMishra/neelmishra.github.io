    Ranking & Calibration Metrics: ROC-AUC, PR-AUC, Brier Score, and ECE

    October 2026 · 5 min read

    In Chapter 01, metrics like Precision, Recall, and $F_1$ required picking a single probability cutoff $\tau$ (such as $0.50$). When a model outputs probabilities $\hat p \in [0, 1]$, we want to answer two simple questions across the entire dataset:

    1. Ranking (ROC-AUC & PR-AUC): Does the model give higher scores to actual positives than to actual negatives?
    2. Calibration (Brier Score & ECE): When the model predicts an $80\%$ probability, does the event actually happen $80\%$ of the time?

    1. ROC-AUC: Do Positives Get Higher Scores Than Negatives?

    As we lower the decision threshold $\tau$ from $1.0$ down to $0.0$, we catch more positives (increasing the True Positive Rate $\operatorname{TPR} = \frac{TP}{TP + FN}$) at the cost of flagging more negatives (increasing the False Positive Rate $\operatorname{FPR} = \frac{FP}{FP + TN}$). Plotting $\operatorname{TPR}$ on the y-axis against $\operatorname{FPR}$ on the x-axis traces the ROC curve.

    The area under this curve (ROC-AUC) has a simple, threshold-free meaning: pick one positive example and one negative example at random; ROC-AUC is the probability that the positive example got a higher score:

    $$\operatorname{ROC-AUC} = \Pr(\hat s_+ > \hat s_-) = \frac{1}{|P|\cdot |N|}\sum_{i \in P}\sum_{j \in N} \mathbf 1[\hat s_i > \hat s_j] \qquad (\text{ties count as } 0.5).$$

    A random coin-flip classifier scores $\mathbf{0.50}$, while a model that ranks every positive above every negative scores $\mathbf{1.00}$.

    Worked Example by Hand ($2$ Positives $\hat s_+ = [0.9, 0.4]$, $2$ Negatives $\hat s_- = [0.6, 0.2]$):

    Positive Score $\hat s_+$Negative Score $\hat s_-$Is $\hat s_+ > \hat s_-$?Pairwise Score
    $0.9$$0.6$Yes ($0.9 > 0.6$)$1$
    $0.9$$0.2$Yes ($0.9 > 0.2$)$1$
    $0.4$$0.6$No ($0.4 < 0.6$)$0$
    $0.4$$0.2$Yes ($0.4 > 0.2$)$1$

    Out of $2 \times 2 = 4$ pairs, $3$ are ordered correctly, so $\operatorname{ROC-AUC} = \frac{3}{4} = \mathbf{0.75}$.

    2. PR-AUC: Why ROC-AUC Misleads on Rare Events

    Why do we ever need a second curve? Look closely at the denominator of $\operatorname{FPR} = \frac{FP}{FP + TN}$. When positives are rare—say $100$ fraudulent transactions and $9{,}900$ normal transactions—$TN$ is huge. Suppose our model catches $TP = 90$ frauds, but also triggers $FP = 500$ false alarms:

    CurveWhat It PlotsAt $TP = 90, FP = 500$Why It Looks Good or Bad
    ROC Curve$\operatorname{TPR}$ vs. $\operatorname{FPR} = \frac{FP}{FP + TN}$$\operatorname{TPR} = 90\%$, $\operatorname{FPR} = \frac{500}{9900} = \mathbf{5.1\%}$Dividing by $9{,}900$ negatives hides the $500$ false alarms.
    PR Curve$\operatorname{Precision} = \frac{TP}{TP + FP}$ vs. $\operatorname{Recall}$$\operatorname{Recall} = 90\%$, $\operatorname{Precision} = \frac{90}{90 + 500} = \mathbf{15.3\%}$Compares $500$ false alarms directly against the $90$ true hits.

    The Precision–Recall AUC (PR-AUC / Average Precision) sums the area under the Precision vs. Recall curve across sorted thresholds:

    $$\operatorname{PR-AUC} = \sum_{k} (R_k - R_{k-1})\,P_k.$$

    Rule of thumb: Use ROC-AUC when classes are roughly balanced; use PR-AUC whenever the positive class is rare.

    3. Calibration: Brier Score and Expected Calibration Error (ECE)

    ROC-AUC and PR-AUC only check the order of scores: if you divide every predicted probability by $10$ (turning $0.90 \to 0.09$ and $0.20 \to 0.02$), the ranking stays identical so ROC-AUC and PR-AUC do not change at all, even though the probabilities are now completely wrong.

    To check whether the probabilities themselves are honest (calibrated), we use two simple metrics:

    1. Brier Score ($\downarrow$): Simply the mean squared error between predicted probabilities $\hat p_i \in [0, 1]$ and binary labels $y_i \in \{0, 1\}$:
      $$\operatorname{Brier} = \frac{1}{N}\sum_{i=1}^N (\hat p_i - y_i)^2 \qquad (\text{perfect} = 0.0,\;\text{coin-flip } 0.5 = 0.25).$$
    2. Expected Calibration Error ($\operatorname{ECE} \downarrow$): Group predictions into confidence bins $B_1, \dots, B_M$ (for example, low confidence $[0, 0.5]$ and high confidence $(0.5, 1.0]$). Inside each bin, compare the average predicted confidence $\operatorname{conf}(B_m)$ with the actual fraction of positives $\operatorname{acc}(B_m)$, weighted by bin size:
      $$\operatorname{ECE} = \sum_{m=1}^M \frac{|B_m|}{N}\,\big|\operatorname{acc}(B_m) - \operatorname{conf}(B_m)\big|.$$

    Worked Calibration Example ($N = 4$ predictions grouped into $2$ bins):

    SamplePredicted $\hat p_i$Actual $y_i$Squared Error $(\hat p_i - y_i)^2$Confidence Bin
    1$0.20$$0$$(0.20 - 0)^2 = 0.04$Bin 1 ($[0, 0.5]$): $\operatorname{conf} = 0.20, \operatorname{acc} = 0.00 \implies \text{gap} = 0.20$
    2$0.60$$0$$(0.60 - 0)^2 = 0.36$Bin 2 ($(0.5, 1.0]$): $3$ samples
    $\operatorname{conf} = \frac{0.6 + 0.8 + 0.9}{3} = \mathbf{0.767}$
    $\operatorname{acc} = \frac{0 + 1 + 1}{3} = \mathbf{0.667} \implies \text{gap} = 0.10$
    3$0.80$$1$$(0.80 - 1)^2 = 0.04$
    4$0.90$$1$$(0.90 - 1)^2 = 0.01$
    • Brier Score: $\frac{0.04 + 0.36 + 0.04 + 0.01}{4} = \frac{0.45}{4} = \mathbf{0.1125}$.
    • ECE: $\frac{1}{4}|0.00 - 0.20| + \frac{3}{4}|0.667 - 0.767| = 0.05 + 0.075 = \mathbf{0.1250}$.

    4. Reference Implementation in PyTorch

    import torch

def roc_auc_pairwise(y_true: torch.Tensor, y_score: torch.Tensor) -> float:
    """Fraction of (positive, negative) pairs where the positive has a higher score."""
    pos = y_score[y_true == 1].unsqueeze(1)
    neg = y_score[y_true == 0].unsqueeze(0)
    return ((pos > neg).float() + 0.5 * (pos == neg).float()).mean().item()

def pr_auc(y_true: torch.Tensor, y_score: torch.Tensor) -> float:
    """Step-wise Average Precision (PR-AUC)."""
    order = torch.argsort(y_score, descending=True)
    y_sorted = y_true[order].float()
    precisions = torch.cumsum(y_sorted, dim=0) / torch.arange(1, len(y_sorted) + 1, dtype=torch.float32)
    return (precisions * y_sorted).sum().div(y_true.sum().clamp(min=1)).item()

def brier_and_ece(y_true: torch.Tensor, y_prob: torch.Tensor, num_bins: int = 2):
    brier = ((y_prob - y_true.float()) ** 2).mean().item()
    edges = torch.linspace(0.0, 1.0, num_bins + 1)
    ece, n = 0.0, len(y_true)
    for m in range(num_bins):
        mask = (y_prob > edges[m]) & (y_prob <= edges[m + 1]) if m > 0 else (y_prob >= 0.0) & (y_prob <= edges[1])
        if mask.any():
            gap = abs(y_true[mask].float().mean().item() - y_prob[mask].mean().item())
            ece += (mask.sum().item() / n) * gap
    return round(brier, 4), round(ece, 4)

print("ROC-AUC (worked example):", roc_auc_pairwise(torch.tensor([1, 1, 0, 0]), torch.tensor([0.9, 0.4, 0.6, 0.2])))
print("Brier, ECE (worked ex.) :", brier_and_ece(torch.tensor([0, 0, 1, 1]), torch.tensor([0.2, 0.6, 0.8, 0.9])))
