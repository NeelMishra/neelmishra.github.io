    GRPO: Group Rewards, One Clear Update

    September 2026 · 5 min read + experiments

    A compact path from “the critic is expensive” to the group-relative update used for reasoning models.

    Start hereSee the update

    The useful idea fits on one prompt

    Ask a policy the same question four times. A verifier scores the four answers. Instead of learning a separate value model to guess the prompt’s difficulty, compare each answer with its group. The better-than-group answers get a positive weight; the worse ones get a negative weight.

    That is Group Relative Policy Optimization (GRPO), introduced as a PPO variant in DeepSeekMath. The paper’s motivation is practical: a critic can consume a large amount of memory when the policy already produces several completions per prompt. GRPO spends those completions on a baseline.

    Three names are enough for the first pass

    NameMeaning in this series
    $G$Number of completions sampled for one prompt
    $r_i$Verifier or reward-model score for completion $i$
    $\hat A_i$Group-relative weight applied to completion $i$

    The word “relative” does real work. A reward of 0.7 is not automatically good; it is good only if the other completions for that prompt scored lower. That makes GRPO especially natural when a verifier can distinguish partial progress, such as a correct final answer or a passing unit test.
