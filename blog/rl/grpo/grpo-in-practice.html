    From Equation to Experiment

    September 2026 · 6 min read

    Follow the group weights into a token-level loss, then inspect one update before running a larger experiment.

    Trace the loopChoose a method

    Prepare the group weights once

    Collect the same number $G$ of answers for each prompt using a frozen rollout policy. Save the generated tokens, response masks, rewards, and old token log probabilities. Keep the reference model fixed within this training stage.

    Arrange rewards as [number_of_prompts, G]. Subtract each prompt’s mean and divide by its group spread, as in chapter 1. Here unbiased=False selects the population standard deviation used in our calculator:

    centered = rewards - rewards.mean(dim=1, keepdim=True)
spread = rewards.std(dim=1, keepdim=True, unbiased=False)
advantage = (centered / (spread + 1e-8)).flatten().detach()

    Flatten the answers in that same prompt/group order. Freeze these advantages and the old log probabilities throughout the updates on this batch. Rescore the stored tokens with the current policy at each optimizer step.

    Line up the token arrays

    Let B be the total number of answers and L their padded token length. The arrays new_logp, old_logp, and ref_logp each have shape [B, L] and score the same token given the same prefix. Only new_logp carries gradients.

    response_mask is a boolean array of that shape: true for generated response tokens, including a generated end token, and false for prompts and padding. Every retained answer needs at least one valid token. The token-alignment chapter shows how to gather these next-token log probabilities.

    Add the reference cost before averaging

    The previous update chapter supplied the clipped score. The extra reference cost uses the ratio reference probability / current probability. Call its logarithm $z$. The paper’s sampled cost is $e^z-z-1$: it is zero when the two token probabilities match and positive otherwise. See DeepSeekMath, Equations 3–4 and Algorithm 1.

    In the code, eps is the clipping tolerance, such as 0.2, and beta is the positive reference-penalty coefficient. torch.expm1(z) computes $e^z-1$ accurately near zero. Negate the clipped score because the optimizer minimizes a loss, then average tokens within each answer and average answers:

    ratio = (new_logp - old_logp).exp()
weight = advantage[:, None]  # Share one weight across an answer's tokens
score = torch.minimum(
    ratio * weight,
    ratio.clamp(1 - eps, 1 + eps) * weight,
)
z = ref_logp - new_logp
reference_cost = torch.expm1(z) - z
per_token_loss = -score + beta * reference_cost
lengths = response_mask.sum(dim=1)
masked_loss = per_token_loss.masked_fill(~response_mask, 0)
loss = (masked_loss.sum(dim=1) / lengths).mean()

optimizer.zero_grad()
loss.backward()
optimizer.step()

    This is the loss calculation, assuming generation, scoring, and token alignment are already done. With the same $G$ for every prompt, averaging answers also gives each prompt equal weight.

    Is the sampled reference cost exactly the KL divergence?

    Its expectation over tokens sampled from the current policy equals that policy’s KL divergence from the reference at a fixed prefix. Once the current policy changes, reused rollout tokens come from an older policy. On those samples, treat this as the paper’s sampled penalty, not an exact KL measurement.

    Inspect one update before comparing runs

    Before the first optimizer step, current/old ratios should be 1 on valid tokens when both scoring paths match. Inspect one prompt’s rewards and advantages, verify that padding contributes zero loss, and check that the reference model receives no gradients. A flat-reward group has no reward-based gradient, but its reference penalty may still update the policy.

    For comparisons, report generated tokens, verifier calls, and compute time. Hold the evaluation problems and decoding budget fixed. Track the diagnostics from chapter 3 alongside held-out correctness; removing the critic does not remove the cost of sampling several answers.

    Choose by the evidence you can collect

    These are starting points, not exclusive categories. PPO also trains language models, and DPO can use pairs collected by an earlier sampling stage. The practical question is whether you have reliable fixed comparisons, useful same-prompt scores, or a reason to learn state values.

    Keep the learning signal in view

    For more on critics and trajectories, return to PPO. For training directly from chosen/rejected pairs, follow DPO. When using a GRPO library, record its reward normalization, token reduction, and reference settings so you know how its objective relates to the version explained here.
