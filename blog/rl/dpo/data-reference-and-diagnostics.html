    Train DPO with Evidence: Data Coverage, Reference Choice, and Diagnostics

    September 2026 · 5 min read + experiments

    Build useful comparisons, understand what offline pairs leave unidentified, and interpret training metrics without confusing them with generated quality.

    Read the explanationTry the calculation

    Check what the pairs actually teach

    Suppose every chosen answer is long and every rejected answer is short. A model could improve its training score by preferring length, even if the intended lesson was correctness. Similar shortcuts can come from formatting, source-model signatures, or different prompt templates.

    Inspect examples across response lengths, topics, and label sources. Write down what should make one answer preferable. Split evaluation by prompt or prompt family before creating variants, so near-duplicate questions do not appear on both sides of the split.

    An unseen answer is still unconstrained

    Imagine three possible responses: A, B, and C. The dataset compares only A with B. Use a uniform reference and $\beta=1$. A policy with probabilities (0.30, 0.20, 0.50) favors A over B by 1.5 to one. So does (0.06, 0.04, 0.90), despite generating C much more often.

    The DPO loss on that pair sees the same relative odds in both policies. Move C’s probability in the figure; the A:B ratio stays fixed:

    This is a constructed example of missing evidence. It does not describe a particular optimizer trajectory. A fixed reference alone cannot make a limited set of pair labels determine every response probability. Include comparisons that distinguish the mistakes and alternatives you care about, then evaluate new generations.

    Record which reference defines the gains

    A common starting point uses the same supervised model for the trainable policy and the frozen reference. The initial gains are then zero, and the pair loss is about 0.6931. A different reference changes the baseline odds and therefore changes the objective.

    Save the checkpoint identity and preprocessing with the run. Recompute cached scores if the reference or scored token positions change. Chapter 4 explains what a valid reference cache contains.

    Keep disagreement visible

    If eight of ten comparable judgments prefer A, the evidence supports a preference with uncertainty. It does not establish that A should win every possible judgment. Keep repeated labels or their counts when available, and inspect disagreements under the stated rubric.

    A dataset in which every observed label agrees can keep rewarding an increasing margin. That is a property of fitting those observations, not proof of an infinitely large quality difference. Use validation and generated-answer evaluation to decide whether further training is useful.

    Separate pair fit from generated quality

    MeasurementWhat it tells youWhat to check alongside it
    Pair loss and marginHow well the model fits stored choicesWhether length or formatting explains the gain
    Pair accuracyHow often the chosen implicit score is largerFresh answers; this is not generation accuracy
    Chosen and rejected log probabilitiesWhich likelihoods actually moveResponse lengths and the token reduction
    KL to the referenceHow much the generation distribution changedWhich distribution sampled the evaluated responses
    Held-out task resultsWhether generated answers meet the rubricJudge consistency, prompt coverage, and decoding settings

    TRL’s DPO documentation describes the logged preference metrics. Its “rewards” are implicit policy-to-reference scores, not independent judgments from a reward model.

    For a policy-to-reference KL estimate, sample answers from the current policy and average their current-minus-reference log probabilities. Averaging those values over an arbitrary fixed preference dataset answers a different question because its answers came from a different distribution.

    Debug in three short passes

    1. One pair: inspect its actual token IDs, response masks, four sequence scores, and chosen/rejected order. If policy and reference match, check the initial loss.
    2. One training run: follow both likelihoods, the margin, and the gradient scale. Verify that the reference receives no updates.
    3. New generations: compare checkpoints on the same held-out prompts, decoding settings, and judging process. Report response length alongside quality.

    The next chapter runs these checks in a small world where the true preference probabilities are known. That separates calculation errors from the uncertainty present in real datasets.
