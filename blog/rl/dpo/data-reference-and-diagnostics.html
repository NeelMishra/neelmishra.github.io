    Train DPO with Evidence: Data Coverage, Reference Choice, and Diagnostics

    September 2026 · 6 min read + experiments

    Build useful comparisons, understand what offline pairs leave unidentified, and interpret training metrics without confusing them with generated quality.

    See the ideaRead the explanationTry the calculation

    A useful pair isolates a meaningful decision

    Suppose every chosen answer contains three paragraphs and every rejected answer contains one. A learner can improve pair accuracy by learning a length cue, even if the intended label concerns correctness. Or suppose rejected answers were generated with a different system prompt, tokenizer artifact, or visible model signature. Those features can become shortcuts.

    Inspect pairs across labels, sources, response lengths, and difficulty. Prefer a rubric that explains the desired comparison rather than treating a single overall score as self-explanatory. Keep reasonable disagreements visible: a terse answer and a detailed answer may trade off usefulness under different requests. Mixing inconsistent conventions without context makes the model fit an average that may satisfy neither.

    Split evaluation by prompt or a suitable prompt-family grouping before making derivative examples. Putting variants of one request in both training and evaluation can inflate apparent generalization. If multiple comparisons share a prompt or response, remember that their errors are correlated; the number of rows is not the number of independent tasks.

    An unobserved response creates a real ambiguity

    Consider a uniform reference over A, B, C and a dataset that only says A is preferred to B. Write a family of policies as $\pi=(0.6(1-c),0.4(1-c),c)$. The A:B odds are always 1.5, so the DPO margin at $\beta=1$ is always $\log1.5$. The loss never changes, even while the model’s probability of C varies.

    A reference-relative loss is therefore not a finite-data guarantee that the full learned distribution stays inside a KL ball. The explicit fixed-reward objective from chapter 2 and the information in a limited preference dataset are different objects. Model architecture and optimization can favor some solutions, but the missing comparison was not supplied by the label.

    View the dataset as a graph for each prompt: responses are nodes, comparisons are edges. In an ideal Bradley–Terry model, connected comparisons with sufficient evidence can identify utility differences up to a shared offset. Disconnected components leave additional offsets unresolved. Language models share parameters across prompts, so this graph is an explanatory idealization; it still exposes why coverage cannot be replaced by a smaller training loss.

    The reference defines what a gain means

    A common setup starts DPO from a supervised policy and freezes a matching reference. Then initial gains are zero, giving the $\log2$ loss check. A different reference changes the baseline odds and therefore the meaning of every preference margin. A fixed reference is part of the objective, not just a memory-management detail.

    Record its checkpoint and preprocessing with the experiment. Keep reference scoring deterministic and without gradients. If using cached scores, changing the reference, response masks, template, or length policy invalidates the relevant entries. Reference synchronization or reference-free scores are variants of the setup; they should be named explicitly instead of silently presented as the same fixed-reference loss.

    Repeated labels explain why a finite margin can be sensible

    For one pair with empirical chosen-side win frequency $p\in(0,1)$, the count-averaged logistic loss is $-p\log\sigma(m)-(1-p)\log\sigma(-m)$. Its derivative is $\sigma(m)-p$, so its unconstrained optimum is $m^*=\log[p/(1-p)]$. If $p=0.8$, this is $\log4\approx1.386$. Finite uncertainty calls for finite confidence.

    If all labels for an independently adjustable pair agree, the empirical loss instead decreases as its margin grows without bound. This is the separability behavior of logistic likelihood, not evidence that the reward difference is infinitely large. Early stopping, data quality, model constraints, or explicitly chosen regularization can matter. Soft labels derived from repeated observations, label smoothing, and a model of label-flip noise are different constructions and should not be conflated.

    A sample $\log\pi_\theta(y\mid x)-\log\pi_{\mathrm{ref}}(y\mid x)$ estimates policy-to-reference KL in expectation when $y$ is sampled from the current policy. Averaging the same quantity over an arbitrary fixed preference dataset does not generally estimate that KL, because the response sampling distribution is different. This distinction parallels the sampling-distribution issue in PPO.

    Diagnose a run in the order that isolates mistakes

    First verify the initial $\log2$ loss when policy and reference should match. Then inspect one pair’s actual token IDs, shifted targets, scored lengths, four sequence scores, and margin. Test padding invariance and chosen/rejected ordering. Check reference gradients and checkpoint identity. These are deterministic questions that do not need a long training run.

    Next examine optimization: gradient norms, learning rate, $\beta$, batch composition, and a small set of repeatedly inspected examples. Finally evaluate new generations with a fixed protocol. Compare models on the same prompt split, decoding settings, judge process, and response-length accounting. Pair-level validation is useful, but it cannot replace evaluating the behavior you intend to deploy.

    Check your understanding: Can preference loss remain exactly constant while KL to the reference changes?

    Yes. In the three-response experiment, the dataset only constrains A:B odds. Moving mass to or from unobserved C preserves those odds but changes the full distribution and its KL.
