    DPO in Code: Score the Right Tokens before Writing the Loss

    September 2026 · 5 min read + experiments

    Align causal logits, exclude prompt and padding positions, sum response log probabilities, and build a correctly paired training step.

    Read the explanationTry the calculation

    Build one response score from its tokens

    Chapter 3 used four whole-response log probabilities. A language model produces token predictions, so we now turn those predictions into the response scores the loss expects.

    Let $x$ be the prompt and $y_1,\ldots,y_L$ the response tokens. Each token is predicted from the prompt and the preceding response tokens, written $y_{<t}$. Their conditional probabilities multiply; taking logs turns that product into a sum:

    $$\log\pi_\theta(y\mid x)=\sum_{t=1}^{L}\log\pi_\theta(y_t\mid x,y_{<t}).$$

    For token log probabilities −0.8, −0.5, and −0.2, the response score is −1.5. Standard DPO uses this sum. Dividing by the response’s length would define a different score.

    Match each prediction to the next token

    A causal decoder’s output at position $j$ predicts the token at position $j+1$. Shift the token IDs and their response mask by one position to line them up. The response mask marks which tokens belong to the answer; the attention mask marks usable, non-padding context. Prompt tokens are context, but are excluded from the response score.

    For $B$ preference pairs, put the chosen and rejected responses into $2B$ batch rows. Let $S$ be the padded sequence length and $V$ the vocabulary size. The following code selects each target token’s log probability and sums only the response positions:

    # IDs and masks: [2B, S]; logits: [2B, S, V]
target_ids = input_ids[:, 1:]
keep = response_mask[:, 1:].bool() & attention_mask[:, 1:].bool()
logp = logits[:, :-1].float().log_softmax(dim=-1)
selected = logp.gather(-1, target_ids.unsqueeze(-1)).squeeze(-1)
sequence_logp = selected.masked_fill(~keep, 0).sum(dim=-1)  # [2B]

    The target IDs in this snippet must be valid vocabulary indices. If labels use −100 to mean “ignore,” replace that index before gathering and ignore the resulting score with the mask. The lab’s response-scoring helper keeps valid IDs and masks separate.

    See why a token mean changes the answer

    The figure compares a three-token chosen answer with a five-token rejected answer. Their policy-minus-reference sequence gains are +0.7 and −0.5. With $\beta=0.5$, the margin is 0.6. Switch from sums to means: each gain is now divided by a different response length, so the loss changes.

    Including EOS scores a completed answer with its ending action. Excluding it scores a different event. Choose a stopping convention and use it consistently for policy and reference scores.

    Inspect the actual token boundary

    Use the same chat template and prompt token IDs for chosen and rejected responses. Tokenizing the prompt and answer separately may not match tokenizing the combined text, especially at whitespace boundaries. Inspect where the response mask first becomes 1.

    Check the text again after truncation. Removing a decisive final sentence can invalidate a preference label, and two different answers can become identical. If EOS and padding share an ID, use their positions and masks to distinguish them.

    Score both models, then apply the pair loss

    The batch layout below puts chosen rows first and rejected rows second. response_logps is the reducer above; dpo_loss is the four-score loss from chapter 3. The reference has no gradients, while the policy does:

    ids, attention, response = batch
reference.eval()
reference.requires_grad_(False)
policy.eval()  # Disables dropout here; gradients still work.
with torch.no_grad():
    ref_logits = reference(input_ids=ids, attention_mask=attention).logits
    ref_scores = response_logps(ref_logits, ids, response, attention)
logits = policy(input_ids=ids, attention_mask=attention).logits
scores = response_logps(logits, ids, response, attention)
chosen, rejected = scores.chunk(2)
ref_chosen, ref_rejected = ref_scores.chunk(2)
loss = dpo_loss(chosen, rejected, ref_chosen, ref_rejected, beta).mean()
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()

    Use a deterministic scoring setup for the initial policy-equals-reference check. The original DPO implementation separates response scoring from preference loss in the same way. These snippets show the core update; model loading, batching, and optimizer setup are separate.

    Cache only scores whose meaning stays fixed

    A fixed reference can score the dataset once before training. Reuse those scores only while the reference checkpoint, tokenization, response masks, and stopping rules remain unchanged. Changing the scored event invalidates the cache.

    TRL’s DPO trainer documentation describes reference-score precomputation and supported loss variants. Record the installed version and selected loss when using a trainer. Next, check whether the pairs and measurements support the behavior you want.
