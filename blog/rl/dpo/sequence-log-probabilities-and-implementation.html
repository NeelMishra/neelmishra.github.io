    DPO in Code: Score the Right Tokens before Writing the Loss

    September 2026 · 6 min read + experiments

    Align causal logits, exclude prompt and padding positions, sum response log probabilities, and build a correctly paired training step.

    See the ideaRead the explanationTry the calculation

    A response probability is a product of conditional probabilities

    For response tokens $y=(y_1,\ldots,y_L)$ and prompt $x$, a causal language model defines $\pi_\theta(y\mid x)=\prod_{t=1}^{L}\pi_\theta(y_t\mid x,y_{<t})$. Taking logs converts that product into a sum:

    $$\log\pi_\theta(y\mid x)=\sum_{t=1}^{L}\log\pi_\theta(y_t\mid x,y_{

    The canonical DPO objective uses this sum, not an average over response tokens. Summing first and averaging the pair losses afterward is different from averaging token scores before forming each margin. A token mean divides each response by its own length and changes the relative weights of long and short responses.

    Align prediction positions with target positions

    A batch of model logits has shape $[2B,S,V]$: two responses per pair, sequence length $S$, vocabulary size $V$. The output at position $j$ predicts the token at position $j+1$. Therefore align logits[:, :-1] with input_ids[:, 1:]. The response mask is defined on token IDs, so shift it to response_mask[:, 1:] as well.

    Do not use the attention mask as the response mask. Attention typically includes prompt tokens because the model needs their content. The response loss excludes prompt tokens because we are scoring the continuation conditioned on that prompt. Padding positions contribute to neither the response score nor the model’s usable context.

    # IDs and masks: [2B, S]; logits: [2B, S, V]
target_ids = input_ids[:, 1:]
keep = response_mask[:, 1:].bool() & attention_mask[:, 1:].bool()
logp = logits[:, :-1].float().log_softmax(dim=-1)
selected = logp.gather(-1, target_ids.unsqueeze(-1)).squeeze(-1)
sequence_logp = selected.masked_fill(~keep, 0).sum(dim=-1)  # [2B]

    This compact snippet assumes every target ID is a valid vocabulary index. If you instead store ignored labels as −100, replace those ignored indices with a safe dummy ID before gathering, then mask their scores out. The lab reducer keeps IDs and Boolean masks separate and rejects empty responses. It upcasts low-precision logits for the reduction while preserving float64 for mathematical checks.

    Watch a reduction change the objective

    Take a chosen response with current token log probabilities $(−0.8,−0.5,−0.2)$ and reference scores $(−1.1,−0.7,−0.4)$. Its sequence gain is $-1.5-(-2.2)=0.7$. Let the rejected response have five tokens, current sum −2.0, and reference sum −1.5, giving gain −0.5. At $\beta=0.5$, the margin is $0.5(0.7+0.5)=0.6$.

    Under token means, the gains become $0.7/3$ and $-0.5/5$, so the margin is about 0.1667. That is not a numerical optimization of the same equation. It is a different score function. Likewise, dropping EOS changes the probability of the event being scored: generating this prefix versus generating this completed answer under the selected stopping convention.

    The shared prefix is a data invariant

    Use the intended chat template, role delimiters, and assistant-start marker. Verify the prefix at the token-ID level. Independently tokenizing a prompt and a response and concatenating their IDs need not reproduce tokenization of the combined text, particularly around boundary whitespace. Prefer a documented formatting/tokenization procedure, then inspect actual examples at the response boundary.

    Identical prompt log-probability terms cancel algebraically from an exact sum-based paired margin. That does not change the definition of $\log\pi(y\mid x)$: it excludes the prompt. Explicit response masks keep the implementation faithful to that conditional event and prevent accidental reliance on cancellation when prefix serialization, truncation, or length normalization differs.

    Truncation can change the label’s meaning. A full chosen answer may be correct only because of a decisive final sentence that is removed by a length limit. A pair can even become identical after truncation. Filter or relabel such examples rather than assuming their original ordering remains informative. If EOS and PAD share an ID, distinguish them by masks and position; token-ID equality alone cannot tell which is real.

    A minimal paired training step

    # Batch layout: chosen rows [0:B], rejected rows [B:2B].
# policy/reference are causal models whose forward returns .logits.
# eval() makes this scoring example deterministic; it does not disable autograd.
policy.eval()
reference.eval()
reference.requires_grad_(False)

ids, attention, response = batch
with torch.no_grad():
    ref_logits = reference(input_ids=ids, attention_mask=attention).logits
    ref_scores = response_logps(ref_logits, ids, response, attention)
logits = policy(input_ids=ids, attention_mask=attention).logits
scores = response_logps(logits, ids, response, attention)
chosen, rejected = scores.chunk(2)
ref_chosen, ref_rejected = ref_scores.chunk(2)
loss = dpo_loss(chosen, rejected, ref_chosen, ref_rejected, beta).mean()
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()

    This is the core step, assuming a valid paired batch and optimizer; it is not a complete large-model training pipeline. The downloadable lab supplies the two mathematical helpers. The model supplies causal attention. Concatenating chosen and rejected rows along the batch axis is safe; packing unrelated sequences into one context requires explicit boundaries so their tokens cannot attend across examples.

    Caching does not make the reference optional

    If the reference and preprocessing stay fixed, its two sequence scores can be precomputed. Cache keys must identify the reference checkpoint or adapter, token IDs, template, response mask, EOS convention, and truncation rules. A cache built under a different scoring event is not interchangeable. With adapters, disabling the trainable adapter reproduces the intended reference only if the remaining weights actually match that reference.

    The authors’ code exposes separate sequence-log-probability reduction and preference-loss functions. TRL provides a production trainer with dataset handling and reference-score precomputation, but its optional losses and defaults evolve. Record the installed version and exact loss configuration when comparing runs. Original implementation, TRL DPO trainer documentation.

    Check your understanding: Should changing logits that predict only padding alter the response score?

    No. The lab changes ignored-position logits and appends padding, then verifies that the response score is unchanged. It also checks that gradients reach the two intended prediction positions and not the ignored ones.
