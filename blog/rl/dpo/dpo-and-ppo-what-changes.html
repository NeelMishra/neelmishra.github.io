    DPO and PPO: Same Motivation, Different Learning Problems

    September 2026 · 6 min read + experiments

    Compare data collection, policy ratios, credit assignment, and evaluation so you can explain precisely what changes when moving between DPO and PPO.

    Read the explanation

    Separate the task, the signal, and the optimizer

    “Improve the assistant’s answers” is a task-level goal. Human comparisons, verifier scores, and reward-model predictions are ways of obtaining a learning signal. DPO and PPO are ways of using particular signals and data arrangements to change a policy. Keeping these levels separate prevents a common mistake: attributing every difference between two training runs to the optimizer’s name.

    A PPO run trained on executable correctness rewards and a DPO run trained on stylistic preference pairs differ in supervision and data as well as optimization. Their comparison cannot isolate “PPO versus DPO.” Before comparing scores, write down what evidence each method received and what behavior the evaluation rewards.

    The PPO model-role table distinguishes current, old, and reference policies. DPO’s reference is the long-lived anchor, not a frozen actor snapshot refreshed merely because another minibatch began. Likewise, DPO’s $\beta$ is not PPO’s clipping parameter $\epsilon$, and neither is an advantage estimate.

    Why DPO does not need a learned token advantage

    The DPO pair loss differentiates a sum of token log probabilities. A chosen response’s sequence score receives one pair-dependent coefficient, and its token score gradients contribute through that sum. The rejected sequence receives the opposite coefficient. The pair label does not identify exactly which sentence caused the preference, so token-level credit is indirect.

    PPO can distribute a trajectory reward through a critic and an advantage estimator. That provides a different mechanism for assigning tokenwise weights, not a guarantee of correct semantic credit. A bad reward model or poorly fitted critic can still produce misleading weights. Conversely, a preference pair differing in a single well-chosen detail can offer useful learning information without a learned critic.

    A simple contrast illustrates the data issue. If two answers share a long correct explanation but differ in the final arithmetic, a response-level label tells DPO which entire continuation was preferred. It does not explicitly label every shared token as responsible. Neither method should be described as reading the annotator’s reason unless that reason is actually part of the training signal.

    What the shared reward-optimization motivation does not imply

    DPO’s derivation connects an implicit preference reward with a KL-regularized policy optimum. PPO is a policy optimization algorithm that can be used with a reward function and reference penalty. This relationship does not imply that finite offline DPO and a particular PPO implementation follow the same trajectory, use the same state/response distribution, or produce the same trained model.

    Even with a shared ideal utility, practical results depend on preference coverage, reward-model fitting, policy realizability, optimizer behavior, regularization conventions, and how far training proceeds. The finite-response lab deliberately chooses a world where these differences can be separated rather than hidden behind a large model.

    A smaller training loop still has resource costs

    Canonical DPO does not require a separately trained reward model, a value model, or online rollout generation during each fixed-dataset optimization stage. It still needs policy forward and backward passes for two responses, plus reference scores that are either computed or validly cached. Two long responses per example can make activation memory and padding waste substantial.

    The number of named model roles does not directly give a memory multiplier. Parameter sharing, adapters, quantization, reference caching, and distributed placement change the actual memory bill. Compare the real configuration: number of scored response tokens, gradient-carrying parameters, optimizer states, activation storage, and generation work. Avoid describing DPO as requiring only forward passes; the trainable policy still needs backpropagation.

    Fresh comparisons change the data regime

    An iterative preference pipeline can generate responses from an updated policy, label new comparisons, and then run another DPO stage. This can expose errors absent from the original dataset. It also adds generation and judging costs, and raises questions about dataset mixing and reference choice. It is useful to state “offline fixed-dataset DPO” or “iterative preference collection” explicitly.

    Other preference objectives may alter token-length normalization, target margins, the reference term, or assumptions about labels. Those changes should be derived and named individually. A library class called a DPO trainer may offer multiple such losses; selecting a different option does not make the resulting objective identical to canonical sigmoid DPO. TRL’s documented loss options.

    Choose the next experiment from the missing evidence

    If you already have representative, trustworthy comparisons, a fixed-dataset DPO experiment lets you test whether the model can learn their distinctions. If the important failures only appear in responses produced by the evolving policy, fresh collection deserves attention. If the task has a direct executable reward, investigate how that reward is sampled and optimized rather than manufacturing preference pairs by habit.

    These are experiment-design considerations, not a ranking that one method always wins. Hold the prompt split and evaluation protocol fixed, examine generated outputs, and report both the training evidence and the compute budget. When a run fails, return to the diagnostics chapter; when an equation is unclear, return to the derivation.

    Check your understanding: Can I replace PPO’s old-policy log probability with a DPO reference score and keep the same interpretation?

    No. PPO’s denominator describes the policy that sampled a recent trajectory. DPO’s reference defines a baseline for preference scores. Their lifetimes, data assumptions, and roles in the objective are different.
