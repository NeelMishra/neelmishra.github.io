    DPO: From Preference Pairs to a Policy You Can Explain

    September 2026 · 5 min read + experiments

    An original visual guide to Direct Preference Optimization: derivation, gradients, token-level implementation, data diagnostics, a runnable PyTorch lab, and the connection to PPO.

    Read the explanation

    One equation, several ideas worth separating

    Direct Preference Optimization (DPO) turns comparisons between responses into a loss for a language model. Its final equation is short. Understanding why it uses a reference model, what its gradient rewards, and which tokens belong in that equation takes more care. This series develops those ideas in order, with a small numerical example at each difficult step.

    These are original notes within Reinforcement Learning → DPO. If you have completed the PPO notes, you already know what a policy and a reference model are. DPO takes a different route from preference evidence to policy parameters. You do not need GAE or the clipped PPO objective to follow its derivation.

    The prerequisites are conditional probability, logarithms, gradients, and basic PyTorch tensor shapes. A language model is treated as a probability distribution over responses given a prompt. The first half works with whole responses; the implementation chapter then opens that probability into token-level terms.

    Pick a reading route

    • First encounter with preference training: read chapters 1–3, calculate the four log probabilities in the margin example, then continue to implementation.
    • Implementing a trainer: use the response-scoring chapter beside the runnable source. Verify the shift and masks before interpreting a loss curve.
    • Trying to understand a disappointing run: start with coverage and diagnostics, then reproduce the lab’s probability counterexamples.
    • Coming from RLHF with PPO: read the derivation, then the workflow comparison. The old-policy denominator and DPO’s fixed reference have different roles.

    A small, consistent vocabulary

    SymbolMeaning
    $x$Shared prompt, including the relevant conversation
    $y_w, y_l$Chosen and rejected responses to that prompt
    $\pi_\theta,\pi_{\mathrm{ref}}$Trainable policy and fixed reference policy
    $r(x,y)$Utility used in the preference model / ideal derivation
    $\beta>0$Reference penalty coefficient in the ideal reward problem
    $\ell_\theta(y\mid x)$Sequence log probability: $\log\pi_\theta(y\mid x)$
    $\Delta$Chosen minus rejected policy-to-reference log-ratio gain
    $m=\beta\Delta$Preference logit; the canonical loss is softplus(−m)

    Use the figures to make a prediction, then check it

    Six chapters include a live calculation: a preference probability curve, an exact reward–KL optimum, a loss and gradient explorer, a token-reduction example, an unseen-response counterexample, or recorded training checkpoints. Predict what a control should change before moving it.

    The lab contains a runnable PyTorch experiment, mathematical assertions, three recorded seeds, and a standalone plot. It uses a fully enumerated response space so that the population optimum is known. Its curves are measurements of that synthetic task, not language-model benchmark claims.

    Keyboard controls, reduced-motion preferences, printing, and reading without JavaScript are supported. Each chapter closes with an expandable question that tests its central distinction.

    Know which version of DPO you are learning

    Unless a section explicitly says otherwise, “DPO” here means the canonical sigmoid preference loss with a fixed reference and an offline pair dataset. Averaging token log probabilities, changing label targets, or refreshing the reference changes the training specification. Learn the baseline well enough to identify those changes before grouping everything under a trainer’s name.

    The original DPO paper, its reference implementation, and the TRL trainer documentation are linked where their equations or implementation choices matter. The worked examples and lab are designed to let you check the underlying reasoning directly.
