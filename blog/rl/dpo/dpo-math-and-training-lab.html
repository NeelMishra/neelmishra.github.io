    A DPO Lab You Can Verify: Exact Checks and Recorded Training Runs

    September 2026 · 5 min read + experiments

    Run the loss and masking checks, fit a finite response policy to synthetic preferences, and compare the learned distribution with an analytic optimum.

    Read the explanationTry the calculation

    Test DPO in a world with known answers

    The downloadable PyTorch lab checks the loss and token reducer, then trains a tiny policy on simulated preferences. It runs on a CPU and downloads no model or dataset. Start with the checks before training:

    python -m venv .venv
# macOS / Linux; on Windows use .venv\Scripts\activate
source .venv/bin/activate
python -m pip install torch
python dpo_lab.py --check
python dpo_lab.py --train --seeds 0 1 2 --output results.json

    Run these commands where you downloaded the file. The README includes setup and plotting instructions. The recorded results contain the versions, settings, preference counts, and saved measurements.

    Each check answers a concrete question

    QuestionWhat the lab checks
    Is the pair loss correct?Known values, gradient signs, β scaling, and extreme margins
    Is the reference fixed?No reference gradients and the expected initial loss
    Are the right tokens scored?Causal shift, ignored positions, extra padding, and empty responses
    Does the derivation agree numerically?Optimal-policy normalization and the reward–KL identity

    For example, the masking check changes logits at positions that should be ignored and verifies that the response score is unchanged. Passing this check validates the reducer; a real language model still needs correct attention and position handling.

    Learn preferences over three answers per prompt

    Each of three prompts has three possible whole responses, A, B, and C. The first prompt uses reference probabilities (0.5, 0.3, 0.2) and true rewards (0, 1, −0.5), matching the derivation’s example. The results file specifies the other prompts.

    The simulator uses the Bradley–Terry preference probability to sample 500 judgments for each response pair. Three pair types across three prompts give 4,500 judgments per seed. The optimizer sees those judgments, not the underlying rewards.

    Counts avoid storing duplicate rows. If a pair gets 350 A-wins and 150 B-wins, its average loss is 70% of the A-win loss plus 30% of the B-win loss. This exactly represents the sampled labels; it is not an invented soft target.

    The policy has three trainable scores per prompt, converted into probabilities. It starts at the reference and takes 400 full-batch Adam steps, using learning rate 0.05 and $\beta=0.7$. This isolates preference learning from language-model infrastructure.

    Distinguish fitting labels from recovering the population

    Training loss uses the sampled judgment counts. Population loss uses the simulator’s exact preference probabilities. Because every answer and pair is known here, we can calculate that population loss directly instead of estimating it on a random test sample.

    We also know the ideal policy from chapter 2. KL to that optimum measures how far the learned distribution is from this target; zero means a match. This is different from KL to the original reference.

    The remaining gap varies across seeds because 500 judgments do not exactly reproduce the underlying preference probabilities. Compare runs using the same population measurement. Lower training loss on one sampled dataset does not by itself mean a better policy than a run trained on another dataset.

    Read the reusable helpers first

    Start with dpo_loss and response_logps. These implement the operations explained in the scoring chapter. Then read optimal_policy and objective for the known target, followed by train for label sampling and optimization.

    The plotting script draws the saved JSON values; it does not rerun training. The experiment verifies behavior in this finite world. It does not measure real annotation quality or a language model’s ability to generate good answers.

    Reduce the number of judgments first

    Try fewer judgments per pair and predict a larger spread across label seeds. Keep the population evaluator fixed so you can distinguish sampling error from optimizer behavior. Save each changed configuration to a separate results file.

    For a second experiment, remove comparisons involving C and revisit the coverage example. If you change $\beta$, also recompute the ideal policy: it belongs to the new reward–reference tradeoff.
