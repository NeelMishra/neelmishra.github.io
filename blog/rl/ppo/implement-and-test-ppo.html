    Build and Test PPO: A Small Agent You Can Actually Inspect

    September 2026 · 5 min read + experiments

    Run a complete PyTorch PPO agent, reproduce three seeded experiments, and test the mathematics before trusting a learning curve.

    Read the explanation

    Run PPO somewhere you can predict the answer

    The single-file PyTorch lab turns chapter 5’s loop into a runnable example. It includes its own tiny environment, so you can focus on the policy, critic, and buffer. NumPy and PyTorch are the only extra runtime dependencies.

    Download the file into a working directory, create a virtual environment, and start with the mathematical checks. These commands use a macOS/Linux shell:

    python -m venv .venv
# macOS / Linux; on Windows use .venv\Scripts\activate
source .venv/bin/activate
python -m pip install numpy torch
python ppo_linewalk.py --check
python ppo_linewalk.py --seeds 0 1 2 --updates 80 --output results.json

    The first script command checks the calculations without training. The second trains three random seeds and writes their measurements to results.json. For recorded package versions and settings, see the saved run data; for running and plotting instructions, see the lab README.

    The task is to walk right

    The agent starts at position 0. It can move left or right, and reaching position 5 ends the episode with reward +1. Every other action costs 0.01. Moving left from position 0 leaves it there.

    An always-right policy pays four step costs and then earns the goal reward: $1-4(0.01)=0.96$. That is the maximum undiscounted episode return. Evaluation also reports how often the agent reaches the goal within 12 actions.

    The collector resets unfinished episodes at that 12-action limit. Treat this as an external interruption: the critic still predicts future reward from the last position. Use the boundary rules from chapter 3. Evaluation’s bounded success rate and the critic’s discounted value answer different questions.

    Read the code in the order data moves

    1. Environment and collection: LineWalk.step saves the successor before resetting. Collection stores the action, reward, old log probability, and old value without gradients.
    2. Advantage preparation: gae walks backward through the ordered buffer and returns actor weights and critic targets.
    3. Optimization: train re-scores the stored actions under the current network. The old log probabilities and targets stay fixed.
    4. Evaluation: evaluate runs separate episodes using its own random generator, so evaluation does not change the training sampler’s random stream.

    The network shares a small hidden layer between its action and value predictions. Each iteration collects 512 transitions from 32 environments, then allows up to four optimizer passes. KL-based stopping may end those passes early. The exact configuration lives in the results file.

    Each point evaluates 512 episodes. By the first post-initialization checkpoint, at 5,120 collected transitions, all three saved runs reached 100% sampled success. The lines connect checkpoints; they do not tell us exactly when learning happened between them.

    This shows that the implementation learns this small task with the saved settings. It is a teaching experiment, not a reproduction of the control benchmarks in the PPO paper. Different seeds or software versions may change the measured path.

    What a successful check means

    The --check command compares GAE with an independent calculation, checks terminal and timeout handling, and verifies PPO’s clipping values and gradients. It also checks that targets are detached and that the current/old ratio starts at one.

    These checks catch calculation and bookkeeping mistakes. The learning curve answers the separate question of whether the complete agent improves in the environment. If a run claims a return above 0.96, inspect reward accumulation and reset handling first.

    Change one thing and predict what will happen

    Start by increasing optimizer epochs while keeping collected transitions fixed. Does policy movement grow, and does early stopping trigger more often? Save the new configuration and compare evaluation return across the same seeds. Once that experiment is clear, try $\lambda=0$ to see how much the actor depends on one-step critic predictions.

    The diagnostics chapter explains which measurements help distinguish a broken update from an unhelpful setting.
