    One Complete PPO Update: What Moves and What Stays Frozen

    September 2026 · 5 min read + experiments

    Follow tensor shapes through collection, GAE, minibatch optimization, entropy regularization, and a KL-based stopping rule.

    Read the explanationTry the calculation

    Collect once, learn several times, then collect again

    The previous chapters built the advantage estimate and the clipped actor loss. This chapter connects them. One PPO iteration has two stages: collect experience with the current policy, then make several small updates using that fixed batch. The updated policy collects the next batch.

    Suppose we run $N$ environments for $T$ steps. The buffer initially has a time axis and an environment axis. It contains $B=TN$ transitions in total. Our small lab uses six observation features per transition:

    Buffer fieldShape in the labWhy it exists
    observations[T, N, 6]Recompute current actor and critic outputs
    actions[T, N]Re-score the sampled categorical action
    old_logp, old_value[T, N] eachFrozen denominator and starting value estimate
    reward, next_value[T, N] eachCompute TD residuals with the actual successor
    terminated, truncated[T, N] Boolean eachSeparate bootstrap and trace boundaries
    advantage, target[T, N] eachFixed actor weights and critic regression labels

    The saved log probabilities describe the collector. The saved values help compute advantages. Neither is recomputed as an “old” quantity after an optimizer step.

    Prepare the actor weights and critic targets

    Run GAE backward while the buffer is still ordered by time. Construct the critic’s return targets before any normalization of the actor’s advantages. These become fixed training data for this iteration.

    Now flatten the buffer to $B$ rows and shuffle those rows into minibatches. An epoch is one pass over the same buffer. It adds optimizer work, not new environment experience. In the figure, follow one stored action: its old probability stays 0.25 while its new probability changes.

    The actor and critic have different jobs

    The actor loss is the negative of the clipped score. The critic loss measures squared error between its current value prediction and the fixed return target. An optional entropy bonus encourages the policy to keep some uncertainty about which action to take.

    Write these as $L_{\mathrm{actor}}$, $L_V$, and $H$. Positive coefficients $c_V$ and $c_H$ control their relative strength. A single loss to minimize is:

    $$L_{\mathrm{total}}=L_{\mathrm{actor}}+c_V L_V-c_H H.$$

    The entropy term has a minus sign because we want more of it while minimizing the loss. Our lab uses half the mean squared error for $L_V$, with $c_V=0.5$ and $c_H=0.01$. Those are lab settings, not mandatory PPO constants.

    Stop reusing a batch if the policy moves too far

    KL divergence measures how different two action distributions are. Here we compare the collection policy with the updated policy at the stored states. A value near zero means little movement. This is useful because clipping alone does not impose a hard limit on policy change.

    The lab estimates this distance after each optimizer step and stops the remaining passes if it exceeds 0.03. The threshold is a tuning choice. The triggering step has already happened; stopping prevents further steps rather than undoing it. Spinning Up’s PPO implementation offers another concrete example of KL-based early stopping.

    Follow one complete iteration

    The pseudocode below combines the pieces. actor_loss includes PPO clipping; value_loss compares current predictions with saved targets. The stop operation exits both inner loops.

    new_dist is the current actor’s action distribution for each observation in the minibatch. In our lab, it is a PyTorch Categorical object built from the actor’s outputs. For one state, it might assign 30% probability to going left and 70% to going right. new_value is the critic’s current value prediction for each observation.

    Inside actor_loss, new_dist.log_prob(batch.actions) gives the new_logp of the stored actions for PPO’s ratio. new_dist.entropy() measures the policy’s uncertainty at each observation; .mean() averages it over the minibatch. “New” means computed using the current network parameters on this pass. The saved old_logp stays fixed.

    for iteration in range(iterations):
    rollout = collect(policy, envs, T, no_grad=True)
    advantage, target = gae_from_ordered_rollout(rollout)
    freeze(rollout.old_logp, advantage, target)
    for epoch in range(K):
        for batch in shuffled_minibatches(rollout, advantage, target):
            new_dist, new_value = actor_critic(batch.obs)
            loss = actor_loss(new_dist, batch) + cV * value_loss(new_value, batch)
            loss -= cH * new_dist.entropy().mean()
            optimizer.zero_grad()
            loss.backward()
            clip_grad_norm_(parameters, max_norm)
            optimizer.step()
            if rollout_kl() > target_kl:
                stop_all_remaining_epochs_for_this_rollout()
    # The next iteration collects fresh experience with the updated policy.

    Before backward(), clear old gradients. The gradient-norm clipping call limits the size of the gradient vector; it is a separate operation from PPO’s probability-ratio clipping. In the actual arrays, current values, targets, log probabilities, and advantages must each have one entry per minibatch row. Shapes [B] and [B, 1] do not subtract element by element.

    This collect-and-reuse structure follows the PPO paper’s Algorithm 1. Our complete source makes the stopping condition and environment resets explicit.

    Count experience separately from reuse

    With 32 environments and 16 steps, one iteration collects 512 transitions. Four epochs with minibatches of 128 allow 16 optimizer steps. The model sees 2,048 sample presentations, but only 512 are newly collected transitions. Report both when comparing experiments.
