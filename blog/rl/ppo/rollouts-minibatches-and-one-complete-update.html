    One Complete PPO Update: What Moves and What Stays Frozen

    September 2026 · 5 min read + experiments

    Follow tensor shapes through collection, GAE, minibatch optimization, entropy regularization, and a KL-based stopping rule.

    Read the explanationTry the calculation

    The outer loop owns the data distribution

    At the beginning of an iteration, the current actor becomes the behavior policy for that collection. Run $N$ environments for $T$ steps with gradients disabled. A rollout may contain complete episodes, partial episodes, or several resets in a single environment column. The storage layout should preserve enough information to distinguish them.

    Buffer fieldShape in the labWhy it exists
    observations[T, N, 6]Recompute current actor and critic outputs
    actions[T, N]Re-score the sampled categorical action
    old_logp, old_value[T, N] eachFrozen denominator and starting value estimate
    reward, next_value[T, N] eachCompute TD residuals with the actual successor
    terminated, truncated[T, N] Boolean eachSeparate bootstrap and trace boundaries
    advantage, target[T, N] eachFixed actor weights and critic regression labels

    A vector of categorical action indices has shape $[B]$, not $[B,1]$. If the critic produces $[B,1]$, squeeze that final singleton dimension. Subtracting a $[B]$ target from a $[B,1]$ value can broadcast into a $[B,B]$ matrix without throwing an exception. Explicit shape assertions are more valuable here than another training run.

    Compute the learning problem once

    Use the two-mask GAE recurrence on the ordered buffer. Build critic targets from raw advantages plus old values. If normalizing actor advantages, do that after constructing targets and before shuffling. These tensors must not retain a gradient graph.

    Then flatten time and environment into $B=TN$ samples. Each optimizer epoch draws a fresh random permutation of indices and splits it into minibatches. This makes the optimization order less correlated; it does not turn the data into independent samples or create extra environment experience.

    Combine three objectives with the correct signs

    The actor maximizes the clipped surrogate. The critic minimizes a squared prediction error. Entropy encourages a broader action distribution, so it is a reward-like term for the actor. A minimization loss is

    $$\mathcal L=-L^{\mathrm{clip}}+c_V\underbrace{\frac12\mathbb E[(V_\phi-\hat V^{\mathrm{target}})^2]}_{L_V}-c_H\mathbb E[H(\pi_\theta(\cdot\mid s))].$$

    The half in $L_V$ is a convention that affects the effective value-loss coefficient. Our lab uses it explicitly with $c_V=0.5$ and $c_H=0.01$. A different implementation without the half needs a different coefficient to match the same gradient. For a categorical distribution, entropy is $-\sum_a\pi(a\mid s)\log\pi(a\mid s)$ and can be calculated exactly.

    Before each step, clear accumulated gradients. Backpropagate the combined loss, clip the global parameter-gradient norm if configured, then call the optimizer. Gradient-norm clipping constrains the size of a gradient vector; it is separate from clipping the PPO surrogate’s likelihood-ratio incentive. Neither should be described as the other.

    Monitor policy movement, not only the loss

    On sampled old-policy actions, let $\ell_t=\log\pi_\theta-\log\pi_{\mathrm{old}}$. One useful nonnegative per-sample diagnostic is $\exp(\ell_t)-1-\ell_t$. With normalized distributions and common support, its expectation under the old policy equals $D_{\mathrm{KL}}(\pi_{\mathrm{old}}\Vert\pi_\theta)$ at the sampled states, because $\mathbb E_{\mathrm{old}}[\exp(\ell_t)]=1$. Its finite-batch average remains an estimate.

    Our lab checks this estimate on the entire stored rollout after each optimizer step. If it exceeds 0.03, it stops further steps on that batch. The check costs additional forward passes but is simple to inspect. Since it happens after a step, an overshoot has already occurred; stopping is not projection or rollback. Other implementations use minibatch estimates or different stopping locations. OpenAI’s Spinning Up implementation is a useful concrete comparison for buffer storage, loss signs, and early stopping. Spinning Up PPO source.

    The complete algorithm at a glance

    for iteration in range(iterations):
    rollout = collect(policy, envs, T, no_grad=True)
    advantage, target = gae_from_ordered_rollout(rollout)
    freeze(rollout.old_logp, advantage, target)
    for epoch in range(K):
        for batch in shuffled_minibatches(rollout, advantage, target):
            new_dist, new_value = actor_critic(batch.obs)
            loss = actor_loss(new_dist, batch) + cV * value_loss(new_value, batch)
            loss -= cH * new_dist.entropy().mean()
            optimizer.zero_grad()
            loss.backward()
            clip_grad_norm_(parameters, max_norm)
            optimizer.step()
            if rollout_kl() > target_kl:
                stop_all_remaining_epochs_for_this_rollout()
    # The next iteration collects fresh experience with the updated policy.

    This block is pseudocode; the named stopping operation exits both inner loops. The downloadable implementation uses an explicit Boolean to do that. It also computes successor values before environment resets, so the mask equations correspond to the actual stored observations.

    Count samples and optimizer work separately

    With 32 environments and 16 steps, each iteration collects 512 transitions. Four epochs and minibatches of 128 permit 16 optimizer steps and 2,048 sample presentations. They do not represent 2,048 newly collected transitions. Increasing epochs increases reuse and policy drift on the same states; increasing rollout size changes the amount of experience and the estimator’s data. Reporting both is necessary for a meaningful experiment comparison.

    Check your understanding: Should the old log probability be updated after the first optimizer epoch?

    No. It must continue to describe the policy that generated the batch. Updating it changes the denominator’s meaning and makes every epoch compare against a different behavior policy, while the actual samples remain unchanged.
