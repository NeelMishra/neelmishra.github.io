    PPO for Language Models: Tokens, Rewards, and Two Different Anchors

    September 2026 · 7 min read + experiments

    Apply the general algorithm to text while separating old and reference policies, handling token masks, and making the sampling distribution explicit.

    Read the explanationTry the calculation

    Translate the task, then reuse the algorithm

    For an autoregressive language model, a state is the prompt plus the response tokens already generated. An action is the next token. The transition appends that token to the prefix. A response ending with EOS is an episode under a common convention. A task score may come from a human-preference reward model, a program verifier, or another explicitly defined evaluator.

    Once those choices are made, the same rollout-and-update loop applies. Sample responses, store action log probabilities, compute rewards and values, estimate advantages, and optimize on those fixed samples. The InstructGPT paper is one historical example of supervised instruction tuning followed by reward-model training and PPO-based RLHF. Its particular recipe is an example rather than the definition of language-model PPO. Ouyang et al., InstructGPT.

    Old and reference policies answer different questions

    RoleWhat it measuresWhen it changes
    $\pi_{\mathrm{old}}$Which policy generated this batch?Refresh at each rollout iteration
    $\pi_\theta$How likely is this action under the trainable actor?Every optimizer step
    $\pi_{\mathrm{ref}}$How far is behavior from a chosen reference?Often held fixed across the run
    $V_\phi$What return is expected from this prefix?Critic optimization
    Task scorerHow good was the response under the task definition?Fixed for a simple PPO training stage

    The old policy controls local reuse: $\rho_t=\pi_\theta(a_t\mid s_t)/\pi_{\mathrm{old}}(a_t\mid s_t)$. The reference policy provides a longer-lived anchor, often initialized from a supervised model. A rollout can stay close to its old policy yet drift far from the reference after many iterations. One KL curve cannot substitute for both comparisons.

    These roles do not require five independent full model copies. Old sampled-action log probabilities can be stored. The critic may share features with the actor or be a separate model. A reward model may be replaced by a verifier. Those are implementation decisions with memory, compute, and optimization consequences.

    A concrete reward decomposition

    For a response of $L$ actions, one possible rollout reward is

    $$R_t=-\beta\!\left(\log\pi_{\mathrm{old}}(a_t\mid s_t)-\log\pi_{\mathrm{ref}}(a_t\mid s_t)\right)+\mathbf1[t=L-1]S(x,y).$$

    Here $S(x,y)$ is the response score and $\beta$ sets the reference penalty strength. Under old-policy action sampling, the expected log-ratio at a fixed prefix is $D_{\mathrm{KL}}(\pi_{\mathrm{old}}\Vert\pi_{\mathrm{ref}})$. An individual sampled log-ratio can be negative; it is a noisy contribution, not a per-token divergence guaranteed to be positive. For the straightforward rollout-reward implementation, freeze these rewards before GAE and the optimizer epochs.

    With $\gamma=1$, a two-action response scored 1.2, sampled old-to-reference log-ratios $(0.10,-0.05)$, and $\beta=0.2$ has rewards $(-0.02,1.21)$ and total return 1.19. The second sampled penalty is negative and therefore adds 0.01. Across samples, the expected divergence penalty still has its usual interpretation. Discounting is a task choice: using $\gamma<1$ with only a terminal score also changes how delayed scores are valued.

    An explicit differentiable KL loss evaluated during optimization is another construction. It can change with the current actor on each step. Do not casually mix that with a fixed rollout reward or count the same penalty twice without intending the resulting objective.

    Align states, actions, and masks

    A causal decoder’s output at a prefix predicts the next token. In a teacher-forced scoring pass, align shifted logits with the sampled response token IDs. The critic value for an action belongs to the prefix before that action. An off-by-one shift can produce plausible-looking tensor shapes while crediting the wrong token.

    Set the policy-loss mask to one on generated response actions and zero on prompt and padding positions. If EOS is an action sampled by the policy, include its log probability and reward/termination convention consistently. If maximum length is part of the finite task, reaching it is terminal; if collection interrupts an otherwise continuing task, treat it as truncation and justify the bootstrap. The label “max tokens” alone does not decide the semantics.

    Loss reduction also matters. Summing token contributions within each response and averaging across responses estimates a trajectory-sum objective. Averaging across all valid tokens introduces a batch-wide length-dependent scale relative to that sum; averaging tokens separately within each response additionally downweights long trajectories relative to short ones. These are different choices, especially with varying lengths and auxiliary losses. State the exact numerator, denominator, and mask instead of writing only loss.mean().

    The logged behavior distribution must be the one that sampled

    If responses are generated with temperature scaling, the behavior distribution includes that scaling. Logging unscaled probabilities while sampling scaled ones makes the old denominator wrong. Top-k and top-p truncation change support as well as probabilities. If a proposed target assigns mass where the behavior distribution assigned zero, the simple action importance-sampling identity no longer covers the target. A teaching implementation can use a full-support distribution with consistent temperature; a production sampler needs an explicit mathematical account of its transforms.

    Even without sampling transforms, dropout or changed normalization can make collection and re-scoring disagree. Padding side, attention masks, position IDs, and cached versus full-prefix execution must reproduce the same conditional distribution within numerical tolerance. Before training, verify ratios near one at every valid response position. Compare a few cached-generation log probabilities against a full teacher-forced pass to catch alignment errors.

    An optimizer improves the score it is given

    Clipping does not establish that a reward model measures the intended behavior. A model may learn formatting tricks, verbosity, or exploitable verifier inputs that raise score without raising quality. Evaluate with checks independent of the training score, inspect responses across reward ranges, and log response length, EOS frequency, task reward, and reference penalty separately.

    Likewise, replacing PPO with another policy optimizer does not automatically fix a misdefined task. Preference-only methods and group-relative estimators change how the learning signal is obtained; they deserve their own derivations rather than being described as removing an arbitrary box from PPO.

    Check your understanding: Can old-policy KL be small while reference-policy KL is large?

    Yes. Each rollout can take a small local step away from its own behavior snapshot while those steps accumulate far from the fixed reference. The two anchors have different lifetimes and measure different changes.
