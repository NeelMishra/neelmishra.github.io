    PPO for Language Models: From Human Preferences to Token Updates

    September 2026 · 12 min read + token walkthrough

    Follow human comparisons into reward-model training, then connect answer scores, token advantages, and PPO updates in one complete RLHF workflow.

    Read the explanationTrace the token prefixes

    How does “I prefer this answer” become a training signal?

    We want a language model to give answers people find useful, accurate, and easy to follow. A person can compare two answers, but PPO needs numbers it can optimize. Reinforcement learning from human feedback (RLHF) connects the two by training a model to predict human preferences, then using its scores as rewards.

    This chapter follows the three-stage recipe used in InstructGPT: learn from example answers, learn a reward model from comparisons, then improve the answer-generating model with PPO. These are separate training stages, with different data and losses.

    First, start with a model that can follow instructions

    In supervised fine-tuning (SFT), the training data contains prompts paired with good demonstration answers. For each answer, ordinary next-token training increases the probability of its tokens given the prompt and preceding answer tokens. This gives PPO a useful starting policy: a model already able to respond to instructions.

    A demonstration says, “Here is an answer to imitate.” The next stage supplies a different kind of supervision: “Of these answers, this one is better.”

    How human preferences are collected

    1. Select a prompt. Use questions and tasks representative of what the assistant should handle.
    2. Generate candidate answers. Sample two or more responses to that same prompt. Different samples from one model can already give different answers.
    3. Ask a human to compare them. Give raters a shared rubric, such as following the request, factual accuracy, and clarity. They choose the better answer or rank several answers.
    4. Save the comparison. For a pair, store the prompt, the preferred answer, and the less preferred answer. A ranking can supply multiple such pairs.
    An illustrative preference record

    Prompt: “Explain overfitting in one sentence.”

    Chosen: “Overfitting is when a model fits its training examples so closely that it performs poorly on new examples.”

    Rejected: “Overfitting means perfect training accuracy guarantees perfect accuracy on new examples.”

    The label records a choice between answers; the person does not have to invent reward numbers or mark every token. “Chosen” also does not mean flawless. With ambiguous comparisons, a collection process can allow ties or abstentions instead of forcing a choice. The simple loss below uses pairs with a selected winner.

    Good collection needs clear rating instructions and checks on disagreements. Keep some prompts and comparisons aside for evaluation. The InstructGPT paper, Sections 3.2–3.5, describes its prompts, raters, demonstrations, and ranked responses.

    Train a scorer to predict those choices

    Let $x$ be the prompt, $y^+$ the chosen response, and $y^-$ the rejected response. The reward model $r_\psi(x,y)$ reads a prompt and a complete response and returns one real-valued score; $\psi$ denotes its trainable parameters. It can be a language-model backbone with a small output layer that produces one number.

    We want the chosen answer to score higher. Turn the difference between the two scores into a predicted probability $q_\psi$ that the chosen answer wins:

    $$q_\psi=\operatorname{sigmoid}\!\left(r_\psi(x,y^+)-r_\psi(x,y^-)\right),\qquad \operatorname{sigmoid}(z)=\frac{1}{1+e^{-z}}.$$

    The sigmoid converts any real number to a value between 0 and 1. Equal scores give $q_\psi=0.5$; a larger positive score difference gives a probability closer to 1.

    $q_\psi$ is a prediction; we still need a loss to train it. The human selected $y^+$, so the observed outcome is “the chosen answer wins.” That gives this comparison a target of 1. A prediction closer to 1 agrees more strongly with this label; a prediction near 0 confidently disagrees.

    Use the standard negative log-likelihood loss: take the probability the model assigns to the observed outcome, take its logarithm, and negate it. Here that probability is exactly $q_\psi$, so:

    $$\ell_{\mathrm{RM}}(\psi)=-\log q_\psi.$$

    Why the logarithm and minus sign? The logarithm increases as $q_\psi$ increases, so maximizing $\log q_\psi$ still favors the human's choice. The minus sign turns that maximization into a loss we can minimize. It gives a loss near 0 when $q_\psi$ is near 1, and a very large loss when $q_\psi$ is near 0. Logarithms also turn products of probabilities into sums, which makes likelihoods across examples convenient to combine.

    For example, predicting a 90% chance for the human's choice gives a loss of about $0.105$; predicting only 10% gives about $2.303$. Lowering this loss pushes $q_\psi$ upward, which means increasing the chosen answer's score relative to the rejected answer's score. Gradient descent makes that change through the reward model's parameters $\psi$.

    This is the loss for one pair; training averages it across pairs. It is the comparison-based reward training used in Learning to Summarize from Human Feedback, Section 3.4.

    The score itself is not a probability or a human-assigned grade. It can be negative or greater than 1. The comparison loss constrains score differences: adding the same constant to both scores leaves the predicted preference unchanged.

    After this stage, freeze the reward model for PPO training. It can now score fresh responses automatically. Humans supplied the comparisons that taught the scorer; they do not have to review every response generated in a PPO batch.

    A response becomes a sequence of token actions

    Write a generated response as $y=(y_0,\ldots,y_{T-1})$, where $T$ is its token count. At position $t$, the model has the prompt and all earlier response tokens. That prefix is the state; the next token is the action:

    $$s_t=(x,y_{<t}),\qquad a_t=y_t.$$

    Here $y_{<t}$ means “response tokens before position $t$.” The actor $\pi_\theta(a_t\mid s_t)$ gives a probability to each possible next token. Sampling one and appending it creates the next state. An end-of-sequence token, EOS, ends the response. For this explanation, a completed response is one episode.

    Which model does which job?

    The SFT model initializes the trainable actor and a frozen reference copy. Each PPO iteration also records the actor that collected its batch, called the old policy. The reward model scores whole answers; a critic learns to predict the reward still to come from a prefix. We write $\theta$ for the actor's parameters and $\phi$ for the critic's.

    RoleInput → outputWhen it changes
    Actor $\pi_\theta$Prefix → next-token probabilitiesDuring PPO optimizer steps
    Old $\pi_{\mathrm{old}}$Same prefix → probabilities used to collect this batchRefresh for each new rollout batch; fixed while reusing it
    Reference $\pi_{\mathrm{ref}}$Same prefix → SFT starting probabilitiesFrozen throughout this PPO stage
    Reward $r_\psi$Prompt + complete response → preference scoreTrained on human comparisons, then frozen
    Critic $V_\phi$Prefix → expected remaining combined rewardTrained alongside the actor

    The reward model judges the finished answer; the critic forecasts its remaining return before it is finished. The critic's target includes the reward and reference penalty defined next. It is not another human-preference classifier.

    PPO clipping compares the current actor with the old policy to limit the incentive for changing this batch's action probabilities. The reference penalty compares behavior with the fixed SFT reference to discourage cumulative drift. Many small updates can move far from the original model even if each stays near its own old policy.

    These roles need not be five full model copies. Store the old sampled-token log probabilities in the batch. The critic can share a backbone with the actor or use a separate network.

    Turn the answer score into rollout rewards

    A learned scorer is imperfect. If the actor only maximizes its score, it may drift toward unusual answers the scorer overvalues. A reference penalty makes departure from the SFT policy costly. Let $\beta>0$ control its strength.

    At each sampled response token, subtract the reference's log probability from the collecting policy's log probability. Call this sampled log ratio $k_t$:

    $$k_t=\log\pi_{\mathrm{old}}(a_t\mid s_t)-\log\pi_{\mathrm{ref}}(a_t\mid s_t).$$

    Call the reward assigned after token $t$ $R_t$. Give each token reward $-\beta k_t$, then add the reward model's answer score once, at the last response token:

    answer_score = reward_model(prompt, response)  # one scalar
reference_log_ratio = old_logp - ref_logp      # one value per response token
reward = -beta * reference_log_ratio
reward[last_response_token] += answer_score

    The arrays contain valid response tokens only. Here old_logp and ref_logp score the same sampled token using the same prefix. Calculate and freeze these rewards before estimating advantages.

    Use $\gamma=1$ in this example: future rewards are not discounted. Summing the token rewards therefore gives the return for the whole response:

    $$G_0=\sum_{t=0}^{T-1}R_t=r_\psi(x,y)-\beta\sum_{t=0}^{T-1}k_t.$$

    The first term rewards a preferred answer; the second accounts for reference drift. Sequence probability is the product of next-token probabilities, so its log ratio is this sum of token log ratios. This connects the code to the sequence-level reward in Fine-Tuning Language Models from Human Preferences, Section 2.2.

    A particular $k_t$ can be negative, giving that token a bonus. Averaging $k_t$ over actions sampled from the old policy at a fixed prefix gives the nonnegative KL divergence from old to reference: a measure of how different their next-token distributions are. The nonnegative statement is about that average, not every sampled token.

    How does one final score teach earlier tokens?

    An early token changes the prefix from which every later token is generated. Its return therefore includes later rewards, including the final answer score. The critic $V_{\mathrm{old}}(s_t)$ is its collection-time prediction of that remaining return. The advantage $\hat A_t$ estimates whether the sampled continuation did better or worse than this expectation.

    With $\gamma=1$, the GAE calculation from Chapter 3 becomes:

    $$\delta_t=R_t+V_{\mathrm{old}}(s_{t+1})-V_{\mathrm{old}}(s_t),\qquad \hat A_t=\delta_t+\lambda\hat A_{t+1}.$$

    The TD error $\delta_t$ compares the observed reward plus the next prediction against the current prediction. Work backward: the next token's advantage feeds the current one, scaled by $\lambda\in[0,1]$. This is how later evidence reaches earlier decisions. For a completed response, set $V_{\mathrm{old}}(s_T)=0$ and $\hat A_T=0$ because no reward remains after the end.

    At $\lambda=1$, the intermediate value terms cancel, leaving $\hat A_t=G_t-V_{\mathrm{old}}(s_t)$, where $G_t$ is the sum of rewards from token $t$ onward. Smaller $\lambda$ relies more on nearby critic predictions. Either way, a token's advantage is an estimate about its continuation, not a human label saying that the token itself is good.

    The critic's fixed training target is $\text{target}_t=\hat A_t+V_{\mathrm{old}}(s_t)$, using the raw advantage. If you normalize advantages for the actor loss, keep that normalized copy separate from this target, as in Chapter 3.

    Score each token from the prefix that produced it

    During optimization, feed the saved prompt and response back through the causal model. Each position can attend to itself and earlier tokens, never later ones. The output just before a stored response token predicts that token; the critic value must also describe the prefix before that action.

    A loss mask is a keep-or-ignore flag: 1 for generated response actions, 0 for prompt and padding positions. Include EOS when it was sampled. The model reads the prompt, but PPO does not treat prompt tokens as actions the actor chose. This alignment is discussed in the RLHF implementation study.

    Choose an averaging rule for different response lengths. Summing token contributions per response and averaging responses keeps each episode's summed contribution. Averaging within each response first reduces each token's weight in longer answers. These produce different losses.

    What actually updates the language model?

    With responses, rewards, advantages, and targets stored, apply the same clipped PPO loss. Here is its core for one minibatch of valid response-token positions. new_logp comes from the current actor, new_value from the current critic, and advantage and target are the frozen estimates above. epsilon is PPO's clip range:

    ratio = (new_logp - old_logp).exp()
unclipped = ratio * advantage
clipped = ratio.clamp(1 - epsilon, 1 + epsilon) * advantage
actor_loss = -torch.minimum(unclipped, clipped).mean()
critic_loss = 0.5 * (new_value - target).square().mean()

    The ratio is $\pi_\theta(a_t\mid s_t)/\pi_{\mathrm{old}}(a_t\mid s_t)$ because exponentiating a difference of logs recovers a ratio. Positive advantages encourage increasing the sampled token's probability; negative ones encourage decreasing it, with PPO clipping limiting the incentive as explained in Chapter 4. The clip range $\epsilon$ and reference strength $\beta$ have different jobs.

    Gradient descent on the actor loss updates $\theta$ through the current log probabilities. Gradient descent on the critic loss updates $\phi$ toward its fixed targets. The saved tokens and reward scores stay fixed; gradients do not train the reward model in this stage.

    Reuse the batch for a limited number of minibatch passes, then generate fresh responses with the updated actor and repeat. The new collector becomes $\pi_{\mathrm{old}}$ for that next batch. The reference and reward model remain frozen. Chapter 5 supplies the full optimizer loop.

    Make collection and training agree

    Use the same action distribution. Temperature changes how peaked the next-token probabilities are. If generation uses it, use that same temperature when saving and recomputing probabilities. Top-k and top-p filters also change the distribution; a simple teaching implementation can omit them. Define the reference probabilities consistently too.

    Check the first ratio. Before any optimizer step, current and old actors are identical, so ratios should be near 1 on valid response tokens. A mismatch often means a token shift, attention-mask error, or inconsistent sampling setting.

    Define what a length cutoff means. If reaching the maximum length ends the task and the capped answer is scored as complete, there is no future value to predict. If it only interrupts collection of a continuing response, bootstrap from its final prefix using the truncation rule. Do not carry an advantage into a different prompt after a reset.

    Check whether people actually prefer the new answers

    A higher reward-model score is evidence about the scorer, not proof of better answers. Compare old and new responses on held-out prompts, using independent human judgments or task checks. Inspect errors and track answer score, reference penalty, response length, and EOS frequency separately.

    The summarization study found that pushing its reward model too far could reduce human preference. If new behavior exposes gaps in the scorer, a broader training cycle can collect more comparisons and retrain it between PPO stages. For tasks with a reliable verifier, such as code tests, that verifier can provide the answer score instead.

    Where DPO changes this workflow

    Direct Preference Optimization (DPO) also starts with chosen/rejected response pairs. Standard DPO trains the policy directly from those pairs, without separately fitting a reward model or running a PPO rollout-and-critic loop. The DPO/PPO comparison explains how its objective makes that possible.
