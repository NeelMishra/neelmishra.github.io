    The Value Function & the Critic

    July 2026 · 20 min read

    Part 3 ended on a working algorithm that nobody would actually run. REINFORCE gives an unbiased gradient of expected reward, and it does so with almost no assumptions — but the price is a variance so large that the estimate is, for practical batch sizes, numerical noise dressed up as a gradient. This post fixes that without touching the unbiasedness, using one of the oldest tricks in the subject: subtract a number you are allowed to subtract.

    Where We Left Off

    The policy-gradient loss we derived was the log-probability of each sampled token, weighted by the return that followed it:

    $$L(\theta) \;=\; -\,\log \pi_\theta(a_t \mid s_t)\, G_t, \qquad G_t = \sum_{k \ge 0} \gamma^k r_{t+k}.$$

    Minimising this raises the probability of tokens that preceded a large return and lowers the probability of tokens that preceded a small one. It is correct in expectation. The trouble is entirely in the word "expectation": we never have the expectation, only a handful of sampled trajectories, and $G_t$ is a ferociously noisy stand-in for it.

    Consider an outcome-reward setup, which is the common case for language: every $r_t$ is zero until the final token, where a reward model or a grader emits a single scalar. Then every token in a winning response is multiplied by the same positive number and pushed up together; every token in a losing response is multiplied by zero and receives no gradient at all. The estimator cannot tell which of the five hundred tokens in a good answer were the good ones — it credits all of them equally — and it learns nothing whatsoever from failures. Average enough samples and the right answer emerges; but "enough" here can mean thousands of rollouts per update, which is exactly what we cannot afford when each rollout is a full generation from a large model.

    Variance, not bias, is the enemy here. REINFORCE already points in the right direction on average. What ruins it is the spread around that average: two rollouts of the same prompt can hand you gradients that disagree in magnitude by orders of magnitude, so any single minibatch is dominated by sampling luck. Every idea in the next three posts — baselines, advantages, GAE — is a variance-reduction device that tries not to reintroduce bias.

    The Baseline Trick

    Here is the move. Take any function $b(s_t)$ that depends on the state but not on the action taken, and subtract it from the weight:

    $$L(\theta) \;=\; -\,\log \pi_\theta(a_t \mid s_t)\,\big(G_t - b(s_t)\big).$$

    The claim is that this changes nothing about where the gradient points on average, no matter what $b$ you pick, as long as it ignores the action. That claim needs a proof, because it is the licence for everything that follows. The proof is three lines. Look at the extra term the baseline introduces, in expectation over the action drawn from the current policy at a fixed state $s$:

    $$\mathbb{E}_{a \sim \pi_\theta}\!\big[\nabla_\theta \log \pi_\theta(a \mid s)\, b(s)\big] \;=\; b(s) \sum_{a} \pi_\theta(a \mid s)\, \nabla_\theta \log \pi_\theta(a \mid s).$$

    Pull $b(s)$ out of the sum — it does not depend on $a$. Now use the identity that made policy gradients work in the first place, $\pi_\theta \nabla_\theta \log \pi_\theta = \nabla_\theta \pi_\theta$, to turn each term back into a plain gradient of a probability:

    $$= b(s) \sum_{a} \nabla_\theta \pi_\theta(a \mid s) \;=\; b(s)\, \nabla_\theta \sum_{a} \pi_\theta(a \mid s) \;=\; b(s)\, \nabla_\theta 1 \;=\; 0.$$

    The sum of the probabilities over all actions is always exactly one, and the gradient of a constant is zero. So the baseline contributes nothing to the expected gradient: it is unbiased for free. We may subtract any action-independent quantity we like and the algorithm still converges to the same place. The only thing left to decide is which subtraction makes the noise smallest.

    Why Subtracting Helps

    If the expected value is untouched, why bother? Because variance is not untouched. Return to the outcome-reward picture. Without a baseline, every token of a successful response carries the weight $G_t = 1$, and the update shoves the whole batch of tokens upward in lockstep. The gradient is a tug-of-war between entire trajectories, and its length swings wildly with how many winners happened to land in the batch.

    Now subtract a baseline equal to a rough guess of the typical return from each state, say $b(s_t) \approx 0.6$. A response that ends up succeeding gets weights $1 - 0.6 = 0.4$ — still positive, still pushed up, but by less. A response that fails gets weights $0 - 0.6 = -0.6$ — now negative, so its tokens are actively pushed down. The baseline has re-centred the weights around zero: roughly half positive, half negative, instead of a pile of same-signed numbers. Same-signed numbers have a large mean and therefore large sample-to-sample swing; re-centred numbers have a mean near zero and cancel far more gracefully across a minibatch. That cancellation is the variance reduction.

    The baseline is also what lets you learn from failure. With a bare $0/1$ reward and no baseline, a failed rollout has $G_t = 0$ everywhere, so it produces literally zero gradient — the model never hears "do not do that." Subtracting $b(s_t)$ turns every token of that failure into a negative weight $-b(s_t)$, which is a real "push this down" signal. Variance reduction is the textbook justification; recovering a usable signal from failures is the one you feel first in practice.

    The Value Function as the Baseline

    Among all valid baselines, one is special: the expected return from the state itself. Define the state-value function of a policy $\pi$ as the return you expect to collect from $s_t$ onward if you keep acting according to $\pi$:

    $$V^{\pi}(s_t) \;=\; \mathbb{E}_{\tau \sim \pi}\!\big[\,G_t \mid s_t\,\big].$$

    Intuitively this is the ideal baseline, and it can be made rigorous: the variance-minimising baseline is a slightly reweighted version of $V^{\pi}$, and $V^{\pi}$ itself captures almost all of the available reduction while being far easier to interpret and to learn. The reason it works so well is that $G_t - V^{\pi}(s_t)$ asks the sharpest possible question about the action: not "was the return large?" but "was the return larger than what this state was already worth?" That is the quantity Part 5 will name the advantage.

    Notice the superscript $\pi$, and take it seriously. The value of a half-written response is only meaningful relative to how the current model would continue it. A prefix that a strong model would finish correctly and a weak model would botch has genuinely different values under the two policies, even though the text on the page is identical. This is why the value function cannot be estimated once and frozen. As training moves the policy, the returns it expects from every state shift with it, so the critic that estimates $V$ has to be re-trained continuously alongside the policy — a moving target chasing a moving target. Hold on to that; it is the source of half of PPO's practical difficulty.

    ▶ Value as the Average Over Continuations

    A prefix $s_t$ can be continued many ways; each completion earns a final reward. The value of a node is the policy-weighted average of the outcomes in its subtree. Press Step to roll the rewards up from the leaves.

    What Value Feels Like in a Response

    Make it concrete with a maths word problem: "A tank holds 240 litres and drains at 8 litres per minute; how long until it is empty?" The reward is $1$ for the final answer $30$ minutes and $0$ otherwise. Consider three partial responses, each a state $s_t$ the critic must score:

    • Low value. "The tank drains, so we add $240 + 8 = 248 \dots$" — the prefix has already committed to the wrong operation. Most continuations of this text land on a wrong number. Its value is near $0$: the state is nearly lost regardless of which token comes next.
    • Medium value. "We need to find how many minutes it takes." — nothing has gone wrong, but nothing has been decided either. A capable policy finishes this correctly a fair fraction of the time and fumbles the arithmetic the rest. Its value sits in the middle.
    • High value. "Divide the volume by the rate: $240 \div 8 = $" — the setup is correct and only a one-step division remains, which the model almost always gets. Its value is near $1$.

    The point to internalise: value is a property of the prefix's prospects, not of the next token. The high-value state above is valuable before you have seen the token that follows it, precisely because the distribution of continuations from it is good. The critic is a forecaster of how the story tends to end from here, and it is that forecast, not any single next token, that the baseline subtracts.

    The Critic in Practice

    We cannot compute $V^{\pi}$ exactly — that would require averaging over every possible continuation of every prefix — so we learn an approximation $V_\phi$ with parameters $\phi$. The critic is almost always a scalar head bolted onto the transformer trunk: the same stack of layers that produces token logits also feeds a single linear output that emits one real number per position. Often the critic shares the backbone with the policy and only the heads differ; sometimes it is a separate network entirely, which doubles the trunk but decouples the two learning problems.

    Whatever the wiring, the critic is trained by regression. It is handed the returns that were actually observed in the rollouts and asked to predict them, under a squared-error loss:

    $$L^{VF}(\phi) \;=\; \big(V_\phi(s_t) - G_t\big)^2.$$

    The targets $G_t$ are not labels from an oracle; they are the discounted sums of the rewards that this very batch of rollouts happened to earn. That is the chicken-and-egg problem in one sentence: the critic is regressing onto returns generated by a policy that the actor is simultaneously changing, so the target distribution drifts out from under it at every step. A critic that has perfectly fit last iteration's policy is already slightly wrong for this one. In practice this is tolerable because the policy moves in small steps — which, not coincidentally, is exactly what PPO's clipping will later enforce — but a critic that lags too far behind poisons every advantage computed from it.

    # Critic: a scalar head sharing the transformer trunk with the policy.
class ActorCritic(nn.Module):
    def __init__(self, trunk, hidden):
        super().__init__()
        self.trunk       = trunk                 # shared transformer backbone
        self.policy_head = nn.Linear(hidden, vocab_size)
        self.value_head  = nn.Linear(hidden, 1)  # one scalar per position

    def forward(self, tokens):
        h      = self.trunk(tokens)              # (batch, seq, hidden)
        logits = self.policy_head(h)             # (batch, seq, vocab)
        values = self.value_head(h).squeeze(-1)  # (batch, seq)
        return logits, values

# Value loss: regress the critic onto the observed returns.
def value_loss(values, returns):
    # values, returns: (batch, seq); returns are computed from real rewards.
    return ((values - returns) ** 2).mean()

    Actor and Critic Together

    A policy that is improved by a gradient is the actor; the value estimator that supplies its baseline is the critic. Training both at once is the actor–critic pattern, and it is a genuine departure from pure REINFORCE, which carries no learned value at all and pays for that simplicity in variance. The actor asks "which tokens should be more likely?"; the critic answers "compared to what?"; and the two are trained in the same loop, the critic on regression targets and the actor on the baseline-adjusted policy gradient.

    The cost is memory. You are now holding two networks in the optimiser instead of one — two sets of parameters, two sets of gradients, two sets of Adam moments — even when they share a trunk, because the value head, its activations, and its optimiser state are all extra. When Part 10 assembles the full PPO training loop you will find four models resident at once (policy, critic, a frozen reference, and a reward model), and the critic is one of the two that a method like GRPO in Part 12 will try to delete precisely to reclaim this memory. For now, just note the trade: we bought a massive variance reduction, and the bill is a second network.

    A Trajectory Worked by Hand

    Take a five-step episode with a single terminal reward and no discounting, $\gamma = 1$: rewards $r = (0,0,0,0,1)$, so the return from every step is $G_t = 1$. Suppose the critic, imperfect as always, has learned the estimates below. The baseline-adjusted weight is $G_t - V_\phi(s_t)$.

    step $t$$G_t$$V_\phi(s_t)$$G_t - V_\phi(s_t)$
    01.000.50+0.50
    11.000.70+0.30
    21.000.60+0.40
    31.000.80+0.20
    41.000.90+0.10

    Before the baseline every weight was $+1$; after it, the weights shrink toward zero and vary from step to step. This is a winning episode, so the weights stay positive — but observe how much smaller and more differentiated they are. Step 4, where the critic already saw success coming ($V=0.90$), barely nudges; step 0, which turned out much better than its lukewarm forecast, moves the most. The gradient now emphasises the tokens that were genuinely surprising, not merely the tokens that happened to be in a good response.

    The signed part of "signed weights" shows up across the batch. Put a losing sibling episode next to this one — same shape, terminal reward $0$, so $G_t = 0$ throughout — and its weights $0 - V_\phi(s_t)$ are all negative:

    losing episode$t=0$$1$$2$$3$$4$
    $V_\phi(s_t)$0.550.600.500.450.40
    $G_t - V_\phi(s_t)$−0.55−0.60−0.50−0.45−0.40

    Without the baseline that failure would have contributed a gradient of exactly zero. With it, every token of the failed attempt is pushed down. Across the two episodes the weights are now genuinely mixed in sign and centred near zero — the variance-reducing structure we were after. Here is the computation in code, using the shape we will reuse in Parts 5 and 6:

    import torch

gamma  = 1.0
rewards = torch.tensor([0., 0., 0., 0., 1.])          # terminal reward only
values  = torch.tensor([0.50, 0.70, 0.60, 0.80, 0.90]) # critic estimates V(s_t)

# Discounted returns G_t, computed backward from the end of the episode.
returns = torch.zeros_like(rewards)
running = 0.0
for t in reversed(range(len(rewards))):
    running    = rewards[t] + gamma * running
    returns[t] = running

baseline_weights = returns - values                    # G_t - V(s_t)
print(returns)           # tensor([1., 1., 1., 1., 1.])
print(baseline_weights)  # tensor([0.50, 0.30, 0.40, 0.20, 0.10])

    The Objective So Far

    We entered with the high-variance REINFORCE loss and leave with a baseline subtracted, at no cost in bias:

    $$L(\theta) \;=\; -\,\log \pi_\theta(a_t \mid s_t)\,\big(G_t - V_\phi(s_t)\big).$$

    That bracket, $G_t - V_\phi(s_t)$, is doing all the interesting work: it measures how much better a trajectory turned out than the state's own forecast. In the next post we give it its proper name — the advantage — connect it to the action-value function $Q$, and discover that $G_t - V_\phi(s_t)$ is only the crudest of several ways to estimate it, the one that inherits every bit of the Monte Carlo return's noise.
