    Debug PPO with Evidence: Ratios, KL, Values, and Real Evaluation

    September 2026 · 5 min read + experiments

    Learn what each training metric can tell you, diagnose failure patterns, and design comparisons that separate data budgets from optimizer reuse.

    Read the explanationTry the calculation

    Check the calculation before changing settings

    A flat reward curve does not tell us what broke. Begin with a check whose answer is known: before the first update on a fresh batch, re-score the stored actions. The current policy is still the collection policy, so every current/old probability ratio should be approximately 1.

    If it is not, inspect the saved policy, action, observation, and log-probability calculation. Dropout or changing observation-normalization statistics can also change the answer. Fix this mismatch before tuning the learning rate.

    Next, print one short trajectory and follow its rewards and boundary flags through GAE. This checks whether the actor is receiving the weights you intended.

    Give each measurement one job

    Start with five measurements. Together they separate task performance, policy movement, exploration, and critic learning:

    MeasurementQuestion it answersHow to read it
    Evaluation return / successIs behavior improving?Measure fresh episodes with the same evaluation protocol.
    KL(old ∥ current)How far did the policy move?Near zero means similar action distributions at the stored states.
    Clip fractionHow many ratios left the clip interval?A threshold count, not a smooth distance.
    EntropyHow spread out are action choices?A collapse means fewer choices are being explored.
    Value lossDoes the critic fit its return targets?Inspect the targets too; fitting incorrect targets is not useful.

    KL is short for Kullback–Leibler divergence. It measures a difference between distributions, not task quality. A policy can move very little and still fail. Likewise, a low training loss is not a substitute for evaluation return.

    See why clip fraction and KL tell different stories

    Use an old policy that chooses left and right equally often. If the new right probability becomes 0.6, the ratios are $0.6/0.5=1.2$ for right and $0.4/0.5=0.8$ for left. With a clip tolerance of 0.2, both sit exactly on the interval boundary.

    A strict outside-the-interval count is still zero, but the distributions have changed, so KL is positive. Move the slider just past 60% and watch the count jump while the distance changes smoothly:

    Clip fraction also does not tell you how many samples have a flat actor contribution. The advantage sign matters, as the clipping chapter showed. An action with positive advantage that becomes much less likely still supplies a corrective signal.

    Choose the next check from the symptom

    What you seeCheck next
    Large KL after one stepVerify initial ratios, then reduce the learning rate or inspect unusually large advantage weights.
    Entropy falls but reward stays lowCheck advantage signs and whether useful rewards occur in the collected data.
    Large critic errorInspect target values, reward scale, and timeout handling before adding network capacity.
    Training loss falls but evaluation worsensCheck policy movement and compare actual sampled behavior with the reward being optimized.

    Change one thing at a time. For example, if extra optimizer epochs increase KL without improving return, the extra reuse is not helping under that configuration. Reducing epochs cannot fix an incorrect ratio calculation.

    Compare runs using the same budget and evaluator

    Count newly collected transitions separately from optimizer work. Four passes over 512 transitions use the same number of sample presentations as one pass over 2,048 transitions, but the second run collected four times as much experience.

    Use several training seeds and show each run, as in the lab results. Keep evaluation episodes, time limits, and action selection consistent. Sampling from the policy and always taking its most likely action are different evaluation protocols.

    Implementation choices can materially change PPO results. Huang et al.’s implementation study provides code and configurations for tracing those choices. Use a specific configuration as the comparison, rather than the algorithm name alone.

    Add complexity one piece at a time

    Once the tiny task works, move to your target environment with a documented reward and termination rule. Add wrappers, normalization, and action transformations one at a time. Keep a known-working run so you can identify which change altered behavior.

    The final PPO chapter applies the same checks to text, where the extra concerns are token masks, response length, and the reward assigned to a whole answer.
