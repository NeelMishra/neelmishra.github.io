    Value Iteration & Dynamic Programming in Practice

    August 2026 · 21 min read · Coursera: Fundamentals of Reinforcement Learning (University of Alberta), Week 4

    The final Week 4 step. Policy iteration evaluates a policy and then greedifies it. But full evaluation is more than improvement actually needs. Value iteration takes the generalized-policy-iteration idea seriously: do the smallest useful amount of evaluation, improve immediately, and repeat.

    From policy iteration to value iteration

    Policy iteration has an inner loop and an outer loop:

    1. Apply $T_\pi$ repeatedly until $V$ is close to $v_\pi$.
    2. Replace $\pi$ by a policy greedy with respect to that $V$.

    Generalized policy iteration says evaluation need not finish before improvement begins. Take the extreme case: perform only one backup, but choose the best action during that backup instead of averaging under a fixed policy.

    $$ \boxed{\, V_{k+1}(s)=\max_a\sum_{s'}\sum_r p(s',r\mid s,a) \big[r+\gamma V_k(s')\big] \,} $$

    This is value iteration. Evaluation and improvement have collapsed into one operation: every state is updated toward the return of the action that looks best under the current successor estimates.

    Policy-evaluation backup

    Average actions using a fixed $\pi(a\mid s)$.

    $$T_\pi V=\sum_a\pi(a\mid s)\sum_{s',r}p(\cdot)\,[r+\gamma V(s')]$$

    Optimality backup

    Select the largest action return.

    $$T_*V=\max_a\sum_{s',r}p(\cdot)\,[r+\gamma V(s')]$$

    The difference is one operator: weighted average versus maximum. That one change turns prediction into control.

    Why the optimality backups converge

    The Bellman optimality operator $T_*$ has $v_*$ as its fixed point. For $\gamma<1$, it is a contraction just like $T_\pi$. The only extra fact required is

    $$ \left|\max_a x_a-\max_a y_a\right|\le \max_a|x_a-y_a|. $$

    Using that inequality before the same probability-weighted bound gives

    $$ \lVert T_*U-T_*V\rVert_\infty\le\gamma\lVert U-V\rVert_\infty. $$

    Therefore repeated optimality backups converge from any starting vector:

    $$ V_{k+1}=T_*V_k \quad\Longrightarrow\quad V_k\longrightarrow v_*. $$

    The $\max$ does not destabilise the iteration. It simply chooses which contraction map is active at each state. As before, undiscounted episodic tasks such as the terminating gridworld require the proper-task argument rather than the $\gamma<1$ contraction proof.

    The value-iteration algorithm

    initialise V(s) arbitrarily, with V(terminal) = 0

repeat:
    delta = 0
    for each non-terminal state s:
        old = V(s)
        V(s) = max_a sum_s',r p(s',r|s,a)
                              [r + gamma V(s')]
        delta = max(delta, abs(old - V(s)))
until delta < theta

for each state s:
    pi(s) = argmax_a sum_s',r p(s',r|s,a)
                           [r + gamma V(s')]

return V, pi

    Notice that no policy is stored during the value updates. $V$ converges first; a greedy policy is extracted at the end. If all maximising actions are retained rather than arbitrarily choosing one, the result describes every optimal action available in each state.

    Watch optimal values propagate

    Run value iteration on the same 4×4 gridworld: terminal corners, reward $-1$ per move, $\gamma=1$. Starting from zero, the first sweep sets every non-terminal state to $-1$. On the second sweep, states two moves from a terminal become $-2$, while one-step states stay at $-1$. The shortest-path structure expands one layer per synchronous sweep.

    For example, once the successor estimates are correct, a state beside a terminal has one action target equal to $-1$ and every action that delays termination has a target at most $-2$. Value iteration keeps $-1$. A greedy extraction then points toward the terminal.

    Policy iteration versus value iteration

    Question Policy iteration Value iteration
    What is backed up? A fixed policy's expectation $T_\pi V$ The best action return $T_*V$
    When is the policy changed? After an evaluation phase Implicitly at every backup; extracted explicitly at the end
    Work per policy change Many evaluation sweeps One optimality sweep
    Number of policy changes Usually fewer Potentially many tiny implicit changes
    GPI interpretation Evaluation and improvement are visibly separated Evaluation is truncated to one sweep and immediately improved

    Neither dominates universally. Policy iteration spends more effort making each value function accurate; value iteration spends less effort per sweep but may need more sweeps. Modified policy iteration fills the continuum between them.

    Synchronous and asynchronous dynamic programming

    The textbook pseudocode describes synchronous DP: sweep through the complete state set in a regular pattern. Large problems make that discipline expensive. Asynchronous DP updates states in any order, possibly revisiting important states many times before touching others.

    Synchronous

    Every sweep covers every state. Predictable and easy to analyse, but it spends equal effort on states whether or not their values are changing.

    Asynchronous

    Choose updates adaptively. Focus on states whose successors just changed, or states the agent visits often. Convergence still requires that no relevant state be neglected forever.

    An in-place left-to-right sweep is already a mild asynchronous schedule because later backups use fresher information. More aggressive schemes lead to ideas such as prioritized sweeping: update where the Bellman error says an update matters most.

    Why this is called bootstrapping

    Every DP target contains an estimate:

    $$ \underbrace{r+\gamma V(s')}_{\text{target built from the current estimate }V(s')}. $$

    We improve the estimate of one state using estimates of successor states. That is bootstrapping. It is efficient because information can move backward through the MDP without waiting for complete episodes, but it also couples the errors: a bad successor estimate temporarily contaminates its predecessors until later sweeps repair it.

    The model requirement and the sampling alternative

    DP computes an exact expectation by summing $p(s',r\mid s,a)$. If the model is unknown, policy evaluation can instead use the definition directly:

    $$ v_\pi(s)=\mathbb E_\pi[G_t\mid S_t=s]. $$

    Collect many returns that start from $s$ under $\pi$ and average them. That is the Monte Carlo idea. It removes the model requirement, but each target waits until the return is known and can vary wildly because it contains every random action and transition in the remainder of the episode.

    Method Target Needs a model? Bootstraps?
    Dynamic programming Exact expectation of $r+\gamma V(s')$ Yes Yes
    Monte Carlo Sampled complete return $G_t$ No No
    Temporal difference (preview) Sampled $R_{t+1}+\gamma V(S_{t+1})$ No Yes

    This table is the bridge from planning to learning: DP gives the clean equations, Monte Carlo removes the model, and temporal-difference learning keeps bootstrapping while also removing the model.

    Efficiency and the curse of dimensionality

    Dynamic programming is dramatically better than brute-force policy search. If every state admits $|\mathcal A|$ actions, there can be $|\mathcal A|^{|\mathcal S|}$ deterministic policies. DP does not enumerate them; it improves values and policies through local backups.

    But “polynomial in the number of states” is not the same as “small.” A dense sweep may inspect every state, every action, and every successor. Worse, the number of states itself can grow exponentially with the number of state variables. Ten binary features already define $2^{10}=1024$ states; one hundred define a table too large to store, let alone sweep.

    The curse is in representation. Tabular DP is not secretly enumerating policies, but it still enumerates states. Function approximation will later replace the table with a parameterised value function that generalises across similar states.

    The Week 4 map

    Evaluate$V\leftarrow T_\pi V$
    →
    Improve$\pi\leftarrow\operatorname{greedy}(V)$
    →
    Collapse$V\leftarrow T_*V$

    Policy evaluation solves prediction. Policy improvement converts accurate predictions into better decisions. Policy iteration alternates the two. Generalized policy iteration relaxes their schedule. Value iteration fuses them into one optimality backup. The rest of reinforcement learning repeatedly revisits this same architecture with less model knowledge, more sampling, and more approximation.
