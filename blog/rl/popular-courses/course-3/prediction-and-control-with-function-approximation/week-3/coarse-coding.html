    Coarse Coding: Overlapping Features

    September 2026 · 19 min read · Prediction and Control with Function Approximation, Week 3

    Features define neighborhoods. Coarse coding covers the state space with overlapping receptive fields. A state activates every field that contains it, so one update transfers to other states sharing those fields.

    Start from one-hot features

    Tabular values can be written as a linear approximator with one feature per state:

    $$\hat v(s,\mathbf w)=\mathbf w^\top\mathbf x(s),$$

    where $\mathbf x(s)$ has exactly one active component. This gives perfect discrimination but no generalization: different states share no active feature.

    State aggregation shares within fixed regions

    State aggregation partitions the space into non-overlapping groups. Every state in one region activates the same group feature.

    Benefit

    One experience updates every state in the same group.

    Limitation

    The boundary is abrupt: states on opposite sides share nothing, even if they are extremely close.

    With one partition, every state still activates exactly one feature. Coarse coding removes that restriction.

    Receptive fields

    Receptive field. Feature $i$ has a region $F_i$ in state space. Its binary activation is $$x_i(s)=\begin{cases}1,&s\in F_i,\\0,&s\notin F_i.\end{cases}$$

    In coarse coding, the regions overlap. A state lying in three fields activates three features. Its representation is therefore multi-hot, not one-hot.

    Move a state through overlapping fields

    The estimate sums shared weights

    For binary features,

    $$\hat v(s,\mathbf w)=\sum_iw_ix_i(s) =\sum_{i:\,s\in F_i}w_i.$$

    Only fields containing $s$ contribute. If features $2$, $3$, and $5$ are active,

    $$\hat v(s,\mathbf w)=w_2+w_3+w_5.$$

    The same weights also contribute to nearby states inside those circles. That is how one parameter update generalizes spatially.

    What one update changes

    For a linear TD update,

    $$\mathbf w\leftarrow\mathbf w+\alpha\delta_t\mathbf x(S_t).$$

    Every active feature receives $\alpha\delta_t$; inactive features do not move. A second state is affected to the extent that it shares those active fields.

    Overlap improves discrimination too

    Generalization is the obvious effect of overlap. The second effect is easy to miss and matters just as much: overlap is also what lets the representation tell states apart.

    Start from the sharpest possible statement of the limit. The receptive fields cut the state space into regions on which the feature vector is constant — every state inside one region activates exactly the same subset of fields. For any two such states $s_1,s_2$,

    $$\mathbf x(s_1)=\mathbf x(s_2)\ \Longrightarrow\ \hat v(s_1,\mathbf w)=\mathbf w^\top\mathbf x(s_1)=\mathbf w^\top\mathbf x(s_2)=\hat v(s_2,\mathbf w).$$
    Inside one region the values are not merely similar, they are identical. And they are identical for every weight vector, so no amount of training can ever separate them. The region, not the individual field, is the true unit of resolution: it is the finest distinction the representation is capable of making, permanently.

    So discrimination is a question about the partition: how small are those regions? And here overlap does something that is not obvious — it shrinks the regions without shrinking the fields.

    Counting the regions makes the effect concrete. With $k$ disjoint fields the only patterns available are “inside field $j$” and “outside everything”, giving about $k$ of them — linear in the number of features. Once the fields overlap with staggered edges, each field contributes two boundaries and the partition has roughly $2k$ cells. At $k=32$ that is 33 patterns against 64, from identical memory.

    Field width sets generalization

    How far one update travels, and therefore how quickly a rough approximation appears early in learning.

    Field count sets discrimination

    How finely the space is partitioned, and therefore how much detail the final solution can ever express.

    These are separate knobs, which is the practical payoff. The intuitive move when you need finer resolution is to shrink the fields — but that sacrifices the broad generalization that made early learning fast. You do not have to: keep the fields wide and add more of them. Width and acuity are only in tension if you hold the feature count fixed.

    What this looks like while learning

    Take a one-dimensional target with a sharp step in it, sample the true values, and watch the estimate form under two codings with the same number of features.

    CodingEarly, after few samplesLate, after many samples
    Narrow intervalsPoor. Each sample informs only a sliver of the space, so the estimate is still visibly rough and needs far more data.Eventually a close match, though it takes a lot of training to get there.
    Wide staggered intervalsThe broad shape of the target appears almost immediately — one sample moves a large region at once.Also better: with many wide intervals the intersections are fine enough to resolve the step.

    The wide coding wins on both counts here: broad fields make learning fast, and having many of them makes the final fit sharp.

    Do not over-generalize from that. It happened because the coding had both properties — wide fields and enough of them. Widening fields while holding the count fixed genuinely does blur detail, and a target whose structure is finer than the region size cannot be represented no matter how long you train. The lesson is that width and count must be chosen together, not that wider is always better.

    Do not leave gaps

    If a state activates no feature, then $\mathbf x(s)=\mathbf 0$ and

    $$\hat v(s,\mathbf w)=0,\qquad \nabla\hat v(s,\mathbf w)=\mathbf 0.$$

    The agent cannot change that prediction through a linear update. A practical coarse-coding design must cover every state that may be visited.

    Beyond two dimensions

    Receptive fields can be circles in two dimensions, intervals in one dimension, or higher-dimensional regions. The principle is unchanged: each feature answers whether the state lies in its field. The computational challenge is finding active fields efficiently, which motivates tile coding.
