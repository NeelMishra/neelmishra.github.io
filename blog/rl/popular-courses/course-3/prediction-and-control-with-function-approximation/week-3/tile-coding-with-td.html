    Tile Coding & Sparse TD Updates

    September 2026 · 24 min read · Prediction and Control with Function Approximation, Week 3

    Tile coding is structured coarse coding. Several offset grids cover the same continuous state space. Each grid activates one tile, producing a sparse multi-hot feature vector that is fast to query and update.

    One tiling is state aggregation

    Lay a regular grid over the state space. Every grid cell is a tile and corresponds to one binary feature. A state activates the tile containing it.

    $$x_i(s)=1\quad\text{for the containing tile},\qquad x_j(s)=0\quad\text{for all other tiles}.$$

    With one grid, this is ordinary state aggregation: states inside a tile are indistinguishable, and crossing a boundary changes the active feature abruptly.

    Stack offset tilings

    Use several grids with slightly different offsets. A state activates one tile in every tiling. Nearby states may differ in one tiling while still sharing tiles in the others, producing smoother generalization and finer discrimination.

    Sparse binary value estimates

    Let $n$ be the number of tilings and $d$ the total number of tiles across all tilings. The feature vector $\mathbf x(s)\in\{0,1\}^d$ contains exactly $n$ ones.

    $$\boxed{\hat v(s,\mathbf w)=\mathbf w^\top\mathbf x(s) =\sum_{i:\,x_i(s)=1}w_i}.$$

    There is no need to multiply or even iterate over all $d$ features. Store the active tile indices and sum only their weights. Lookup cost is $O(n)$, independent of the total number of tiles.

    TD updates only active tiles

    Linear semi-gradient TD is

    $$\delta_t=R_{t+1}+\gamma\hat v(S_{t+1},\mathbf w)-\hat v(S_t,\mathbf w),$$
    $$\mathbf w\leftarrow\mathbf w+\alpha\delta_t\mathbf x(S_t).$$

    Because $\mathbf x(S_t)$ is binary and sparse,

    $$\boxed{w_i\leftarrow w_i+\alpha\delta_t \quad\text{for every active tile }i;}$$ $$\boxed{w_j\text{ is unchanged for every inactive tile }j.}$$

    Every tiling contributes one active weight, so both prediction and update touch a fixed number of parameters per state.

    Scale the step size by active features

    If $n$ active weights each receive the full step size, adding more tilings also enlarges the total change in the value estimate. A common normalization is

    $$\boxed{\alpha=\frac{\alpha'}{n}},$$

    where $\alpha'$ controls the overall update scale. Then each active weight changes by $\alpha'\delta_t/n$, and their combined first-order effect stays comparable as $n$ changes.

    Sparse tile-coded TD(0)

    One tile-coded TD update
    1Find active tile indices $I(S_t)$, one from each tiling.
    2Compute $\hat v(S_t)=\sum_{i\in I(S_t)}w_i$.
    3Observe $R_{t+1},S_{t+1}$ and compute $\delta_t=R_{t+1}+\gamma\hat v(S_{t+1})-\hat v(S_t)$.
    4for each active tile index $i\in I(S_t)$:
    5Update the corresponding weight: $w_i\leftarrow w_i+(\alpha'/n)\delta_t$

    Offsets determine the overlap pattern

    If every tiling is shifted in exactly the same direction, the resulting activation regions can have an unintended diagonal bias. Diverse or randomized offsets make generalization more homogeneous.

    Aligned offset pattern

    Cheap and regular, but can favor diagonal directions.

    Diverse offsets

    Creates richer intersections and reduces directional artifacts.

    Offsets also create partial tiles at boundaries. Even if a tile width divides the state range exactly, a shifted tiling may need one extra tile to cover both ends.

    Rectangular tiles through input scaling

    Square tiles generalize equally in both coordinate units. To generalize more along one dimension, rescale that coordinate before coding:

    $$\tilde s=(c_1s_1,\ldots,c_ks_k).$$

    A square grid in the scaled space corresponds to rectangular tiles in the original space. Small $c_j$ compresses dimension $j$, making each tile cover a wider original range along that axis.

    Why multiple tilings beat one aggregation

    Consider 1000 ordered states and tiles covering 200 states each.

    RepresentationFeaturesStates distinguishable within 200-state span?
    One state aggregation5 groupsNo; all 200 states share one feature.
    50 offset tilingsAbout 6 boundary-aware tiles per tiling, 300 totalYes; different overlap patterns distinguish nearby states.

    Both use broad 200-state tiles, but offset intersections let tile coding preserve much finer value differences. The price is more memory; sparse activation keeps each query cheap.

    The high-dimensional limit

    A full grid over $k$ dimensions grows exponentially with $k$. If each dimension has $m$ intervals, one tiling can require $m^k$ tiles. Possible mitigations include hashing active tiles and tiling small subsets of dimensions separately.

    Separate dimensions only when the problem permits it. Factorized tilings save memory but cannot represent interactions between dimensions that never appear together in a feature.
