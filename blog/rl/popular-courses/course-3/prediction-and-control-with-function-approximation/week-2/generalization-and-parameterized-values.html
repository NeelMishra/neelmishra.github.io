    Generalization & Parameterized Value Functions

    September 2026 · 20 min read · Prediction and Control with Function Approximation, Week 2

    The shift from Course 2. Tabular methods store one number for every state. Function approximation stores a much smaller set of weights and uses them to estimate many states at once.

    Why lookup tables stop working

    A tabular value function keeps a separate entry $V(s)$ for every state. This is ideal when the state space is small: any state can be represented exactly, and updating one entry leaves every other entry unchanged.

    Large or continuous state spaces break that strategy. A camera image, a robot configuration, or a board position can admit far more states than an agent can visit or store. Worse, a new state receives no benefit from experience gathered in a similar state.

    Tabular memory

    One parameter per state. Excellent discrimination, but no sharing.

    $$\text{parameters}=|\mathcal S|.$$

    Function approximation

    A shared parameter vector estimates every state. Experience can transfer.

    $$\hat v(s,\mathbf w)\approx v_\pi(s),\qquad \mathbf w\in\mathbb R^d.$$

    Generalization and discrimination

    Generalization. An update learned at one state also changes estimates at related states.
    Discrimination. The representation can assign different values to states that require different predictions.

    Both are necessary. A road-following agent should transfer knowledge among visually similar clear roads, but it must distinguish a clear road from a nearly identical view containing a wall.

    RepresentationGeneralizationDiscriminationFailure mode
    One value for all statesMaximumNoneStates that need different values are forced together.
    Tabular, one value per stateNoneMaximumUnvisited states learn nothing; memory grows with $|\mathcal S|$.
    Shared features and weightsControlled by featuresControlled by featuresPoor features can share too much or too little.
    Design goal

    Share parameters between states that should have similar values, while preserving the distinctions that matter for return.

    Make the value function adjustable

    A fixed formula such as $f(x,y)=x+y$ maps states to numbers, but an agent cannot learn if the formula has nothing adjustable. Introduce parameters:

    $$\hat v(s,\mathbf w)=w_1x(s)+w_2y(s).$$

    The features $x(s)$ and $y(s)$ describe the state. The weights $w_1,w_2$ are changed by learning. One weight update alters every state that uses that feature.

    Two weights reshape an entire grid

    Linear value-function approximation

    Collect all state features into a vector $\mathbf x(s)=(x_1(s),\ldots,x_d(s))^\top$. A linear approximator is

    $$\boxed{\hat v(s,\mathbf w)=\mathbf w^\top\mathbf x(s)=\sum_{i=1}^d w_ix_i(s)}.$$

    Linear means linear in the weights. The features themselves can be nonlinear functions of the state: distances, radial basis functions, tile indicators, or outputs from a fixed preprocessing pipeline.

    The gradient is especially simple:

    $$\boxed{\nabla_{\mathbf w}\hat v(s,\mathbf w)=\mathbf x(s)}.$$

    Therefore the active features determine exactly which weights move during learning and which other states inherit the update.

    A table is a linear approximator in disguise

    For state $s_j$, define a one-hot feature vector with a $1$ only in position $j$:

    $$\mathbf x(s_j)=(0,\ldots,0,\underbrace{1}_{j},0,\ldots,0)^\top.$$

    Then

    $$\hat v(s_j,\mathbf w)=\mathbf w^\top\mathbf x(s_j)=w_j.$$

    Only $w_j$ changes when $s_j$ is updated, so there is no generalization. Tabular learning is not a separate mathematical world; it is the one-hot endpoint of linear function approximation.

    Features decide what gets shared

    Two states with similar feature vectors receive similar estimates and similar updates. If $\mathbf x(s)$ and $\mathbf x(\tilde s)$ overlap strongly, changing $\mathbf w$ for one tends to affect the other. This creates generalization without explicitly listing neighboring states.

    A global optimum can still be a poor value function. If every state uses the same constant feature $\mathbf x(s)=(1)$, the best possible estimate is only a visitation-weighted average. Optimization cannot recover distinctions that the representation erased.

    What changes with a neural network?

    A neural network replaces the dot product with a nonlinear map, but the interface remains the same:

    $$s\longmapsto \hat v(s,\mathbf w).$$

    The parameters are now all network weights. Nonlinearity increases expressive power, but it also makes the optimization landscape and convergence analysis more difficult. The linear case provides the clean foundation.
