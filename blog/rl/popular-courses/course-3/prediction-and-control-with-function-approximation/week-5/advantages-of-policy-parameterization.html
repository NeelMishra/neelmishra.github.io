    Advantages of Policy Parameterization

    September 2026 · 21 min read · Prediction and Control with Function Approximation, Week 5

    Three separate arguments. A parameterized policy can tighten its own exploration without an $\varepsilon$ schedule; it can represent stochastic behaviour that beats every deterministic policy once states are aliased by the features; and on some problems the policy is simply a much easier function to represent than the value function.

    Greedification the agent controls itself

    An $\varepsilon$-greedy agent explores because we told it to, at a rate we chose. That has an unavoidable consequence: the behaviour policy can never be better than

    $$\pi(a_{\text{best}}\mid s)=1-\varepsilon+\frac{\varepsilon}{|\mathcal A|},$$

    no matter how accurate the action values become. Even with perfect estimates, a fixed $\varepsilon$ leaves a permanent tax on performance, because a fraction $\varepsilon\,(|\mathcal A|-1)/|\mathcal A|$ of the decisions are made uniformly at random.

    The usual fix is to decay $\varepsilon$ on a schedule. That works, but the schedule is ours, not the agent's: we have to guess in advance how long exploration should last, and the agent has no way to tell us that it has already seen enough of one region and too little of another.

    A softmax policy makes this part of learning. Because the probabilities depend on differences of preferences,

    $$\pi(a\mid s,\boldsymbol\theta)=\frac{e^{h(s,a,\boldsymbol\theta)}}{\sum_b e^{h(s,b,\boldsymbol\theta)}}\ \xrightarrow[\ h(s,a)-h(s,b)\ \to\ \infty\ ]{}\ 1,$$

    the agent starts stochastic (small, similar preferences, near-uniform exploration) and becomes as deterministic as it wants by growing the gaps. Nothing external has to shrink. Early on, when the estimates are poor, the gaps are small and the policy hedges; later, when one action is consistently better, the gap widens and the policy concentrates. Exploration ends when the evidence says it should, which is what "autonomous" means here.

    Approaching determinism is not the same as reaching it. $\pi(a\mid s,\boldsymbol\theta)$ is never exactly $0$ or $1$ for finite preferences, so a softmax policy can only get arbitrarily close to greedy. That residual randomness is usually a feature; it is also why policy gradient methods need bounded step sizes to stop preferences from blowing up early on a lucky streak.

    When the best policy you can represent is stochastic

    In a finite MDP with a tabular representation there is always a deterministic optimal policy: pick $\arg\max_a q_*(s,a)$ in each state, breaking ties arbitrarily. Randomizing can tie that value but never beat it.

    That guarantee quietly assumes each state can be treated on its own. Function approximation breaks the assumption. If two states share the same feature vector — because tiles are coarse, because the sensors cannot tell them apart, because the aggregation lumps them together — then the policy is forced to act the same way in both. The set of policies you can represent shrinks, and the best element of that smaller set may well be stochastic.

    State aliasing. Two distinct states $s\ne s'$ with $\mathbf x(s)=\mathbf x(s')$ are aliased: every parameterized policy satisfies $\pi(\cdot\mid s,\boldsymbol\theta)=\pi(\cdot\mid s',\boldsymbol\theta)$. Deterministic representable policies then commit to one action for the whole aliased group.

    The short corridor, worked out exactly

    Here is the smallest example that makes the point. Three non-terminal states in a row, two actions (left and right), reward $-1$ on every step, episode ends when the agent leaves the rightmost state to the right.

    Now suppose the features cannot distinguish the three states — they all get the same feature vector. Then the policy has exactly one number to choose: $p=\pi(\text{right}\mid\cdot,\boldsymbol\theta)$, used in all three states.

    1

    Both deterministic policies fail. With $p=0$ the agent presses left in $S_0$ forever and bounces off the wall, so the episode never ends. With $p=1$ it moves $S_0\to S_1$, and from $S_1$ "right" sends it back to $S_0$, so it oscillates forever. Both give an expected return of $-\infty$.

    2

    Any interior $p$ terminates with probability one. Every action keeps positive probability, so the sequence of moves that reaches the goal has positive probability at every visit, and the expected number of steps is finite.

    3

    Expected steps, exactly. Let $J_i$ be the expected number of steps to termination from $S_i$, and $q=1-p$. Reading the diagram,

    $$J_0=1+pJ_1+qJ_0,\qquad J_1=1+pJ_0+qJ_2,\qquad J_2=1+q J_1.$$

    The first equation gives $J_0=\tfrac1p+J_1$. Substituting that and $J_2$ into the middle equation leaves $J_1(q-q^2)=3-p$, and since $q-q^2=pq$,

    $$J_1=\frac{3-p}{pq},\qquad\boxed{\ J_0=\frac{1}{p}+\frac{3-p}{pq}=\frac{2(2-p)}{p(1-p)}\ }.$$

    Because every step costs $-1$, the value of the start state is $v_{\pi_{\boldsymbol\theta}}(S_0)=-J_0$.

    4

    The optimum is genuinely stochastic. Setting $\frac{d}{dp}J_0=0$ gives $p^2-4p+2=0$, so

    $$p^\star=2-\sqrt2\approx0.586,\qquad J_0(p^\star)=\frac{2(\sqrt2)}{(2-\sqrt2)(\sqrt2-1)}\approx11.66.$$

    A start-state value of about $-11.7$, against $-\infty$ for both deterministic options. Randomizing is not a compromise here; it is the only thing that works.

    The $\varepsilon$-greedy comparison is instructive. Suppose the values correctly identify "right" as the better action for the aliased group and we act $\varepsilon$-greedily with $\varepsilon=0.1$. Then $p=1-\varepsilon+\varepsilon/2=0.95$, and the same formula gives

    $$J_0(0.95)=\frac{2(2-0.95)}{0.95\times0.05}\approx44.2,$$

    a start-state value near $-44$: finite, because $\varepsilon$-greedy is stochastic too, but roughly four times worse than the best stochastic policy. $\varepsilon$-greedy can only offer randomness of one shape — a spike plus a uniform floor — and here the right amount of randomness is $41\%$ on the "wrong" action. A parameterized policy can simply learn that number.

    Sometimes the policy is the simpler object

    The last argument is about representation cost. There is no rule that says the value function is easier to approximate than the policy; on some problems it is dramatically harder.

    Mountain Car is the standard illustration. The near-optimal policy is a single sign test: accelerate in the direction the car is already moving. Drawn in the position-velocity plane it is two half-planes split by a line. The optimal value function over the same plane is a spiral-shaped surface that tile-coded Sarsa needs hundreds of episodes to shape, as we saw in week 4.

    The lesson is to ask which function you actually need. Value-based control learns a hard object and then extracts an easy one from it. If the easy object is what you want, and it is representable with far fewer parameters, learning it directly can be much cheaper — and it also handles continuous actions, where $\max_a\hat q(s,a,\mathbf w)$ is itself an optimization problem.

    None of this makes value functions obsolete. The next posts build actor-critic methods, which learn a policy and a value function, using the value function only where it genuinely helps: as a low-variance baseline for the policy update.
