    Actor-Critic with Softmax Policies

    September 2026 · 21 min read · Prediction and Control with Function Approximation, Week 5

    Filling in the blanks. The actor-critic loop never said what $\hat v$ and $\pi$ actually are. Here we commit: linear features for both, a softmax over linear action preferences for the actor, and continuous states with a finite action set. Every gradient in the algorithm then has a closed form you can write in two lines of code.

    The two parameterizations

    The critic estimates a state value, so it needs features of the state alone. The actor scores state-action pairs, so its preferences need features of both:

    Critic

    $$\hat v(s,\mathbf w)\doteq\mathbf w^\top\mathbf x(s)$$

    $\mathbf x(s)\in\mathbb R^{d}$ from tile coding, coarse coding, or any other state feature map from week 3.

    Actor

    $$h(s,a,\boldsymbol\theta)\doteq\boldsymbol\theta^\top\mathbf x_h(s,a),\qquad \pi(a\mid s,\boldsymbol\theta)=\frac{e^{h(s,a,\boldsymbol\theta)}}{\sum_b e^{h(s,b,\boldsymbol\theta)}}$$

    $\mathbf x_h(s,a)\in\mathbb R^{d|\mathcal A|}$ built by stacking, exactly as for action values in week 4.

    Reusing the stacking trick means one copy of the state features per action, with every block but the chosen action's set to zero. The consequence is a size mismatch that surprises people the first time: with three actions the actor carries three times as many parameters as the critic, even though both read the same underlying features.

    $$\mathbf x_h(s,a_1)=\big[\underbrace{\mathbf 0}_{a_0},\ \underbrace{\mathbf x(s)}_{a_1},\ \underbrace{\mathbf 0}_{a_2}\big]^\top\in\mathbb R^{3d},\qquad \mathbf w\in\mathbb R^{d}.$$
    Preferences are not values, even when they share features. $\mathbf w$ and $\boldsymbol\theta$ read the same $\mathbf x(s)$, but they are trained by different rules towards different things: $\mathbf w$ towards an unbiased estimate of the differential return, $\boldsymbol\theta$ towards whatever ranking makes the policy better. Nothing forces $\boldsymbol\theta$ to end up proportional to any value function.

    Selecting an action

    Because the normalizer is per-state, the policy is effectively a separate softmax distribution in every state. Acting is a three-step procedure at each time step:

    1. scorecompute $h(s,a,\boldsymbol\theta)=\boldsymbol\theta^\top\mathbf x_h(s,a)$ for each of the $|\mathcal A|$ actions
    →
    2. normalizeexponentiate and divide to get a probability vector over actions
    →
    3. sampledraw $A_t$ in proportion to those probabilities

    With stacked features each preference only touches its own block, so scoring all actions costs $|\mathcal A|$ sparse dot products — and with binary features such as tile codings, each of those is a handful of additions. In practice you subtract $\max_b h(s,b,\boldsymbol\theta)$ before exponentiating, which changes nothing mathematically (softmax is shift invariant) and avoids overflow.

    The critic update

    Linear values make the critic's gradient trivial:

    $$\nabla\hat v(s,\mathbf w)=\mathbf x(s)\qquad\Longrightarrow\qquad \mathbf w\leftarrow\mathbf w+\alpha^{\mathbf w}\,\delta\,\mathbf x(S_t).$$

    This is differential semi-gradient TD, unchanged. With sparse binary features only the active entries of $\mathbf w$ move, at a cost proportional to the number of active features rather than $d$.

    The actor update, derived

    The actor needs $\nabla\ln\pi(a\mid s,\boldsymbol\theta)$. Take the log of the softmax first, which turns the quotient into a difference:

    1
    $$\ln\pi(a\mid s,\boldsymbol\theta)=h(s,a,\boldsymbol\theta)-\ln\sum_{b}e^{h(s,b,\boldsymbol\theta)}.$$
    2

    The first term is linear, so its gradient is the feature vector: $\nabla h(s,a,\boldsymbol\theta)=\mathbf x_h(s,a)$.

    3

    For the second term, differentiate the log-sum-exp with the chain rule:

    $$\nabla\ln\sum_b e^{h(s,b,\boldsymbol\theta)}=\frac{\sum_b e^{h(s,b,\boldsymbol\theta)}\,\mathbf x_h(s,b)}{\sum_c e^{h(s,c,\boldsymbol\theta)}}=\sum_b\pi(b\mid s,\boldsymbol\theta)\,\mathbf x_h(s,b),$$

    because each ratio $e^{h(s,b)}/\sum_c e^{h(s,c)}$ is just $\pi(b\mid s,\boldsymbol\theta)$.

    4

    Subtracting gives the eligibility vector in closed form:

    $$\boxed{\ \nabla\ln\pi(a\mid s,\boldsymbol\theta)=\mathbf x_h(s,a)-\sum_b\pi(b\mid s,\boldsymbol\theta)\,\mathbf x_h(s,b)\ }$$

    Read it as what I did minus what I usually do: the features of the action actually taken, minus the average features under the current policy. If the policy already almost always picks $a$, the two terms nearly cancel and the update is tiny; if $a$ was a long shot, the difference is large and the update is correspondingly bold. That is the $1/\pi$ factor from the sampled estimator, reappearing in a numerically friendly form.

    $$\boldsymbol\theta\leftarrow\boldsymbol\theta+\alpha^{\boldsymbol\theta}\,\delta\,\Big[\mathbf x_h(S_t,A_t)-\sum_b\pi(b\mid S_t,\boldsymbol\theta)\,\mathbf x_h(S_t,b)\Big].$$

    What the update does to each block

    Stacking makes the eligibility vector easy to picture. Since $\mathbf x_h(s,b)$ is $\mathbf x(s)$ inside block $b$ and zero elsewhere, the entry of $\nabla\ln\pi$ inside block $b$ is

    $$\big[\nabla\ln\pi(a\mid s,\boldsymbol\theta)\big]_{\text{block }b}=\big(\mathbb 1[b=a]-\pi(b\mid s,\boldsymbol\theta)\big)\,\mathbf x(s).$$

    Every block is the same state feature vector, scaled by a single number. The taken action gets $1-\pi(a\mid s)$, which is positive; every other action gets $-\pi(b\mid s)$, which is negative; and the coefficients sum to zero, so the blocks pull against one another exactly as much as the chosen one pushes.

    This differs from Sarsa in an important way. A stacked-linear Sarsa update touched only the block of the action taken. The actor update touches every block, because raising one action's probability necessarily lowers the others. Sparsity in the features still holds — only active features move — but sparsity across actions does not.

    Push the "peaked" slider up while keeping the same action: as $\pi(A_t\mid s)\to1$ the coefficient $1-\pi(A_t\mid s)$ shrinks towards zero and the update fades. A confident policy that gets a pleasant surprise barely moves; the same surprise on an action it rarely takes moves it a great deal.

    The instantiated loop

    Actor-critic with linear features and a softmax policy, continuing case
    1features $\mathbf x(s)\in\mathbb R^{d}$; stacked $\mathbf x_h(s,a)\in\mathbb R^{d|\mathcal A|}$; step sizes $\alpha^{\mathbf w},\alpha^{\boldsymbol\theta},\alpha^{\bar R}>0$
    2initialize $\bar R\leftarrow0$, $\mathbf w\leftarrow\mathbf 0$, $\boldsymbol\theta\leftarrow\mathbf 0$ (a uniform random policy), and $S$
    3loop forever:
    4$h_b\leftarrow\boldsymbol\theta^\top\mathbf x_h(S,b)$ for every $b$; $\ \pi\leftarrow\operatorname{softmax}(h)$; $\ A\sim\pi$
    5take $A$, observe $R$ and $S'$
    6$\delta\leftarrow R-\bar R+\mathbf w^\top\mathbf x(S')-\mathbf w^\top\mathbf x(S)$
    7$\bar R\leftarrow\bar R+\alpha^{\bar R}\delta$
    8$\mathbf w\leftarrow\mathbf w+\alpha^{\mathbf w}\delta\,\mathbf x(S)$
    9for each block $b$: $\ \boldsymbol\theta_b\leftarrow\boldsymbol\theta_b+\alpha^{\boldsymbol\theta}\delta\big(\mathbb 1[b=A]-\pi_b\big)\mathbf x(S)$
    10$S\leftarrow S'$

    Initializing $\boldsymbol\theta=\mathbf 0$ makes every preference zero, so the agent starts with a uniform random policy over actions — maximal exploration, chosen by the initialization rather than by an $\varepsilon$ parameter, and tightened by learning rather than by a schedule.
