    Episodic Sarsa with Function Approximation

    September 2026 · 22 min read · Prediction and Control with Function Approximation, Week 4

    Control needs action values. Everything from weeks 2 and 3 carries over unchanged, except that the feature vector must now describe a state and an action. The standard trick is to stack one copy of the state features per action and zero out every block but the one you took.

    From state values to action values

    Prediction with approximation gave us a parameterized state-value function. For linear features that was

    $$v_\pi(s)\approx\hat v(s,\mathbf w)\doteq\mathbf w^\top\mathbf x(s).$$

    Control needs to rank actions in a state, so we need $q_\pi$ instead:

    $$\boxed{q_\pi(s,a)\approx\hat q(s,a,\mathbf w)\doteq\mathbf w^\top\mathbf x(s,a)}.$$

    Two things changed, and only two. The function now takes an action argument, and the feature vector $\mathbf x(s,a)$ must represent the action as well as the state. The weight vector is still a single flat $\mathbf w$, and the update rule will still be a semi-gradient step. The whole question is how to build $\mathbf x(s,a)$.

    Stacking: one feature block per action

    Suppose we already have a state feature map $\mathbf x(s)\in\mathbb R^{d}$ from tile coding, coarse coding, or state aggregation. The simplest way to add actions is to keep a separate function approximator for every action, and to express those separate approximators inside one long vector.

    Stacked feature representation. For $|\mathcal A|$ actions, define $\mathbf x(s,a)\in\mathbb R^{d\,|\mathcal A|}$ as $|\mathcal A|$ stacked copies of $\mathbf x(s)$, where the block belonging to $a$ holds the real features and every other block is set to zero.
    $$\mathbf x(s,a_k)=\big[\underbrace{\mathbf 0}_{a_0},\ \ldots,\ \underbrace{\mathbf x(s)}_{a_k},\ \ldots,\ \underbrace{\mathbf 0}_{a_{|\mathcal A|-1}}\big]^\top.$$

    With $\mathcal A(s)=\{a_0,a_1,a_2\}$ and four state features, $\mathbf x(s)$ of length 4 becomes $\mathbf x(s,a)$ of length 12. Only four entries are ever non-zero.

    Because the blocks never overlap, the dot product $\mathbf w^\top\mathbf x(s,a)$ only touches the weights in block $a$. That is exactly what "a separate approximator per action" means: no weight is shared between two actions. There is generalization across states, none across actions.

    Computing action values

    Take four features and three actions. Say the state $s_0$ activates features 0 and 3, so $\mathbf x(s_0)=[1,0,0,1]^\top$, and the weight vector is split into three blocks of four:

    $$\mathbf w=\big[\underbrace{0.7,\,0.1,\,0.4,\,0.3}_{a_0},\ \underbrace{2.2,\,1.0,\,0.6,\,1.8}_{a_1},\ \underbrace{1.3,\,1.1,\,0.9,\,1.7}_{a_2}\big]^\top.$$

    Each action value is the sum of the weights in that action's block whose feature is active:

    $$\hat q(s_0,a_0,\mathbf w)=0.7+0.3=1,\qquad \hat q(s_0,a_1,\mathbf w)=2.2+1.8=4,\qquad \hat q(s_0,a_2,\mathbf w)=1.3+1.7=3.$$

    The greedy action in $s_0$ is $a_1$. Note what we never did: we never built the length-12 vector, and we never multiplied by any zeros. With binary features the whole computation is "look up the active indices, offset them into the right block, add".

    The gradient is the feature vector

    For a linear parameterization the gradient of the estimate with respect to the weights is just the features:

    $$\nabla\hat q(s,a,\mathbf w)=\mathbf x(s,a).$$

    Combined with stacking, this has a pleasant consequence. Since $\mathbf x(s,a)$ is zero outside block $a$,

    $$\boxed{\text{a Sarsa update on }(S_t,A_t)\text{ changes only the weights in block }A_t.}$$

    Weights for the other actions are untouched, exactly as if you had trained $|\mathcal A|$ independent linear predictors and only fed this sample to one of them.

    Action values from a neural network

    Stacking features is not specific to linear approximation, and it is not the only option. The two common neural-network parameterizations are:

    The left layout is the stacking idea in disguise. The last hidden layer produces a state feature vector, and each action value is a separate linear readout of those shared features. Generalization happens across states, through the hidden layers, but each output row of weights belongs to exactly one action.

    The right layout feeds the action in as part of the input. Now the hidden units can mix state and action, so learning about one action can change the estimate for a different action. Tile coding gives you the same thing if you tile jointly over state and action variables instead of stacking.

    Generalizing across actions is a design decision, not a free win. It helps when actions are ordered or geometrically related, such as steering angles or torques, and it hurts when they are arbitrary labels whose values have no reason to be similar. The one-output-per-action layout also gives you every $\hat q(s,\cdot)$ in a single forward pass, which matters for $\varepsilon$-greedy and for $\max_a$ targets.

    Episodic semi-gradient Sarsa

    With $\hat q$ in place, the control algorithm is the usual generalized policy iteration loop: act $\varepsilon$-greedily with respect to the current estimates, then move the estimates toward a bootstrapped target.

    Episodic semi-gradient Sarsa for estimating $\hat q\approx q_*$
    1input a differentiable parameterization $\hat q:\mathcal S\times\mathcal A\times\mathbb R^{d}\to\mathbb R$
    2parameters: step size $\alpha>0$, small $\varepsilon>0$
    3initialize $\mathbf w\in\mathbb R^{d}$ arbitrarily, e.g. $\mathbf w=\mathbf 0$
    4for each episode:
    5$S,A\leftarrow$ initial state and action, e.g. $\varepsilon$-greedy in $\hat q(S,\cdot,\mathbf w)$
    6for each step of the episode:
    7take $A$, observe $R,S'$
    8if $S'$ is terminal: $\mathbf w\leftarrow\mathbf w+\alpha\big[R-\hat q(S,A,\mathbf w)\big]\nabla\hat q(S,A,\mathbf w)$, go to next episode
    9choose $A'$ from $\hat q(S',\cdot,\mathbf w)$, e.g. $\varepsilon$-greedy
    10$\mathbf w\leftarrow\mathbf w+\alpha\big[R+\gamma\hat q(S',A',\mathbf w)-\hat q(S,A,\mathbf w)\big]\nabla\hat q(S,A,\mathbf w)$
    11$S\leftarrow S'$, $A\leftarrow A'$

    Three details are worth pausing on.

    1

    The parameterized action value replaces the table entry. Where tabular Sarsa wrote $Q(S,A)$, we now write $\hat q(S,A,\mathbf w)$, in both the target and the estimate being corrected.

    2

    The update moves weights, not cells. The scalar TD error is multiplied by $\nabla\hat q(S,A,\mathbf w)$, so the correction is spread over every weight that contributed to the estimate. This is the same structure as semi-gradient TD; only the function being differentiated changed.

    $$\delta_t=R_{t+1}+\gamma\hat q(S_{t+1},A_{t+1},\mathbf w)-\hat q(S_t,A_t,\mathbf w),\qquad \mathbf w\leftarrow\mathbf w+\alpha\delta_t\nabla\hat q(S_t,A_t,\mathbf w).$$
    3

    It is still semi-gradient. The target $R+\gamma\hat q(S',A',\mathbf w)$ depends on $\mathbf w$, but we do not differentiate through it. Only the gradient of the current estimate appears.

    The terminal case in line 8 is not a special rule, just bookkeeping: $\hat q(S',A',\mathbf w)$ is defined to be $0$ for terminal $S'$, so the target collapses to $R$. Forgetting this and bootstrapping off a terminal state is a classic source of silently wrong value functions.

    What the update looks like for stacked linear features

    Put the pieces together. With $\hat q(s,a,\mathbf w)=\mathbf w^\top\mathbf x(s,a)$ and binary stacked features, the whole step is:

    $$\boxed{w_i\leftarrow w_i+\alpha\delta_t\quad\text{for each active feature }i\text{ in block }A_t,}$$ $$\boxed{w_j\text{ unchanged everywhere else.}}$$

    If the state features come from $n$ tilings, the update touches $n$ weights out of $d\,|\mathcal A|$, and the usual step-size normalization $\alpha=\alpha'/n$ from tile coding still applies.

    Takeaway

    Action values under function approximation are the same machinery as state values with a wider feature vector. Stacking gives you an independent approximator per action for free; joint state-action features or an action input give you generalization across actions when the problem supports it.
